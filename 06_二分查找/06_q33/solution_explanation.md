# LeetCode 33. 搜索旋转排序数组解析

## 题目描述

给定一个原本按升序排列的整数数组 `nums`，它在某个未知位置发生了一次旋转。

例如：

```text
[0, 1, 2, 4, 5, 6, 7]
```

可能会变成：

```text
[4, 5, 6, 7, 0, 1, 2]
```

再给定一个目标值 `target`，要求返回它在数组中的下标。

如果不存在，返回：

```text
-1
```

题目还保证：

```text
数组中的元素互不相同
```

---

## 先理解题意

这题看起来像普通二分，但和普通升序数组有一个关键区别：

```text
整个数组不再完全有序
```

所以你不能只靠：

```python
nums[mid] < target
```

来判断答案一定在左边还是右边。

例如：

```text
nums = [4, 5, 6, 7, 0, 1, 2]
target = 0
mid 指到 7
```

虽然：

```text
7 > 0
```

但答案并不在左边，而是在右边。

所以这题真正的突破口不是“直接比较 `nums[mid]` 和 `target`”，而是：

```text
每次以 mid 切开后，左右两半里一定至少有一半是有序的
```

只要先找到哪一半有序，再判断 `target` 是否落在那一半里，就能继续二分。

---

## 方法一：线性扫描

### 思路

最直接的方法就是从左到右遍历数组。

如果当前元素等于 `target`，直接返回下标。

如果扫完整个数组还没找到，就返回 `-1`。

---

### 为什么可行

因为线性扫描会检查每个位置，所以不会漏掉目标值。

只要 `target` 存在，就一定会被扫描到。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 这个方法差在哪里

它当然正确，但没有利用数组“虽然旋转了，但仍然保留局部有序”的结构。

题目要求最好做到 `O(log n)`，所以最终还是要回到二分。

---

## 方法二：二分查找（面试主推）

这是最适合面试的方法。

---

### 核心想法

虽然整个数组不是完全有序的，但由于它是由一个升序数组旋转得到的，而且元素互不相同，所以每次取到 `mid` 后：

```text
[left, mid] 和 [mid, right] 里，一定至少有一边是有序的
```

于是每一轮都做两步：

1. 判断哪一半是有序的
2. 判断 `target` 是否落在这段有序区间里

如果在，就去这半边找；如果不在，就去另一半找。

---

### 第一步：先看 `nums[mid]` 是不是目标值

这是普通二分和这题都一样的第一步。

如果：

```python
nums[mid] == target
```

就可以直接返回 `mid`。

---

### 第二步：判断左半边是否有序

如果：

```python
nums[left] <= nums[mid]
```

说明：

```text
[left, mid] 这一段是有序的
```

为什么这个判断成立？

因为如果旋转点不在左半边，那左半边就保持原来的升序结构。

而在“元素互不相同”的前提下，`nums[left] <= nums[mid]` 正好能说明左半边没有被旋转点打断。

这时候再判断：

```python
nums[left] <= target < nums[mid]
```

如果成立，说明 `target` 在左半边的有序区间里，所以：

```python
right = mid - 1
```

否则说明 `target` 不在左半边，应该去右边：

```python
left = mid + 1
```

---

### 第三步：如果左半边无序，那右半边一定有序

如果：

```python
nums[left] > nums[mid]
```

那就说明旋转点落在左半边，因此：

```text
[mid, right] 这一段一定有序
```

这时候判断：

```python
nums[mid] < target <= nums[right]
```

如果成立，说明 `target` 在右半边有序区间里，所以：

```python
left = mid + 1
```

否则说明它不在右边，应该去左边：

```python
right = mid - 1
```

---

### 为什么这题还能二分

这题的难点不在代码，而在“为什么每次都能放心砍掉一半”。

理由其实很简单：

- 如果某一半是有序的，而且 `target` 落在这个有序范围内，那么答案只能在这一半
- 如果 `target` 不落在这个有序范围内，那么它一定不在这一半

因此每一轮都能明确排除掉一半区间。

这就是 `O(log n)` 能成立的根本原因。

---

### 用例推演

以：

```text
nums = [4, 5, 6, 7, 0, 1, 2]
target = 0
```

为例。

开始时：

```text
left = 0
right = 6
mid = 3
nums[mid] = 7
```

先看左半边：

```text
nums[left] = 4
nums[mid] = 7
```

因为：

```text
4 <= 7
```

说明左半边 `[4, 5, 6, 7]` 有序。

再看 `target = 0` 是否在这个区间里：

```text
4 <= 0 < 7
```

不成立，所以答案不在左边，只能去右边：

```python
left = mid + 1
```

此时：

```text
left = 4
right = 6
mid = 5
nums[mid] = 1
```

再看左半边：

```text
nums[left] = 0
nums[mid] = 1
```

因为：

```text
0 <= 1
```

说明左半边 `[0, 1]` 有序。

这次 `target = 0` 落在这个区间里，所以：

```python
right = mid - 1
```

于是缩成：

```text
left = 4
right = 4
```

最后就能找到：

```text
nums[4] = 0
```

返回 `4`。

---

### 和前面几道边界二分的区别

`q35`、`q34`、`q69` 这类题，本质上更像在找：

```text
某个边界位置
```

所以思考方式通常是：

```text
mid 是否满足某种单调条件
```

但 `q33` 不一样。

它不是在找上下界，而是在一个“局部有序、整体被旋转”的数组里定位目标值。

因此这里的关键不是：

```text
第一个合法位置 / 最后一个合法位置
```

而是：

```text
哪一半有序，target 是否在这一半里
```

这个判断方式和普通边界二分是两条不同的思路。

---

### 复杂度

- 时间复杂度：`O(log n)`
- 空间复杂度：`O(1)`

---

## 为什么这是最适合面试的写法

因为它同时满足三点：

1. 明确利用了旋转数组的结构特征
2. 推理过程稳定，不需要背很怪的技巧
3. 代码长度适中，边界也比较自然

面试里可以直接这样解释：

```text
虽然数组整体不是升序的，但每次以 mid 切开后，至少有一半是有序的。
我先判断哪一半有序，再判断 target 是否落在这段有序区间里，
从而决定下一轮去左边还是右边。
```

---

## 最终建议

这题最值得记住的不是整段代码，而是这两层判断：

```text
先判断哪一半有序
再判断 target 是否落在这段有序区间里
```

最核心的代码骨架就是：

```python
if nums[left] <= nums[mid]:
    if nums[left] <= target < nums[mid]:
        right = mid - 1
    else:
        left = mid + 1
else:
    if nums[mid] < target <= nums[right]:
        left = mid + 1
    else:
        right = mid - 1
```

把这段判断真正理解了，这题基本就稳了。
