# LeetCode 875. 爱吃香蕉的珂珂 解析

## 题目描述

有一只叫珂珂的猴子，要在 `h` 小时内吃完所有香蕉。

给你一个数组 `piles`，`piles[i]` 表示第 `i` 堆香蕉有多少根。

珂珂每小时会选择一堆香蕉，然后吃掉最多 `k` 根：

- 如果这一堆少于 `k` 根，就把这一堆全部吃完
- 这一小时不能再去吃别的堆

请你返回：

```text
为了在 h 小时内吃完所有香蕉，最小的吃香蕉速度 k 是多少
```

例如：

```text
piles = [3, 6, 7, 11], h = 8
```

答案是：

```text
4
```

因为：

- 速度 `k = 4` 时，总共需要 `1 + 2 + 2 + 3 = 8` 小时
- 速度 `k = 3` 时，总共需要 `1 + 2 + 3 + 4 = 10` 小时，不够

---

## 先理解题意

这题表面上看是在问：

```text
吃香蕉的速度是多少
```

但本质上是在问：

```text
有没有一个最小的速度，使得总耗时 <= h
```

关键点有两个：

### 1. 固定一个速度后，总耗时是可以算出来的

如果速度是 `k`，那么一堆 `pile` 需要的小时数就是：

```python
ceil(pile / k)
```

为了避免 `ceil`，面试里更常写成：

```python
(pile + k - 1) // k
```

比如：

```text
pile = 7, k = 3
```

需要的小时数是：

```text
(7 + 3 - 1) // 3 = 3
```

因为 7 根香蕉不可能 2 小时吃完，必须 3 小时。

---

### 2. 这个问题有单调性

如果速度变快，总耗时只会：

- 变小
- 或者不变

不会变大。

也就是说：

- 某个速度 `k` 不行
- 那么比它更小的速度也都不行

反过来：

- 某个速度 `k` 可以
- 那么比它更大的速度也都可以

这就形成了很典型的结构：

```text
前面一段都不合法，后面一段都合法
```

所以这题适合做：

```text
找第一个合法答案
```

也就是标准的二分答案。

---

## 方法一：线性枚举速度

### 思路

最直接的方法是从速度 `1` 开始，一直试到 `max(piles)`：

- 如果当前速度能在 `h` 小时内吃完
- 这就是最小合法速度，直接返回

---

### 为什么可行

最小速度不可能小于 `1`，也不可能大于 `max(piles)`：

- 小于 `1` 没意义
- 如果速度等于 `max(piles)`，每堆最多一小时，已经足够快

所以直接把所有可能速度试一遍，一定能找到答案。

---

### 复杂度

- 时间复杂度：`O(n * max(piles))`
- 空间复杂度：`O(1)`

这里 `n` 是香蕉堆数。

---

### 这个方法差在哪里

它虽然容易想到，但太慢了。

因为 `max(piles)` 可能很大，如果一档一档试速度，很多计算都是浪费的。

既然“能否在 `h` 小时内吃完”有单调性，我们就没必要从头试到尾，可以直接二分答案。

---

## 方法二：二分答案（面试主推）

这是最适合面试的方法。

它的核心不是在数组里找数，而是在答案空间里找：

```text
第一个合法速度
```

这题你也可以把它理解成：

```text
对区间 [1, max(piles)] 做 q35 那种 lower_bound
```

只是这里判断“是否合法”的依据，不再是数组元素比较，而是：

```python
hours_needed(speed) <= h
```

---

### 二分的搜索空间是什么

速度 `k` 的范围是：

```text
[1, max(piles)]
```

因为：

- 最慢就是每小时吃 1 根
- 最快没有必要超过最大那堆的香蕉数

---

### 如何判断一个速度是否合法

定义：

```python
hours_needed(speed)
```

表示速度为 `speed` 时，吃完全部香蕉需要多少小时。

具体做法是把每一堆的耗时加起来：

```python
total += (pile + speed - 1) // speed
```

如果最终：

```python
total <= h
```

说明这个速度合法，可以在规定时间内吃完。

---

### 为什么可以二分

因为合法性是单调的：

- 速度小的时候，不合法
- 速度越来越大后，会进入合法区间
- 再往后也一直合法

所以答案就是：

```text
第一个让 total <= h 成立的速度
```

---

### 代码怎么收缩区间

设：

```python
left = 1
right = max(piles)
```

每次取：

```python
mid = (left + right) // 2
```

如果 `mid` 合法，说明答案可能就是 `mid`，也可能在更左边，所以：

```python
right = mid - 1
```

如果 `mid` 不合法，说明答案一定在右边，所以：

```python
left = mid + 1
```

循环结束后，`left` 就会停在：

```text
第一个合法速度
```

这和 `q35` 的“找第一个 `>= target` 的位置”本质是同一种思路。

---

### 为什么最后返回 `left`

这里用的是闭区间写法：

```python
while left <= right:
```

当循环结束时，区间里所有“不合法速度”都被排到左边，所有“合法速度”都在右边。

此时：

```text
left = right + 1
```

并且：

- `right` 停在最后一个不合法速度
- `left` 停在第一个合法速度

所以答案应该返回：

```python
left
```

---

## 方法对比

### 方法一：线性枚举

- 优点：最直观，容易理解
- 缺点：太慢，没有利用单调性

### 方法二：二分答案

- 优点：时间复杂度更优，思路清楚，面试高频
- 缺点：需要先意识到“答案具有单调性”

---

## 最适合面试的方法

最适合面试的是：

```text
方法二：二分答案
```

原因有三个：

1. 这题最核心的考点就是看你能不能识别出“单调性”
2. 写法本质上就是“找第一个合法答案”，非常标准
3. 代码不长，边界也稳定，容易在面试里一次写对

---

## 面试里建议怎么解释

可以按这个顺序说：

1. 先固定一个速度 `k`，那么总耗时可以算出来
2. 速度越快，总耗时越小，所以合法性具有单调性
3. 因此答案空间 `[1, max(piles)]` 可以二分
4. 我们要找的是“第一个使总耗时 `<= h` 的速度”
5. 所以二分时：
   - 合法就继续往左找
   - 不合法就往右找

如果你把这题和前面的二分题联系起来，也可以直接说：

```text
这题不是在数组里二分，而是在答案空间里做 q35 型的 lower_bound
```

这句话通常会让面试官立刻知道你理解得很清楚。
