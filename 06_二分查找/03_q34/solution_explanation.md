# LeetCode 34. 在排序数组中查找元素的第一个和最后一个位置解析

## 题目描述

给定一个按非递减顺序排列的整数数组 `nums`，和一个目标值 `target`。

要求返回 `target` 在数组中第一次出现的位置和最后一次出现的位置。

如果数组里不存在 `target`，返回：

```text
[-1, -1]
```

例如：

```text
nums = [5, 7, 7, 8, 8, 10], target = 8
```

答案是：

```text
[3, 4]
```

因为 `8` 从下标 `3` 开始，到下标 `4` 结束。

---

## 先理解题意

这题表面是在找一个数出现的位置范围。

但如果换个角度，会更适合用二分：

```text
左边界 = 第一个大于等于 target 的位置
右边界 = 最后一个小于等于 target 的位置
```

为什么这样想更自然？

因为数组有序，所以相同的 `target` 一定会连成一段。

只要我们能找到：

- 这段区间从哪里开始
- 这段区间在什么地方结束

整个答案就出来了。

例如：

```text
nums = [5, 7, 7, 8, 8, 10], target = 8
```

- 第一个 `>= 8` 的位置是 `3`
- 最后一个 `<= 8` 的位置是 `4`

所以：

```text
左边界 = 3
右边界 = 4
```

---

## 方法一：线性扫描

### 思路

最直接的方法就是从左到右扫一遍数组。

扫描过程中：

1. 第一次遇到 `target` 时，记录左边界
2. 后面每次再遇到 `target`，持续更新右边界

扫完以后：

- 如果从来没遇到过 `target`，返回 `[-1, -1]`
- 否则返回记录下来的左右边界

---

### 为什么可行

因为线性扫描不会漏掉任何元素。

第一次遇到 `target` 的位置，一定就是最左边界；最后一次遇到 `target` 的位置，一定就是最右边界。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 这个方法差在哪里

它当然正确，但没有利用“数组有序”这个关键信息。

既然数组已经排好序，就没必要把每个元素都看一遍。我们完全可以用二分更快地缩小范围。

---

## 方法二：二分查找（面试主推）

这是最适合面试的方法。

---

### 核心想法

这题最稳的写法不是“直接找目标值”，而是把问题拆成两个边界问题：

1. 找第一个 `>= target` 的位置
2. 找最后一个 `<= target` 的位置

然后：

```text
left_bound = 第一个 >= target 的位置
right_bound = 最后一个 <= target 的位置
```

这样写的好处是：

- 逻辑统一
- 边界清楚
- 不需要在遇到 `target` 时写很多特殊分支

---

### 第一次二分：找第一个 `>= target` 的位置

设：

```text
left = 0
right = len(nums) - 1
```

每次取中点：

```text
mid = (left + right) // 2
```

如果：

```text
nums[mid] < target
```

说明 `mid` 和它左边都不可能是左边界，因为它们都太小了。

所以答案只能在右边：

```python
left = mid + 1
```

否则说明：

```text
nums[mid] >= target
```

`mid` 有可能就是答案，但也可能左边还有更早的位置满足条件，所以继续向左收缩：

```python
right = mid - 1
```

循环结束后，`left` 就会停在：

```text
第一个 >= target 的位置
```

---

### 第二次二分：找最后一个 `<= target` 的位置

第二次二分几乎一样，只是条件换成：

```text
nums[mid] <= target
```

如果满足这个条件，说明 `mid` 是一个合法的右边界候选，但还不一定是最右边那个，所以继续向右：

```python
left = mid + 1
```

否则说明：

```text
nums[mid] > target
```

这时 `mid` 太大了，不可能落在右边界里，所以向左收缩：

```python
right = mid - 1
```

循环结束后，`right` 就会停在：

```text
最后一个 <= target 的位置
```

---

### 为什么要先判断 `target` 是否存在

拿到左边界以后，还不能立刻返回答案。

因为数组里可能根本没有 `target`。

例如：

```text
nums = [5, 7, 7, 8, 8, 10], target = 6
```

此时“第一个 `>= 6` 的位置”会停在下标 `1`，但 `nums[1]` 是 `7`，不是 `6`。

所以要先判断：

```python
if left_bound == len(nums) or nums[left_bound] != target:
    return [-1, -1]
```

只有确认左边界位置上真的是 `target`，才能继续求右边界。

---

### 用例推演

以：

```text
nums = [5, 7, 7, 8, 8, 10], target = 8
```

为例。

第一次二分找第一个 `>= 8` 的位置，最后得到：

```text
left_bound = 3
```

第二次二分找最后一个 `<= 8` 的位置，最后得到：

```text
right_bound = 4
```

最终答案就是：

```text
[3, 4]
```

---

### 复杂度

- 时间复杂度：`O(log n)`
- 空间复杂度：`O(1)`

---

## 为什么这是最适合面试的写法

因为它满足面试里最重要的几个要求：

1. 利用了有序数组这个核心条件
2. 两次二分的逻辑高度统一，不容易写乱
3. 边界意义明确，比较容易口头解释
4. 即使数组为空、目标不存在、目标出现在开头或结尾，都能自然处理

面试里可以直接这样概括：

```text
我先用二分找第一个大于等于 target 的位置，确定左边界；
再用二分找最后一个小于等于 target 的位置，确定右边界。
如果左边界越界，或者那个位置不是 target，说明目标不存在。
```

---

## 最终建议

这题建议按下面顺序掌握：

1. 先理解线性扫描为什么一定对
2. 再理解为什么有序数组更适合二分
3. 最后记住这道题真正要找的是两个边界，而不是“某一个 target”

最推荐记住的结论是：

```text
左边界 = 第一个 >= target 的位置
右边界 = 最后一个 <= target 的位置
```

这比死记某个模板更稳定，也更容易迁移到其他边界二分题。
