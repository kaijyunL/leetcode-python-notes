# LeetCode 154. 寻找旋转排序数组中的最小值 II 解析

## 题目描述

给定一个经过旋转的升序数组 `nums`，请你返回其中的最小值。

和 `q153` 的区别是：

```text
这题允许重复元素
```

例如：

```text
nums = [2, 2, 2, 0, 1]
```

答案是：

```text
0
```

---

## 先理解题意

这题和 `q153` 是同一类问题：

- 原数组本来是升序的
- 经过一次旋转后，数组被分成了两段递增区间
- 最小值就是旋转断点位置的那个数

例如：

```text
[3, 4, 5, 1, 2]
```

最小值就是：

```text
1
```

如果没有重复元素，我们可以像 `q153` 一样比较干净地二分。

但这题多了重复元素后，会出现一种麻烦情况：

```text
nums[mid] 和 nums[right] 相等
```

这时你没法像 `q153` 那样立刻判断最小值在左边还是右边。

所以这题的关键不是重新发明一套全新二分，而是：

```text
在 q153 的基础上，额外处理“重复元素让判断失效”的情况
```

---

## 方法一：线性扫描

### 思路

最直接的方法就是从左到右遍历整个数组，维护当前见过的最小值。

遍历结束后返回它。

---

### 为什么可行

因为它看了每个元素一次，所以全局最小值一定不会漏掉。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 这个方法差在哪里

它当然正确，但没有利用旋转数组的结构信息。

这题真正值得掌握的是：

```text
虽然有重复元素，
但多数情况下仍然能通过 nums[mid] 和 nums[right] 的关系缩小区间
```

所以可以继续考虑二分。

---

## 方法二：二分查找（面试主推）

这是最适合面试的方法。

虽然它在最坏情况下会退化到 `O(n)`，但思路自然、代码短、边界也比较稳。

---

### 核心想法

每一轮都比较：

```python
nums[mid] 和 nums[right]
```

这里继续拿 `right` 当参照物，是因为它始终属于当前搜索区间，能帮助我们判断：

```text
mid 更像落在左边那段较大的区间，
还是右边那段较小的区间
```

---

### 情况一：`nums[mid] > nums[right]`

如果：

```python
nums[mid] > nums[right]
```

说明 `mid` 落在左边那段较大的区间里。

例如：

```text
nums = [4, 5, 6, 7, 0, 1, 2, 4]
mid 指到 7
right 指到 4
```

这里：

```text
7 > 4
```

说明最小值一定在 `mid` 右边，所以可以写：

```python
left = mid + 1
```

因为 `nums[mid]` 明显不是最小值，所以 `mid` 可以直接丢掉。

---

### 情况二：`nums[mid] < nums[right]`

如果：

```python
nums[mid] < nums[right]
```

说明从 `mid` 到 `right` 这一段是有序的，而且 `mid` 已经落在右边那段较小区间里。

这时最小值有两种可能：

1. 就是 `mid`
2. 在 `mid` 左边

所以这里不能写：

```python
right = mid - 1
```

而要写：

```python
right = mid
```

原因是：

```text
mid 本身可能就是最小值
```

---

### 情况三：`nums[mid] == nums[right]`

这就是和 `q153` 最大的区别。

如果：

```python
nums[mid] == nums[right]
```

我们就没法判断最小值到底在左边还是右边。

例如：

```text
nums = [10, 1, 10, 10, 10]
left = 0
right = 4
mid = 2
nums[mid] = 10
nums[right] = 10
```

这时候你无法根据大小关系判断方向。

但可以安全地写：

```python
right -= 1
```

---

### 为什么 `right -= 1` 是安全的

这里很多人最担心的是：

```text
把 right 丢掉，会不会把最小值删掉？
```

答案是不会。

因为现在：

```python
nums[mid] == nums[right]
```

这说明：

- 如果 `nums[right]` 不是最小值，丢掉它当然没问题
- 如果 `nums[right]` 是最小值，那么 `nums[mid]` 和它一样小，答案在区间里仍然还保留着一份

所以这一轮虽然无法判断方向，但可以去掉一个“重复且不提供额外信息”的右端点。

这一步也正是最坏时间复杂度会退化到 `O(n)` 的原因：

```text
如果大量元素都相等，
有时每一轮只能把 right 往左缩 1 格
```

---

### 为什么循环条件是 `left < right`

这题维护的是一个闭区间：

```text
[left, right]
```

并且始终保证：

```text
最小值一定在这个区间里
```

所以目标不是把区间查空，而是不断收缩，直到只剩一个位置。

当：

```text
left == right
```

时，这个位置就是最小值所在位置。

因此循环条件写：

```python
while left < right
```

最后返回：

```python
nums[left]
```

---

### 用例推演

以：

```text
nums = [2, 2, 2, 0, 1]
```

为例。

初始时：

```text
left = 0
right = 4
mid = 2
nums[mid] = 2
nums[right] = 1
```

因为：

```text
2 > 1
```

说明最小值在右边，所以：

```python
left = mid + 1
```

搜索区间缩成下标范围：

```text
[3, 4]
```

接着：

```text
left = 3
right = 4
mid = 3
nums[mid] = 0
nums[right] = 1
```

因为：

```text
0 < 1
```

说明最小值可能就是 `mid`，或者还在它左边。但当前区间里 `mid` 已经是最左端，所以直接：

```python
right = mid
```

最后：

```text
left = right = 3
```

返回：

```text
nums[3] = 0
```

---

### 为什么不能照搬某些固定 `nums[-1]` 的写法

有些同学在 `q153` 里会写：

```python
if nums[mid] > nums[-1]:
    left = mid + 1
else:
    right = mid - 1
```

这个思路在无重复元素时还能成立，但到这题会出问题。

例如：

```text
nums = [2, 2, 2, 0, 1, 2]
nums[-1] = 2
```

如果你判断：

```python
nums[i] > nums[-1]
```

会得到：

```text
False False False False False False
```

它已经失去了“前半段大、后半段小”的分界效果。

所以这题更稳的写法不是拿固定的 `nums[-1]` 当参照，而是：

```text
每一轮都拿当前区间的 nums[right] 做动态比较
```

---

## 面试里为什么主推方法二

面试里最推荐你写方法二。

原因有三点：

1. 它明显利用了题目的旋转数组结构，比线性扫描更有针对性
2. 代码量不大，三种分支都很自然，现场比较容易复现
3. 即使面试官追问重复元素为什么会退化，你也能顺着 `nums[mid] == nums[right]` 这一支解释清楚

你可以把核心思路概括成一句话：

```text
我仍然比较 nums[mid] 和 nums[right] 来判断最小值方向；
如果两者相等，说明方向信息丢失，就安全地缩掉一个 right。
```

---

## 复杂度对比

### 方法一：线性扫描

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

### 方法二：二分查找

- 平均时间复杂度：`O(log n)`
- 最坏时间复杂度：`O(n)`
- 空间复杂度：`O(1)`
