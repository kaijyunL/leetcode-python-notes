# LeetCode 153. 寻找旋转排序数组中的最小值解析

## 题目描述

给定一个原本按升序排列的数组 `nums`，它在某个未知位置发生了一次旋转。

例如：

```text
[0, 1, 2, 4, 5, 6, 7]
```

可能会变成：

```text
[4, 5, 6, 7, 0, 1, 2]
```

现在要求你返回数组中的最小值。

题目保证：

```text
数组中的元素互不相同
```

---

## 先理解题意

这题和 `q33` 很像，都是旋转数组。

但目标不一样：

- `q33` 是找某个具体的 `target`
- `q153` 是找整个数组里最小的那个值

因为原数组本来是升序的，所以最小值其实就是：

```text
旋转点所在的位置
```

也可以理解成：

```text
第一段较大的递增区间结束后，第二段较小的递增区间开头的那个数
```

例如：

```text
[4, 5, 6, 7, 0, 1, 2]
```

这里最小值就是：

```text
0
```

它正好是旋转后的断点位置。

---

## 方法一：线性扫描

### 思路

最直接的方法就是从左到右扫描整个数组，维护当前见过的最小值。

遍历结束后，返回这个最小值。

---

### 为什么可行

因为线性扫描会看完每个元素，所以全局最小值一定不会漏掉。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 这个方法差在哪里

它当然正确，但没有利用旋转数组的结构信息。

这题真正的优化点在于：

```text
虽然整体不是完全升序，
但可以通过 nums[mid] 和 nums[right] 的关系判断最小值在哪一边
```

所以可以继续用二分。

---

## 方法二：二分查找（面试主推）

这是最适合面试的方法。

---

### 核心想法

每一轮都比较：

```python
nums[mid] 和 nums[right]
```

为什么和 `nums[right]` 比较最自然？

因为 `right` 始终在当前搜索区间里，它是一个动态参照物，能直接告诉我们：

```text
mid 落在左边那段较大的区间，还是右边那段较小的区间
```

---

### 情况一：`nums[mid] > nums[right]`

如果：

```python
nums[mid] > nums[right]
```

说明 `mid` 落在旋转点左边那段较大的递增区间里。

例如：

```text
nums = [4, 5, 6, 7, 0, 1, 2]
mid 指到 7
right 指到 2
```

这里：

```text
7 > 2
```

说明最小值不可能在 `mid` 左边这段较大的区间里停住，真正的最小值一定在 `mid` 右边。

因此可以直接写：

```python
left = mid + 1
```

这里能排除 `mid`，因为 `nums[mid]` 明显不是最小值。

---

### 情况二：`nums[mid] <= nums[right]`

如果：

```python
nums[mid] <= nums[right]
```

说明从 `mid` 到 `right` 这一段是有序的，而且 `mid` 落在右边那段较小的区间里。

这时最小值有两种可能：

1. 就是 `mid`
2. 在 `mid` 左边

因此这里不能把 `mid` 丢掉，应该写：

```python
right = mid
```

而不能写成：

```python
right = mid - 1
```

因为 `mid` 本身可能就是最小值。

---

### 为什么循环条件是 `left < right`

这题的主推写法和 `q35`、`q69` 那类边界题不完全一样。

它维护的是一个闭区间：

```text
[left, right]
```

并且保证：

```text
最小值一定在这个区间里
```

每一轮都把区间缩小，但不会把答案误删掉。

所以目标不是“把区间查空”，而是：

```text
把区间收缩到只剩一个点
```

当：

```text
left == right
```

时，这个位置就是最小值所在位置。

因此循环条件写成：

```python
while left < right
```

最后返回：

```python
nums[left]
```

或者 `nums[right]` 也一样，因为结束时两者相等。

这也是为什么它虽然写 `left < right`，但本质上不是半开区间模板。

---

### 为什么没有旋转也成立

例如：

```text
nums = [11, 13, 15, 17]
```

第一次：

```text
left = 0
right = 3
mid = 1
nums[mid] = 13
nums[right] = 17
```

因为：

```text
13 <= 17
```

说明从 `mid` 到 `right` 有序，最小值可能是 `mid`，也可能还在左边。

所以：

```python
right = mid
```

继续缩小后，最终会收敛到下标 `0`，返回：

```text
11
```

所以“没有旋转”只是这题的一个特殊情况，这套逻辑依然成立。

---

### 用例推演

以：

```text
nums = [4, 5, 6, 7, 0, 1, 2]
```

为例。

开始时：

```text
left = 0
right = 6
mid = 3
nums[mid] = 7
nums[right] = 2
```

因为：

```text
7 > 2
```

说明最小值一定在右边，所以：

```python
left = mid + 1
```

区间变成：

```text
[4, 6]
```

这时：

```text
mid = 5
nums[mid] = 1
nums[right] = 2
```

因为：

```text
1 <= 2
```

说明最小值在左边或就是 `mid`，所以：

```python
right = mid
```

区间变成：

```text
[4, 5]
```

再比较一次：

```text
mid = 4
nums[mid] = 0
nums[right] = 1
```

因为：

```text
0 <= 1
```

所以：

```python
right = mid
```

最后收敛到：

```text
left = right = 4
```

返回：

```text
nums[4] = 0
```

---

### 和边界二分的关系

这题主推写法是“单点收敛型”二分。

但它也可以从边界角度理解：

如果用 `nums[-1]` 当参照，那么数组会被分成两段：

```text
nums[i] > nums[-1]    -> 左边那段较大的数
nums[i] <= nums[-1]   -> 右边那段较小的数
```

例如：

```text
nums = [4, 5, 6, 7, 0, 1, 2]
nums[-1] = 2
```

对应判断结果是：

```text
T T T T F F F
```

那么最小值位置其实就是：

```text
第一个满足 nums[i] <= nums[-1] 的位置
```

也就是第一个 `False` 的位置。

所以这题和 `q35` 的边界思维其实也能连起来，只是面试里更推荐直接用 `nums[mid]` 和 `nums[right]` 做收敛写法，更短，也更自然。

---

### 复杂度

- 时间复杂度：`O(log n)`
- 空间复杂度：`O(1)`

---

## 为什么这是最适合面试的写法

因为它有几个优点：

1. 只用一个简单比较就能决定收缩方向
2. 代码短，边界清楚
3. 比“固定拿 `nums[-1]` 做边界模板”更自然

面试里可以直接这样解释：

```text
我每次比较 nums[mid] 和 nums[right]。
如果 nums[mid] > nums[right]，说明 mid 在左边大区间里，最小值一定在右边；
否则说明 mid 落在右边小区间里，最小值在左边或者就是 mid。
这样不断收缩，直到 left == right。
```

---

## 最终建议

这题最值得记住的核心代码是：

```python
if nums[mid] > nums[right]:
    left = mid + 1
else:
    right = mid
```

以及它背后的两句话：

```text
nums[mid] > nums[right]  -> 最小值在右边
nums[mid] <= nums[right] -> 最小值在左边或就是 mid
```

把这两句真正理解了，这题就不会乱。
