# LeetCode 162. 寻找峰值解析

## 题目描述

给定一个整数数组 `nums`，请你找到任意一个峰值元素，并返回它的下标。

峰值元素指的是严格大于左右相邻元素的元素。

题目额外规定：

```text
nums[-1] = -inf
nums[n] = -inf
```

也就是说，数组两端外面都可以看成负无穷。

例如：

```text
nums = [1, 2, 3, 1]
```

答案可以返回：

```text
2
```

因为 `nums[2] = 3`，它比左右两边都大。

---

## 先理解题意

这题有两个很关键的点：

1. 题目要的是“任意一个峰值”，不是固定找最左峰值或最右峰值
2. 两边外侧都视为 `-inf`，所以峰值一定存在

为什么峰值一定存在？

因为数组要么：

- 中间某个位置先上升后下降，那转折点就是峰值
- 一路上升到末尾，那最后一个元素右边是 `-inf`，所以末尾就是峰值
- 一路下降到开头，那第一个元素左边是 `-inf`，所以开头就是峰值

所以这题不是“有没有峰值”的问题，而是“怎么更快找到一个峰值”。

---

## 方法一：线性扫描

### 思路

最直接的做法是从左到右扫描，找第一个下降点。

也就是找到第一个满足：

```text
nums[i] > nums[i + 1]
```

的位置。

一旦出现这种情况，`i` 就是一个峰值。

如果一直都没有下降，说明整个数组单调上升，那么最后一个位置就是峰值。

---

### 为什么可行

如果扫描过程中第一次出现：

```text
nums[i] > nums[i + 1]
```

那说明在 `i` 这里开始下坡了。

而在它之前如果一直没有下降，说明从左往右是一路爬上来的，所以 `nums[i]` 一定高于左边，也高于右边，于是它就是峰值。

如果始终没出现下降，说明数组一直在上升，那最后一个元素右边又是 `-inf`，因此最后一个元素就是峰值。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 这个方法差在哪里

它当然正确，但没有利用局部坡度信息把搜索范围快速缩小。

这题最有价值的优化点是：

```text
只比较 nums[mid] 和 nums[mid + 1]，
就能判断哪一侧一定存在峰值
```

这正是二分能成立的原因。

---

## 方法二：二分查找（面试主推）

这是最适合面试的方法。

---

### 核心想法

这题不是 `q35`、`q69` 那种“找上下界”的边界二分。

它更像是：

```text
通过 mid 位置的坡度，判断哪一边一定存在峰值
```

每次只看：

```text
nums[mid] 和 nums[mid + 1]
```

就够了。

---

### 为什么比较 `nums[mid]` 和 `nums[mid + 1]`

如果：

```text
nums[mid] < nums[mid + 1]
```

说明从 `mid` 到 `mid + 1` 是上坡。

既然右边在上升，那么右半边一定能找到峰值。

为什么一定有？

- 如果右边后面某处开始下降，那么下降前那个位置就是峰值
- 如果右边一路升到区间末尾，那么最右端也会因为外侧是 `-inf` 而成为峰值

所以这种情况下可以放心丢掉左半边：

```python
left = mid + 1
```

---

如果：

```text
nums[mid] > nums[mid + 1]
```

说明从 `mid` 到 `mid + 1` 是下坡。

这时候峰值一定在左半边，而且 `mid` 自己也可能就是峰值。

所以这里不能写：

```python
right = mid - 1
```

因为那样会把 `mid` 直接丢掉。

正确写法是：

```python
right = mid
```

把 `mid` 留在下一轮继续判断。

---

### 为什么这里用 `while left < right`

这题的写法和前面几道边界题不一样。

它维护的是一个闭区间：

```text
[left, right]
```

并且保证：

```text
这个区间里一定存在峰值
```

每次根据坡度，把区间缩到左半边或右半边，但都会保留那个“一定还有峰值”的部分。

所以这题不是：

```text
找第一个合法位置
找最后一个合法位置
```

而是：

```text
不断缩小范围，直到区间只剩一个点
```

循环结束条件是：

```text
left == right
```

这时这个位置就是某个峰值。

因此最后返回：

```python
left
```

或者返回 `right` 也一样，因为这时两者相等。

---

### 为什么 `mid + 1` 不会越界

这题里我们会访问：

```python
nums[mid + 1]
```

之所以安全，是因为循环条件是：

```python
while left < right:
```

只要 `left < right`，就一定有：

```text
mid < right
```

因此：

```text
mid + 1 <= right
```

所以 `mid + 1` 始终在有效范围内。

这个细节在面试里很值得顺手说一下。

---

### 用例推演

以：

```text
nums = [1, 2, 3, 1]
```

为例。

开始时：

```text
left = 0
right = 3
```

第一次：

```text
mid = 1
nums[1] = 2
nums[2] = 3
```

因为：

```text
2 < 3
```

说明右边是上坡，右侧一定有峰值：

```python
left = mid + 1
```

变成：

```text
left = 2
right = 3
```

第二次：

```text
mid = 2
nums[2] = 3
nums[3] = 1
```

因为：

```text
3 > 1
```

说明左侧包含 `mid` 一定有峰值：

```python
right = mid
```

变成：

```text
left = 2
right = 2
```

循环结束，返回 `2`。

---

### 复杂度

- 时间复杂度：`O(log n)`
- 空间复杂度：`O(1)`

---

## 为什么这是最适合面试的写法

因为它同时满足几件事：

1. 明确利用了题目的结构信息，而不是硬扫一遍
2. 证明链条比较短，只要说明“上坡一侧一定有峰值，下坡一侧也一定保留峰值”
3. 代码短，而且不需要维护额外状态

面试里可以直接这样概括：

```text
我每次比较 nums[mid] 和 nums[mid + 1]。
如果右边更大，说明右侧还在上坡，右边一定存在峰值；
如果左边更大，说明左侧包含 mid 一定存在峰值。
这样每次都能把区间缩小一半，直到 left == right。
```

---

## 最终建议

这题最值得记住的不是某个固定模板名，而是这个判断：

```text
nums[mid] < nums[mid + 1]  -> 峰值在右边
nums[mid] > nums[mid + 1]  -> 峰值在左边或就是 mid
```

再配上这句代码：

```python
if nums[mid] < nums[mid + 1]:
    left = mid + 1
else:
    right = mid
```

基本就能把这题稳稳写出来。
