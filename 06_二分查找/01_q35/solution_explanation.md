# LeetCode 35. 搜索插入位置解析

## 题目描述

给定一个升序排列的整数数组 `nums` 和一个目标值 `target`。

如果 `target` 在数组中，返回它的下标。

如果不在数组中，返回它按顺序应该插入的位置。

例如：

```text
nums = [1, 3, 5, 6], target = 5
```

答案是：

```text
2
```

再比如：

```text
nums = [1, 3, 5, 6], target = 2
```

答案是：

```text
1
```

因为 `2` 应该插入到 `1` 和 `3` 之间。

---

## 先理解题意

这题表面上看是在“找一个数”。

但更准确地说，它在找的是：

```text
target 应该落在哪个位置，才能让数组继续保持升序
```

所以答案有两种情况：

1. 如果数组里本来就有 `target`，返回它当前下标。
2. 如果没有，就返回第一个大于等于 `target` 的位置。

例如：

```text
nums = [1, 3, 5, 6], target = 7
```

因为所有数都比 `7` 小，所以应该插到最后，答案是：

```text
4
```

而：

```text
nums = [1, 3, 5, 6], target = 0
```

因为所有数都比 `0` 大，所以应该插到最前面，答案是：

```text
0
```

---

## 方法一：线性扫描

### 思路

最直接的做法就是从左到右扫描数组，找到第一个满足：

```text
nums[i] >= target
```

的位置。

这个位置就是答案。

因为：

- 如果 `nums[i] == target`，它本来就在这里
- 如果 `nums[i] > target`，那 `target` 就应该插在它前面

如果扫完整个数组都没有找到，说明：

```text
target 比所有元素都大
```

那就应该插到数组末尾，返回：

```text
len(nums)
```

---

### 为什么可行

因为数组是升序的。

所以一旦找到第一个 `>= target` 的位置，它一定就是最靠左、也就是最合适的插入位置。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 这个方法差在哪里

它当然正确，但没有利用“数组有序”这一点来加速。

既然数组已经升序，通常就应该想到：

```text
可以用二分查找把查找范围快速缩小
```

---

## 方法二：二分查找（面试主推）

这是最适合面试的写法。

---

### 核心想法

这题可以理解成在找：

```text
第一个大于等于 target 的位置
```

为什么这样想最自然？

因为：

- 如果这个位置上的值刚好等于 `target`，返回它
- 如果这个位置上的值大于 `target`，那 `target` 就应该插在这里

所以我们并不一定非要“找到 target 本身”，而是在找它应该落下来的最左位置。

---

### 二分过程怎么推进

设：

```text
left = 0
right = len(nums) - 1
```

每次取中点：

```text
mid = (left + right) // 2
```

然后看 `nums[mid]` 和 `target` 的关系。

如果：

```text
nums[mid] < target
```

说明：

```text
mid 以及它左边的位置都不可能是答案
```

因为这些位置上的值都太小了。

所以答案只能在右边：

```python
left = mid + 1
```

如果：

```text
nums[mid] >= target
```

说明：

```text
mid 有可能就是答案，但也可能左边还有更早的位置同样满足
```

所以应该继续往左边收缩：

```python
right = mid - 1
```

---

### 为什么最后返回 `left`

这是整题最关键的一点。

循环结束时：

```text
left > right
```

这时 `left` 会停在：

```text
第一个大于等于 target 的位置
```

所以直接返回 `left` 就是答案。

这也正好覆盖三种情况：

1. `target` 在数组中，`left` 最后停在它的位置。
2. `target` 不在数组中但中间可插入，`left` 停在第一个更大的元素位置。
3. `target` 比所有元素都大，`left` 最后会走到 `len(nums)`。

---

### 用例子走一遍

输入：

```text
nums = [1, 3, 5, 6], target = 2
```

开始：

```text
left = 0, right = 3
```

---

### 第一次

```text
mid = 1
nums[mid] = 3
```

因为：

```text
3 >= 2
```

说明答案在左边，或者就是 `mid`，所以：

```text
right = 0
```

---

### 第二次

```text
left = 0, right = 0
mid = 0
nums[mid] = 1
```

因为：

```text
1 < 2
```

说明 `0` 不可能是答案，所以：

```text
left = 1
```

此时：

```text
left = 1, right = 0
```

循环结束，返回 `left = 1`。

这正是正确答案。

---

## 为什么这是最适合面试的方法

原因很直接：

1. 复杂度更好：`O(log n)`。
2. 它真正利用了数组有序这个条件。
3. 这题非常适合训练“找第一个满足条件的位置”这种二分视角。

如果面试官问“你是怎么想到的”，可以按这条线讲：

```text
先从线性扫描出发
-> 发现本质上是在找第一个大于等于 target 的位置
-> 数组有序，所以可以二分
-> 小于 target 就去右边，大于等于 target 就继续压左边
-> 最后 left 停住的位置就是插入位置
```

---

## 方法对比

| 方法 | 思路 | 时间复杂度 | 空间复杂度 | 面试建议 |
|---|---|---:|---:|---|
| 方法一 | 线性扫描第一个 `>= target` 的位置 | `O(n)` | `O(1)` | 只适合理解 |
| 方法二 | 二分查找第一个 `>= target` 的位置 | `O(log n)` | `O(1)` | **面试主推** |

---

## 总结

这题最值得记住的不是“搜索插入位置”这几个字，而是下面这句话：

```text
本质上是在找第一个大于等于 target 的位置
```

真正理解了这一点，这题就会自然落成：

```text
小于 target 就去右边，大于等于 target 就继续压左边，最后返回 left
```

这就是本题的核心解法。
