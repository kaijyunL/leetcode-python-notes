# LeetCode 84. 柱状图中最大的矩形 (Largest Rectangle in Histogram)

## 题目

给定 `n` 个非负整数 `heights`，用来表示柱状图中各个柱子的高度。
每个柱子彼此相邻，且宽度为 `1`。

求在该柱状图中，能够勾勒出来的矩形的 **最大面积**。

比如：

```text
heights = [2, 1, 5, 6, 2, 3]
```

最大面积是：

```text
10
```

因为 `5` 和 `6` 这两根柱子可以一起撑出一个高度为 `5`、宽度为 `2` 的矩形：

```text
5 * 2 = 10
```

---

## 这题真正考的是什么

表面上看，这题是在问：

```text
能勾勒出的最大矩形面积是多少
```

但真正要识别出来的结构是：

```text
每一根柱子，作为矩形的高度时，它最多能往左右撑多宽
```

关键观察是：

```text
最大矩形的高度，一定等于某一根柱子的高度
```

因为如果某个矩形的高度不是任何一根柱子的高度，
你总能把它抬高到最近那根柱子的顶部，得到一个更大的矩形。

所以问题就变成：

```text
对每一根柱子 i，以 heights[i] 为高，它能撑出的最大宽度是多少
```

而撑宽的边界是：

```text
左边第一个比它矮的柱子 left
右边第一个比它矮的柱子 right
```

中间这一段都比它高，所以宽度就是：

```text
right - left - 1
```

面积就是：

```text
heights[i] * (right - left - 1)
```

这就把题目变成了一个标准的：

```text
找每个位置左右两侧第一个更小的元素
```

而这正是 **单调栈** 的经典信号。

---

## 为什么它是 739 的镜像

这题和 `739` 每日温度是同一套模板，只是方向反过来：

| | 739 每日温度 | 84 柱状图最大矩形 |
| --- | --- | --- |
| 找的是什么 | 右边第一个 **更大** | 左右两边第一个 **更小** |
| 栈维护什么 | 从栈底到栈顶 **递减** | 从栈底到栈顶 **递增 / 非递减** |
| 谁来结算 | 当前更大的元素结算栈顶 | 当前更小的元素结算栈顶 |
| 结算时机 | 当前 > 栈顶时 | 当前 < 栈顶时 |

一句话总结：

```text
739 是“来个更大的，结算前面更小的”
84 是“来个更小的，结算前面更大的”
```

所以只要 `739` 的模板吃透了，这题几乎就是把比较符号反过来。

---

## 方法一：枚举高度 + 中心扩散

### 核心思路

既然最大矩形的高度一定等于某根柱子的高度，
那就枚举每一根柱子 `i`，以 `heights[i]` 作为高：

- 向左扩散，找到第一个比 `heights[i]` 矮的位置 `left`
- 向右扩散，找到第一个比 `heights[i]` 矮的位置 `right`
- 宽度 `= right - left - 1`
- 面积 `= heights[i] * width`

取所有面积的最大值。

这是完全照着“以每根柱子为高”的定义来的，没有任何技巧。

---

### 例子

看：

```text
heights = [2, 1, 5, 6, 2, 3]
```

#### 第 2 根柱子：`5`

向左找第一个更矮的：

- 第 1 根是 `1`，比 `5` 矮，停

所以 `left = 1`。

向右找第一个更矮的：

- 第 3 根是 `6`，不够矮
- 第 4 根是 `2`，比 `5` 矮，停

所以 `right = 4`。

宽度：

```text
4 - 1 - 1 = 2
```

面积：

```text
5 * 2 = 10
```

#### 第 4 根柱子：`2`

向左：

- 第 3 根 `6` 不够矮
- 第 2 根 `5` 不够矮
- 第 1 根 `1` 更矮，停

`left = 1`。

向右：

- 第 5 根 `3` 不够矮
- 越界，停

`right = 6`（越界位置）。

宽度：

```text
6 - 1 - 1 = 4
```

面积：

```text
2 * 4 = 8
```

把所有柱子都算一遍，最大就是 `10`。

---

### 为什么它可行

因为它就是题目的定义：

```text
以每根柱子为高，撑到左右第一个更矮处
```

逻辑上一定正确，只是慢。

---

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

最坏情况下，比如高度严格递增，

每根柱子向左都要一路扫到开头。

---

### 评价

这是一个很适合建立题意直觉的保底做法。
它把“以每根柱子为高”这件事讲清楚了，
而单调栈要优化的，正是这里重复的左右扫描。

---

## 方法二：单调递增栈 + 哨兵（面试主推）

### 先用一句话说清栈在干什么

想象所有柱子 **从左往右排队**，每根柱子都想算出：

```text
以我为高度，最多能撑多宽的矩形
```

但它自己算不出来，因为它不知道右边什么时候会来一根比自己矮的柱子。

所以我们用一个栈，让柱子们 **排队等着**：
凡是还没等到“右边那根更矮的”的柱子，都待在栈里。

一旦新来一根柱子比栈顶矮，就说明：

```text
栈顶这根柱子的右边界终于到了
```

于是栈顶出列，开始算自己的面积。

这就是栈在这题里唯一的作用：

```text
存那些还没算完面积的柱子，等一根更矮的来结算它们
```

---

### 为什么栈要“从底到顶越来越高”

因为柱子是按从左到右的顺序进栈的。
如果每根进栈的柱子都比前一根高，栈就会自然形成一个 **越来越高的序列**。

为什么要保持这个顺序？

因为一旦来了一根 **矮** 的柱子，
它能结算的一定是 **从栈顶开始、所有比它高的柱子**：

- 栈顶最高，先被结算
- 一直弹到栈顶不比它高为止

这就保证了：**每根柱子被弹出来的那一刻，它的右边界就是当前这根矮柱子。**

---

### 左边界为什么不用另外找

柱子被弹出后，要算面积还需要 **左边界**（左边第一个比它矮的位置）。

关键点来了：

```text
弹出后的新栈顶，就是它的左边界
```

为什么？

因为栈是从底到顶越来越高的。
当前这根柱子被弹出后，剩下栈顶一定比它矮（否则它就不会被弹）。
而这个新栈顶的位置在它左边（因为它更早进栈）。

所以：

```text
左边界 = 弹出后的新栈顶
右边界 = 当前这根矮柱子
宽度 = 右 - 左 - 1
```

这就是单调栈最巧妙的地方：**左边界的存在是免费的，栈自己就存着。**

---

### 来个矮的，可能一口气结算多个

当前这根矮柱子，可能同时是好几根栈顶柱子的右边界。

比如栈里从底到顶是 `[2, 5, 6, 7]`，
这时来一根 `2`：

- `7` 比 `2` 高，弹出结算
- `6` 比 `2` 高，继续弹出结算
- `5` 比 `2` 高，继续弹出结算
- `2` 不比 `2` 高，停

所以结算必须用 `while`，不能只弹一次。

---

### 哨兵技巧

到这里，思路已经清楚了，但还有两个麻烦：

1. 栈空的时候没法算左边界
2. 遍历完了，栈里可能还剩柱子没结算

这两个麻烦可以用一个小技巧一次性解决：**在首尾各加一根高度为 0 的柱子。**

```text
heights = [0] + heights + [0]
```

#### 前面的 `0`：永远待在栈底当左边界

它比所有柱子都矮，所以永远不会被弹出，一直待在栈底。
这样任何柱子被弹出后，栈里至少还有这个 `0`，
左边界永远算得出来，不用单独判空。

#### 后面的 `0`：逼所有柱子出栈

它比所有柱子都矮，
所以遍历到最后时，它会一口气把栈里所有还没结算的柱子全弹出来。

不用再写一段循环来清栈了。

这就是哨兵的价值：**用两根假柱子，把边界处理全省掉。**

---

### 过程演示

看经典例子（已加哨兵）：

```text
heights = [0, 2, 1, 5, 6, 2, 3, 0]
下标     = [0, 1, 2, 3, 4, 5, 6, 7]
```

初始化：

```text
stack = []
max_area = 0
```

规则就一句话：**来的矮就结算栈顶，来的高就入栈等着。**

#### i = 0，高 `0`

栈空，入栈等着：

```text
stack = [0]
```

#### i = 1，高 `2`

`2` 比栈顶 `0` 高，不触发结算，入栈等着：

```text
stack = [0, 1]
```

#### i = 2，高 `1`

`1` 比栈顶（下标 `1`，高 `2`）矮，结算它：

- 弹出下标 `1`，高 `2`
- 左边界 = 新栈顶 `0`（那根高度 `0` 的哨兵）
- 宽度 = `2 - 0 - 1 = 1`
- 面积 = `2 * 1 = 2`

再看 `1` 不比新栈顶（高 `0`）矮，停。入栈：

```text
stack = [0, 2]
max_area = 2
```

#### i = 3，高 `5`

`5` 比栈顶（高 `1`）高，入栈等着：

```text
stack = [0, 2, 3]
```

#### i = 4，高 `6`

`6` 比栈顶（高 `5`）高，入栈等着：

```text
stack = [0, 2, 3, 4]
```

#### i = 5，高 `2`（关键一步）

`2` 比栈顶（下标 `4`，高 `6`）矮，结算 `6`：

- 弹出 `4`，高 `6`
- 左 = 新栈顶 `3`
- 宽 = `5 - 3 - 1 = 1`
- 面积 = `6 * 1 = 6`（一根 `6` 柱子只能撑宽 `1`）

`2` 还比新栈顶（下标 `3`，高 `5`）矮，继续结算 `5`：

- 弹出 `3`，高 `5`
- 左 = 新栈顶 `2`
- 宽 = `5 - 2 - 1 = 2`（`5` 和 `6` 一起撑，宽度 `2`）
- 面积 = `5 * 2 = 10`  ← 最大

`2` 不比新栈顶（高 `1`）矮，停。入栈：

```text
stack = [0, 2, 5]
max_area = 10
```

这一步最能体现栈的价值：`2` 来了，一口气结算了 `6` 和 `5`，
因为它们俩都在等"右边第一根更矮的"，而 `2` 正好就是。

#### i = 6，高 `3`

`3` 比栈顶（高 `2`）高，入栈等着：

```text
stack = [0, 2, 5, 6]
```

#### i = 7，高 `0`（尾部哨兵，清场）

`0` 比栈顶（下标 `6`，高 `3`）矮，结算 `3`：

- 弹出 `6`，高 `3`
- 左 = `5`
- 宽 = `7 - 5 - 1 = 1`
- 面积 = `3`

`0` 还比新栈顶（下标 `5`，高 `2`）矮，继续结算 `2`：

- 弹出 `5`，高 `2`
- 左 = `2`
- 宽 = `7 - 2 - 1 = 4`（这根 `2` 从下标 `3` 一直撑到 `6`）
- 面积 = `8`

`0` 还比新栈顶（下标 `2`，高 `1`）矮，继续结算 `1`：

- 弹出 `2`，高 `1`
- 左 = `0`
- 宽 = `7 - 0 - 1 = 6`（这根 `1` 矮，能撑满整个图）
- 面积 = `6`

`0` 不比新栈顶（高 `0`）矮，停。遍历结束。

尾部哨兵 `0` 就像一个"清场信号"，
把所有还在栈里等着的柱子一次性全结算了。最大面积仍是 `10`。

---

### 为什么这是面试主推

#### 1. 它直接复用 739 的模板

只要把 `739` 里：

```text
当前更大 → 结算栈顶（递减栈）
```

换成：

```text
当前更小 → 结算栈顶（递增栈）
```

就是这题的主流程。

#### 2. 它把重复扫描彻底消掉了

方法一里，同一个区间会被反复扫。

单调栈的关键是：

```text
每个下标只入栈一次，也只出栈一次
```

所以总操作数是线性的。

#### 3. 哨兵让代码非常干净

加两个 `0` 之后：

- 不用判空栈
- 不用遍历后再清栈
- 主循环就是纯粹的 `while + append`

这是这题最值得记的工程小技巧之一。

---

### 面试代码

```python
class Solution:
    def largestRectangleArea(self, heights: list[int]) -> int:
        heights = [0] + heights + [0]
        stack = []
        max_area = 0

        for i, h in enumerate(heights):
            while stack and h < heights[stack[-1]]:
                h_idx = stack.pop()
                height = heights[h_idx]
                width = i - stack[-1] - 1
                max_area = max(max_area, height * width)

            stack.append(i)

        return max_area
```

---

### 容易出错的地方

#### 1. 栈里要存下标，不要只存高度

因为算宽度需要两个下标相减：

```python
width = i - stack[-1] - 1
```

如果你只存高度，就没法算宽度。

#### 2. 这里用 `<`，等高柱子先不弹

触发结算的条件是当前柱子 **比栈顶矮**：

```python
while stack and h < heights[stack[-1]]:
```

注意是严格小于，不是小于等于。
也就是说，遇到等高柱子时，先不结算，让它进栈等着。

为什么这样不会漏？

比如 `[2, 2]`，等高时都进栈，
最后尾部哨兵 `0` 来了，从右往左依次结算：

- 先结算右边那个 `2`，宽度 `1`，面积 `2`
- 再结算左边那个 `2`，宽度 `2`，面积 `4`

最大值 `4` 不会丢，只是晚一点才算。

这和 `739` 正好相反，`739` 是找更高温，用 `>`。

#### 3. 必须是 `while`，不能写成 `if`

因为一根更矮的柱子可能一口气结算多个栈顶。

比如：

```text
[0, 5, 6, 7, 2, 0]
```

当读到 `2` 时，它会连续结算 `7`、`6`、`5`。

#### 4. 弹出后直接用新的栈顶当左边界

很多人会犯一个错：弹掉栈顶后，
去单独找一个“左边第一个更矮”的位置。

其实不用重新线性扫描，因为栈已经保留了左侧候选边界。

如果没有等高柱子，**弹出后的新栈顶就是左边第一个更矮的位置**。
如果有等高柱子，中间几次弹出的宽度可能偏窄，
但最左边那根等高柱子最终会拿到完整宽度，所以最大面积不会丢。

这就是单调栈能一次遍历算完的核心。

#### 5. 哨兵的两个 `0` 缺一不可

- 去掉前面的 `0`：弹出栈顶后栈可能空了，`stack[-1]` 会报错
- 去掉后面的 `0`：遍历结束后栈里会剩柱子没结算，结果可能偏小

---

### 复杂度

- 时间复杂度：`O(n)`，每个下标只进出栈一次
- 空间复杂度：`O(n)`，栈最多存 `n` 个下标

---

## 两种方法的关系

- **方法一**：按“以每根柱子为高”的定义，向左右扩散找边界，建立题意直觉
- **方法二**：把左右扩散优化成“一次遍历里用栈顺手算出边界”，正式进入单调栈模板

这题最值得记住的一句话是：

```text
最大矩形的高度一定等于某根柱子的高度；于是问题变成“找每根柱子左右第一个更矮的位置”，而这正是单调递增（非递减）栈的标准活
```

想通这一点，再对比 `739`，就会发现两题其实是同一个模板的两个方向。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：枚举高度 + 中心扩散 | `O(n^2)` | `O(1)` | 直观保底，建立“以柱为高”的直觉 |
| 方法二：单调递增栈 + 哨兵 | `O(n)` | `O(n)` | 面试主推，单调栈经典题 |
