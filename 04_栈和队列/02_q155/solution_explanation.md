# LeetCode 155. 最小栈

## 题目

设计一个支持以下操作的数据结构：

- `push(x)`：将元素 `x` 推入栈中
- `pop()`：删除栈顶元素
- `top()`：获取栈顶元素
- `getMin()`：获取栈中的最小元素

并要求这四个操作都尽量高效，其中题目最关键的要求是：

```text
getMin() 必须做到 O(1)
```

---

## 这题真正卡人的地方是什么

普通栈只负责：

- 从栈顶插入
- 从栈顶删除
- 查看栈顶

这些操作天然都是 `O(1)`。

但 `getMin()` 不一样。

如果你什么额外信息都不存，那你每次想知道最小值时，就只能：

```text
把整个栈扫一遍
```

这显然是 `O(n)`，不符合题目要求。

所以这题的关键不是“会不会写栈”，而是：

```text
你能不能在每次 push / pop 时，顺手把“当前最小值”也维护好
```

也就是说：

- 不是等到 `getMin()` 时再去算
- 而是在平时每一步操作里，就把最小值信息存下来

这就是这题的设计核心。

---

## 方法一：`getMin()` 时遍历整个栈

### 核心思路

最直接的做法就是：

- `push`、`pop`、`top` 都照普通栈来
- 只有 `getMin()` 时，调用一次 `min(self.stack)`

这当然能得到正确答案，但问题是：

```text
最小值不是提前维护的，而是临时现查的
```

---

### 例子

如果当前栈是：

```text
[5, 3, 7, 2, 8]
```

那：

- `top()` 直接看最后一个元素，得到 `8`
- `getMin()` 需要把 5 个元素全看一遍，才知道最小值是 `2`

所以 `getMin()` 变成了线性时间。

---

### 为什么不合题意

题目要求的是：

```text
getMin() = O(1)
```

而遍历栈显然做不到。

所以方法一只能算保底理解版，用来说明为什么我们必须额外存辅助信息。

---

### 复杂度

- `push`：`O(1)`
- `pop`：`O(1)`
- `top`：`O(1)`
- `getMin`：`O(n)`
- 额外空间复杂度：`O(1)`

---

## 方法二：栈里同时存 `(当前值, 当前最小值)`

### 核心思路

既然 `getMin()` 不能临时去算，那就改成：

```text
每次 push 时，把“这个元素入栈后，当前栈的最小值”也一起存进去
```

这样栈里每个位置都不再只存一个值，而是存一个二元组：

```text
(当前值, 到这个位置为止的最小值)
```

例如：

- 压入 `5` 后，存 `(5, 5)`
- 再压入 `3` 后，存 `(3, 3)`
- 再压入 `7` 后，存 `(7, 3)`
- 再压入 `2` 后，存 `(2, 2)`

这样栈顶的第二项，永远就是当前最小值。

---

### 过程演示

依次压入：

```text
5, 3, 7, 2
```

栈会变成：

```text
[(5, 5), (3, 3), (7, 3), (2, 2)]
```

这时：

- `top()` 看栈顶第一项，得到 `2`
- `getMin()` 看栈顶第二项，得到 `2`

如果此时 `pop()`，栈变成：

```text
[(5, 5), (3, 3), (7, 3)]
```

那新的 `getMin()` 直接又变回栈顶第二项 `3`。

你会发现：

```text
根本不需要重新扫描，因为最小值历史已经提前记在每一层里了
```

---

### 为什么可行

因为对于每一个新入栈元素 `x`：

- 如果它比之前最小值还小，那新的最小值就是 `x`
- 否则新的最小值仍然是之前那个最小值

所以当前层的最小值一定是：

```text
min(x, 之前那一层记录的最小值)
```

只要在 `push` 时把这个结果记下来，之后 `getMin()` 就能直接 `O(1)` 读取。

---

### 代码

```python
class MinStack:
    def __init__(self):
        self.stack = []

    def push(self, val: int) -> None:
        current_min = val if not self.stack else min(val, self.stack[-1][1])
        self.stack.append((val, current_min))

    def pop(self) -> None:
        self.stack.pop()

    def top(self) -> int:
        return self.stack[-1][0]

    def getMin(self) -> int:
        return self.stack[-1][1]
```

---

### 优点和局限

- **优点**：思路特别直，最容易第一次想出来
- **优点**：四个操作都能做到 `O(1)`
- **局限**：每个元素都要额外带一个“当前最小值”，重复信息比较多

所以它是非常好的过渡版本，但还不是我最想主推的面试写法。

---

### 复杂度

- `push`：`O(1)`
- `pop`：`O(1)`
- `top`：`O(1)`
- `getMin`：`O(1)`
- 额外空间复杂度：`O(n)`

---

## 方法三：数据栈 + 最小值栈（面试主推）

### 核心思路

方法二的问题是：

```text
每个元素都要重复存一份“当前最小值”
```

那能不能把“数据”和“最小值信息”拆开维护？

可以。

我们准备两个栈：

- `stack`：正常存所有数据
- `min_stack`：只在必要时存当前最小值

规则是：

### `push(val)`

- `val` 一定进 `stack`
- 如果 `min_stack` 为空，或者 `val <= min_stack[-1]`，就让 `val` 也进 `min_stack`

### `pop()`

- 先弹出 `stack` 的栈顶值 `x`
- 如果 `x == min_stack[-1]`，说明弹掉的正是当前最小值，那 `min_stack` 也要一起弹

### `getMin()`

- 直接返回 `min_stack[-1]`

这样最小值始终单独维护在另一个栈顶上。

---

### 为什么这里必须是 `<=`

这是这题最容易写错的细节之一。

假设你依次压入：

```text
2, 2, 3
```

如果你只在 `val < min_stack[-1]` 时才压入 `min_stack`，
那么两个 `2` 里只会记录一次最小值。

之后如果你弹出一个 `2`，你会误以为最小值已经没了，
但实际上栈里还剩下另一个 `2`。

所以这里必须写成：

```text
val <= min_stack[-1]
```

这样重复最小值会被完整记录，弹出时才能一一对应。

---

### 过程演示

依次执行：

```text
push(5), push(3), push(7), push(3), push(2)
```

#### 1. push(5)

- `stack = [5]`
- `min_stack = [5]`

#### 2. push(3)

- `stack = [5, 3]`
- `min_stack = [5, 3]`

因为 `3 <= 5`，所以它也是新的最小值。

#### 3. push(7)

- `stack = [5, 3, 7]`
- `min_stack = [5, 3]`

因为 `7` 不是更小值，所以不进 `min_stack`。

#### 4. push(3)

- `stack = [5, 3, 7, 3]`
- `min_stack = [5, 3, 3]`

注意这里虽然 `3` 没有更小，但它等于当前最小值，仍然要压入。

#### 5. push(2)

- `stack = [5, 3, 7, 3, 2]`
- `min_stack = [5, 3, 3, 2]`

现在 `getMin()` 直接返回 `2`。

如果之后连续 `pop()`：

- 弹掉 `2`，`min_stack` 也弹掉 `2`
- 再弹掉 `3`，`min_stack` 也弹掉一个 `3`

于是最小值会正确回退到上一个状态。

这就是双栈法真正稳定的地方。

---

### 面试代码

```python
class MinStack:
    def __init__(self):
        self.stack = []
        self.min_stack = []

    def push(self, val: int) -> None:
        self.stack.append(val)
        if not self.min_stack or val <= self.min_stack[-1]:
            self.min_stack.append(val)

    def pop(self) -> None:
        val = self.stack.pop()
        if val == self.min_stack[-1]:
            self.min_stack.pop()

    def top(self) -> int:
        return self.stack[-1]

    def getMin(self) -> int:
        return self.min_stack[-1]
```

---

### 为什么这是面试主推

### 1. 职责分离很清楚

- `stack` 负责“正常栈功能”
- `min_stack` 负责“最小值追踪”

代码结构清晰，面试官很容易看懂你的设计意图。

### 2. 它保留了 `O(1)` 的全部操作

所有操作都只碰栈顶，所以仍然全部是 `O(1)`。

### 3. 它比方法二更像真正的数据结构设计

方法二是“把辅助信息绑在每个元素身上”；
方法三是“把辅助信息抽成一个独立结构”。

这种设计感更强，也更容易迁移到：

- 最大栈
- 带辅助统计信息的栈
- 需要同时维护多个属性的数据结构题

### 4. 它最值得你记的细节很明确

这题面试里最爱追问的一句就是：

```text
为什么 push 时要用 <=，不是 < ？
```

如果你能顺着“重复最小值也要一一记录”讲清楚，说明你是真的理解了这个结构。

---

### 复杂度

- `push`：`O(1)`
- `pop`：`O(1)`
- `top`：`O(1)`
- `getMin`：`O(1)`
- 额外空间复杂度：`O(n)`

---

### 容易出错的地方

### 1. 把 `<=` 写成 `<`

这会在重复最小值场景下出错。

### 2. 弹出主栈后，忘了同步弹出 `min_stack`

如果当前弹出的正好是最小值，`min_stack` 必须一起更新。

### 3. 把 `min_stack` 写成和 `stack` 完全同步，但自己又没想清楚逻辑

其实也能写成“每次都把当前最小值压进去”的同步版，
但如果没有统一好规则，`push/pop` 很容易自己绕晕。

这也是为什么我更建议你主记当前这版：

```text
只在出现新最小值或重复最小值时压入 min_stack
```

规则更清晰。

---

## 三种方法的关系

- **方法一**：说明为什么“现查最小值”不符合题意
- **方法二**：第一次把“当前最小值”跟随栈状态一起存下来
- **方法三**：把数据与最小值追踪拆成两个结构，作为主推写法

这题最值得记住的一句话是：

```text
getMin() 想要 O(1)，就不能在查询时现算，而要在每次 push / pop 时把最小值状态提前维护好
```

一旦这句话想通，这题就不再是“背模板”，而是一个很自然的数据结构设计题。
