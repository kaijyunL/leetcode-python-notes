# LeetCode 739. 每日温度

## 题目

给定一个整数数组 `temperatures`，表示每天的温度。

请返回一个数组 `answer`，其中：

- `answer[i]` 表示第 `i` 天之后，第一次出现更高温度还要等几天
- 如果之后都不会再升温，则 `answer[i] = 0`

比如：

```text
temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
```

答案是：

```text
[1, 1, 4, 2, 1, 1, 0, 0]
```

因为：

- 第 0 天 `73`，第 1 天 `74` 更高，所以等 `1` 天
- 第 2 天 `75`，要等到第 6 天 `76`，所以等 `4` 天
- 第 6 天 `76` 后面没有更高温，所以是 `0`

---

## 这题真正考的是什么

表面上看，这题是在问：

```text
每一天往后第一个更高温在哪
```

但真正要识别出来的结构是：

```text
当前这一天，是否能帮前面一些“还没找到更高温”的日子结算答案
```

比如当你扫到某一天温度 `72` 时，
它不只是“自己这一天的信息”，它还可能同时解决前面很多天：

- 比 `72` 低的、还在等待的人
- 而且这些人里，最该优先结算的一定是最近那几个

这就很像：

```text
有一批下标在等“第一个比自己大的元素”出现
```

这正是 **单调栈** 的经典信号。

---

## 为什么它是单调栈母题

这题是单调栈最经典的模板之一，因为它几乎把模板的三个核心点都写全了：

### 1. 栈里存的是“还没结算答案的下标”

这些下标对应的日子都还在等右边第一个更高温。

### 2. 栈要保持单调

这里要维护的是：

```text
从栈底到栈顶，温度递减
```

因为一旦来了更高温，就会从栈顶开始一路结算。

### 3. 当前元素负责结算前面的元素

当前温度如果比栈顶高，就说明：

```text
栈顶那一天终于等到了它右边第一个更高温
```

于是可以立刻算出距离。

这套结构会直接迁移到：

- `496` Next Greater Element I
- `503` Next Greater Element II
- `84` 柱状图中最大的矩形
- `42` 接雨水
- `901` 股票价格跨度

所以 `739` 不是普通一道题，而是 **单调栈入门模板题**。

---

## 方法一：暴力向后扫描

### 核心思路

对每一天 `i`：

- 直接从 `i + 1` 往后找
- 找到第一个 `temperatures[j] > temperatures[i]` 的位置
- 把 `j - i` 填进答案
- 如果一直找不到，就保持 `0`

这是最直观的做法。

---

### 例子

还是看：

```text
temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
```

#### 第 0 天：`73`

向后看：

- 第 1 天是 `74`
- 已经更高

所以答案是：

```text
1
```

#### 第 2 天：`75`

向后看：

- `71` 不够
- `69` 不够
- `72` 不够
- `76` 更高

所以答案是：

```text
6 - 2 = 4
```

#### 第 6 天：`76`

向后再也没有更高温，所以答案是：

```text
0
```

---

### 为什么它可行

因为题目定义本来就是“向右找到第一个更高温”。

暴力法只是完全照着定义来实现，没有任何技巧。

---

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`（不算输出数组）

最坏情况下，比如温度严格递减，
每一天都要一路扫到末尾。

---

### 评价

这是一个很适合建立题意直觉的保底做法，
但面试里通常不会主推，因为它没有利用“前面那些天正在等答案”这个结构。

---

## 方法二：单调递减栈存下标（面试主推）

### 核心思路

我们用一个栈，存放那些：

```text
还没有找到右边第一个更高温的下标
```

并且让这些下标对应的温度保持：

```text
从栈底到栈顶递减
```

为什么要递减？

因为一旦当前温度比栈顶高，说明：

- 栈顶这一天终于等到了更高温
- 可以弹出并结算答案

而且当前温度可能连续比多个栈顶都高，
所以必须用 `while` 一直弹。

最后，再把当前下标压栈，表示它也开始等待未来更高温。

---

### 过程演示

看这个经典例子：

```text
temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
```

初始化：

```text
ans = [0, 0, 0, 0, 0, 0, 0, 0]
stack = []
```

#### 第 0 天：`73`

栈空，直接入栈：

```text
stack = [0]
```

#### 第 1 天：`74`

当前温度 `74` 大于栈顶第 0 天的 `73`，
说明第 0 天等到了第一个更高温：

```text
ans[0] = 1 - 0 = 1
```

弹栈后再把第 1 天入栈：

```text
ans = [1, 0, 0, 0, 0, 0, 0, 0]
stack = [1]
```

#### 第 2 天：`75`

同理，`75 > 74`，结算第 1 天：

```text
ans[1] = 2 - 1 = 1
```

然后入栈：

```text
ans = [1, 1, 0, 0, 0, 0, 0, 0]
stack = [2]
```

#### 第 3 天：`71`

`71` 不大于 `75`，不能结算任何人，直接入栈：

```text
stack = [2, 3]
```

#### 第 4 天：`69`

也不能结算，继续入栈：

```text
stack = [2, 3, 4]
```

#### 第 5 天：`72`

现在开始结算：

- `72 > 69`，所以第 4 天答案是 `1`
- `72 > 71`，所以第 3 天答案是 `2`
- `72` 不大于 `75`，停止

于是：

```text
ans = [1, 1, 0, 2, 1, 0, 0, 0]
stack = [2, 5]
```

#### 第 6 天：`76`

继续结算：

- `76 > 72`，第 5 天答案是 `1`
- `76 > 75`，第 2 天答案是 `4`

于是：

```text
ans = [1, 1, 4, 2, 1, 1, 0, 0]
stack = [6]
```

#### 第 7 天：`73`

不能结算第 6 天，入栈：

```text
stack = [6, 7]
```

遍历结束后，栈里剩下的下标都等不到更高温，答案保持 `0`。

---

### 为什么这是面试主推

### 1. 它最直接命中“下一个更大元素”结构

这题不是单纯往后找，
而是在维护一批“等待被更大值结算”的位置。

而单调栈正是这个结构的标准解法。

### 2. 它把重复扫描彻底消掉了

暴力法里，很多区间会被反复看。

单调栈的关键优化是：

```text
每个下标只入栈一次，也只出栈一次
```

所以总操作数是线性的。

### 3. 它是后续很多题的模板

这题最值得记住的不是答案本身，
而是这个模板：

```text
当前元素来了，如果它更强，就不断结算栈顶；结算完后自己再入栈等待未来
```

后面很多单调栈题，本质都在复用这句话。

### 4. 代码结构非常稳

主流程固定就是：

- `while`：当前元素结算前面的元素
- `append`：当前元素入栈

写熟以后会非常顺。

---

### 面试代码

```python
class Solution:
    def dailyTemperatures(self, temperatures: list[int]) -> list[int]:
        n = len(temperatures)
        ans = [0] * n
        stack = []

        for i, temp in enumerate(temperatures):
            while stack and temp > temperatures[stack[-1]]:
                prev = stack.pop()
                ans[prev] = i - prev

            stack.append(i)

        return ans
```

---

### 容易出错的地方

### 1. 栈里要存下标，不要只存温度

因为最终要返回的是：

```text
等几天
```

所以你必须能算：

```python
i - prev_index
```

如果你只存温度，就没法算距离。

### 2. 比较条件要用 `>`，不是 `>=`

题目要求的是：

```text
更高温
```

不是“更高或相等”。

比如两个 `73` 不能互相结算。

### 3. 这里必须是 `while`，不能写成 `if`

因为当前温度可能一口气结算多个前面的日子。

比如：

```text
[75, 71, 69, 72]
```

当你读到 `72` 时，
它会同时结算 `69` 和 `71`。

### 4. 遍历结束后，不需要再额外处理栈

栈里剩下的人，本来就表示：

```text
右边没有更高温
```

它们的答案保持 `0` 就对了。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

## 两种方法的关系

- **方法一**：先按题目定义，建立“向右找第一个更高温”的直觉
- **方法二**：把题目升级成“当前元素来结算前面等待的人”，正式进入单调栈模板

这题最值得记住的一句话是：

```text
当前这一天的温度，不只是自己的信息；它还负责给前面那些比它低、仍在等待的日子结算答案
```

这句话一旦想通，单调递减栈就会非常自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力向后扫描 | `O(n^2)` | `O(1)` | 直观保底，适合理解题意 |
| 方法二：单调递减栈存下标 | `O(n)` | `O(n)` | 面试主推，单调栈母题 |

