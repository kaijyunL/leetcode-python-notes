# LeetCode 394. 字符串解码

## 题目

给定一个经过编码的字符串 `s`，请你把它解码后返回。

编码规则是：

```text
k[encoded_string]
```

表示方括号里的字符串需要重复 `k` 次。

你可以默认：

- `k` 一定是正整数
- 输入字符串始终合法
- 不会出现额外空格
- 原始数据里不会把数字当普通字母使用

比如：

- `"3[a]2[bc]" -> "aaabcbc"`
- `"3[a2[c]]" -> "accaccacc"`
- `"2[abc]3[cd]ef" -> "abcabccdcdcdef"`

---

## 这题真正考的是什么

这题表面上是字符串题，但它真正考的是：

```text
当你看到一个 ] 时，它结束的一定是最近那个还没结束的 [ 这一层
```

这句话非常关键。

比如：

```text
3[a2[c]]
```

最里面的 `c` 要先和最近的 `2[` 结合，先变成：

```text
acc
```

然后这一整段 `acc` 才会再和外层的 `3[` 结合，变成：

```text
accaccacc
```

所以这题真正需要维护的，不是“所有括号层级同时怎么展开”，而是：

```text
最近一个尚未完成的嵌套层是谁
```

这就是典型的 **后进先出**，天然适合用栈。

---

## 先把每一层要保存的信息想清楚

当你读到一个 `[` 时，说明你要进入新的一层。

进入新层之前，当前这一层已经有两类信息必须先存起来：

1. **前面已经拼好的字符串前缀**
2. **这一层接下来要重复多少次**

因为等你把方括号里面那一层完全解完之后，回来时要做的事情一定是：

```text
上一层前缀 + 当前层结果 * 重复次数
```

比如：

```text
2[ab3[c]]
```

处理到第二个 `[` 时：

- 外层当前前缀是 `ab`
- 当前重复次数是 `3`

所以进入内层前，你必须把这两个状态保存起来。

这就是这题最核心的状态设计。

---

## 方法一：递归按索引解析当前层

### 核心思路

把整个字符串看成一层一层的嵌套结构。

我们写一个递归函数，专门负责：

```text
从当前位置开始，解析当前这一层，直到遇到对应的 ] 为止
```

在这一层里：

- 遇到数字，就累计重复次数
- 遇到 `[`，递归去解里面那一层
- 遇到 `]`，说明当前层结束，返回结果
- 遇到普通字母，就直接拼到当前层结果里

也就是说，递归天然帮你做了“进入新层 / 返回上一层”这件事。

---

### 例子

看：

```text
s = "3[a2[c]]"
```

外层先读到 `3[`，进入下一层。

下一层里先读到 `a`，当前结果变成：

```text
a
```

然后读到 `2[`，再进入更里层。

最里层读到 `c`，遇到 `]` 后返回：

```text
c
```

上一层拿到它后做：

```text
"a" + "c" * 2 = "acc"
```

再遇到外层 `]`，返回：

```text
"acc" * 3 = "accaccacc"
```

---

### 为什么它可行

因为每个 `[` 都对应一个独立子问题：

```text
先把这一层完整解出来，再把结果交给外层继续拼接
```

这和递归处理括号嵌套的结构完全一致。

---

### 复杂度

如果输入长度是 `n`，解码后结果长度是 `m`，那么：

- 时间复杂度：`O(n + m)`
- 空间复杂度：`O(m + d)`

其中 `d` 是嵌套深度。

因为解析输入要花 `O(n)`，真正把答案字符串构造出来要花 `O(m)`。

---

### 评价

这个方法很适合理解：

```text
字符串解码，本质上是在按层展开一个嵌套结构
```

但如果放到这章“栈和队列”里，它更像一个帮助建立结构感的补充写法，
不是最适合作为第一主记版本的实现。

---

## 方法二：栈里保存进入 `[` 前的“前缀字符串 + 重复次数”（面试主推）

### 核心思路

既然每进入一层之前，都必须先保存：

- 当前已经拼好的前缀
- 当前累计好的重复次数

那最自然的写法就是：

- 遇到数字：更新当前 `repeat`
- 遇到普通字母：加入当前层字符串
- 遇到 `[`：把 **当前前缀 + 重复次数** 压栈，然后开始处理新层
- 遇到 `]`：弹出上一层状态，把当前层结果按次数展开，再接回上一层前缀

这正好和栈的含义完全一致。

---

### 过程演示

继续看：

```text
s = "3[a2[c]]"
```

初始化：

- `stack = []`
- `cur = ""`
- `repeat = 0`

#### 读到 `3`

累计次数：

```text
repeat = 3
```

#### 读到 `[`

把进入这一层前的状态压栈：

```text
stack = [("", 3)]
```

然后开始新层：

```text
cur = ""
repeat = 0
```

#### 读到 `a`

当前层字符串变成：

```text
cur = "a"
```

#### 读到 `2`

累计次数：

```text
repeat = 2
```

#### 读到 `[`

再次压栈：

```text
stack = [("", 3), ("a", 2)]
```

开启更里层：

```text
cur = ""
repeat = 0
```

#### 读到 `c`

```text
cur = "c"
```

#### 读到 `]`

弹出上一层状态 `("a", 2)`，合并：

```text
cur = "a" + "c" * 2 = "acc"
```

#### 再读到 `]`

弹出上一层状态 `("", 3)`，再合并：

```text
cur = "" + "acc" * 3 = "accaccacc"
```

最终答案就是：

```text
accaccacc
```

---

### 为什么这是面试主推

### 1. 它最直接命中这题的状态本质

这题最核心的不是“怎么拼字符串”，而是：

```text
进入新层之前，要先把上一层的状态完整保存起来
```

而这个状态恰好就是一对：

- 前缀字符串
- 重复次数

方法二把这件事表达得最完整。

### 2. 栈模型和括号嵌套完全同构

- `[`：进入一层，压栈保存现场
- `]`：退出一层，弹栈恢复现场

结构非常自然。

### 3. 多位数字、嵌套、前后缀都能统一处理

像这些情况：

- `10[a]`
- `3[a2[c]]`
- `abc3[cd]xyz`

在这套流程里都只是同一套状态转移，不需要额外分支。

### 4. 代码短、稳定、面试里不容易乱

主流程只有四类字符：

- 数字
- `[`
- `]`
- 普通字母

而且每类字符的动作都很固定，特别适合讲清楚。

---

### 面试代码

```python
class Solution:
    def decodeString(self, s: str) -> str:
        stack = []
        cur = ""
        repeat = 0

        for ch in s:
            if ch.isdigit():
                repeat = repeat * 10 + int(ch)
            elif ch == "[":
                stack.append((cur, repeat))
                cur = ""
                repeat = 0
            elif ch == "]":
                previous, times = stack.pop()
                cur = previous + cur * times
            else:
                cur += ch

        return cur
```

---

### 复杂度

如果输入长度是 `n`，解码后结果长度是 `m`，那么：

- 时间复杂度：`O(n + m)`
- 空间复杂度：`O(m + d)`

其中 `d` 是嵌套深度。

---

### 容易出错的地方

### 1. 多位数字不能只读一位

比如：

```text
10[a]
```

这里重复次数是 `10`，不是 `1`。

所以数字要写成：

```python
repeat = repeat * 10 + int(ch)
```

### 2. 遇到 `[` 后要把 `repeat` 清零

因为这个次数已经被压栈保存了；
如果不清零，下一层继续读数字时就会串层。

### 3. `]` 时拼接顺序不能写反

正确的是：

```text
上一层前缀 + 当前层结果 * 次数
```

也就是：

```python
previous + current * times
```

不是反过来。

### 4. 普通字母可能出现在括号外面

比如：

```text
abc3[cd]xyz
```

前面的 `abc` 和后面的 `xyz` 都要原样保留。

---

## 方法三：两个栈分别保存重复次数和前缀字符串

### 核心思路

方法二把状态打包成一个二元组压栈。

如果你想把两个状态拆开看，也可以写成两个栈：

- 一个栈存重复次数
- 一个栈存进入当前层之前的前缀字符串

遇到 `[` 时同时压入；
遇到 `]` 时同时弹出，再完成合并。

本质上它和方法二完全一样，只是状态存储方式不同。

---

### 代码

```python
class Solution:
    def decodeString(self, s: str) -> str:
        count_stack = []
        string_stack = []
        cur = ""
        repeat = 0

        for ch in s:
            if ch.isdigit():
                repeat = repeat * 10 + int(ch)
            elif ch == "[":
                count_stack.append(repeat)
                string_stack.append(cur)
                cur = ""
                repeat = 0
            elif ch == "]":
                times = count_stack.pop()
                previous = string_stack.pop()
                cur = previous + cur * times
            else:
                cur += ch

        return cur
```

---

### 它和方法二的关系

两者本质完全一样：

- 都是栈处理嵌套层级
- 都是在 `[` 时保存现场
- 都是在 `]` 时恢复现场并拼接
- 都能做到相同复杂度

区别只在于：

- **方法二**：一个栈里直接放完整状态，表达更紧凑
- **方法三**：把状态拆成两个栈，层次更直白

如果是第一次准备这题，我更建议先把方法二吃透；
如果你更喜欢把状态拆清楚看，方法三也很好写。

---

### 复杂度

- 时间复杂度：`O(n + m)`
- 空间复杂度：`O(m + d)`

---

## 三种方法的关系

- **方法一**：帮助理解“按层解析嵌套结构”
- **方法二**：正式进入最标准的栈解法，主记这一版
- **方法三**：和方法二本质相同，只是把状态拆开保存

这题最值得记住的一句话是：

```text
每个 ] 收束的，一定是最近那个还没结束的 [ 这一层，所以进入新层前必须先把旧层状态保存起来
```

这句话一旦想通，整题就会非常自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：递归按索引解析 | `O(n + m)` | `O(m + d)` | 结构感强，适合理解嵌套解析 |
| 方法二：栈保存前缀和次数 | `O(n + m)` | `O(m + d)` | 面试主推，最标准、最稳 |
| 方法三：双栈分别保存状态 | `O(n + m)` | `O(m + d)` | 同样优秀，状态拆得更开 |

其中：

- `n` 是输入字符串长度
- `m` 是解码后字符串长度
- `d` 是嵌套深度

---

## 总结

如果你现在只准备记一个版本：

```text
就记方法二：栈里保存进入 [ 前的“前缀字符串 + 重复次数”
```

因为它最完整地表达了这题真正的状态变化：**进入新层先存现场，退出当前层再恢复现场并拼接结果**。

如果你还想把这题吃得更透，再补上：

```text
方法一：递归按层解析
方法三：双栈拆开保存状态
```

这样你会更清楚地看到：不管写成递归还是栈，这题本质上都在做同一件事——**按嵌套层级展开字符串**。
