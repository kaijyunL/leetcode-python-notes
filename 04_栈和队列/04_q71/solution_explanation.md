# LeetCode 71. 简化路径

## 题目

给定一个 Unix 风格的绝对路径 `path`，请你把它化简成规范路径。

规范路径需要满足：

1. 一定以 `/` 开头
2. 两个目录名之间只有一个 `/`
3. 末尾不能有多余的 `/`（根目录 `/` 除外）
4. `.` 表示当前目录，等于什么都不做
5. `..` 表示回到上一级目录
6. 超过根目录继续往上时，仍然停在根目录

---

## 这题真正考的是什么

这题表面上是字符串题，但它真正考的是：

```text
路径里的目录进入和返回上一级，是否符合“后进先出”
```

比如路径：

```text
/a/b/../c
```

它的过程其实是：

- 进入 `a`
- 再进入 `b`
- 遇到 `..`，撤销最近一次进入，也就是退出 `b`
- 再进入 `c`

这里最关键的一句就是：

```text
回退到上一级时，取消的一定是最近一次进入的目录
```

这就是典型的 **后进先出**，天然适合用栈。

所以这题不是单纯“处理斜杠”，而是：

```text
把路径拆成一条条指令，再用栈维护当前有效目录层级
```

---

## 先把三种特殊片段分清楚

把路径按 `/` 拆开后，每一段只会落在这几类里：

- **空串 `""`**：来自连续 `/`，直接忽略
- **`.`**：表示当前目录，直接忽略
- **`..`**：表示返回上一级，如果栈非空就弹栈
- **普通目录名**：压入栈中

比如：

```text
path = "/a//b/./../c/"
```

按 `/` 拆开后是：

```text
["", "a", "", "b", ".", "..", "c", ""]
```

逐段处理：

- `""`：忽略
- `"a"`：入栈 -> `["a"]`
- `""`：忽略
- `"b"`：入栈 -> `["a", "b"]`
- `"."`：忽略
- `".."`：弹栈 -> `["a"]`
- `"c"`：入栈 -> `["a", "c"]`
- `""`：忽略

最后得到：

```text
/a/c
```

---

## 方法一：手动扫描字符，自己提取每一段路径

### 核心思路

不用 `split('/')`，而是自己从左到右扫描字符串：

1. 先跳过连续的 `/`
2. 提取两个 `/` 之间的那一段名字
3. 再根据这一段是 `.`、`..` 还是普通目录名来处理栈

也就是说，它本质上还是栈，
只是“路径分段”这一步不是交给 `split`，而是自己手动做。

---

### 例子

还是看：

```text
path = "/home//foo/"
```

扫描时会依次提取出：

```text
home
foo
```

连续的 `//` 会被跳过，不会被当成真正目录。

于是：

- 读到 `home`：入栈 -> `["home"]`
- 读到 `foo`：入栈 -> `["home", "foo"]`

最后得到：

```text
/home/foo
```

---

### 为什么它可行

因为无论你是用 `split`，还是自己手动扫描，
本质都只是为了把路径还原成一段一段的“目录指令”。

只要每段都能被正确提取出来，后面的栈逻辑就完全一样。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 评价

这个方法适合帮助你理解：

```text
路径化简 = 先分段，再处理每一段的语义
```

但面试里通常不会主推它，
因为手动扫描会多出不少边界处理细节，代码也更长。

---

## 方法二：`split('/')` + 栈维护目录层级（面试主推）

### 核心思路

既然题目的核心是“按段处理路径”，那最自然的写法就是：

1. 先用 `/` 把路径拆成很多段
2. 用栈维护当前有效目录
3. 最后再把栈里的目录用 `/` 拼回去

处理规则很固定：

- 遇到 `""` 或 `"."`：忽略
- 遇到 `".."`：如果栈不空，就弹出一个目录
- 遇到普通目录名：压栈

最后答案就是：

```text
"/" + "/".join(stack)
```

如果栈为空，那结果自然就是根目录 `/`。

---

### 过程演示

看这个例子：

```text
path = "/a/./b/../../c/"
```

先分割：

```text
["", "a", ".", "b", "..", "..", "c", ""]
```

#### 读到 `""`

忽略，栈还是：

```text
[]
```

#### 读到 `"a"`

普通目录，入栈：

```text
["a"]
```

#### 读到 `"."`

当前目录，忽略：

```text
["a"]
```

#### 读到 `"b"`

普通目录，入栈：

```text
["a", "b"]
```

#### 读到 `".."`

返回上一级，弹栈：

```text
["a"]
```

#### 再读到 `".."`

继续返回上一级：

```text
[]
```

#### 读到 `"c"`

普通目录，入栈：

```text
["c"]
```

最后拼接结果：

```text
/c
```

---

### 为什么这是面试主推

### 1. 它最直接抓住题目本质

这题真正重要的不是字符本身，而是每一段路径的语义：

- 进入目录
- 原地不动
- 回到上一级

`split('/')` 正好把这些语义单位直接切出来。

### 2. 栈模型特别自然

`..` 的含义就是：

```text
撤销最近一次进入的目录
```

这和栈顶弹出完全一致。

### 3. 代码短、结构稳、边界清楚

你只需要统一处理 4 类片段：

- 空串
- `.`
- `..`
- 普通目录名

写起来很稳，面试里不容易错。

### 4. 它把字符串处理和栈处理分得很清楚

这其实是很典型的两阶段思维：

- **先解析输入**：把路径切成片段
- **再执行指令**：用栈模拟目录变化

这种写法特别像真正的工程代码，也更容易讲清楚。

---

### 面试代码

```python
class Solution:
    def simplifyPath(self, path: str) -> str:
        stack = []

        for part in path.split("/"):
            if part == "" or part == ".":
                continue
            if part == "..":
                if stack:
                    stack.pop()
            else:
                stack.append(part)

        return "/" + "/".join(stack)
```

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

其中 `n` 是路径字符串长度。

---

### 容易出错的地方

### 1. 忘了忽略空串

连续斜杠会让 `split('/')` 产生空串。

比如：

```text
/home//foo/
```

分割后会有 `""`，这些都不能当目录名入栈。

### 2. `..` 到根目录以上时不能继续弹

比如：

```text
/../../a
```

前两个 `..` 都应该被忽略，最终结果是：

```text
/a
```

所以弹栈前一定要先判断栈是否为空。

### 3. 把 `...` 错当成 `..`

只有刚好等于 `".."` 才表示返回上一级。

像：

```text
/.../b
```

其中 `...` 是一个合法目录名，不能特殊处理。

### 4. 根目录要返回 `/`

如果最后栈空，拼接结果应该是：

```text
/
```

而不是空字符串。

---

## 两种方法的关系

- **方法一**：自己手动做路径分段，更适合理解输入到底是怎么被拆开的
- **方法二**：直接 `split('/')` 后交给栈处理，是标准面试写法

这题最值得记住的一句话是：

```text
简化路径，本质上是在执行一串“进入目录 / 回退目录”的指令，而“回退最近一次进入”天然就是栈
```

这句话一旦想通，整题就会很自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：手动扫描并提取路径段 | `O(n)` | `O(n)` | 能帮助理解路径分段，但代码更碎 |
| 方法二：`split('/')` + 栈 | `O(n)` | `O(n)` | 面试主推，最自然、最稳 |
