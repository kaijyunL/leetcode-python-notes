# LeetCode 150. 逆波兰表达式求值

## 题目

给定一个字符串数组 `tokens`，表示一个逆波兰表达式（后缀表达式），请你计算并返回表达式的值。

题目里只会出现这四种运算符：

- `+`
- `-`
- `*`
- `/`

其中除法有一个特别关键的要求：

```text
结果必须向 0 截断
```

比如：

- `5 / 2 = 2`
- `-5 / 2 = -2`

所以在 Python 里，这题通常会写成：

```python
int(a / b)
```

而不是直接写 `a // b`。

---

## 什么是逆波兰表达式

平时我们更熟悉的是中缀表达式：

```text
2 + 1
(2 + 1) * 3
```

逆波兰表达式会把运算符放到后面：

```text
2 1 +
2 1 + 3 *
```

也就是：

- 数字先出现
- 运算符等到需要计算时才出现

比如：

```text
tokens = ["2", "1", "+", "3", "*"]
```

它表示的其实就是：

```text
(2 + 1) * 3
```

---

## 这题真正的识别点是什么

从左到右扫描 `tokens` 时，你会发现一个很关键的规律：

```text
一旦遇到运算符，它就一定要拿“最近两个还没被使用的数字”来计算
```

这句话非常重要。

因为“最近两个还没被使用的数字”天然就是一种：

```text
后进先出
```

而后进先出最适合的数据结构，就是栈。

所以这题表面上在算表达式，实际上考的是：

```text
你能不能识别出“最近待处理元素”应该用栈维护
```

---

## 方法一：不断找到第一个运算符并折叠列表

### 核心思路

最直接的想法是把 `tokens` 看成一个会不断缩短的列表。

每一轮：

1. 从左到右找第一个运算符
2. 它前面两个位置一定是它的两个操作数
3. 先算出结果
4. 再把“两个数字 + 一个运算符”这 3 项，折叠成 1 项结果

不断重复，直到列表只剩一个数字。

---

### 例子

```text
tokens = ["2", "1", "+", "3", "*"]
```

第一轮找到 `+`：

```text
2 + 1 = 3
```

列表变成：

```text
["3", "3", "*"]
```

第二轮找到 `*`：

```text
3 * 3 = 9
```

列表变成：

```text
["9"]
```

最终答案就是 `9`。

---

### 为什么它能做对

因为合法逆波兰表达式中，只要出现一个运算符，
它前面最近的两个尚未折叠掉的数字，一定正是它现在应该消费的两个操作数。

所以不断做这种“局部折叠”，最终一定能把整个表达式收缩成一个结果。

---

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(n)`

因为你会反复扫描列表，还会不断创建新列表。

---

### 评价

这个方法很适合建立“逆波兰表达式其实是在不断合并局部结果”的直觉，
但它没有抓住最自然的数据结构，因此面试里一般不会主推。

---

## 方法二：栈里存数字，遇到运算符就弹两个数计算（面试主推）

### 核心思路

既然每次运算符都只关心：

```text
最近两个还没参与运算的数字
```

那我们就用一个栈来维护这些数字。

规则非常直接：

- 遇到数字：压栈
- 遇到运算符：弹出两个数字，算出结果，再把结果压回栈

最后栈里只剩一个数，它就是答案。

---

### 过程演示

看这个例子：

```text
tokens = ["4", "13", "5", "/", "+"]
```

#### 读到 `4`

数字，入栈：

```text
[4]
```

#### 读到 `13`

数字，入栈：

```text
[4, 13]
```

#### 读到 `5`

数字，入栈：

```text
[4, 13, 5]
```

#### 读到 `/`

弹出两个数：

- 第一次弹出：`5`
- 第二次弹出：`13`

注意这里真正要算的是：

```text
13 / 5
```

不是 `5 / 13`。

结果向 0 截断后是 `2`，压回栈：

```text
[4, 2]
```

#### 读到 `+`

再弹两个数：

- 第一次弹出：`2`
- 第二次弹出：`4`

计算：

```text
4 + 2 = 6
```

压回栈：

```text
[6]
```

最后栈里只剩 `6`，所以答案是 `6`。

---

### 这题最容易错的两个细节

### 1. 操作数顺序不能写反

遇到运算符时：

- 第一次弹出的是右操作数 `b`
- 第二次弹出的是左操作数 `a`

所以：

- 减法必须写 `a - b`
- 除法必须写 `a / b`

不能写反。

比如：

```text
["4", "2", "-"]
```

真正应该算：

```text
4 - 2 = 2
```

而不是 `2 - 4`。

### 2. Python 里不能直接用 `//`

因为：

```text
-3 // 2 = -2
```

这是向下取整；
但题目要求的是向 0 截断，所以应该得到：

```text
-1
```

因此这里更稳的是：

```python
int(a / b)
```

---

### 面试代码

```python
class Solution:
    def evalRPN(self, tokens: list[str]) -> int:
        stack = []
        operators = {"+", "-", "*", "/"}

        for token in tokens:
            if token not in operators:
                stack.append(int(token))
                continue

            right = stack.pop()
            left = stack.pop()

            if token == "+":
                stack.append(left + right)
            elif token == "-":
                stack.append(left - right)
            elif token == "*":
                stack.append(left * right)
            else:
                stack.append(int(left / right))

        return stack[-1]
```

---

### 为什么这是面试主推

### 1. 它最直接命中题目结构

逆波兰表达式的计算，本质上就是：

```text
数字先存起来，运算符出现时就把最近两个结果合并
```

这和栈完全同构。

### 2. 逻辑非常稳

主流程只有两种情况：

- 数字入栈
- 运算符弹两个数再压回结果

结构简单，面试里很不容易写乱。

### 3. 复杂度就是最优级别

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

每个 token 只会被处理一次。

### 4. 题目最关键的追问点都能自然展开

这题面试里最爱追问的，通常就是：

- 为什么先弹右操作数，再弹左操作数？
- 为什么 Python 里要用 `int(a / b)`？

而这两个点都正好落在方法二的主流程里，特别适合讲解。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

## 方法三：栈 + 运算映射表

### 核心思路

本质上还是方法二，只是把“运算符怎么计算”这部分单独抽出来，
让主循环更统一。

也就是：

- 数字：照常入栈
- 运算符：从映射表里拿出对应操作，再处理两个栈顶数字

这样写法会更整齐，也更方便以后扩展新运算符。

---

### 代码

```python
class Solution:
    def evalRPN(self, tokens: list[str]) -> int:
        stack = []
        operations = {
            "+": lambda a, b: a + b,
            "-": lambda a, b: a - b,
            "*": lambda a, b: a * b,
            "/": lambda a, b: int(a / b),
        }

        for token in tokens:
            if token not in operations:
                stack.append(int(token))
                continue

            right = stack.pop()
            left = stack.pop()
            stack.append(operations[token](left, right))

        return stack[-1]
```

---

### 它和方法二的关系

两者本质完全一样：

- 都是栈
- 都是 `O(n)` 时间
- 都要注意减法、除法顺序
- 都要注意向 0 截断

区别只在于：

- **方法二**：判断分支更显式，第一次写更稳
- **方法三**：结构更整齐，但抽象程度更高一点

如果是第一次学这题，我更建议先把方法二吃透；
如果你已经很熟表达式栈题，方法三会写得更顺。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

## 三种方法的关系

- **方法一**：先建立“逆波兰表达式是在不断折叠局部结果”的直觉
- **方法二**：正式进入标准栈解法，主记这一版
- **方法三**：在方法二基础上，把运算逻辑进一步抽出来

这题最值得记住的一句话是：

```text
逆波兰表达式里，运算符一出现，就只会消耗最近两个尚未使用的数字
```

这句话一旦想通，栈解法就几乎是顺着题目自己长出来的。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：不断折叠列表 | `O(n^2)` | `O(n)` | 直观保底，适合理解“局部合并” |
| 方法二：栈直接弹两数计算 | `O(n)` | `O(n)` | 面试主推，最标准、最稳 |
| 方法三：栈 + 运算映射表 | `O(n)` | `O(n)` | 同样优秀，代码更整齐 |

---

## 总结

如果你现在只准备记一个版本：

```text
就记方法二：栈里存数字，遇到运算符就弹两个数计算
```

因为它最贴题、最稳，也最方便把“左右操作数顺序”和“向 0 截断”这两个关键细节讲清楚。

如果你已经把这套流程很熟了，再补上：

```text
方法三：栈 + 运算映射表
```

你写起来会更快，也更像熟练状态下的表达式题写法。
