# LeetCode 32. 最长有效括号 (Longest Valid Parentheses)

## 题目

给定一个只包含 `(` 和 `)` 的字符串，找出最长有效（格式正确且连续）括号子串的长度。

比如：

```text
s = ")()())"
```

答案是：

```text
4
```

因为 `()()` 是最长的有效括号子串。

---

## 这题真正考的是什么

表面上看，这题是在问：

```text
最长的合法括号子串有多长
```

但和 `20` 有效的括号不同，`20` 是问 **整个串是否合法**，
这题是问 **串里某一段连续子串最长能有多合法**。

关键区别在于：

```text
20：整个串要全对
32：串里可以有断点，找最长的一段连续合法子串
```

所以这题的核心难点不是“怎么判断括号合不合法”，
而是 **“怎么算出某一段合法子串的长度”**。

要算长度，就必须知道这段子串的 **起点和终点**。
这正是这题和 `20` 的分水岭：

```text
20 只需要在栈里匹配
32 必须在栈里存下标，才能算长度
```

所以这题被定位成 **#20 的终极升级版**：
同样是括号匹配，但要把栈里存的内容从“字符”升级成“位置”。

---

## 为什么栈里要存下标，而不是字符

`20` 有效的括号里，栈里存字符就够了，
因为它只要判断“能不能配对完”。

但这题要算 **长度**。
长度 = 当前位置 - 这段合法子串的起点。

所以你必须知道：

```text
当前匹配上的这段，是从哪个位置开始的
```

这就要求栈里存的是 **下标**，不是字符。

具体来说，栈里存的是 **还没被匹配的位置**，
栈顶就是“当前这段合法子串的左边界参照点”。

---

## 方法一：暴力枚举所有偶数子串

### 核心思路

最长有效括号子串一定是偶数长度（每个 `(` 配一个 `)`）。
所以枚举所有偶数长度的子串，用栈判断每个子串是否合法，取最长。

这是完全照着定义来的保底做法。

---

### 为什么它可行

因为它就是题目的直接实现：

```text
找所有可能的连续子串，判断合法性，取最长
```

逻辑一定正确，只是非常慢。

---

### 复杂度

- 时间复杂度：`O(n^3)`，枚举所有偶数子串 `O(n^2)`，每个子串用栈验证 `O(n)`
- 空间复杂度：`O(n)`，验证时用的栈

---

### 评价

这个方法基本不会被采用，但能帮你建立“合法括号串”的直觉。
它太慢，连 `O(n^2)` 都不如，面试里只能当口述起点。

---

## 方法二：动态规划

### 核心思路

定义 `dp[i]` 为 **以 `s[i]` 结尾的最长有效括号长度**。

最终答案就是 `max(dp)`。

关键是怎么转移。分两种情况，都是 `s[i] == ')'` 时才有意义
（以 `(` 结尾不可能合法，`dp[i] = 0`）：

#### 情况一：`...()`

即 `s[i-1] == '('`，当前 `)` 和前一个 `(` 直接配对：

```text
dp[i] = dp[i-2] + 2
```

`dp[i-2]` 是这对括号前面那段合法子串的长度，接上即可。

#### 情况二：`...))`

即 `s[i-1] == ')'`。
此时要看 `s[i]` 这个 `)` 能不能和它前面更早的一个 `(` 配对。

那个 `(` 的位置是：

```text
j = i - dp[i-1] - 1
```

因为 `dp[i-1]` 是以 `i-1` 结尾的合法子串长度，
跳过这段，前面那个字符如果是 `(`，就能和 `s[i]` 配对。

如果 `s[j] == '('`，则：

```text
dp[i] = dp[i-1] + 2 + dp[j-1]
```

- `dp[i-1]`：中间那段合法子串
- `2`：当前配对的一对
- `dp[j-1]`：这对括号之前那段合法子串

---

### 例子

```text
s = "()(())"
```

逐位算 `dp`：

| i | s[i] | 情况 | dp[i] |
| --- | --- | --- | --- |
| 0 | `(` | — | 0 |
| 1 | `)` | `()`，dp[1] = dp[-1] + 2 = 2 | 2 |
| 2 | `(` | — | 0 |
| 3 | `(` | — | 0 |
| 4 | `)` | `()`，dp[4] = dp[2] + 2 = 2 | 2 |
| 5 | `)` | `))`，j = 5 - 2 - 1 = 2，s[2] = `(`，dp[5] = dp[4] + 2 + dp[1] = 2+2+2 = 6 | 6 |

最大值 `6`，即整个串。

---

### 复杂度

- 时间复杂度：`O(n)`，一次遍历
- 空间复杂度：`O(n)`，dp 数组

---

### 评价

DP 解法时间也是 `O(n)`，但状态转移里下标跳来跳去，
边界很容易写错。面试里如果一时想不到栈，可以写 DP，
但不如栈直观。

---

## 方法三：栈存下标（面试主推）

### 核心思路

用一个栈，存 **下标**。
栈里始终维护着“还没被匹配的位置”，栈顶就是 **当前合法子串的左边界参照点**。

做法：

1. 栈底先放一个 `-1`，作为初始参照点
2. 遇到 `(`：把它的下标入栈（它等待被某个 `)` 匹配）
3. 遇到 `)`：
   - 先弹栈（尝试和栈顶的 `(` 配对）
   - 如果弹完后 **栈空了**：说明这个 `)` 是多余的，没人跟它配对。把它的下标入栈，作为新的参照点
   - 如果弹完后 **栈不空**：匹配成功，当前合法长度 = `i - stack[-1]`

---

### 为什么栈底要放 -1

因为算长度需要 `当前下标 - 栈顶下标`。
如果没有 `-1`，第一个合法子串匹配完栈就空了，没法做减法。

比如 `s = "()"`：

- `i=0`，`(` 入栈，`stack = [-1, 0]`
- `i=1`，`)` 弹出 `0`，栈剩 `[-1]`
- 长度 = `1 - (-1) = 2` ✓

如果不放 `-1`，弹出后栈空，就算不出长度。

`-1` 的含义是：**合法子串的起点前一个位置**。
这样 `i - stack[-1]` 正好就是子串长度。

---

### 为什么要存下标

因为长度 = 当前位置 - 起点。
栈里存下标，栈顶就是“当前这段还没匹配完的左边界”。

如果只存字符，你只知道“配没配对”，但不知道“配了多长”。

---

### 过程演示

```text
s = ")()())"
```

初始化：

```text
stack = [-1]
max_ans = 0
```

#### i = 0，`)`

弹栈，弹出 `-1`，栈空了。
说明这个 `)` 多余，把它的下标入栈当新参照点：

```text
stack = [0]
```

#### i = 1，`(`

入栈：

```text
stack = [0, 1]
```

#### i = 2，`)`

弹栈，弹出 `1`，栈剩 `[0]`，不空。
匹配成功：

```text
长度 = 2 - 0 = 2
max_ans = 2
```

#### i = 3，`(`

入栈：

```text
stack = [0, 3]
```

#### i = 4，`)`

弹栈，弹出 `3`，栈剩 `[0]`，不空。
匹配成功：

```text
长度 = 4 - 0 = 4
max_ans = 4
```

#### i = 5，`)`

弹栈，弹出 `0`，栈空了。
这个 `)` 多余，入栈当新参照点：

```text
stack = [5]
```

遍历结束，`max_ans = 4`。

---

### 为什么这是面试主推

#### 1. 它直接从 20 的栈思路升级

`20` 是栈存字符，这题是栈存下标。
思路一脉相承，但解决了一个新问题：算长度。

#### 2. 逻辑清晰，不容易写错

主流程就是：

- `(` 入栈
- `)` 弹栈，空了就把自己入栈，不空就算长度

比 DP 的下标跳跃好写很多。

#### 3. 它能体现“用栈存什么”的判断力

这题考的不是“会不会用栈”，而是“栈里该存什么”。
能想到存下标，说明你理解了“算长度需要位置信息”。

---

### 面试代码

```python
class Solution:
    def longestValidParentheses(self, s: str) -> int:
        max_ans = 0
        stack = [-1]

        for i, ch in enumerate(s):
            if ch == "(":
                stack.append(i)
            else:
                stack.pop()
                if not stack:
                    stack.append(i)
                else:
                    max_ans = max(max_ans, i - stack[-1])

        return max_ans
```

---

### 容易出错的地方

#### 1. 栈底必须放 -1，不能是空栈起步

否则第一个合法子串匹配完栈就空了，没法算长度。

#### 2. 弹栈前不需要判空

因为栈底始终有一个“参照点”兜底，不会空。
弹完后如果空了，说明当前 `)` 是多余的。

#### 3. 右括号多余时，要把它入栈当新参照点

```python
if not stack:
    stack.append(i)
```

这一步很多人会漏。漏了的话，后面所有长度都会算错，
因为参照点没更新。

#### 4. 存的是下标，不是字符

算长度需要 `i - stack[-1]`，所以栈里必须是下标。

---

### 复杂度

- 时间复杂度：`O(n)`，每个字符进出栈一次
- 空间复杂度：`O(n)`，栈最多存 `n` 个下标

---

## 方法四：正向反向各扫一遍（空间最优）

### 核心思路

用两个计数器 `left` 和 `right` 记录 `(` 和 `)` 的数量。

#### 正向扫描

- 遇到 `(`，`left++`
- 遇到 `)`，`right++`
- `left == right` 时，更新最大长度 `2 * right`
- `right > left` 时，说明右括号多了，这段断了，重置 `left = right = 0`

#### 为什么还要反向扫描

因为正向扫描处理不了 `((()` 这种 **左括号比右括号多** 的情况。
正向扫完 `left` 一直大于 `right`，永远不会触发更新。

所以再从右往左扫一遍，把 `(` 和 `)` 的角色互换：

- `left > right` 时重置（左括号多了）
- `left == right` 时更新

两次扫描取最大值，就能覆盖所有情况。

---

### 为什么它可行

合法括号串里 `(` 和 `)` 数量相等。
正向扫描能抓住 `) ` 过多导致的断点，
反向扫描能抓住 `(` 过多导致的断点。
两次合起来，所有断点都抓住了。

---

### 复杂度

- 时间复杂度：`O(n)`，两次遍历
- 空间复杂度：`O(1)`，只用常数个变量

---

### 评价

这是空间最优解。但它不如栈直观，而且要扫两次，
逻辑上不如栈解法“一气呵成”。面试里如果被追问
“能不能 O(1) 空间”，再给出这个解法。

---

## 四种方法的关系

- **方法一**：暴力枚举所有偶数子串，建立“合法括号串”的直觉，但 `O(n^3)` 太慢
- **方法二**：DP，把“以 i 结尾的最长合法长度”做成状态，`O(n)` 但下标跳跃容易写错
- **方法三**：栈存下标，从 `20` 的栈思路直接升级，用栈顶当合法子串的左边界参照点，面试主推
- **方法四**：双计数器正反各扫一遍，空间最优 `O(1)`，但不如栈直观

这题最值得记住的一句话是：

```text
算长度需要知道起点；所以栈里不能存字符，要存下标，用栈顶当合法子串的左边界参照点
```

想通这一点，栈存下标的写法就会非常自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力枚举偶数子串 | `O(n^3)` | `O(n)` | 太慢，仅作直觉起点 |
| 方法二：动态规划 | `O(n)` | `O(n)` | 下标跳跃，容易写错 |
| 方法三：栈存下标 | `O(n)` | `O(n)` | 面试主推，从 20 直接升级 |
| 方法四：双计数器正反扫描 | `O(n)` | `O(1)` | 空间最优，被追问时再给 |
