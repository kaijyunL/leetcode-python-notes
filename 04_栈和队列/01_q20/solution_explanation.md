# LeetCode 20. 有效的括号

## 题目

给定一个只包含 `(`、`)`、`[`、`]`、`{`、`}` 的字符串 `s`，判断它是否是有效括号串。

一个有效括号串需要同时满足：

1. 左括号必须被同类型的右括号闭合
2. 左括号必须按正确顺序闭合
3. 每个右括号都必须有它前面对应的左括号

---

## 这题为什么是栈的入门题

这题最关键的约束不是“数量对不对”，而是：

```text
最近打开的左括号，必须最先被关闭
```

这句话天然对应栈的 **后进先出**。

比如字符串：

```text
{ [ ( ) ] }
```

你最后看到的那个还没匹配的左括号一定是 `(`，所以遇到 `)` 时，也必须优先和它匹配；
如果你让更早的 `{` 或 `[` 先去匹配，顺序就乱了。

所以这题真正考的不是“括号会不会配”，而是你能不能识别出：

```text
需要维护“最近一个还没匹配的左括号”
```

这就是栈。

---

## 方法一：反复删除相邻合法括号对

### 核心思路

如果一个括号串最终是合法的，那么在不断化简的过程中，里面一定会反复出现：

```text
()   []   {}
```

这种已经就地配好的相邻括号对。

所以可以不断执行：

1. 把字符串里的 `()`、`[]`、`{}` 替换为空
2. 如果某一轮替换后字符串没有变化，就停止
3. 最后看字符串是否为空

如果最后能删成空串，说明全部配对成功；否则说明还有不能消掉的残留结构。

---

### 例子

```text
s = "([{}])"
```

第一轮删掉 `{}`：

```text
([])
```

第二轮删掉 `[]`：

```text
()
```

第三轮删掉 `()`：

```text
""
```

最后为空，所以合法。

而：

```text
s = "([)]"
```

里面没有任何相邻的 `()`、`[]`、`{}` 可以直接删，
所以第一轮后字符串不变，说明它不合法。

---

### 为什么可行

合法括号串一定能不断拆掉最内层的一对括号；
每拆掉一层，剩下的部分仍然是合法括号串。

所以只要能一直删到空串，就说明整体合法。

---

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(n)`

因为每轮替换都可能重新扫描整条字符串，而且会创建新字符串。

---

### 评价

这是一个很适合建立直觉的保底做法，但面试里一般不会主推，
因为它没有抓住这题真正的数据结构本质。

---

## 方法二：栈里存左括号，右括号时弹出匹配（面试主推）

### 核心思路

扫描字符串时：

- 遇到左括号：先压栈，表示“它还没被匹配”
- 遇到右括号：必须和栈顶那个最近的左括号匹配

如果出现下面任何一种情况，直接返回 `False`：

1. 右括号出现时，栈是空的
2. 栈顶左括号类型不匹配
3. 扫描结束后，栈里还有剩余左括号

---

### 过程演示

看这个例子：

```text
s = "{[()]}"
```

#### 读到 `{`

栈：

```text
{
```

#### 读到 `[` 

栈：

```text
{ [
```

#### 读到 `(`

栈：

```text
{ [ (
```

#### 读到 `)`

它必须匹配栈顶 `(`，匹配成功后弹栈。

栈：

```text
{ [
```

#### 读到 `]`

匹配栈顶 `[`，弹栈。

栈：

```text
{
```

#### 读到 `}`

匹配栈顶 `{`，弹栈。

栈：

```text
空
```

扫描结束后栈为空，所以合法。

---

### 面试代码

```python
class Solution:
    def isValid(self, s: str) -> bool:
        if len(s) % 2 == 1:
            return False

        pairs = {")": "(", "]": "[", "}": "{"}
        stack = []

        for ch in s:
            if ch in pairs:
                if not stack or stack.pop() != pairs[ch]:
                    return False
            else:
                stack.append(ch)

        return not stack
```

---

### 为什么它是面试主推

### 1. 它最直接体现栈的本质

这题最重要的就是维护：

```text
最近一个还没匹配的左括号
```

而栈顶恰好就是这个东西。

### 2. 逻辑非常稳

你只需要处理三种失败情形：

- 栈空却来了右括号
- 栈顶类型不匹配
- 最后栈没清空

结构简单，面试里不容易写乱。

### 3. 它是后续很多题的起点

像：

- `32` 最长有效括号
- 表达式解析
- 标签匹配
- 编译器里的括号/语法检查

都和这套“栈维护未完成结构”的思路有关。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

这是这题最标准的复杂度。

---

### 容易出错的地方

### 1. 栈空时直接 `pop`

如果右括号先出现，比如：

```text
"]"
```

你不能直接 `pop`，要先判断栈是否为空。

### 2. 只统计数量，不管顺序

比如：

```text
([)]
```

左右括号数量都对，但顺序不合法。

所以这题绝不能只做计数。

### 3. 最后忘了检查栈是否为空

比如：

```text
"(("
```

遍历过程中不会报错，但最后仍然不合法，因为有左括号没闭合。

---

## 方法三：栈里直接压“期待出现的右括号”

### 核心思路

方法二压栈的是左括号；
方法三更进一步，遇到左括号时，直接把它未来应该匹配的右括号压入栈。

也就是：

- 看到 `(`，压入 `)`
- 看到 `[`，压入 `]`
- 看到 `{`，压入 `}`

这样当你读到一个右括号时，只要看它是否等于栈顶即可。

---

### 例子

```text
s = "([])"
```

#### 读到 `(`

栈里压入“期待的 `)`”：

```text
)
```

#### 读到 `[`

栈里再压入“期待的 `]`”：

```text
) ]
```

#### 读到 `]`

它等于栈顶期待值 `]`，弹栈。

栈：

```text
)
```

#### 读到 `)`

它等于栈顶期待值 `)`，弹栈。

最后栈空，合法。

---

### 代码

```python
class Solution:
    def isValid(self, s: str) -> bool:
        if len(s) % 2 == 1:
            return False

        expected = {"(": ")", "[": "]", "{": "}"}
        stack = []

        for ch in s:
            if ch in expected:
                stack.append(expected[ch])
            else:
                if not stack or stack.pop() != ch:
                    return False

        return not stack
```

---

### 它和方法二的关系

本质上它们是同一类解法，都是栈。

区别只在于：

- **方法二**：栈里存“已经出现的左括号”
- **方法三**：栈里存“未来应该出现的右括号”

方法三写起来更短一点，但理解门槛比方法二略高一点。

如果你是第一次学这题，我建议先吃透方法二；
如果你已经很熟栈匹配，这个版本会更顺手。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

## 三种方法的关系

- **方法一**：先建立“合法括号串可以不断消掉最内层配对”的直觉
- **方法二**：正式进入标准栈解法，主记这一版
- **方法三**：在方法二基础上，把代码再写得更紧凑一点

这题最值得记住的一句话是：

```text
不是去找“某个括号能和谁配”，而是始终维护“最近一个还没配对的左括号是谁”
```

这句话一旦想通，栈解法就很自然了。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：反复删除相邻合法括号对 | `O(n^2)` | `O(n)` | 直观保底，适合建立化简直觉 |
| 方法二：栈存左括号并弹栈匹配 | `O(n)` | `O(n)` | 面试主推，最标准的栈模板 |
| 方法三：栈存期待的右括号 | `O(n)` | `O(n)` | 同样优秀，代码更紧凑 |

---

## 总结

如果你现在只准备记一个版本：

```text
就记方法二：栈里存左括号，遇到右括号时弹出匹配
```

因为它最符合直觉、最适合第一次建立“括号匹配 = 栈”的模型。

如果你已经把这个模型吃透，再补上：

```text
方法三：栈里直接压期待的右括号
```

你写这题会更快，也更像面试里熟练状态下的写法。
