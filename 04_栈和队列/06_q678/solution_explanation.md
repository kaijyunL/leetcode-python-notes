# LeetCode 678. 有效的括号字符串

## 题目

给定一个只包含 `(`、`)` 和 `*` 的字符串 `s`，判断它是否可能是一个有效括号串。

这里 `*` 可以被看成三种角色中的任意一种：

- 左括号 `(`
- 右括号 `)`
- 空字符 `""`

也就是说，`*` 不是固定含义，而是可以按需要临时扮演不同角色。

比如：

- `"()"` 是有效的
- `"(*)"` 也是有效的，因为 `*` 可以当空串
- `"(*))"` 也是有效的，因为 `*` 可以当 `(`

---

## 这题和 `20` 最大的区别是什么

`20` 题里，每个字符身份都固定：

- `(` 就是左括号
- `)` 就是右括号

所以你只需要老老实实做匹配。

但 `678` 不一样，关键变化在于：

```text
* 不是一个确定角色，而是一个“可调整的缓冲位”
```

这会带来一个很重要的后果：

```text
扫描到当前位置时，我们未必只对应一种“还剩几个左括号没匹配”的状态，而可能对应一个范围
```

这正是这题从普通栈题，走向 **贪心上下界** 的核心原因。

---

## 先想清楚：为什么普通计数不够

如果没有 `*`，我们只要关心：

```text
当前还有多少个左括号没匹配
```

但有了 `*` 以后，同一个前缀可能有多种解释。

比如：

```text
s = "(*"
```

这里最后的 `*`：

- 可以当空串，此时还剩 `1` 个左括号
- 可以当 `)`，此时还剩 `0` 个左括号
- 可以当 `(`，此时还剩 `2` 个左括号

也就是说，扫到这里时，不是只有一个状态，而是：

```text
可能剩 0~2 个左括号没匹配
```

这题真正考的，就是你能不能识别出：

```text
我们不必精确记录“唯一状态”，而是维护一个“可行状态范围”
```

---

## 方法一：把 `*` 暴力尝试成三种角色

### 核心思路

最直接的想法就是：

- 遇到 `(`：未匹配左括号数 `+1`
- 遇到 `)`：未匹配左括号数 `-1`
- 遇到 `*`：分别尝试把它当成
  - `(`
  - `)`
  - 空串

只要三种选择里有一种最终能让整个字符串合法，就返回 `True`。

这其实就是在枚举所有可能解释。

---

### 例子

看：

```text
s = "(*)"
```

读到 `*` 时，有三条分支：

- 当 `(`：变成 `(()`
- 当 `)`：变成 `())`
- 当空串：变成 `()`

其中第三种能成功，所以答案是 `True`。

---

### 为什么它可行

因为题目本来就在问：

```text
是否存在一种对所有 * 的解释方式，使整个串合法
```

那暴力枚举当然能做对。

---

### 复杂度

- 时间复杂度：最坏 `O(3^n)`
- 空间复杂度：最坏 `O(n)`

因为每个 `*` 都可能裂成 3 条分支。

---

### 评价

这是一个很适合建立题意直觉的保底写法：

```text
* 的本质，就是一个三选一的可变角色
```

但面试里一般不会主推，因为分支爆炸太快。

---

## 方法二：两个栈分别记录 `(` 和 `*` 的位置

### 核心思路

既然 `*` 有时可以拿来顶替括号，那我们可以先尽量按“位置匹配”去处理。

扫描字符串时：

- 遇到 `(`：把下标压入 `left_stack`
- 遇到 `*`：把下标压入 `star_stack`
- 遇到 `)`：优先匹配最近的 `(`；如果没有，再拿一个 `*` 来顶替 `(`

这样先保证：

```text
每个右括号出现时，前面都能找到一个东西和它配对
```

扫描结束后，如果还有剩余的 `(`，就只能靠后面的 `*` 去顶替成 `)`。

这里有一个极关键的限制：

```text
拿来补右括号的 *，位置必须在这个 ( 的后面
```

所以最后要按下标顺序继续匹配。

---

### 过程演示

看这个例子：

```text
s = "(*))"
```

#### 读到 `(`

```text
left_stack = [0]
star_stack = []
```

#### 读到 `*`

```text
left_stack = [0]
star_stack = [1]
```

#### 读到 `)`

优先消耗左括号：

```text
left_stack = []
star_stack = [1]
```

#### 再读到 `)`

没有左括号了，就拿 `*` 顶成 `(`：

```text
left_stack = []
star_stack = []
```

最后两个栈都能处理干净，所以合法。

---

### 为什么它可行

因为这题最终还是绕不开一个事实：

```text
括号匹配不仅要数量对，还要顺序对
```

双栈写法把这两个要求拆开处理得很清楚：

- 扫描过程中，优先解决当前 `)` 的匹配问题
- 扫描结束后，再检查剩余 `(` 能不能被后面的 `*` 补成 `)`

---

### 代码

```python
class Solution:
    def checkValidString(self, s: str) -> bool:
        left_stack = []
        star_stack = []

        for i, ch in enumerate(s):
            if ch == "(":
                left_stack.append(i)
            elif ch == "*":
                star_stack.append(i)
            else:
                if left_stack:
                    left_stack.pop()
                elif star_stack:
                    star_stack.pop()
                else:
                    return False

        while left_stack and star_stack:
            if left_stack[-1] > star_stack[-1]:
                return False
            left_stack.pop()
            star_stack.pop()

        return not left_stack
```

---

### 容易出错的地方

### 1. 最后不能只看数量，还要看位置顺序

比如：

```text
s = "*()(" 
```

虽然有 `*`，也有剩余的 `(`，但前面的 `*` 不能跑到后面去当右括号。

所以必须保证：

```text
star_index > left_index
```

### 2. 遇到 `)` 时，要优先消耗真正的 `(`

因为 `(` 的匹配能力更“刚性”，`*` 更灵活。

把 `*` 留到后面，会更安全。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 评价

这是一个非常好的中间层解法：

- 仍然保留了栈匹配的结构感
- 又把 `*` 的灵活性考虑进来了

如果你刚从 `20` 过来，这个方法很适合作为桥梁。

## 方法三：贪心维护“可能剩余左括号数量”的上下界（面试主推）

### 核心思路

这题最厉害的一点在于：

```text
我们其实不需要知道“当前精确剩了几个左括号”
只需要知道“它最少可能剩多少、最多可能剩多少”
```

于是我们维护两个值：

- `low`：当前 **最少** 还可能剩几个左括号
- `high`：当前 **最多** 还可能剩几个左括号

扫描每个字符时：

### 遇到 `(`

它一定会让未匹配左括号数 `+1`：

- `low += 1`
- `high += 1`

### 遇到 `)`

它一定会让未匹配左括号数 `-1`：

- `low -= 1`
- `high -= 1`

但 `low` 不能小于 `0`，因为“最少剩几个左括号”不可能是负数。

### 遇到 `*`

它有三种身份：

- 当 `(`：让数量 `+1`
- 当 `)`：让数量 `-1`
- 当空串：让数量不变

所以它会把可行区间扩成：

- `low -= 1`
- `high += 1`

同样，`low` 也不能掉到 `0` 以下。

---

### 为什么一旦 `high < 0` 就可以立刻失败

如果连“最多可能剩几个左括号”都已经小于 `0` 了，说明：

```text
无论怎么解释前面的 *，右括号都已经多到兜不住了
```

那后面再出现什么都救不回来，直接返回 `False`。

---

### 为什么最后只要看 `low == 0`

扫描结束后：

- 如果 `low == 0`，说明存在一种解释方式，能让最终未匹配左括号数恰好为 `0`
- 如果 `low > 0`，说明无论怎么解释，至少还剩这么多个左括号没被关掉

所以最终判断条件就是：

```text
low == 0
```

---

### 过程演示

看：

```text
s = "(*))"
```

初始化：

```text
low = 0
high = 0
```

#### 读到 `(`

```text
low = 1
high = 1
```

#### 读到 `*`

它可以当 `)`、空串、`(`，所以：

```text
low = 0
high = 2
```

#### 读到 `)`

```text
low = 0
high = 1
```

#### 再读到 `)`

```text
low = 0
high = 0
```

扫描结束后 `low == 0`，说明存在合法解释，答案是 `True`。

---

### 为什么这是面试主推

### 1. 它最直接抓住了这题真正的本质

这题最难的地方，不是“怎么匹配括号”，而是：

```text
* 会让状态不再唯一，而是变成一个可能范围
```

方法三正面处理了这个范围。

### 2. 它把指数级分支压缩成了一个区间

暴力法在枚举很多可能；
贪心法的高明之处在于：

```text
把所有可能状态压缩成 [low, high] 这个区间
```

这就是这题最值得学的技巧。

### 3. 复杂度最优而且代码最短

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

每个字符只处理一次，也不用额外栈。

### 4. 特别适合讲“为什么贪心成立”

这题不是拍脑袋贪，而是因为：

- `low` 保存最乐观的下界
- `high` 保存最宽松的上界
- 只要区间没有断掉，就说明仍然有合法解释存在

这个逻辑非常完整。

---

### 面试代码

```python
class Solution:
    def checkValidString(self, s: str) -> bool:
        low = 0
        high = 0

        for ch in s:
            if ch == "(":
                low += 1
                high += 1
            elif ch == ")":
                low = max(low - 1, 0)
                high -= 1
            else:
                low = max(low - 1, 0)
                high += 1

            if high < 0:
                return False

        return low == 0
```

---

### 容易出错的地方

### 1. `low` 要随时夹到 `0`

因为“最少剩余左括号数”不可能为负。

所以：

```python
low = max(low - 1, 0)
```

是关键细节。

### 2. 提前失败要看 `high < 0`

不能看 `low < 0`。

因为 `low` 只是最小可能值；
真正表示“所有可能都没救了”的，是连最大可能值 `high` 都已经小于 `0`。

### 3. 最后判断要看 `low == 0`

不是看 `high == 0`。

因为 `high` 只表示“最多可能剩多少”，不代表一定能刚好收束为 `0`。

---

## 三种方法的关系

- **方法一**：先理解 `*` 真的是三选一角色
- **方法二**：把这题重新拉回“按位置做括号匹配”的栈视角
- **方法三**：正式抓住题目本质，把所有可能状态压缩成一个可行区间

这题最值得记住的一句话是：

```text
678 真正维护的，不是某一个确定的未匹配左括号数量，而是“它还可能落在哪个范围里”
```

这句话一旦想通，贪心上下界就会非常自然。
