# LeetCode 234. 回文链表（Palindrome Linked List）解析

## 题目描述

给你一个链表的头节点 `head`，请你判断这个链表是否是回文链表。

回文的意思是：

```text
正着读和反着读都一样
```

例如：

```text
1 -> 2 -> 2 -> 1
```

是回文。

而：

```text
1 -> 2
```

就不是回文。

---

## 先理解这题在考什么

这题表面上是在判断“链表是不是回文”，但真正考的是一组组合能力：

```text
快慢指针找中点 + 反转链表 + 两段链表逐个比较
```

数组题里判断回文很简单，因为可以双指针从两端往中间收。

但链表不支持随机访问，你没法直接拿到“最右边那个节点”。

所以这题的核心难点其实是：

```text
怎么在链表里拿到“后半部分的逆序视角”
```

而最经典的办法就是：

1. 用快慢指针找到中点
2. 把后半段链表反转
3. 然后让前半段和反转后的后半段逐个比较

这就是这题真正的标准解。

---

## 方法一：复制到数组后双端比较

### 思路

最直观的方法是：

1. 先把链表所有值抄到数组里
2. 然后像普通数组回文判断那样，用左右双指针比较

例如：

```text
1 -> 2 -> 3 -> 2 -> 1
```

抄到数组里就是：

```text
[1, 2, 3, 2, 1]
```

这时就可以直接比较：

- `1 == 1`
- `2 == 2`
- 中间 `3` 不用管

全部相等就是回文。

---

### 代码

```python
class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        values = []
        cur = head

        while cur:
            values.append(cur.val)
            cur = cur.next

        left = 0
        right = len(values) - 1

        while left < right:
            if values[left] != values[right]:
                return False
            left += 1
            right -= 1

        return True
```

---

### 为什么可行

因为数组天然支持从左端和右端同时访问。

一旦链表被转成数组，问题就退化成最熟悉的：

```text
判断数组是不是回文
```

所以这个方法很适合建立第一直觉。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 它的不足

这个方法虽然简单，但没有用上这题真正想考的链表技巧。

面试官如果继续追问“能不能用 `O(1)` 额外空间”，你还是得回到方法二。

---

## 方法二：快慢指针 + 反转后半段 + 逐个比较（面试主推）

### 核心思路

因为链表不能直接从尾部往前看，所以我们换个思路：

```text
把后半段链表原地反转，让它变成“可以从前往后比较”的样子
```

整个过程分四步：

1. 用快慢指针找到前半段结尾
2. 反转后半段链表
3. 从头部和后半段新头同时往后比
4. 比完后把链表恢复回来（更稳、更完整）

这题最关键的转化就是：

```text
不能直接从尾巴往前比，那就把后半段反过来，再从前往后比
```

---

## 为什么快慢指针能找到合适的切分点

让 `slow` 每次走一步，`fast` 每次走两步。

当 `fast` 到末尾时，`slow` 就走到了中间附近。

为了让代码更稳定，我们常写成：

```python
while fast.next and fast.next.next:
    slow = slow.next
    fast = fast.next.next
```

这样循环结束后：

- 如果链表长度是偶数，`slow` 停在前半段最后一个节点
- 如果链表长度是奇数，`slow` 停在正中间节点

于是：

```text
从 slow.next 开始反转，刚好就是“后半段”
```

这也是为什么奇数长度时，中间那个节点天然会被跳过，不需要单独参与比较。

---

## 用例子走一遍

假设链表是：

```text
1 -> 2 -> 3 -> 2 -> 1
```

### 第 1 步：找中点

快慢指针结束后：

```text
slow 停在值为 3 的节点
```

所以后半段是：

```text
2 -> 1
```

### 第 2 步：反转后半段

反转后变成：

```text
1 -> 2
```

### 第 3 步：前后比较

前半段从头开始：

```text
1 -> 2 -> 3 -> ...
```

后半段从反转后的头开始：

```text
1 -> 2
```

逐个比较：

- `1 == 1`
- `2 == 2`

全部匹配，所以它是回文。

注意这里只需要比较后半段的长度，因为后半段更短。

---

### 面试代码

```python
class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        if head is None or head.next is None:
            return True

        first_half_end = self._find_first_half_end(head)
        second_half_start = self._reverse_list(first_half_end.next)

        palindrome = True
        p1 = head
        p2 = second_half_start

        while p2:
            if p1.val != p2.val:
                palindrome = False
                break
            p1 = p1.next
            p2 = p2.next

        first_half_end.next = self._reverse_list(second_half_start)
        return palindrome
```

---

## 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 真正用到了链表核心技巧

这题本质不是“会不会判断回文”，而是：

```text
会不会在链表里做中点定位、局部反转和分段比较
```

方法二刚好把这些能力都练到了。

### 2. 额外空间最优

除了少量指针变量，没有再开数组。

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这就是题目进阶最想要的答案。

### 3. 结构清晰，容易讲

这套模板非常适合面试口述：

```text
找中点 -> 反转后半段 -> 前后比较 -> 恢复链表
```

不容易乱，而且每一步都能说出目的。

---

## 为什么比较完最好恢复链表

LeetCode 一般只看返回值，很多写法比较完不恢复也能通过。

但从代码习惯上说，恢复更完整，因为：

- 不会破坏原链表结构
- 逻辑更闭环
- 面试里会显得更细致

所以我这里主推版本把恢复也写进去了。

如果你时间特别紧，也可以先写不恢复版本，等主逻辑写对以后再补。

---

### 容易出错的地方

### 1. 找中点时循环条件写错

如果你直接写成：

```python
while fast and fast.next:
```

那得到的 `slow` 更像“后半段起点”，而不是“前半段结尾”。

这不是一定错，但要和后面“从哪里开始反转”配套。

我这里采用的是更稳定的一套：

```python
while fast.next and fast.next.next:
```

然后从 `slow.next` 开始反转。

### 2. 奇数长度时把中间节点也拿去比较

比如：

```text
1 -> 2 -> 3 -> 2 -> 1
```

中间的 `3` 不需要参与比较。

如果切分点不对，就容易把它算进去，导致逻辑绕乱。

### 3. 反转完忘了保存头节点

比较时，应该让一个指针从 `head` 出发，另一个从：

```text
反转后的后半段头节点
```

出发。

如果没把这个新头存下来，后面就没法比较。

### 4. 比较长度写成整条链表长度

后半段长度更短，所以写：

```python
while p2:
```

最自然。

只要后半段全部匹配，就已经够说明是回文了。

---

### 面试里怎么讲

你可以这样解释：

```text
链表没法像数组那样从两端往中间直接比较，所以我先用快慢指针找到中点，再把后半段原地反转。这样前半段和反转后的后半段就都能从前往后走了。我再用两个指针逐个比较节点值，如果都相同就是回文。比较结束后我再把后半段反转回来，恢复原链表。整个过程只遍历几次链表，时间复杂度 O(n)，额外空间复杂度 O(1)。
```

这就是这题最标准的讲法。

## 方法三：递归做对称比较（补充理解）

### 思路

递归的想法是：

```text
先一路递归到链表尾部，再在回溯时和头部指针同步比较
```

你可以把它理解成“用递归调用栈模拟从右往左访问节点”。

做法是：

1. 用一个成员变量 `front` 指向头节点
2. 递归函数先走到最尾部
3. 回溯时，当前节点相当于从右往左回来
4. 每次拿 `front.val` 和当前回溯节点的值比较
5. 比完后让 `front` 往后走一格

这样就实现了“左边一个、右边一个”的对称检查。

---

### 代码

```python
class Solution:
    def isPalindrome(self, head: Optional[ListNode]) -> bool:
        self.front = head

        def dfs(node: Optional[ListNode]) -> bool:
            if node is None:
                return True

            if not dfs(node.next):
                return False

            if self.front.val != node.val:
                return False

            self.front = self.front.next
            return True

        return dfs(head)
```

---

### 为什么可行

因为递归深入到底以后，回溯顺序正好是：

```text
尾节点 -> 倒数第二个节点 -> ... -> 头节点
```

而 `front` 一直是：

```text
头节点 -> 第二个节点 -> ... -> 尾节点
```

于是它们就形成了一一对应的对称比较。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

额外空间来自递归调用栈。

---

### 它适合什么时候学

它适合作为：

- 帮你理解“回文判断本质上是左右对称比较”
- 练习链表递归写法
- 看懂别人题解里的递归版本

但如果你现在只准备记一个版本：

```text
还是优先记方法二
```

---

## 三种方法的关系

这题三种做法的递进关系很清楚：

- **方法一**：先转数组，再做最熟悉的双端比较
- **方法二**：链表原地找中点、反转后半段并比较，这是面试主推
- **方法三**：借助递归回溯做左右对称比较

这题最值得抓住的一句话是：

```text
链表不能直接从尾部往前看，所以就把后半段反转过来，再和前半段从左到右比较
```

只要这句话真的想通，方法二就会很自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：复制到数组后双端比较 | `O(n)` | `O(n)` | 最直观，适合建立第一感觉 |
| 方法二：快慢指针 + 反转后半段 + 比较 | `O(n)` | `O(1)` | 面试主推 |
| 方法三：递归做对称比较 | `O(n)` | `O(n)` | 有助于理解，但栈空间更高 |

## 总结

这题最重要的不是死记步骤，而是想清楚：

```text
链表不方便从两端同时读，所以必须把“后半段”变成一个也能从前往后读的结构。
```

而最经典的办法就是：

```text
快慢指针找中点 + 反转后半段 + 前后逐个比较
```

如果你现在只准备记一个版本：

```text
就记方法二：快慢指针 + 反转后半段 + 逐个比较
```
