# LeetCode 25. K 个一组翻转链表（Reverse Nodes in k-Group）解析

## 题目描述

给你链表头节点 `head`，每 `k` 个节点一组进行翻转，请你返回修改后的链表。

注意两点：

- `k` 是正整数
- 如果最后剩下的节点数不足 `k` 个，就保持原顺序不动

例如：

```text
head = 1 -> 2 -> 3 -> 4 -> 5, k = 2
```

结果是：

```text
2 -> 1 -> 4 -> 3 -> 5
```

再比如：

```text
head = 1 -> 2 -> 3 -> 4 -> 5, k = 3
```

结果是：

```text
3 -> 2 -> 1 -> 4 -> 5
```

这题的关键不是“整条链表反转”，而是：

```text
按长度为 k 的小段，一段一段地判断、翻转、再接回去
```

这就是它和 `206`、`24`、`92` 的最大区别。

---

## 先理解这题到底在考什么

很多人第一次看这题，会直接想到：

```text
反转链表，不就是 206 吗？
```

但这题并不是把整条链表一次性反过来。

它更像是在问你：

```text
如果我把链表切成一段一段，每段长度是 k，你能不能只反转完整的一段，并且把前后重新接好吗？
```

所以这题真正考的是三件事：

- 你能不能找到当前这一组的边界
- 你会不会对“局部链表”做反转
- 你能不能把翻转后的这一组和前后链表重新接回去

也就是说，这题的本质是：

```text
分组反转 + 指针重连
```

---

## 这题和 `206`、`24`、`92` 的关系

这题非常适合和前面几道反转题一起看。

### 和 `206` 的关系

`206` 是：

```text
整条链表反转
```

`25` 则是：

```text
每次只拿出一小段长度为 k 的链表，局部做一次 206，再接回原链表
```

所以你完全可以把这题理解成：

```text
25 = 找出一组长度为 k 的小链表 + 对这组做 206 + 接回去 + 继续下一组
```

### 和 `24` 的关系

`24` 是两两交换节点。

如果你把 `25` 的 `k` 固定成 `2`，那它本质上就变成了：

```text
每 2 个一组翻转
```

也就是 `24` 的更一般版本。

### 和 `92` 的关系

`92` 是：

```text
把指定区间 [left, right] 反转一次
```

`25` 则是：

```text
不断地对多个固定长度区间重复做反转
```

所以这题可以看成“局部反转题族”的综合版。

---

## 为什么这题的难点不在“反转”，而在“分组”

如果只看单组反转，其实就是 `206` 的内容。

真正麻烦的是：

### 1. 你得先确认当前剩余节点够不够 `k` 个

如果不够，就不能反转，必须原样保留。

### 2. 你得把这一组从原链表里逻辑上隔离出来

不管你是“真的切断”还是“用 stop 边界控制”，本质都是在做这件事。

### 3. 你得把翻转后的头尾重新接回整条链表

也就是：

- 前一段尾巴接翻转后新头
- 翻转后新尾接下一段头

这才是这题最容易乱的地方。

所以这题最该记住的一句话是：

```text
反转本身不是最难的，难的是先找准这一组、再把这一组前后重新接好
```

---

## 为什么 `dummy` 在这题里几乎是必备的

这题很容易出现一个边界：

```text
第一组反转后，整条链表的头节点会变
```

例如：

```text
1 -> 2 -> 3 -> 4 -> 5, k = 2
```

第一组翻转后就会变成：

```text
2 -> 1 -> 3 -> 4 -> 5
```

也就是说原来的 `head = 1` 已经不是新头了。

如果没有 `dummy`，你就得不断处理：

- 新头是谁
- 第一组和后续组的连接是否统一
- 返回时到底返回哪个节点

所以最稳的写法通常一定会先加：

```text
dummy -> head
```

这样无论当前处理的是第一组还是中间组，逻辑都统一了。

---

## 方法一：收集节点后按组反转再重连

### 思路

最直观的保底方法是：

1. 先遍历链表，把所有节点收集到数组中
2. 按每 `k` 个节点分组
3. 如果当前组长度正好是 `k`，就在数组里把这组节点顺序反过来
4. 最后按数组里的顺序把所有节点重新串起来

例如：

```text
1 -> 2 -> 3 -> 4 -> 5, k = 2
```

收集后是：

```text
[1, 2, 3, 4, 5]
```

按组反转后变成：

```text
[2, 1, 4, 3, 5]
```

再按这个顺序重连即可。

---

### 代码

```python
class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        if head is None or k <= 1:
            return head

        nodes = []
        cur = head
        while cur:
            nodes.append(cur)
            cur = cur.next

        for i in range(0, len(nodes), k):
            if i + k <= len(nodes):
                nodes[i : i + k] = reversed(nodes[i : i + k])

        for i in range(len(nodes) - 1):
            nodes[i].next = nodes[i + 1]

        if nodes:
            nodes[-1].next = None
            return nodes[0]
        return None
```

---

### 为什么可行

因为数组已经把节点顺序明确地表示出来了。

只要你在数组层面把每个完整长度为 `k` 的分组顺序翻转，再把节点按新顺序连回去，最终链表顺序就正确。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 它的不足

这个方法很好想，但不是面试最值得主记的版本。

因为：

### 1. 它没有真正训练到链表局部反转

它更像是在“借数组改顺序”。

### 2. 它用了额外 `O(n)` 空间

和这题更有价值的原地解法相比，不够漂亮。

所以这题真正该掌握的还是方法二。

---

## 方法二：找到一整组后切断，按 `206` 反转再接回（面试主推）

### 核心思路

这题最标准、最值得主记的版本，就是：

```text
先找到这一组的第 k 个节点 -> 把这一组切成独立小链表 -> 用 206 反转 -> 再把前后接回去
```

整个过程可以拆成 5 步：

1. 用 `pre` 站在当前组前面
2. 从 `pre` 往后走 `k` 步，找到这一组的尾节点 `kth`
3. 如果找不到，说明剩余节点不足 `k` 个，直接结束
4. 记住下一组起点 `group_next = kth.next`，再把当前组切断
5. 对当前组做一次 `206` 风格反转，然后把翻转后的头尾重新接回

也就是说，核心不是整条链表一起处理，而是反复做：

```text
找一组 -> 反转这一组 -> 接回去
```

---

## 为什么这个思路很自然

因为你已经知道：

```text
整条链表反转 = 206
```

那现在题目只是额外加了一个条件：

```text
每次只准反转 k 个，而且最后不够 k 个的不反转
```

于是最自然的想法就是：

- 我先把这一组找出来
- 只对这一组做 `206`
- 做完再接回整条链表

这其实是把大题拆回熟悉的小题。

所以这题最值得记的一句话就是：

```text
25 题本质上是在反复调用“长度为 k 的局部 206”
```

---

## 用例子完整走一遍

假设：

```text
head = 1 -> 2 -> 3 -> 4 -> 5
k = 2
```

加上哑节点以后：

```text
dummy -> 1 -> 2 -> 3 -> 4 -> 5
```

开始时：

- `pre = dummy`

### 第 1 组：`1 -> 2`

从 `pre` 开始往后走 2 步，找到：

```text
kth = 2
```

下一组起点是：

```text
group_next = 3
```

把当前组切断：

```text
1 -> 2 -> None
```

对这组做 `206` 反转后得到：

```text
2 -> 1
```

再接回去：

```text
dummy -> 2 -> 1 -> 3 -> 4 -> 5
```

这时：

- 翻转后新尾巴其实是原来的 `1`
- 所以下一轮让 `pre = 1`

### 第 2 组：`3 -> 4`

同样找到：

```text
kth = 4
```

下一组起点：

```text
group_next = 5
```

切断并反转后得到：

```text
4 -> 3
```

接回去：

```text
dummy -> 2 -> 1 -> 4 -> 3 -> 5
```

### 第 3 组：只剩 `5`

这时剩余节点不足 `k = 2` 个。

所以：

```text
保持原样，不再反转
```

最终答案就是：

```text
2 -> 1 -> 4 -> 3 -> 5
```

---

### 面试代码

```python
class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        if head is None or k <= 1:
            return head

        dummy = ListNode(0, head)
        pre = dummy

        while True:
            kth = self.get_kth(pre, k)
            if kth is None:
                break

            group_head = pre.next
            group_next = kth.next
            kth.next = None

            new_head = self.reverse_list(group_head)
            pre.next = new_head
            group_head.next = group_next

            pre = group_head

        return dummy.next

    def get_kth(self, start: ListNode, k: int) -> Optional[ListNode]:
        cur = start
        for _ in range(k):
            cur = cur.next
            if cur is None:
                return None
        return cur

    def reverse_list(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev = None
        cur = head
        while cur:
            next_node = cur.next
            cur.next = prev
            prev = cur
            cur = next_node
        return prev
```

---

### 为什么可行

因为每一轮开始时，我们都能保证：

```text
pre 后面是还没处理的链表，dummy 到 pre 这一段已经是答案的正确前缀
```

然后：

- 如果后面还能凑出完整 `k` 个节点，就把这一组正确翻转并接回
- 如果凑不出，就说明剩余部分必须保留原样

这样每轮都把答案正确地向后推进，最终整个链表就是正确结果。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这是这题最经典、最推荐现场手写的版本。

---

### 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 它把题目拆成了熟悉的小问题

- 找 `k` 个节点
- 做一次 `206`
- 接回去

逻辑非常顺。

### 2. 它的结构最稳

有了 `dummy` 和 `pre`，第一组和中间组的处理完全统一。

### 3. 它最能体现“分组反转”的本质

这题最重要的不是背某个花哨写法，而是建立这个过程感：

```text
每次只处理一组完整区间
```

### 4. 复杂度最漂亮

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 容易出错的地方

### 1. 没先判断当前剩余节点是否够 `k` 个

不足 `k` 个就必须原样保留，不能硬反转。

### 2. 反转前忘了保存 `group_next`

一旦你切断或开始反转，不提前保存下一组起点，就容易把后面的链表丢掉。

### 3. 接回去时把新尾巴搞错

反转前的 `group_head`，反转后会变成：

```text
当前组的新尾巴
```

所以应该由它去接 `group_next`。

### 4. 翻转完后 `pre` 更新错了

翻转后新的 `pre` 应该移动到当前组的新尾，也就是原来的 `group_head`。

---

## 方法三：递归处理每一组，按 `[head, stop)` 反转区间

### 核心思路

除了“切断后反转再接回”的写法，这题还可以写成很漂亮的递归版本。

思路是：

1. 先从 `head` 出发看后面有没有完整 `k` 个节点
2. 如果不够，直接返回 `head`
3. 如果够，就把前 `k` 个节点这个区间 `[head, stop)` 反转
4. 让反转后的尾节点（原来的 `head`）去接递归处理后的剩余部分

也就是说：

```text
先处理当前这一组，再把后面的答案递归接上
```

这里最关键的技巧是区间写法：

```text
反转 [head, stop)
```

也就是：

- 包含 `head`
- 不包含 `stop`

这样循环条件非常干净。

---

## 为什么这个写法值得学

因为它把问题表达得特别整洁：

```text
当前这一组如果够 k 个，就先反转这一组；后面的部分继续递归做同样的事
```

这和很多链表递归题的结构很像。

而且 `[head, stop)` 这种区间写法也很值得掌握，
在链表局部反转题里很常见。

---

### 代码

```python
class Solution:
    def reverseKGroup(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        if head is None or k <= 1:
            return head

        stop = head
        for _ in range(k):
            if stop is None:
                return head
            stop = stop.next

        new_head = self.reverse_range(head, stop)
        head.next = self.reverseKGroup(stop, k)
        return new_head

    def reverse_range(
        self,
        start: Optional[ListNode],
        stop: Optional[ListNode],
    ) -> Optional[ListNode]:
        prev = stop
        cur = start

        while cur is not stop:
            next_node = cur.next
            cur.next = prev
            prev = cur
            cur = next_node

        return prev
```

---

### 为什么可行

因为每一层递归都在做同一件事：

```text
如果当前开始的这段够 k 个，就先把这 k 个正确反转，再把剩余链表的答案接到这一组尾巴上
```

而 `reverse_range(head, stop)` 保证了当前这一组会被完整反转，
之后原来的 `head` 变成这组的新尾，再去连接递归结果。

所以整条链表会一组一组正确拼起来。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n / k)` 到 `O(n)`

更准确地说，额外空间来自递归调用栈；
递归层数大约是分组数，也就是 `n / k` 级别。

---

### 它适合什么时候记

它非常适合作为：

- 对方法二的递归表达补充
- 理解链表半开区间 `[head, stop)`
- 练递归视角下的局部反转

但如果你现在只准备记一个最稳版本：

```text
还是优先记方法二
```

因为方法二更稳、更直观，也更适合现场写。

---

## 三种方法的关系

这题三种做法的递进关系很清楚：

- **方法一**：先把节点收集出来，按组改顺序再重连，属于保底做法
- **方法二**：找到完整一组后切断，按 `206` 反转再接回，这是面试主推
- **方法三**：把同样的分组反转过程写成递归版，强调 `[head, stop)` 区间思维

这题最值得抓住的一句话是：

```text
25 题不是“把链表反转”，而是“反复找到完整的 k 个节点区间，对这个区间做局部反转，然后把前后重新接好”
```

只要这句话真正想通，方法二就会非常自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：收集节点后按组反转再重连 | `O(n)` | `O(n)` | 最直观，但不是真正原地分组反转 |
| 方法二：找到整组后切断并按 `206` 反转接回 | `O(n)` | `O(1)` | 面试主推 |
| 方法三：递归按 `[head, stop)` 反转每组 | `O(n)` | 递归栈 `O(n / k)` | 表达优雅，适合理解递归版 |

---

## 总结

这题最重要的，不是背某个长模板，而是先建立这个过程感：

```text
先判断这一组够不够 k 个；够的话只反转这一组；翻转后记得把前面、当前组、后面三部分重新接回
```

如果你现在只准备记一个版本：

```text
就记方法二：找到整组后切断，按 206 反转再接回
```

因为它最能把 `206`、分组边界判断、以及链表重连这三个核心动作清楚地串起来。
