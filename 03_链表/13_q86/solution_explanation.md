# LeetCode 86. 分隔链表（Partition List）解析

## 题目描述

给你一个链表的头节点 `head`，以及一个整数 `x`。

请你把链表重新分隔成两部分：

- 所有 **小于 `x`** 的节点放前面
- 所有 **大于等于 `x`** 的节点放后面

并且题目还特别强调：

```text
两个分区内部的相对顺序都必须保持不变
```

例如：

```text
head = 1 -> 4 -> 3 -> 2 -> 5 -> 2
x = 3
```

答案应该是：

```text
1 -> 2 -> 2 -> 4 -> 3 -> 5
```

注意这里不是把链表排序了，而是：

- 小于 `3` 的节点：`1, 2, 2`
- 大于等于 `3` 的节点：`4, 3, 5`

然后把这两段按原相对顺序拼起来。

---

## 先理解这题到底在考什么

这题表面上看起来像“重排链表”，但真正考的是：

```text
你能不能在遍历链表时，把节点稳定地分流到两条子链表里，再把它们接起来
```

这里最重要的不是“分成前后两部分”，而是：

```text
稳定
```

也就是：

- 所有 `< x` 的节点，彼此先后顺序不能乱
- 所有 `>= x` 的节点，彼此先后顺序也不能乱

所以这题不是在做：

```text
排序
```

而是在做：

```text
稳定分区（stable partition）
```

这个区别一定要先想清楚。

---

## 为什么这题不能简单理解成“排序”

很多人第一次看这题，会下意识觉得：

```text
把小的放前面，大的放后面，不就是某种排序吗？
```

其实不是。

比如：

```text
1 -> 4 -> 3 -> 2 -> 5 -> 2, x = 3
```

如果真的排序，结果会更接近：

```text
1 -> 2 -> 2 -> 3 -> 4 -> 5
```

但题目答案是：

```text
1 -> 2 -> 2 -> 4 -> 3 -> 5
```

因为这里要求保留原本相对顺序：

- `4` 原本在 `3` 前面，所以在后半段里也必须 `4` 在 `3` 前面
- 两个 `2` 原本的先后顺序也不能变

所以这题真正的关键词是：

```text
按条件分流，但不打乱各自内部顺序
```

一旦这句话想通，方法二就会非常自然。

---

## 为什么“双链表分流”是最自然的思路

既然要求是：

- 把 `< x` 的放前面
- 把 `>= x` 的放后面
- 两边内部都保持原顺序

那最自然的做法就是准备两条链表：

- `less`：专门接收所有 `< x` 的节点
- `greater_or_equal`：专门接收所有 `>= x` 的节点

遍历原链表时：

- 当前节点 `< x`，就接到 `less` 尾部
- 当前节点 `>= x`，就接到 `greater_or_equal` 尾部

因为我们始终都是：

```text
按遍历顺序追加到尾部
```

所以每个分区内部的相对顺序会天然保留。

最后再做一件事：

```text
把 less 链表尾部接到 greater_or_equal 链表头部
```

答案就出来了。

这就是这题最标准的主线。

---

## 为什么这题和 `21` 有点像

你可以把它和 `21` 合并两个有序链表对比着看。

- `21`：每次从两条链表里选一个接到结果后面
- `86`：每次根据条件，把当前节点接到两条链表中的一条后面

它们的共同点是：

```text
都在维护多个链表尾部，并不断把节点接到某条链表末尾
```

所以这题也非常适合继续练熟：

- `dummy` 哑节点
- `tail` 尾指针
- 最后把多条链表拼起来

---

## 方法一：收集值后重建链表

### 思路

最直观的保底方法是：

1. 先把原链表的值全部收集到数组里
2. 按顺序把 `< x` 的值放进前半段数组
3. 再把 `>= x` 的值放进后半段数组
4. 根据新顺序重建一条新链表

例如：

```text
1 -> 4 -> 3 -> 2 -> 5 -> 2, x = 3
```

先收集出：

```text
[1, 4, 3, 2, 5, 2]
```

再分成：

```text
less = [1, 2, 2]
greater_or_equal = [4, 3, 5]
```

拼起来就是：

```text
[1, 2, 2, 4, 3, 5]
```

然后按这个顺序重建链表。

---

### 代码

```python
class Solution:
    def partition(self, head: Optional[ListNode], x: int) -> Optional[ListNode]:
        values = []
        cur = head

        while cur:
            values.append(cur.val)
            cur = cur.next

        ordered = [value for value in values if value < x]
        ordered += [value for value in values if value >= x]

        dummy = ListNode(0)
        tail = dummy
        for value in ordered:
            tail.next = ListNode(value)
            tail = tail.next

        return dummy.next
```

---

### 为什么可行

因为数组阶段已经把最终顺序排好了。

只要你：

- 先按原顺序挑出所有 `< x`
- 再按原顺序挑出所有 `>= x`

那拼起来的顺序就一定满足题意。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 它的不足

这个方法当然能做，但最大问题是：

```text
没有真正练到链表题最核心的指针分流能力
```

它更像是“先把链表转成数组再处理”。

而这题最值得掌握的，其实是：

```text
直接在链表上把节点分到两条子链表里
```

所以面试里更推荐方法二。

---

## 方法二：双链表分割合并（面试主推）

### 核心思路

这题最标准的做法就是：

```text
一边遍历原链表，一边把节点稳定地分流到 less 和 greater_or_equal 两条链表
```

我们准备四个关键变量：

- `less_dummy`：小于区链表的哑节点
- `greater_dummy`：大于等于区链表的哑节点
- `less_tail`：小于区当前尾节点
- `greater_tail`：大于等于区当前尾节点

然后遍历原链表：

- 如果 `cur.val < x`，把它接到 `less_tail` 后面
- 否则把它接到 `greater_tail` 后面

遍历完成后：

1. 先把后半段尾部断开：`greater_tail.next = None`
2. 再把前半段尾部连到后半段头：`less_tail.next = greater_dummy.next`

最后返回：

```text
less_dummy.next
```

---

## 为什么这个思路能想到

因为题目要求的不是复杂重排，而只是：

```text
按一个条件把节点分成两组，并且每组内部保持原顺序
```

而“保持原顺序”最自然的做法就是：

```text
谁先遍历到，就谁先追加到对应链表尾部
```

这和数组里常见的“稳定分区”思路是一样的。

只不过在链表里，你不需要移动数组元素，而是直接改：

```text
next 指针
```

这就是这题的本质。

---

## 用例子走一遍

假设：

```text
head = 1 -> 4 -> 3 -> 2 -> 5 -> 2
x = 3
```

开始时：

```text
less_dummy -> None
greater_dummy -> None
less_tail = less_dummy
greater_tail = greater_dummy
```

### 第 1 个节点：`1`

因为 `1 < 3`，把它接到 `less` 链表尾部：

```text
less: 1
greater: 空
```

### 第 2 个节点：`4`

因为 `4 >= 3`，接到 `greater` 链表尾部：

```text
less: 1
greater: 4
```

### 第 3 个节点：`3`

因为 `3 >= 3`，继续接到 `greater` 尾部：

```text
less: 1
greater: 4 -> 3
```

### 第 4 个节点：`2`

因为 `2 < 3`，接到 `less` 尾部：

```text
less: 1 -> 2
greater: 4 -> 3
```

### 第 5 个节点：`5`

接到 `greater` 尾部：

```text
less: 1 -> 2
greater: 4 -> 3 -> 5
```

### 第 6 个节点：`2`

接到 `less` 尾部：

```text
less: 1 -> 2 -> 2
greater: 4 -> 3 -> 5
```

### 最后拼接

先把：

```text
greater_tail.next = None
```

再做：

```text
less_tail.next = greater_dummy.next
```

最终得到：

```text
1 -> 2 -> 2 -> 4 -> 3 -> 5
```

这正好是答案。

---

### 面试代码

```python
class Solution:
    def partition(self, head: Optional[ListNode], x: int) -> Optional[ListNode]:
        less_dummy = ListNode(0)
        greater_dummy = ListNode(0)
        less_tail = less_dummy
        greater_tail = greater_dummy

        cur = head
        while cur:
            if cur.val < x:
                less_tail.next = cur
                less_tail = less_tail.next
            else:
                greater_tail.next = cur
                greater_tail = greater_tail.next
            cur = cur.next

        greater_tail.next = None
        less_tail.next = greater_dummy.next
        return less_dummy.next
```

---

## 为什么 `greater_tail.next = None` 非常重要

这是这题最容易被忽略、但也最容易出 bug 的地方。

因为我们在分流时，接到 `greater` 链表里的节点，原本的 `next` 指针还保留着原链表里的连接关系。

如果最后不手动断开，可能出现这种情况：

```text
后半段末尾节点，仍然指回某个已经被接进前半段的节点
```

于是链表就可能形成环。

例如：

```text
1 -> 4 -> 3 -> 2, x = 3
```

分流后：

- `less` 想要的是：`1 -> 2`
- `greater` 想要的是：`4 -> 3`

但原链表里 `3.next` 其实还是 `2`。

如果你忘了：

```text
greater_tail.next = None
```

最后再把 `2` 接到 `4 -> 3` 前面，就会出现：

```text
1 -> 2 -> 4 -> 3 -> 2 -> 4 -> 3 -> ...
```

也就是死循环。

所以这句不是“可有可无的收尾”，而是：

```text
保证链表结构正确的关键一步
```

---

## 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 完全贴合题目本质

这题不是排序，也不是复杂反转，它本质就是：

```text
稳定分流 + 最后拼接
```

方法二把这个本质表达得最直接。

### 2. 内部顺序天然保留

因为所有节点都是：

```text
按原遍历顺序追加到各自链表尾部
```

所以不需要额外处理“相对顺序保持”这个要求。

### 3. 复杂度最好

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这里只用了常数个指针，没有新开和 `n` 成比例的辅助结构。

### 4. 还能顺带练熟链表拼接能力

这题会反复训练你：

- 怎么维护一条链表尾部
- 怎么把一个节点安全接到尾部
- 怎么把两条链表拼起来
- 怎么避免尾部没断开导致成环

这几件事在后面的链表题里会反复出现。

---

### 容易出错的地方

### 1. 忘了后半段尾部要断开

也就是前面说的：

```python
greater_tail.next = None
```

少了这句，代码可能运行看似正常，但某些用例会形成环。

### 2. 以为需要新建节点

其实完全不用。

这题更自然的做法是：

```text
直接复用原链表节点，只改 next 指针
```

### 3. 误以为这题会打乱内部顺序

不会。

因为我们一直都是“遇到谁，就把谁追加到对应链表尾部”，
所以稳定性是天然满足的。

### 4. 遍历时把当前节点弄丢

如果你在一些变体写法里会主动断链，那一定要先保存：

```python
next_node = cur.next
```

否则当前节点一旦被你摘下来，后面的链表就找不到了。

---

### 面试里怎么讲

你可以这样解释：

```text
这题不是排序，而是稳定分区。我会准备两条辅助链表，一条收集所有小于 x 的节点，一条收集所有大于等于 x 的节点。遍历原链表时，如果当前节点小于 x，就把它追加到 less 链表尾部，否则追加到 greater 链表尾部。因为始终是按遍历顺序追加，所以两个分区内部的相对顺序都会被保留。遍历结束后，我先把 greater 链表尾部断开，避免形成环，再把 less 链表尾部接到 greater 链表头部，最后返回 less_dummy.next。这样时间复杂度 O(n)，额外空间复杂度 O(1)。
```

这就是这题最标准的说法。

---

## 方法三：先断链再分流的安全写法（补充理解）

### 思路

方法二已经足够好，但还有一种很值得看的变体：

```text
每次取出当前节点时，先把它从原链表里摘干净，再接到对应子链表尾部
```

也就是：

1. 先保存 `next_node = cur.next`
2. 再做 `cur.next = None`
3. 然后根据 `cur.val < x` 还是 `>= x`，把它接到对应链表尾部
4. 最后 `cur = next_node`

这样写的好处是：

```text
每个被接入子链表的节点，next 指针都是干净的
```

于是最后甚至不需要额外再写一次：

```python
greater_tail.next = None
```

因为这些节点在接进去之前就已经断干净了。

---

### 代码

```python
class Solution:
    def partition(self, head: Optional[ListNode], x: int) -> Optional[ListNode]:
        less_dummy = ListNode(0)
        greater_dummy = ListNode(0)
        less_tail = less_dummy
        greater_tail = greater_dummy

        cur = head
        while cur:
            next_node = cur.next
            cur.next = None

            if cur.val < x:
                less_tail.next = cur
                less_tail = cur
            else:
                greater_tail.next = cur
                greater_tail = cur

            cur = next_node

        less_tail.next = greater_dummy.next
        return less_dummy.next
```

---

### 为什么可行

因为它和方法二本质还是同一件事：

```text
根据值把节点稳定地分到两条链表中
```

只是它在“接进去之前”多做了一步清理：

```text
先把当前节点的旧 next 关系切断
```

所以代码的安全感会更强，也更容易帮你真正理解：

```text
链表题里一个节点接到新位置之前，原来的连接关系不一定还能保留
```

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 它适合什么时候学

它适合作为：

- 帮你真正理解为什么方法二最后要断尾
- 看懂“摘节点再接入”的链表写法
- 让你在做复杂链表题时更注意旧链接残留的问题

但如果你现在只准备记一个版本：

```text
还是优先记方法二
```

因为方法二更标准，也更常见。

---

## 三种方法的关系

这题三种做法的递进关系很清楚：

- **方法一**：先按值收集再重建链表，最直观保底
- **方法二**：双链表稳定分流后合并，这是面试主推
- **方法三**：在方法二基础上改成“先断链再接入”的安全写法

这题最值得抓住的一句话是：

```text
86 题不是排序，而是把节点按条件稳定地分流到两条链表里，然后再拼起来
```

只要这句话真正想通，方法二就会非常自然。
