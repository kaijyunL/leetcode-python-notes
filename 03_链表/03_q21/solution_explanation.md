# LeetCode 21. 合并两个有序链表（Merge Two Sorted Lists）解析

## 题目描述

给你两个按升序排列的链表 `list1` 和 `list2`，请你把它们合并成一个新的升序链表并返回。

注意这里的“新链表”，并不一定要求你新建所有节点。更自然的做法通常是：

```text
直接调整原链表节点之间的连接关系
```

例如：

```text
list1 = 1 -> 2 -> 4
list2 = 1 -> 3 -> 4
```

合并后得到：

```text
1 -> 1 -> 2 -> 3 -> 4 -> 4
```

---

## 先理解这题在考什么

这题表面上是在“合并两个链表”，但核心其实是：

```text
当两个链表都已经有序时，怎样每一步都选出当前更小的那个节点
```

你可以把它理解成“归并排序里 merge 那一步”的链表版本。

最关键的条件就是：

```text
两个链表本身已经有序
```

这意味着每次只需要比较两个链表的当前头节点，谁小就先接谁。

所以这题真正考的是：

- 你能不能想到“每次只比较当前两个头”
- 你会不会用链表指针把结果串起来
- 你会不会用 `dummy` 哑节点简化边界处理

---

## 方法一：收集所有值后排序重建

### 思路

最直观的保底思路是：

1. 先遍历 `list1`，把值都放进数组
2. 再遍历 `list2`，继续放进数组
3. 对数组排序
4. 按排序后的结果重新建一条新链表

例如：

```text
list1 = 1 -> 2 -> 4
list2 = 1 -> 3 -> 4
```

先收集出：

```text
[1, 2, 4, 1, 3, 4]
```

排序后：

```text
[1, 1, 2, 3, 4, 4]
```

再按这个顺序重建新链表。

---

### 代码

```python
class Solution:
    def mergeTwoLists(
        self,
        list1: Optional[ListNode],
        list2: Optional[ListNode],
    ) -> Optional[ListNode]:
        values = []

        cur = list1
        while cur:
            values.append(cur.val)
            cur = cur.next

        cur = list2
        while cur:
            values.append(cur.val)
            cur = cur.next

        values.sort()

        dummy = ListNode(0)
        cur = dummy

        for value in values:
            cur.next = ListNode(value)
            cur = cur.next

        return dummy.next
```

---

### 为什么可行

因为数组排序后，所有值的相对大小关系已经正确了。

只要你按排好序的结果重新建链表，最终答案自然就是升序的。

---

### 复杂度

- 时间复杂度：`O((m + n) log(m + n))`
- 空间复杂度：`O(m + n)`

---

### 不足在哪里

这个方法的最大问题是：

```text
它几乎没利用“两个链表原本已经有序”这个条件
```

题目已经把一半工作帮你做完了，你却还是把所有值拿出来重新排序，显然不划算。

所以更自然的问题就是：

```text
能不能不重新排序，而是边比较边合并？
```

这就来到方法二。

---

## 方法二：哑节点 + 迭代合并（面试主推）

### 核心思路

因为两个链表都是升序的，所以每一步只需要比较：

```text
list1 当前头节点 和 list2 当前头节点
```

谁小，谁就应该接到结果链表的后面。

为了让“接到结果链表尾部”这件事更好写，我们引入两个角色：

- `dummy`：结果链表的虚拟头节点
- `cur`：始终指向结果链表当前的尾部

这样每次选出较小节点后，只要做两件事：

1. `cur.next` 指向较小节点
2. `cur` 往后移动一步

然后把被选中的那个链表也往后移动一格。

---

## 为什么这个思路能想到

因为两个链表都已经有序，所以每个时刻真正有资格成为“当前答案下一个节点”的，只可能是：

```text
list1 的头 或 list2 的头
```

不可能跳到更后面的节点去选，因为后面的节点只会更大。

这就是这题最关键的贪心直觉：

```text
每一步只看两个头，选更小的那个
```

选完以后，这个节点就可以放心接到结果链表末尾，因为它一定是当前全局最小的未使用节点。

---

## 为什么要用哑节点 `dummy`

如果不用 `dummy`，你一开始会很麻烦，因为你得先决定：

```text
合并后链表的头节点到底来自 list1 还是 list2
```

而有了 `dummy` 以后，逻辑会统一很多：

- 不用单独处理第一个节点
- 不用反复判空决定头节点
- 所有“接到尾部”的动作完全一致

这是链表题里非常重要的技巧。

---

## 用例子走一遍

假设：

```text
list1 = 1 -> 2 -> 4
list2 = 1 -> 3 -> 4
```

开始时：

```text
dummy -> None
cur = dummy
```

### 第 1 步

比较两个头：

```text
1 和 1
```

这里选谁都可以。为了写法稳定，我们可以约定：

```text
如果 list1.val <= list2.val，就先接 list1
```

于是把 `list1` 的第一个 `1` 接到结果里。

结果变成：

```text
dummy -> 1
```

然后：

- `cur` 移到这个 `1`
- `list1` 后移到 `2`

### 第 2 步

再比较：

```text
2 和 1
```

这次接 `list2` 的 `1`。

结果变成：

```text
1 -> 1
```

然后：

- `cur` 后移
- `list2` 后移到 `3`

### 第 3 步

比较：

```text
2 和 3
```

接 `2`。

### 第 4 步

比较：

```text
4 和 3
```

接 `3`。

### 第 5 步

比较：

```text
4 和 4
```

按约定先接 `list1` 的 `4`。

这时 `list1` 已经空了。

### 最后一步

其中一个链表空了以后，不需要继续逐个比较。

因为另一个链表剩下的部分本来就已经有序，所以直接：

```text
cur.next = 剩余那条链表
```

即可。

---

### 面试代码

```python
class Solution:
    def mergeTwoLists(
        self,
        list1: Optional[ListNode],
        list2: Optional[ListNode],
    ) -> Optional[ListNode]:
        dummy = ListNode(0)
        cur = dummy

        while list1 and list2:
            if list1.val <= list2.val:
                cur.next = list1
                list1 = list1.next
            else:
                cur.next = list2
                list2 = list2.next
            cur = cur.next

        cur.next = list1 if list1 else list2
        return dummy.next
```

---

### 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 最贴题目条件

它把“两个链表已经有序”这个条件用到了极致：

```text
每次只比较两个头节点
```

### 2. 写法最稳

有了 `dummy` 以后，头节点和中间节点的处理完全统一。

面试里最怕的是边界一多就乱，而这个写法非常稳。

### 3. 复杂度最好

- 时间复杂度：`O(m + n)`
- 空间复杂度：`O(1)`

这是这题最标准、也最推荐现场手写的版本。

---

### 容易出错的地方

这题最常见的错误有两个。

### 1. 忘了最后把剩余链表接上去

如果循环条件写的是：

```text
while list1 and list2
```

那循环结束时，最多只会有一条链表还有剩余。

这时一定别忘了：

```text
cur.next = list1 if list1 else list2
```

### 2. 不敢直接复用原节点

很多人会以为必须新建节点，其实没必要。

这题直接把原节点重新串起来就可以，反而更省空间，也更符合链表题直觉。

---

### 面试里怎么讲

你可以这样解释：

```text
因为两个链表都是升序的，所以每一步只需要比较两个链表当前的头节点。
谁更小，就把谁接到结果链表尾部。
为了简化头节点处理，我使用一个 dummy 虚拟头节点，再用 cur 维护结果链表尾部。
当其中一条链表走完后，另一条链表剩下的部分本来就已经有序，所以直接接到尾部即可。
这样每个节点只访问一次，时间复杂度是 O(m+n)，额外空间复杂度是 O(1)。
```

这就是这题最标准的说法。

---

## 方法三：递归合并（补充理解）

### 思路

递归的想法是：

```text
先决定当前这一层的头节点是谁，再递归处理剩下部分
```

如果 `list1.val <= list2.val`，那么合并后链表的头节点就应该是 `list1`，而它后面接的应该是：

```text
merge(list1.next, list2)
```

反之同理。

递归终止条件也非常自然：

- 如果 `list1` 空了，直接返回 `list2`
- 如果 `list2` 空了，直接返回 `list1`

---

### 代码

```python
class Solution:
    def mergeTwoLists(
        self,
        list1: Optional[ListNode],
        list2: Optional[ListNode],
    ) -> Optional[ListNode]:
        if not list1:
            return list2
        if not list2:
            return list1

        if list1.val <= list2.val:
            list1.next = self.mergeTwoLists(list1.next, list2)
            return list1

        list2.next = self.mergeTwoLists(list1, list2.next)
        return list2
```

---

### 为什么可行

因为每一层递归都在做同一件事：

```text
从 list1 和 list2 当前头节点里选出更小的那个，作为这一层的答案头
```

剩下的问题结构完全一样，所以自然可以递归下去。

---

### 复杂度

- 时间复杂度：`O(m + n)`
- 空间复杂度：`O(m + n)`

这里的空间复杂度来自递归调用栈。

---

### 它适合什么时候学

它适合作为：

- 递归思维训练
- 理解“当前头节点选谁”这种分治写法
- 帮你更深地理解迭代版本质上在做什么

但如果你现在是二刷，或者面试只准备记一种：

```text
还是优先记方法二
```

---

## 三种方法的关系

这题三种做法的递进关系非常清楚：

- **方法一**：不利用原有顺序，先全部拿出来再排序
- **方法二**：真正利用有序条件，边比较边合并，这是面试主推
- **方法三**：把方法二的“选头节点”逻辑换成递归表达

所以这题最值得抓住的一句话是：

```text
两个链表都已有序，所以每一步只需要比较当前两个头节点
```

一旦这句话通了，方法二就会非常自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：收集后排序重建 | `O((m + n) log(m + n))` | `O(m + n)` | 能做，但没用满有序条件 |
| 方法二：哑节点 + 迭代合并 | `O(m + n)` | `O(1)` | 面试主推 |
| 方法三：递归合并 | `O(m + n)` | `O(m + n)` | 有助于理解，但现场不如迭代稳 |

---

## 总结

这题最重要的不是背“合并链表模板”，而是想明白这件事：

```text
每一步真正有资格被接到结果链表尾部的，只可能是两个链表当前的头节点之一
```

只要这句话你能顺着讲出来，这题基本就真正掌握了。

如果你现在只准备记一个版本：

```text
就记方法二：哑节点 + 迭代合并
```
