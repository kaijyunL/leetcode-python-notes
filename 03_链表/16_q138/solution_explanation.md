# LeetCode 138. 随机链表的复制（Copy List with Random Pointer）解析

## 题目描述

给你一个链表的头节点 `head`。

这个链表和普通单链表不一样，因为每个节点除了有：

- `next`：指向下一个节点
- `random`：可以随机指向链表中的任意节点，也可以是 `None`

题目要求你返回这条链表的 **深拷贝**。

这里“深拷贝”的意思是：

```text
新链表中的每个节点都必须是全新节点，不能和原链表共用任何节点对象
```

而且：

- 新链表的 `val` 要和原链表对应节点一致
- 新链表的 `next` 结构要和原链表一致
- 新链表的 `random` 指向关系也要和原链表一致
- 新链表中的 `random` 不能再指回原链表中的节点

例如，如果原链表里：

```text
A.random = C
```

那么复制后应该变成：

```text
A'.random = C'
```

而不是：

```text
A'.random = C
```

这正是这题最核心的要求。

---

## 先理解这题到底在考什么

这题表面上看是链表题，但它比普通链表题多了一层难点：

```text
每个节点不只连着下一个节点，还可能通过 random 指向任意位置
```

所以这题真正考的不是“会不会把 next 连起来”，而是：

```text
你能不能始终知道：原链表里的某个节点，对应的新节点到底是谁
```

这句话非常重要。

因为如果你只会顺着 `next` 一路复制值，那你最多只能把线性顺序搭出来；
但一旦要处理 `random`，你就必须回答：

```text
原节点 X.random 指向的那个旧节点 Y，对应的新节点 Y' 在哪里？
```

所以这题的本质其实是：

```text
维护一份“旧节点 -> 新节点”的映射关系
```

一旦这句话想通，后面的所有做法就都只是：

- 这个映射关系是放在 **哈希表** 里
- 还是临时藏在 **链表结构本身** 里

这也正是方法一和方法二的分界线。

---

## 为什么这题不能只复制值

很多人第一次做会下意识想：

```text
我就把每个节点的 val 复制过去不就行了？
```

但这远远不够。

因为题目不是要求你复制一个值序列，而是要求你复制：

```text
节点之间的指向关系
```

尤其是 `random`，它可能：

- 指向前面的节点
- 指向后面的节点
- 指向自己
- 指向 `None`

例如下面这条链表：

```text
7 -> 13 -> 11
```

如果：

- `7.random = None`
- `13.random = 7`
- `11.random = 13`

那复制出来的不只是值 `[7, 13, 11]`，更重要的是这些“谁指向谁”的关系也必须一模一样。

所以这题真正难的地方不是建节点，而是：

```text
把 next 和 random 都指到“新链表里的对应节点”上
```

---

## 为什么这题有点像“图的复制”

普通单链表里，每个节点只会沿着 `next` 往后走，结构比较单纯。

但这题一旦加入 `random`，一个节点就可能同时有两条边：

- `next`
- `random`

这样看起来就更像：

```text
一个节点图，只不过其中一条边刚好形成了线性链表
```

所以这题其实也可以从“复制图/复制带缓存的递归”角度去理解。

不过因为原题本身的 `next` 仍然是一条标准链表，
所以最自然的主线还是：

- 先用哈希表直接维护映射
- 再进一步学习“交织复制”这个高级链表技巧

---

## 方法一：哈希表两遍复制

### 思路

最直观的做法就是直接维护：

```text
旧节点 -> 新节点
```

具体分两遍：

1. 第一遍遍历原链表，只创建所有新节点，并把映射存进哈希表
2. 第二遍再根据映射，把每个新节点的 `next` 和 `random` 补齐

为什么要分两遍？

因为你在处理某个节点的 `random` 时，
它可能指向一个你还没走到的后面节点。

例如：

```text
A.random = D
```

如果你一边走一边只复制当前节点，那当你走到 `A` 时，`D'` 可能还没创建出来。

所以最稳的想法就是：

```text
先把所有新节点都造出来，再统一连边
```

---

### 代码

```python
class Solution:
    def copyRandomList(self, head: Optional[Node]) -> Optional[Node]:
        if head is None:
            return None

        mapping = {}
        cur = head
        while cur:
            mapping[cur] = Node(cur.val)
            cur = cur.next

        cur = head
        while cur:
            copy = mapping[cur]
            copy.next = mapping.get(cur.next)
            copy.random = mapping.get(cur.random)
            cur = cur.next

        return mapping[head]
```

---

### 为什么可行

因为哈希表已经明确回答了这题最关键的问题：

```text
任意一个旧节点，对应的新节点是谁
```

一旦这个映射有了，连接 `next` 和 `random` 就非常机械：

- 旧的 `cur.next` 对应到新的 `mapping[cur.next]`
- 旧的 `cur.random` 对应到新的 `mapping[cur.random]`

所以它其实是在“先建点，再连边”。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 它的优点和不足

### 优点

- 最直观
- 最容易一次写对
- 最容易把“深拷贝”和“映射关系”讲清楚

### 不足

它的主要问题是：

```text
为了保存映射，额外用了一个哈希表
```

所以更自然的问题就是：

```text
能不能不额外开哈希表，而是把映射关系临时藏在链表本身里？
```

这就来到方法二。

---

## 方法二：节点交织复制 + 拆分（面试主推）

### 核心思路

这题最巧妙的地方就在这里：

```text
我不把“旧节点 -> 新节点”的映射放进哈希表，而是直接把新节点插到旧节点后面
```

如果原链表是：

```text
A -> B -> C
```

那第一步复制后，我们把它变成：

```text
A -> A' -> B -> B' -> C -> C'
```

这样一来，会发生一个非常关键的事情：

```text
每个旧节点的副本节点，刚好就是它的 next
```

也就是说：

- `A.next` 就是 `A'`
- `B.next` 就是 `B'`
- `C.next` 就是 `C'`

这相当于把：

```text
旧节点 -> 新节点
```

这份映射直接写进了链表结构里。

然后整个过程分成 3 步：

1. 把每个复制节点插到原节点后面
2. 利用这个临时映射设置所有复制节点的 `random`
3. 再把交织在一起的链表拆成原链表和复制链表

这就是这题最值得记的技巧。

---

## 为什么这个思路能想到

因为方法一的本质其实不是“哈希表很重要”，而是：

```text
必须能快速找到旧节点对应的新节点
```

哈希表只是实现这个映射的一种方式。

那我们就可以继续追问：

```text
除了哈希表，还有没有别的地方可以暂时存这份映射？
```

答案就是：

```text
直接把副本节点插到原节点后面
```

这样旧节点要找对应的新节点时，不用查表，直接 `node.next` 就行。

这就是方法二最漂亮的地方：

```text
用链表自己的 next 指针代替哈希表
```

---

## 用例子完整走一遍

假设原链表是：

```text
A(7) -> B(13) -> C(11)
```

并且：

- `A.random = None`
- `B.random = A`
- `C.random = B`

### 第 1 步：交织插入副本节点

把每个新节点插到原节点后面：

```text
A -> A' -> B -> B' -> C -> C'
```

此时：

- `A.next = A'`
- `B.next = B'`
- `C.next = C'`

于是“旧节点 -> 新节点”的对应关系已经有了。

### 第 2 步：设置副本节点的 `random`

现在看 `B.random = A`。

那 `B'` 应该指向 `A'`。

而因为：

- `B' = B.next`
- `A' = A.next`

所以：

```text
B'.random = B.random.next
```

同理，`C.random = B`，所以：

```text
C'.random = C.random.next
```

也就是：

```python
copy.random = cur.random.next if cur.random else None
```

### 第 3 步：拆分链表

现在交织链表里已经同时包含：

- 原链表节点
- 副本链表节点

接下来只需要把它们拆开：

```text
原链表恢复成：A -> B -> C
复制链表变成：A' -> B' -> C'
```

最后返回 `A'` 即可。

---

### 面试代码

```python
class Solution:
    def copyRandomList(self, head: Optional[Node]) -> Optional[Node]:
        if head is None:
            return None

        cur = head
        while cur:
            next_node = cur.next
            copy = Node(cur.val, next_node)
            cur.next = copy
            cur = next_node

        cur = head
        while cur:
            copy = cur.next
            copy.random = cur.random.next if cur.random else None
            cur = copy.next

        new_head = head.next
        cur = head
        while cur:
            copy = cur.next
            cur.next = copy.next
            if copy.next:
                copy.next = copy.next.next
            cur = cur.next

        return new_head
```

---

### 为什么这个方法最适合面试

如果你已经先把方法一想通了，那这题最值得主记的版本就是这一种。

### 1. 它抓住了题目的真正核心

这题最本质的是：

```text
怎么维护旧节点到新节点的映射
```

方法二没有否定这个本质，只是把映射从哈希表换成了链表结构本身。

### 2. 它非常有技巧含量

这不是普通链表题里常见的“快慢指针 / 反转 / 哑节点”模板，
而是一种很有代表性的：

```text
把辅助信息临时写进原数据结构
```

这种思路特别值得学。

### 3. 复杂度更优

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`（不计返回结果本身）

这是这题最经典、最漂亮的空间优化写法。

---

### 容易出错的地方

### 1. 忘了 `copy.random` 不是直接指向 `cur.random`

错误想法是：

```python
copy.random = cur.random
```

这会让复制链表里的指针直接指回原链表。

正确的是：

```python
copy.random = cur.random.next if cur.random else None
```

因为 `cur.random.next` 才是那个随机目标节点的副本。

### 2. 拆分时只顾着拿出新链表，忘了恢复原链表

方法二会临时把原链表改成交织结构。

所以最后拆分时，你必须同时做两件事：

- 恢复原链表的 `next`
- 重建复制链表的 `next`

少做任意一边，结构都会乱。

### 3. 误以为空间复杂度 `O(1)` 表示没有创建新节点

这题无论如何都必须创建 `n` 个新节点，
因为这是“深拷贝”的基本要求。

这里说的 `O(1)`，指的是：

```text
除了答案链表本身，没有额外再开和 n 成正比的辅助结构
```

这一点不要混淆。

---

### 面试里怎么讲

你可以这样解释：

```text
这题的本质是维护“旧节点到新节点”的映射。最直观的做法是用哈希表，但还能继续优化空间。我的做法是先把每个副本节点插到原节点后面，这样旧节点的 next 就临时变成了它的副本，相当于把映射直接写进链表里。接着我就可以用 cur.random.next 来给副本节点设置 random，因为原 random 节点后面紧跟着就是它的副本。最后再把交织在一起的链表拆成原链表和复制链表。这样每个节点只处理常数次，时间复杂度 O(n)，额外空间复杂度 O(1)。
```

这就是这题最标准也最有亮点的讲法。

---

## 方法三：递归 + 哈希缓存（图视角补充）

### 思路

如果你愿意把这题看成“带两条边的节点图”，
那它也可以写成递归版。

定义一个递归函数 `clone(node)`，表示：

```text
返回旧节点 node 对应的新节点
```

那么对于任意节点：

- 新节点值是 `node.val`
- 新节点的 `next` 应该是 `clone(node.next)`
- 新节点的 `random` 应该是 `clone(node.random)`

但这里必须配一个缓存 `memo`，因为：

- `random` 可能指回前面节点
- `random` 可能指向自己
- 不缓存就会重复建节点，甚至死递归

所以这其实是：

```text
用 DFS + memo 去复制一个特殊结构图
```

---

### 代码

```python
class Solution:
    def copyRandomList(self, head: Optional[Node]) -> Optional[Node]:
        memo = {}

        def clone(node: Optional[Node]) -> Optional[Node]:
            if node is None:
                return None
            if node in memo:
                return memo[node]

            copy = Node(node.val)
            memo[node] = copy
            copy.next = clone(node.next)
            copy.random = clone(node.random)
            return copy

        return clone(head)
```

---

### 为什么可行

因为递归函数始终在做同一件事：

```text
给我一个旧节点，我返回它唯一对应的新节点
```

而 `memo` 保证了：

- 同一个旧节点只会创建一次副本
- 所有指向这个旧节点的边，最后都会指向同一个副本节点

所以深拷贝关系就能成立。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

这里的空间复杂度来自：

- 哈希缓存
- 递归调用栈

---

### 它适合什么时候学

它适合作为：

- 把这题从“链表题”拓宽成“带缓存的图复制”理解
- 练习递归 + memo 的写法
- 帮你更深入理解“映射关系”才是本质

但如果你现在只准备记一个版本：

```text
还是优先记方法二
```

因为方法二才是这题最有代表性、最值得专门掌握的链表技巧。

---

## 三种方法的关系

这题三种做法的递进关系很清楚：

- **方法一**：直接用哈希表显式维护“旧节点 -> 新节点”的映射，最稳最直观
- **方法二**：把映射关系临时藏进链表结构里，交织复制后再拆分，这是面试主推
- **方法三**：把题目看成图复制问题，用递归 + memo 去理解深拷贝本质

这题最值得抓住的一句话是：

```text
138 题真正难的不是 next，而是如何让每个旧节点的 next/random 都准确指向“对应的新节点”
```

一旦这句话通了，方法一和方法二都会变得很自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：哈希表两遍复制 | `O(n)` | `O(n)` | 最稳最直观，先建立深拷贝映射概念 |
| 方法二：节点交织复制 + 拆分 | `O(n)` | `O(1)` | 面试主推，技巧含量最高 |
| 方法三：递归 + 哈希缓存 | `O(n)` | `O(n)` | 有助于理解“图复制”视角 |

---

## 总结

这题最重要的，不是死记某一句 `random` 怎么写，而是先想清楚：

```text
深拷贝的本质，是让原链表里的每个节点，都能找到自己唯一对应的新节点，然后把所有 next/random 边重新接到这些新节点上
```

如果你现在只准备记一个版本：

```text
就记方法二：节点交织复制 + 拆分
```

但真正上手时，最好先把方法一顺着讲通，再去吃透方法二的空间优化技巧。
