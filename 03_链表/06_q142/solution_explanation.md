# LeetCode 142. 环形链表 II（Linked List Cycle II）解析

## 题目描述

给你一个链表的头节点 `head`，如果链表中存在环，请返回环的**入口节点**；如果没有环，返回 `None`。

注意：

- 这里的 `pos` 只是评测系统用来描述“尾节点连回哪个下标”的辅助信息
- `pos` **不是函数参数**
- 你真正要返回的是：

```text
环开始的那个节点对象
```

而不是入口节点的值。

---

## 先理解这题在考什么

`141` 问的是：

```text
有没有环？
```

而 `142` 更进一步，它问的是：

```text
如果有环，环是从哪里开始的？
```

所以这题其实分成两层：

1. 先判断是否存在环
2. 如果存在，再找出入口节点

真正难的不是“判环”，而是：

```text
为什么快慢指针相遇以后，还能继续推出入口位置？
```

这就是这题最核心的地方。

---

## 方法一：哈希集合记录访问过的节点

### 思路

最直观的方法仍然是：

1. 从 `head` 开始遍历
2. 用集合记录已经访问过的节点
3. 如果当前节点第一次重复出现，那它就是环入口
4. 如果最后走到 `None`，说明无环

为什么“第一次重复出现的节点”就是入口？

因为在单链表里，你沿着 `next` 往前走，第一次重新回到旧节点的时候，恰好就是：

```text
第一次进入闭环时的那个入口节点
```

---

### 代码

```python
class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        visited = set()
        cur = head

        while cur:
            if cur in visited:
                return cur
            visited.add(cur)
            cur = cur.next

        return None
```

---

### 为什么可行

无环链表中，每个节点最多访问一次。

如果某个节点再次出现，说明你已经绕回来了；而第一次绕回来的那个点，正是环入口。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 不足在哪里

这个方法虽然直接，但需要额外集合。

而这题最经典的地方恰恰在于：

```text
不用额外空间，也能把入口找出来
```

这就来到方法二。

---

## 方法二：Floyd 快慢指针相遇后找入口（面试主推）

### 核心思路

这题分两阶段。

### 阶段一：先找相遇点

和 `141` 一样：

- `slow` 每次走 1 步
- `fast` 每次走 2 步

如果没有环，`fast` 最终会走到 `None`。

如果有环，它们一定会在环内某个位置相遇。

### 阶段二：从头节点和相遇点同时出发

一旦相遇：

1. 保留 `slow` 在相遇点不动
2. 新建一个指针 `entry`，从 `head` 出发
3. 让 `slow` 和 `entry` 都每次走 1 步
4. 它们再次相遇的地方，就是环入口

也就是：

```text
一个从头走，一个从相遇点走，同速前进，再次相遇就是入口
```

---

## 为什么这个思路能想到

这题最关键的是理解：

```text
相遇点和入口之间，隐藏着一个距离关系
```

假设：

- 从头到入口的距离是 `a`
- 从入口到相遇点的距离是 `b`
- 从相遇点再走到入口的距离是 `c`
- 环长就是 `b + c`

当快慢指针第一次相遇时：

- `slow` 走了：`a + b`
- `fast` 走了：`a + b + k(b + c)`，其中 `k >= 1`

因为 `fast` 速度是 `slow` 的 2 倍，所以：

```text
2(a + b) = a + b + k(b + c)
```

化简得到：

```text
a + b = k(b + c)
```

继续整理：

```text
a = k(b + c) - b = (k - 1)(b + c) + c
```

这一句最重要：

```text
a = 若干圈环长 + c
```

它表示：

- 从头到入口的距离是 `a`
- 从相遇点到入口的距离是 `c`，只差若干整圈

所以：

- 一个指针从头开始走 `a` 步会到入口
- 另一个指针从相遇点开始走 `c + 若干整圈` 步，也会到入口

两个人同速前进，最终就会在入口相遇。

---

## 用例子走一遍

假设链表是：

```text
3 -> 2 -> 0 -> -4
     ^         |
     |_________|
```

入口节点是值为 `2` 的节点。

### 第一步：先用快慢指针找相遇点

开始时：

```text
slow = head
fast = head
```

经过若干轮以后，它们会在环里某个位置相遇。这个相遇点不一定是入口，可能是 `0`，也可能是 `-4`。

### 第二步：一个从头走，一个从相遇点走

比如它们在 `-4` 相遇。

这时：

- `entry = head`，从 `3` 开始
- `slow` 继续留在 `-4`

然后两者都每次走一步：

- `entry`: `3 -> 2`
- `slow`: `-4 -> 2`

于是它们在值为 `2` 的节点相遇。

这个节点就是环入口。

---

### 面试代码

```python
class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = head
        fast = head

        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

            if slow is fast:
                entry = head
                while entry is not slow:
                    entry = entry.next
                    slow = slow.next
                return entry

        return None
```

---

### 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 直接承接 `141`

前半段就是 `141` 的 Floyd 判圈。

### 2. 真正利用了题目结构

它不是额外存访问历史，而是直接利用“相遇后的距离关系”推出入口。

### 3. 代码短，但含金量高

虽然背后有推导，但真正代码非常短。

### 4. 复杂度最好

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这是这题最标准、最推荐现场手写的版本。

---

### 容易出错的地方

### 1. 以为第一次相遇点就是入口

不是。

快慢指针第一次相遇的位置通常只是：

```text
环里的某个点
```

并不一定正好是入口。

### 2. 没有先判断无环情况

如果没有环，`fast` 或 `fast.next` 会先为空。

这时必须直接返回 `None`，不能继续找入口。

### 3. 第二阶段让两个指针速度不同

找入口时一定要注意：

```text
两个指针都每次只走一步
```

这样距离关系才成立。

### 4. 返回节点值而不是节点对象

题目要求返回的是：

```text
入口节点本身
```

不是 `entry.val`。

---

### 面试里怎么讲

你可以这样解释：

```text
我先用 Floyd 快慢指针判断链表是否有环。
如果没有环，fast 会先走到空，直接返回 None。
如果有环，slow 和 fast 会在环内相遇。
相遇后我再用一个指针从 head 出发，另一个指针留在相遇点，两者每次都走一步。
根据相遇距离关系，它们再次相遇的位置就是环入口。
整个过程时间复杂度 O(n)，额外空间复杂度 O(1)。
```

这就是这题最标准的讲法。

---

## 方法三：先求环长，再双指针对齐入口（补充理解）

### 思路

如果你已经用 Floyd 找到了环内相遇点，那么还可以进一步先求出：

```text
环的长度
```

做法是：

1. 从相遇点出发绕一圈，统计步数，得到环长 `cycle_len`
2. 准备两个指针 `p1`、`p2` 都从 `head` 出发
3. 先让 `p2` 比 `p1` 提前走 `cycle_len` 步
4. 然后两者一起每次走一步
5. 它们第一次相遇的地方，就是环入口

为什么？

因为两个指针始终相差一个环长，所以当前面的指针刚进入环入口时，后面的指针也正好被“补齐”到入口。

---

### 代码

```python
class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = head
        fast = head

        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:
                cycle_len = 1
                cur = slow.next
                while cur is not slow:
                    cur = cur.next
                    cycle_len += 1

                p1 = head
                p2 = head
                for _ in range(cycle_len):
                    p2 = p2.next

                while p1 is not p2:
                    p1 = p1.next
                    p2 = p2.next

                return p1

        return None
```

---

### 为什么可行

关键在于：

```text
两个指针之间始终隔着一个完整环长
```

所以当前面的指针进入入口时，后面的指针也恰好走到入口。

它本质上仍然是在利用环的结构，只是换成了“先求环长再对齐”的思路。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 它适合什么时候学

它适合作为：

- 帮你更深理解 `142` 的环结构
- 看到别的题解时能认出来
- 训练“先求环长，再做双指针对齐”的思维

但如果你现在是二刷，或者面试只准备记一个版本：

```text
还是优先记方法二
```

---

## 三种方法的关系

这题三种做法的递进关系很清楚：

- **方法一**：显式记录访问历史，第一次重复节点就是入口
- **方法二**：先相遇，再利用距离关系找入口，这是面试主推
- **方法三**：同样基于 Floyd，只是改成“先求环长，再对齐入口”

这题最值得抓住的一句话是：

```text
快慢指针第一次相遇点不一定是入口，但从头节点和相遇点同时出发、同速前进，会在入口再次相遇
```

一旦这句话想通，`142` 就真正掌握了。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：哈希集合记录节点 | `O(n)` | `O(n)` | 直观好懂，适合第一层理解 |
| 方法二：Floyd 相遇后找入口 | `O(n)` | `O(1)` | 面试主推 |
| 方法三：先求环长再找入口 | `O(n)` | `O(1)` | 有助于深化理解 |

---

## 总结

这题最重要的不是只会背代码，而是要真正理解：

```text
第一次相遇只能证明有环；
真正的入口，要靠“头节点到入口的距离 = 相遇点到入口的距离（模环长）”这个关系推出来。
```

如果你现在只准备记一个版本：

```text
就记方法二：Floyd 快慢指针相遇后找入口
```
