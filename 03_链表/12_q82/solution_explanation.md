# LeetCode 82. 删除排序链表中的重复元素 II（Remove Duplicates from Sorted List II）解析

## 题目描述

给定一个 **已排序** 的链表头节点 `head`，请你删除所有含有重复数字的节点，
只保留原链表中 **只出现一次** 的数字，最后返回仍然有序的新链表。

例如：

```text
输入：1 -> 2 -> 3 -> 3 -> 4 -> 4 -> 5
输出：1 -> 2 -> 5
```

再比如：

```text
输入：1 -> 1 -> 1 -> 2 -> 3
输出：2 -> 3
```

注意这题和 `83` 很像，但又不是同一道题。

- `83`：重复值保留一个
- `82`：只要某个值重复出现，这个值对应的节点要整段删光

这正是这题最容易混淆的地方。

---

## 先理解这题到底比 `83` 难在哪

很多人第一次看到这题，会下意识套用 `83` 的思路：

```text
如果当前节点和下一个节点相同，就删掉下一个节点
```

但这在 `82` 里是不够的。

因为 `82` 的要求不是：

```text
把重复压缩成一个
```

而是：

```text
只要某个值重复出现，这一整段都不能留
```

例如：

```text
1 -> 2 -> 3 -> 3 -> 4 -> 4 -> 5
```

这里的 `3 -> 3` 不是删掉一个 `3` 后留下一个，
而是这两个 `3` 都要消失；`4 -> 4` 也是一样。

所以这题真正考的是：

```text
你能不能在有序链表里识别出“重复值整段”，并把整段一起跳过去
```

而不是只会删掉“当前多出来的一个节点”。

这也是为什么它常被看作：

```text
83 的进阶版
```

---

## 为什么“有序”这个条件特别关键

题目说链表已经有序，这意味着：

```text
相同的值一定会连续出现
```

例如：

```text
1 -> 1 -> 1 -> 2 -> 3 -> 3
```

重复值不会分散在链表各处，而是会形成一段一段的连续块。

这让我们可以把问题理解成：

- 某一段值只出现一次：保留这一个节点
- 某一段值出现两次及以上：整段删除

也就是说，这题不是在一个一个节点地判断，
而是在一段一段地判断：

```text
这一段值，是保留，还是整段删掉
```

这个视角一旦建立起来，方法二就会非常自然。

---

## 为什么这题里 `dummy` 是必须的

这题最麻烦的边界情况是：

```text
头节点本身就属于重复段
```

比如：

```text
1 -> 1 -> 2 -> 3
```

最终答案应该是：

```text
2 -> 3
```

也就是说，原来的头节点会被删掉。

如果没有一个统一的前驱节点，代码里就要不断判断：

- 现在删的是不是头节点
- 新头节点要不要单独处理
- 返回时到底返回谁

所以这题最稳的做法一定是先加：

```text
dummy -> head
```

这样一来：

- 原来的头节点也有前驱了
- 头节点被删除和中间节点被删除完全统一
- 最后统一返回 `dummy.next`

这就是为什么 `82` 和 `83` 最大的代码区别之一，就是这里必须有 `dummy`。

---

## 方法一：哈希计数后重建链表

### 思路

最直观的保底方法是：

1. 第一次遍历链表，统计每个值出现了几次
2. 第二次遍历链表，只把出现次数为 `1` 的值接进新链表

例如：

```text
1 -> 2 -> 3 -> 3 -> 4 -> 4 -> 5
```

统计结果是：

```text
1:1, 2:1, 3:2, 4:2, 5:1
```

那最后只保留：

```text
1 -> 2 -> 5
```

---

### 代码

```python
from collections import Counter


class Solution:
    def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
        counts = Counter()
        cur = head

        while cur:
            counts[cur.val] += 1
            cur = cur.next

        dummy = ListNode(0)
        tail = dummy
        cur = head

        while cur:
            if counts[cur.val] == 1:
                tail.next = ListNode(cur.val)
                tail = tail.next
            cur = cur.next

        return dummy.next
```

---

### 为什么可行

因为哈希表已经把“某个值是否重复”这个问题提前回答掉了。

第二次遍历时，你不需要再判断复杂的链表结构，
只需要看：

```text
这个值的出现次数是不是 1
```

如果是，就保留；不是，就跳过。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 它的不足

这个方法虽然稳，但有两个明显问题：

### 1. 没有真正利用“有序链表”

即使链表没排序，这个方法也能做。

说明它没用上题目最宝贵的信息：

```text
重复值一定相邻
```

### 2. 没有训练到链表原地删段能力

这题更值得练的是：

```text
在链表里发现一整段重复值后，直接把这段跳过去
```

所以面试里更推荐方法二。

---

## 方法二：哑节点 + 扫描整段重复值（面试主推）

### 核心思路

这题最标准的想法是：

```text
每次扫描当前值这一整段，如果这段长度大于 1，就整段删掉；如果长度正好是 1，就保留
```

我们维护两个关键指针：

- `prev`：当前已经确认安全、并且保留在答案链表里的最后一个节点
- `cur`：正在扫描的当前值段的起点

流程如下：

1. 让 `cur` 向后扫，看当前值这一段有多长
2. 如果发现当前值重复了，说明这一整段都不能留，让 `prev.next` 直接跳到这一段之后
3. 如果当前值没有重复，说明 `cur` 是唯一节点，这时才让 `prev` 向后移动
4. 然后继续处理下一段

这题的关键不是：

```text
发现重复就删一个
```

而是：

```text
发现重复就把这一整段全跳过去
```

---

## 为什么这个思路能想到

因为链表是有序的，所以相同值一定挨在一起。

这意味着你面对的不是“零散的重复节点”，而是：

```text
一个个重复值块
```

于是问题就从：

```text
怎么删重复节点
```

变成了：

```text
怎么判断当前这段值要保留，还是整段跳过
```

这个转换非常关键。

你可以把整个链表想成由很多“值段”组成：

```text
[1] [2] [3,3] [4,4] [5]
```

- 长度为 1 的段，保留
- 长度大于 1 的段，删除

方法二正是在链表里原地完成这件事。

---

## 用例子走一遍

假设链表是：

```text
1 -> 2 -> 3 -> 3 -> 4 -> 4 -> 5
```

加上哑节点以后：

```text
dummy -> 1 -> 2 -> 3 -> 3 -> 4 -> 4 -> 5
```

开始时：

- `prev = dummy`
- `cur = 1`

### 第 1 段：值 `1`

往后看，`1` 后面不是 `1`，说明这一段长度是 `1`，可以保留。

所以：

- `prev` 前进到 `1`
- `cur` 前进到 `2`

### 第 2 段：值 `2`

同理，`2` 后面不是 `2`，也是唯一值。

所以：

- `prev` 前进到 `2`
- `cur` 前进到第一个 `3`

### 第 3 段：值 `3`

发现：

```text
3 -> 3
```

说明值 `3` 这一段是重复段。

我们让 `cur` 一直往后扫，直到离开值 `3` 这一段。

扫完以后，`cur` 来到第一个 `4`。

这时不能保留 `3` 这一段，所以执行：

```text
prev.next = cur
```

也就是让值 `2` 后面直接接到 `4`。

链表此时逻辑上变成：

```text
dummy -> 1 -> 2 -> 4 -> 4 -> 5
```

注意：

```text
prev 这时不能动
```

因为新接上的 `4` 也可能仍然是一段重复值的开始。

### 第 4 段：值 `4`

同样发现：

```text
4 -> 4
```

说明值 `4` 这一整段也不能留。

继续扫过整段 `4` 后，`cur` 来到 `5`。

再执行：

```text
prev.next = cur
```

于是链表变成：

```text
dummy -> 1 -> 2 -> 5
```

### 第 5 段：值 `5`

`5` 没有重复，可以保留。

最终答案就是：

```text
1 -> 2 -> 5
```

这就是这题最完整的过程。

---

### 面试代码

```python
class Solution:
    def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prev = dummy
        cur = head

        while cur:
            duplicate = False

            while cur.next and cur.val == cur.next.val:
                duplicate = True
                cur = cur.next

            if duplicate:
                prev.next = cur.next
            else:
                prev = prev.next

            cur = cur.next

        return dummy.next
```

---

### 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 把题目条件用满了

排序链表的价值就在于：

```text
重复值一定形成连续段
```

方法二正好完全利用了这个性质。

### 2. `dummy` 把边界统一掉了

头节点被删和中间某一段被删，处理方式完全一样。

### 3. 真正练到了链表原地删段

这题最值得掌握的能力不是“会统计次数”，而是：

```text
看到一整段重复值时，能直接把这段从链表里摘掉
```

### 4. 复杂度最优

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这是这题最标准、最适合现场手写的版本。

---

### 容易出错的地方

### 1. 误以为和 `83` 一样，只删掉后一个重复节点

`83` 是：

```text
保留一个
```

`82` 是：

```text
整段删光
```

这是两题最根本的区别。

### 2. 删除重复段后错误地让 `prev` 前进

如果当前值这一段被删掉了，说明新接到 `prev.next` 的节点还没有检查过。

所以重复段删除后：

```text
prev 不能动
```

### 3. 忘了头节点也可能被删

例如：

```text
1 -> 1 -> 2
```

答案是：

```text
2
```

如果不用 `dummy`，这里很容易写出很多特殊分支。

---

### 面试里怎么讲

你可以这样解释：

```text
因为链表已经有序，所以相同值一定连续出现。那我就不把问题看成“删某个重复节点”，而是看成“扫描当前值这一整段”。我先加一个 dummy 节点统一处理头节点被删除的情况，然后用 prev 指向已经确认保留部分的尾部，用 cur 扫描当前值这一段。如果 cur 这一段长度大于 1，说明这个值重复了，我就让 prev.next 直接跳到这一段之后；如果长度等于 1，说明这个值只出现一次，就让 prev 前进。这样每个节点最多被访问常数次，所以时间复杂度 O(n)，额外空间复杂度 O(1)。
```

这就是这题最标准的讲法。

---

## 方法三：延续 `83` 题风格的前驱指针写法（补充理解）

### 思路

如果你已经很熟悉 `83`，那这题还可以写成一种更像“`83` 升级版”的风格：

```text
让 pre 永远站在已确定安全部分的尾部，然后检查 pre 后面的两个节点是不是相同
```

循环结构通常写成：

```python
while pre.next and pre.next.next:
```

然后分成两种情况：

- 如果 `pre.next.val != pre.next.next.val`，说明 `pre.next` 是唯一值，可以安全保留，`pre` 后移
- 如果 `pre.next.val == pre.next.next.val`，说明重复段开始了，用一个 `while` 把这个值整段删掉

这个写法特别适合你已经把 `83` 刷熟之后，做风格迁移。

---

### 代码

```python
class Solution:
    def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        pre = dummy

        while pre.next and pre.next.next:
            if pre.next.val == pre.next.next.val:
                value = pre.next.val
                while pre.next and pre.next.val == value:
                    pre.next = pre.next.next
            else:
                pre = pre.next

        return dummy.next
```

---

### 为什么可行

因为它仍然是在做同一件事：

```text
如果当前值重复，就把这一整段删掉；如果当前值不重复，就把前驱往后推进
```

只是它把“扫描段”的逻辑，换成了更贴近 `83` 的写法。

这也是为什么很多人会说：

```text
82 就是 83 加上 dummy，再把“删一个”升级成“删整段”
```

这个说法非常准确。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 它适合什么时候学

它适合作为：

- 看懂 `83 -> 82` 的代码风格演化
- 帮你强化 `pre.next` / `pre.next.next` 这种链表前驱视角
- 对比“显式扫描当前段”和“前驱判断 + 整段删除”两种表达方式

但如果你现在只准备记一个版本：

```text
还是优先记方法二
```

因为方法二更容易从“值段”的角度把题讲清楚。

---

## 三种方法的关系

这题三种做法的递进关系非常清楚：

- **方法一**：先统计每个值出现次数，再重建答案链表
- **方法二**：真正利用有序链表，扫描每个值段并原地跳过重复段，这是面试主推
- **方法三**：把方法二写成更贴近 `83` 的前驱指针风格

这题最值得抓住的一句话是：

```text
82 题不是在“删一个重复节点”，而是在“判断当前值这一整段是保留还是整段删除”
```

只要这句话真正想通，方法二就会很自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：哈希计数后重建链表 | `O(n)` | `O(n)` | 直观保底，但没练到原地删段 |
| 方法二：哑节点 + 扫描整段重复值 | `O(n)` | `O(1)` | 面试主推 |
| 方法三：延续 `83` 题风格的前驱指针写法 | `O(n)` | `O(1)` | 有助于理解 `83 -> 82` 的升级关系 |

---

## 总结

这题最重要的，不是死记“发现重复怎么改指针”，而是先想清楚：

```text
因为链表有序，所以重复值一定形成连续段；而 82 题要求的是对这整段做保留或删除的决策
```

如果你现在只准备记一个版本：

```text
就记方法二：哑节点 + 扫描整段重复值
```
