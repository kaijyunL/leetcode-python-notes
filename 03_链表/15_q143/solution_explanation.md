# LeetCode 143. 重排链表（Reorder List）解析

## 题目描述

给你一个单链表的头节点 `head`，链表形如：

```text
L0 -> L1 -> L2 -> ... -> Ln
```

请你将它重排为：

```text
L0 -> Ln -> L1 -> Ln-1 -> L2 -> Ln-2 -> ...
```

注意：

```text
不能只改节点值，必须真正调整节点之间的 next 指针
```

例如：

```text
1 -> 2 -> 3 -> 4
```

重排后变成：

```text
1 -> 4 -> 2 -> 3
```

再比如：

```text
1 -> 2 -> 3 -> 4 -> 5
```

重排后变成：

```text
1 -> 5 -> 2 -> 4 -> 3
```

---

## 先理解这题到底在考什么

这题表面上像是在“从尾巴不断拿节点插到前面”。

但如果你真的这么做，会很快发现一个问题：

```text
单链表没法从尾巴往前走
```

每次想拿最后一个节点，都得从头重新扫一遍，这会很慢。

所以这题真正考的不是“会不会照着结果模拟”，而是：

```text
你能不能把目标序列 L0, Ln, L1, Ln-1, ... 转化成更容易在链表上实现的几个标准操作
```

这几个标准操作恰好就是：

- 找链表中点
- 反转链表后半段
- 交替合并两条链表

所以这题本质上是一道链表综合题：

```text
143 = 找中点 + 206 反转链表 + 交替合并
```

这也是为什么它经常被当作链表阶段的综合检查题。

---

## 为什么“找中点 + 反转后半段 + 交替合并”最自然

假设原链表是：

```text
1 -> 2 -> 3 -> 4 -> 5
```

目标是：

```text
1 -> 5 -> 2 -> 4 -> 3
```

如果你把它拆开看，会发现：

- 前半段还是按原顺序走：`1 -> 2 -> 3`
- 后半段要按倒序插入进来：`5 -> 4`

也就是说，真正的任务其实是：

```text
把后半段翻转，然后和前半段交替穿插
```

于是整题就自然变成三步：

1. 先找中点，把链表分成前后两半
2. 把后半段原地反转
3. 让两半链表交替合并

这就是方法二的核心主线，也是最值得掌握的版本。

---

## 方法一：收集所有节点后双指针重连

### 思路

最直观的保底方法是：

1. 遍历整个链表，把所有节点按顺序放进数组 `nodes`
2. 用双指针 `left`、`right` 分别指向数组头尾
3. 按 `左 -> 右 -> 左+1 -> 右-1` 的顺序重新连接节点
4. 最后记得把尾节点的 `next` 设成 `None`，防止成环

例如：

```text
1 -> 2 -> 3 -> 4 -> 5
```

收集后数组是：

```text
[1, 2, 3, 4, 5]
```

重连顺序是：

```text
1 -> 5 -> 2 -> 4 -> 3
```

---

### 代码

```python
class Solution:
    def reorderList(self, head: Optional[ListNode]) -> None:
        if head is None:
            return

        nodes = []
        cur = head
        while cur:
            nodes.append(cur)
            cur = cur.next

        left = 0
        right = len(nodes) - 1

        while left < right:
            nodes[left].next = nodes[right]
            left += 1

            if left == right:
                break

            nodes[right].next = nodes[left]
            right -= 1

        nodes[left].next = None
```

---

### 为什么可行

因为数组把链表节点的位置关系显式化了。

一旦你能按下标直接拿到：

- 最左边还没用的节点
- 最右边还没用的节点

那就可以严格按题目要求的顺序去重连。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 它的不足

这个方法好理解，但没有体现链表题真正想考的点。

问题在于：

```text
它借助数组绕开了“单链表不能从尾巴往前找”的困难
```

所以它适合：

- 建立第一层直觉
- 面试卡住时先写一个能过的版本

但如果你要主记这题，还是应该看方法二。

---

## 方法二：找中点 + 反转后半段 + 交替合并（面试主推）

### 核心思路

这题最标准的解法就是把原链表拆成两半：

- 前半段保持原顺序
- 后半段反转后，再与前半段交替合并

例如：

```text
1 -> 2 -> 3 -> 4 -> 5
```

### 第 1 步：找中点并断开

用快慢指针找到中点。

对于上面的例子，断开后可以得到：

```text
前半段：1 -> 2 -> 3
后半段：4 -> 5
```

### 第 2 步：反转后半段

把后半段反转：

```text
5 -> 4
```

### 第 3 步：交替合并

把两条链表交替穿插：

```text
1 -> 5 -> 2 -> 4 -> 3
```

这样就正好得到答案。

---

## 为什么这个思路能想到

因为目标顺序本身就在提示你：

```text
前面取一个，后面取一个，前面再取一个，后面再取一个
```

而前半段本来就是正序的，不需要改。

真正麻烦的是：

```text
后半段需要按尾到头的顺序拿出来
```

对于单链表，最自然的办法不是反复去尾部找，而是：

```text
先把后半段整体反转
```

一旦反转完成，后半段就也变成“从头开始刚好能按需要顺序取”的状态了。

这就是这题最关键的转化。

---

## 用例子完整走一遍

假设：

```text
head = 1 -> 2 -> 3 -> 4 -> 5
```

### 第 1 步：找中点

使用快慢指针后，`slow` 最终停在节点 `3`。

于是把链表断开：

```text
第一段：1 -> 2 -> 3
第二段：4 -> 5
```

这里的断开非常重要：

```text
slow.next = None
```

不然你后面在合并时很容易把旧链接也带着走，导致结构混乱甚至成环。

### 第 2 步：反转第二段

把：

```text
4 -> 5
```

反转成：

```text
5 -> 4
```

### 第 3 步：交替合并

此时两条链表分别是：

```text
第一段：1 -> 2 -> 3
第二段：5 -> 4
```

交替穿插：

- 先接 `1 -> 5`
- 再接 `2 -> 4`
- 最后剩下 `3`

结果就是：

```text
1 -> 5 -> 2 -> 4 -> 3
```

---

### 面试代码

```python
class Solution:
    def reorderList(self, head: Optional[ListNode]) -> None:
        if head is None or head.next is None:
            return

        slow = head
        fast = head.next
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

        second = slow.next
        slow.next = None

        prev = None
        cur = second
        while cur:
            next_node = cur.next
            cur.next = prev
            prev = cur
            cur = next_node
        second = prev

        first = head
        while second:
            next_first = first.next
            next_second = second.next

            first.next = second
            second.next = next_first

            first = next_first
            second = next_second
```

---

### 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 它最贴近题目本质

它没有借助数组去“模拟顺序”，而是真的解决了：

```text
后半段要倒着取，怎样在链表里实现
```

答案就是：

```text
先反转后半段，再交替合并
```

### 2. 它复用了多个经典链表技巧

这个方法几乎把链表阶段最重要的几个基本功都串起来了：

- 快慢指针找中点
- 原地反转链表
- 双指针合并链表

会写这题，说明你的链表基本功已经比较成体系。

### 3. 复杂度最好

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这是这题最标准、最推荐现场手写的版本。

---

### 容易出错的地方

### 1. 忘了把前后两半断开

也就是忘了写：

```python
slow.next = None
```

如果不断开，原链表前半段和后半段还连在一起，后面再反转和合并时非常容易形成错误链接。

### 2. 合并时没先保存两个后继节点

交替合并时，一定要先保存：

```text
next_first 和 next_second
```

否则你一旦改了 `next`，后面的链表就可能找不到了。

### 3. 误以为要返回新头节点

这题函数签名通常是：

```text
Do not return anything, modify head in-place instead
```

所以这题重点不是返回，而是把原链表重排好。

### 4. 合并结束后忘记考虑奇偶长度

奇数长度时，前半段通常会比后半段多一个节点。

例如：

```text
1 -> 2 -> 3 -> 4 -> 5
```

最后会剩下节点 `3`，但由于前面已经断链且交替接法正确，它会自然留在最后，不需要额外复杂处理。

---

### 面试里怎么讲

你可以这样解释：

```text
这题的目标顺序是头、尾、第二个、倒数第二个……所以本质上是在把前半段正序节点和后半段倒序节点交替合并。对于单链表，后半段如果想按倒序取，最自然的办法就是先把后半段反转。于是我先用快慢指针找中点，把链表拆成两半；再把后半段原地反转；最后用两个指针把前半段和反转后的后半段交替合并。这样每个节点只处理常数次，时间复杂度 O(n)，额外空间复杂度 O(1)。
```

这就是这题最标准的讲法。

---

## 方法三：栈保存后半段节点后交替插入

### 思路

如果你还没有完全吃透“反转后半段”这个操作，也可以用栈来模拟“从尾巴往前拿节点”。

做法是：

1. 先用快慢指针找到中点，并把链表断成前后两半
2. 把后半段节点依次压栈
3. 从前半段头开始，每次弹出一个栈顶节点插到当前节点后面

为什么这个方法有帮助？

因为栈的特点就是：

```text
后进先出
```

刚好对应：

```text
先拿到最后一个节点，再拿到倒数第二个节点
```

也就是题目要求的尾部顺序。

而且由于我们在压栈前已经做了：

```python
slow.next = None
```

所以前半段和后半段已经断开，交替插入后不会把旧尾巴错误地连回去。

---

### 代码

```python
class Solution:
    def reorderList(self, head: Optional[ListNode]) -> None:
        if head is None or head.next is None:
            return

        slow = head
        fast = head.next
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

        second = slow.next
        slow.next = None

        stack = []
        cur = second
        while cur:
            stack.append(cur)
            cur = cur.next

        first = head
        while stack:
            tail = stack.pop()
            next_first = first.next
            first.next = tail
            tail.next = next_first
            first = next_first
```

---

### 为什么可行

因为栈顶永远是当前“还没用过的最靠右节点”。

所以每一轮：

- 当前前半段节点 `cur` 保持顺序
- 从栈里弹出的节点负责提供“从右往左”的顺序

这样交替插入后，就能得到和题目一致的排列。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 它适合什么时候学

它适合作为：

- 帮你理解“为什么答案需要尾部逆序节点”
- 用辅助结构模拟“从后往前取节点”
- 过渡到方法二前的中间台阶

但如果你现在只准备记一个版本：

```text
还是优先记方法二
```

因为方法二才是这题最标准、最省空间的写法。

---

## 三种方法的关系

这题三种做法的递进关系很清楚：

- **方法一**：先把所有节点拿出来，用数组直接按目标顺序重连
- **方法二**：把后半段反转后与前半段交替合并，这是面试主推
- **方法三**：用栈模拟“从尾到头取节点”，帮助理解尾部顺序来源

这题最值得抓住的一句话是：

```text
143 题不是在“从尾巴反复找节点”，而是在把后半段倒过来之后，和前半段做交替编织
```

只要这句话通了，方法二就会很自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：收集节点后双指针重连 | `O(n)` | `O(n)` | 最直观，适合建立顺序感 |
| 方法二：找中点 + 反转后半段 + 交替合并 | `O(n)` | `O(1)` | 面试主推 |
| 方法三：栈保存后半段节点后交替插入 | `O(n)` | `O(n)` | 有助于理解“尾部逆序插入” |

---

## 总结

这题最重要的不是背某个固定模板，而是先想明白：

```text
目标顺序的难点只在于“后半段需要倒着参与合并”，而单链表处理倒序最自然的方法就是反转后半段
```

如果你现在只准备记一个版本：

```text
就记方法二：找中点 + 反转后半段 + 交替合并
```
