# LeetCode 147. 对链表进行插入排序（Insertion Sort List）解析

## 题目描述

给你一个链表的头节点 `head`，请你使用 **插入排序** 对链表进行排序，并返回排序后的链表头节点。

例如：

```text
4 -> 2 -> 1 -> 3
```

排序后变成：

```text
1 -> 2 -> 3 -> 4
```

再比如：

```text
-1 -> 5 -> 3 -> 4 -> 0
```

排序后变成：

```text
-1 -> 0 -> 3 -> 4 -> 5
```

这题不是泛泛地让你“把链表排好序”，而是明确指定：

```text
要用插入排序这个过程来做
```

这点很重要。

---

## 先理解这题到底在考什么

很多排序题的重点是：

```text
怎样把时间复杂度做到更优
```

但这题不是单纯在考“最快排序链表”。

它更像是在问你：

```text
如果必须按插入排序的思路做，链表版应该怎么写？
```

插入排序在数组里的直觉是：

- 前面一段已经有序
- 取当前元素
- 把它插入到前面有序段里正确的位置

到了链表里，这个过程会变成：

```text
维护一段已经排好序的链表，然后每次从后面拿一个节点，插回这段有序链表的正确位置
```

所以这题真正考的是：

- 你能不能把“已排序部分”和“未排序部分”分开看
- 你会不会在链表里做“摘节点 + 插节点”
- 你能不能用 `dummy` 统一插入到头部的边界情况

这就是这题的核心。

---

## 为什么链表特别适合“插入”

在数组里做插入排序时，虽然“找到位置”不难理解，但真正插入时往往要搬动很多元素。

而链表不一样。

在链表里，一旦你找到了插入位置的前驱节点 `prev`，插入动作只需要改两条指针：

```python
cur.next = prev.next
prev.next = cur
```

所以链表版插入排序的关键不在于“怎么搬”，而在于：

```text
怎么找到 cur 应该插到哪里
```

也就是说，这题最关键的动作其实是：

```text
在已排序链表里寻找插入位置
```

---

## 为什么这题里 `dummy` 特别重要

这题最麻烦的边界情况是：

```text
当前节点要插到整个有序链表的最前面
```

比如：

```text
4 -> 2 -> 1 -> 3
```

当你处理 `2` 时，它应该插到 `4` 前面。

如果没有 `dummy`，你就得单独判断：

- 这次是不是要改头节点
- 新头是谁
- 头插入和中间插入怎么统一

而加了哑节点以后：

```text
dummy -> 已排序链表
```

所有插入操作都会统一成：

```text
把当前节点插到某个前驱节点之后
```

哪怕是插到真正头节点前面，前驱也仍然是 `dummy`。

所以这题里 `dummy` 基本是必备工具。

---

## 这题和 `148` 的关系

这点很值得顺手讲清楚。

`147` 题是在练：

```text
链表版插入排序
```

它的意义更像是：

- 让你学会链表里的局部插入
- 让你理解“有序前缀 + 当前节点插入”这个过程
- 作为链表排序入门题

但如果题目只是问“把链表排序”，那更好的主线通常是 `148`：

```text
归并排序链表，时间复杂度 O(n log n)
```

所以你可以这样理解两题关系：

- **`147`**：练链表插入排序过程，重点是技巧和结构理解
- **`148`**：练真正高效的链表排序，重点是分治和归并

这也是为什么 `147` 常被放在 `148` 前面做。

## 方法一：收集值后排序再覆盖回链表

### 思路

最直观的保底方法是：

1. 遍历链表，把所有节点值收集到数组里
2. 对数组排序
3. 再遍历原链表，把排好序的值依次写回节点

例如：

```text
4 -> 2 -> 1 -> 3
```

先收集出：

```text
[4, 2, 1, 3]
```

排序后：

```text
[1, 2, 3, 4]
```

再把这些值覆盖回原链表，就得到答案。

---

### 代码

```python
class Solution:
    def insertionSortList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        values = []
        cur = head

        while cur:
            values.append(cur.val)
            cur = cur.next

        values.sort()

        cur = head
        for value in values:
            cur.val = value
            cur = cur.next

        return head
```

---

### 为什么可行

因为排序后的数组已经给出了正确顺序。

只要你把这些值依次写回原链表，最终链表里的值序就会正确。

---

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：`O(n)`

---

### 它的不足

这个方法能做，但它其实有两个明显问题：

### 1. 它不是真正的“链表插入排序”

它只是借助数组先排好序，再把结果写回来。

换句话说：

```text
它做的是“排序值”，不是“在链表里做插入过程”
```

### 2. 它没有练到链表指针能力

这题更值得掌握的是：

```text
从链表里摘出当前节点，再把它插到已排序部分的正确位置
```

所以真正该主记的还是方法二、方法三。

---

## 方法二：哑节点 + 每次从头找插入位置

### 核心思路

这是最标准、最朴素的链表插入排序。

我们维护一条新的已排序链表，头部用 `dummy` 统一管理。

每次从原链表里拿出一个节点 `cur`，然后做两件事：

1. 从 `dummy` 开始向后扫描，找到第一个比 `cur.val` 大的位置前驱 `prev`
2. 把 `cur` 插到 `prev` 和 `prev.next` 之间

整个过程就是不断重复：

```text
摘当前节点 -> 在已排序部分里找位置 -> 插进去
```

这才是插入排序在链表上的原始形态。

---

## 为什么这个思路能想到

因为“插入排序”这个名字本身就在提示你：

```text
不是整体重排，而是每次只处理一个当前节点，把它插进前面已经排好序的部分
```

在链表里，这就自然对应成：

- 前面已有序
- 当前节点单独拿出来
- 从前往后找插入点
- 改两条指针完成插入

所以这题最本质的过程就是：

```text
维护一个越来越长的有序链表
```

---

## 用例子走一遍

假设原链表是：

```text
4 -> 2 -> 1 -> 3
```

开始时，已排序部分为空：

```text
dummy -> None
```

### 第 1 步：处理 `4`

当前 `cur = 4`。

从 `dummy` 开始找位置，发现后面没有节点，直接插入：

```text
dummy -> 4
```

### 第 2 步：处理 `2`

当前 `cur = 2`。

从 `dummy` 开始找，发现 `4 > 2`，所以 `2` 应该插在 `4` 前面：

```text
dummy -> 2 -> 4
```

### 第 3 步：处理 `1`

同理，`1` 应该插到最前面：

```text
dummy -> 1 -> 2 -> 4
```

### 第 4 步：处理 `3`

从头扫描，经过 `1`、`2`，停在 `2` 后面，因为：

- `2 <= 3`
- `4 > 3`

所以插入后得到：

```text
dummy -> 1 -> 2 -> 3 -> 4
```

最后返回 `dummy.next`。

---

### 面试代码

```python
class Solution:
    def insertionSortList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0)
        cur = head

        while cur:
            next_node = cur.next

            prev = dummy
            while prev.next and prev.next.val <= cur.val:
                prev = prev.next

            cur.next = prev.next
            prev.next = cur
            cur = next_node

        return dummy.next
```

---

### 为什么可行

因为在每一轮开始前，我们都能保证：

```text
dummy 后面的链表已经有序
```

于是当前节点 `cur` 只需要插到那个有序链表里的正确位置，
插完以后，整条链表仍然有序。

这就是标准插入排序的不变式。

---

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

---

### 它的不足

这个方法虽然完全符合插入排序定义，但有一个明显缺点：

```text
不管当前节点本来是不是已经在正确位置，每次都要从 dummy 重新扫一遍
```

如果原链表本来就几乎有序，这样会做很多重复扫描。

所以更自然的问题就是：

```text
能不能先判断一下当前节点是不是本来就应该接在已排序尾部，如果是，就别回头重扫？
```

这就来到方法三。

---

## 方法三：维护已排序尾节点 `last_sorted`（面试主推）

### 核心思路

方法三仍然是插入排序，只是做了一个很重要的优化。

我们额外维护：

- `last_sorted`：当前已排序部分的最后一个节点
- `cur`：下一个待处理节点，也就是 `last_sorted.next`

此时分两种情况：

### 情况 1：`cur` 本来就应该接在尾部

如果：

```text
last_sorted.val <= cur.val
```

说明当前节点 `cur` 已经不破坏顺序了，它就应该继续待在已排序尾部后面。

那这时根本不用插入，只需要：

```text
把 last_sorted 往后挪一格
```

### 情况 2：`cur` 应该插到前面

如果：

```text
last_sorted.val > cur.val
```

说明顺序被打破了，当前节点应该插到前面去。

这时才从 `dummy` 开始向后找位置，把 `cur` 插进去。

所以方法三最值得记的一句话就是：

```text
只有当当前节点打破有序尾部时，才回头扫描寻找插入位置；如果当前节点本来就比尾部大，直接跳过
```

---

## 为什么这个优化很自然

因为插入排序的很多输入并不是完全乱序。

例如：

```text
1 -> 2 -> 3 -> 5 -> 4
```

前面大部分都已经有序，真正“出问题”的只有最后一个 `4`。

如果你还是每次都从头扫描，就太浪费了。

而方法三的观察是：

```text
如果当前节点已经 >= 已排序部分尾值，那它根本不用重新插
```

这个判断可以帮你跳过很多无意义扫描。

所以它依然是插入排序，只是更贴近“局部失序才修正”的直觉。

---

## 用例子完整走一遍

假设：

```text
head = -1 -> 5 -> 3 -> 4 -> 0
```

开始时：

- 已排序部分先看作 `-1`
- `last_sorted = -1`
- `cur = 5`

### 第 1 步：处理 `5`

因为：

```text
-1 <= 5
```

说明 `5` 本来就该接在尾部。

所以直接：

- `last_sorted` 移到 `5`
- `cur` 移到 `3`

已排序部分逻辑上变成：

```text
-1 -> 5
```

### 第 2 步：处理 `3`

发现：

```text
5 > 3
```

说明 `3` 不能待在当前尾部后面，要插回前面。

从 `dummy` 开始找，最后会插到 `-1` 和 `5` 之间：

```text
-1 -> 3 -> 5 -> 4 -> 0
```

注意这时：

- `last_sorted` 仍然是 `5`
- 因为 `5` 还是当前已排序部分的尾部
- 下一待处理节点变成 `4`

### 第 3 步：处理 `4`

发现：

```text
5 > 4
```

继续从头找位置，插到 `3` 和 `5` 之间：

```text
-1 -> 3 -> 4 -> 5 -> 0
```

### 第 4 步：处理 `0`

发现：

```text
5 > 0
```

从头找位置，插到 `-1` 和 `3` 之间：

```text
-1 -> 0 -> 3 -> 4 -> 5
```

排序完成。

---

### 面试代码

```python
class Solution:
    def insertionSortList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if head is None or head.next is None:
            return head

        dummy = ListNode(0, head)
        last_sorted = head
        cur = head.next

        while cur:
            if last_sorted.val <= cur.val:
                last_sorted = cur
            else:
                prev = dummy
                while prev.next and prev.next.val <= cur.val:
                    prev = prev.next

                last_sorted.next = cur.next
                cur.next = prev.next
                prev.next = cur

            cur = last_sorted.next

        return dummy.next
```

---

### 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 它仍然完全符合插入排序定义

它没有换排序方法，本质上还是：

```text
当前节点如果不在正确位置，就把它插入到已排序部分里
```

所以这仍然是插入排序，不是别的技巧替代。

### 2. 它比基础版更聪明

它不会机械地每次从头扫，而是先利用：

```text
已排序部分尾节点的值
```

做一次快速判断。

这使得“本来就有序”或“接近有序”的情况会快很多。

### 3. 它最能体现插入排序的特点

插入排序的典型优势本来就不是最坏情况，而是：

```text
数据已经部分有序时，能利用已有顺序
```

方法三正好把这个特点体现出来了。

### 4. 它是 `147` 这题最值得掌握的版本

虽然最坏情况仍是 `O(n^2)`，但这题本来考的就不是 `148` 那种最优排序复杂度，
而是链表版插入排序本身。

---

### 容易出错的地方

### 1. 插入前忘了先把 `cur` 从原位置摘出来

也就是忘了：

```python
last_sorted.next = cur.next
```

如果你不先摘掉 `cur`，后面再把它插入前面，链表结构就会乱。

### 2. 插入后错误地移动 `last_sorted`

当 `cur` 被插到前面时：

```text
last_sorted 不能动
```

因为已排序尾部并没有变，尾部仍然是原来的 `last_sorted`。

### 3. 搜索插入位置时忘了从 `dummy` 开始

因为当前节点可能要插到整个链表最前面。

如果不是从 `dummy` 开始，就很容易漏掉头插入情况。

### 4. 误以为这题最优复杂度应该是 `O(n log n)`

不是。

这题指定的是：

```text
插入排序
```

所以它的重点在“插入排序过程如何在链表上实现”，而不是追求一般排序题的最优上界。

如果想练真正的链表高效排序，那是 `148` 的主线。

---

### 面试里怎么讲

你可以这样解释：

```text
我会把链表看成“已排序部分 + 待处理部分”。基础做法是每次拿当前节点，从 dummy 开始在已排序部分里寻找插入位置，再把它插进去。进一步优化时，我维护一个 last_sorted 表示已排序部分的尾节点。如果当前节点 cur 的值本来就不小于尾节点值，说明它已经在正确位置，只需要把 last_sorted 向后移动；只有当 cur 打破有序性时，我才从 dummy 开始寻找插入位置并把 cur 插回前面。这样仍然是插入排序，额外空间 O(1)，最坏时间复杂度 O(n^2)，但在链表已经部分有序时会更高效。
```

这就是这题最标准的讲法。

---

## 三种方法的关系

这题三种做法的递进关系很清楚：

- **方法一**：先把值拿出来排序再写回，最直观但不是真正链表插入排序
- **方法二**：标准链表插入排序，每次都从头找插入位置
- **方法三**：在方法二基础上用 `last_sorted` 做优化，这是面试主推

这题最值得抓住的一句话是：

```text
147 题的核心不是“把链表排好”，而是“维护一个有序前缀，并把当前节点插回这个有序前缀的正确位置”
```

只要这句话真正想通，方法二和方法三都会很自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：收集值后排序再覆盖回链表 | `O(n log n)` | `O(n)` | 最直观，但不是真正链表插入排序 |
| 方法二：哑节点 + 每次从头找插入位置 | `O(n^2)` | `O(1)` | 标准插入排序主线 |
| 方法三：维护已排序尾节点 `last_sorted` | `O(n^2)` 最坏，`O(n)` 最好 | `O(1)` | 面试主推 |

这题最重要的，不是死记某个模板，而是先想清楚：

```text
插入排序在链表里的本质，就是维护一段已经有序的链表，然后把当前节点插到这段有序链表的正确位置
```

如果你现在只准备记一个版本：

