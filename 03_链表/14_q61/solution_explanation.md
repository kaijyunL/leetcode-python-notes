# LeetCode 61. 旋转链表（Rotate List）解析

## 题目描述

给你一个链表的头节点 `head`，以及一个非负整数 `k`。

请你把链表向右旋转 `k` 个位置，并返回旋转后的新头节点。

例如：

```text
head = 1 -> 2 -> 3 -> 4 -> 5
k = 2
```

向右旋转两次后，结果是：

```text
4 -> 5 -> 1 -> 2 -> 3
```

再比如：

```text
head = 0 -> 1 -> 2
k = 4
```

因为链表长度是 `3`，所以右旋 `4` 次其实等价于右旋 `1` 次，结果是：

```text
2 -> 0 -> 1
```

---

## 先理解这题到底在考什么

这题表面上是在“把链表往右搬”，但真正考的是：

```text
你能不能把“重复旋转很多次”转化成“一次定位新的切分点”
```

如果按字面意思做，你会想到：

- 每次把最后一个节点拿到最前面
- 重复做 `k` 次

这当然能做，但会很慢。

这题真正的关键在于想明白：

```text
旋转之后，链表节点本身没有变，只是“从哪里断开、从哪里重新开始”变了
```

也就是说，这题的核心不是反复移动节点，而是：

```text
找到新的头节点和新的尾节点
```

这个视角一旦建立，方法二就会非常自然。

---

## 为什么 `k % n` 这一步特别重要

设链表长度是 `n`。

如果你把链表向右旋转 `n` 次，会发生什么？

```text
整条链表刚好转一圈，结果和原来完全一样
```

所以：

```text
右旋 k 次 和 右旋 (k % n) 次，效果完全相同
```

这一步非常关键，因为题目里的 `k` 可能远大于链表长度。

例如：

```text
head = 0 -> 1 -> 2
k = 4
n = 3
```

那真正有意义的旋转次数其实是：

```text
4 % 3 = 1
```

所以我们后面几乎一定会先做：

```python
k %= n
```

一旦取模后 `k == 0`，就说明旋转一整圈后回到原状，直接返回原链表即可。

---

## 为什么“成环再断开”是最自然的主线

原链表如果是：

```text
1 -> 2 -> 3 -> 4 -> 5
```

你想把最后两个节点 `4 -> 5` 挪到前面，本质上是在做：

```text
把链表从某个位置切开，然后把后半段接到前面
```

最自然的操作顺序其实是：

1. 先让原尾节点连回原头节点，形成一个环
2. 然后找到新的尾节点位置
3. 在新尾节点处断开这个环

为什么这样好想？因为一旦成环：

```text
从任何一个位置开始走，都能得到某种“旋转后的链表”
```

于是问题就不再是“怎么搬动后面那几段”，而变成：

```text
新的头在哪里，新的尾在哪里
```

这就是这题最标准的转化。

---

## 方法一：重复做单步右旋

### 思路

最直观的做法是每次只右旋一步：

1. 找到尾节点 `tail` 和尾节点前一个节点 `prev`
2. 让 `tail.next = head`
3. 更新 `head = tail`
4. 再让 `prev.next = None`

如果要右旋 `k` 次，就重复做 `k` 次。

例如：

```text
1 -> 2 -> 3 -> 4 -> 5
```

右旋一步会变成：

```text
5 -> 1 -> 2 -> 3 -> 4
```

再右旋一步：

```text
4 -> 5 -> 1 -> 2 -> 3
```

---

### 代码

```python
class Solution:
    def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        if head is None or head.next is None or k == 0:
            return head

        length = 0
        cur = head
        while cur:
            length += 1
            cur = cur.next

        k %= length
        if k == 0:
            return head

        for _ in range(k):
            prev = None
            tail = head
            while tail.next:
                prev = tail
                tail = tail.next

            tail.next = head
            head = tail
            prev.next = None

        return head
```

---

### 为什么可行

因为“右旋一步”这件事本身很明确：

```text
把最后一个节点摘下来，挂到最前面
```

重复做 `k` 次，自然就完成了右旋 `k` 次。

---

### 复杂度

- 时间复杂度：`O(k * n)`，若先取模则是 `O((k % n) * n)`
- 空间复杂度：`O(1)`

---

### 它的不足

这个方法好理解，但问题也很明显：

```text
每次旋转 1 步都要重新扫到尾部，太浪费了
```

而题目真正更值得掌握的是：

```text
不重复旋转，而是一次性找到新的切分位置
```

这就来到方法二。

---

## 方法二：求长度 + 成环 + 找新尾断开（面试主推）

### 核心思路

这题最标准的想法是：

```text
先把链表连成一个环，再在正确的位置断开
```

整个过程分成 4 步：

1. 遍历链表，求长度 `n`，并找到原尾节点 `old_tail`
2. 计算真实旋转次数：`k % n`
3. 让 `old_tail.next = head`，把链表连成环
4. 找到新的尾节点 `new_tail`，并在它后面断开

这题最值得记的一句话就是：

```text
右旋 k 次，本质上是把链表切成“前半段 + 后半段”，让后半段接到前面；成环后只需要找到新的尾节点，把环在那儿断开
```

---

## 为什么新的尾节点在第 `n - k - 1` 个位置

假设：

```text
1 -> 2 -> 3 -> 4 -> 5
n = 5, k = 2
```

右旋 2 次后，新的头节点应该是：

```text
4
```

因为后面两个节点 `4 -> 5` 会被搬到前面。

那新的尾节点自然就是：

```text
3
```

也就是说：

- 新头是原链表里的第 `n - k` 个节点（从 0 开始看是索引 `n-k`）
- 新尾是它前一个节点，也就是原链表里的第 `n - k - 1` 个节点

对于这个例子：

```text
n - k - 1 = 5 - 2 - 1 = 2
```

索引 2 对应的正是节点 `3`。

所以一个特别好记的结论是：

```text
成环后，从原头出发走 n-k-1 步，会停在新的尾节点
```

这就是后面代码里要做的事情。

---

## 用例子完整走一遍

假设：

```text
head = 1 -> 2 -> 3 -> 4 -> 5
k = 2
```

### 第 1 步：求长度和原尾

遍历后得到：

- `n = 5`
- `old_tail = 5`

### 第 2 步：取模

```text
k = 2 % 5 = 2
```

仍然是 2，不变。

### 第 3 步：成环

执行：

```text
5.next = 1
```

链表变成：

```text
1 -> 2 -> 3 -> 4 -> 5 -> 回到 1
```

### 第 4 步：找到新尾

新尾应该在：

```text
n - k - 1 = 5 - 2 - 1 = 2
```

也就是从原头 `1` 出发走 2 步：

- 第 0 个：`1`
- 第 1 个：`2`
- 第 2 个：`3`

所以：

```text
new_tail = 3
new_head = 4
```

### 第 5 步：断开环

执行：

```text
new_tail.next = None
```

于是链表变成：

```text
4 -> 5 -> 1 -> 2 -> 3
```

这就是答案。

---

### 面试代码

```python
class Solution:
    def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        if head is None or head.next is None or k == 0:
            return head

        length = 1
        old_tail = head
        while old_tail.next:
            length += 1
            old_tail = old_tail.next

        k %= length
        if k == 0:
            return head

        old_tail.next = head

        new_tail = head
        for _ in range(length - k - 1):
            new_tail = new_tail.next

        new_head = new_tail.next
        new_tail.next = None
        return new_head
```

---

## 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 把“重复旋转”变成“一次切分”

这题真正的思维升级就在这里：

```text
不是真的去转很多次，而是一次性找出转完后新的头尾位置
```

这是最值得掌握的地方。

### 2. `k % n` 把大数旋转压缩掉了

哪怕 `k` 很大，真正有效的旋转次数也不会超过 `n - 1`。

这让问题一下子变得很干净。

### 3. 成环再断开，逻辑特别统一

成环后，任何旋转结果都只是在某个地方断开环。

这个视角非常优雅，也非常好讲。

### 4. 复杂度最好

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这是这题最标准、最推荐现场手写的版本。

---

### 容易出错的地方

### 1. 忘了先对 `k` 取模

如果不取模，`k` 很大时你会做很多无意义的旋转判断。

而且这题最关键的数学化简就是：

```text
k %= n
```

### 2. `k % n == 0` 时忘了提前返回

如果 `k` 正好是长度的整数倍，旋转后链表不变。

这时如果你还继续成环，很容易把本来没问题的链表弄成环后再多写很多逻辑。

### 3. 新尾位置算错一位

最常见的错法就是把：

```text
length - k - 1
```

写成别的数字，导致新头和新尾错位。

你只要死记住一句：

```text
new_tail 是新头前一个节点
```

就不容易错。

### 4. 忘了最后断开环

也就是：

```python
new_tail.next = None
```

如果少了这句，结果链表会一直绕圈。

---

### 面试里怎么讲

你可以这样解释：

```text
我先遍历链表求出长度 n，并拿到原尾节点。因为右旋 n 次等于不动，所以我先把 k 变成 k % n。接着我把原尾连回原头，让链表形成一个环。这样问题就变成：找到新的尾节点并把环断开。右旋 k 次后，新头会是原链表里的第 n-k 个节点，所以新尾就是它前一个节点，也就是从原头走 n-k-1 步到达的位置。最后我记录 new_head = new_tail.next，再执行 new_tail.next = None 断开环，返回 new_head。这样时间复杂度 O(n)，额外空间复杂度 O(1)。
```

这就是这题最标准的讲法。

---

## 方法三：收集节点后按切分点重连

### 思路

如果你还没有完全适应“成环再断开”的想法，可以先用数组辅助理解。

做法是：

1. 先把所有节点按顺序收集到数组里
2. 设链表长度为 `n`，真实旋转次数为 `k % n`
3. 新头节点会是数组下标 `n-k` 处的节点
4. 新尾节点会是数组下标 `n-k-1` 处的节点
5. 把原尾连回原头，再在新尾处断开

这个方法其实仍然是在练：

```text
找新的头尾切分点
```

只是通过数组把位置关系看得更直观。

---

### 代码

```python
class Solution:
    def rotateRight(self, head: Optional[ListNode], k: int) -> Optional[ListNode]:
        if head is None or head.next is None or k == 0:
            return head

        nodes = []
        cur = head
        while cur:
            nodes.append(cur)
            cur = cur.next

        n = len(nodes)
        k %= n
        if k == 0:
            return head

        new_tail = nodes[n - k - 1]
        new_head = new_tail.next
        nodes[-1].next = head
        new_tail.next = None
        return new_head
```

---

### 为什么可行

因为数组把链表节点的位置关系直接显式化了。

一旦你知道：

- 哪个节点是新头
- 哪个节点是新尾

后面就只是两步固定操作：

```text
原尾接原头，新尾断开
```

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 它适合什么时候学

它适合作为：

- 帮你先看懂“旋转本质上是在改切分点”
- 用数组视角理解 `n-k` 和 `n-k-1` 的位置含义
- 对比“位置直观”和“原地成环”两种写法

但如果你现在只准备记一个版本：

```text
还是优先记方法二
```

因为方法二才是最标准、最省空间的写法。

---

## 三种方法的关系

这题三种做法的递进关系很清楚：

- **方法一**：真的去做“每次右旋一步”，最直观但效率低
- **方法二**：先求长度、成环、找到新尾后断开，这是面试主推
- **方法三**：用数组把新头新尾的位置关系看得更直观

这题最值得抓住的一句话是：

```text
61 题不是在反复旋转节点，而是在找到旋转完成后新的头节点和尾节点，然后改一次切分点
```

只要这句话真正想通，方法二就会非常自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：重复做单步右旋 | `O((k % n) * n)` | `O(1)` | 直观保底，但重复扫描太多 |
| 方法二：求长度 + 成环 + 找新尾断开 | `O(n)` | `O(1)` | 面试主推 |
| 方法三：收集节点后按切分点重连 | `O(n)` | `O(n)` | 有助于理解切分点位置 |

---

## 总结

这题最重要的不是背某个“旋转模板”，而是先想清楚：

```text
旋转不会改变节点集合，只会改变从哪里开始、在哪里断开；所以核心是定位新的头尾，而不是重复搬节点
```

如果你现在只准备记一个版本：

```text
就记方法二：求长度 + 成环 + 找新尾断开
```
