# LeetCode 160. 相交链表（Intersection of Two Linked Lists）解析

## 题目描述

给你两个单链表的头节点 `headA` 和 `headB`，请你找出并返回两个链表相交的起始节点。

如果两个链表没有交点，返回 `None`。

这里的“相交”要特别注意，不是值相同，而是：

```text
两个链表从某个节点开始，后面整段都是同一批节点
```

也就是说，判断是否相交时，比的是：

```text
是不是同一个节点对象
```

而不是 `val` 是否相等。

例如：

```text
A: 4 -> 1 -> 8 -> 4 -> 5
B: 5 -> 6 -> 1 -> 8 -> 4 -> 5
```

如果两个链表真的在值为 `8` 的位置相交，那么这个 `8` 后面的 `4 -> 5` 也都必须是共享节点。

---

## 先理解这题在考什么

这题表面上是在找“两个链表里有没有相同部分”，但真正考的是：

```text
怎样判断两个链表是否指向同一个节点引用
```

一旦两个链表相交，就会出现一个很重要的性质：

```text
从交点开始，后面的所有节点都完全重合
```

所以你要找的其实就是：

- 第一个公共节点引用
- 而不是第一个相同数值

这也是这题最容易想错的地方。

---

## 方法一：暴力枚举比较节点引用

### 思路

最直观的办法就是：

1. 先遍历链表 `A` 的每一个节点
2. 对于 `A` 中的每个节点，再完整遍历一遍链表 `B`
3. 只要发现某个节点是同一个对象，就返回它

也就是把问题写成：

```text
A 里的每个节点，去 B 里挨个比一遍
```

---

### 代码

```python
class Solution:
    def getIntersectionNode(
        self,
        headA: Optional[ListNode],
        headB: Optional[ListNode],
    ) -> Optional[ListNode]:
        a = headA

        while a:
            b = headB
            while b:
                if a is b:
                    return a
                b = b.next
            a = a.next

        return None
```

---

### 为什么可行

因为如果两条链表真的相交，那么交点一定同时出现在 `A` 和 `B` 的遍历过程中。

暴力法虽然慢，但它没有漏掉任何可能的节点对，所以最终一定能找到答案。

---

### 复杂度

- 时间复杂度：`O(m * n)`
- 空间复杂度：`O(1)`

---

### 不足在哪里

这个方法最大的问题是：

```text
大量重复比较，太慢
```

如果 `A` 长度是 `m`，`B` 长度是 `n`，最坏情况下几乎要把两条链表两两全比一遍。

所以自然会想到：

```text
能不能把一条链表访问过的节点先记下来？
```

这就来到方法二。

---

## 方法二：哈希集合记录访问过的节点

### 思路

先遍历链表 `A`，把每个节点对象都放进哈希集合。

然后再遍历链表 `B`：

- 如果当前节点已经在集合里，说明这个节点就是交点
- 如果不在，就继续往后走

本质上是把“查某个节点是否在 `A` 里出现过”这件事，从线性查找优化成了哈希查找。

---

### 代码

```python
class Solution:
    def getIntersectionNode(
        self,
        headA: Optional[ListNode],
        headB: Optional[ListNode],
    ) -> Optional[ListNode]:
        seen = set()
        cur = headA

        while cur:
            seen.add(cur)
            cur = cur.next

        cur = headB
        while cur:
            if cur in seen:
                return cur
            cur = cur.next

        return None
```

---

### 为什么可行

因为集合里存的是链表 `A` 的所有节点引用。

所以当你遍历链表 `B` 时，只要发现某个节点已经在集合里，就说明：

```text
这个节点同时属于 A 和 B
```

它自然就是交点。

---

### 复杂度

- 时间复杂度：`O(m + n)`
- 空间复杂度：`O(m)`

---

### 不足在哪里

这个方法已经很快了，但它还要额外开一个集合。

而这题其实还有一个更巧妙的方法，可以做到：

- 时间复杂度仍然是 `O(m + n)`
- 额外空间复杂度降到 `O(1)`

这就是方法三。

---

## 方法三：双指针走等距（面试主推）

### 核心思路

这是这题最经典、最值得记住的方法。

假设：

- 链表 `A` 独有部分长度是 `a`
- 链表 `B` 独有部分长度是 `b`
- 公共部分长度是 `c`

那么：

- 指针 `p1` 先走 `A` 再走 `B`，总路程是 `a + c + b`
- 指针 `p2` 先走 `B` 再走 `A`，总路程是 `b + c + a`

也就是：

```text
A + B 和 B + A 的总长度完全一样
```

所以只要让：

- `p1` 走完 `A` 就切到 `headB`
- `p2` 走完 `B` 就切到 `headA`

那么它们最终一定会在同一个位置相遇。

如果有交点，就会在交点相遇；如果没有交点，就会在 `None` 相遇。

---

## 为什么这个思路能想到

这题真正难的地方，不是代码，而是直觉。

很多人一开始会想：

```text
两条链表长度不一样，怎么对齐？
```

双指针法的妙处就在于：

```text
不手动算长度，也能自动把长度差补回来
```

谁先走完自己的链表，就去走对方的链表。

这样一来：

- 长链表多出来的那一段
- 会被另一个指针在第二轮补走掉

最后两个指针走过的总路程完全一样，于是就对齐了。

这就是“走等距”的本质。

---

## 用例子走一遍

假设：

```text
A: 4 -> 1 -> 8 -> 4 -> 5
B: 5 -> 6 -> 1 -> 8 -> 4 -> 5
```

公共部分是：

```text
8 -> 4 -> 5
```

其中：

- `A` 独有部分是 `4 -> 1`
- `B` 独有部分是 `5 -> 6 -> 1`

开始时：

```text
p1 = headA
p2 = headB
```

### 第一轮

- `p1` 先走完 `A`
- `p2` 先走完 `B`

这时候它们还没对齐，因为两条链表前面的独有部分长度不同。

### 切换头节点后

- `p1` 去走 `B`
- `p2` 去走 `A`

此时两个人都把“自己没走过的那条链表前缀”补走了一遍。

最终它们会一起到达：

```text
值为 8 的那个共享节点
```

如果这题没有交点，那么它们最终会一起变成：

```text
None
```

---

### 面试代码

```python
class Solution:
    def getIntersectionNode(
        self,
        headA: Optional[ListNode],
        headB: Optional[ListNode],
    ) -> Optional[ListNode]:
        p1 = headA
        p2 = headB

        while p1 is not p2:
            p1 = p1.next if p1 else headB
            p2 = p2.next if p2 else headA

        return p1
```

---

### 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 用满了题目结构

它真正抓住了这题的核心：

```text
两条链表前缀长度不同，但总长度可以通过换头补齐
```

### 2. 不需要额外空间

不建集合，不改链表，只靠两个指针就能完成。

### 3. 代码短，而且稳定

核心循环就一行切换逻辑，面试时非常适合手写。

### 4. 复杂度最好

- 时间复杂度：`O(m + n)`
- 空间复杂度：`O(1)`

这是这题最标准、最推荐现场手写的版本。

---

### 容易出错的地方

### 1. 把“相交”理解成值相等

这题一定要比较：

```text
是不是同一个节点对象
```

而不是：

```text
节点值是不是一样
```

所以代码里更准确的写法是：

```text
p1 is p2
```

而不是只比 `val`。

### 2. 以为没交点时会死循环

不会。

如果没有交点，两个指针最终都会走完整个 `A + B` 和 `B + A`，然后一起变成 `None`。

这时：

```text
None is None
```

循环自然结束。

### 3. 想先手动算长度

当然也可以先算长度再对齐，但那样步骤更多、代码更绕。

这题最值得掌握的，其实就是这种“不算长度、自动对齐”的双指针思想。

---

### 面试里怎么讲

你可以这样解释：

```text
我用两个指针 p1 和 p2，分别从 headA 和 headB 出发。
p1 走完 A 就去走 B，p2 走完 B 就去走 A。
这样两个指针最终都会走过 A+B 和 B+A 这两段总长度相同的路径。
如果两条链表相交，它们会在第一个公共节点相遇；如果不相交，它们会同时走到 None。
整个过程只遍历两条链表各最多两次，时间复杂度是 O(m+n)，额外空间复杂度是 O(1)。
```

这就是这题最标准的讲法。

---

## 三种方法的关系

这题三种做法的递进关系也很清楚：

- **方法一**：什么条件都不利用，直接两两比较节点
- **方法二**：用哈希集合把“是否访问过”优化掉
- **方法三**：不用额外空间，靠双指针自动补齐长度差，这是面试主推

这题最值得抓住的一句话就是：

```text
不是找相同值，而是找第一个相同节点引用
```

理解了这句话，再配合“双指针走等距”，这题就真正通了。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力枚举比较节点引用 | `O(m * n)` | `O(1)` | 能做，但重复比较太多 |
| 方法二：哈希集合记录节点 | `O(m + n)` | `O(m)` | 直观好写，但要额外空间 |
| 方法三：双指针走等距 | `O(m + n)` | `O(1)` | 面试主推 |

---

## 总结

这题最重要的不是背结论，而是想清楚两件事：

```text
第一，相交比的是节点引用，不是节点值；
第二，双指针通过“走完自己再走对方”可以自动补齐长度差。
```

如果你现在只准备记一个版本：

```text
就记方法三：双指针走等距
```
