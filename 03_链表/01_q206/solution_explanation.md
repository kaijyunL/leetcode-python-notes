# LeetCode 206. 反转链表（Reverse Linked List）解析

## 题目描述

给你单链表的头节点 `head`，请你把链表反转，并返回反转后的头节点。

例如：

```text
输入：1 -> 2 -> 3 -> 4 -> 5 -> None
输出：5 -> 4 -> 3 -> 2 -> 1 -> None
```

这题的关键不是“把值倒过来写一遍”，而是要真正理解：

```text
怎样把每个节点的 next 指针方向反过来
```

---

## 先理解题意

如果这是数组，反转很简单，因为我们可以直接按下标访问。

但链表不一样。

链表里的每个节点只知道：

- 自己的值
- 下一个节点是谁

所以这题真正考的是：

```text
你能不能在遍历链表的过程中，安全地修改指针方向，同时不把后面的链表弄丢
```

这里最容易出错的点只有一个：

```text
当前节点一旦改了 next，就可能找不到原来的下一个节点
```

所以后面所有正确做法，本质上都在解决这件事。

---

## 方法一：辅助数组重建答案

### 思路

最直观的想法是：

1. 先遍历一遍链表，把所有节点值收集到数组里
2. 再从后往前读取数组，重建一条新的链表

例如：

```text
head = 1 -> 2 -> 3
```

先收集出：

```text
[1, 2, 3]
```

再倒着建新链表：

```text
3 -> 2 -> 1
```

这个方法的好处是：

```text
完全不需要在原链表上做复杂指针操作
```

所以它很适合拿来建立最初直觉。

---

### 代码

```python
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        values = []
        current = head

        while current:
            values.append(current.val)
            current = current.next

        dummy = ListNode(0)
        tail = dummy

        for value in reversed(values):
            tail.next = ListNode(value)
            tail = tail.next

        return dummy.next
```

---

### 为什么可行

因为它把问题拆成了两步：

- 原链表负责提供顺序
- 新链表负责生成反向结果

只要数组里的值顺序正确，倒着重建出来的新链表顺序也一定正确。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 不足在哪里

这个方法虽然容易想到，但它没有利用链表本身的结构优势。

它的问题是：

- 额外用了数组
- 额外新建了链表
- 不是面试里最想看到的“原地反转指针”

所以接下来更自然的问题就是：

```text
能不能不借助额外数组，而是直接把 next 指针反过来？
```

这就来到方法二。

---

## 方法二：双指针迭代反转（面试主推）

### 核心思路

如果当前节点是 `cur`，前一个已经反转好的节点是 `pre`，那么当前这一步最关键的动作就是：

```text
把 cur.next 从“指向后面”改成“指向前面”
```

也就是：

```text
cur.next = pre
```

但在改之前，必须先把原来的下一个节点存起来，不然链表会断掉。

所以每轮循环固定做 4 件事：

1. 先保存 `next_node = cur.next`
2. 再执行反转 `cur.next = pre`
3. 然后移动 `pre = cur`
4. 最后移动 `cur = next_node`

---

## 为什么这个思路能想到

因为题目要求的不是排序、不是重建，而是：

```text
把每条边的方向反过来
```

链表里每个节点只有一条 `next` 边，所以反转本质上就是在遍历时不断做：

```text
当前节点指回前一个节点
```

于是我们自然就会需要两个角色：

- `pre`：表示已经反转好的前半段头节点
- `cur`：表示当前正在处理的节点

而 `next_node` 只是为了防止断链的临时变量。

这就是这题最核心的推导过程。

---

## 用例子把过程走一遍

假设：

```text
1 -> 2 -> 3 -> None
```

开始时：

```text
pre = None
cur = 1
```

### 第 1 轮

先保存：

```text
next_node = 2
```

然后反转：

```text
1.next = None
```

此时链表局部变成：

```text
1 -> None
```

再移动：

```text
pre = 1
cur = 2
```

### 第 2 轮

先保存：

```text
next_node = 3
```

反转：

```text
2.next = 1
```

局部变成：

```text
2 -> 1 -> None
```

再移动：

```text
pre = 2
cur = 3
```

### 第 3 轮

先保存：

```text
next_node = None
```

反转：

```text
3.next = 2
```

得到：

```text
3 -> 2 -> 1 -> None
```

最后：

```text
pre = 3
cur = None
```

循环结束，返回 `pre`。

---

### 面试代码

```python
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        pre = None
        cur = head

        while cur:
            next_node = cur.next
            cur.next = pre
            pre = cur
            cur = next_node

        return pre
```

---

### 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

原因很简单：

### 1. 逻辑最贴题意

它做的就是这题本身要你做的事：

```text
逐个节点反转 next 指针
```

### 2. 代码最短、最稳

你只需要记住循环里的 4 步：

```text
存后继 -> 反转指针 -> pre 前进 -> cur 前进
```

现场非常容易复现。

### 3. 复杂度最好

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这是这题最经典、最标准、也最适合手写的版本。

---

### 容易出错的地方

这题面试最容易错的不是大思路，而是顺序。

一定要先：

```text
保存 cur.next
```

再去改：

```text
cur.next = pre
```

如果顺序反了，你就再也找不到后面的链表了。

---

### 面试里怎么讲

你可以直接这样解释：

```text
我用两个指针 pre 和 cur。
pre 表示已经反转好的前半段链表头，cur 表示当前要处理的节点。
每次先保存 cur 的下一个节点，避免断链；
然后把 cur.next 指向 pre，完成当前节点的反转；
接着让 pre 和 cur 一起往前推进。
当 cur 走到空时，pre 就是新的头节点。
```

如果你能把这段话顺着讲出来，这题基本就算真正掌握了。

---

## 方法三：递归反转（补充理解）

### 思路

递归的想法是：

```text
先把 head 后面的链表反转好，再回来处理 head 自己
```

也就是说，假设：

```text
head -> head.next -> ...
```

后半段已经被递归地反转完成，那么当前这一层只需要做两件事：

1. 让 `head.next.next = head`
2. 让 `head.next = None`

这样当前节点就接到反转后链表的尾部去了。

---

### 代码

```python
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        if not head or not head.next:
            return head

        new_head = self.reverseList(head.next)
        head.next.next = head
        head.next = None
        return new_head
```

---

### 为什么可行

因为递归函数返回的是：

```text
以 head.next 为起点的那段链表反转后的新头节点
```

既然后半段已经反转好了，那么当前层只要把自己接到那段链表后面即可。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

这里的空间复杂度不是新开数组，而是递归调用栈。

---

### 它适合什么时候学

它适合作为：

- 对“链表反转”更深一层的理解
- 练递归思维
- 看懂 `head.next.next = head` 这种写法到底为什么成立

但如果你当前目标是：

```text
面试时只记一个最稳版本
```

那还是优先记方法二，不要主记递归。

---

## 三种方法的关系

这题三种做法的递进关系其实非常清楚：

- **方法一**：先别碰复杂指针，先用数组把“反过来”这件事看明白
- **方法二**：开始真正原地反转 `next` 指针，这是面试主解
- **方法三**：把同样的指针反转逻辑，换成递归视角理解

所以你复习时最好的顺序是：

```text
先理解方法二
如果还想加深，再看方法三
方法一只作为最初直觉补充
```

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：辅助数组重建答案 | `O(n)` | `O(n)` | 好理解，但不是原地反转 |
| 方法二：双指针迭代反转 | `O(n)` | `O(1)` | 面试主推 |
| 方法三：递归反转 | `O(n)` | `O(n)` | 有助于理解，但现场不如迭代稳 |

---

## 总结

这题最重要的不是背“反转链表模板”，而是把下面这句话真正想明白：

```text
我在修改当前节点 next 之前，必须先保存原来的下一个节点
```

只要这句话你是通的，方法二就能很自然地写出来。

如果你现在只准备记一个版本：

```text
就记方法二：双指针迭代反转
```
