# LeetCode 141. 环形链表（Linked List Cycle）解析

## 题目描述

给你一个链表的头节点 `head`，判断链表中是否有环。

如果链表中有某个节点，可以通过不断沿着 `next` 指针继续走，最终又回到之前访问过的某个节点，那么这个链表就有环。

返回：

- 有环：`True`
- 无环：`False`

注意题目里的 `pos` 只是评测系统用来描述“尾节点连回哪个位置”的辅助信息，**不是函数参数**。

---

## 先理解这题在考什么

这题表面上是在问“链表会不会无限走下去”，但本质其实是：

```text
如何判断遍历过程中是否回到了之前访问过的节点
```

如果你从 `head` 出发一直沿着 `next` 走：

- **无环**：最终一定会走到 `None`
- **有环**：你会在环里一直绕圈，永远走不到 `None`

所以这题的关键不在于值，而在于：

```text
某个节点是否被再次访问到
```

---

## 方法一：哈希集合记录访问过的节点

### 思路

最直观的思路就是：

1. 从头开始遍历链表
2. 每到一个节点，就看看它是否已经在集合里
3. 如果已经出现过，说明你绕回来了，链表有环
4. 如果没出现过，就把它加入集合继续走
5. 如果最后走到 `None`，说明无环

本质上就是把“是否来过这里”显式记下来。

---

### 代码

```python
class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        visited = set()
        cur = head

        while cur:
            if cur in visited:
                return True
            visited.add(cur)
            cur = cur.next

        return False
```

---

### 为什么可行

因为无环链表里的每个节点最多只会被访问一次。

如果某个节点第二次出现，只有一种可能：

```text
你已经进入了一个闭环
```

所以哈希集合能非常直接地判断出是否成环。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 不足在哪里

这个方法的缺点是：

```text
要额外开一个集合来记录访问历史
```

而这题更经典、也更常考的写法，是不用额外空间的快慢指针。

这就来到方法二。

---

## 方法二：Floyd 快慢指针（同一起点，面试主推）

### 核心思路

我们定义两个指针：

- `slow`：每次走 1 步
- `fast`：每次走 2 步

然后让它们都从 `head` 出发。

接下来会有两种情况：

- **如果没有环**：`fast` 一定会先走到 `None`
- **如果有环**：`fast` 进入环后会不断追上 `slow`，最终两者一定相遇

所以判断逻辑就是：

```text
能相遇就有环，走到空就无环
```

---

## 为什么这个思路能想到

这题的难点不在“遍历”，而在：

```text
不额外存历史，怎么知道自己是不是绕回来了？
```

如果只有一个指针，你很难知道当前是不是回到了以前的位置。

但一旦你让两个指针在环里以不同速度前进，就会出现一个关键现象：

```text
快指针每轮都会比慢指针多走一步
```

这意味着在环里，快慢指针之间的距离会不断变化。

只要有环，快指针迟早会从后面追上慢指针，就像跑道上的快选手套圈一样。

这就是 Floyd 判圈算法的核心直觉。

---

## 用例子走一遍

假设链表是：

```text
3 -> 2 -> 0 -> -4
     ^         |
     |_________|
```

也就是尾节点 `-4` 指回值为 `2` 的节点，形成一个环。

开始时：

```text
slow = head
fast = head
```

### 第 1 轮

- `slow` 走一步，到 `2`
- `fast` 走两步，到 `0`

### 第 2 轮

- `slow` 到 `0`
- `fast` 到 `2`

### 第 3 轮

- `slow` 到 `-4`
- `fast` 走两步后也到 `-4`

于是：

```text
slow is fast
```

说明有环。

如果没有环，那么 `fast` 总会更快到达链表末尾，此时就能直接返回 `False`。

---

### 面试代码

```python
class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        slow = head
        fast = head

        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next

            if slow is fast:
                return True

        return False
```

---

### 为什么这个方法最适合面试

如果这题你只记一种写法，就记这一种。

### 1. 不需要额外空间

整个过程只用了两个指针。

### 2. 代码短，而且稳定

循环条件和判断逻辑都非常清晰：

```text
fast 能走两步就继续；相遇就说明有环
```

### 3. 能直接衔接 `142`

`142. Linked List Cycle II` 就是在这个 Floyd 思路上继续往下推。

所以 `141` 最值得掌握的版本，就是这个“同一起点”的标准写法。

### 4. 复杂度最好

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这是这题最标准、最推荐现场手写的版本。

---

### 容易出错的地方

### 1. 忘了先判断 `fast` 和 `fast.next`

因为 `fast` 每次要走两步，所以循环前提必须是：

```text
fast and fast.next
```

否则会空指针出错。

### 2. 一上来就判断 `slow is fast`

如果你让 `slow = fast = head`，那一开始它们本来就相等。

所以正确写法是：

- 先移动
- 再判断是否相遇

### 3. 用值比较而不是节点比较

这题判断相遇，比的是：

```text
是不是同一个节点对象
```

所以更准确的写法是：

```text
slow is fast
```

而不是比较 `val`。

---

### 面试里怎么讲

你可以这样解释：

```text
我用 Floyd 快慢指针判断链表是否有环。
slow 每次走一步，fast 每次走两步。
如果链表无环，fast 最终会走到空；如果链表有环，fast 进入环后一定会追上 slow。
因此只要在遍历过程中出现 slow 和 fast 指向同一个节点，就说明链表有环。
整个过程时间复杂度 O(n)，额外空间复杂度 O(1)。
```

这就是这题最标准的讲法。

---

## 方法三：快慢指针错位起跑（补充理解）

### 思路

你也会经常看到另一种写法：

- `slow = head`
- `fast = head.next`

这样一来，两者初始时就不相等，所以可以直接写：

```python
while slow is not fast:
```

如果中途 `fast` 或 `fast.next` 为空，就说明没有环；否则继续移动，直到相遇。

这个版本本质上和方法二完全一样，仍然是 Floyd 判圈，只是：

```text
把“先移动再判断”换成了“错位起跑再循环判断”
```

---

### 代码

```python
class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        if not head or not head.next:
            return False

        slow = head
        fast = head.next

        while slow is not fast:
            if not fast or not fast.next:
                return False
            slow = slow.next
            fast = fast.next.next

        return True
```

---

### 为什么可行

虽然起点不同，但本质还是：

- `slow` 每轮走 1 步
- `fast` 每轮走 2 步
- 有环就会相遇
- 无环就会走到空

只是它把相遇判断写到了循环条件里。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 它适合什么时候学

它适合作为：

- 看到别人的题解时能认出来
- 理解同一个 Floyd 思想可以有不同写法
- 帮你看懂像 `while p1 is not p2` 这种“循环条件里判断相遇”的风格

但如果你现在是二刷，或者面试只准备记一个版本：

```text
还是优先记方法二
```

---

## 三种方法的关系

这题三种做法的递进关系很清楚：

- **方法一**：显式记录访问历史，最直观
- **方法二**：不用额外空间，标准 Floyd 判圈，这是面试主推
- **方法三**：和方法二本质一样，只是换一种循环写法

这题最值得抓住的一句话是：

```text
只要链表有环，快指针在环里迟早会追上慢指针
```

一旦这句话真正想通，`141` 和后面的 `142` 就都会顺很多。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：哈希集合记录节点 | `O(n)` | `O(n)` | 直观好懂，适合建立第一层理解 |
| 方法二：Floyd 快慢指针（同一起点） | `O(n)` | `O(1)` | 面试主推 |
| 方法三：快慢指针错位起跑 | `O(n)` | `O(1)` | 本质相同，作为补充理解 |

---

## 总结

这题最重要的不是背模板，而是想清楚：

```text
如果链表有环，那么两个速度不同的指针进入环后一定会相遇；
如果没有环，快指针一定先走到空。
```

如果你现在只准备记一个版本：

```text
就记方法二：Floyd 快慢指针（同一起点）
```
