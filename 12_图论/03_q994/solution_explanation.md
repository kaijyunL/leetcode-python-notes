# LeetCode 994. 腐烂的橘子（Rotting Oranges）

## 题目描述

给定一个 `m x n` 的网格 `grid`：

- `0`：空格子
- `1`：新鲜橘子
- `2`：腐烂橘子

每过一分钟，腐烂橘子会使它上下左右相邻的新鲜橘子腐烂。

求全部新鲜橘子腐烂所需的最少分钟数；如果有新鲜橘子永远无法腐烂，返回 `-1`。

---

## 先建立题感

这题最关键的一句话是：

> 所有腐烂橘子在同一分钟里同时感染四周。

它不是“从一个橘子出发，沿一条路一直传染到底”。而是像水波一样，一圈一圈往外扩散。

以题目样例为例：

```text
初始（第 0 分钟）
2 1 1
1 1 0
0 1 1
```

左上角 `(0, 0)` 是初始腐烂橘子。它在第 1 分钟只能感染 `(0, 1)` 和 `(1, 0)`：

```text
第 1 分钟后
2 2 1
2 1 0
0 1 1
```

这时 `(0, 1)`、`(1, 0)` 虽然已经腐烂，但它们要到第 2 分钟才能继续感染：

```text
第 2 分钟后
2 2 2
2 2 0
0 1 1
```

继续扩散：

```text
第 3 分钟后          第 4 分钟后
2 2 2               2 2 2
2 2 0               2 2 0
0 2 1               0 2 2
```

所以答案是 `4`。

你要先形成这个画面：

> 第几分钟腐烂，取决于它距离最近初始腐烂橘子的最短步数。

这正是 BFS 一层一层搜索所表达的含义。

---

## 这题和第 200 / 695 题有什么不同

这三题都在二维网格中上下左右移动，但问题不同：

| 题目 | 问什么 | 最自然的核心动作 |
| --- | --- | --- |
| 200 岛屿数量 | 有几个连通块 | 找到一块后把整块标记掉 |
| 695 最大岛屿面积 | 每个连通块多大 | DFS 返回一块的面积 |
| 994 腐烂的橘子 | 扩散最少要几轮 | 一层一层同步扩散 |

第 994 题不能直接照搬 200 / 695 的 DFS 直觉。

DFS 擅长“从一个点一路走到底”；但这题问的是“所有点同步扩散后，最晚什么时候到达”，因此必须保留层次。

---

## 循序渐进的解法分析

### 方法一：逐分钟扫描并统一更新（直观模拟）

这是最容易从题意直接写出来的方法。

#### 思路

每一分钟做三件事：

1. 扫描整个网格，找出当前所有值为 `2` 的腐烂橘子。
2. 查看它们上下左右是否有新鲜橘子，把这些新鲜橘子记到 `to_rot`。
3. 扫描结束后，统一把 `to_rot` 中的位置改为 `2`。

然后进入下一分钟。

#### 为什么不能在扫描时直接改成 `2`

仍以样例为例。第 1 分钟扫描到 `(0, 0)` 时，如果立刻把 `(0, 1)` 改成 `2`，之后扫描又走到 `(0, 1)`，它就会在同一分钟继续感染 `(0, 2)`。

这样程序会错误地认为：

```text
第 1 分钟： (0, 0) -> (0, 1) -> (0, 2)
```

但题意要求 `(0, 2)` 在第 2 分钟才腐烂。

因此要把“本分钟将腐烂的橘子”先暂存在 `to_rot` 中，等整轮扫描完成后再统一更新。

这就是模拟同步变化时最常见的规则：

> 先读取旧状态，收集新状态，最后一起提交。

#### 为什么会慢

假设网格是一条长链，感染需要 `O(mn)` 分钟才能传到最后。每一分钟都重新扫描 `O(mn)` 个格子，因此最坏时间复杂度是：

```text
O(mn) 分钟 × O(mn) 扫描 = O((mn)^2)
```

它正确、直观，但会反复检查大量已经无关的格子。

#### 复杂度

- 时间复杂度：`O((mn)^2)`
- 空间复杂度：`O(mn)`，最坏情况下 `to_rot` 会存放很多新腐烂位置。

### 方法二：多源 BFS（最适合面试）

这是本题的标准解法，也是面试主推。

#### 第一步：把“分钟”翻译为“BFS 的层”

普通 BFS 的特点是：

```text
第 0 层：起点
第 1 层：距离起点 1 步的位置
第 2 层：距离起点 2 步的位置
```

而本题中，一次上下左右感染就是走 1 步。

所以：

```text
第 0 层：初始腐烂橘子
第 1 层：第 1 分钟腐烂的橘子
第 2 层：第 2 分钟腐烂的橘子
```

这题不止一个起点怎么办？把所有初始腐烂橘子都同时放进队列。

这就叫**多源 BFS**：不是从一个起点开始，而是从多个起点同时开始。

#### 第二步：三个变量分别做什么

```python
queue = deque()
fresh = 0
minutes = 0
```

- `queue`：保存已经腐烂、可以在后续分钟向外感染的坐标。
- `fresh`：还剩多少新鲜橘子。它用于判断是否全部完成。
- `minutes`：已经完成了多少轮扩散。

初始化遍历网格时：

- 遇到 `2`：立刻入队，因为它从第 0 分钟就能感染别人。
- 遇到 `1`：`fresh += 1`。

#### 第三步：为什么要固定当前层大小

核心循环是：

```python
while queue and fresh:
    for _ in range(len(queue)):
        r, c = queue.popleft()
        # 感染相邻新鲜橘子，并把它们加入 queue
    minutes += 1
```

进入 `for` 前的 `len(queue)` 是“这一分钟开始时已经腐烂的橘子数量”。

这一轮中被感染的新橘子虽然会入队，但不能在本轮继续被取出处理；它们属于下一分钟。

例如样例中的队列变化：

```text
初始：queue = [(0, 0)]，fresh = 6，minutes = 0

处理第 0 层：只处理 (0, 0)
    感染 (1, 0)、(0, 1)
    queue 变为 [(1, 0), (0, 1)]
本层结束：minutes = 1

处理第 1 层：只处理 (1, 0)、(0, 1)
    感染 (1, 1)、(0, 2)
    queue 变为 [(1, 1), (0, 2)]
本层结束：minutes = 2

处理第 2 层：感染 (2, 1)
本层结束：minutes = 3

处理第 3 层：感染 (2, 2)
本层结束：minutes = 4，fresh = 0
```

如果不固定层大小，而是 `while queue:` 中一路 `popleft()`，第 1 分钟新增的橘子会在第 1 分钟继续扩散，分钟层次就丢失了。

#### 第四步：为什么新鲜橘子入队时要马上改为 `2`

```python
grid[nr][nc] = 2
fresh -= 1
queue.append((nr, nc))
```

一个新鲜橘子可能同时挨着两个腐烂橘子。

如果第一次发现它时不立刻标记为 `2`，第二个腐烂橘子也会把它再次加入队列，造成重复处理和 `fresh` 重复减少。

因此“发现时标记”既是访问标记，也是防重入队。

#### 第五步：为什么最后还要看 `fresh`

看这个例子：

```text
2 0 1
```

队列中的 `(0, 0)` 无法跨过 `0` 感染 `(0, 2)`。BFS 很快结束，但 `fresh` 仍然是 `1`。

所以：

```python
return minutes if fresh == 0 else -1
```

`queue` 空只表示“已经没有传播源了”；`fresh == 0` 才表示“所有新鲜橘子都处理完了”。

#### 为什么这是最适合面试的方法

1. **题意和模型完全一致**：同步扩散对应 BFS 分层。
2. **没有重复扫描**：每个格子最多入队一次。
3. **代码自然**：初始化全部感染源，按层处理四个方向。
4. **容易说清正确性**：第 `k` 层恰好就是第 `k` 分钟腐烂的橘子。

#### 面试时怎么讲

```text
这题是多源 BFS。所有初始腐烂橘子都是第 0 分钟的感染源，因此先全部入队。
BFS 每处理一层，就表示过去了一分钟；这一层的橘子感染相邻新鲜橘子，
新感染的橘子进入下一层。最后如果 fresh 归零，返回分钟数；否则说明存在隔离的新鲜橘子，返回 -1。
```

#### 复杂度

- 时间复杂度：`O(mn)`。每个格子至多入队、出队一次。
- 空间复杂度：`O(mn)`。最坏情况下队列会保存 `O(mn)` 个坐标。

## 边界情况

### 1. 一开始就没有新鲜橘子

```text
0 2
```

此时 `fresh == 0`，答案是 `0`，而不是 `1`。因为没有发生任何感染。

代码中的 `while queue and fresh` 会直接跳过循环，最后返回 `0`。

### 2. 没有腐烂橘子，但有新鲜橘子

```text
1 1
```

初始队列为空，无法开始传播，`fresh > 0`，最终返回 `-1`。

### 3. 有多个初始腐烂橘子

```text
2 1 2
```

两个 `2` 必须同时作为第 0 层入队；中间的 `1` 只需 1 分钟腐烂。

---

## 两种方法怎么选

### 如果你在理解题意

先理解方法一：同一分钟的变化要“先收集、后统一更新”。这样你会明白为什么时间不能被压缩。

### 如果你在准备面试

直接掌握方法二：**多源 BFS**。

它不是在方法一上硬套模板，而是把“每分钟同步扩散”准确翻译成“BFS 每一层”。

---

## 总结

- 方法一：逐分钟模拟，直观但反复扫描，`O((mn)^2)`。
- 方法二：多源 BFS，按层表示分钟，`O(mn)`，也是面试主推。
- 本题最重要的迁移点：看到“多个起点同时向外扩散，求最少轮数/最短时间”，优先想到多源 BFS。
