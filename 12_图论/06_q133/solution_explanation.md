# LeetCode 133. 克隆图

## 题目要我们做什么

题目给你一张无向连通图的一个节点对象 `node`，要求从这个起点出发，把整张图复制一份，并返回新图中对应的起点。

每个节点由下面这个类表示：

```python
class Node:
    def __init__(self, val=0, neighbors=None):
        self.val = val
        self.neighbors = neighbors if neighbors is not None else []
```

这里的 `neighbors` 不是邻居的数字列表，而是邻居的 `Node` 对象列表。比如节点 1 连着节点 2 和节点 4，实际关系是：

```text
node1.neighbors = [node2, node4]
```

### 邻接表和 Node 对象是什么关系

题目示例常用邻接表展示图：

```python
adjList = [[2, 4], [1, 3], [2, 4], [1, 3]]
```

它表示：

```text
节点 1 的邻居是节点 2、4
节点 2 的邻居是节点 1、3
节点 3 的邻居是节点 2、4
节点 4 的邻居是节点 1、3
```

也就是：

```text
1 ----- 2
|       |
|       |
4 ----- 3
```

邻接表是题目用来展示、输入和检查图结构的简洁形式。测试系统会根据它构造出 `Node` 对象之间的引用关系，再把起点对象传给 `cloneGraph`。因此函数里处理的是 `node.val` 和 `node.neighbors`，不是 `adjList` 这个二维列表。

### “克隆”具体要求什么

返回图的结构和原图一样：每个节点的值相同，邻居关系也相同；但返回图里的节点必须是新对象，不能继续引用原图节点。比如克隆后：

```text
原图：  node1 -> node2
新图： clone1 -> clone2
```

其中 `clone1.val == node1.val`，但 `clone1 is not node1`；并且 `clone1.neighbors` 中放的是 `clone2`，不是原图的 `node2`。这就是深拷贝。

如果起点是 `None`，没有图可复制，返回 `None`。

## 先建立题感

复制一张图需要给每个旧节点创建一个新节点，并把新节点按原来的邻居关系连起来。难点是图可能有环，所以同一个旧节点会从不同路径再次遇到；必须记住它已经对应哪个副本，才能复用这个副本并保留原图结构。

用字典记录：

```text
旧节点对象 -> 新节点对象
```

后面的 DFS 就围绕这张对应表完成复制。

## 解法分析

复制一张图要完成两件事：给每个旧节点建一个新节点，再让新节点之间按原图的关系互相连接。

### 方法一：两次遍历

第一遍走遍原图，给每个旧节点创建一个副本，存入字典 `visited[旧节点] = 新节点`。第二遍再走原图，把每个旧邻居对应的新节点加入副本的 `neighbors`。

它很好理解，但建点和连边分成两遍。时间复杂度 `O(V + E)`，空间复杂度 `O(V)`。代码见 `solution_1_two_pass.py`。

### 方法二：DFS，一次遍历完成（面试主推）

既然已经从旧节点走到了它的邻居，可以在递归返回时直接得到邻居的副本，顺手连接起来。代码的顺序就是解法：

```python
def dfs(old):
    if old in visited:
        return visited[old]

    new = Node(old.val)
    visited[old] = new
    for nei in old.neighbors:
        new.neighbors.append(dfs(nei))
    return new
```

`dfs(old)` 的含义：**返回旧节点 `old` 对应的新节点**。如果之前复制过，就返回同一个副本；没复制过，就新建、登记，然后给它接上克隆后的邻居。

为什么 `visited[old] = new` 要放在递归邻居之前？看只有两个互为邻居的节点：

```text
旧图：1 <-> 2

dfs(1)：创建 1’，先登记 1 -> 1’
    dfs(2)：创建 2’，先登记 2 -> 2’
        dfs(1)：已经登记，直接返回 1’
    把 1’ 放进 2’.neighbors；dfs(2) 返回 2’
把 2’ 放进 1’.neighbors；dfs(1) 返回 1’
```

如果先递归再登记，`dfs(2)` 回到 `dfs(1)` 时查不到旧节点 1，就会再次创建 1 的副本，沿环反复递归。

这里 `new.neighbors.append(dfs(nei))` 加入的是 **新邻居**。直接写 `append(nei)` 会让新图仍然指向旧图，不是深拷贝。

字典的键使用旧节点对象，因为它表示“这个对象对应哪个副本”。题目测试用例的 `val` 是唯一的，但直接用对象作键更贴合复制关系，也不依赖编号。

DFS 每个旧节点只创建一次，每条邻接关系只检查一次。时间复杂度 `O(V + E)`，额外空间 `O(V)`（字典和最坏情况下的递归栈）。代码见 `solution_2_dfs.py`。

### 方法三：BFS + 字典

把递归栈换成队列：先创建起点副本并登记；每次取出一个旧节点，遍历它的邻居。邻居没复制过就创建并入队，再把邻居副本加到当前副本的 `neighbors`。

它和方法二做的是同一件事，适合担心递归深度的场景。时间复杂度 `O(V + E)`，空间复杂度 `O(V)`。代码见 `solution_3_bfs.py`。

## 面试怎么讲

推荐方法二。可以直接说：“用字典记录旧节点到新节点的对应关系。DFS 遇到已复制节点就返回已有副本；否则先创建并登记，再递归克隆邻居，把返回的新节点接到当前副本上。先登记能防止环导致无限递归。”
