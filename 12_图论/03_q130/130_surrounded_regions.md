# LeetCode 130. 被围绕的区域 (Surrounded Regions)

## 题目描述
给你一个 `m x n` 的矩阵 `board`，由字符 `'X'` 和 `'O'` 组成。

你需要把所有被 `'X'` **完全包围**的 `'O'` 改成 `'X'`。

注意：
- 如果某个 `'O'` 在边界上，或者它和边界上的 `'O'` 连通，
- 那么它就**不能**被改成 `'X'`。

题目要求你**原地修改**矩阵。

---

## 先建立题感
这题最容易想错的地方是：

很多人一上来会想：

> 遇到一个 `'O'`，判断它是不是被包围。

这个思路很容易把自己绕进去，因为你要为每一块 `'O'` 单独判断它能不能走到边界，处理起来很麻烦。

这题更好的思路是**反着想**：

> 不去找“谁该被改掉”，而是先找“谁一定不能被改掉”。

谁一定不能被改掉？
- 边界上的 `'O'`
- 和边界 `'O'` 连通的 `'O'`

所以这题的本质是：

> **先从边界出发，把所有安全的 `'O'` 标记出来；剩下没被标记的 `'O'`，才是真正被包围的。**

这就是这题最核心的思维转变，也是面试里的重点。

---

## 循序渐进的解法分析

### 方法一：对每个 `'O'` 单独判断能否逃到边界（直观但很笨）

#### 思路
1. 遍历每个格子。
2. 如果当前格子是 `'O'`，就尝试从它出发搜索：
   - 看看它所在连通块能不能走到边界。
3. 如果不能走到边界，说明这一整块 `'O'` 都被包围，改成 `'X'`。
4. 如果能走到边界，就保留。

#### 为什么这个方法笨
因为你会重复做很多判断。

比如同一块很大的 `'O'` 连通区域：
- 你从里面一个点判断一次
- 从另一个点又判断一次
- 本质上是在重复搜索同一个连通块

即使你想办法优化，也会让实现变得很绕。

所以它的问题主要是：
- 思路顺着题面，但不够巧
- 重复搜索多
- 面试里不如“边界反推”有水平

#### 复杂度
- 最坏时间复杂度：`O((mn)^2)` 级别
- 空间复杂度：和搜索有关，最坏可到 `O(mn)`

### 方法二：边界 DFS + visited（最适合面试）

这是这题最推荐的标准面试解法。

#### 核心思路
不是去找“哪些 `'O'` 应该变成 `'X'`”，而是先找：

- **哪些 `'O'` 一定是安全的**

安全的 `'O'` 有两类：
1. 边界上的 `'O'`
2. 与边界 `'O'` 连通的 `'O'`

所以做法是：

1. 扫描四条边界
2. 只要在边界上发现 `'O'`，就从它出发做 DFS
3. 把所有和边界连通的 `'O'` 都标记成“安全”
4. 最后再遍历整个矩阵：
   - 如果是 `'O'` 且不安全，改成 `'X'`
   - 如果是 `'O'` 且安全，保留

#### 为什么这个思路这么关键
因为题目里真正难的不是“如何搜”，而是：

> **你到底该从哪里开始搜。**

如果你从每个 `'O'` 自己去判断，会很乱；
但如果你从边界出发，只做一件事：

> 把所有“不可能被包围”的 `'O'` 全部找出来。

那剩下的自然就是答案。

这就是这题的本质。

#### 为什么它最适合面试
因为这题面试官最想听到的，通常不是“我会写 DFS”，而是：

> **我知道这题要反过来想，从边界出发。**

你只要把这个思想说出来，基本就已经抓住重点了。

面试时你可以按这个顺序讲：

1. 被包围的 `'O'` 一定**不能**和边界连通
2. 所以先从边界 `'O'` 出发，把所有安全区域标记出来
3. 最后剩下的 `'O'` 才是被包围的，统一翻成 `'X'`

这个表述会非常顺。

#### 一个小例子
```text
X X X X
X O O X
X X O X
X O X X
```

这里：
- `(3,1)` 是边界上的 `'O'`，它一定安全
- 与它连通的 `'O'` 也安全

而中间那一块：
- `(1,1)`、`(1,2)`、`(2,2)`

它们都不能通到边界，所以最终会被改成 `'X'`。

结果会变成：

```text
X X X X
X X X X
X X X X
X O X X
```

#### 这题你真正要掌握的点
1. **为什么从边界出发？**  
   因为边界 `'O'` 和与其连通的 `'O'` 一定不能被填掉。

2. **DFS 在这里的作用是什么？**  
   不是统计数量，也不是算面积，而是标记“安全区域”。

3. **最后为什么还能再扫一遍？**  
   因为没有被标记为安全的 `'O'`，就是被包围的 `'O'`。

4. **和第 200 / 695 题的不同点是什么？**  
   前两题是“找每个连通块然后统计答案”，这题是“先找特殊连通块（边界连通块），再处理剩余部分”。

#### 复杂度
- 时间复杂度：`O(mn)`  
  每个格子最多被访问有限次。
- 空间复杂度：`O(mn)`  
  主要来自 `visited` 矩阵；递归栈最坏也可能到 `O(mn)`。

### 方法三：边界 DFS + 原地标记（最优解法）

既然题目要求原地修改，我们可以进一步把 `visited` 也省掉。

常见写法是：
- 先从边界 `'O'` 出发
- 把所有安全的 `'O'` 临时改成一个特殊字符，比如 `'#'`
- 然后再统一遍历整个矩阵：
  - `'O'` -> `'X'`（说明它被包围）
  - `'#'` -> `'O'`（说明它安全，恢复回来）

#### 思路
1. 扫描四条边界
2. 遇到 `'O'` 就 DFS，把所有连通的安全格子改成 `'#'`
3. 再遍历整个矩阵：
   - `'O'` 改成 `'X'`
   - `'#'` 改回 `'O'`

#### 为什么它是最优解法
因为它把“安全标记”直接写在原数组里：
- 不需要额外 `visited`
- 思路仍然清晰
- 也符合题目“原地修改”的要求

#### 复杂度
- 时间复杂度：`O(mn)`
- 空间复杂度：
  - 若不算递归栈，额外空间 `O(1)`
  - 若算递归栈，最坏 `O(mn)`

#### 面试时怎么说更稳妥
你可以这样说：

> 标准写法可以用 visited 记录哪些 `'O'` 是从边界扩散出来的安全区域。
> 如果想进一步优化空间，就直接把这些安全 `'O'` 临时改成特殊字符，比如 `'#'`，最后再恢复。

再补一句：

> 这样既避免了额外 visited 数组，也满足题目原地修改的要求。

#### 代码文件
- `solution_dfs_inplace.py`

## 三种方法怎么选

### 如果你现在在建立题感
先把下面这句话彻底想透：

> 这题不是找“谁该删”，而是先找“谁不能删”。

只要这句话通了，这题就通了。

### 如果你在准备面试
**首选讲法：方法二（边界 DFS + visited）**

原因：
1. 反向思维容易展示思考深度
2. 不修改输入，逻辑清楚
3. “边界出发标记安全区域”特别适合口述
4. 很容易和第 200 / 695 题做区分

### 如果面试官继续问优化
再补充：
- **方法三（原地标记 `#`）**

这样就会显得你不仅懂标准解，也知道如何把辅助空间压掉。

## 面试回答模板
你可以直接这样说：

```text
这道题不能从每个 O 去判断它会不会被包围，那样会很绕。
更好的思路是反过来想：凡是边界上的 O，以及和边界 O 连通的 O，一定不能被替换。
所以我会先从四条边界出发做 DFS，把所有安全的 O 标记出来。
最后再遍历整个矩阵，所有没被标记的 O 都说明被包围了，把它们改成 X 即可。

如果不想修改输入，可以用 visited；
如果想优化空间，可以把安全的 O 原地改成 #，最后再恢复成 O。
```

## 总结
- **最直观但偏笨的写法**：对每个 `'O'` 单独判断能否逃到边界
- **最适合面试的写法**：边界 DFS + visited
- **最优解法**：边界 DFS + 原地 `#` 标记
