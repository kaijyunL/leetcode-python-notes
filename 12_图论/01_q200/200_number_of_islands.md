# LeetCode 200. 岛屿数量 (Number of Islands)

## 题目描述
给你一个由 `'1'`（陆地）和 `'0'`（水）组成的二维网格 `grid`，请你统计网格中岛屿的数量。

岛屿总是被水包围，并且每座岛屿只能由**水平或垂直方向**上相邻的陆地连接形成。

---

## 先建立题感
这道题本质上不是“数一数有多少个 `1`”，而是：

> **数一数这个二维网格里有多少个连通块。**

只要两个陆地格子能够通过“上、下、左、右”连起来，它们就属于同一座岛。

所以这题的核心不是单个格子，而是：

- 找到一块陆地；
- 把和它连在一起的整块陆地全部找出来；
- 这整块只计数 1 次。

---

## 循序渐进的解法分析

我们按“先好理解，再做优化”的顺序来。

### 方法一：显式建图再统计连通块（思路最直观，但实现偏笨）

这是一个很容易想到的图论写法。

#### 思路
1. 把每个陆地格子看成一个图上的节点。
2. 如果两个陆地格子上下或左右相邻，就在它们之间连一条边。
3. 整张图建完后，问题就变成：
   - **这张无向图里有多少个连通块？**
4. 再用 DFS / BFS 去统计连通块数量。

#### 为什么说它“暴力/偏笨”
因为这道题里的网格本身就已经隐含了图结构。

也就是说：
- 你完全可以在网格上直接搜；
- 没必要先把整张图的邻接关系都显式建出来。

所以这种做法的主要问题不是时间复杂度太差，而是：
- 多做了一层“建图”工作；
- 代码更绕；
- 面试里不如直接在网格上 DFS 来得自然。

#### 复杂度
- 时间复杂度：`O(mn)`
- 空间复杂度：`O(mn)`

#### 代码文件
- `solution_brute_force.py`

### 方法二：DFS + visited 矩阵（最适合面试）

这是我最推荐你在面试里**优先讲**的方法。

它的好处是：
- 思路非常自然；
- 不依赖修改原始输入；
- 代码结构清楚，边界好讲；
- 面试官通常一听就知道你理解了“连通块统计”。

#### 核心思路
我们从左到右、从上到下遍历整个网格。

当遍历到某个格子 `(r, c)` 时：
- 如果它是水 `'0'`，直接跳过；
- 如果它是陆地 `'1'`，但已经访问过，说明它属于前面某座已经统计过的岛，也跳过；
- 如果它是**未访问过的陆地 `'1'`**，说明我们发现了一座新的岛：
  1. `count += 1`
  2. 从这个格子出发做一次 DFS
  3. 把与它连通的所有陆地全部标记为已访问

这样做的关键在于：

> 每次发现“一个新的未访问陆地”，就意味着发现了一整座新岛屿。

因为这次 DFS 会把整座岛全部吃掉，后面再遇到这座岛上的其它格子时，就不会重复计数了。

#### 为什么这个方法特别适合面试
你可以按下面这个顺序讲，逻辑会非常顺：

1. **先把题目翻译成图论语言**  
   网格中的每个陆地格子是一个节点，上下左右相邻表示连边，本题就是求连通块数量。

2. **再说统计策略**  
   遍历整个网格，遇到一个未访问的陆地，就说明发现了一个新的连通块，答案加一。

3. **最后说如何避免重复统计**  
   用 DFS 从当前点出发，把整块陆地全部标记成 visited。

这三句话基本就把整题讲明白了。

#### 一个小例子
```text
1 1 0 0
1 0 0 1
0 0 1 1
```

遍历过程：

- 扫到 `(0, 0)`，是未访问陆地：
  - `count = 1`
  - DFS 会把 `(0,0)`、`(0,1)`、`(1,0)` 全部标记掉
- 继续扫描，前面那块岛的格子都已经访问过了，不再重复计数
- 扫到 `(1, 3)`，又是未访问陆地：
  - `count = 2`
  - DFS 会把 `(1,3)`、`(2,3)`、`(2,2)` 标记掉

最终答案就是 `2`。

#### 这题你真正要掌握的点
1. **什么时候答案加一？**  
   不是遇到一个 `1` 就加一，而是遇到一个“未访问的 `1`”才加一。

2. **DFS 的作用是什么？**  
   不是为了求路径，而是为了把当前整座岛一次性全部标记掉。

3. **为什么不会漏？**  
   因为外层遍历会扫到每个格子。

4. **为什么不会重？**  
   因为一旦某座岛被 DFS 处理过，整座岛都被标记了。

#### 复杂度
- 时间复杂度：`O(mn)`  
  每个格子最多进入 DFS 一次。
- 空间复杂度：`O(mn)`  
  主要是 `visited` 矩阵。

#### 代码文件
- `solution_dfs_visited.py`

### 方法三：原地 DFS 感染法（最优解法）

在方法二里，我们用了一个 `visited` 矩阵来记录哪些格子已经访问过。

其实还可以再优化一步：

- 既然访问过的陆地以后就不需要再保留为 `'1'`；
- 那么我们可以直接把它改成 `'0'`；
- 这样就不需要额外的 `visited` 矩阵了。

这就是常见的**原地标记 / 感染法 / 淹没法**。

#### 思路
1. 遍历整个网格。
2. 遇到 `'1'`，说明发现新岛屿，答案加一。
3. 立刻从这个位置做 DFS：
   - 把当前格子改成 `'0'`
   - 再递归处理它上下左右相邻的陆地
4. 这样整座岛都会被“淹没”为 `'0'`

后面再次遍历到这些格子时，它们已经变成水了，自然不会重复计数。

#### 为什么它是最优解法
因为它保留了 DFS 解法的核心优点：
- 仍然只遍历每个格子一次；
- 仍然是清晰的连通块统计；
- 但省掉了 `visited` 矩阵这部分额外空间。

#### 复杂度
- 时间复杂度：`O(mn)`
- 空间复杂度：
  - 若不算递归栈，额外空间是 `O(1)`
  - 若算递归栈，最坏为 `O(mn)`

#### 面试时怎么说更稳妥
如果面试官问你“还能不能优化空间”，你可以这样答：

> 可以。把 visited 数组去掉，直接把访问过的 `'1'` 改成 `'0'`。这样就能原地完成标记，省掉一份 `O(mn)` 的 visited 空间。

再补一句：

> 但这种写法会修改输入，如果题目或业务场景不允许改原数组，就继续用 visited 版本。

这句话很加分，因为你不仅会优化，还知道优化的代价。

#### 代码文件
- `solution_dfs_inplace.py`

## 三种方法怎么选

### 如果你现在在刷题入门
先理解：
- 什么是连通块；
- 为什么“发现一个未访问陆地”就等于“发现一座新岛”；
- 为什么一次 DFS 能把整座岛处理完。

### 如果你在准备面试
**首选讲法：方法二（DFS + visited）**

原因：
1. 逻辑最完整；
2. 不修改输入，表达更稳；
3. 面试中最好讲清楚；
4. 更容易把“统计连通块”这个本质讲出来。

### 如果面试官继续追问优化
再给出：
- **方法三（原地 DFS）**

这是你在标准解基础上的自然优化，层次会很好。
