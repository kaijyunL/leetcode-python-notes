# LeetCode 207. 课程表 (Course Schedule)

## 题目描述
你这个学期必须选修 `numCourses` 门课程，记为 `0` 到 `numCourses - 1`。

在选修某些课程之前需要一些先修课程。先修课程按数组 `prerequisites` 给出，其中 `prerequisites[i] = [ai, bi]`，表示如果要学习课程 `ai` 则**必须**先学习课程 `bi`。

请你判断是否可能完成所有课程的学习。

### 示例
```
输入: numCourses = 2, prerequisites = [[1, 0]]
输出: true
解释: 学课程 1 之前要学课程 0，没有冲突。

输入: numCourses = 2, prerequisites = [[1, 0], [0, 1]]
输出: false
解释: 1 需要先修 0，0 又需要先修 1，互相依赖，永远学不完。
```

---

## 先建立题感

这题表面是"能不能选完课"，但翻译成图论一句话就是：

> **把课程看作节点，"先修关系"看作有向边，判断这张有向图是否有环。**

`[a, b]` 翻译成边 → **`b → a`**（学完 b 才能学 a，方向是从先修课指向后修课）。

- 无环 → 拓扑排序成立 → 能选完 → `true`
- 有环 → 卡死 → 选不完 → `false`

所以这题的核心只有一句话：

> **检测有向图里有没有环。**

剩下的就是选哪种检测方法的事。

---

## 解法循序渐进

### 方法一：朴素 Kahn 算法（反复扫描入度为 0 的节点）

#### 思路
现实生活里你怎么排课？

> "没人卡我的课，我先上；上完之后，那些需要我做先修的课，先修要求减少一门。"

一直这样滚下去：
1. 算出每门课的**入度**（多少门课要先修过才能学它）
2. 每一轮扫描所有课，找出**入度为 0** 且还没上过的课，"上"掉它
3. 把它指向的每门后修课的入度都减 1
4. 反复直到一轮里找不到入度为 0 的课
5. 如果所有课都上过 → 无环 → `true`；否则有环 → `false`

#### 为什么这个方法偏"笨"
每一轮都要重新扫一遍所有课程找入度为 0 的，最坏要扫 `V` 轮，每轮 `O(V)`，时间是 `O(V² + E)`。其实没必要每轮重新扫——下一节优化就解决了。

#### 复杂度
- 时间：`O(V² + E)`
- 空间：`O(V + E)`

#### 代码文件

### 方法二：DFS + 三色标记法

#### 思路
DFS 检测有向图环的标准写法，给每个节点维护一个**状态**：

| 颜色 | 状态码 | 含义 |
|---|---|---|
| 白 | `0` | 还没访问过 |
| 灰 | `1` | 正在 DFS 这条路径上（"访问中"） |
| 黑 | `2` | 已经完成、子树确认无环 |

规则：
1. 从每个白色节点开始 DFS
2. 进入一个节点时，把它染成灰
3. 遍历邻居：
   - 邻居是灰 → **沿当前路径走回了自己 → 有环 → 直接返回 false**
   - 邻居是白 → 递归下去，递归返回 false 则向上传播 false
   - 邻居是黑 → 已确认无环子树，跳过
4. 出来时把当前节点染黑

#### 关键直觉
**灰色 = "正走在当前这条 DFS 路径上"**。沿着边走又回到一个灰色节点，说明这条路径绕了一圈回到自己——**这就是环的定义**。

黑色相当于一个"缓存"：这个节点出发能到的所有路径都已经验证过没环了，下次再访问它直接跳过，不重复 DFS。

#### 复杂度
- 时间：`O(V + E)`
- 空间：`O(V + E)`（图 + 递归栈 + 颜色数组）

#### 代码文件
- `solution_2_dfs_3color.py`

### 方法三：BFS + Kahn 算法（队列优化，**最适合面试**）

这是本题最推荐的标准面试解法，下面会讲得详细一些。

#### 核心思路
方法一的核心想法是对的，但每轮重新扫描太浪费。用**队列**把"入度刚刚降到 0"的节点直接接住，就不用反复扫描了：

1. **预处理**：建邻接表 `graph`，算每个节点的**入度** `in_degree`
2. **初始化队列**：把所有入度为 0 的节点一次性入队
3. **循环**：队列非空时
   - 出队一个节点 `u`，计数 `+1`
   - 对 `u` 的每个后继 `v`：`in_degree[v] -= 1`
   - 如果 `v` 的入度刚刚降到 0 → 入队
4. **判断**：循环结束后，如果**出队过的节点数 == numCourses**，说明所有课都能按某种顺序学完 → `true`；否则有节点入度永远降不到 0，被环锁住了 → `false`

#### 为什么 Kahn 在这题特别自然
**入度 = "还有多少先修课要学"**。

- 入度 0 的课 = "现在就能上的课"
- 学一门课 = 它指向的所有后修课"先修要求减 1"
- 反复出队入队的过程，就是"现实里一学期一学期把课往后排"

整个过程几乎可以一句话讲完：

> 把所有没人卡的课塞进队列，一边学一边解锁后续课程；最后能学完就说明无环。

#### 为什么它最适合面试
原因有几个：

1. **不依赖递归**，没有递归栈爆掉的风险，工程上更稳
2. **直接给出选课顺序**——把每次出队的节点记下来就是拓扑序，**直接能改成 [LeetCode 210](https://leetcode.com/problems/course-schedule-ii/) 的解法**，加一行代码就行
3. **现实直觉好**，面试官一听就懂："没要求的先做，做完解锁后续"，比染色更贴近生活
4. **代码量适中**，逻辑清晰，没有"先登记还是先递归"这种容易写错的坑
5. **方便回答追问**：
   - 为什么这样做能检测环？→ 环里的节点入度永远 ≥ 1，永远进不了队
   - 怎么扩展到输出选课顺序？→ 出队顺序就是拓扑序
   - 为什么不用 DFS？→ 工程上避免递归栈太深，且 BFS 自带顺序

讲清楚这几个点，这题就稳了。

#### 容易写错的地方（面试自检清单）

**1. 边的方向别搞反**

`prerequisites[i] = [a, b]` 意思是"学 a 前要学 b"，所以边是 **`b → a`**（先修 → 后修）。

```python
for a, b in prerequisites:
    graph[b].append(a)   # ✅ 学完 b 解锁 a
    in_degree[a] += 1    # ✅ a 多了一个先修要求
```

写反了整个图都反了，结果可能正好相反，**这是这题最常见的 bug**。

**2. 必须先把所有入度为 0 的入队，不能只入队 0 号节点**

```python
# ❌ 错误：只从 0 开始
queue = deque([0])

# ✅ 正确：所有入度为 0 的都先入队
queue = deque(i for i in range(numCourses) if in_degree[i] == 0)
```

图可能是不连通的，可能有多个独立的"起点"。

**3. 入度降为 0 才入队，不是"减 1 就入队"**

```python
for v in graph[u]:
    in_degree[v] -= 1
    if in_degree[v] == 0:   # ✅ 只在归零时入队
        queue.append(v)
```

把 `==` 写成减 1 就入队，节点会被重复处理。

**4. 计数用变量，别用 `len(queue)`**

要单独维护一个 `taken = 0` 计数器，每出队一个 +1。最后比较 `taken == numCourses`。
直接看队列长度只能看到当前队列里的，看不到总共出队过多少。

#### 一个小例子
课程关系（4 门课）：

```
prerequisites = [[1, 0], [2, 0], [3, 1], [3, 2]]
```

图（边是 先修 → 后修）：

```
    0 ──► 1
    │     │
    ▼     ▼
    2 ──► 3
```

入度：`[0, 1, 1, 2]`

BFS 过程：

| 步骤 | 队列 | 出队 | 入度变化 | 计数 |
|---|---|---|---|---|
| 初始 | `[0]` | - | `[0, 1, 1, 2]` | 0 |
| 出队 0 | `[1, 2]` | 0 | `[0, 0, 0, 2]` | 1 |
| 出队 1 | `[2]` | 1 | `[0, 0, 0, 1]` | 2 |
| 出队 2 | `[3]` | 2 | `[0, 0, 0, 0]` | 3 |
| 出队 3 | `[]` | 3 | `[0, 0, 0, 0]` | 4 |

`taken = 4 == numCourses` → **true**

如果改成有环的 `[[0, 1], [1, 0]]`：
- 入度：`[1, 1]`
- 初始队列空（没有入度为 0 的）
- 循环根本进不去
- `taken = 0 ≠ 2` → **false** ✅

#### 复杂度
- 时间：`O(V + E)`
  每个节点最多入队出队一次，每条边最多遍历一次。
- 空间：`O(V + E)`
  邻接表 + 入度数组 + 队列。

#### 代码文件
- `solution_3_bfs_kahn.py`

## 三种方法怎么选

### 如果你现在在建立题感
先把这一句话彻底想透：

> 题目翻译成图论就是"判断有向图是否有环"，拓扑排序能成立就无环。

### 如果你在准备面试
**首选讲法：方法三（BFS Kahn 算法）**

原因：
1. 代码不长，逻辑直接
2. 现实直觉好讲（"没要求的先做"）
3. 自然过渡到 210 题（输出选课顺序），面试官常会追问这个
4. 工程上不依赖递归栈，能直接吹一波鲁棒性

### 如果面试官继续追问
- "DFS 怎么做？" → **方法二（三色标记）** 是另一个标准答案
- "怎么输出选课顺序？" → Kahn 出队顺序就是拓扑序
- "如果图非常大，哪种好？" → BFS，递归栈不受深度限制

这样就显得你不仅会写标准解，还能对比不同方法的优劣。

## 面试回答模板
你可以直接这样说：

```text
这题本质是判断有向图有没有环：把课程当节点，先修关系当有向边。
如果图无环，拓扑排序成立，就能选完所有课。

我会用 Kahn 算法（BFS 拓扑排序）：
1. 先建邻接表和入度数组
2. 把所有入度为 0 的课入队（它们没有任何先修要求，可以马上学）
3. 每出队一门课，就把它指向的所有后修课的入度减 1
4. 如果某门后修课的入度刚好降到 0，就把它入队
5. 最后看总共出队过的课数是不是等于 numCourses

如果等于，说明所有课都能找到一个合法顺序学完，返回 true；
否则一定有一组课互相依赖卡住了，返回 false。

时间和空间复杂度都是 O(V + E)。

这种写法的好处是不用递归，工程上更稳，
而且把出队顺序记下来就是拓扑序，
能直接扩展到 210 题输出选课顺序。
```

## 总结
- **最朴素的写法**：反复扫描入度为 0 的节点（朴素 Kahn）
- **最适合面试的写法**：BFS + 队列优化的 Kahn 算法（**首选**）
- **同样最优的另一种思路**：DFS + 三色标记法（白灰黑）

三种方法的核心都是检测有向图的环。面试时优先讲方法三，被追问就补方法二。
