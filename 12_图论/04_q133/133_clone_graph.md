# LeetCode 133. 克隆图 (Clone Graph)

## 题目描述
给你无向**连通**图中一个节点的引用，请你返回该图的**深拷贝**（克隆）。

图中每个节点都包含它的值 `val` 和其相邻节点列表 `neighbors`：

```python
class Node:
    def __init__(self, val=0, neighbors=None):
        self.val = val
        self.neighbors = neighbors if neighbors is not None else []
```

测试用例的写法是邻接表，第 `i` 个列表代表节点 `i` 的邻居（节点值与下标一致，从 1 开始）。

例如：
```
adjList = [[2,4],[1,3],[2,4],[1,3]]
```
表示这是一张 4 个节点的环：1-2-3-4-1。

---

## 先建立题感

这题表面是“图的复制”，但真正卡人的不是 DFS / BFS，而是**两个细节**：

1. **图里有环**：如果你顺着邻居一路递归下去，碰到已经访问过的节点会无限循环。
2. **深拷贝意味着每个节点只能被复制一次**：必须区分“老节点”和“新节点”，并保证它们一一对应。

所以这题真正的核心是一句话：

> **用一个哈希表把“老节点 → 新节点”记住，遇到过的就直接返回，不要再复制一次。**

只要这句话想通了，剩下的就是选 DFS 还是 BFS 的事。

另一个容易踩的坑：

> 新节点的 `neighbors` 必须装的是**新节点**，而不是老节点。

很多人第一次写会直接把老的 `neighbor` 接上去，导致“拷贝”出来的图其实仍然指向原图。

---

## 循序渐进的解法分析

### 方法一：两次遍历（先建点，再连边）

#### 思路
最朴素的写法是把建点和连边分成两步：

1. **第一遍**：从起点出发遍历一次原图（BFS 或 DFS），把每个老节点都创建一个对应的新节点，存进哈希表 `old → new`。
2. **第二遍**：再次遍历每个老节点，把它的邻居一个一个拿出来，从哈希表里查到对应的新节点，挂到新节点的 `neighbors` 里。

这种写法的好处是：建点和连边逻辑分得很清楚，思路最直观，不容易混。

#### 为什么这个方法偏“笨”
因为完全没必要分两次：
- 第一次遍历其实已经走过了每个节点和每条边
- 第二次遍历是在重复同样的结构

它能跑通，但相比一边遍历一边连边的写法，是多走了一遍。

#### 复杂度
- 时间复杂度：`O(V + E)`
- 空间复杂度：`O(V)`（哈希表 + 队列/递归栈）

### 方法二：DFS + 哈希表（最适合面试）

这是这题最推荐的标准面试解法，下面会讲得详细一些。

#### 核心思路
用一个哈希表 `visited: 老节点 → 新节点`，配合递归：

1. 进入函数时，先看这个老节点有没有被复制过：
   - 如果有，直接返回它对应的新节点（这一步是**避免环导致死循环**的关键）。
2. 如果没有，就为它建一个新节点，**先存进哈希表**。
3. 然后递归处理它的每个邻居，把递归返回的“邻居的新副本”挂到当前新节点的 `neighbors` 上。

关键顺序：**先把新节点登记进哈希表，再去递归邻居。** 顺序反了会无限递归。

#### 为什么 DFS 在这里特别自然
因为这题本质上就是“顺着指针抄一份”，DFS 的递归调用栈正好就是**沿着图的边走一步**：

- 走到一个新节点 → 复制它
- 复制完 → 顺着它的邻居继续走
- 走过的节点用哈希表挡住，不重复走

整个过程几乎可以一句话讲完：

> 遇到没复制的就复制并登记，然后递归克隆所有邻居；遇到复制过的就直接拿出来用。

#### 为什么它最适合面试
原因有几个：

1. **代码量最短**，递归 5~10 行就能写完，写得快。
2. **能完美表达“克隆 + 防环”的核心思想**，面试官最想听到的就是这两点。
3. **天然处理环和重复邻居**，因为哈希表查找是 `O(1)`，不会重复递归。
4. **方便回答后续追问**，比如：
   - 为什么需要哈希表？→ 防环 + 一一对应
   - 为什么要先登记再递归？→ 不然碰到环会无限调用
   - 怎么改成 BFS？→ 改成队列，先建好点再连边

讲清楚这几个点，这题就稳了。

#### 容易写错的地方（面试自检清单）

1. **先登记，再递归**

   错的写法：
   ```python
   new_node = Node(node.val)
   for nei in node.neighbors:
       new_node.neighbors.append(dfs(nei))
   visited[node] = new_node      # ❌ 太晚了
   return new_node
   ```
   如果图里有环（例如 1-2-1），递归到邻居 2 时，2 又会去递归回 1，
   但此时哈希表里还没有 1，于是又会再建一个 1 的副本，无限循环。

   正确做法：
   ```python
   new_node = Node(node.val)
   visited[node] = new_node      # ✅ 先登记
   for nei in node.neighbors:
       new_node.neighbors.append(dfs(nei))
   return new_node
   ```

2. **哈希表的 key 必须是“老节点”本身，不是 `val`**

   测试数据里每个节点的 `val` 都不同，所以用 `val` 当 key 也能跑通；
   但题目并没有规定 `val` 一定唯一，更通用的写法是直接用 **节点对象本身**作为 key（Python 默认按对象身份哈希）。

3. **`neighbors` 一定要挂新节点**

   下面这样就是错的：
   ```python
   new_node.neighbors = node.neighbors   # ❌ 这是老节点的引用
   ```
   一定要走哈希表 / 递归，把每个邻居都换成它对应的新副本。

4. **边界情况：输入是 `None`**

   原题中如果输入空节点，直接返回 `None` 即可。
   面试时记得在开头补一句判断，会显得更稳。

#### 一个小例子
原图（一个 4 节点环）：

```
1 --- 2
|     |
4 --- 3
```

DFS 从 1 出发：

1. 复制 1，登记 `{1: 1'}`
2. 处理 1 的邻居 2：复制 2，登记 `{1: 1', 2: 2'}`
   - 处理 2 的邻居 1：哈希表已有，直接返回 `1'`
   - 处理 2 的邻居 3：复制 3，登记 `{..., 3: 3'}`
     - 处理 3 的邻居 2：返回 `2'`
     - 处理 3 的邻居 4：复制 4，登记 `{..., 4: 4'}`
       - 处理 4 的邻居 3：返回 `3'`
       - 处理 4 的邻居 1：返回 `1'`
3. 处理 1 的邻居 4：返回 `4'`

整张图被完整复制，环结构也保留住了。

#### 复杂度
- 时间复杂度：`O(V + E)`
  每个节点访问一次，每条边访问两次（无向图）。
- 空间复杂度：`O(V)`
  哈希表存所有节点；递归栈最坏也是 `O(V)`。

### 方法三：BFS + 哈希表（迭代写法）

#### 思路
和方法二完全等价，只是把递归换成了队列：

1. 复制起点，登记到哈希表 `{old_start: new_start}`，并把起点入队。
2. 每次从队列取出一个**老节点**：
   - 遍历它的每个邻居
   - 如果这个邻居没复制过：复制它、登记进哈希表、入队
   - 把这个邻居对应的**新节点**挂到当前节点对应的新节点的 `neighbors` 上。

也就是说：BFS 一边走一边连边，不需要走两遍。

#### 为什么也算最优解
- 时间复杂度和方法二完全一样
- 没有递归栈的风险，更适合**节点数特别多、层很深**的图
- 思路非常稳，没有“先登记还是先递归”的坑

#### 复杂度
- 时间复杂度：`O(V + E)`
- 空间复杂度：`O(V)`

#### 代码文件
- `solution_bfs.py`

## 三种方法怎么选

### 如果你现在在建立题感
先把这一句话彻底想透：

> 这题要做两件事：**一是复制，二是防环**。
> 哈希表负责防环，DFS / BFS 负责走遍每个节点和每条边。

### 如果你在准备面试
**首选讲法：方法二（DFS + 哈希表）**

原因：
1. 代码最短，逻辑最直接
2. 哈希表的作用容易讲清楚（防环 + 一一对应）
3. “先登记再递归”是这题最有信息量的细节，能体现你想过环的问题
4. 可以自然地把方法三作为“追问优化”补出来

### 如果面试官继续问优化或工程化
再补充：
- **方法三（BFS + 哈希表）**：避免递归栈过深，工程上更稳

这样就显得你不仅会写标准解，还知道在什么场景该换写法。

## 面试回答模板
你可以直接这样说：

```text
这道题的关键点其实只有两个：一是要深拷贝，意味着每个老节点必须有一个唯一的新节点对应；
二是图里可能有环，不能简单地顺着邻居一路递归。

所以我会用一个哈希表存“老节点 → 新节点”的映射。
每次进到一个老节点：
  - 如果它已经被复制过，直接从哈希表里拿对应的新节点返回；
  - 如果还没有，就先复制它、登记到哈希表，再递归处理它的所有邻居，把递归返回的新邻居挂到当前新节点上。

这里有一个细节很重要：必须先登记到哈希表，再去递归邻居。
否则碰到环时，递归会再回到当前节点，又会建出一个新副本，造成死循环。

时间和空间复杂度都是 O(V + E) 和 O(V)。
如果担心递归栈太深，也可以换成 BFS：起点入队 + 复制，之后每次出队取老节点，
把它的每个邻居复制或在哈希表里查到，再连到当前新节点的 neighbors 里。
```

---

## 总结
- **最朴素的写法**：两次遍历，先建点再连边
- **最适合面试的写法**：DFS + 哈希表（先登记，再递归）
- **同样最优、工程更稳的写法**：BFS + 哈希表

三种方法的时间复杂度都是 `O(V + E)`，差别在于代码风格和递归 / 迭代。
面试时优先讲方法二，被追问就补方法三。
