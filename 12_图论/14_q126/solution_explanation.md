# LeetCode 126. 单词接龙 II（Word Ladder II）解析

## 题目描述

给定两个单词 `beginWord` 和 `endWord`，以及一个单词列表 `wordList`。

每次转换只能改一个字母，并且转换后的单词必须在 `wordList` 里。

要求返回：

```text
从 beginWord 到 endWord 的所有最短转换序列
```

例如：

```text
beginWord = "hit"
endWord = "cog"
wordList = ["hot","dot","dog","lot","log","cog"]
```

返回：

```text
[
  ["hit","hot","dot","dog","cog"],
  ["hit","hot","lot","log","cog"]
]
```

---

## 先理解这题到底难在哪

这题不是只要你返回：

```text
最短长度是多少
```

也不是只要你返回：

```text
其中一条最短路径
```

而是要你返回：

```text
所有最短路径
```

这就比 LeetCode 127 要难一层。

因为 127 只要找到最短长度，普通 BFS 找到终点就可以结束。

但 126 不行。

126 的关键点是：

```text
同一个单词在最短层里，可能有多个前驱
```

你如果只记住其中一个前驱，就会漏答案。

---

## 先把题目看成图

把每个单词看成图里的一个节点。

如果两个单词：

```text
只差一个字符
```

那它们之间就连一条边。

例如：

```text
hot -> dot
hot -> lot
dot -> dog
lot -> log
dog -> cog
log -> cog
```

于是问题就变成：

```text
在无权图里，找 beginWord 到 endWord 的所有最短路径
```

无权图的最短路，第一反应就应该是：

```text
BFS
```

但在正式上 BFS 之前，我们先看一个最直观的方法。

---

## 方法一：构图后 DFS 枚举所有路径

### 思路

最直接的想法是：

1. 先把所有单词之间的连边建出来
2. 然后从 `beginWord` 出发做 DFS
3. 枚举所有不重复路径
4. 只保留长度最短的那些路径

这个思路是成立的。

因为只要图建对了，DFS 确实可以把所有从起点到终点的简单路径都找出来。

---

### 为什么可行

因为它没有漏掉任何可能路径。

最后我们只要维护一个当前最短长度：

- 如果找到更短路径，就清空旧答案，保留新路径
- 如果找到同样短的路径，就追加进去

逻辑上完全正确。

---

### 为什么会慢

问题在于：

```text
路径数量可能非常多
```

DFS 会把大量明显不是最短的路径也走一遍。

而且如果我们先显式构图，还要先做一轮：

```text
两两比较单词是否只差一个字符
```

这一步本身就不便宜。

所以这个方法更适合理解题目，不适合作为真正提交版。

---

### 复杂度

设：

- `N` 是单词数量
- `L` 是每个单词长度

那么：

- 构图时间复杂度约为 `O(N^2 * L)`
- DFS 枚举路径在最坏情况下会指数爆炸
- 空间复杂度也会比较高

所以它很容易超时。

---

## 方法二：BFS 分层 + 记录前驱 + 回溯（面试主推）

### 为什么先想到 BFS

因为这是一个：

```text
无权图最短路径问题
```

BFS 天然按“层”推进：

- 第 0 层是起点
- 第 1 层是一步能到的单词
- 第 2 层是两步能到的单词
- ...

所以 BFS 第一次到达某一层时，就保证这层对应的是最短步数。

---

### 但这题不能只记一个父节点

这是这题最关键的地方。

例如：

```text
hit -> hot -> dot -> dog -> cog
hit -> hot -> lot -> log -> cog
```

当 BFS 扩展到：

```text
dog
log
```

这一层时，它们都可以走到：

```text
cog
```

所以对 `cog` 来说，它在最短路径图里有两个前驱：

```text
dog 和 log
```

如果你只记一个，比如只记 `dog`，那最后回溯时就只能找出一条路径，另一条就丢了。

所以我们要记录的是：

```text
每个单词在最短层中的所有前驱
```

而不是单个前驱。

---

### 整体思路

分成两步。

### 第一步：BFS 分层找最短路径图

BFS 时我们不直接保存完整路径，而是保存：

```text
child -> 它有哪些前驱 parent
```

比如：

```text
parents["cog"] = {"dog", "log"}
parents["dog"] = {"dot"}
parents["log"] = {"lot"}
parents["dot"] = {"hot"}
parents["lot"] = {"hot"}
parents["hot"] = {"hit"}
```

这样 BFS 结束后，我们实际上拿到的是一张：

```text
只包含最短路径关系的前驱图
```

---

### 第二步：从 endWord 回溯出所有答案

既然我们已经知道每个节点有哪些最短前驱，那就可以从 `endWord` 反向 DFS：

- 从 `cog` 往回走到 `dog` 和 `log`
- 再继续往回走
- 一直走到 `beginWord`

这样就能把所有最短路径全部拼出来。

---

### 为什么要按层删除已访问单词

这一步特别容易写错。

很多人会在发现 `next_word` 的那一刻，立刻把它标成“以后不能再访问”。

这样在 126 里会出问题。

因为：

```text
同一层的多个单词，可能都应该指向同一个 next_word
```

还是刚才那个例子：

- `dog` 能到 `cog`
- `log` 也能到 `cog`

如果你在 `dog` 第一次发现 `cog` 时，马上彻底封掉 `cog`，那 `log -> cog` 这条最短边就记不进去了。

正确做法是：

```text
一整层处理完之后，再把这一层用过的点整体移除
```

这样同一层里的多个父节点，才能同时连向同一个子节点。

这是这题最关键的实现细节之一。

---

### 用例子走一遍

题目：

```text
beginWord = "hit"
endWord = "cog"
wordList = ["hot","dot","dog","lot","log","cog"]
```

### 第 0 层

```text
hit
```

能到：

```text
hot
```

于是：

```text
parents["hot"] = {"hit"}
```

### 第 1 层

```text
hot
```

能到：

```text
dot
lot
```

于是：

```text
parents["dot"] = {"hot"}
parents["lot"] = {"hot"}
```

### 第 2 层

```text
dot
lot
```

能到：

```text
dog
log
```

于是：

```text
parents["dog"] = {"dot"}
parents["log"] = {"lot"}
```

### 第 3 层

```text
dog
log
```

它们都能到：

```text
cog
```

于是：

```text
parents["cog"] = {"dog", "log"}
```

这时我们就知道已经到达终点所在的最短层了。

接下来回溯：

- `cog <- dog <- dot <- hot <- hit`
- `cog <- log <- lot <- hot <- hit`

倒过来就是两条答案。

### 复杂度分析

设：

- `N` 是单词数量
- `L` 是单词长度

在 BFS 里，每次尝试把一个位置替换成 26 个字母来找邻居。

所以 BFS 主体的时间复杂度可以近似看成：

```text
O(N * L * 26)
```

另外，最后还要把所有最短路径回溯并输出。

所以总时间复杂度还要再加上：

```text
答案总长度
```

空间复杂度主要来自：

- 单词集合
- BFS 层集合
- 前驱表 `parents`
- 回溯路径

可以近似理解为：

```text
O(N + 最短路径图大小)
```

## 为什么这个方法最适合面试

最适合面试的方法就是：

```text
BFS 分层找最短层，再记录所有前驱，最后回溯出全部答案
```

原因有三个。

### 1. 它正好对应题目本质

题目本质就是：

```text
无权图里的所有最短路径
```

BFS 负责“最短”，前驱表负责“所有”。

这个拆分非常自然。

### 2. 它比暴力 DFS 高效得多

暴力 DFS 会枚举大量无用路径。

而 BFS 先把“最短层”限制出来，再回溯，只在正确答案范围内工作。

### 3. 它比双向 BFS 更适合讲清楚

继续优化当然还能做双向 BFS。

但双向 BFS 在这题里实现会更绕，尤其是前驱方向、层合并和结果回溯都更难讲。

如果是面试，先把这版稳定写对、清楚讲明白，通常更合适。

---

## 面试里可以怎么讲

你可以这样解释：

```text
这题可以看成无权图里的所有最短路径问题。
我先用 BFS 按层扩展，因为 BFS 天然能保证第一次到达某一层就是最短步数。
但这题不能只记录一个父节点，因为同一个单词在最短层里可能有多个前驱。
所以我会用一个 parents 映射，记录每个单词的所有最短前驱。
等 BFS 第一次到达 endWord 所在层后，就停止继续向更深层扩展。
最后再从 endWord 反向回溯到 beginWord，把所有最短路径拼出来。
```

这套说法比较完整，也能体现你真的理解了这题。

---

## 总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：构图 + DFS 枚举 | 构图 `O(N^2 * L)`，搜索最坏指数级 | 高 | 适合理解，但容易超时 |
| 方法二：BFS + 前驱回溯 | BFS 约 `O(N * L * 26)`，外加输出答案代价 | `O(N + 最短路径图大小)` | 面试主推 |

这题最重要的一句话是：

```text
BFS 负责找“最短层”，前驱表负责保留“所有最短来源”，最后再回溯出全部最短路径。
```

如果你把这句话真正想明白，这题就通了。
