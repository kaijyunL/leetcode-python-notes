# LeetCode 210. 课程表 II (Course Schedule II)

## 题目描述
现在你总共有 `numCourses` 门课需要选，记为 `0` 到 `numCourses - 1`。给你一个数组 `prerequisites`，其中 `prerequisites[i] = [ai, bi]`，表示在选修课程 `ai` 前必须先选修课程 `bi`。

**返回你为了学完所有课程所安排的学习顺序。** 可能会有多个正确的顺序，你只要返回任意一种就可以了。如果不可能完成所有课程，返回一个空数组 `[]`。

### 示例
```
输入: numCourses = 2, prerequisites = [[1, 0]]
输出: [0, 1]

输入: numCourses = 4, prerequisites = [[1, 0], [2, 0], [3, 1], [3, 2]]
输出: [0, 1, 2, 3]  或  [0, 2, 1, 3]   （任意一个合法顺序都行）

输入: numCourses = 1, prerequisites = []
输出: [0]

输入: numCourses = 2, prerequisites = [[1, 0], [0, 1]]
输出: []                                （有环，没法完成）
```

## 先建立题感

这题就是 [LeetCode 207](../05_q207/207_course_schedule.md) 的**加强版**：

| | 207 | 210 |
|---|---|---|
| 问题 | 能不能学完？ | 学完的顺序是什么？ |
| 返回 | `bool` | `List[int]`（空表示不行） |
| 算法核心 | 判断有向图有无环 | **输出有向图的拓扑序** |

**关键认识：** 207 的算法过程其实**早就把顺序算出来了**，只是没记下来。

- Kahn 算法（BFS）：**出队顺序就是拓扑序**，只要边出队边 `append` 到结果数组
- DFS 三色标记：把"完成染黑"的顺序**反转**一下就是拓扑序

所以这题和 207 是 **"加一行代码就能从 true/false 升级到完整顺序"** 的关系。

## 解法循序渐进

### 方法一：朴素 Kahn（反复扫描入度为 0 的节点）

#### 思路
和 207 方法一完全一样，唯一区别是把"被选中的课的编号"**按顺序记进结果数组**：

1. 算每门课的入度
2. 每轮扫描所有课，找一门入度为 0 且没上过的，append 到 `order` 数组
3. 把它指向的后修课入度减 1
4. 重复
5. 最后 `len(order) == numCourses` 就返回 `order`，否则返回 `[]`

#### 复杂度
- 时间：`O(V² + E)`
- 空间：`O(V + E)`

#### 代码文件
- `solution_1_naive_kahn.py`

### 方法二：DFS 后序逆序（拓扑排序的 DFS 版）

#### 思路
DFS 拓扑排序的标准做法：**节点完成 DFS 时把它 push 到结果，最后整体反转**。

1. 用三色标记法（白/灰/黑）做 DFS
2. 检测到环 → 返回 `[]`
3. 一个节点把所有后继都 DFS 完了，再把自己 append 到 `order`
4. 最后 `order[::-1]` 就是拓扑序

#### 为什么"后序逆序"就是拓扑序
直观理解：

> 一个节点能被"完成"，说明它能到达的所有节点都已经完成了。
> 也就是说，**完成顺序在前的节点，依赖关系反而在后面**。
> 把这个顺序反过来，就变成"被依赖的在前，依赖别人的在后"——这正是拓扑序。

举例 `0 → 1 → 2`：
- DFS 从 0 出发 → 进 1 → 进 2
- 2 没有后继，先完成 → `order = [2]`
- 回到 1，1 完成 → `order = [2, 1]`
- 回到 0，0 完成 → `order = [2, 1, 0]`
- 反转 → `[0, 1, 2]` ✅

#### 复杂度
- 时间：`O(V + E)`
- 空间：`O(V + E)`

#### 代码文件
- `solution_2_dfs_postorder.py`

### 方法三：BFS + Kahn 算法（**最适合面试**）

这是本题最推荐的标准面试解法，下面会详细讲。

#### 核心思路
**和 207 方法三的唯一区别：多一个 `order` 列表，每次出队就 append 进去。**

1. 建邻接表 `graph`，算入度 `in_degree`
2. 把所有入度为 0 的节点入队
3. 循环：出队一个节点 `u`
   - **`order.append(u)`** ← 唯一新增的一行
   - 对 `u` 的每个后继 `v`：`in_degree[v] -= 1`，若降到 0 则入队
4. 结束后判断：
   - `len(order) == numCourses` → 返回 `order`
   - 否则 → 有环 → 返回 `[]`

#### 为什么出队顺序就是拓扑序
回想 Kahn 的过程：

> 一个节点能出队，必须先满足"它的所有先修课都已经出过队了"（这样入度才能减到 0）。

也就是说：

- 出队的节点 = "所有先修课已经搞定的节点" = "可以学了"
- 出队顺序 = "学习顺序" = **拓扑序**

这是 Kahn 算法的最强卖点：**算法运行过程本身就在生成拓扑序，零额外开销**。

#### 为什么它最适合面试

1. **代码和 207 几乎一样**，从 207 题"无缝升级"，面试官追问"那 210 怎么做"时你能秒答
2. **不依赖递归**，没有递归栈风险，工程上更稳
3. **现实直觉好**，"没要求的先做，做完解锁后续，按出队顺序就是选课顺序"
4. **复杂度最优** `O(V + E)`
5. **容易扩展**：如果题目改成"按字典序最小的合法顺序"——把 `deque` 换成小顶堆 `heapq` 就行；如果改成"并行选课，问最短学期数"——Kahn 一层一层 BFS 即可

#### 容易写错的地方（面试自检清单）

**1. 边的方向别搞反**（和 207 一样的坑）

`prerequisites[i] = [a, b]` 意思是"学 a 前要学 b"，所以边是 **`b → a`**。

```python
for a, b in prerequisites:
    graph[b].append(a)   # ✅ 学完 b 解锁 a
    in_degree[a] += 1
```

**2. 有环时返回 `[]`，不是返回半截的 `order`**

```python
if len(order) == numCourses:
    return order
return []                # ✅ 别忘了这一行
```

如果有环，`order` 里会装着"那些不在环上的课"，但这不是合法答案——题目要求要么全做完，要么返回空。

**3. 别把"入度"当成"出度"**

- **入度** = 有多少课指向我 = "我有多少先修要求"
- **出度** = 我指向多少课 = "我能解锁多少后续课"

Kahn 用的是**入度归零**进队列。写反了整个算法就崩了。

**4. 入度降为 0 才入队**

```python
in_degree[v] -= 1
if in_degree[v] == 0:    # ✅ 必须等于 0
    queue.append(v)
```

不是 `<= 0`，不是减一就入队。

#### 一个小例子
`numCourses = 4, prerequisites = [[1, 0], [2, 0], [3, 1], [3, 2]]`

图：
```
    0 ──► 1
    │     │
    ▼     ▼
    2 ──► 3
```

入度：`[0, 1, 1, 2]`

BFS 过程：

| 步骤 | 队列 | 出队 | 入度变化 | order |
|---|---|---|---|---|
| 初始 | `[0]` | - | `[0, 1, 1, 2]` | `[]` |
| 出队 0 | `[1, 2]` | 0 | `[0, 0, 0, 2]` | `[0]` |
| 出队 1 | `[2]` | 1 | `[0, 0, 0, 1]` | `[0, 1]` |
| 出队 2 | `[3]` | 2 | `[0, 0, 0, 0]` | `[0, 1, 2]` |
| 出队 3 | `[]` | 3 | `[0, 0, 0, 0]` | `[0, 1, 2, 3]` |

`len(order) == 4 == numCourses` → 返回 `[0, 1, 2, 3]` ✅

注意：如果队列实现不同（比如换成栈或堆），结果可能是 `[0, 2, 1, 3]`，**这两个都是合法答案**。

#### 复杂度
- 时间：`O(V + E)`
- 空间：`O(V + E)`

#### 代码文件
- `solution_3_bfs_kahn.py`

## 三种方法怎么选

### 如果你已经会 207
**直接套 207 的代码**，只改两个地方：
- 多一个 `order` 列表，出队时 append
- 返回类型从 `bool` 改成 `List[int]`，根据 `len(order) == numCourses` 决定返回 `order` 还是 `[]`

### 如果你在准备面试
**首选讲法：方法三（BFS Kahn 算法）**

原因：
1. 和 207 一脉相承，能展示"算法复用"
2. 出队顺序天然就是拓扑序，几乎零思维负担
3. 后续扩展性强（字典序最小、最短学期数、并行调度……）

### 如果面试官继续追问
- "DFS 怎么做？" → 方法二，**后序遍历的逆序**就是拓扑序
- "如果要字典序最小？" → Kahn 把 `deque` 换 `heapq`
- "如果要算最少学期数？" → Kahn 改成分层 BFS，每层 `+1` 学期

## 207 vs 210 代码对比

为了直观感受"加一行就升级"，把 207 和 210 的 Kahn 实现并排放：

**207 (只判断)**
```python
queue = deque(i for i in range(numCourses) if in_degree[i] == 0)
taken = 0
while queue:
    u = queue.popleft()
    taken += 1
    for v in graph[u]:
        in_degree[v] -= 1
        if in_degree[v] == 0:
            queue.append(v)
return taken == numCourses
```

**210 (输出顺序)**
```python
queue = deque(i for i in range(numCourses) if in_degree[i] == 0)
order = []
while queue:
    u = queue.popleft()
    order.append(u)              # ← 变化 ①：记录顺序
    for v in graph[u]:
        in_degree[v] -= 1
        if in_degree[v] == 0:
            queue.append(v)
return order if len(order) == numCourses else []   # ← 变化 ②：返回顺序或空
```

差别就两处，**这就是为什么面试官常常把 207 和 210 连着出**——会一个等于会两个。

## 面试回答模板
你可以直接这样说：

```text
这道题就是 207 的延续。207 只问"能不能完成"，210 问"完成的顺序"。
我会用 Kahn 算法（BFS 拓扑排序），它的出队顺序天然就是一个合法的拓扑序。

具体做法：
1. 建邻接表和入度数组（注意 [a, b] 表示 b → a）
2. 把所有入度为 0 的课入队（这些是没有先修要求的）
3. 每出队一门课 u：
   - 把 u 加进结果数组
   - 把 u 指向的所有后修课的入度减 1
   - 哪门后修课入度刚降到 0，就入队
4. 最后看结果数组的长度：
   - 等于 numCourses → 返回结果数组（一个合法选课顺序）
   - 否则 → 有环卡住了 → 返回空数组

为什么出队顺序就是拓扑序？因为一门课能出队，必须先满足
它所有的先修课都已经出过队了——这正好是拓扑序的定义。

时间和空间复杂度都是 O(V + E)。
如果想要字典序最小的合法顺序，把队列换成小顶堆即可。
```

## 总结
- **最朴素的写法**：朴素 Kahn，每轮扫描入度为 0 的节点
- **最适合面试的写法**：BFS Kahn 算法（**首选**，从 207 无缝升级）
- **另一个最优解**：DFS 后序逆序（三色标记 + 反转完成顺序）

207 和 210 是一对孪生题，**算法骨架完全一样**，只是 210 多记一个顺序数组。面试时优先讲方法三，被追问就补方法二。
