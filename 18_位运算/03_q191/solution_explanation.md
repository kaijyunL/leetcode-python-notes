# LeetCode 191. 位1的个数（Number of 1 Bits）循序渐进解析

## 题目描述
给你一个整数 `n`，请你返回它的二进制表示中 `1` 的个数。

这个数量也叫做 **Hamming Weight**。

例如：

- `n = 11`
  - 二进制是 `1011`
  - 一共有 `3` 个 `1`
  - 答案是 `3`

- `n = 128`
  - 二进制是 `10000000`
  - 一共有 `1` 个 `1`
  - 答案是 `1`

---

## 先理解题意
这道题本质上不是在考十进制，而是在考：

**怎么统计一个数的二进制里有多少个 `1`。**

所以你看到题目后，脑子里最好先把问题翻译成：

- 先把这个数看成一串二进制位
- 然后数里面有几个 `1`

比如：

```text
11 -> 1011 -> 3 个 1
```

题目本身不难，关键在于：
- 最直观的方法是什么
- 更符合位运算专题的方法是什么
- 面试时应该重点讲哪一种

> 说明：如果把题目中的整数看成固定 32 位，那么下面几种方法的时间复杂度都可以视为 `O(1)`。
> 为了更方便理解，这里按“二进制位数”来分析复杂度，也就是写成 `O(log n)` 或 `O(k)`。

---

## 1. 二进制字符串统计

### 思路
最直接的想法就是：

1. 先把 `n` 转成二进制字符串
2. 再遍历字符串，统计里面有多少个字符 `'1'`

### 为什么可行
因为题目要的就是“二进制中 `1` 的个数”。

那我们完全可以先把二进制形式显式地拿出来，再去数。

比如：

```text
11 -> 1011
```

然后逐个字符看：
- 第 1 位是 `1`
- 第 2 位是 `0`
- 第 3 位是 `1`
- 第 4 位是 `1`

所以一共是 `3`。

### 复杂度分析
- **时间复杂度：** `O(log n)`
- **空间复杂度：** `O(log n)`

### 评价
这个方法最容易想到，也最容易理解。

但它本质上不是“位运算解法”，而是借助字符串来做，所以如果面试官在考位运算，这通常不是最想看到的方法。

---

## 2. 逐位右移检查最低位

### 思路
既然目标是统计二进制里有多少个 `1`，那我们也可以不转字符串，而是直接一位一位检查。

做法是：

1. 看当前最低位是不是 `1`
   - 用 `n & 1` 判断
2. 如果是，就把答案加一
3. 然后把 `n` 右移一位
4. 重复直到 `n` 变成 `0`

### 为什么 `n & 1` 能判断最低位
因为：

- `1` 的二进制是 `...0001`
- `n & 1` 只会保留 `n` 的最低位

所以：

- 如果最低位是 `1`，那么 `n & 1 = 1`
- 如果最低位是 `0`，那么 `n & 1 = 0`

这就正好能告诉我们：当前这一位是不是 `1`。

### 为什么右移之后还能继续数
右移一位相当于把当前最低位“看完就丢掉”，然后把下一位移到最低位的位置。

这样我们每次都只检查最低位，就能把整个二进制从右往左扫完。

### 用例子走一遍
假设 `n = 11`，二进制是：

```text
1011
```

过程如下：

1. `n = 1011`
   - `n & 1 = 1`
   - `ans = 1`
   - 右移后 `n = 0101`

2. `n = 0101`
   - `n & 1 = 1`
   - `ans = 2`
   - 右移后 `n = 0010`

3. `n = 0010`
   - `n & 1 = 0`
   - `ans = 2`
   - 右移后 `n = 0001`

4. `n = 0001`
   - `n & 1 = 1`
   - `ans = 3`
   - 右移后 `n = 0000`

结束，答案就是 `3`。

### 复杂度分析
- **时间复杂度：** `O(log n)`
- **空间复杂度：** `O(1)`

### 评价
这个方法已经是标准位运算思路了。

它的优点是：
- 很直观
- 不依赖字符串
- 面试里容易讲清楚

但它会把每一位都检查一遍。如果一个数很长，但其中只有少量几个 `1`，那还有进一步优化空间。

## 3. Brian Kernighan 算法

### 思路
这是这道题最经典、最适合面试的方法。

核心操作只有一句：

```python
n &= n - 1
```

这句代码每执行一次，都会把 `n` 二进制中 **最右边的那个 `1` 去掉**。

所以我们只要：

1. 每做一次 `n &= n - 1`，就说明去掉了一个 `1`
2. 计数器加一
3. 一直做到 `n = 0`

最后计数器的值，就是 `1` 的总个数。

### 为什么 `n & (n - 1)` 能去掉最右边的 `1`
这是这道题最关键的地方，必须讲明白。

假设某个数的二进制长这样：

```text
xxxx1000...000
```

也就是说：
- 最右边那个 `1` 的右侧全是 `0`
- 左边的 `xxxx` 先不用管

那么 `n - 1` 会变成：

```text
xxxx0111...111
```

你可以看到两件事：

1. 最右边那个 `1` 变成了 `0`
2. 它右边原来的所有 `0` 都变成了 `1`

这时候再做按位与：

```text
xxxx1000...000
xxxx0111...111
----------------
xxxx0000...000
```

结果就是：
- 最右边那个 `1` 被清掉了
- 更高位保持不变
- 更低位都变成 `0`

所以每执行一次 `n &= n - 1`，就会恰好消掉一个 `1`。

### 用具体例子看
还是用 `n = 11`，二进制是：

```text
1011
```

第一次：

```text
n     = 1011
n - 1 = 1010
& 后   = 1010
```

去掉了最右边那个 `1`。

第二次：

```text
n     = 1010
n - 1 = 1001
& 后   = 1000
```

又去掉了一个 `1`。

第三次：

```text
n     = 1000
n - 1 = 0111
& 后   = 0000
```

再去掉一个 `1`。

一共做了 `3` 次，说明原来有 `3` 个 `1`。

### 这个方法比方法二优化了什么
方法二是：
- 不管这一位是 `0` 还是 `1`
- 都老老实实检查一遍

方法三是：
- 不去管那些 `0`
- 每次直接删掉一个 `1`

所以它的循环次数不是“总位数”，而是“`1` 的个数”。

如果一个数里 `1` 很少，这个方法会更高效。

### 复杂度分析
- **时间复杂度：** `O(1 的个数)`，也可以写成 `O(k)`，其中 `k` 是二进制中 `1` 的数量
- **空间复杂度：** `O(1)`

---

## 哪个方法最适合面试

### 最适合面试的方法：方法三（Brian Kernighan）

原因有三个：

1. **它是标准位运算优化方法**
   - 很符合这道题所在专题
   - 面试官通常就想看你会不会这个技巧

2. **它不是死记结论，而是有明确推导过程**
   - 关键在于理解 `n & (n - 1)` 为什么能删掉最右边的 `1`
   - 只要把这个讲清楚，整个方法就立住了

3. **它比逐位右移更进一步**
   - 不是检查所有位
   - 而是只处理那些真正为 `1` 的位

### 面试里推荐怎么讲
比较稳的一种讲法是：

1. 先说最直接可以把它转成二进制后统计
2. 然后说更位运算一点的做法是逐位右移，用 `n & 1` 看最低位
3. 最后再升级到最优：`n &= n - 1` 每次消掉一个 `1`
4. 补一句：所以循环多少次，就有多少个 `1`

这样就能把“从直观到优化”的过程讲完整。

---

## 总结

- **方法一：二进制字符串统计**
  - 最容易理解
  - 但不够“位运算”

- **方法二：逐位右移检查最低位**
  - 是标准位运算入门写法
  - 一位一位统计

- **方法三：Brian Kernighan 算法**
  - 每次直接消掉一个 `1`
  - 是这题最经典、最适合面试的方法
