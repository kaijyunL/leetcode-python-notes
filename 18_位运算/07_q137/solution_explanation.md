# LeetCode 137. 只出现一次的数字 II（Single Number II）循序渐进解析

## 题目描述

给你一个整数数组 `nums`，其中：

- 除了某个元素只出现一次以外
- 其余每个元素都恰好出现三次

请你找出那个只出现一次的元素。

题目要求你尽量做到：

- 时间复杂度：`O(n)`
- 额外空间复杂度：`O(1)`

例子一：

```text
输入：nums = [2, 2, 3, 2]
输出：3
```

例子二：

```text
输入：nums = [0, 1, 0, 1, 0, 1, 99]
输出：99
```

---

## 先理解题意

这题是 LeetCode 136「只出现一次的数字」的进阶版。

136 题里：

- 其他数字都出现两次
- 只有一个数字出现一次

所以可以直接把所有数字异或起来，因为：

```text
x ^ x = 0
```

成对数字会全部抵消。

但 137 题里，其他数字是出现三次：

```text
x, x, x
```

直接异或不行，因为：

```text
x ^ x ^ x = x
```

三个相同数字不会被异或消掉。

所以我们要换一个角度：既然每个重复数字都出现三次，那么它们在每一个二进制位上的贡献，也应该是 3 的倍数。

这就引出最经典的方法：

> 对每个二进制位分别统计 `1` 的个数，然后对 3 取余。

---

## 方法一：暴力计数

### 思路

最朴素的做法是：

1. 遍历数组里的每个数字 `num`
2. 再扫一遍数组，统计 `num` 出现了多少次
3. 如果次数是 `1`，返回它

### 为什么可行

题目要找的就是出现一次的数字。

所以只要真的数出每个数字出现了几次，就一定能找到答案。

### 为什么慢

如果数组长度是 `n`，每拿出一个数字都重新扫一遍数组，整体就是 `O(n^2)`。

这个方法能帮助理解题意，但不适合提交。

### 复杂度分析

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

---

## 方法二：哈希表计数

### 思路

暴力解法慢在重复统计。

所以我们可以用哈希表记录每个数字出现的次数：

1. 第一遍遍历 `nums`，统计每个数字出现了几次
2. 第二遍遍历哈希表，找到出现次数为 `1` 的数字

### 这一步优化了什么

暴力解法里，同一个数字的出现次数可能会被重复计算很多次。

哈希表的优化点是：

- 每个元素只处理一次
- 计数结果直接存起来

这样时间复杂度可以降到 `O(n)`。

### 为什么还不够好

题目希望额外空间是 `O(1)`。

哈希表需要存不同数字的出现次数，最坏情况下会用到 `O(n)` 空间，所以还不是最优。

### 复杂度分析

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

## 方法三：逐位统计 mod 3

### 核心思路

既然除了答案以外，其他数字都出现三次，那么对任意一个二进制位来说：

- 出现三次的数字，在这一位上贡献的 `1` 的数量一定是 `3` 的倍数
- 只有出现一次的那个数字，会让某些位多出来 `1`

所以我们可以：

1. 枚举 32 个二进制位
2. 统计所有数字在当前位上有多少个 `1`
3. 对这个数量 `% 3`
4. 如果余数是 `1`，说明答案在这一位上是 `1`

### 用例子理解

以：

```text
nums = [2, 2, 3, 2]
```

看二进制低几位：

```text
2 = 10
2 = 10
3 = 11
2 = 10
```

第 0 位，也就是最低位：

```text
0 + 0 + 1 + 0 = 1
1 % 3 = 1
```

说明答案最低位是 `1`。

第 1 位：

```text
1 + 1 + 1 + 1 = 4
4 % 3 = 1
```

说明答案第 1 位也是 `1`。

所以答案低两位是：

```text
11
```

也就是 `3`。

### 为什么这个方法成立

假设某一位上，出现三次的数字贡献了 `count_repeat` 个 `1`。

因为每个重复数字都出现三次，所以：

```text
count_repeat 一定是 3 的倍数
```

再加上答案数字在这一位上的贡献：

- 如果答案这一位是 `0`，总数 `% 3 = 0`
- 如果答案这一位是 `1`，总数 `% 3 = 1`

所以 `count % 3` 就能还原答案在这一位上的值。

### Python 负数怎么处理

Python 的整数不是固定 32 位，负数有无限符号位。

为了和 LeetCode 的 32 位整数语义一致，我们按 32 位来统计：

```python
for i in range(32):
```

构造完 `result` 后，如果最高符号位，也就是第 31 位是 `1`，说明结果是负数。

这时要把它从 32 位补码转回 Python 负数：

```python
if result >= 1 << 31:
    result -= 1 << 32
```

例如：

```text
0xFFFFFFFF
```

在 32 位补码里是 `-1`，但 Python 直接看是 `4294967295`。

减去 `2^32`：

```text
4294967295 - 4294967296 = -1
```

这样就转回了 Python 的负数。

### 复杂度分析

固定统计 32 位：

- 时间复杂度：`O(32n)`，也就是 `O(n)`
- 空间复杂度：`O(1)`

### 评价

这是这题最推荐的面试方法。

它的优点是：

- 思路清晰
- 容易从“出现三次”这个条件推出来
- 代码稳定
- 可以自然处理负数，只要最后做一次 32 位补码转换

## 方法四：有限状态机位运算

### 核心思路

方法三是逐位统计。

还可以把每一位出现 `1` 的次数看成一个状态机：

```text
出现 0 次 -> 出现 1 次 -> 出现 2 次 -> 出现 0 次
```

因为出现三次就应该被清掉。

我们用两个变量记录每一位当前的状态：

- `ones`：这一位目前出现了 `1` 次
- `twos`：这一位目前出现了 `2` 次

当新数字 `num` 进来时，更新：

```python
ones = (ones ^ num) & ~twos
twos = (twos ^ num) & ~ones
```

遍历结束后，出现三次的位都被清掉，`ones` 中保留的就是只出现一次的数字。

### 为什么它能工作

对每一个二进制位单独看，它的状态会按下面规律变化：

```text
0 次：ones = 0, twos = 0
1 次：ones = 1, twos = 0
2 次：ones = 0, twos = 1
3 次：ones = 0, twos = 0
```

也就是说，我们用两个 bit 就能表示“当前这一位的出现次数 mod 3”。

`ones` 最后保存的是出现次数 `% 3 == 1` 的位。

这正好就是答案。

### 复杂度分析

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

### 评价

这个方法代码很短，但推导不如逐位统计直观。

如果面试官特别关注位运算技巧，可以补充这个方法；如果是正常面试，主讲逐位统计更稳。

---

## 哪个方法最适合面试

### 最适合面试的方法：方法三（逐位统计 mod 3）

这题最推荐面试中主讲方法三。

原因有三个。

第一，它直接利用了题目条件。

题目说其他数字都出现三次，那么每个二进制位上的 `1` 的总数也应该按 3 抵消。

第二，它比有限状态机更容易解释。

逐位统计只需要说明：

```text
每一位的 1 的个数 % 3，就是答案这一位
```

第三，它对负数也比较容易处理。

只要按 32 位统计，最后看最高符号位是否为 `1`，再转回 Python 负数即可。

### 面试里可以这样讲

一套比较顺的表达是：

1. 如果用哈希表计数，可以做到 `O(n)`，但空间是 `O(n)`
2. 题目要求常数空间，所以尝试从二进制位入手
3. 对任意一位，出现三次的数字贡献的 `1` 的数量一定是 3 的倍数
4. 所以统计每一位所有数字的 `1` 的个数，再对 3 取余
5. 余数为 `1` 的位，就是答案中应该为 `1` 的位
6. Python 中按 32 位处理，最后如果结果超过 `2^31 - 1`，转回负数

---

## 总结

- 方法一：暴力计数
  - 好理解
  - 时间复杂度 `O(n^2)`

- 方法二：哈希表计数
  - 时间复杂度 `O(n)`
  - 但空间复杂度 `O(n)`

- 方法三：逐位统计 mod 3
  - 最适合面试主讲
  - 时间复杂度 `O(n)`，空间复杂度 `O(1)`
  - 核心是每一位的 `1` 的数量对 3 取余

- 方法四：有限状态机位运算
  - 代码短
  - 位运算味道更浓
  - 但推导成本更高，适合作为进阶补充
