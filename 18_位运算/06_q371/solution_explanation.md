# LeetCode 371. 两整数之和（Sum of Two Integers）循序渐进解析

## 题目描述

给你两个整数 `a` 和 `b`，请你返回它们的和。

要求是：不能使用加法运算符 `+` 和减法运算符 `-`。

例子一：

```text
输入：a = 1, b = 2
输出：3
```

例子二：

```text
输入：a = 2, b = 3
输出：5
```

这题真正想考的不是普通加法，而是：

> 加法在二进制层面到底是怎么发生的。

---

## 先理解题意

如果不能用 `+` 和 `-`，那就不能直接写：

```python
return a + b
```

我们要把加法拆成二进制里的两个动作：

1. 不考虑进位时，每一位相加的结果
2. 哪些位置会产生进位

以一位二进制为例：

```text
0 + 0 = 0，不进位
0 + 1 = 1，不进位
1 + 0 = 1，不进位
1 + 1 = 0，进 1
```

观察这张表：

- 不考虑进位的结果，正好是异或 `^`
- 是否产生进位，正好是按位与 `&`

所以二进制加法可以拆成：

```text
无进位和 = a ^ b
进位 = (a & b) << 1
```

然后继续把“无进位和”和“进位”加起来，直到没有进位为止。

这就是这题的核心。

---

## Python 里为什么要额外处理负数

这题在 C/C++/Java 这类固定 32 位整数语言里比较直接。

但 Python 的整数不是固定 32 位，而是可以无限扩展。尤其是负数，Python 会表现得像有无限个前导 `1`。

比如从概念上看：

```text
-1 可以看成 ...11111111
```

如果直接对负数做下面这类循环：

```python
while b:
    carry = (a & b) << 1
    a = a ^ b
    b = carry
```

有些负数场景可能无法按预期收敛，因为符号位会无限延伸。

所以 Python 解这题时，通常要手动模拟 32 位整数：

```python
MASK = 0xFFFFFFFF
MAX_INT = 0x7FFFFFFF
```

含义是：

- `MASK`：只保留低 32 位
- `MAX_INT`：32 位有符号整数的最大正数

每次运算后都用 `& MASK` 截断到 32 位，最后再把结果转回 Python 的有符号整数。

---

## 方法一：逐位模拟二进制加法

### 思路

先用最接近手算加法的方式理解。

我们从低位到高位，一位一位处理：

1. 取出 `a` 当前位
2. 取出 `b` 当前位
3. 加上上一位传来的 `carry`
4. 算出当前位结果
5. 算出下一位进位

只不过这里不能用 `+`，所以当前位结果和进位都要用位运算表达。

### 当前位结果怎么求

一位二进制里，不考虑进位时：

```text
0 和 0 -> 0
0 和 1 -> 1
1 和 0 -> 1
1 和 1 -> 0
```

这正好是异或。

如果还要把旧进位 `carry` 也算进来，那么当前位就是：

```python
sum_bit = bit_a ^ bit_b ^ carry
```

### 下一位进位怎么求

在三个值 `bit_a`、`bit_b`、`carry` 里，只要至少两个是 `1`，下一位就会产生进位。

所以可以写成：

```python
carry = (bit_a & bit_b) | (bit_a & carry) | (bit_b & carry)
```

意思是：

- `bit_a` 和 `bit_b` 都是 `1`
- 或者 `bit_a` 和旧 `carry` 都是 `1`
- 或者 `bit_b` 和旧 `carry` 都是 `1`

三种情况任意一种成立，下一位就有进位。

### 为什么要处理 32 位

为了兼容负数，我们先把 `a` 和 `b` 都截断成 32 位：

```python
a &= MASK
b &= MASK
```

然后只模拟 32 位。

最后得到的 `result` 如果不超过 `MAX_INT`，说明它是非负数，直接返回。

如果超过 `MAX_INT`，说明最高位是符号位 `1`，要把它转回 Python 的负数表示：

```python
return ~(result ^ MASK)
```

比如 32 位里的：

```text
0xFFFFFFFF
```

应该表示 `-1`，而不是 Python 里的正数 `4294967295`。

### 复杂度分析

因为固定只处理 32 位：

- 时间复杂度：`O(1)`
- 空间复杂度：`O(1)`

### 评价

这个方法适合用来理解加法的底层过程。

它比较直观，但代码稍长。面试里通常不需要写到这么细，可以直接讲方法二。

## 方法二：异或加进位迭代

### 核心思路

二进制加法可以拆成两部分：

```text
a ^ b        表示不考虑进位的和
(a & b) << 1 表示进位
```

如果进位不为 `0`，说明还没加完。

那就继续把：

```text
无进位和
进位
```

再做同样的加法。

直到进位变成 `0`，此时无进位和就是最终答案。

### 用例子走一遍

以 `a = 2`，`b = 3` 为例：

```text
2 = 010
3 = 011
```

第一轮：

```text
无进位和：010 ^ 011 = 001
进位：   (010 & 011) << 1 = 100
```

现在问题变成：

```text
001 + 100
```

第二轮：

```text
无进位和：001 ^ 100 = 101
进位：   (001 & 100) << 1 = 000
```

进位为 `0`，结束。

```text
101 = 5
```

所以答案是 `5`。

### 为什么这个过程一定能结束

在固定 32 位整数里，进位只能不断往更高位移动。

我们每次都把结果截断在低 32 位：

```python
carry = ((a & b) << 1) & MASK
a = (a ^ b) & MASK
b = carry
```

所以进位最多传播 32 次。最终 `b` 会变成 `0`。

### Python 负数怎么转回来

循环结束后，`a` 是一个 32 位结果。

如果：

```python
a <= MAX_INT
```

说明它是非负数，直接返回。

否则说明它对应的是 32 位补码负数，需要转成 Python 负数：

```python
return ~(a ^ MASK)
```

举个例子：

```text
32 位结果：0xFFFFFFFE
它表示：-2
```

转回 Python：

```python
~(0xFFFFFFFE ^ 0xFFFFFFFF)
= ~0x00000001
= -2
```

### 复杂度分析

固定 32 位下：

- 时间复杂度：`O(1)`
- 空间复杂度：`O(1)`

如果按整数的二进制位数 `k` 泛化理解，也可以说是：

- 时间复杂度：`O(k)`
- 空间复杂度：`O(1)`

## 哪个方法最适合面试

### 最适合面试的方法：方法二（异或加进位迭代）

面试里最推荐写方法二：

```python
while b:
    carry = ((a & b) << 1) & MASK
    a = (a ^ b) & MASK
    b = carry
```

原因有三个。

第一，它直接对应二进制加法的本质。

- `a ^ b` 是无进位加法
- `(a & b) << 1` 是进位

第二，代码短。

核心循环只有几行，容易写完，也容易解释。

第三，它能体现你知道 Python 的特殊坑。

如果面试语言是 Python，一定要说明负数需要用 32 位掩码处理，否则 `a = -1, b = 1` 这类用例容易出问题。

### 面试里可以这样讲

一套比较顺的表达是：

1. 二进制加法可以拆成“无进位和”和“进位”
2. 无进位和用异或：`a ^ b`
3. 进位用按位与后左移：`(a & b) << 1`
4. 如果进位不为 `0`，就继续把无进位和与进位相加
5. 在 Python 中需要用 `0xFFFFFFFF` 把结果限制为 32 位
6. 最后如果结果超过 `0x7FFFFFFF`，说明它是负数补码，要转回 Python 负数

这套讲法比只背 `a ^ b` 和 `a & b` 更稳，因为它解释了公式为什么成立，也解释了 Python 里的边界问题。

---

## 总结

- 方法一：逐位模拟二进制加法
  - 最接近手算过程
  - 适合理解当前位和进位怎么来
  - 代码较长，不是面试首选

- 方法二：异或加进位迭代
  - 最适合面试主讲
  - `a ^ b` 表示无进位和
  - `(a & b) << 1` 表示进位
  - Python 中要额外用 32 位掩码处理负数
