# LeetCode 338. 比特位计数（Counting Bits）循序渐进解析

## 题目描述
给你一个整数 `n`，请你返回一个长度为 `n + 1` 的数组 `ans`，其中：

- `ans[i]` 表示整数 `i` 的二进制表示中 `1` 的个数
- 也就是 `i` 的 Hamming Weight

例如：

- `n = 2`
  - `0` 的二进制是 `0`，有 `0` 个 `1`
  - `1` 的二进制是 `1`，有 `1` 个 `1`
  - `2` 的二进制是 `10`，有 `1` 个 `1`
  - 所以答案是 `[0, 1, 1]`

- `n = 5`
  - `0, 1, 2, 3, 4, 5` 的答案依次是
  - `[0, 1, 1, 2, 1, 2]`

---

## 先理解题意
这题和 191 题很像，但又不完全一样。

191 题是：
- 给你一个数
- 问你这个数里有几个 `1`

338 题是：
- 给你一个 `n`
- 让你把 `0 ~ n` 每个数里有几个 `1` 都算出来

所以最直接的想法肯定是：

- 对每个 `i`
- 单独调用一次“统计 `1` 的个数”的方法

但这样做虽然能过，还不够好。

因为这题真正想考的是：

**前面的结果，能不能帮助你更快地得到后面的结果。**

这就是 DP 的切入点。

---

## 1. 逐个数字调用统计函数

### 思路
最朴素的做法是：

1. 从 `0` 遍历到 `n`
2. 对每个数单独统计二进制里 `1` 的个数
3. 把结果放进答案数组

如果你已经会了 191 题里的 Brian Kernighan 算法，那这里完全可以直接复用。

### 为什么可行
因为题目要求的就是把每个数的 `1` 的个数都算出来。

那我们就一个一个算，最后收集起来。

这个思路没有技巧，但绝对正确。

### 举个例子
假设 `n = 5`：

- `0 -> 0`
- `1 -> 1`
- `2 -> 1`
- `3 -> 2`
- `4 -> 1`
- `5 -> 2`

最终得到：

```text
[0, 1, 1, 2, 1, 2]
```

### 复杂度分析
如果对每个数都用位运算单独统计，那么总复杂度大致是：

- **时间复杂度：** `O(n log n)`
- **空间复杂度：** `O(1)`（不算返回数组）

如果把返回数组算进去，则总空间是 `O(n)`。

### 为什么还不够好
问题在于：

- `2` 的答案算了一次
- `3` 的答案又重新算
- `4` 的答案又重新算

也就是说，我们没有利用“相邻数字之间其实存在规律”这件事。

## 2. DP：利用最低位

### 思路
观察一个数 `i` 的二进制：

- 如果最低位是 `0`，那它的 `1` 的个数和 `i >> 1` 一样
- 如果最低位是 `1`，那它的 `1` 的个数就是 `i >> 1` 的答案再加 `1`

这两种情况其实可以统一写成：

```python
ans[i] = ans[i >> 1] + (i & 1)
```

这就是这题非常经典的一种 DP。

### 为什么这个转移成立
这一步一定要讲清楚两个符号的含义：

#### `i >> 1` 表示什么
`i >> 1` 就是把 `i` 的二进制整体右移一位，相当于去掉最低位。

比如：

```text
13 = 1101
13 >> 1 = 110 = 6
```

也就是说：
- `i >> 1` 保留了除最低位之外的其他高位部分
- 所以 `i` 的 `1` 的个数 = `i >> 1` 的 `1` 的个数 + 最低位是不是 `1`

#### `i & 1` 表示什么
`i & 1` 只会取出 `i` 的最低位：
- 最低位是 `0`，结果就是 `0`
- 最低位是 `1`，结果就是 `1`

所以：

```python
ans[i] = ans[i >> 1] + (i & 1)
```

就是在说：

**当前这个数的 1 的个数 = 去掉最低位之后的 1 的个数 + 最低位贡献的 0 或 1。**

### 用例子走一遍
以 `i = 5` 为例：

```text
5 = 101
5 >> 1 = 10 = 2
5 & 1 = 1
```

而：
- `ans[2] = 1`
- 所以 `ans[5] = ans[2] + 1 = 2`

确实正确。

再看 `i = 6`：

```text
6 = 110
6 >> 1 = 11 = 3
6 & 1 = 0
```

而：
- `ans[3] = 2`
- 所以 `ans[6] = ans[3] + 0 = 2`

也正确。

### 为什么这就是 DP
因为我们在求 `ans[i]` 的时候，依赖的是更小的状态 `ans[i >> 1]`。

而 `i >> 1 < i`，所以当我们从小到大遍历 `i = 1...n` 时，所需要的旧答案一定已经算好了。

### 复杂度分析
- **时间复杂度：** `O(n)`
- **空间复杂度：** `O(n)`（返回数组本身）

### 评价
这个方法非常适合面试：
- 公式短
- 规律清楚
- 容易解释

## 3. DP：利用去掉最右边的 1

### 思路
我们还可以直接复用 191 题里的核心技巧：

```python
i & (i - 1)
```

这个操作会把 `i` 二进制中 **最右边的那个 `1` 去掉**。

所以：

```python
ans[i] = ans[i & (i - 1)] + 1
```

意思是：
- 先把 `i` 最右边那个 `1` 去掉
- 剩下的那个更小的数，它有多少个 `1` 我们已经知道了
- 再加上刚刚去掉的这一个 `1`

### 为什么这个转移成立
假设：

```text
i = 1011000
```

那么：

```text
i - 1 = 1010111
```

再做：

```text
i & (i - 1)
```

会变成：

```text
1010000
```

也就是：
- 最右边那个 `1` 被删掉了
- 其他更高位保留下来

所以 `i` 的 `1` 的个数，显然就是：
- “删掉一个 `1` 之后那个数”的 `1` 的个数
- 再加 `1`

这就是：

```python
ans[i] = ans[i & (i - 1)] + 1
```

### 用例子走一遍
看 `i = 6`：

```text
6 = 110
6 - 1 = 101
6 & 5 = 100 = 4
```

所以：
- `ans[6] = ans[4] + 1`
- `ans[4] = 1`
- 所以 `ans[6] = 2`

正确。

再看 `i = 7`：

```text
7 = 111
7 - 1 = 110
7 & 6 = 110 = 6
```

所以：
- `ans[7] = ans[6] + 1`
- `ans[6] = 2`
- `ans[7] = 3`

也正确。

### 这个方法和方法二的区别
方法二是从“最低位”角度想：

```python
ans[i] = ans[i >> 1] + (i & 1)
```

方法三是从“删掉一个 1”角度想：

```python
ans[i] = ans[i & (i - 1)] + 1
```

两者都是对的，都是 `O(n)`。

区别在于：
- 方法二更直观，适合第一次想到
- 方法三和 191 的联系更强，位运算味道更浓

---

## 哪个方法最适合面试

### 最适合面试的方法：方法二（利用最低位）

原因有三个：

1. **公式最自然**
   - 去掉最低位后，看剩余部分
   - 再看最低位是不是 `1`

2. **讲解很顺**
   - `i >> 1` 表示去掉最低位
   - `i & 1` 表示最低位本身
   - 两部分一加，逻辑非常清楚

3. **代码短且稳定**
   - 不容易写错
   - 也容易记住

### 面试里推荐怎么讲
比较稳的一种讲法是：

1. 先说最直接做法是对每个数单独统计 `1` 的个数
2. 然后指出这样重复计算太多
3. 再引出 DP：`ans[i]` 能不能由更小的数推出
4. 最后给出：

```python
ans[i] = ans[i >> 1] + (i & 1)
```

如果面试官继续追问，也可以补充：

```python
ans[i] = ans[i & (i - 1)] + 1
```

---

## 总结

- **方法一：逐个数字单独统计**
  - 好理解
  - 但有重复计算

- **方法二：DP + 最低位**
  - 最推荐面试使用
  - 公式自然、解释顺畅

- **方法三：DP + 去掉最右边的 1**
  - 和 191 联系紧
  - 位运算味道更强
