# LeetCode 338. 比特位计数（Counting Bits）循序渐进解析

## 题目描述

给你一个整数 `n`，返回一个长度为 `n + 1` 的数组 `ans`，其中：

- `ans[i]` 表示整数 `i` 的二进制表示中 `1` 的个数
- `i` 的范围是 `0 <= i <= n`

也就是说，这题不是只问一个数里有几个 `1`，而是要一次性求出：

```text
0, 1, 2, ..., n
```

这些数字各自的二进制 `1` 的个数。

例子一：

```text
输入：n = 2
输出：[0, 1, 1]
```

解释：

```text
0 -> 0  -> 0 个 1
1 -> 1  -> 1 个 1
2 -> 10 -> 1 个 1
```

例子二：

```text
输入：n = 5
输出：[0, 1, 1, 2, 1, 2]
```

解释：

```text
0 -> 0   -> 0
1 -> 1   -> 1
2 -> 10  -> 1
3 -> 11  -> 2
4 -> 100 -> 1
5 -> 101 -> 2
```

常见约束是：

- `0 <= n <= 10^5`

这个约束提示我们：单独统计每个数也许能过，但题目更希望我们用线性时间把所有答案一次性推出来。

---

## 先理解题意

这题和 LeetCode 191「位1的个数」关系很近。

191 题是：

- 给一个数 `x`
- 求 `x` 的二进制里有几个 `1`

338 题是：

- 给一个上界 `n`
- 求 `0 ~ n` 每个数的二进制里有几个 `1`

所以最直接的想法是：对 `0 ~ n` 中的每个数，都调用一次 191 题里的统计函数。

这个思路肯定正确，但它有一个明显问题：**每个数字都从头统计，没有复用前面已经算过的结果。**

比如：

```text
5 = 101
2 = 10
```

`5` 去掉最低位之后就是 `2`。如果我们已经知道 `2` 有几个 `1`，其实就没必要把 `5` 的所有二进制位重新数一遍。

这就是这题的核心切入点：

> 当前数字的答案，能不能由更小数字的答案推出来？

只要能做到这一点，就可以把逐个统计的重复计算优化成动态规划。

---

## 方法一：逐个数字单独统计

### 思路

先不考虑复用结果，最朴素的做法是：

1. 创建答案数组 `ans`
2. 从 `0` 遍历到 `n`
3. 对每个数字 `num`，单独统计它的二进制中有几个 `1`
4. 把统计结果加入 `ans`

统计单个数字时，可以用 Brian Kernighan 算法：

```python
num &= num - 1
```

这一步每执行一次，都会删除 `num` 二进制中最右边的一个 `1`。

### 为什么可行

题目要求的是每个数字的 `1` 的个数。

那我们就对每个数字分别求一次。虽然没有技巧，但完全符合题意。

比如 `n = 5`：

```text
0 -> 0
1 -> 1
2 -> 1
3 -> 2
4 -> 1
5 -> 2
```

最终得到：

```text
[0, 1, 1, 2, 1, 2]
```

### 为什么会慢

慢点在于：每个数字都被当成一个全新的问题处理。

比如 `6 = 110`，它和 `3 = 11`、`4 = 100` 都有明显关系，但这个方法没有利用这些关系。

如果从二进制位数角度看，一个不超过 `n` 的数字最多有 `O(log n)` 位，所以对 `0 ~ n` 每个数字都单独统计，总体就是：

- 时间复杂度：`O(n log n)`
- 额外空间复杂度：`O(1)`，不算返回数组

如果把返回数组也算进去，空间是 `O(n)`。

### 这一层的意义

这个方法适合作为起点。它帮我们确认：

- 题目本质是“统计二进制中 1 的个数”
- 单个数字的问题我们已经会做
- 接下来要优化的是“对每个数字重复统计”这件事

## 方法二：DP + 最低位

### 核心思路

观察一个数字 `i` 的二进制。

如果把 `i` 的最低位去掉，剩下的数字就是：

```python
i >> 1
```

而 `i` 的最低位本身可以用：

```python
i & 1
```

取出来。

所以，`i` 的 `1` 的个数可以拆成两部分：

```text
i 的 1 的个数
= 去掉最低位之后的 1 的个数 + 最低位是不是 1
```

写成状态转移就是：

```python
ans[i] = ans[i >> 1] + (i & 1)
```

### 为什么这个转移成立

这里有两个关键符号。

#### `i >> 1` 表示去掉最低位

右移一位会把二进制整体往右挪，相当于丢掉最低位。

例如：

```text
13 = 1101
13 >> 1 = 110 = 6
```

所以 `i >> 1` 保留的是 `i` 除最低位以外的高位部分。

#### `i & 1` 表示最低位的贡献

`1` 的二进制是：

```text
...0001
```

所以 `i & 1` 只会看 `i` 的最低位：

- 如果最低位是 `0`，结果是 `0`
- 如果最低位是 `1`，结果是 `1`

这正好就是最低位对答案的贡献。

因此：

```python
ans[i] = ans[i >> 1] + (i & 1)
```

这句话的含义是：

> 当前数字的答案 = 去掉最低位后的答案 + 最低位贡献。

### 用例子走一遍

看 `i = 5`：

```text
5 = 101
5 >> 1 = 10 = 2
5 & 1 = 1
```

`ans[2] = 1`，所以：

```text
ans[5] = ans[2] + 1 = 2
```

再看 `i = 6`：

```text
6 = 110
6 >> 1 = 11 = 3
6 & 1 = 0
```

`ans[3] = 2`，所以：

```text
ans[6] = ans[3] + 0 = 2
```

### 为什么可以从小到大遍历

求 `ans[i]` 时依赖的是 `ans[i >> 1]`。

只要 `i >= 1`，就一定有：

```text
i >> 1 < i
```

所以我们从 `1` 遍历到 `n` 时，`ans[i >> 1]` 一定已经提前算好了。

这就是动态规划在这题里的含义：用更小数字的答案推出当前数字的答案。

### 复杂度分析

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`，返回数组本身

### 评价

这是这题最推荐的面试方法。

它的优势是：

- 公式短
- 推导自然
- 不依赖特殊记忆
- 对奇数、偶数都能统一处理

## 方法三：DP + 去掉最右边的 1

### 核心思路

还可以从另一个角度复用 191 题的技巧。

对任意正整数 `i`：

```python
i & (i - 1)
```

会把 `i` 二进制中最右边的那个 `1` 删除。

所以：

```python
ans[i] = ans[i & (i - 1)] + 1
```

含义是：

1. 先把 `i` 最右边的一个 `1` 删掉
2. 删完之后得到一个更小的数 `i & (i - 1)`
3. 这个更小数的答案已经算过了
4. 再加回刚刚删掉的那个 `1`

### 为什么 `i & (i - 1)` 能删掉最右边的 1

假设 `i` 的二进制长这样：

```text
xxxx1000
```

这里的 `1` 是最右边的那个 `1`，它右边全是 `0`。

那么 `i - 1` 会变成：

```text
xxxx0111
```

再做按位与：

```text
xxxx1000
xxxx0111
--------
xxxx0000
```

结果就是最右边的那个 `1` 被清掉了，更高位保持不变。

### 用例子走一遍

看 `i = 6`：

```text
6 = 110
6 - 1 = 101
6 & 5 = 100 = 4
```

所以：

```text
ans[6] = ans[4] + 1 = 1 + 1 = 2
```

看 `i = 7`：

```text
7 = 111
7 - 1 = 110
7 & 6 = 110 = 6
```

所以：

```text
ans[7] = ans[6] + 1 = 2 + 1 = 3
```

### 为什么可以从小到大遍历

对于任意正整数 `i`：

```text
i & (i - 1) < i
```

因为它至少删除了 `i` 里的一个 `1`。

所以从 `1` 到 `n` 正序计算时，`ans[i & (i - 1)]` 也一定已经算好了。

### 复杂度分析

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`，返回数组本身

### 和方法二的区别

两种 DP 都是 `O(n)`，区别主要是思考角度不同：

- 方法二：去掉最低位，再加上最低位的贡献
- 方法三：直接删掉最右边的一个 `1`，再加 `1`

方法三很漂亮，但需要你能清楚解释 `i & (i - 1)` 的作用。

## 哪个方法最适合面试

### 最适合面试的方法：方法二（DP + 最低位）

我更推荐面试中主讲方法二：

```python
ans[i] = ans[i >> 1] + (i & 1)
```

原因有三个。

第一，推导最自然。

一个数字的二进制可以拆成：

```text
高位部分 + 最低位
```

`i >> 1` 对应高位部分，`i & 1` 对应最低位贡献，这个拆法非常直接。

第二，边界稳定。

`ans[0] = 0` 是天然初始值。从 `i = 1` 开始遍历即可，不需要额外分奇偶或特殊处理。

第三，代码短且不容易写错。

核心循环只有一行：

```python
for i in range(1, n + 1):
    ans[i] = ans[i >> 1] + (i & 1)
```

如果面试官追问其他位运算关系，再补充方法三即可。

### 面试里可以这样讲

一套比较顺的表达是：

1. 最直接的做法是对 `0 ~ n` 的每个数字都单独统计 `1` 的个数，时间大约是 `O(n log n)`
2. 但这样没有复用前面的结果，所以考虑动态规划
3. 对当前数字 `i`，右移一位 `i >> 1` 相当于去掉最低位
4. 最低位是否为 `1` 可以用 `i & 1` 得到
5. 因此 `ans[i] = ans[i >> 1] + (i & 1)`
6. 因为 `i >> 1 < i`，所以从小到大遍历时依赖状态已经算过

这套讲法能体现你不是背公式，而是从题意一步步推出状态转移。

---

## 总结

- 方法一：逐个数字单独统计
  - 好理解
  - 但每个数字都重新计算，时间复杂度约为 `O(n log n)`

- 方法二：DP + 最低位
  - 最推荐面试主讲
  - 状态转移是 `ans[i] = ans[i >> 1] + (i & 1)`
  - 时间复杂度 `O(n)`，空间复杂度 `O(n)`

- 方法三：DP + 去掉最右边的 1
  - 状态转移是 `ans[i] = ans[i & (i - 1)] + 1`
  - 和 LeetCode 191 的 Brian Kernighan 技巧联系很紧
  - 同样是 `O(n)`，但讲解时要把 `i & (i - 1)` 说明白
