# LeetCode 268. 丢失的数字（Missing Number）循序渐进解析

## 题目描述
给定一个包含 `n` 个 **不同数字** 的数组 `nums`，数组中的数字都在区间 `[0, n]` 内。

也就是说：
- 理论上应该一共有 `n + 1` 个数字：`0, 1, 2, ..., n`
- 但现在数组里只给了你 `n` 个数字
- 其中恰好少了一个数字

请你找出这个缺失的数字。

例如：

- `nums = [3, 0, 1]`
  - 这里 `n = 3`
  - 理论上应该有 `0, 1, 2, 3`
  - 实际少了 `2`
  - 答案是 `2`

- `nums = [0, 1]`
  - 这里 `n = 2`
  - 理论上应该有 `0, 1, 2`
  - 实际少了 `2`
  - 答案是 `2`

题目通常还会追问：能不能做到 `O(n)` 时间、`O(1)` 额外空间。

---

## 先理解这道题的本质
这题不是让你“找一个没出现过的任意数字”，而是：

- 数字范围已经固定为 `[0, n]`
- 总共应该有 `n + 1` 个数
- 现在只少了其中一个

也就是说，这题的关键是：

**“完整集合”和“当前数组”之间只差一个数。**

所以我们的思路一般都会围绕：
- 怎么表示完整集合
- 怎么把缺失的那个数找出来

---

## 1. 排序后查缺口

### 思路
最直接的做法之一是先排序。

排序后，如果数组没有缺失，理想情况应该是：

- 下标 `0` 放数字 `0`
- 下标 `1` 放数字 `1`
- 下标 `2` 放数字 `2`
- ...

所以我们排序后逐个检查：
- 如果 `nums[i] != i`，那说明缺失的就是 `i`
- 如果前面都对上了，那缺失的就是最后的 `n`

### 为什么可行
因为数组中的数字互不重复，而且范围正好是 `[0, n]`。

排序之后，这些数应该按从小到大排好。
如果缺了某个数，比如缺了 `2`，那从下标 `2` 开始，后面的数字都会“往前挤一位”，于是我们第一次看到 `nums[i] != i` 的地方，就是答案。

### 举个例子
`nums = [3, 0, 1]`

排序后变成：

```text
[0, 1, 3]
```

检查下标：
- `i = 0`，`nums[0] = 0`，正常
- `i = 1`，`nums[1] = 1`，正常
- `i = 2`，`nums[2] = 3`，不等于 `2`

所以缺失的数字就是 `2`。

### 复杂度分析
- **时间复杂度：** `O(n log n)`
- **空间复杂度：** 取决于排序实现；如果按 Python 的排序，一般记作 `O(n)`

### 评价
这个方法容易想到，也容易写对。
但它没有达到线性时间，所以还可以继续优化。

---

## 2. 哈希集合

### 思路
既然我们知道答案一定在 `[0, n]` 之间，那就可以先把数组里的数字都放进一个集合里，然后从 `0` 到 `n` 逐个检查哪个数字不在集合中。

第一个不在集合里的数，就是缺失的数字。

### 为什么比排序更直接
排序的本质是把数组重新排好再查。

而哈希集合的想法是：
- 我不关心顺序
- 我只关心某个数在不在

集合最适合做“存在性判断”，所以这题可以很自然地想到它。

### 举个例子
`nums = [9, 6, 4, 2, 3, 5, 7, 0, 1]`

这里 `n = 9`，理论上应该有 `0~9`。

我们把数组放进集合后，从 `0` 开始查：
- `0` 在
- `1` 在
- `2` 在
- `3` 在
- `4` 在
- `5` 在
- `6` 在
- `7` 在
- `8` 不在

所以答案就是 `8`。

### 复杂度分析
- **时间复杂度：** `O(n)`
- **空间复杂度：** `O(n)`

### 评价
这个方法已经满足线性时间了，而且面试里也很稳。
不过它还用了额外集合，所以如果题目继续要求常数空间，我们还要继续优化。

## 3. 数学求和

### 思路
这题还有一个非常自然的想法：

既然完整集合应该是 `0 + 1 + 2 + ... + n`，那么：

- 先算出理论总和
- 再减去数组的实际总和
- 剩下的差值，就是丢失的数字

### 为什么成立
因为数组里除了一个数没了之外，其他数字都还在。

所以：

```text
完整总和 - 实际总和 = 缺失的那个数
```

### 举个例子
`nums = [3, 0, 1]`

- `n = 3`
- 理论总和是 `0 + 1 + 2 + 3 = 6`
- 实际总和是 `3 + 0 + 1 = 4`

所以：

```text
6 - 4 = 2
```

答案就是 `2`。

### 公式怎么写
`0 + 1 + 2 + ... + n` 的公式是：

```text
n * (n + 1) // 2
```

所以可以直接写成：

```python
expected = n * (n + 1) // 2
actual = sum(nums)
return expected - actual
```

### 复杂度分析
- **时间复杂度：** `O(n)`
- **空间复杂度：** `O(1)`

### 这个方法的优点
它非常短，非常适合面试时快速写出正确答案。

但有些面试官在位运算专题里，会更想看你有没有想到异或做法，所以还可以再往下一步。

## 4. 位运算异或

### 思路
这题和 136 题很像，核心也是“成对抵消”。

我们把两部分全部异或起来：

1. 数字 `0 ~ n`
2. 数组里的所有数字

因为除了缺失的那个数字之外，其余数字都会在这两部分里各出现一次，所以它们都会两两抵消，最后剩下的就是缺失的数字。

### 为什么成立
异或有三个关键性质：

1. `a ^ a = 0`
2. `0 ^ a = a`
3. 异或满足交换律和结合律

这意味着：
- 相同的数字异或后会消掉
- 计算顺序不重要

所以如果把 `0 ~ n` 和 `nums` 放在一起全部异或：
- 出现过的数字都会配对消失
- 唯一没配对的，就是缺失的数字

### 用例子走一遍
`nums = [3, 0, 1]`

这里 `n = 3`。

理论完整数字是：

```text
0, 1, 2, 3
```

数组实际有：

```text
3, 0, 1
```

全部异或起来：

```text
(0 ^ 1 ^ 2 ^ 3) ^ (3 ^ 0 ^ 1)
```

重新组合：

```text
(0 ^ 0) ^ (1 ^ 1) ^ (3 ^ 3) ^ 2
```

前面都抵消掉，最后只剩：

```text
2
```

所以答案是 `2`。

### 为什么代码里常写成“下标异或值”
一种常见写法是：

- 先把 `ans` 初始化为 `n`
- 再遍历数组，把每个下标 `i` 和对应值 `nums[i]` 都异或进来

也就是：

```python
ans = n
for i, num in enumerate(nums):
    ans ^= i ^ num
return ans
```

为什么这样等价？

因为这其实正是在异或：

- 所有下标 `0, 1, 2, ..., n - 1`
- 再加上一个 `n`
- 再加上数组中的所有数字

合起来刚好就是：

- `0 ~ n` 这一整套数字
- 再异或数组里的所有数字

所以逻辑完全一样。

### 复杂度分析
- **时间复杂度：** `O(n)`
- **空间复杂度：** `O(1)`

---

## 哪个方法最适合面试

### 最适合面试的方法：方法三（数学求和）或方法四（异或）

这题和 136 稍微不同。

#### 如果面试追求的是：写得快、讲得稳
那 **方法三：数学求和** 往往最适合。

原因是：
- 思路非常直观
- 代码最短
- 时间 `O(n)`、空间 `O(1)`
- 不容易写错

#### 如果面试官明显在考位运算
那 **方法四：异或** 更加对题。

因为它能体现你对异或“抵消”性质的理解，也能和 136 题形成联系。

### 面试里推荐怎么讲
比较稳的一种讲法是：

1. 先说最直接可以排序或用集合
2. 然后指出题目希望做到线性时间、常数空间
3. 再给出数学求和法：完整总和减实际总和
4. 如果想进一步展示位运算能力，再补异或做法

这样会显得你的解法层次很清楚。

---

## 总结

- **方法一：排序后查缺口**
  - 直观
  - 但时间复杂度是 `O(n log n)`

- **方法二：哈希集合**
  - 时间到 `O(n)`
  - 但空间还是 `O(n)`

- **方法三：数学求和**
  - 时间 `O(n)`，空间 `O(1)`
  - 非常适合面试快速作答

- **方法四：位运算异或**
  - 时间 `O(n)`，空间 `O(1)`
  - 更能体现位运算思维

如果是这题单独面试，我会优先写 **数学求和**；如果是在位运算专题里连续追问，我会重点讲 **异或解法**。
