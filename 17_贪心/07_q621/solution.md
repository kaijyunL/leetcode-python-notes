# LeetCode 621 - 任务调度器（Task Scheduler）

## 题意

给定一个任务列表 `tasks`，每个任务用一个大写字母表示。

同一种任务之间必须间隔至少 `n` 个单位时间。

每个单位时间里，CPU 可以做两件事之一：

- 执行一个任务
- 空闲 `idle`

要求：

> **完成所有任务所需的最短时间。**

---

## 样例先理解

例如：

```text
tasks = ["A", "A", "A", "B", "B", "B"]
n = 2
```

同一种任务之间必须隔开 `2` 个单位。

一种合法安排是：

```text
A B idle A B idle A B
```

长度是 `8`。

为什么中间必须有 `idle`？

因为 `A` 有 3 个，两个 `A` 之间至少要隔 `2` 个位置。

如果只看 `A`，它们至少要长这样：

```text
A _ _ A _ _ A
```

这已经形成了两个空槽：

```text
A [ _ _ ] A [ _ _ ] A
```

`B` 可以填进去：

```text
A [ B _ ] A [ B _ ] A
```

还剩两个空位填不了别的任务，所以只能 idle：

```text
A B idle A B idle A
```

最后还有一个 `B` 可以放在末尾：

```text
A B idle A B idle A B
```

答案是 `8`。

---

## 先把题目换个说法

这题真正限制我们的，不是任务种类多，而是：

> **出现次数最多的任务，会强迫整体时间轴拉长。**

比如 `A` 出现了 4 次，`n = 2`。

只看 `A`，最少也要摆成：

```text
A _ _ A _ _ A _ _ A
```

前 3 个 `A` 后面都要留出长度为 `n` 的冷却区。

所以出现次数最多的任务，是整个调度的骨架。

其它任务能填进这些空位，就不会增加总时间。

如果填不满，就会出现 idle。

如果任务很多，空位不够填，答案就至少是任务总数 `len(tasks)`。

---

## 方法一：最大堆模拟调度过程

对应文件：

```text
17_贪心/07_q621/solution_1_heap_simulation.py
```

### 思路

每个时间点，都优先执行当前剩余次数最多、并且不在冷却中的任务。

这个思路很直觉：

> **次数越多的任务越难安排，应该越早处理。**

为了实现它，用两个结构：

- 最大堆 `heap`：保存当前可以执行的任务剩余次数
- 队列 `cooldown`：保存正在冷却的任务，以及它什么时候可以重新进入堆

Python 只有最小堆，所以用负数模拟最大堆。

### 代码里几个变量

- `time`：当前已经过去的时间
- `heap`：可以立刻执行的任务，里面存负数次数
- `cooldown`：冷却队列，元素是 `(ready_time, count)`

其中：

```text
ready_time
```

表示这个任务下一次可以被执行的时间。

如果某任务在时间 `time` 被执行，并且冷却时间是 `n`，那它下一次最早可以在：

```text
time + n + 1
```

再次执行。

例如 `n = 2`：

```text
时间 1 执行 A
时间 2 和 3 不能执行 A
时间 4 才能再次执行 A
```

所以是 `1 + 2 + 1 = 4`。

### 整个流程

1. 统计每种任务出现次数
2. 把所有次数放进最大堆
3. 当 `heap` 或 `cooldown` 还有任务时，不断推进时间
4. 每个时间点先把冷却结束的任务放回堆
5. 如果堆里有可执行任务，就执行剩余次数最多的那个
6. 如果它还有剩余次数，就放入冷却队列
7. 如果堆为空但冷却队列不空，这个时间点就是 idle

### 为什么可行

每一步选剩余次数最多的可执行任务，是为了优先消耗最难安排的任务。

冷却队列保证了同一种任务不会在 `n` 个单位时间内重复执行。

所以这个方法是对调度过程的直接模拟。

### 复杂度

设任务数量为 `m`，任务种类数为 `k`。

- 时间复杂度：`O(T log k)`，`T` 是最终调度长度
- 空间复杂度：`O(k)`

在本题里 `k <= 26`。

### 评价

这个方法适合理解“冷却时间”到底怎么运作。

但它不是面试里最简洁的答案，因为题目只要求最短时间，不要求返回具体调度序列。

如果只求长度，可以直接用数学公式。

## 方法二：数学贪心公式

对应文件：

```text
17_贪心/07_q621/solution_2_math_greedy.py
```

### 这是本题最适合面试的方法

先统计每种任务出现次数。

假设最高频任务出现次数是：

```text
max_count
```

比如：

```text
A 出现 4 次
```

那么只看 `A`，它会形成：

```text
A _ _ A _ _ A _ _ A
```

这里有几个完整块？

最后一个 `A` 后面不需要再留冷却区。

所以完整块数量是：

```text
max_count - 1
```

每个完整块长度是：

```text
n + 1
```

因为它包含：

```text
一个高频任务 + n 个冷却位置
```

所以骨架长度至少是：

```text
(max_count - 1) * (n + 1) + 1
```

最后这个 `+ 1` 是最后一个最高频任务。

### 如果最高频任务不止一种

例如：

```text
tasks = ["A", "A", "A", "B", "B", "B"]
n = 2
```

最高频是：

```text
A 出现 3 次
B 出现 3 次
```

这时骨架不是：

```text
A _ _ A _ _ A
```

而应该把同样最高频的任务一起放在最后一列：

```text
A B _ A B _ A B
```

所以如果有 `max_kinds` 种任务都出现了 `max_count` 次，公式最后不是加 `1`，而是加：

```text
max_kinds
```

于是骨架长度是：

```text
(max_count - 1) * (n + 1) + max_kinds
```

### 为什么还要和 `len(tasks)` 取最大值

公式算的是：

> **最高频任务强行撑开的最短骨架长度。**

但如果其它任务非常多，完全可以把这些冷却空位填满，甚至还会把时间轴继续往后排。

例如：

```text
tasks = ["A", "A", "A", "B", "B", "B", "C", "C", "D", "D"]
n = 2
```

最高频任务骨架可能只有 `8`，但总共有 `10` 个任务。

CPU 每个时间只能执行一个任务，所以答案不可能小于：

```text
len(tasks)
```

因此最终答案是：

```text
max(len(tasks), (max_count - 1) * (n + 1) + max_kinds)
```

### 公式里的变量

- `total_tasks = len(tasks)`：任务总数
- `max_count`：最高频任务出现了多少次
- `max_kinds`：有多少种任务都达到了最高频
- `frame_length`：由最高频任务撑开的骨架长度

代码就是：

```text
frame_length = (max_count - 1) * (n + 1) + max_kinds
answer = max(total_tasks, frame_length)
```

### 用样例走一遍

```text
tasks = ["A", "A", "A", "B", "B", "B"]
n = 2
```

统计：

```text
A -> 3
B -> 3
```

所以：

```text
max_count = 3
max_kinds = 2
```

套公式：

```text
frame_length = (3 - 1) * (2 + 1) + 2
             = 2 * 3 + 2
             = 8
```

任务总数是：

```text
len(tasks) = 6
```

所以：

```text
answer = max(6, 8) = 8
```

### 再看一个没有 idle 的例子

```text
tasks = ["A", "A", "A", "B", "B", "B", "C", "C", "D", "D"]
n = 2
```

统计：

```text
A -> 3
B -> 3
C -> 2
D -> 2
```

公式骨架：

```text
(3 - 1) * (2 + 1) + 2 = 8
```

但任务总数是 `10`。

因为其它任务足够多，可以把冷却空位填满，所以答案是：

```text
max(10, 8) = 10
```

### 复杂度

- 时间复杂度：`O(m)`
- 空间复杂度：`O(1)`

这里 `m` 是任务数量，空间复杂度按 26 个大写字母看作常数。

### 为什么它最适合面试

因为题目只问最短时间，不问具体执行顺序。

数学贪心公式直接抓住了限制答案的核心：

> **最高频任务决定最少需要多少冷却槽，其它任务只是在填槽。**

相比堆模拟，它代码更短、复杂度更低，也更容易在面试里快速写完。

### 面试里怎么讲最顺

你可以直接这样说：

> 我先统计每种任务的频率。出现次数最多的任务会决定时间轴的下限。假设最高频是 `max_count`，那它会形成 `max_count - 1` 个完整间隔块，每个块长度是 `n + 1`。如果有多个任务都达到最高频，它们会一起占据最后一组位置，所以骨架长度是 `(max_count - 1) * (n + 1) + max_kinds`。不过如果任务总数本身更多，说明其它任务可以填满所有 idle，答案至少是 `len(tasks)`，所以最终取两者最大值。

## 哪个方法最适合面试

### 结论

**方法二：数学贪心公式。**

### 原因

- 它直接返回最短时间，不需要真的模拟调度
- 时间复杂度更优，代码更短
- 核心解释清楚后，边界也很好处理
- 高频任务、多最高频任务、无 idle 三种情况都能覆盖

如果面试官要求输出实际调度序列，再考虑方法一的堆模拟。

---

## 总结

这题最关键的是抓住最高频任务：

1. **最高频任务会撑开时间轴**
2. **其它任务优先填进冷却空位**
3. **如果其它任务足够多，答案就是任务总数**
4. **如果填不满，答案就是最高频任务撑开的骨架长度**

两种方法的递进关系：

1. **最大堆模拟**：按时间线真实模拟任务执行和冷却，适合理解过程
2. **数学贪心公式**：只计算最短长度，是面试首选
