# 55. Jump Game

## 题目理解

给你一个非负整数数组 `nums`，你一开始站在下标 `0`。

数组里的每个元素 `nums[i]` 表示：

- 站在位置 `i` 时
- 最多可以向右跳 `nums[i]` 步

你需要判断：**是否能到达最后一个下标。**

例如：

- `nums = [2,3,1,1,4]`，答案是 `True`
  - 从下标 `0` 最多跳 `2` 步
  - 可以跳到下标 `1`
  - 再从下标 `1` 跳到最后
- `nums = [3,2,1,0,4]`，答案是 `False`
  - 你虽然前面能走一段
  - 但会卡在下标 `3`
  - 因为 `nums[3] = 0`，后面再也过不去

这道题最关键的不是“具体怎么跳”，而是：

> **到当前位置之前，我们最远能到哪里？**

如果某个位置你根本到不了，那它后面的跳跃能力再强也没意义。

---

## 方法一：动态规划（从右往左判断）

### 思路

先从一个比较直观、但没那么快的角度来想。

定义：

```text
good[i] = 从位置 i 出发，是否能到达最后一个下标
```

那么最后一个位置一定是好位置：

```text
good[n - 1] = True
```

接着从右往左看每个位置 `i`：

- 从 `i` 最远可以跳到 `i + nums[i]`
- 只要这个范围里存在某个 `j` 满足 `good[j] = True`
- 那么 `good[i]` 也应该是 `True`

也就是：

```text
good[i] = 是否存在 j ∈ [i + 1, i + nums[i]]，使得 good[j] = True
```

最后只要看 `good[0]` 即可。

### 代码

```python
class Solution:
    def canJump(self, nums: list[int]) -> bool:
        n = len(nums)
        good = [False] * n
        good[-1] = True

        for i in range(n - 2, -1, -1):
            farthest = min(n - 1, i + nums[i])
            for j in range(i + 1, farthest + 1):
                if good[j]:
                    good[i] = True
                    break

        return good[0]
```

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(n)`

### 评价

这个方法的优点是：

- 很容易把“能否到终点”写成状态
- 能帮助你理解这题的递推关系

但问题也明显：

- 每个位置都可能往后扫很多格
- 存在不少重复检查

所以它适合作为**理解型过渡方法**，但不是最优解。

## 方法二：贪心维护最远可达位置（最优解）

### 思路

这题真正的突破口是：

> 我们其实不需要知道“具体跳哪一步”，只需要知道“当前最远能到哪”。

定义一个变量：

```text
farthest = 遍历到当前位置之前，最远能到达的下标
```

从左到右遍历数组。

当来到位置 `i` 时，只有两种情况：

#### 情况一：`i > farthest`

说明当前位置根本到不了。

既然连 `i` 都到不了，那后面的任何位置更不可能通过它到达，直接返回 `False`。

#### 情况二：`i <= farthest`

说明当前位置是可达的。

那我们就可以利用这里的跳跃能力，更新最远可达位置：

```text
farthest = max(farthest, i + nums[i])
```

如果某一时刻：

```text
farthest >= n - 1
```

就表示最后一个下标已经可达，可以直接返回 `True`。

### 为什么这个贪心是对的

因为对这道题来说，某个位置是否值得关心，只取决于：

- 它能不能到达
- 到达之后能把“最远可达边界”推进到哪里

而“具体是从哪条路径来到这里”的信息，并不会影响后续结果。

所以我们只保留最重要的全局信息：

```text
当前能覆盖到的最右边界
```

这就是贪心成立的原因。

### 代码

```python
class Solution:
    def canJump(self, nums: list[int]) -> bool:
        farthest = 0

        for i, step in enumerate(nums):
            if i > farthest:
                return False

            farthest = max(farthest, i + step)
            if farthest >= len(nums) - 1:
                return True

        return True
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

### 评价

这是这道题最常见、最适合面试的写法。

优点：

- 只遍历一遍
- 不需要额外数组
- 正确性很好解释
- 代码短，现场手写稳定

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，贪心维护最远可达位置。**

### 为什么它最适合面试

这道题面试时，面试官通常想看你是否能识别出：

- 它不是最短路径问题
- 也不需要真的把所有跳法枚举出来
- 关键在于维护“可达范围”

如果你上来先说：

1. 我可以用 DP 判断每个位置能不能到终点
2. 但这样会重复扫描很多区间
3. 进一步观察会发现，只要维护当前最远能到哪就够了

这个递进过程会很自然。

### 面试时推荐怎么讲

你可以这样讲：

> 我从左到右扫描数组，并维护一个 `farthest`，表示当前最远能到达的下标。如果扫描到某个位置 `i` 时发现 `i > farthest`，说明这个位置根本到不了，那后面也不可能到达，直接返回 `False`。否则我就用 `i + nums[i]` 去更新 `farthest`。如果最后 `farthest` 能覆盖到最后一个下标，就说明答案是 `True`。

这套说法很短，但逻辑是完整的。

### 面试最推荐代码

```python
class Solution:
    def canJump(self, nums: list[int]) -> bool:
        farthest = 0

        for i, step in enumerate(nums):
            if i > farthest:
                return False
            farthest = max(farthest, i + step)

        return True
```

上面这版和前面的最优代码本质一样，只是把“提前返回 `True`”省掉了，表达更紧凑。

---

## 总结

### 递进关系

1. **动态规划**
   - 定义 `good[i]` 表示从 `i` 能否到终点
   - 容易理解，但会重复扫描

2. **贪心维护最远可达位置**
   - 不关心具体路径
   - 只关心当前可达边界能否持续向右推进
   - 是本题最优、最推荐的解法

### 一句话记忆

> **一路维护“最远能到哪”，一旦当前位置已经超出这个边界，就说明走不到终点。**
