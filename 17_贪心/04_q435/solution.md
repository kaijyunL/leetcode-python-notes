# LeetCode 435 - 无重叠区间（Non-overlapping Intervals）

## 题意

给定若干区间 `intervals`，其中每个区间是 `[start, end]`。

要求你移除最少数量的区间，使剩下的区间互不重叠，返回最少移除数量。

这题里：

- 如果两个区间只是边界接上，比如 `[1, 2]` 和 `[2, 3]`
- 这 **不算重叠**，可以同时保留

---

## 样例先理解

例如：

```text
intervals = [[1, 2], [2, 3], [3, 4], [1, 3]]
```

这 4 个区间里：

- `[1, 2]`
- `[2, 3]`
- `[3, 4]`

这 3 个可以一起留下，因为它们首尾相接但没有重叠。

问题出在 `[1, 3]`：

- 它和 `[1, 2]` 重叠
- 它也和 `[2, 3]` 重叠

所以最少删掉 1 个区间就够了，答案是 `1`。

---

## 先把题目换个说法

题目问的是：

> **最少删除多少个区间，才能让剩下的区间互不重叠。**

这个说法可以直接换成：

> **最多能保留多少个互不重叠的区间。**

因为：

```text
最少移除数量 = 区间总数 - 最多可保留数量
```

这个转化非常重要。

后面不管是 `DP` 还是贪心，核心其实都在想：

> **怎样保留尽可能多的不重叠区间。**

---

## 方法一：DP 求最多能保留多少个区间

对应文件：

```text
17_贪心/04_q435/solution_1_dp.py
```

### 思路

先按左端点排序。

然后定义：

- `dp[i]`：以 `intervals[i]` 作为最后一个区间时，最多能保留多少个互不重叠区间

对于每个 `i`，去看前面的每个 `j`：

- 如果 `intervals[j][1] <= intervals[i][0]`
- 说明 `j` 可以接在 `i` 前面
- 那就可以尝试：

```text
dp[i] = max(dp[i], dp[j] + 1)
```

最后：

- `max(dp)` 是最多能保留的区间数
- 答案就是 `n - max(dp)`

### 为什么可行

因为它把问题变成了：

> 枚举“最后一个保留的区间是谁”，再从前面找所有能接上的情况。

这是很标准的“前面状态转移到后面”写法。

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(n)`

### 问题在哪里

它会做很多重复比较。

每个区间都要回头看前面所有区间，规模一大就慢。

所以关键是：

> **能不能不把前面所有区间都比较一遍，而是直接知道“该保留谁”。**

---

## 从重叠里提炼一个关键观察

假设当前有两个重叠区间：

```text
[a, b]
[c, d]
```

而且它们发生了重叠。

这时如果你只能留下一个，应该留谁？

答案是：

> **留下右端点更小的那个。**

### 为什么

因为右端点更小，代表它结束得更早。

结束得越早，后面能接上的新区间就越多。

举个最直接的例子：

```text
[1, 100]
[2, 3]
```

如果它们重叠：

- 留 `[1, 100]`，后面几乎什么都接不上
- 留 `[2, 3]`，后面还有很多空间

所以：

> **一旦发生重叠，保留结束更早的区间，一定更不吃亏。**

这个结论一出来，贪心就成立了。

## 方法二：按起点排序，重叠时删右端更大的

对应文件：

```text
17_贪心/04_q435/solution_2_greedy_keep_shorter.py
```

### 思路

先按左端点排序。

然后从左到右扫，用：

- `prev_end`：当前保留下来的最后一个区间的右端点
- `remove_count`：已经移除了多少个区间

接着看当前区间 `[start, end]`：

#### 情况一：不重叠

如果：

```text
start >= prev_end
```

说明它可以直接接在前一个保留区间后面。

那就保留它，并更新：

```text
prev_end = end
```

#### 情况二：发生重叠

如果：

```text
start < prev_end
```

说明当前区间和前一个保留区间重叠了。

这时必须删掉一个，所以：

```text
remove_count += 1
```

删谁更合适？

根据上面的关键观察：

> **应该保留右端点更小的那个。**

所以更新成：

```text
prev_end = min(prev_end, end)
```

含义是：

- 如果当前区间更短，就丢掉前一个，留下当前这个
- 如果前一个结束更早，就丢掉当前这个，继续保留前一个

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：`O(1)`

### 评价

这个写法很贴题意，因为它直接在做“删哪个”。

但它有个小地方容易卡一下：

```text
prev_end = min(prev_end, end)
```

第一次写这题时，有些人会在这里想一下。

## 方法三：按右端排序，统计最多能保留多少个区间

对应文件：

```text
17_贪心/04_q435/solution_3_greedy_by_end.py
```

### 这是本题最适合面试的方法

这版直接站在“最多保留多少个区间”的角度来做。

先按右端点从小到大排序。

然后维护两个量：

- `keep_count`：当前最多保留了多少个不重叠区间
- `prev_end`：最后一个被保留下来的区间的右端点

### 为什么按右端点排序最关键

因为我们已经知道：

> **如果多个区间发生重叠，优先保留结束更早的那个。**

那最直接的做法就是：

> **干脆一开始就按结束时间从早到晚排。**

这样每次只要发现一个新区间能接上，就立刻保留它。

因为当前这个区间已经是“目前能选到的结束最早的区间”了。

### 整个流程

先排序：

```text
按 end 从小到大排序
```

然后：

1. 先保留第一个区间
2. 从第二个区间开始往后扫
3. 如果当前区间的 `start >= prev_end`
   - 说明不重叠
   - 可以保留
   - `keep_count += 1`
   - `prev_end = end`
4. 如果 `start < prev_end`
   - 说明重叠
   - 直接跳过当前区间
   - 因为当前已经保留的是结束更早的那个，不需要换

最后答案：

```text
len(intervals) - keep_count
```

### 用样例走一遍

样例：

```text
intervals = [[1, 2], [2, 3], [3, 4], [1, 3]]
```

先按右端点排序：

```text
[1, 2], [2, 3], [1, 3], [3, 4]
```

初始：

```text
keep_count = 1
prev_end = 2
```

继续往后看：

- `[2, 3]`：`2 >= 2`，不重叠，保留
  - `keep_count = 2`
  - `prev_end = 3`
- `[1, 3]`：`1 < 3`，重叠，跳过
- `[3, 4]`：`3 >= 3`，不重叠，保留
  - `keep_count = 3`
  - `prev_end = 4`

最后：

```text
总数 4 - 保留 3 = 移除 1
```

答案就是 `1`。

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：`O(1)`

### 为什么它最适合面试

因为它有 3 个优点：

1. **变量少**：只需要 `keep_count` 和 `prev_end`
2. **不容易写错**：重叠时直接跳过，不用写 `min(...)`
3. **证明顺**：核心就一句话——想保留更多区间，就优先保留结束更早的区间

### 面试里怎么讲最顺

你可以直接这样说：

> 这题可以转成“最多保留多少个互不重叠区间”。一旦两个区间重叠，应该优先保留结束更早的那个，因为它给后面留下的空间更大。所以我先按右端点排序，再从左到右扫描；如果当前区间能接在前一个保留区间后面，我就把它留下。最后用总数减去保留数，就是最少移除数。

---

## 哪个方法最适合面试

### 结论

**方法三：按右端排序的贪心。**

### 原因

- 它是经典区间调度写法，面试官最容易听懂
- 代码短，边界简单
- 证明主线清楚：**结束越早，越给后面留空间**
- 不需要在重叠时额外比较保留谁，写起来更稳

---

## 总结

这题最关键的不是记住“区间贪心”四个字，而是记住下面这句：

> **如果发生重叠，就优先保留右端点更小的那个。**

三种方法的递进关系：

1. **DP**：先求最多能保留多少个不重叠区间
2. **按起点排序的贪心**：重叠时删右端更大的，直接按题意做
3. **按右端排序的贪心**：经典写法，也是最适合面试的方法
