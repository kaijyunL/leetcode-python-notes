# LeetCode 763 - 划分字母区间（Partition Labels）

## 题意

给定一个字符串 `s`，要求把它划分成尽可能多的片段，并且满足：

> **同一个字母最多只能出现在一个片段里。**

最后返回每个片段的长度。

换句话说，如果某个字母已经被放进了一个片段，那么这个字母在字符串里的所有出现位置，都必须被这个片段包含。

---

## 样例先理解

例如：

```text
s = "ababcbacadefegdehijhklij"
```

答案是：

```text
[9, 7, 8]
```

对应划分：

```text
"ababcbaca" | "defegde" | "hijhklij"
```

为什么第一个片段必须到下标 `8`？

看第一个字符 `a`：

```text
a 最后一次出现在下标 8
```

所以只要片段里包含了开头这个 `a`，这个片段至少要覆盖到下标 `8`。

但在 `0 ~ 8` 这个过程中，我们又遇到了 `b` 和 `c`：

- `b` 最后一次出现在下标 `5`
- `c` 最后一次出现在下标 `7`

它们都没有超过 `8`，所以第一个片段可以在 `8` 结束。

也就是：

```text
下标: 0 1 2 3 4 5 6 7 8
字符: a b a b c b a c a
```

到下标 `8` 时，当前片段里出现过的所有字母都已经收完了，所以可以切一刀。

---

## 先把题目换个说法

这题表面上是字符串划分，实际是在问：

> **每个字符要求覆盖一段区间，怎样把这些区间合并成最小的几个互不相交片段。**

比如字符 `a`：

```text
a 出现在 0, 2, 6, 8
```

那只要某个片段包含 `a`，它就必须覆盖：

```text
[0, 8]
```

字符 `b` 出现在：

```text
1, 3, 5
```

它对应区间：

```text
[1, 5]
```

因为 `[0, 8]` 和 `[1, 5]` 有重叠，所以它们必须放在同一个片段里。

所以这题可以先理解成：

> **把每个字符的首尾区间拿出来，然后合并所有重叠区间。**

---

## 方法一：字符区间合并

对应文件：

```text
17_贪心/06_q763/solution_1_interval_merge.py
```

### 思路

先记录每个字符第一次出现和最后一次出现的位置。

例如：

```text
s = "ababcbaca"
```

得到：

```text
a -> [0, 8]
b -> [1, 5]
c -> [4, 7]
```

这些区间有重叠，所以最终会合并成：

```text
[0, 8]
```

片段长度就是：

```text
8 - 0 + 1 = 9
```

### 整个流程

1. 遍历字符串，记录每个字符的首尾位置
2. 把所有字符区间取出来
3. 按区间起点排序
4. 从左到右合并重叠区间
5. 每合并出一个最终区间，就把长度加入答案

### 为什么可行

因为一个字符只能出现在一个片段里。

所以对于每个字符来说，它第一次出现到最后一次出现的整段范围，必须被同一个片段完整包含。

如果两个字符对应的范围有重叠，它们就不能被分到两个片段里，只能继续合并。

最终合并出来的每个区间，就是一个合法片段。

### 复杂度

设字符串长度为 `n`，字符种类数为 `k`。

- 时间复杂度：`O(n + k log k)`
- 空间复杂度：`O(k)`

在本题里字符是小写英文字母，所以 `k <= 26`，可以认为排序部分是常数级。

### 评价

这个方法非常适合用来理解题意。

它把“字符不能跨片段出现”翻译成了“字符的首尾区间必须被同一段包含”。

但面试时还有更短的一次扫描写法。

## 方法二：一次扫描维护当前片段的最远边界

对应文件：

```text
17_贪心/06_q763/solution_2_greedy.py
```

### 这是本题最适合面试的方法

方法一里，我们先显式构造了每个字符的区间，再合并区间。

但其实不需要真的把区间列表建出来。

我们只需要知道：

> **当前片段必须至少延伸到哪里。**

这个位置就是当前片段里所有字符的最后出现位置的最大值。

代码里有两个关键变量：

- `start`：当前片段的起点
- `end`：当前片段必须覆盖到的最远位置

### 整个流程

先记录每个字符最后一次出现的位置：

```text
last[ch] = 字符 ch 最后一次出现的下标
```

然后从左到右扫描字符串。

当扫描到下标 `i`、字符 `ch` 时：

```text
end = max(end, last[ch])
```

意思是：

> 既然当前片段里已经包含了 `ch`，那这个片段至少要覆盖到 `ch` 最后一次出现的位置。

如果某一刻：

```text
i == end
```

说明从 `start` 到 `i` 之间出现过的所有字符，它们的最后一次出现位置都没有超过 `i`。

也就是说：

> **当前片段里的字符已经全部收齐了，可以在这里切开。**

于是把长度加入答案：

```text
i - start + 1
```

然后下一个片段从：

```text
start = i + 1
```

开始。

### 用样例走一遍

```text
s = "ababcbacadefegdehijhklij"
```

先看第一段。

最后出现位置大致是：

```text
a -> 8
b -> 5
c -> 7
```

扫描过程：

```text
i = 0, ch = a, end = max(0, 8) = 8
i = 1, ch = b, end = max(8, 5) = 8
i = 2, ch = a, end = 8
i = 3, ch = b, end = 8
i = 4, ch = c, end = max(8, 7) = 8
...
i = 8, ch = a, i == end
```

到 `i = 8` 时，说明第一段可以结束。

长度是：

```text
8 - 0 + 1 = 9
```

然后从 `9` 开始处理下一段。

### 为什么这样是对的

当前片段从 `start` 开始。

只要我们遇到一个字符 `ch`，这个片段就必须覆盖到 `last[ch]`。

所以 `end` 始终表示：

> **当前片段为了收齐所有已出现字符，最远必须到达的位置。**

如果还没走到 `end`，说明至少有某个字符后面还会再出现，不能切。

如果走到了 `end`，说明当前片段里所有字符的最后位置都已经被覆盖，继续往后切开不会违反题意。

这就是贪心成立的原因：

> **每次能切就立刻切，才能得到尽可能多的片段。**

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这里空间复杂度按 26 个小写字母看作常数。

### 为什么它最适合面试

因为它同时满足三点：

1. **代码短**：两次线性扫描
2. **变量清楚**：`start` 管片段起点，`end` 管必须覆盖到哪里
3. **推导自然**：从字符最后出现位置直接推出切分边界

### 面试里怎么讲最顺

你可以直接这样说：

> 因为同一个字符不能出现在两个片段里，所以一个片段只要包含了某个字符，就必须覆盖到这个字符最后一次出现的位置。我先记录每个字符最后一次出现的位置，然后从左到右扫描，用 `end` 表示当前片段必须覆盖到的最远下标。每遇到一个字符，就用它的最后位置更新 `end`。当当前位置 `i == end` 时，说明当前片段里所有字符都已经收齐，可以切一刀，并记录这个片段长度。

## 哪个方法最适合面试

### 结论

**方法二：一次扫描维护当前片段的最远边界。**

### 原因

- 它是本题最经典的贪心写法
- 不需要显式构造和合并区间
- 边界条件非常清楚：`i == end` 就切
- 能自然解释“为什么每次能切就切”

---

## 总结

这题最关键的是把字符串问题转换成区间边界问题：

1. **一个字符的所有出现位置必须被同一个片段包含**
2. **所以当前片段必须覆盖到所有已出现字符的最后出现位置**
3. **当扫描位置到达这个最远边界时，就可以切开**

两种方法的递进关系：

1. **字符区间合并**：先把每个字符看成一个首尾区间，帮助理解题意
2. **一次扫描贪心**：不显式建区间，只维护当前片段的最远边界，是面试首选
