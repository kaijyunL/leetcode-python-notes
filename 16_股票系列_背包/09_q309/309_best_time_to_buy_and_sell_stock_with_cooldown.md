# 309. Best Time to Buy and Sell Stock with Cooldown

## 题目理解

给你一个数组 `prices`，`prices[i]` 表示第 `i` 天股票的价格。

你可以进行多次交易，但有两个限制：

- 同一时间只能持有 **一股** 股票
- **卖出后的第二天不能买入**，也就是有 1 天冷冻期

例如：

- `prices = [1,2,3,0,2]`，答案是 `3`
  - 第 1 天买入 `1`，第 2 天卖出 `2`，赚 `1`
  - 第 3 天冷冻，不能买
  - 第 4 天买入 `0`，第 5 天卖出 `2`，再赚 `2`
  - 总利润是 `3`
- `prices = [1]`，答案是 `0`
  - 只有一天，根本来不及完成一次买卖
- `prices = [2,1,2,0,1]`，答案是 `1`
  - 这组数据很适合和第 `122` 题对比
  - 如果没有冷冻期，可以赚 `2`
  - 但有冷冻期时，卖掉之后第二天不能立刻再买，所以只能赚 `1`

这题和第 `122` 题看起来很像，都是：

- 可以做很多次交易
- 同一时间只能持有一股

但第 `309` 题多了一个条件：

```text
卖出后的下一天不能买入
```

这个限制会直接破坏第 `122` 题里“把所有正差值都加起来”的贪心结论。

所以这题最关键的不是“还能不能多次交易”，而是：

> **冷冻期让“空仓”这个状态分裂成了两种不同情况。**

也正因为如此，这题非常适合按下面的顺序理解：

```text
暴力递归 -> 记忆化递归 -> 三状态 DP -> 状态压缩 DP
```

---

## 为什么这题不能直接沿用第 122 题的贪心

第 `122` 题可以把所有正差值都加起来，是因为：

- 没有手续费
- 没有冷冻期
- 没有交易次数上限

所以一段连续上涨：

```text
1 -> 2 -> 3 -> 4
```

你可以：

- 第一天买，第四天卖

也可以：

- 第一天买第二天卖
- 第二天买第三天卖
- 第三天买第四天卖

利润完全一样。

但第 `309` 题不行。

比如：

```text
prices = [1, 2, 3, 0, 2]
```

如果你在价格 `3` 那天卖出，下一天价格 `0` 虽然很低，
但你却 **不能立刻买入**。

这说明：

- “今天结束后手里没股票，而且明天可以买”
- “今天结束后手里没股票，但因为今天刚卖过，明天不能买”

这两个状态虽然都叫“空仓”，但下一天的可选操作完全不同。

所以从这题开始，不能再只用“持股 / 空仓”两个状态粗暴处理，
必须把“刚卖出”单独拆出来。

---

## 方法一：暴力递归

### 思路

先完全不写 DP，直接把每天的选择递归出来。

定义：

```text
dfs(day, holding) = 从第 day 天开始，在 holding 持股状态下，后面最多能赚多少钱
```

和第 `122` 题一样，`holding` 表示当前是否持有股票。

区别在于：

- 如果今天卖出，明天不能买
- 所以卖出之后，下一步要直接跳到 `day + 2`

### 情况一：当前没有持股

这时有两种选择：

1. 今天什么都不做，去下一天
2. 今天买入，利润减去 `prices[day]`

所以：

```text
dfs(day, 0) = max(
    dfs(day + 1, 0),
    -prices[day] + dfs(day + 1, 1)
)
```

### 情况二：当前持有股票

这时也有两种选择：

1. 今天继续持有，去下一天
2. 今天卖出，利润加上 `prices[day]`，然后跳过冷冻日

所以：

```text
dfs(day, 1) = max(
    dfs(day + 1, 1),
    prices[day] + dfs(day + 2, 0)
)
```

### 边界

当 `day >= n` 时，后面已经没有天数可用了：

- 如果当前没有持股，后面利润是 `0`
- 如果当前还持股，说明股票没卖掉，这条路径不合法

所以：

```text
dfs(day, 0) = 0          (day >= n)
dfs(day, 1) = -∞         (day >= n)
```

### 代码

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        n = len(prices)

        def dfs(day: int, holding: bool) -> int:
            if day >= n:
                return 0 if not holding else float("-inf")

            best = dfs(day + 1, holding)
            if holding:
                best = max(best, prices[day] + dfs(day + 2, False))
            else:
                best = max(best, -prices[day] + dfs(day + 1, True))

            return best

        return dfs(0, False)
```

### 复杂度

- 时间复杂度：指数级
- 空间复杂度：`O(n)`，主要来自递归深度

### 评价

这个方法的价值在于：

- 把“卖出后要跳过一天”这件事先想清楚
- 让后面的状态定义变得自然

但它会重复计算很多状态，不能作为最终解法。

## 方法二：记忆化递归

### 思路

暴力递归慢，是因为同一个状态会被重复算很多遍。

比如：

```text
dfs(day, holding)
```

只要：

- `day` 相同
- `holding` 相同

后面的最优利润就一定相同。

所以我们可以把已经算过的状态存起来。

状态定义和转移都不变：

```text
dfs(day, 0) = max(dfs(day + 1, 0), -prices[day] + dfs(day + 1, 1))
dfs(day, 1) = max(dfs(day + 1, 1), prices[day] + dfs(day + 2, 0))
```

### 代码

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        n = len(prices)
        memo = {}

        def dfs(day: int, holding: bool) -> int:
            if day >= n:
                return 0 if not holding else float("-inf")

            key = (day, holding)
            if key in memo:
                return memo[key]

            best = dfs(day + 1, holding)
            if holding:
                best = max(best, prices[day] + dfs(day + 2, False))
            else:
                best = max(best, -prices[day] + dfs(day + 1, True))

            memo[key] = best
            return best

        return dfs(0, False)
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 评价

这个方法已经能通过，而且很适合作为“递归 -> DP”的过渡版本。

优点：

- 思路自然
- 冷冻期的影响体现在转移里，非常直观

缺点：

- 还是递归写法
- 面试里一般不如迭代 DP 稳定

## 方法三：三状态 DP（最适合面试）

### 为什么这里不能只写两种状态

在第 `122` 题里，我们可以只区分：

- 持股
- 空仓

因为所有空仓状态，下一天都可以买。

但这题不行。

因为“空仓”至少分成两类：

1. **今天刚卖出**，明天不能买
2. **今天本来就在休息**，明天可以买

它们对下一天的影响不同，所以必须拆开。

### 状态定义

为了和第 `122` 题保持一致，这里继续约定：

```text
0 = 空仓 / 可买
1 = 持股
```

第 `309` 题只是比第 `122` 题多了一个“刚卖出”状态，所以补成：

```text
dp[i][0] = 到第 i 天结束时，手里没股票，且明天可以买的最大利润
dp[i][1] = 到第 i 天结束时，手里持有股票的最大利润
dp[i][2] = 到第 i 天结束时，今天刚卖出股票的最大利润
```

这样记最稳：

```text
先记住 122：0 空仓，1 持股
309 只是额外补一个 2 = 刚卖出
```

这里最关键的是 `dp[i][2]`。

它表示：

```text
今天刚卖掉，所以明天会进入冷冻限制
```

### 第 0 天怎么初始化

第 `0` 天结束时：

- 空仓 / 可买：什么都不做，利润是 `0`
- 持股：说明今天买了，利润是 `-prices[0]`
- 今天刚卖出：不可能，记为 `-∞`

所以：

```text
dp[0][0] = 0
dp[0][1] = -prices[0]
dp[0][2] = -∞
```

### 转移怎么推

#### 1. 空仓 / 可买状态 `dp[i][0]`

今天结束时空仓且明天可以买，有两种来源：

1. 昨天就在空仓 / 可买，今天继续休息
2. 昨天刚卖出，今天冷冻结束，转成可买状态

所以：

```text
dp[i][0] = max(dp[i - 1][0], dp[i - 1][2])
```

#### 2. 持股状态 `dp[i][1]`

今天结束时持股，有两种来源：

1. 昨天就持股，今天继续拿着
2. 昨天处于空仓 / 可买状态，今天买入

注意：

- 不能从“昨天刚卖出”转过来买
- 因为卖出后的第二天是冷冻期

所以：

```text
dp[i][1] = max(dp[i - 1][1], dp[i - 1][0] - prices[i])
```

#### 3. 今天刚卖出 `dp[i][2]`

如果今天刚卖出，那说明昨天必须持有股票，今天把它卖掉：

```text
dp[i][2] = dp[i - 1][1] + prices[i]
```

这里只有这一种来源。

### 为什么这三条转移是最关键的

这三条转移本质上把题目限制完整编码进去了：

- 想买，只能从 `空仓 / 可买` 转到 `持股`
- 想卖，只能从 `持股` 转到 `刚卖出`
- 冷冻结束后，才能从 `刚卖出` 回到 `空仓 / 可买`

也就是说：

```text
空仓 / 可买 -> 持股 -> 刚卖出 -> 空仓 / 可买
```

这就是这题真正的状态机。

### 代码

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        if not prices:
            return 0

        n = len(prices)
        dp = [[0, 0, 0] for _ in range(n)]

        dp[0][0] = 0
        dp[0][1] = -prices[0]
        dp[0][2] = float("-inf")

        for i in range(1, n):
            dp[i][0] = max(dp[i - 1][0], dp[i - 1][2])
            dp[i][1] = max(dp[i - 1][1], dp[i - 1][0] - prices[i])
            dp[i][2] = dp[i - 1][1] + prices[i]

        return max(dp[n - 1][0], dp[n - 1][2])
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 评价

这是我最推荐的面试写法。

优点：

- 冷冻期为什么需要额外状态，讲得最清楚
- 转移关系非常标准
- 很适合继续推广到股票系列其他题

缺点：

- 不是空间最优

但对于面试来说，它的逻辑清晰度通常比省掉这点空间更重要。

## 方法四：状态压缩 DP（最优解）

### 思路

观察方法三会发现：

第 `i` 天只依赖第 `i - 1` 天。

所以我们没必要保存整张 `dp` 表，只需要保留前一天的三个状态：

- `rest`：当天结束时空仓 / 可买
- `hold`：当天结束时持股
- `sold`：当天结束时今天刚卖出

虽然这里不再写数字下标，但语义仍然和方法三一致：

```text
0 = rest（空仓 / 可买）
1 = hold（持股）
2 = sold（刚卖出）
```

初始时：

```text
rest = 0
hold = -prices[0]
sold = -∞
```

每天更新：

```text
new_rest = max(rest, sold)
new_hold = max(hold, rest - price)
new_sold = hold + price
```

这里一定要注意：

- 三个新状态都必须基于“前一天”的状态计算
- 所以更新时要先保存旧值

### 代码

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        if not prices:
            return 0

        rest = 0
        hold = -prices[0]
        sold = float("-inf")

        for price in prices[1:]:
            prev_rest = rest
            prev_hold = hold
            prev_sold = sold

            rest = max(prev_rest, prev_sold)
            hold = max(prev_hold, prev_rest - price)
            sold = prev_hold + price

        return max(rest, sold)
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

### 评价

这是这道题的最优写法。

优点：

- 时间最优
- 空间最优
- 保留了完整状态机含义

缺点：

- 如果前面的三状态意义没讲清楚，这一版容易写对了但说不清

所以它更适合作为：

```text
在方法三讲清楚之后，再给出的优化版
```

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法三，三状态 DP。**

### 原因

#### 方法一：暴力递归

- 适合起步
- 能看清“卖出后跳一天”
- 但会超时

#### 方法二：记忆化递归

- 能通过
- 是递归到 DP 的自然过渡
- 但现场书写一般不如迭代稳

#### 方法三：三状态 DP

- 状态拆分最清楚
- 冷冻期为什么需要额外状态，最容易讲明白
- 很适合面试口述

#### 方法四：状态压缩 DP

- 是最终最优写法
- 但建立在你已经理解三状态含义的基础上

所以综合来看：

> **方法三最稳，方法四最优。**

## 最适合面试的方法：详细讲解

### 1. 先说为什么这题比 122 难

第 `122` 题里，只要手里没股票，下一天就可以买。

但这题不行。

因为如果今天刚卖出，明天会处于冷冻期，
这时虽然手里没股票，但你不能立刻再买。

所以：

```text
空仓 ≠ 同一种状态
```

这是这题最核心的区别。

### 2. 为什么要拆成三种状态

你可以这样讲：

- `hold`：今天结束后手里有股票
- `sold`：今天结束后刚卖掉股票
- `rest`：今天结束后手里没股票，而且明天可以买

这里最关键的是 `sold` 和 `rest` 的区别。

它们都没有股票，但：

- `sold` 说明明天还受冷冻限制
- `rest` 说明明天已经可以正常买入

如果不把这两个状态分开，转移就会写乱。

### 3. 为什么 `hold` 只能从 `rest` 转过来

因为买入动作不能紧跟着卖出发生。

也就是说：

- 昨天如果是 `sold`，今天处于冷冻期
- 今天不能买

所以持股状态只能来自：

```text
昨天已经持股
或者
昨天处于空仓 / 可买，今天买入
```

这就是：

```text
dp[i][1] = max(dp[i - 1][1], dp[i - 1][0] - prices[i])
```

### 4. 为什么答案不是 `dp[n - 1][1]`

因为 `dp[n - 1][1]` 表示最后一天结束时还持有股票。

这意味着：

```text
股票还没卖掉
```

显然不是最优结果。

所以最终答案应该取：

- 最后一天处于空仓 / 可买状态
- 或最后一天刚卖出

也就是：

```text
max(dp[n - 1][0], dp[n - 1][2])
```

### 5. 面试时推荐怎么讲

你可以这样说：

> 这题和第 122 题最大的区别是卖出后有一天冷冻期，所以“空仓”不能再只看成一种状态，而要拆成“今天刚卖出”和“已经休息可买”两种。于是我定义三状态 DP：持股、刚卖出、休息。买入只能从休息转来，卖出只能从持股转来，冷冻结束后刚卖出才能转成休息。这样就能完整表达题目的限制。

这套讲法通常很稳，也很容易让面试官看出你是真的理解了冷冻期的影响。

### 面试最推荐代码

```python
class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        if not prices:
            return 0

        n = len(prices)
        dp = [[0, 0, 0] for _ in range(n)]

        dp[0][0] = 0
        dp[0][1] = -prices[0]
        dp[0][2] = float("-inf")

        for i in range(1, n):
            dp[i][0] = max(dp[i - 1][0], dp[i - 1][2])
            dp[i][1] = max(dp[i - 1][1], dp[i - 1][0] - prices[i])
            dp[i][2] = dp[i - 1][1] + prices[i]

        return max(dp[n - 1][0], dp[n - 1][2])
```

## 总结

### 递进关系

1. **暴力递归**
   - 先把“卖出后要跳过一天”写清楚
   - 是最原始的决策树

2. **记忆化递归**
   - 去掉重复状态
   - 从搜索平滑过渡到 DP

3. **三状态 DP**
   - 把冷冻期影响完整编码成状态机
   - 最适合面试讲解

4. **状态压缩 DP**
   - 只保留前一天的三个状态
   - 是最终最优写法

### 一句话记忆

> **第 309 题的记法，直接沿用第 122 题：`0 = 空仓 / 可买`，`1 = 持股`，再额外补一个 `2 = 刚卖出` 来表达冷冻期。**
