# 322. Coin Change

## 题目理解

给你一个整数数组 `coins`，表示不同面额的硬币；再给你一个整数 `amount`，表示总金额。

每种硬币都可以使用无限次。

你需要返回：

> 凑出总金额 `amount` 所需要的最少硬币个数。

如果无论怎么选都凑不出来，返回 `-1`。

例如：

```text
coins = [1, 2, 5], amount = 11
11 = 5 + 5 + 1
答案是 3
```

```text
coins = [2], amount = 3
凑不出来
答案是 -1
```

这道题是非常经典的一维 DP / 完全背包题。

如果按学习路径来走，最适合这样理解：

```text
暴力递归 -> 记忆化递归 -> 动态规划
```

---

## 为什么这题适合这样学

这题最容易卡住的点，不是代码本身，而是：

- 状态怎么定义
- 为什么转移是对的
- 为什么最后是完全背包

所以不建议一上来就死记 DP 模板，而是先从最直观的暴力递归出发。

这样你会很清楚地看到：

1. 最初的问题是什么
2. 重复子问题出现在哪里
3. 为什么记忆化能优化
4. 为什么最后能自然落到一维 DP

---

## 方法一：暴力递归

### 思路

先从最直观的想法开始。

如果现在还剩 `remain` 钱没有凑出来，那么下一步可以尝试选任意一种硬币：

- 选 `1`
- 选 `2`
- 选 `5`
- ...

选了某个硬币 `coin` 之后，问题就变成：

```text
还需要凑 remain - coin
```

所以可以定义：

```text
dfs(remain) = 凑出 remain 所需的最少硬币数
```

那么转移就是：

```text
dfs(remain) = min(dfs(remain - coin) + 1)
```

其中 `coin` 遍历所有面额。

### 边界

```text
remain == 0  -> 已经凑好了，返回 0
remain < 0   -> 这条路走不通，返回无穷大
```

这里返回“无穷大”是为了后面 `min(...)` 时自然过滤掉非法方案。

### 代码

```python
from typing import List


# 方法一：暴力递归
class Solution:
    def coinChange(self, coins: List[int], amount: int) -> int:
        def dfs(remain: int) -> int:
            if remain == 0:
                return 0
            if remain < 0:
                return float("inf")

            best = float("inf")
            for coin in coins:
                best = min(best, dfs(remain - coin) + 1)

            return best

        answer = dfs(amount)
        return -1 if answer == float("inf") else answer
```

### 复杂度

- 时间复杂度：指数级，非常慢
- 空间复杂度：`O(amount)`，主要是递归栈深度

### 评价

这个方法的价值主要在于：

- 帮你把状态定义想清楚
- 帮你把“最后一步/下一步怎么选”想清楚

但它不能作为最终解法，因为会重复计算大量子问题。

## 方法二：记忆化递归

### 思路

暴力递归为什么慢？

因为同一个 `remain` 会被反复计算很多次。

比如：

```text
coins = [1, 2, 5], amount = 11
```

你从 11 往下递归时，像 `dfs(6)`、`dfs(4)`、`dfs(1)` 这类状态，会从很多不同路径重复来到。

那就很自然：

> 已经算过的 `dfs(remain)`，直接存起来，下次不要重复算。

于是加一个 `memo` 字典：

- 如果 `remain` 已经算过，直接返回
- 如果没算过，再去递归求值

### 代码

```python
from typing import List


# 方法二：记忆化递归
class Solution:
    def coinChange(self, coins: List[int], amount: int) -> int:
        memo = {}

        def dfs(remain: int) -> int:
            if remain == 0:
                return 0
            if remain < 0:
                return float("inf")
            if remain in memo:
                return memo[remain]

            best = float("inf")
            for coin in coins:
                best = min(best, dfs(remain - coin) + 1)

            memo[remain] = best
            return best

        answer = dfs(amount)
        return -1 if answer == float("inf") else answer
```

### 复杂度

- 时间复杂度：`O(amount * len(coins))`
- 空间复杂度：`O(amount)`

### 评价

这个方法已经能通过，而且从暴力递归升级过来非常自然。

优点：

- 思路直观
- 转移关系清晰
- 很适合理解“状态复用”

缺点：

- 还是递归写法
- 面试里通常不如迭代 DP 稳定

## 方法三：动态规划（最适合面试）

### 为什么这个最适合面试

这是这题最推荐的标准答案。

原因有 4 个：

1. 复杂度好：`O(amount * len(coins))`
2. 没有递归，写法稳定
3. 和完全背包模型完全一致
4. 状态、转移、边界都非常容易讲清楚

所以如果面试里只准备一个最终答案，优先准备这个。

---

### 第一步：定义状态

定义：

```text
dp[x] = 凑出金额 x 所需的最少硬币数
```

我们的目标就是：

```text
dp[amount]
```

这个定义非常直接，因为题目问的就是“凑出某个金额的最少硬币数”。

---

### 第二步：想最后一步

如果我们要求 `dp[x]`，那么最后一枚硬币可能是：

- `1`
- `2`
- `5`
- ...

假设最后一枚选的是 `coin`，那么在选它之前，前面必须已经凑出了：

```text
x - coin
```

如果凑出 `x - coin` 的最优答案是 `dp[x - coin]`，那么再加上当前这枚硬币，总硬币数就是：

```text
dp[x - coin] + 1
```

于是转移就来了：

```text
dp[x] = min(dp[x], dp[x - coin] + 1)
```

前提是：

```text
coin <= x
```

因为金额不能减成负数。

---

### 第三步：边界怎么定

最核心的边界是：

```text
dp[0] = 0
```

因为凑出 0 元，不需要任何硬币。

其余位置先初始化成一个“不可能的很大值”，例如：

```text
amount + 1
```

为什么可以这样设？

因为就算最差情况，只要 `coins` 里有 `1`，最多也只会用 `amount` 枚硬币；
如果没有 `1`，那一些状态本来就不可达，用 `amount + 1` 作为“无穷大”也很方便。

所以初始化为：

```text
dp = [0] + [amount + 1] * amount
```

---

### 第四步：用例子走一遍

以：

```text
coins = [1, 2, 5], amount = 11
```

为例。

初始化后：

```text
dp[0] = 0
其余位置先是 12
```

接着从小到大更新：

- `dp[1] = 1`，因为 `1 = 1`
- `dp[2] = 1`，因为 `2 = 2`
- `dp[3] = 2`，因为 `3 = 1 + 2`
- `dp[5] = 1`，因为 `5 = 5`
- `dp[10] = 2`，因为 `10 = 5 + 5`
- `dp[11] = 3`，因为 `11 = 5 + 5 + 1`

最后答案就是：

```text
3
```

---

### 第五步：为什么这其实就是完全背包

这题本质上就是完全背包：

- 物品：不同面额的硬币
- 每种物品：可以无限次使用
- 背包容量：`amount`
- 目标：恰好凑出 `amount`
- 优化目标：所用硬币个数最少

所以这是一个非常标准的：

> 完全背包中“凑出目标值的最少物品数”问题。

这句话在面试里说出来，会很加分。

---

### 代码

```python
from typing import List


# 方法三：动态规划
class Solution:
    def coinChange(self, coins: List[int], amount: int) -> int:
        dp = [0] + [amount + 1] * amount

        for total in range(1, amount + 1):
            for coin in coins:
                if coin <= total:
                    dp[total] = min(dp[total], dp[total - coin] + 1)

        return -1 if dp[amount] == amount + 1 else dp[amount]
```

### 复杂度

- 时间复杂度：`O(amount * len(coins))`
- 空间复杂度：`O(amount)`

---

### 面试时推荐怎么讲

你可以这样讲：

#### 1. 先定义状态

```text
dp[x] 表示凑出金额 x 所需的最少硬币数
```

#### 2. 再解释最后一步

要凑出 `x`，最后一枚硬币可以是任意一个 `coin`。

如果最后选了 `coin`，那前面必须已经凑出 `x - coin`。

#### 3. 写出转移

```text
dp[x] = min(dp[x], dp[x - coin] + 1)
```

#### 4. 说明边界

```text
dp[0] = 0
```

#### 5. 最后补一句模型归类

这是一个标准的完全背包最少物品数问题。

这套讲法非常稳，而且逻辑很完整。

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法三，动态规划。**

### 原因

#### 方法一：暴力递归

- 只能帮助推导状态
- 会超时
- 不能作为最终答案

#### 方法二：记忆化递归

- 可以通过
- 思路也很自然
- 但递归写法在面试里通常没有迭代 DP 稳

#### 方法三：动态规划

- 复杂度最优级别
- 写法清晰
- 非常好讲
- 还能自然归到完全背包

所以综合来看：

> **方法三最稳，最标准，也最适合作为面试答案。**

## 最适合面试的方法：详细讲解

### 1. 这题到底在求什么

题目要的不是“能不能凑出来”，而是：

```text
最少用多少枚硬币能凑出 amount
```

所以状态里必须体现“最少枚数”。

这就是为什么定义成：

```text
dp[x] = 凑出 x 的最少硬币数
```

而不是定义成 `True/False`。

---

### 2. 为什么要枚举最后一枚硬币

DP 最常见的思路之一，就是想：

> 最后一步发生了什么？

对于金额 `x`，最后一步一定是放进了一枚硬币。

这枚硬币可以是 `coins` 中的任意一个 `coin`。

一旦最后一枚硬币确定了，那么前面的子问题就唯一确定为：

```text
x - coin
```

所以这题最自然的转移，就是从“最后一枚硬币”来拆。

---

### 3. 为什么转移一定正确

因为任意一个合法方案，最后总会有一枚硬币。

而我们在转移时，把所有可能的最后一枚硬币都枚举了一遍：

```text
coin in coins
```

也就是说：

- 所有合法方案都不会漏
- 每个方案都会对应到某个 `dp[x - coin] + 1`
- 再取最小值，自然就是最优解

这是这道题最关键的正确性来源。

---

### 4. 为什么初始化要用 `amount + 1`

因为我们需要一个“足够大”的值表示当前不可达。

`amount + 1` 很合适，原因是：

- 如果一个状态真的能被凑出来，那么最优答案不可能比 `amount` 还大太多
- 用 `amount + 1` 可以当作哨兵值
- 后面判断是否可达也很方便

最终只要看：

```text
dp[amount] == amount + 1
```

就知道这个金额是不是不可达。

---

### 5. 为什么循环顺序这样写

这里写成：

```python
for total in range(1, amount + 1):
    for coin in coins:
```

含义是：

- 先把每个金额的答案求出来
- 对当前金额，尝试所有可用硬币

这种写法非常适合讲“状态转移”，因为你是在直接求 `dp[1]`、`dp[2]`、...、`dp[amount]`。

对面试表达来说很顺。

---

### 6. 面试里一句话讲完

你可以直接这样总结：

> 我定义 `dp[x]` 表示凑出金额 `x` 所需的最少硬币数。对于每个 `x`，枚举最后一枚使用的硬币 `coin`，如果 `coin <= x`，那么就可以从 `dp[x - coin] + 1` 转移过来，所以转移方程是 `dp[x] = min(dp[x], dp[x - coin] + 1)`。边界是 `dp[0] = 0`，最后如果 `dp[amount]` 仍然是初始化值，就说明无法凑出，返回 `-1`。

这基本就是标准满分回答。

---

## 总结

### 递进关系

1. **暴力递归**
   - 最直观
   - 但重复子问题很多

2. **记忆化递归**
   - 消除重复计算
   - 已经可以通过

3. **动态规划**
   - 最稳定
   - 最适合面试
   - 也是这题最推荐的写法

### 最终建议

- **如果你在刷一维 DP 题单**：主攻方法三
- **如果你想理解推导过程**：按方法一 -> 方法二 -> 方法三顺着看
- **如果你在准备面试**：把方法三的状态定义、转移和完全背包本质讲熟
