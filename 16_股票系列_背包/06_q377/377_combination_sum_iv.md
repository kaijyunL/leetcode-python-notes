# 377. Combination Sum IV

## 题目理解

给你一个没有重复元素的整数数组 `nums`，再给你一个目标值 `target`。

数组中的每个数都可以使用无限次。

你需要返回：

> 有多少种不同的排列，可以凑出 `target`

注意这题问的是：

```text
排列数
```

不是组合数。

也就是说：

```text
1 + 2 + 1
1 + 1 + 2
2 + 1 + 1
```

这三种在这题里要算：

```text
3 种不同排列
```

例如：

```text
nums = [1, 2, 3], target = 4
```

答案是：

```text
7
```

因为一共有这 7 种排列：

```text
1 + 1 + 1 + 1
1 + 1 + 2
1 + 2 + 1
2 + 1 + 1
2 + 2
1 + 3
3 + 1
```

这题和第 518 题很像：

- 都是计数题
- 数字都可以无限使用

但核心区别是：

- 第 518 题算的是 **组合数**
- 第 377 题算的是 **排列数**

这就会直接决定：

```text
循环顺序不一样
```

如果按学习路径来走，最适合这样理解：

```text
暴力递归 -> 记忆化递归 -> 一维 DP
```

这题没必要强行写二维 DP，因为一维状态本身就已经很自然。

---

## 为什么这题要重点盯住“顺序”

这题最容易错的地方不是状态定义，而是：

```text
为什么第 518 题外层枚举硬币，这题却外层枚举目标值
```

原因只有一句话：

- **组合数**：顺序不重要
- **排列数**：顺序重要

这题里，最后一个位置放的是谁，会影响答案。

所以最自然的想法不是：

```text
我现在允许用哪些数
```

而是：

```text
我要凑出 total，最后一个位置放哪个数
```

这也是后面一维 DP 写法的根本原因。

---

## 方法一：暴力递归

### 思路

定义：

```text
dfs(remain) = 凑出 remain 的排列数
```

如果现在还剩 `remain`，那么最后一步可以放任何一个 `num`，只要：

```text
num <= remain
```

那么问题就变成：

```text
dfs(remain - num)
```

所以：

```text
dfs(remain) = sum(dfs(remain - num))
```

其中 `num` 遍历所有可选数字。

### 边界

```text
remain == 0 -> 1
```

因为：

```text
凑到刚好为 0，表示形成了 1 种合法排列
```

### 代码

```python
from typing import List


# 方法一：暴力递归
class Solution:
    def combinationSum4(self, nums: List[int], target: int) -> int:
        def dfs(remain):
            if remain == 0:
                return 1

            ways = 0
            for num in nums:
                if num <= remain:
                    ways += dfs(remain - num)
            return ways

        return dfs(target)
```

### 复杂度

- 时间复杂度：指数级，较慢
- 空间复杂度：`O(target)`，主要来自递归深度

### 评价

这个方法的价值在于把“排列数”的本质想清楚：

- 凑出 `total` 时，要枚举最后一个位置放什么
- 不同顺序会在不同递归路径里分别被统计

但重复子问题很多，不能作为最终解法。

---

## 方法二：记忆化递归

### 思路

暴力递归的问题是：

```text
dfs(remain)
```

会被反复计算。

只要 `remain` 一样，后面的答案就完全一样。

所以可以加缓存。

状态定义和转移都不变：

```text
dfs(remain) = sum(dfs(remain - num))
```

### 代码

```python
from typing import List


# 方法二：记忆化递归
class Solution:
    def combinationSum4(self, nums: List[int], target: int) -> int:
        memo = {}

        def dfs(remain):
            if remain == 0:
                return 1
            if remain in memo:
                return memo[remain]

            ways = 0
            for num in nums:
                if num <= remain:
                    ways += dfs(remain - num)

            memo[remain] = ways
            return ways

        return dfs(target)
```

### 复杂度

- 时间复杂度：`O(target * len(nums))`
- 空间复杂度：`O(target)`

### 评价

这个方法已经能通过，而且和递归思路完全一致。

但面试里通常更推荐直接写迭代 DP。

## 方法三：一维 DP（最适合面试）

### 为什么这个最适合面试

这是我最推荐的面试写法。

原因：

1. 状态定义最自然
2. 转移和递归完全一致
3. 最容易把“为什么这是排列数”讲清楚
4. 时间复杂度和空间复杂度都很好

---

### 第一步：先定义状态

定义：

```text
dp[total] = 凑出 total 的排列数
```

最终答案就是：

```text
dp[target]
```

这里状态只需要一维。

因为这题不需要区分“前几种数字”，它只关心：

```text
凑出某个 total，有多少种排列
```

### 为什么这题不强行写二维 DP

第 518 题写二维 DP 是因为：

> 需要用“前 `i` 种硬币”这个维度来避免顺序重复计数

但 377 问的是排列数，不同顺序本来就要分开算。

所以你不需要像 518 那样用 `i` 去限制“允许使用哪些数字”。

一维状态就完全够用了。

### 初始化怎么设

```python
dp = [0] * (target + 1)
dp[0] = 1
```

以 `target = 4` 为例，初始化的结果是：

```text
dp[0] = 1   # 什么都不放，算 1 种
dp[1] = 0   # 还没开始算，初始为 0
dp[2] = 0   # 还没开始算，初始为 0
dp[3] = 0   # 还没开始算，初始为 0
dp[4] = 0   # 还没开始算，初始为 0
```

其他位置设为 `0`，表示这些状态还没被任何排列路径到达过。  
随着后面逐个计算，它们会被正确更新成对应的排列数。

---

### 第二步：为什么转移这样写

如果要凑出 `total`，那么最后一个位置可以放任意一个 `num`，只要：

```text
num <= total
```

如果最后一个位置放的是 `num`，那么前面就必须先凑出：

```text
total - num
```

因此：

```text
dp[total] += dp[total - num]
```

合起来就是：

```text
dp[total] = sum(dp[total - num])
```

其中 `num` 遍历所有 `<= total` 的数字。

这里是加法，因为题目问的是排列数。

用一个具体例子，把整个 DP 表格走一遍。

```text
nums = [1, 2, 3], target = 4
```

初始化：

```text
dp[0] = 1
dp[1] = 0
dp[2] = 0
dp[3] = 0
dp[4] = 0
```

然后 `total` 从 `1` 到 `4` 依次算：

### 算 dp[1]

最后一个位置可以放：

- `1`，前面要凑出 `0`，贡献 `dp[0] = 1`

```text
dp[1] = dp[0] = 1
```

实际排列就是：`1`

### 算 dp[2]

最后一个位置可以放：

- `1`，前面凑 `1`，贡献 `dp[1] = 1`
- `2`，前面凑 `0`，贡献 `dp[0] = 1`

```text
dp[2] = dp[1] + dp[0] = 1 + 1 = 2
```

实际排列就是：`1+1`、`2`

### 算 dp[3]

最后一个位置可以放：

- `1`，前面凑 `2`，贡献 `dp[2] = 2`
- `2`，前面凑 `1`，贡献 `dp[1] = 1`
- `3`，前面凑 `0`，贡献 `dp[0] = 1`

```text
dp[3] = dp[2] + dp[1] + dp[0] = 2 + 1 + 1 = 4
```

实际排列就是：`1+1+1`、`1+2`、`2+1`、`3`

### 算 dp[4]

最后一个位置可以放：

- `1`，前面凑 `3`，贡献 `dp[3] = 4`
- `2`，前面凑 `2`，贡献 `dp[2] = 2`
- `3`，前面凑 `1`，贡献 `dp[1] = 1`

```text
dp[4] = dp[3] + dp[2] + dp[1] = 4 + 2 + 1 = 7
```

实际排列就是：

- 最后放 `1` 的 4 种：`1+1+1+1`、`1+2+1`、`2+1+1`、`3+1`
- 最后放 `2` 的 2 种：`1+1+2`、`2+2`
- 最后放 `3` 的 1 种：`1+3`

总共 7 种。

这正对应代码里的：

```text
dp[total] += dp[total - num]
```

---

### 第三步：为什么循环要这样写

代码是：

```python
for total in range(1, target + 1):
    for num in nums:
        if num <= total:
            dp[total] += dp[total - num]
```

这几行的意思是：

- 外层枚举 `total`：现在去算凑出 `1..target` 的排列数
- 内层枚举 `num`：对每个 `total`，去试“最后一个位置放哪个数”

为什么必须外层枚举 `total`？

因为这题问的是：

```text
排列数
```

不同顺序要分开统计。

所以对每个 `total`，要把所有可能的“最后一个数”都枚举一遍。

这正是：

```text
外层目标值，内层数字
```

如果反过来写成外层枚举 `num`，那就更像第 518 题的组合数写法，不同顺序会被合并掉。

---

### 第四步：边界怎么定

最关键的边界是：

```text
dp[0] = 1
```

表示：

```text
凑出 0 有 1 种方式：什么都不放
```

这是所有转移的起点。

---

### 代码

```python
from typing import List


# 方法三：一维 DP
class Solution:
    def combinationSum4(self, nums: List[int], target: int) -> int:
        dp = [0] * (target + 1)
        dp[0] = 1

        for total in range(1, target + 1):
            for num in nums:
                if num <= total:
                    dp[total] += dp[total - num]

        return dp[target]
```

### 复杂度

- 时间复杂度：`O(target * len(nums))`
- 空间复杂度：`O(target)`

---

### 面试时推荐怎么讲

你可以这样讲：

> 我定义 `dp[total]` 表示凑出 `total` 的排列数。对每个 `total`，我要去枚举最后一个位置放哪个数 `num`。如果最后放的是 `num`，那么前面就必须先凑出 `total - num`，所以有转移 `dp[total] += dp[total - num]`。边界是 `dp[0] = 1`，表示什么都不放是一种合法方式。因为这题统计的是排列数，不同顺序要分开，所以循环必须写成外层枚举 `total`，内层枚举 `num`。

### 方法递进关系

到这里四种方法已经完整了，它们之间的关系是：

1. **暴力递归**：先把思路想清楚——凑出 `total`，枚举最后一个数，往前推
2. **记忆化递归**：在暴力递归上加缓存，去掉 `dfs(remain)` 的重复计算
3. **一维 DP**：把递归直接改写成迭代，状态和转移完全一致，是最稳的面试写法
4. **排序 + DP**：和方法三一样，只是内层提前 `break`，属于常数优化

方法一到方法三，本质上都在做同一件事：

```text
dp[total] = sum(dp[total - num])
```

区别只在于：

- 暴力递归：重复计算很多子问题
- 记忆化递归：加 `memo` 避免重复
- 一维 DP：直接从小到大填表，去掉递归开销

方法四没有改变核心思路，只是在方法三基础上做了内层循环的常数优化。

## 方法四：排序后的等价 DP 写法

### 思路

可以先对 `nums` 排序。

这样在枚举 `num` 时，一旦：

```text
num > total
```

就可以直接 `break`，少做一些无效判断。

核心状态和转移都不变，仍然是：

```text
dp[total] += dp[total - num]
```

### 代码

```python
from typing import List


# 方法四：排序 + 一维 DP
class Solution:
    def combinationSum4(self, nums: List[int], target: int) -> int:
        nums.sort()
        dp = [0] * (target + 1)
        dp[0] = 1

        for total in range(1, target + 1):
            for num in nums:
                if num > total:
                    break
                dp[total] += dp[total - num]

        return dp[target]
```

### 复杂度

- 时间复杂度：`O(target * len(nums))`
- 空间复杂度：`O(target)`

### 评价

它本质上和方法三一样，只是把内层的一些无效判断提前剪掉。

如果不特别强调常数优化，面试里通常直接写方法三就够了。

---

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法三，一维 DP。**

### 原因

- 状态最自然：`dp[total]`
- 转移最自然：枚举最后一个数
- 最容易说明“为什么这是排列数”
- 代码短，边界清楚，口述稳定

方法四虽然也不错，但只是方法三的常数优化版。

---

## 和 518 的区别一定要记住

### 518

- 问的是：组合数
- 顺序不重要
- 写法是：外层枚举硬币，内层枚举金额

### 377

- 问的是：排列数
- 顺序重要
- 写法是：外层枚举目标值，内层枚举数字

一句话记忆：

> **518 是组合，所以先定物品；377 是排列，所以先定目标值，再枚举最后一个位置放什么。**

---

## 总结

### 递进关系

1. **暴力递归**
   - 最直观
   - 帮你理解“最后一个位置放哪个数”

2. **记忆化递归**
   - 去掉重复子问题
   - 和递归思路一致

3. **一维 DP**
   - 最适合面试
   - 直接把递归改成迭代

4. **排序后的等价 DP**
   - 本质不变
   - 只是少做一点无效判断

### 最终建议

如果你是为了：

- **理解题目**：先看递归，再看 DP
- **准备面试**：重点准备方法三
- **和背包题对比记忆**：一定和第 518 题放在一起看
