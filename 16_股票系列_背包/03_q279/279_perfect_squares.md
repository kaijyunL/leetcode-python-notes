# 279. Perfect Squares

## 题目理解

给定一个正整数 `n`，请你返回：

> 凑出 `n` 所需要的最少完全平方数个数。

这里的完全平方数指：

```text
1, 4, 9, 16, 25, ...
```

例如：

```text
n = 12
12 = 4 + 4 + 4
答案是 3

n = 13
13 = 4 + 9
答案是 2
```

这道题有两个非常经典的视角：

1. **完全背包 / 一维 DP**
2. **最短步数 / BFS**

如果按刷题训练路线来理解，这题最自然的主线还是：

```text
暴力递归 -> 记忆化递归 -> 动态规划 -> BFS 另一种视角
```

---

## 为什么这题我写 4 种方法

这题很适合完整走一遍状态推导链。

因为它最开始看起来像“随便拆数”，但其实一旦把状态想清楚，后面会非常顺：

```text
方法一：暴力递归
方法二：记忆化递归
方法三：动态规划（最适合面试）
方法四：BFS（同阶最优的另一种思路）
```

这样写不是为了凑方法数，而是为了把这题背后的两种核心思维都练到：

- 从“剩余量”出发做 DP
- 从“最少步数”出发做 BFS

---

## 方法一：暴力递归

### 思路

先只想最直观的做法。

如果当前还剩 `remain` 没凑出来，那么可以尝试：

- 选 `1`
- 选 `4`
- 选 `9`
- ...
- 选所有不超过 `remain` 的完全平方数

然后递归去解决剩下的部分。

定义：

```text
dfs(remain) = 凑出 remain 所需的最少完全平方数个数
```

那么有：

```text
dfs(remain) = min(dfs(remain - square) + 1)
```

其中 `square` 遍历所有 `<= remain` 的完全平方数。

边界：

```text
remain == 0 时，不需要再选任何数，所以返回 0
```

### 代码

```python
# 方法一：暴力递归
class Solution:
    def numSquares(self, n: int) -> int:
        squares = []
        i = 1
        while i * i <= n:
            squares.append(i * i)
            i += 1

        def dfs(remain):
            if remain == 0:
                return 0

            best = remain
            for square in squares:
                if square > remain:
                    break
                best = min(best, dfs(remain - square) + 1)

            return best

        return dfs(n)
```

### 复杂度

- 时间复杂度：指数级，近似 `O(sqrt(n)^n)`，实际非常慢
- 空间复杂度：`O(n)`，递归栈深度

### 评价

这个方法适合理解“状态和选择是怎么来的”，但不适合作为最终答案。

最大问题是：

- 很多 `dfs(remain)` 会被反复计算
- 重复子问题非常严重

---

## 方法二：记忆化递归

### 思路

既然暴力递归慢，是因为同一个 `remain` 会重复算很多次，那就把已经算过的结果存起来。

仍然定义：

```text
dfs(remain) = 凑出 remain 所需的最少完全平方数个数
```

只是这次加一个 `memo`：

- 如果 `remain` 之前算过，直接返回
- 没算过，再递归求值并存起来

### 代码

```python
# 方法二：记忆化递归
class Solution:
    def numSquares(self, n: int) -> int:
        squares = []
        i = 1
        while i * i <= n:
            squares.append(i * i)
            i += 1

        memo = {}

        def dfs(remain):
            if remain == 0:
                return 0
            if remain in memo:
                return memo[remain]

            best = remain
            for square in squares:
                if square > remain:
                    break
                best = min(best, dfs(remain - square) + 1)

            memo[remain] = best
            return best

        return dfs(n)
```

### 复杂度

- 时间复杂度：`O(n * sqrt(n))`
- 空间复杂度：`O(n)`

### 评价

这个方法已经很好了。

优点：

- 保留了最自然的递归思路
- 很容易从暴力解法升级上来

缺点：

- 还是有递归栈
- 面试里有些人会更偏爱迭代 DP

---

## 方法三：动态规划（最适合面试）

### 为什么这个最适合面试

这是我最推荐的面试写法。

原因：

1. 时间复杂度已经很好：`O(n * sqrt(n))`
2. 没有递归，边界和转移都很稳定
3. 它和“完全背包”模型完全一致，容易迁移到别的题
4. 在你这套题单里，这题放在一维 DP 专题里，用 DP 来讲最顺

---

### 第一步：先定义状态

定义：

```text
dp[x] = 凑出 x 所需要的最少完全平方数个数
```

我们的目标就是：

```text
dp[n]
```

---

### 第二步：想清楚转移为什么成立

如果我们要凑出 `x`，最后一步一定是选了某个完全平方数 `square`。

那么在选这个 `square` 之前，前面已经先凑出了：

```text
x - square
```

所以：

- 凑出 `x - square` 的最优答案是 `dp[x - square]`
- 再加上当前这个平方数，总代价就是 `dp[x - square] + 1`

于是：

```text
dp[x] = min(dp[x], dp[x - square] + 1)
```

其中 `square` 遍历所有 `<= x` 的完全平方数。

---

### 第三步：边界怎么定

最基本的边界是：

```text
dp[0] = 0
```

因为凑出 0，不需要任何平方数。

其他位置一开始都可以设成一个很大的值，表示：

```text
还没有被更新到
```

例如：

```text
dp[1..n] = n
```

因为最差也可以全用 `1` 来凑，所以答案绝不会超过 `n`。

---

### 第四步：为什么这就是完全背包

这题本质上非常像完全背包：

- 物品：`1, 4, 9, 16, ...`
- 每个物品可以无限使用
- 目标：凑出总和 `n`
- 代价：使用的物品数量最少

所以这是一个非常标准的：

> 无限选物品，求最少个数 的 DP 问题。

---

### 第五步：用例子走一遍

以：

```text
n = 12
```

为例。

完全平方数有：

```text
1, 4, 9
```

初始化：

```text
dp[0] = 0
其余先看作很大
```

往后推：

- `dp[1] = 1`，因为 `1 = 1`
- `dp[4] = 1`，因为 `4 = 4`
- `dp[8] = 2`，因为 `8 = 4 + 4`
- `dp[12] = 3`，因为 `12 = 4 + 4 + 4`

所以答案是：

```text
3
```

---

### 代码

```python
# 方法三：动态规划
class Solution:
    def numSquares(self, n: int) -> int:
        squares = []
        i = 1
        while i * i <= n:
            squares.append(i * i)
            i += 1

        dp = [0] + [n] * n

        for total in range(1, n + 1):
            for square in squares:
                if square > total:
                    break
                dp[total] = min(dp[total], dp[total - square] + 1)

        return dp[n]
```

### 复杂度

- 时间复杂度：`O(n * sqrt(n))`
- 空间复杂度：`O(n)`

---

### 面试时推荐怎么讲

你可以这样讲：

#### 1. 先定义状态

```text
dp[x] = 凑出 x 所需的最少完全平方数个数
```

#### 2. 再解释最后一步

要凑出 `x`，最后一次一定是选了某个平方数 `square`。

那么前面必须已经凑出：

```text
x - square
```

#### 3. 写出转移

```text
dp[x] = min(dp[x], dp[x - square] + 1)
```

#### 4. 说明边界

```text
dp[0] = 0
```

#### 5. 最后补一句模型归类

这是一个：

> 完全背包里“凑出目标值的最少物品数”问题。

这种讲法会很完整，而且逻辑非常顺。

## 方法四：BFS（同阶最优的另一种视角）

### 思路

这题也可以从“最少步数”的角度理解。

把每个当前和 `total` 看成一个节点。

如果当前在 `total`，那么可以走到：

```text
total + 1
total + 4
total + 9
...
```

也就是：

```text
total -> total + square
```

每走一条边，就表示：

- 又用了一个完全平方数

那么题目就变成：

> 从 `0` 出发，最少走多少步能到 `n`

这正是 BFS 最擅长解决的问题。

因为 BFS 是按层扩展的：

- 第 1 层：用 1 个平方数能凑出的数
- 第 2 层：用 2 个平方数能凑出的数
- 第 3 层：用 3 个平方数能凑出的数

第一次到达 `n` 的层数，就是答案。

### 代码

```python
# 方法四：BFS
from collections import deque


class Solution:
    def numSquares(self, n: int) -> int:
        squares = []
        i = 1
        while i * i <= n:
            squares.append(i * i)
            i += 1

        queue = deque([0])
        visited = {0}
        steps = 0

        while queue:
            steps += 1

            for _ in range(len(queue)):
                total = queue.popleft()

                for square in squares:
                    nxt = total + square
                    if nxt == n:
                        return steps
                    if nxt > n:
                        break
                    if nxt not in visited:
                        visited.add(nxt)
                        queue.append(nxt)

        return 0
```

### 复杂度

- 时间复杂度：`O(n * sqrt(n))`
- 空间复杂度：`O(n)`

### 评价

这个方法非常漂亮。

优点：

- 直接对应“最少个数 = 最短步数”
- 很容易解释为什么第一次到达就是最优

缺点：

- 如果当前专题在练 DP，这个思路会稍微跳出主线
- 面试官如果就是想看你能不能把它归成完全背包，那 DP 更合适

---

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法三，动态规划。**

### 为什么不是别的方法

#### 方法一：暴力递归

- 太慢
- 只能用来推导状态
- 不能作为最终答案

#### 方法二：记忆化递归

- 可以通过
- 但还是递归
- 面试里不如迭代 DP 稳

#### 方法四：BFS

- 复杂度同样很好
- 思路也很漂亮
- 但如果题目被放在 DP 语境里，很多时候 DP 更顺手、更容易被接受

所以综合来看：

> **方法三最稳、最好讲、最像标准面试答案。**

## 最适合面试的方法：详细讲解

### 第一步：先把问题翻译成状态

题目问的是：

```text
凑出 n 最少要几个完全平方数
```

所以自然定义：

```text
dp[x] = 凑出 x 的最少平方数个数
```

这个状态定义非常直接，没有绕。

---

### 第二步：枚举“最后一个平方数”

假设现在要求 `dp[x]`。

那最后一个加进去的平方数，可能是：

- `1`
- `4`
- `9`
- ...

如果最后一个选的是 `square`，那前面一定已经先凑出了：

```text
x - square
```

所以：

```text
dp[x] = min(dp[x - square] + 1)
```

这里的 `+ 1`，就是把最后这个平方数算进去。

这一步是整道题最核心的地方。

---

### 第三步：为什么这个转移一定不会漏

因为任意一种把 `x` 拆成平方数之和的方案，最后一定有“最后一个平方数”。

而我们在转移时：

- 把所有可能的平方数都枚举了一遍
- 对每一种情况都尝试更新答案

所以：

- 不会漏掉合法方案
- 取最小值之后得到的一定是最优解

这就是转移正确性的根本原因。

---

### 第四步：边界为什么是 `dp[0] = 0`

因为：

```text
凑出 0，不需要任何平方数
```

这个边界一定要先有。

否则像：

```text
dp[1] = dp[0] + 1
```

这种最基础的转移就没法成立。

---

### 第五步：为什么时间复杂度是 `O(n * sqrt(n))`

外层要算：

```text
1 到 n
```

一共 `n` 个状态。

对每个状态 `x`，要枚举所有不超过 `x` 的平方数，数量大约是：

```text
sqrt(x)
```

总体就是：

```text
O(n * sqrt(n))
```

---

### 第六步：面试里怎么说最自然

你可以这样讲：

> 我把这题看成完全背包。定义 `dp[x]` 表示凑出 `x` 所需的最少完全平方数个数。对每个 `x`，我去枚举最后一个使用的完全平方数 `square`，那么前面就必须先凑出 `x - square`，所以转移是 `dp[x] = min(dp[x], dp[x - square] + 1)`。边界是 `dp[0] = 0`。最后返回 `dp[n]`。

这套表达非常稳。

---

## 总结

### 递进关系

1. **暴力递归**
   - 最直观
   - 但重复子问题严重

2. **记忆化递归**
   - 解决重复计算
   - 已经能过

3. **动态规划**
   - 迭代稳定
   - 最适合面试

4. **BFS**
   - 同阶最优
   - 提供“最短步数”视角

### 最终建议

- **刷题训练主线**：优先掌握方法三 DP
- **如果你想拓宽视角**：再看方法四 BFS
- **如果面试要讲推导过程**：可以从方法一/二顺着过渡到方法三
