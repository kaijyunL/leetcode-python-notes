# 494. 目标和

## 题目理解

给你一个非负整数数组 `nums` 和一个整数 `target`。

你可以在数组里的每个数前面放一个 `+` 或 `-`，然后把整个表达式计算出来。

问：

```text
有多少种不同的方法，可以让最终结果等于 target
```

例如：

```text
nums = [1, 1, 1, 1, 1], target = 3
```

一种可行表达式是：

```text
-1 + 1 + 1 + 1 + 1 = 3
```

这题答案是：

```text
5
```

---

## 这题最关键的转化

表面看，这题是在每个数前面选 `+` 或 `-`。

但真正的关键，是把它转成背包问题。

设：

- 加正号的那部分数字和为 `P`
- 加负号的那部分数字和为 `N`

那么有：

```text
P - N = target
P + N = sum(nums)
```

两式相加：

```text
2P = sum(nums) + target
```

所以：

```text
P = (sum(nums) + target) // 2
```

这就等价于：

> 从 `nums` 里选一些数，使它们的和等于 `P`，问有多少种选法。

所以这题本质上是：

> **0-1 背包计数问题**

不是问“能不能凑出来”，而是问：

> **有多少种方法凑出来。**

---

## 为什么有时可以直接返回 0

从上面的转化可以看出，目标和 `P` 必须合法。

### 情况 1：`abs(target) > sum(nums)`

因为所有数加起来的绝对值最多就是 `sum(nums)`。

如果目标比这个还大，不可能达到。

直接返回：

```text
0
```

### 情况 2：`sum(nums) + target` 是奇数

因为：

```text
P = (sum(nums) + target) / 2
```

如果分子是奇数，就不可能得到整数 `P`。

而背包容量必须是整数。

也就是说，不存在合法转化。

也直接返回：

```text
0
```

---

## 按刷题路线应该怎么学

这题最适合按下面顺序理解：

```text
暴力递归 -> 记忆化递归 -> 二维 DP -> 一维优化 DP
```

和第 416 题很像，但有一个核心区别：

- 第 416 题问的是：能不能凑出来
- 第 494 题问的是：有多少种方法凑出来

所以这里的 DP 不再是布尔值，而是：

```text
方案数
```

---

## 方法一：暴力递归

### 思路

对于每个数，都有两种选择：

- 前面放 `+`
- 前面放 `-`

所以可以定义：

```text
dfs(index, current_sum) = 处理到下标 index 时，当前和是 current_sum，最终能得到 target 的方案数
```

对于 `nums[index]`：

```text
加号：dfs(index + 1, current_sum + nums[index])
减号：dfs(index + 1, current_sum - nums[index])
```

所以总方案数就是两条路之和。

### 边界

当所有数字都处理完时：

- 如果 `current_sum == target`，说明找到 1 种方法
- 否则是 0 种方法

### 代码

```python
from typing import List


# 方法一：暴力递归
class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        def dfs(index, current_sum):
            if index == len(nums):
                return 1 if current_sum == target else 0

            return dfs(index + 1, current_sum + nums[index]) + dfs(index + 1, current_sum - nums[index])

        return dfs(0, 0)
```

### 复杂度

- 时间复杂度：`O(2^n)`
- 空间复杂度：`O(n)`

### 评价

这个方法的价值在于帮助你理解题目的“正负号二叉决策树”。

但它会枚举所有可能，效率太低。

---

## 方法二：记忆化递归

### 思路

暴力递归的问题在于：

很多状态会重复。

比如：

```text
dfs(index, current_sum)
```

同一个 `index` 和同一个 `current_sum`，后面的结果其实完全一样。

所以可以加缓存。

定义仍然不变：

```text
dfs(index, current_sum) = 从 index 开始处理，当前和为 current_sum 时，最终得到 target 的方案数
```

如果某个状态已经算过，直接返回缓存。

### 代码

```python
from typing import List


# 方法二：记忆化递归
class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        memo = {}

        def dfs(index, current_sum):
            if index == len(nums):
                return 1 if current_sum == target else 0

            key = (index, current_sum)
            if key in memo:
                return memo[key]

            memo[key] = dfs(index + 1, current_sum + nums[index]) + dfs(index + 1, current_sum - nums[index])
            return memo[key]

        return dfs(0, 0)
```

### 复杂度

- 时间复杂度：`O(n * sum(nums))`
- 空间复杂度：`O(n * sum(nums))`

### 评价

这个方法已经能通过，而且从暴力递归升级过来很顺。

但在面试里，如果你已经完成了等价转化，通常更推荐直接写 DP。

---

## 方法三：二维 DP（最适合面试）

### 为什么这个最适合面试

这是我最推荐的面试写法。

因为它有几个优点：

1. 先完成题意转化，体现建模能力
2. 状态定义清楚
3. 转移方程直观
4. 虽然不是空间最优，但最容易讲明白

---

### 第一步：完成等价转化

设数组总和为：

```text
total = sum(nums)
```

如果我们把选正号的数之和记作 `positive`，就有：

```text
positive - (total - positive) = target
```

化简得：

```text
2 * positive = total + target
positive = (total + target) // 2
```

所以问题转成：

```text
从 nums 中选一些数，使它们的和等于 positive，一共有多少种选法
```

前提是：

- `abs(target) <= total`
- `total + target` 必须是偶数

否则直接返回 0。

---

### 第二步：定义状态

定义：

```text
dp[i][j] = 使用前 i 个数，凑出和 j 的方案数
```

这里的前 `i` 个数指的是：

```text
nums[0], nums[1], ..., nums[i - 1]
```

最终答案就是：

```text
dp[n][positive]
```

---

### 第三步：想清楚转移

当前处理的数是：

```text
num = nums[i - 1]
```

对于这个数，有两种选择：

#### 1. 不选它

那方案数来自：

```text
dp[i - 1][j]
```

#### 2. 选它

如果 `j >= num`，那还可以从：

```text
dp[i - 1][j - num]
```

转移过来。

所以：

```text
dp[i][j] = dp[i - 1][j]
if j >= num:
    dp[i][j] += dp[i - 1][j - num]
```

注意这里不是 `or`，而是 `+`。

因为我们在统计方案数。

---

### 第四步：边界

最关键的边界是：

```text
dp[0][0] = 1
```

意思是：

```text
一个数都不选，凑出和 0，有 1 种方法
```

这 1 种方法就是“什么都不选”。

而：

```text
dp[0][j] = 0   (j > 0)
```

因为没有数字，不可能凑出正数和。

---

### 代码

```python
from typing import List


# 方法三：二维 DP
class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        total = sum(nums)
        if abs(target) > total or (total + target) % 2 == 1:
            return 0

        positive = (total + target) // 2
        n = len(nums)
        dp = [[0] * (positive + 1) for _ in range(n + 1)]
        dp[0][0] = 1

        for i in range(1, n + 1):
            num = nums[i - 1]
            for current in range(positive + 1):
                dp[i][current] = dp[i - 1][current]
                if current >= num:
                    dp[i][current] += dp[i - 1][current - num]

        return dp[n][positive]
```

### 复杂度

- 时间复杂度：`O(n * positive)`
- 空间复杂度：`O(n * positive)`

---

### 面试时推荐怎么讲

你可以这样说：

#### 1. 先做等价转化

原题不是直接做正负号，而是转成：

```text
从数组中选一些数，使它们的和等于 (sum(nums) + target) // 2
```

#### 2. 再定义状态

```text
dp[i][j] 表示前 i 个数凑出和 j 的方案数
```

#### 3. 再解释转移

- 不选当前数：`dp[i - 1][j]`
- 选当前数：`dp[i - 1][j - num]`

所以是两部分方案数相加。

#### 4. 最后说边界

```text
dp[0][0] = 1
```

表示什么都不选，凑出 0，有 1 种方法。

这套讲法会很完整。

---

## 方法四：一维优化 DP（最优解法）

### 思路

因为二维 DP 的每一行只依赖上一行，所以可以压缩成一维。

定义：

```text
dp[j] = 当前处理到某个前缀时，凑出和 j 的方案数
```

初始时：

```text
dp[0] = 1
```

表示凑出 0 的方案数有 1 种。

每处理一个 `num`，就更新：

```text
dp[j] += dp[j - num]
```

---

### 为什么必须倒序

因为每个数只能用一次。

如果正序更新，就会在同一轮里重复使用当前这个数，变成完全背包。

所以必须：

```text
for j in range(positive, num - 1, -1)
```

---

### 代码

```python
from typing import List


# 方法四：一维优化 DP
class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        total = sum(nums)
        if abs(target) > total or (total + target) % 2 == 1:
            return 0

        positive = (total + target) // 2
        dp = [0] * (positive + 1)
        dp[0] = 1

        for num in nums:
            for current in range(positive, num - 1, -1):
                dp[current] += dp[current - num]

        return dp[positive]
```

### 复杂度

- 时间复杂度：`O(n * positive)`
- 空间复杂度：`O(positive)`

### 评价

这是这题更常见的最优写法。

优点：

- 时间复杂度优秀
- 空间更省
- 代码也不长

缺点：

- 需要解释清楚为什么必须倒序
- 如果面试里一上来写，思路不如二维版直观

---

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法三，二维 DP。**

### 为什么

#### 方法一：暴力递归

- 能帮助理解正负号决策树
- 但复杂度太高

#### 方法二：记忆化递归

- 可以通过
- 也很自然
- 但不如 DP 稳定

#### 方法四：一维优化 DP

- 是最优写法
- 但需要额外解释倒序遍历

所以综合来看：

> **方法三最适合面试；方法四最适合作为优化。**

## 最适合面试的方法：详细讲解

### 第一步：先把题目翻译对

这题表面上是在每个数前面放 `+` 或 `-`。

但更容易处理的版本是：

```text
选出一部分数作为正号部分，让它们的和等于 positive
```

其中：

```text
positive = (sum(nums) + target) // 2
```

所以难点不在写代码，而在先完成转化。

---

### 第二步：为什么这是背包计数

转化之后，题目就变成：

```text
从 nums 里选一些数，和恰好等于 positive，有多少种选法
```

这里每个数只能选一次，所以是：

```text
0-1 背包
```

同时题目问的是“多少种方法”，所以状态里存的不是 `True/False`，而是：

```text
方案数
```

---

### 第三步：为什么状态定义成 `dp[i][j]`

因为我们需要同时知道：

- 已经考虑了前几个数
- 当前想凑出的和是多少

所以定义：

```text
dp[i][j] = 前 i 个数凑出和 j 的方案数
```

这个定义既有“物品维度”，又有“容量维度”，非常标准。

---

### 第四步：为什么转移是相加

因为对于当前数 `num`，只有两种选择：

- 不选它
- 选它

这两种情况对应的是两批不同方案，所以要：

```text
相加
```

而不是取最大值，也不是布尔或。

所以：

```text
dp[i][j] = dp[i - 1][j]
if j >= num:
    dp[i][j] += dp[i - 1][j - num]
```

---

### 第五步：为什么边界是 `dp[0][0] = 1`

因为：

```text
一个数都不选，凑出和 0，有且只有 1 种方法
```

这 1 种方法就是“空方案”。

这是很多计数 DP 的关键边界。

---

### 第六步：如果面试官追问优化怎么办

你可以补一句：

> 因为每一行只依赖上一行，所以可以压成一维数组。又因为每个数只能用一次，所以必须倒序更新，避免同一个数在一轮里被重复使用。

这样就把标准解法和最优解法都讲完整了。

---

## 总结

### 递进关系

1. **暴力递归**
   - 理解每个数前面放 `+` 或 `-`
   - 本质是二叉决策树

2. **记忆化递归**
   - 减少重复状态
   - 从暴力法自然升级

3. **二维 DP**
   - 转化成 0-1 背包计数问题
   - 最适合面试

4. **一维优化 DP**
   - 空间更优
   - 是最终常见最优写法

### 最终建议

- **刷题主线**：优先掌握方法三
- **如果你想把这题真正吃透**：补方法四
- **如果你准备面试**：把“题意转化 + 计数 DP + 倒序优化”讲顺
