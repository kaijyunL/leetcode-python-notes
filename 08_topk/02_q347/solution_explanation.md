# LeetCode 347. 前 K 个高频元素

## 题目理解

给定整数数组 `nums` 和整数 `k`，返回出现频率最高的 `k` 个元素。答案内部的顺序不限。

```text
nums = [1, 1, 1, 2, 2, 3]
k = 2

1 出现 3 次
2 出现 2 次
3 出现 1 次

答案 = [1, 2]
```

这题不是找“值最大的 `k` 个数”，而是找“**出现次数最大的 `k` 个数**”。因此第一步一定是统计每个数的频率：

```python
freq = Counter(nums)
```

统计后，问题就变成了：从若干个 `(元素, 频率)` 中，选出频率最大的 `k` 个元素。

---

## 方法一：哈希表 + 按频率排序

文件：`solution_1_sort.py`

### 思路

先用哈希表统计频率，再把所有不同元素按频率从大到小排序，取前 `k` 个。

```text
nums = [1, 1, 1, 2, 2, 3]

统计后：
1 -> 3
2 -> 2
3 -> 1

按频率降序：
(1, 3), (2, 2), (3, 1)

取前 2 个元素：1、2
```

设 `m` 为不同元素的数量。排序后，频率最大的 `k` 个元素自然位于前 `k` 个位置。

### 复杂度

- 时间复杂度：`O(n + m log m)`。统计是 `O(n)`，排序 `m` 个不同元素是 `O(m log m)`；因为 `m <= n`，最坏为 `O(n log n)`。
- 空间复杂度：`O(m)`，用于频率表和排序结果。

### 局限

我们只需要前 `k` 个元素，却把 `m` 个元素全部排出了顺序。当 `k` 远小于 `m` 时，完整排序做了额外工作。

## 方法二：哈希表 + 大小为 k 的最小堆

文件：`solution_2_heap.py`

### 思路

统计频率后，用最小堆维护“当前频率最高的 `k` 个元素”。

堆内每一项写为：

```python
(count, num)
```

Python 的最小堆会让频率最小的元素位于堆顶。于是堆顶表示：

```text
当前选出的 k 个候选元素中，频率最低的那一个。
```

遍历每个 `(num, count)` 时：

```text
堆未满：直接加入。
count <= 堆顶频率：当前元素进不了前 k，跳过。
count > 堆顶频率：当前元素更应该保留，用它替换堆顶。
```

遍历结束后，堆中就是频率最高的 `k` 个元素。

### 过程举例

```text
nums = [1, 1, 1, 2, 2, 3]
k = 2
```

频率表为：

```text
1 -> 3
2 -> 2
3 -> 1
```

处理这些频率：

```text
(3, 1)：堆未满，加入 -> [(3, 1)]
(2, 2)：堆未满，加入 -> [(2, 2), (3, 1)]
(1, 3)：1 <= 堆顶频率 2，跳过
```

最后堆中的元素是 `1` 和 `2`。堆本身只保证堆顶最小，不保证所有元素按频率排好；题目允许任意返回顺序，所以可以直接取出元素。

### 复杂度

- 时间复杂度：`O(n + m log k)`。统计是 `O(n)`，每个不同元素最多进行一次 `O(log k)` 的堆操作。
- 空间复杂度：`O(m + k)`。频率表占 `O(m)`，堆最多占 `O(k)`。

### 适用场景

当不同元素很多但 `k` 较小时，堆避免了完整排序；当数据持续到来时，也可以持续维护一个大小为 `k` 的堆。

它不满足本题的线性时间进阶要求，但这是 Top K 问题中最通用、最常用的思路。

## 方法三：哈希表 + 频率桶

文件：`solution_3_bucket.py`

这是本题满足 `O(n)` 时间要求的面试主推方法。

### 为什么频率可以直接当桶下标

数组长度为 `n`。任一元素至少出现 `1` 次，至多出现 `n` 次，因此所有可能频率只在这个确定范围内：

```text
1, 2, 3, ..., n
```

我们可以创建 `n + 1` 个桶：

```python
buckets = [[] for _ in range(n + 1)]
```

其中：

```text
buckets[1]：所有出现 1 次的元素
buckets[2]：所有出现 2 次的元素
...
buckets[n]：所有出现 n 次的元素
```

这和普通桶排序不同：普通桶排序按“数值范围”分桶；这里按“频率范围”分桶。

### 过程举例

```text
nums = [1, 1, 1, 2, 2, 3]
k = 2
n = 6
```

先统计：

```text
1 -> 3
2 -> 2
3 -> 1
```

再按频率放入桶：

```text
buckets[1] = [3]
buckets[2] = [2]
buckets[3] = [1]
```

从频率最高的桶向下取元素：

```text
从 buckets[6] 扫到 buckets[3]：前面为空，到 buckets[3] 取到 1
继续扫到 buckets[2]：取到 2
已得到 k = 2 个元素，返回 [1, 2]
```

为什么这样一定正确？因为扫描顺序是频率从高到低：

```text
还没扫描到的桶，频率一定更低；
已经取到的元素，频率一定不低于之后任何元素。
```

因此得到 `k` 个元素时，它们就是频率最高的 `k` 个元素。同一个桶内的元素频率相同，内部顺序不影响答案。

### 为什么时间是 O(n)

设 `m` 为不同元素数量，且 `m <= n`：

```text
统计频率：遍历 n 个元素，O(n)
放入频率桶：遍历 m 个不同元素，O(m)
倒序扫描桶：最多扫描 n 个桶，O(n)
```

总时间为：

```text
O(n) + O(m) + O(n) = O(n)
```

没有比较排序，也不需要维护堆，因此满足题目要求。

### 复杂度

- 时间复杂度：`O(n)`。
- 空间复杂度：`O(n)`。频率表至多存 `n` 个元素，桶数组有 `n + 1` 个位置，桶内合计也只存 `m` 个不同元素。

### 面试中怎么选

本题明确要求优于 `O(n log n)` 时，优先写频率桶：频率范围天然被数组长度限制在 `1` 到 `n`，所以可以直接线性扫描。

若题目变成数据流、频率范围不方便预先确定，或面试官更关心通用 Top K 模板，则改用大小为 `k` 的最小堆。

## 方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 面试定位 |
| --- | --- | --- | --- |
| 哈希表 + 按频率排序 | `O(n + m log m)` | `O(m)` | 基线解法 |
| 哈希表 + 大小为 k 的最小堆 | `O(n + m log k)` | `O(m + k)` | Top K 通用解 |
| 哈希表 + 频率桶 | `O(n)` | `O(n)` | 本题主推 |

`m` 是不同元素的数量，且满足 `m <= n`。

## 容易出错的地方

```text
1. 堆中比较的是出现次数 count，不是元素本身 num。
2. 要维护前 k 个高频元素，应使用最小堆；堆顶是当前候选中频率最低的元素。
3. 桶下标是频率，桶里存的是元素；不要反过来。
4. 结果内部顺序不限，堆内和同一频率桶内的顺序不需要额外排序。
```
