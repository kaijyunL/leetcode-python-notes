# LeetCode 973. 最接近原点的 K 个点

## 题目理解

给定二维点数组 `points`，其中 `points[i] = [x, y]`，返回距离原点 `(0, 0)` 最近的 `k` 个点。返回结果内部的顺序不限。

点 `[x, y]` 到原点的欧几里得距离为：

```text
sqrt(x^2 + y^2)
```

例如：

```text
points = [[1, 3], [-2, 2]]

[1, 3]   的距离 = sqrt(1^2 + 3^2) = sqrt(10)
[-2, 2]  的距离 = sqrt((-2)^2 + 2^2) = sqrt(8)

sqrt(8) < sqrt(10)
所以距离最近的点是 [-2, 2]
```

### 为什么只比较距离平方

平方根函数在非负数范围内单调递增，因此：

```text
sqrt(a) < sqrt(b) 等价于 a < b
```

所以比较两个点的远近时，不需要真的计算平方根，只比较：

```python
distance_squared = x * x + y * y
```

这样既避免浮点数，也让代码更直接。

---

## 方法一：按距离平方排序

文件：`solution_1_sort.py`

### 思路

把所有点按距离平方从小到大排序，排在前 `k` 个的就是离原点最近的 `k` 个点：

```python
points = sorted(points, key=lambda point: point[0] ** 2 + point[1] ** 2)
return points[:k]
```

例如：

```text
points = [[3, 3], [5, -1], [-2, 4]

[3, 3]  的距离平方 = 18
[5, -1] 的距离平方 = 26
[-2, 4] 的距离平方 = 20

排序后 = [[3, 3], [-2, 4], [5, -1]]
取前 2 个 = [[3, 3], [-2, 4]]
```

### 复杂度

- 时间复杂度：`O(n log n)`，排序占主导。
- 空间复杂度：`O(n)`。当前实现使用 `sorted()`，会创建一个新的排序结果列表。

### 面试定位

这是最自然、最容易写对的基线解法。若题目没有要求更优复杂度，面试中可以先说明并写出它；但它把所有点都排好序，做了超过“只找前 `k` 个点”所需的工作。

## 方法二：大小为 k 的最大堆

文件：`solution_2_maxheap.py`

### 思路

我们只想保留距离最小的 `k` 个点。遍历所有点时，用一个大小最多为 `k` 的**最大堆**保存当前最接近的候选点：

```text
堆中：当前见过的距离最小的 k 个点
堆顶：这 k 个候选点里距离最远的点
```

当新点到来时：

```text
堆未满：直接加入。
新点比堆顶更近：它应进入候选集合，替换堆顶。
新点不比堆顶更近：它不可能属于当前最近的 k 个点，跳过。
```

Python 的 `heapq` 是最小堆，没有直接的最大堆。我们把距离平方取反后存入堆：

```python
(-distance_squared, x, y)
```

距离越大，负数越小，反而越容易成为最小堆堆顶。例如：

```text
距离平方：26、20、18
取负后： -26、-20、-18

最小值是 -26，对应原来的最大距离 26。
```

因此 `heap[0]` 正好表示当前候选点中最远的那个点。

### 过程举例

```text
points = [[3, 3], [5, -1], [-2, 4]]
k = 2
```

距离平方分别是：

```text
[3, 3]  -> 18
[5, -1] -> 26
[-2, 4] -> 20
```

处理过程：

```text
加入 [3, 3]：堆中距离为 18
加入 [5, -1]：堆中距离为 26、18，堆顶是最远的 26
处理 [-2, 4]：20 < 26，说明它更近，替换距离为 26 的点

最终保留距离为 18、20 的两个点
```

### 复杂度

- 时间复杂度：`O(n log k)`。每个点至多进行一次 `O(log k)` 的堆操作。
- 空间复杂度：`O(k)`。

### 适用场景

当 `k` 明显小于 `n` 时，堆避免了完整排序；若点是持续到来的数据流，也可以一直维护这个大小为 `k` 的最大堆。

## 方法三：三路快速选择

文件：`solution_3_quickselect.py`

这是本题追求平均 `O(n)` 时间时的主推方法。

### 从快速排序想到快速选择

快速排序会根据一个基准值 `pivot` 分区，然后递归排序左右两边。

本题不需要所有点的完整顺序。我们只需要距离从小到大时，第 `k - 1` 个下标之前的 `k` 个点。因此每次分区后，只保留包含目标下标的一侧：

```python
target = k - 1
```

这里是 `k - 1`，不是 `n - k`，因为代码按**距离从小到大**的顺序分区：

```text
第 1 近的点在下标 0
第 k 近的点在下标 k - 1
```

### 三路分区

随机选一个点的距离平方作为 `pivot_distance`，把当前区间分成三段：

```text
[left, less_end - 1]          : 距离小于 pivot_distance
[less_end, greater_start]     : 距离等于 pivot_distance
[greater_start + 1, right]    : 距离大于 pivot_distance
```

例如：

```text
points = [[3, 3], [5, -1], [-2, 4]]
距离平方 = [18, 26, 20]
k = 2
target = 1

假设 pivot_distance = 20
```

分区后，点的具体排列可能不同，但距离关系会变成：

```text
距离 < 20：18
距离 = 20：20
距离 > 20：26
```

此时：

```text
小于 pivot 的区域只有下标 0
等于 pivot 的区域是下标 1
target = 1 落在等于 pivot 的区域
```

所以前 `2` 个位置一定已经是距离最小的两个点，直接返回 `points[:k]`。

分区后根据目标下标决定下一步：

```text
target < less_end：目标在“小于 pivot”的左区间，只保留左边。
target > greater_start：目标在“大于 pivot”的右区间，只保留右边。
否则：目标落在“等于 pivot”的中间区间，前 k 个点已确定，直接返回。
```

三路分区会把所有距离等于 `pivot_distance` 的点一次放到中间，避免重复距离导致反复分区。

### 为什么平均时间是 O(n)

单次分区要扫描当前区间一次。随机选择基准点后，平均能丢弃一大块不包含目标下标的点，工作量可近似看成：

```text
n + n / 2 + n / 4 + ... < 2n
```

因此平均时间是 `O(n)`。

极端情况下，若每次基准点都很差，只能排除一个点，时间会退化为 `O(n^2)`。随机选择基准点能显著降低这种情况的概率。

### 复杂度

- 时间复杂度：平均 `O(n)`，最坏 `O(n^2)`。
- 空间复杂度：`O(1)` 额外空间，不计返回的 `k` 个点。代码原地交换，会修改传入的 `points`。

### 面试中怎么选

建议先说明排序法：它简单、稳定，时间为 `O(n log n)`；然后指出只需要前 `k` 个点，可以使用堆优化到 `O(n log k)`，或用快速选择做到平均 `O(n)`。

若面试官要求最优的平均时间复杂度，写三路快速选择；若时间紧或没有复杂度追问，排序法是稳妥的首答。

## 方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 是否修改 points | 面试定位 |
| --- | --- | --- | --- | --- |
| 按距离平方排序 | `O(n log n)` | `O(n)` | 否 | 稳妥的基线解法 |
| 大小为 k 的最大堆 | `O(n log k)` | `O(k)` | 否 | Top K 通用解 |
| 三路快速选择 | 平均 `O(n)`，最坏 `O(n^2)` | `O(1)` 额外空间 | 是 | 复杂度优化主解 |

## 容易出错的地方

```text
1. 比较 x^2 + y^2，不需要也不应计算 sqrt。
2. Python 的 heapq 是最小堆；要维护最近的 k 个点，堆顶必须是候选中最远的点，因此存负距离模拟最大堆。
3. 快速选择按距离升序定位，第 k 近的目标下标是 k - 1。
4. 快速选择只缩小搜索区间，不需要像快速排序那样处理两边；并且会原地修改 points。
```
