# LeetCode 215. 数组中的第 K 个最大元素

## 题目理解

给定整数数组 `nums` 和整数 `k`，返回排序后第 `k` 大的元素。

这里的“第 `k` 大”要**把重复元素也算进去**，不是第 `k` 个不同的数：

```text
nums = [3, 2, 3, 1, 2, 4, 5, 5, 6]
从大到小排序 = [6, 5, 5, 4, 3, 3, 2, 2, 1]

k = 4
答案 = 4
```

最直接的做法是完整排序，但题目要求平均 `O(n)` 时间，说明还需要学习“不排完全部元素，只找到目标位置”的做法。

---

## 方法一：排序后取值

文件：`solution_1_sort.py`

### 思路

把数组从小到大排序后，最后一个元素是第 `1` 大，倒数第 `k` 个就是第 `k` 大：

```python
nums.sort()
return nums[-k]
```

例如：

```text
nums = [3, 2, 1, 5, 6, 4]
排序后 = [1, 2, 3, 4, 5, 6]
k = 2
nums[-2] = 5
```

### 复杂度

- 时间复杂度：`O(n log n)`。
- 空间复杂度：取决于排序实现。Python 的 `list.sort()` 最坏可能使用 `O(n)` 辅助空间。

### 局限

它做了比题目所需更多的工作：我们只需要第 `k` 大，不需要知道剩余元素彼此的完整顺序。因此它适合作为基线解法，但不满足题目的平均 `O(n)` 要求。

## 方法二：大小为 k 的最小堆

文件：`solution_2_minheap.py`

### 思路

“第 `k` 大”意味着：最终只需要保留数组中最大的 `k` 个元素。

用一个大小始终不超过 `k` 的**最小堆**保存这些候选元素：

```text
堆中保存当前见过的最大的 k 个数
堆顶保存这 k 个数中最小的一个
```

遍历每个 `num`：

```text
num <= 堆顶：num 不可能进入当前最大的 k 个数，跳过。
num > 堆顶：num 应进入候选集合，弹出堆顶后加入 num。
```

遍历结束后，堆中恰好是全数组最大的 `k` 个数；其中最小的堆顶，自然就是第 `k` 大。

### 过程举例

```text
nums = [3, 2, 1, 5, 6, 4]
k = 2
```

先拿前 `k` 个数建最小堆：

```text
[3, 2] -> 堆为 [2, 3]
```

继续遍历：

```text
1 <= 2：跳过，最大的两个数仍是 3、2
5 > 2：替换堆顶，堆为 [3, 5]
6 > 3：替换堆顶，堆为 [5, 6]
4 <= 5：跳过
```

最终堆为 `[5, 6]`，堆顶 `5` 是第 `2` 大。

### 复杂度

- 时间复杂度：`O(n log k)`。建堆是 `O(k)`，之后最多进行 `n - k` 次堆操作，每次 `O(log k)`。
- 空间复杂度：`O(k)`。

### 适用场景

当 `k` 明显小于 `n` 时，它比完整排序更省；当数据是持续到来的流式数据时，也可以一直维护这个大小为 `k` 的堆。

它没有达到严格的平均 `O(n)`，但代码稳定、容易解释，是很实用的 Top K 通用解法。

## 方法三：三路快速选择

文件：`solution_3_quickselect.py`

这是本题最适合面试的解法，也是通常用于满足题目平均 `O(n)` 要求的做法。

### 从快速排序想到快速选择

快速排序每次选择一个 `pivot`，把数组分成左右两部分，再递归排序两边。

但本题只要一个位置的值，不需要两边都排好。若已经知道目标在某一侧，另一侧以后永远不会影响答案，可以直接丢弃。

代码按**从大到小**的顺序理解数组：

```text
第 1 大的目标下标是 0
第 k 大的目标下标是 k - 1
```

所以：

```python
target = k - 1
```

### 三路分区

随机选择一个 `pivot`，把当前区间分成三段：

```text
[left, greater_end - 1] : 大于 pivot
[greater_end, less_start] : 等于 pivot
[less_start + 1, right] : 小于 pivot
```

例如当前元素是：

```text
[3, 2, 1, 5, 6, 4]，pivot = 3
```

分区后只需关心相对关系，可以看作：

```text
[5, 6, 4] | [3] | [2, 1]
  大于 3     等于 3   小于 3
```

若 `k = 2`，则 `target = 1`。目标下标在“大于 `3`”的区域，因此第 `2` 大一定在左边 `[5, 6, 4]`，右边的 `3、2、1` 可以全部丢弃。

分区完成后有三种情况：

```text
target < greater_end：目标在大于 pivot 的左区间，保留左边。
greater_end <= target <= less_start：目标落在等于 pivot 的中间区间，直接返回。
target > less_start：目标在小于 pivot 的右区间，保留右边。
```

三路分区的价值在于：若数组里有很多重复值，所有等于 `pivot` 的元素会一次放入中间区间。只要 `target` 落在其中，就立刻结束，不会像单路分区那样反复处理相同元素。

### 为什么平均时间是 O(n)

一次分区要扫描当前区间，因此花费与当前区间长度成正比。

随机选择 `pivot` 时，平均能丢弃一大块不可能含答案的元素。工作量可以近似看成：

```text
n + n / 2 + n / 4 + ... < 2n
```

因此平均时间是 `O(n)`。

极端情况下，若每次 `pivot` 都很差，只排除一个元素，时间会退化为 `O(n^2)`。随机选取 `pivot` 能显著降低这种情况发生的概率；三路分区还能避免大量重复值造成的无效分割。

### 复杂度

- 时间复杂度：平均 `O(n)`，最坏 `O(n^2)`。
- 空间复杂度：`O(1)` 额外空间。

代码会原地交换元素，因此会修改传入的 `nums`。

### 面试中怎么选

面试时建议按下面的顺序表达：

```text
排序可以做，时间是 O(n log n)。
若 k 较小或数据持续到来，可以用大小为 k 的最小堆，时间是 O(n log k)。
本题要求平均 O(n)，我会用随机三路快速选择：每轮分区后只保留包含第 k 大的那一侧。
```

快速选择是本题的面试主推方法：它满足题目目标，且三路分区能自然处理重复元素。

## 方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 是否修改 nums | 面试定位 |
| --- | --- | --- | --- | --- |
| 排序后取值 | `O(n log n)` | 取决于排序实现 | 是 | 基线解法 |
| 大小为 k 的最小堆 | `O(n log k)` | `O(k)` | 否 | Top K 通用解 |
| 三路快速选择 | 平均 `O(n)`，最坏 `O(n^2)` | `O(1)` | 是 | 本题主推 |

## 容易出错的地方

```text
1. 第 k 大不是第 k 个不同的元素，重复值必须保留。
2. 最小堆维护的是“最大的 k 个数”，所以堆顶才是第 k 大；不能误用最大堆。
3. 本代码按降序定位，目标下标是 k - 1；若改为按升序分区，目标下标才是 n - k。
4. 快速选择每次只缩小搜索区间，不能像快速排序一样继续处理另一侧。
```
