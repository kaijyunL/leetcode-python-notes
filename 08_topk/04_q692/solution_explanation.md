# LeetCode 692. 前 K 个高频单词

## 题目理解

给定单词列表 `words` 和整数 `k`，返回出现频率最高的 `k` 个单词。

这题有两条排序规则：

```text
1. 出现频率更高的单词排在前面。
2. 频率相同时，字典序更小的单词排在前面。
```

例如：

```text
words = ["i", "love", "leetcode", "i", "love", "coding"]
k = 2

i        出现 2 次
love     出现 2 次
coding   出现 1 次
leetcode 出现 1 次
```

`i` 和 `love` 的频率相同，比较字典序：

```text
"i" < "love"
```

所以结果是：

```text
["i", "love"]
```

与 Q347 的区别在于：Q347 的返回顺序可以任意；本题不仅要选出前 `k` 个单词，还必须按上述两条规则排列结果。

设：

```text
n = words 中单词总数
m = 不同单词数量，m <= n
```

第一步都需要统计频率：

```python
freq = Counter(words)
```

之后的问题是：如何按“频率降序、字典序升序”选出并返回前 `k` 个单词。

---

## 方法一：哈希表 + 双关键字排序

文件：`solution_1_sort.py`

### 思路

统计频率后，对所有不同单词排序。Python 按元组从左到右比较，因此可以把每个单词的排序键写成：

```python
(-freq[word], word)
```

它正好同时表达了两条题目规则：

```text
-freq[word]：频率越高，负数越小，升序排序时越靠前。
word：频率相同后，字典序越小，越靠前。
```

例如：

```text
i        -> (-2, "i")
love     -> (-2, "love")
coding   -> (-1, "coding")
leetcode -> (-1, "leetcode")
```

按元组升序排序后的顺序为：

```text
(-2, "i")
(-2, "love")
(-1, "coding")
(-1, "leetcode")
```

取前 `k` 个单词即可。

### 代码核心

```python
ordered_words = sorted(freq, key=lambda word: (-freq[word], word))
return ordered_words[:k]
```

这里 `freq` 迭代出来的是所有不同单词，不会重复排序原数组中的相同单词。

### 复杂度

- 时间复杂度：`O(n + m log m)`。统计是 `O(n)`，对 `m` 个不同单词排序是 `O(m log m)`。
- 空间复杂度：`O(m)`，用于频率表和排序结果。

### 面试定位

这是本题最推荐的面试首答。代码短，排序规则直接对应题意，且最终本来就必须按频率和字典序输出结果。

## 方法二：哈希表 + 大小为 k 的最小堆

文件：`solution_2_heap.py`

当 `k` 明显小于不同单词数 `m` 时，可以不排序所有单词，只维护当前最好的 `k` 个候选单词。

### 堆顶应该放谁

堆中保留的是“当前最符合题意的 `k` 个单词”。因此最小堆堆顶必须是这 `k` 个候选中**最差、最容易被替换**的单词：

```text
频率更低的单词更差。
频率相同时，字典序更大的单词更差。
```

也就是说，堆顶的优先级必须是：

```text
频率升序，字典序降序。
```

遍历每个不同单词后，若堆大小超过 `k`，弹出堆顶；留下的就是当前最好的 `k` 个单词。

### 为什么不能直接存 `(frequency, word)`

Python 最小堆会先比较频率，频率相同时比较单词本身。

若直接存：

```python
(frequency, word)
```

那么同频时字典序小的单词会先成为堆顶。但它是更应该被保留的单词，不应该优先弹出。

例如：

```text
words = ["a", "b", "c"]
k = 2
```

三个单词频率都为 `1`，正确结果应为：

```text
["a", "b"]
```

若使用 `(1, "a")`、`(1, "b")`、`(1, "c")` 建最小堆，堆满后会先弹出 `"a"`，错误地保留 `"b"`、`"c"`。

### 如何让字典序大的单词先弹出

`heapq` 不支持传入自定义 `key`，所以用 `ReverseWord` 包装单词，并反转它的比较结果：

```python
class ReverseWord:
    def __lt__(self, other):
        return self.word > other.word
```

于是：

```text
ReverseWord("c") < ReverseWord("b")
```

在最小堆看来，字典序大的 `"c"` 更小，会更接近堆顶。

堆元素写成：

```python
(frequency, ReverseWord(word))
```

比较顺序就是：

```text
先比较 frequency：更低频的单词在堆顶。
频率相同，再比较 ReverseWord：字典序更大的单词在堆顶。
```

### 为什么最后还要排序

堆只能保证堆顶是最小元素，不能保证堆数组整体已经按题目要求排列。

题目要求的最终顺序是：

```text
频率降序，字典序升序。
```

所以取出堆中的 `k` 个元素后，还要按：

```python
(-frequency, word)
```

排序一次再返回。

### 复杂度

- 时间复杂度：`O(n + m log k + k log k)`。
- 空间复杂度：`O(m + k)`。频率表占 `O(m)`，堆占 `O(k)`。

### 面试定位

这是 Top K 的通用进阶写法，但本题的同频字典序规则使堆实现明显更复杂。只有在 `k << m`，或面试官明确要求避免完整排序时，才优先写它。

---

## 方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 面试定位 |
| --- | --- | --- | --- |
| 哈希表 + 双关键字排序 | `O(n + m log m)` | `O(m)` | 本题面试首选 |
| 哈希表 + 大小为 k 的最小堆 | `O(n + m log k + k log k)` | `O(m + k)` | `k` 很小时的进阶解 |

## 容易出错的地方

```text
1. 题目不是只按频率排序；频率相同时必须按字典序升序。
2. 普通排序的 key 是 (-frequency, word)，不能写成 (frequency, word)。
3. 最小堆堆顶应是最差候选：频率最低；频率相同则字典序最大。
4. 堆内元素不是最终答案顺序，返回前还要按 (-frequency, word) 排序。
```
