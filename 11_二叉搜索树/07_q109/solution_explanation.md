# LeetCode 109 - 有序链表转换二叉搜索树

## 题目

给定一个单链表的头节点 `head`，其中元素已经按升序排列。

请你把它转换成一棵高度平衡的二叉搜索树。

这里的高度平衡指的是：

```text
每个节点的左右子树高度差不超过 1
```

---

## 先抓住这题的本质

这题和第 `108` 题很像：

```text
108 题：有序数组 -> 平衡 BST
109 题：有序链表 -> 平衡 BST
```

BST 的关键性质是：

```text
中序遍历结果一定是升序
```

题目现在直接给了我们一个升序链表，所以本质问题变成：

```text
如何从这个有序序列里选根节点，让左右子树尽量平均？
```

答案还是：

```text
每次选中间位置做根
```

难点不在“选中点”本身，而在：

```text
链表不能像数组那样 O(1) 访问中间位置
```

所以第 109 题真正考的是：

```text
你怎么处理“链表不支持随机访问”这个限制
```

---

## 解法总览

按“从简单暴力到最优”的顺序，建议这样理解：

1. 先把链表转成数组，再按第 108 题的方法递归建树
2. 直接在链表上用快慢指针找中点，分治建树
3. 先统计链表长度，再用“中序模拟”一次遍历完成建树

其中最适合面试的最终答案是：

```text
解法三：长度统计 + 中序模拟
```

原因很简单：

```text
时间复杂度最优：O(n)
额外空间更优：O(log n)（递归栈）
思路也最能体现你对 BST 中序性质的理解
```

不过在面试里，最稳的回答顺序通常是：

1. 先给出解法一，快速拿到一个正确答案
2. 主动指出它用了额外数组，不够优
3. 再给出解法三作为最终优化答案

这样会比一上来直接写最优解更有层次。

---

## 解法一：链表转数组 + 递归切片

对应文件：

```text
11_二叉搜索树/07_q109/solution_1_array_slice.py
```

### 思路

先把链表全部读进数组：

```text
-10 -> -3 -> 0 -> 5 -> 9
```

变成：

```text
[-10, -3, 0, 5, 9]
```

这样问题就直接退化成第 `108` 题。

接着：

1. 取数组中点作为根
2. 左半边递归建左子树
3. 右半边递归建右子树

核心代码形态：

```python
nums = []
while head:
    nums.append(head.val)
    head = head.next

def build(values):
    if not values:
        return None

    mid = len(values) // 2
    root = TreeNode(values[mid])
    root.left = build(values[:mid])
    root.right = build(values[mid + 1:])
    return root
```

### 为什么这是“简单暴力”

因为它本质上绕开了链表的限制：

```text
链表不好取中点？
那我先把它改造成数组再说。
```

这个思路非常直观，几乎不会写错。

### 复杂度

```text
链表转数组：O(n)
递归建树：由于切片不断复制子数组，整体时间约 O(n log n)
额外空间：O(n)
```

### 优缺点

优点：

```text
最好理解，最容易写对
```

缺点：

```text
没有真正利用链表结构
切片有额外复制开销
```

所以它适合作为入门解，不适合作为最终面试答案。

## 解法二：快慢指针找中点 + 断链分治

对应文件：

```text
11_二叉搜索树/07_q109/solution_2_slow_fast_split.py
```

### 思路

既然根节点应该取中点，那我们可以直接在链表里找中点。

找中点的方法是经典快慢指针：

1. `slow` 一次走一步
2. `fast` 一次走两步
3. 当 `fast` 到尾部时，`slow` 正好在中点

找到中点后：

1. 中点做根节点
2. 把链表从中点前面断开
3. 左半段递归建左子树
4. 右半段递归建右子树

核心代码形态：

```python
prev = None
slow = head
fast = head

while fast and fast.next:
    prev = slow
    slow = slow.next
    fast = fast.next.next

if prev:
    prev.next = None
```

这里：

```text
slow 是中点
prev 是 slow 前一个节点
prev.next = None 用来把左半段链表断开
```

### 这个方法比解法一好在哪里

它不再额外创建数组，直接在链表上分治。

所以它比“转数组”更贴近题目本身。

### 但为什么它还不是最优

因为每一层递归都要重新扫描链表找中点。

比如长度为 `n` 的链表：

1. 根节点这一层扫描大约 `n`
2. 下一层左右各扫描 `n/2`
3. 再下一层左右各扫描 `n/4`

整棵树加起来是：

```text
n + n + n + ...（共 log n 层）
```

所以总时间复杂度是：

```text
O(n log n)
```

### 复杂度

```text
时间复杂度：O(n log n)
空间复杂度：O(log n)
```

### 适用场景

如果你已经想到“链表转数组”太粗暴，想直接在链表上做分治，这个方法很自然。

但如果题目追求最优复杂度，就还可以继续优化。

## 解法三：统计长度 + 中序模拟

对应文件：

```text
11_二叉搜索树/07_q109/solution_3_inorder_simulation.py
```

## 这是最适合面试的最终答案

这个方法的难点在于：

```text
你不能先找到中点节点，再递归左右
```

因为那样会不断重复扫描链表。

它的关键转换是：

```text
不要想着“先找到根”
而是想着“按 BST 的中序顺序去消费链表”
```

---

## 为什么“中序模拟”能成立

有序链表本身就是升序的：

```text
-10 -> -3 -> 0 -> 5 -> 9
```

而 BST 的中序遍历顺序也是升序的：

```text
左 -> 根 -> 右
```

所以我们完全可以把链表当成：

```text
BST 中序遍历时将要依次访问到的节点序列
```

也就是说：

1. 先递归构造左子树
2. 左子树构造完成后，当前链表节点正好就是根
3. 根节点创建完，把链表指针向后移动一位
4. 再递归构造右子树

这个顺序和 BST 的中序遍历是完全一致的。

---

## 先建“形状”，再填“值”

这是这题最关键的一层理解。

我们先统计链表长度 `n`，然后递归定义一个函数：

```python
build(left, right)
```

它的含义不是：

```text
去链表里找 [left, right] 的中点节点
```

而是：

```text
构造出一个包含 right - left + 1 个节点的平衡 BST
```

节点数量确定以后，中点位置也就确定了：

```python
mid = (left + right) // 2
```

然后递归顺序必须是：

```python
left_subtree = build(left, mid - 1)
root = TreeNode(current.val)
current = current.next
right_subtree = build(mid + 1, right)
```

注意这里的重点：

```text
左子树不是靠“值范围”建出来的
而是靠“节点个数”先把结构建出来
```

等左子树建完以后，链表指针正好走到了当前子树应当使用的根节点位置。

这就是为什么它只需要一次线性扫描。

---

## 用例子走一遍

链表：

```text
-10 -> -3 -> 0 -> 5 -> 9
```

长度为 `5`，所以第一次调用：

```python
build(0, 4)
```

中点：

```python
mid = 2
```

但这时先不急着创建值为 `0` 的根节点，而是先构造左子树：

```python
build(0, 1)
```

继续递归：

1. `build(0, 0)` 会先创建 `-10`
2. 回到 `build(0, 1)` 时，当前链表节点变成 `-3`，于是创建 `-3`
3. 左子树完成后，回到 `build(0, 4)`，当前链表节点正好走到 `0`
4. 于是 `0` 被创建为整棵树的根
5. 再继续去建右子树，依次消费 `5` 和 `9`

最终构造出的 BST 中序遍历刚好就是：

```text
-10, -3, 0, 5, 9
```

这和原链表顺序完全一致。

## 最优解代码框架

```python
def get_length(head):
    n = 0
    while head:
        n += 1
        head = head.next
    return n

def build(left, right):
    if left > right:
        return None

    mid = (left + right) // 2

    left_subtree = build(left, mid - 1)

    root = TreeNode(self.current.val)
    self.current = self.current.next

    root.left = left_subtree
    root.right = build(mid + 1, right)
    return root
```

你会发现，这个递归函数根本没有去“找中点节点”。

它只是：

```text
按照平衡 BST 的结构递归展开
然后按中序位置依次消费链表节点
```

这正是这题最巧妙的地方。

---

## 复杂度

```text
时间复杂度：O(n)
空间复杂度：O(log n)
```

解释：

1. 统计链表长度遍历一次 `O(n)`
2. 建树过程中每个链表节点只被消费一次 `O(n)`
3. 递归深度是平衡树高度 `O(log n)`

---

## 三种解法对比

| 解法 | 思路 | 时间复杂度 | 额外空间 | 面试建议 |
| --- | --- | --- | --- | --- |
| 解法一 | 转数组 + 切片递归 | O(n log n) | O(n) | 适合先说，快速给出正确答案 |

## 面试里怎么回答最稳

建议顺序：

1. 先说最容易想到的是“链表转数组”，这样可以直接复用第 108 题
2. 再指出这个做法用了额外数组，而且切片还有拷贝开销
3. 接着说可以直接在链表上用快慢指针找中点，但每层都要重新扫描链表，时间还是 O(n log n)
4. 最后给出“长度统计 + 中序模拟”的 O(n) 解法

这样面试官一般会觉得你：

```text
不是只会背答案，而是真的在做逐步优化
```

---

## 面试最容易写错的点

### 1. 忘了链表不能随机访问

如果你把链表当数组一样去找第 `mid` 个节点，而且每次都从头走，会导致整体复杂度退化。

### 2. 没理解“中序模拟”的顺序

最优解不是：

```text
先创建根，再建左子树，再建右子树
```

而是：

```text
先建左子树
再用当前链表节点创建根
最后建右子树
```

这个顺序不能错。

### 3. `self.current` 移动时机写错

必须在创建当前根节点之后再移动到下一个链表节点。

### 4. 基准条件写错

递归终止条件是：

```python
if left > right:
    return None
```

不是别的。
