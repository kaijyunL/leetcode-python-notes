# LeetCode 167. 两数之和 II - 输入有序数组 (Two Sum II)

## 题目

给定一个下标从 **1** 开始、已按 **非递减顺序排列** 的整数数组 `numbers`，
找出相加之和等于目标数 `target` 的两个数。

返回它们的下标 `[index1, index2]`，其中 `index1 < index2`。

注意：

- 每个输入恰好对应一个答案
- 不能重复使用同一个元素
- 必须只使用常量级额外空间

比如：

```text
numbers = [2, 7, 11, 15], target = 9
```

答案是：

```text
[1, 2]
```

因为 `numbers[0] + numbers[1] = 2 + 7 = 9`，下标从 1 开始所以返回 `[1, 2]`。

---

## 这题真正考的是什么

表面上看，这题是在问：

```text
在有序数组里找两个数，加起来等于目标
```

和 `1` 两数之和的区别在于：

```text
1：数组无序，用哈希表
167：数组有序，用双指针
```

数组有序这个条件，是这题的命门。
它让你不需要哈希表，就能在 `O(n)` 时间、`O(1)` 空间里找到答案。

所以这题考的核心是：

```text
怎么利用“有序”这个条件，把暴力 O(n^2) 优化到 O(n)
```

---

## 方法一：暴力枚举

### 核心思路

枚举所有两两组合，检查和是否等于 `target`。

这是完全照着定义来的保底做法，没有利用任何条件。

---

### 为什么它可行

因为它就是题目的直接实现：

```text
试遍所有可能的两数组合，找到就返回
```

逻辑一定正确，只是慢。

---

### 复杂度

- 时间复杂度：`O(n^2)`，两层循环
- 空间复杂度：`O(1)`

---

### 评价

这是保底做法，适合建立题意直觉。
但它完全没利用“数组有序”这个条件，面试里不会主推。

---

## 方法二：二分查找

### 核心思路

既然数组有序，可以固定第一个数 `numbers[i]`，
然后在它右边用二分查找找 `target - numbers[i]`。

这利用了一半的条件：**有序 → 可以二分**。

---

### 例子

```text
numbers = [2, 3, 4], target = 6
```

固定 `numbers[0] = 2`，找 `6 - 2 = 4`：
在 `[3, 4]` 里二分，找到 `4` 在下标 `2`。
返回 `[1, 3]`（下标从 1 开始）。

---

### 复杂度

- 时间复杂度：`O(n log n)`，遍历 `O(n)`，每次二分 `O(log n)`
- 空间复杂度：`O(1)`

---

### 评价

这是从暴力到双指针的过渡：
它利用了“有序可以二分”，但还没充分利用“两个数可以同时调整”。
双指针就是把这步也优化掉。

---

## 方法三：对撞双指针（面试主推）

### 核心思路

用两个指针，一个在左端（`left`），一个在右端（`right`）：

- `left` 指向当前最小的数
- `right` 指向当前最大的数

算它们的和 `s = numbers[left] + numbers[right]`：

- `s == target`：找到了
- `s < target`：和太小，`left` 右移（换一个更大的数）
- `s > target`：和太大，`right` 左移（换一个更小的数）

---

### 为什么小了挪左、大了挪右不会漏答案

这是这题最关键的问题：

```text
为什么每次只挪一个指针，不会把正确答案漏掉？
```

想清楚这一点，双指针就彻底懂了。

#### 当 `s < target` 时，为什么要挪 `left`

此时 `numbers[left] + numbers[right] < target`，和太小。

`right` 已经指向当前最大的数了，
如果 `numbers[left]` 配 `numbers[right]` 都还不够大，
那 `numbers[left]` 配 `right` 左边任何一个数只会 **更小**（因为右边的数更小）。

所以：

```text
numbers[left] 这个数，和右边任何数配都不可能凑成 target
```

它被排除了，`left` 可以安心右移。

#### 当 `s > target` 时，为什么要挪 `right`

同理，和太大。

`left` 已经指向当前最小的数了，
如果 `numbers[right]` 配 `numbers[left]` 都太大，
那 `numbers[right]` 配 `left` 右边任何一个数只会 **更大**。

所以：

```text
numbers[right] 这个数，和左边任何数配都不可能凑成 target
```

它被排除了，`right` 可以安心左移。

#### 一句话总结

```text
每次挪指针，都是在排除一个不可能的数
```

这就是对撞双指针不漏答案的核心。

---

### 过程演示

```text
numbers = [2, 7, 11, 15], target = 9
```

初始化：

```text
left = 0 (指向 2)
right = 3 (指向 15)
```

#### 第 1 步

```text
s = 2 + 15 = 17 > 9
```

和太大，`right` 左移：

```text
right = 2 (指向 11)
```

#### 第 2 步

```text
s = 2 + 11 = 13 > 9
```

还是太大，`right` 继续左移：

```text
right = 1 (指向 7)
```

#### 第 3 步

```text
s = 2 + 7 = 9 == target
```

找到了！返回 `[left + 1, right + 1] = [1, 2]`（下标从 1 开始）。

---

### 为什么这是面试主推

#### 1. 它是最优解

- 时间 `O(n)`：两个指针合起来走一遍
- 空间 `O(1)`：只用两个变量

完美满足题目“常量级额外空间”的要求。

#### 2. 它充分利用了有序性

暴力和二分都只用了一半条件，
双指针把“有序”这个条件用到了极致：

```text
小了挪左（换大的），大了挪右（换小的）
```

#### 3. 它是对撞指针的模板

这题是双指针专题的入门模板。
后面的 `11` 盛最多水的容器、`15` 三数之和，都是在这个模板上变体。

---

### 面试代码

```python
class Solution:
    def twoSum(self, numbers: list[int], target: int) -> list[int]:
        left, right = 0, len(numbers) - 1

        while left < right:
            s = numbers[left] + numbers[right]
            if s == target:
                return [left + 1, right + 1]
            elif s < target:
                left += 1
            else:
                right -= 1

        return []
```

---

### 容易出错的地方

#### 1. 返回的下标从 1 开始

题目明确说下标从 1 开始，所以要 `+1`：

```python
return [left + 1, right + 1]
```

很多人会忘了 `+1`。

#### 2. 终止条件是 `left < right`，不是 `<=`

两指针相遇时，指向同一个元素，不能和自己配对。
所以 `left < right` 就够了。

#### 3. 比较和的大小时，挪的是单个指针

```python
if s < target:
    left += 1      # 只挪 left
else:
    right -= 1     # 只挪 right
```

不要两个一起挪。每次只排除一个不可能的数。

#### 4. 不需要处理“找不到”的情况

题目保证恰好有一个答案，所以循环里一定能 `return`。
末尾的 `return []` 只是兜底，正常不会走到。

---

### 复杂度

- 时间复杂度：`O(n)`，两个指针合起来走一遍
- 空间复杂度：`O(1)`，只用两个变量

---

## 三种方法的关系

- **方法一**：暴力枚举所有组合，保底做法，没利用有序性
- **方法二**：固定一个数 + 二分找另一个，利用了“有序可以二分”
- **方法三**：对撞双指针，两个数同时调整，把有序性用到极致

这题最值得记住的一句话是：

```text
数组有序时，小了挪左换大的，大了挪右换小的；每次挪指针都在排除一个不可能的数
```

想通这一点，对撞双指针就会非常自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力枚举 | `O(n^2)` | `O(1)` | 保底，没利用有序性 |
| 方法二：二分查找 | `O(n log n)` | `O(1)` | 过渡，利用了一半条件 |
| 方法三：对撞双指针 | `O(n)` | `O(1)` | 面试主推，最优解 |

---

如果你现在只准备记一个版本：

```text
就记方法三：对撞双指针
```

因为它同时帮你巩固了三件事：

- 利用有序性：有序数组找两数，不用哈希表
- 不漏答案的证明：每次挪指针都在排除一个不可能的数
- 对撞指针模板：`left` 从左、`right` 从右，小了挪左、大了挪右

这题是双指针专题的对撞指针入门模板。
