# LeetCode 986. 区间列表的交集解析

## 题目描述

给定两个由若干闭区间组成的列表 `firstList` 和 `secondList`。

每个区间表示为：

```text
[start, end]
```

并且每个列表内部：

- 区间已经按起点升序排列
- 同一个列表中的区间彼此不重叠

请你返回这两个区间列表的交集。

例如：

```text
firstList = [[0,2],[5,10],[13,23],[24,25]]
secondList = [[1,5],[8,12],[15,24],[25,26]]
```

答案是：

```text
[[1,2],[5,5],[8,10],[15,23],[24,24],[25,25]]
```

---

## 先理解题意

两个闭区间有交集，当且仅当：

```text
max(左端点) <= min(右端点)
```

例如：

```text
[5, 10] 和 [8, 12]
```

它们的交集是：

```text
[8, 10]
```

因为：

- 交集左端点是 `max(5, 8) = 8`
- 交集右端点是 `min(10, 12) = 10`

而如果：

```text
[0, 2] 和 [3, 5]
```

则：

```text
max(0, 3) = 3
min(2, 5) = 2
```

此时 `3 > 2`，说明没有交集。

所以这题的核心不在于“怎么求交集”，而在于：

```text
如何高效地在两组有序区间里推进指针
```

---

## 方法一：两层枚举所有区间对

### 思路

最直接的做法就是：

1. 枚举 `firstList` 里的每个区间
2. 再枚举 `secondList` 里的每个区间
3. 对每一对区间计算是否有交集
4. 如果有，就把交集加入答案

计算两区间交集的方法很直接：

```text
start = max(a_start, b_start)
end = min(a_end, b_end)
```

如果：

```text
start <= end
```

说明交集存在，加入：

```text
[start, end]
```

---

### 为什么可行

因为它把两组列表之间所有可能的区间对都试了一遍。

只要某个交集存在，对应的那两个区间一定会被枚举到。

---

### 复杂度

- 时间复杂度：`O(mn)`
- 空间复杂度：`O(1)`，不算输出

这里：

- `m = len(firstList)`
- `n = len(secondList)`

---

### 这个方法慢在哪里

慢在：

```text
明明两个列表都已经有序，而且各自内部还不重叠，但仍然把所有区间对都比较了一遍
```

这就浪费了“有序”这个条件。

所以接下来最自然的优化方向就是：

```text
能不能像合并两个有序数组一样，同时推进两边的指针？
```

---

## 方法二：双指针推进（面试主推）

这是本题最经典、也最适合面试写的解法。

---

### 核心想法

设两个指针：

- `i` 指向 `firstList` 当前区间
- `j` 指向 `secondList` 当前区间

每次只看这两个当前区间：

```text
firstList[i]
secondList[j]
```

先判断它们是否有交集。

如果有，就把交集加入答案。

然后关键问题是：

```text
下一步该移动 i 还是移动 j？
```

答案是：

```text
谁先结束，就移动谁
```

---

### 为什么“谁先结束就移动谁”

这一步是整题最关键的地方。

假设当前两个区间是：

```text
A = [a1, a2]
B = [b1, b2]
```

如果：

```text
a2 < b2
```

说明区间 `A` 更早结束。

那么无论后面 `secondList` 里的区间是什么，`A` 都不可能再和当前 `B` 之后的任何区间产生新的、更靠后的重叠了。

因为：

```text
A 已经到 a2 结束了
```

而 `secondList` 后面的区间起点只会更大。

所以：

```text
A 已经没有继续保留的价值，应该移动 i
```

同理，如果：

```text
b2 < a2
```

就移动 `j`。

如果两者结束位置一样，移动哪一个都可以，通常写成 `else: j += 1` 或者任意一边都行。

---

### 为什么这个推进不会漏答案

因为每次留下的那个区间，仍然有机会和另一边后续区间继续相交。

被移动掉的那个区间，则已经不可能再和后面的区间形成新的交集。

所以这个推进策略既不会重复，也不会漏解。

---

### 用例子走一遍

输入：

```text
firstList = [[0,2],[5,10],[13,23],[24,25]]
secondList = [[1,5],[8,12],[15,24],[25,26]]
```

开始时：

```text
i = 0 -> [0,2]
j = 0 -> [1,5]
```

交集是：

```text
[1,2]
```

因为第一个区间先结束：

```text
2 < 5
```

所以移动 `i`。

---

现在：

```text
i = 1 -> [5,10]
j = 0 -> [1,5]
```

交集是：

```text
[5,5]
```

这次第二个区间先结束：

```text
5 < 10
```

所以移动 `j`。

---

现在：

```text
i = 1 -> [5,10]
j = 1 -> [8,12]
```

交集是：

```text
[8,10]
```

因为第一个区间先结束：

```text
10 < 12
```

所以移动 `i`。

后面继续同样推进，最终就会得到完整答案。

---

### 为什么时间复杂度是 `O(m + n)`

因为：

- 指针 `i` 最多走完整个 `firstList`
- 指针 `j` 最多走完整个 `secondList`

每次循环至少有一个指针前进一格。

所以总步数是线性的：

```text
O(m + n)
```

---

### 为什么这是最适合面试的方法

原因很明确：

1. 它真正利用了“两个列表有序且各自不重叠”的条件。
2. 复杂度从 `O(mn)` 降到了 `O(m + n)`。
3. 代码短，推导逻辑清楚，面试现场容易稳定写出来。

如果面试官问“你是怎么想到的”，可以按这条线讲：

```text
先从比较所有区间对出发
-> 发现两个列表本身都有序
-> 当前只需要关心两边各自的当前区间
-> 交集算完后，先结束的那个区间不可能再贡献后续交集
-> 所以移动结束更早的那个指针
```

这条推导链是完整的。

---

## 方法对比

| 方法 | 思路 | 时间复杂度 | 空间复杂度 | 面试建议 |
|---|---|---:|---:|---|
| 方法一 | 两层枚举所有区间对 | `O(mn)` | `O(1)` | 只适合理解 |
| 方法二 | 双指针同时推进 | `O(m + n)` | `O(1)` | **面试主推** |

---

## 总结

这题最值得记住的不是“区间交集模板”，而是下面这句话：

```text
两个当前区间比较完以后，先结束的那个区间不可能再参与后续交集，所以可以直接丢掉
```

真正理解了这一点，这题就会自然落成：

```text
双指针 + 当前区间求交 + 移动结束更早的一边
```

这就是本题的核心解法。
