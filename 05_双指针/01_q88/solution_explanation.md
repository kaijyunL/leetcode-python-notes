# LeetCode 88. 合并两个有序数组 (Merge Sorted Array)

## 题目

给定两个按 **非递减顺序** 排列的整数数组 `nums1` 和 `nums2`，
另有整数 `m` 和 `n`，分别表示 `nums1` 和 `nums2` 里的元素数目。

把 `nums2` 合并到 `nums1` 中，使合并后的数组同样按非递减顺序排列。

注意：结果要 **直接存在 `nums1` 里**，不能返回新数组。
`nums1` 的初始长度是 `m + n`，前 `m` 个是有效元素，后 `n` 个是 `0`（占位，要被覆盖）。
`nums2` 的长度是 `n`。

比如：

```text
nums1 = [1, 2, 3, 0, 0, 0], m = 3
nums2 = [2, 5, 6],          n = 3
```

合并后：

```text
nums1 = [1, 2, 2, 3, 5, 6]
```

---

## 这题真正考的是什么

表面上看，这题是在问：

```text
把两个有序数组合并成一个有序数组
```

但真正要识别出来的点是：

```text
nums1 末尾有一段空闲空间，能不能就地完成合并，不用额外数组
```

如果不在意空间，这题非常简单：把 `nums2` 塞进 `nums1` 后半段，再排个序就行。
但面试官会追问：

```text
能不能不用额外空间，还能保持 O(m+n) 的时间？
```

这题的精髓就在于：**利用 `nums1` 后面的空闲位，从后往前填。**

---

## 为什么从后往前填是关键

如果从前往后填，会有一个问题：

```text
你可能把 nums1 里还没处理的元素给覆盖掉
```

比如 `nums1 = [1, 2, 3, 0, 0, 0]`，`nums2 = [2, 5, 6]`。
你想把 `nums2` 的 `2` 放到 `nums1` 第一个位置，
但那里已经有 `1` 了，一覆盖就丢了。

但从后往前填就完全没这个问题：

```text
nums1 的最后面是空闲的，随便填
```

而且两个数组都是有序的，最大的元素一定在各自末尾。
从后往前比，谁大谁就填到 `nums1` 最后面。

**一句话：从后往前，大数填后面，永远不覆盖还没处理的有效元素。**

---

## 方法一：暴力合并后排序

### 核心思路

把 `nums2` 全部塞进 `nums1` 后半段，然后对整个 `nums1` 排序。

这是最直接的做法，完全没用到“两个数组本来就有序”这个条件。

---

### 代码

```python
class Solution:
    def merge(self, nums1: list[int], m: int, nums2: list[int], n: int) -> None:
        nums1[m:] = nums2
        nums1.sort()
```

---

### 复杂度

- 时间复杂度：`O((m+n) log(m+n))`，排序是主要开销
- 空间复杂度：`O(log(m+n))`，排序用的辅助栈

---

### 评价

这是保底做法，适合快速过题。
但它 **浪费了“两个数组已经有序”这个条件**，面试里不会主推。

---

## 方法二：正向双指针 + 辅助数组

### 核心思路

既然两个数组都有序，就用两个指针分别指向开头，
每次比较两个指针指向的元素，小的先放进一个辅助数组。

这就是归并排序里“合并两个有序段”的标准做法。

---

### 代码

```python
class Solution:
    def merge(self, nums1: list[int], m: int, nums2: list[int], n: int) -> None:
        sorted_arr = []
        p1, p2 = 0, 0

        while p1 < m and p2 < n:
            if nums1[p1] <= nums2[p2]:
                sorted_arr.append(nums1[p1])
                p1 += 1
            else:
                sorted_arr.append(nums2[p2])
                p2 += 1

        if p1 < m:
            sorted_arr.extend(nums1[p1:m])
        if p2 < n:
            sorted_arr.extend(nums2[p2:n])

        nums1[:] = sorted_arr
```

---

### 为什么它可行

它正确利用了“两个数组有序”这个条件，
把时间从 `O((m+n) log(m+n))` 降到 `O(m+n)`。

但代价是多开了一个辅助数组，空间是 `O(m+n)`。

---

### 复杂度

- 时间复杂度：`O(m+n)`，两个数组各扫一遍
- 空间复杂度：`O(m+n)`，辅助数组

---

### 评价

这是从暴力到最优的过渡：
它把“利用有序性”这件事讲清楚了，
但还没利用 `nums1` 末尾的空闲空间。
方法三就是把这个空间省掉。

---

## 方法三：逆向双指针（面试主推）

### 核心思路

方法二用辅助数组，是因为从前往后填会覆盖 `nums1` 还没处理的元素。

但如果 **从后往前填**，问题就消失了：

```text
nums1 的最后面是空闲的，随便填
```

三个指针：

- `p1` 指向 `nums1` 有效部分的末尾（`m - 1`）
- `p2` 指向 `nums2` 的末尾（`n - 1`）
- `p` 指向 `nums1` 最终位置的末尾（`m + n - 1`）

每次比较 `nums1[p1]` 和 `nums2[p2]`：

- 谁大，谁就填到 `nums1[p]`
- 填完的那个指针往前挪，`p` 也往前挪

一直填到 `p1` 或 `p2` 有一个越界。

---

### 为什么不会覆盖

从后往前填时，`p` 指向的位置一定是空闲的。
因为：

```text
p = m + n - 1, p1 = m - 1
p - p1 = n >= 0
```

也就是说，`p` 永远在 `p1` 右边（或重合），
所以填 `nums1[p]` 时，不会碰到 `nums1[p1]` 还没处理的元素。

这就是从后往前填最妙的地方：**空间复用，天然安全。**

---

### 过程演示

```text
nums1 = [1, 2, 3, 0, 0, 0], m = 3
nums2 = [2, 5, 6],          n = 3
```

初始化：

```text
p1 = 2 (指向 3)
p2 = 2 (指向 6)
p  = 5 (指向最后一个位置)
```

#### 第 1 步

`nums1[2]=3` vs `nums2[2]=6`，`6` 大，填到 `nums1[5]`：

```text
nums1 = [1, 2, 3, 0, 0, 6]
p2 → 1, p → 4
```

#### 第 2 步

`nums1[2]=3` vs `nums2[1]=5`，`5` 大，填到 `nums1[4]`：

```text
nums1 = [1, 2, 3, 0, 5, 6]
p2 → 0, p → 3
```

#### 第 3 步

`nums1[2]=3` vs `nums2[0]=2`，`3` 大，填到 `nums1[3]`：

```text
nums1 = [1, 2, 3, 3, 5, 6]
p1 → 1, p → 2
```

#### 第 4 步

`nums1[1]=2` vs `nums2[0]=2`，相等，取 `nums2` 的填到 `nums1[2]`：

```text
nums1 = [1, 2, 2, 3, 5, 6]
p2 → -1 (越界), p → 1
```

`p2` 越界，`nums2` 全部填完，结束。

最终 `nums1 = [1, 2, 2, 3, 5, 6]`。

---

### 为什么这是面试主推

#### 1. 它是最优解

- 时间 `O(m+n)`：利用了有序性，线性扫一遍
- 空间 `O(1)`：利用了 `nums1` 末尾空闲位，不用辅助数组

面试官问“能不能不用额外空间”，这就是标准答案。

#### 2. 它的思路有清晰递进

```text
方法一：不在意有序性，合并后排序
方法二：利用有序性，但用辅助数组
方法三：利用有序性 + 利用 nums1 空闲位，空间降到 O(1)
```

每一步优化点都明确。

#### 3. 核心技巧一句话能说清

```text
从后往前填，大数填后面，永远不覆盖还没处理的有效元素
```

---

### 面试代码

```python
class Solution:
    def merge(self, nums1: list[int], m: int, nums2: list[int], n: int) -> None:
        p1, p2 = m - 1, n - 1
        p = m + n - 1

        while p1 >= 0 and p2 >= 0:
            if nums1[p1] > nums2[p2]:
                nums1[p] = nums1[p1]
                p1 -= 1
            else:
                nums1[p] = nums2[p2]
                p2 -= 1
            p -= 1

        # nums2 有剩余则抄进去；nums1 有剩余不用动，它们已经在正确位置
        while p2 >= 0:
            nums1[p] = nums2[p2]
            p -= 1
            p2 -= 1
```

---

### 容易出错的地方

#### 1. 必须从后往前，不能从前往后

从前往后填会覆盖 `nums1` 还没处理的元素。
从后往前填，`p` 永远在 `p1` 右边，不会覆盖。

#### 2. 比较的是 `>`，不是 `>=`

```python
if nums1[p1] > nums2[p2]:
```

相等时取 `nums2` 的（走 `else` 分支）。
取哪个都行，不影响正确性，但写 `>` 更直观：严格大才从 `nums1` 拿。

#### 3. 最后只剩 nums1 有剩余时，不用动

因为 `nums1` 的有效元素本来就在前面的正确位置上。
只有 `nums2` 有剩余时，才需要抄进 `nums1` 前面。

很多人会多写一个 `while p1 >= 0` 的循环，其实没必要。

#### 4. 三个指针的初始位置容易搞反

- `p1 = m - 1`：`nums1` 有效部分的最后一个
- `p2 = n - 1`：`nums2` 的最后一个
- `p = m + n - 1`：`nums1` 总长的最后一个

记住：**都是从各自范围的最右端开始。**

---

### 复杂度

- 时间复杂度：`O(m+n)`，两个指针合起来走一遍
- 空间复杂度：`O(1)`，只用三个变量

---

## 三种方法的关系

- **方法一**：暴力合并后排序，保底做法，浪费了有序性
- **方法二**：正向双指针 + 辅助数组，利用了有序性，但没利用空闲位
- **方法三**：逆向双指针，既利用有序性又利用空闲位，空间降到 `O(1)`

这题最值得记住的一句话是：

```text
从后往前填，大数填后面，nums1 末尾的空闲位天然安全
```

想通这一点，逆向双指针就会非常自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力合并后排序 | `O((m+n)log(m+n))` | `O(log(m+n))` | 保底，浪费了有序性 |
| 方法二：正向双指针 + 辅助数组 | `O(m+n)` | `O(m+n)` | 过渡，利用了有序性 |
| 方法三：逆向双指针 | `O(m+n)` | `O(1)` | 面试主推，最优解 |

---

## 总结

如果你现在只准备记一个版本：

```text
就记方法三：逆向双指针
```

因为它同时帮你巩固了三件事：

- 利用有序性：两个有序数组合并，线性扫一遍就够
- 利用空闲位：`nums1` 末尾是空的，从后往前填不覆盖
- 边界处理：只剩 `nums2` 时才抄，只剩 `nums1` 时不用动

这题是双指针专题的第一题，也是最简单的一题。
把它吃透，后面的对撞指针、快慢指针都会顺很多。
