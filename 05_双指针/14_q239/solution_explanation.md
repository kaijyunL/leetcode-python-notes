# LeetCode 239. 滑动窗口最大值解析

## 题目描述

给定一个整数数组 `nums` 和一个大小为 `k` 的滑动窗口。

窗口从数组最左侧移动到最右侧，每次只向右移动一位。

请你返回每个窗口中的最大值。

例如：

```text
nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
```

窗口依次是：

```text
[1, 3, -1] -> 最大值 3
[3, -1, -3] -> 最大值 3
[-1, -3, 5] -> 最大值 5
[-3, 5, 3] -> 最大值 5
[5, 3, 6] -> 最大值 6
[3, 6, 7] -> 最大值 7
```

所以答案是：

```text
[3, 3, 5, 5, 6, 7]
```

---

## 先理解题意

这题不是让你求：

```text
整个数组的最大值
```

而是：

```text
每个长度为 k 的连续窗口，各自的最大值
```

所以本质上是一个固定窗口问题。

关键难点在于：

```text
窗口每向右滑动一格，如何快速知道新的最大值
```

如果每次都重新扫一遍整个窗口，当然能做，但会重复很多工作。

---

## 方法一：每个窗口重新求最大值

### 思路

最直接的方法就是：

1. 枚举每个长度为 `k` 的窗口
2. 对当前窗口重新求一次最大值
3. 把结果加入答案

例如窗口 `[1, 3, -1]` 的最大值是 `3`，下一轮窗口变成 `[3, -1, -3]`，再重新求一次最大值。

---

### 为什么可行

因为它把每个窗口都真实算了一遍。

只要某个窗口存在，它的最大值就一定能被求出来。

---

### 复杂度

- 时间复杂度：`O((n - k + 1) * k)`
- 空间复杂度：`O(1)`，不算输出

通常也写成：

```text
O(nk)
```

---

### 这个方法慢在哪里

慢在：

```text
相邻窗口高度重叠，但最大值计算每次都从头来
```

比如从：

```text
[1, 3, -1]
```

滑到：

```text
[3, -1, -3]
```

其实只少了一个 `1`、多了一个 `-3`，但你仍然重新扫描了整个窗口。

所以接下来会自然想到：

```text
能不能维护一个“当前窗口最大值候选集合”，不要每次都重算？
```

---

## 方法二：最大堆 + 懒删除

### 思路

可以用一个最大堆维护窗口内元素。

但 Python 只有最小堆，所以常见做法是把数值取反，放入：

```text
(-nums[i], i)
```

这样堆顶就是当前最大值候选。

每次窗口右移时：

1. 把新元素压入堆
2. 检查堆顶下标是否已经滑出窗口
3. 如果滑出窗口，就不断弹出
4. 堆顶剩下的元素就是当前窗口最大值

---

### 为什么要带下标

因为仅仅存值不够。

窗口滑动后，你必须知道堆顶元素是不是已经不在当前窗口里了。

所以要存：

```text
(值, 下标)
```

这样才能判断：

```text
下标 < 当前窗口左边界
```

是否过期。

---

### 为什么叫“懒删除”

因为堆里可能还留着一些已经离开窗口的旧元素。

我们不主动去堆里搜索并删除它们，而是：

```text
只有当它跑到堆顶时，才把它弹掉
```

这就叫懒删除。

---

### 复杂度

- 时间复杂度：`O(n log n)` 或更精确地说接近 `O(n log k)`
- 空间复杂度：`O(n)` 或近似 `O(k)`

面试里通常会把这种写法当成一个中等优化版本，但不是最优。

---

### 它和最优解相比差在哪里

它的核心问题是：

```text
堆只能快速拿到“最大值”，但不能快速维护“谁已经过期、谁已经没有竞争力”
```

更准确地说，堆顶虽然是当前最大值候选，但堆内部仍然保留很多无用元素。

如果想做到真正线性时间，需要一种结构，既能维护窗口顺序，又能维护数值大小关系。

这就引出单调队列。

---

## 方法三：单调队列（面试主推）

这是本题最经典、也最适合面试的解法。

---

### 核心想法

我们维护一个双端队列 `deque`，里面存的是：

```text
下标
```

并且让这些下标对应的值保持：

```text
从队头到队尾单调递减
```

也就是说：

```text
nums[deque[0]] >= nums[deque[1]] >= nums[deque[2]] ...
```

这样一来，队头永远就是当前窗口最大值的下标。

---

### 为什么要存下标，不直接存值

因为窗口是会滑动的。

你必须知道某个元素是不是已经离开窗口了，所以一定要记录位置。

只存值的话，无法判断它是否过期。

---

### 为什么要保持单调递减

这是整题最关键的一步。

假设当前要加入一个新元素 `nums[i]`。

如果队尾对应的值比它小，比如：

```text
队尾是 3，新元素是 5
```

那么这个 `3` 以后就不可能再成为窗口最大值了。

原因是：

1. `5` 比 `3` 更大
2. `5` 比 `3` 更晚离开窗口

所以只要 `5` 进来了，这个 `3` 就彻底失去竞争力，可以直接从队尾弹掉。

这就是为什么代码里会写：

```python
while deque and nums[deque[-1]] <= nums[i]:
    deque.pop()
```

---

### 队列里到底保留的是什么

保留的是：

```text
当前窗口里，仍然有机会成为最大值的下标
```

那些：

- 已经过期的
- 或者被后面更大的元素完全压制的

都会被移除。

所以这个队列不是“窗口所有元素”，而是“最大值候选人列表”。

---

### 窗口滑动时做哪三件事

每来到一个新下标 `right`，做三件事：

1. 先把队头里已经滑出窗口的下标弹掉
2. 再把队尾里所有比当前元素小或相等的下标弹掉
3. 把当前下标加入队尾

当窗口长度达到 `k` 之后：

```text
队头就是当前窗口最大值
```

把 `nums[deque[0]]` 加入答案即可。

---

### 用例子走一遍

输入：

```text
nums = [1, 3, -1, -3, 5, 3, 6, 7]
k = 3
```

---

### 处理 `1`

队列原来为空，直接加入：

```text
deque = [0]   # 值是 1
```

---

### 处理 `3`

队尾对应的 `1` 比当前 `3` 小，直接弹掉。

因为以后只要 `3` 还在窗口里，`1` 就不可能成为最大值。

然后加入 `3`：

```text
deque = [1]   # 值是 3
```

---

### 处理 `-1`

`-1` 比队尾 `3` 小，所以直接放到队尾：

```text
deque = [1, 2]   # 值是 [3, -1]
```

现在窗口 `[1, 3, -1]` 已经形成，队头对应值 `3`，所以第一个答案是：

```text
3
```

---

### 继续滑动到 `5`

当前元素是 `5`。

队尾 `-3`、`-1`、`3` 都比 `5` 小，所以全都弹掉。

最后只剩：

```text
deque = [4]   # 值是 5
```

这就表示：

```text
5` 直接压制了前面所有更小的候选人
```

所以它会成为后面一段时间里的最大值。

---

### 为什么时间复杂度是 `O(n)`

虽然代码里也有 `while`，但整体仍然是线性时间。

原因是每个下标最多：

- 进队一次
- 从队头弹出一次
- 或从队尾弹出一次

不会反复进出。

所以总操作次数是线性的。

---

### 为什么这是最适合面试的方法

原因很明确：

1. 复杂度最优：`O(n)`。
2. 这题本来就是单调队列的代表题。
3. 它真正利用了窗口重叠的信息，而不是每次重算。

如果面试官问“你怎么想到的”，可以按这条线讲：

```text
先从每个窗口重新求最大值出发
-> 发现重复扫描太多
-> 再想到用堆维护最大值候选
-> 但堆里会留很多过期或无效元素
-> 所以需要一种同时维护顺序和大小关系的结构
-> 最后得到单调递减队列
```

这个推导过程是完整的。

---

## 方法对比

| 方法 | 思路 | 时间复杂度 | 空间复杂度 | 面试建议 |
|---|---|---:|---:|---|
| 方法一 | 每个窗口重新求最大值 | `O(nk)` | `O(1)` | 只适合理解 |
| 方法二 | 最大堆 + 懒删除 | `O(n log n)` 近似 `O(n log k)` | `O(n)` | 过渡思路 |
| 方法三 | 单调递减队列 | `O(n)` | `O(k)` | **面试主推** |

---

## 总结

这题最值得记住的不是“单调队列模板”四个字，而是下面这句话：

```text
如果一个元素比新来的元素小，而且还更早离开窗口，那它以后就不可能再成为最大值
```

真正理解了这一点，就能自然推出：

```text
维护一个从大到小的候选队列，队头永远是当前窗口最大值
```

这就是本题的核心解法。
