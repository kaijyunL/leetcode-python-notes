# LeetCode 18. 四数之和（4Sum）解析

## 题目描述

给定一个整数数组 `nums` 和一个目标值 `target`，请你找出所有满足下面条件的四元组：

- 下标互不相同
- 四个数的和等于 `target`
- 结果里不能有重复四元组

例如：

```text
nums = [1, 0, -1, 0, -2, 2], target = 0
```

答案是：

```text
[[-2, -1, 1, 2], [-2, 0, 0, 2], [-1, 0, 0, 1]]
```

---

## 先理解题意

这题和 `15. 三数之和` 非常像，只是从三个数变成了四个数。

真正的要求不是“随便找四个数”，而是：

```text
找出所有不重复的四元组
```

所以它有两个核心难点：

1. 不能漏解。
2. 不能重复收集答案。

如果只是找“是否存在一个解”，难度会低很多；但这题要返回全部唯一答案，去重就是关键部分。

---

## 方法一：四重循环 + 集合去重

### 思路

最直接的想法就是枚举所有四元组：

- 第一个位置选 `i`
- 第二个位置选 `j`
- 第三个位置选 `k`
- 第四个位置选 `l`

只要满足：

```text
i < j < k < l
```

就保证四个位置互不相同，而且不会重复枚举同一组下标。

每次算出：

```text
nums[i] + nums[j] + nums[k] + nums[l]
```

如果刚好等于 `target`，就把这四个数加入答案。

但数组里可能有重复数字，所以直接收集会得到重复四元组。最简单的处理方式是：

1. 先对数组排序
2. 把四元组转成元组放进 `set`

这样可以在结果层面做去重。

---

### 为什么可行

因为它把所有可能的四元组都试了一遍。

只要某组解存在，遍历到那四个位置时就一定会被找到。

这是最朴素的正确性来源：

```text
全枚举，所以不会漏
```

---

### 复杂度

- 时间复杂度：`O(n^4)`
- 空间复杂度：`O(m)`，`m` 是去重集合里保存的四元组数量

---

### 这个方法慢在哪里

慢在：

```text
固定前两个数之后，后两个数仍然是完全暴力地再枚举
```

也就是说，它没有利用任何顺序信息。

所以接下来最自然的优化方向就是：

```text
固定前两个数之后，能不能更快地找另外两个数？
```

这就引到排序 + 双指针。

---

## 方法二：排序 + 两层固定 + 双指针（面试主推）

这是本题最经典、也最适合面试写的解法。

---

### 第一步：先排序

排序后，数组从小到大排列。

这一点非常关键，因为排序同时解决了两件事：

1. 让双指针移动有明确方向。
2. 让去重变得自然。

---

### 第二步：固定两个数，把问题变成“两数之和”

如果我们先固定 `nums[i]` 和 `nums[j]`，那么剩下的问题就变成：

```text
在 j 右边的区间里，找两个数，使它们的和等于 target - nums[i] - nums[j]
```

也就是说，四数之和被拆成了：

```text
固定两个数 + 在右边找两数之和
```

这和 `3Sum` 的思路完全一脉相承：

- `3Sum`：固定一个数，再找两数之和
- `4Sum`：固定两个数，再找两数之和

---

### 第三步：为什么双指针可以工作

固定 `i` 和 `j` 之后，设：

- `left = j + 1`
- `right = n - 1`

当前四数之和是：

```text
total = nums[i] + nums[j] + nums[left] + nums[right]
```

如果：

- `total < target`，说明当前和偏小，要让它变大，所以 `left += 1`
- `total > target`，说明当前和偏大，要让它变小，所以 `right -= 1`
- `total == target`，说明找到一个答案

这里双指针成立的根本原因是：

```text
数组有序，所以 left 右移会让和变大，right 左移会让和变小
```

---

### 第四步：去重怎么做

这题的去重比 `3Sum` 多一层，但原则完全一样。

#### 第一层去重：`i`

如果：

```text
nums[i] == nums[i - 1]
```

那就直接跳过。

原因是以前一个相同数字开头的所有组合，上一轮已经找过了。

---

#### 第二层去重：`j`

如果：

```text
nums[j] == nums[j - 1]
```

并且这是同一轮 `i` 下的重复 `j`，也要跳过。

原因和 `i` 一样：

```text
以前一个相同 nums[j] 作为第二个数的所有组合，这一层已经找过了
```

---

#### 内层去重：`left` 和 `right`

当找到一个答案后，不能只简单地 `left += 1`、`right -= 1`，还要继续跳过重复值。

否则就会把同样的四元组重复加入答案。

所以命中后要继续做：

- 左边跳过连续重复值
- 右边跳过连续重复值

---

### 第五步：为什么可以剪枝

这题如果只写“两层固定 + 双指针”，已经是 `O(n^3)` 了，能过大多数情况。

但 `4Sum` 比 `3Sum` 多一层循环，数据一大，常数差异会很明显，所以剪枝很有价值。

#### 对 `i` 这一层的最小和剪枝

当前固定 `nums[i]` 后，如果最小的四个数之和都已经大于 `target`：

```text
nums[i] + nums[i + 1] + nums[i + 2] + nums[i + 3] > target
```

那后面更大的 `i` 只会让和更大，所以可以直接 `break`。

---

#### 对 `i` 这一层的最大和剪枝

如果当前 `nums[i]` 加上后面最大的三个数，仍然小于 `target`：

```text
nums[i] + nums[n - 3] + nums[n - 2] + nums[n - 1] < target
```

说明当前 `i` 太小，就算搭配最大的三个数也不够，只能换下一个更大的 `i`，所以直接 `continue`。

---

#### 对 `j` 这一层也可以做同样的剪枝

固定 `i` 和 `j` 后，同理可得：

- 最小可能和都大于 `target`，直接 `break`
- 最大可能和都小于 `target`，直接 `continue`

这一步的本质不是背公式，而是：

```text
用当前层能取得的最小和、最大和，判断这条分支还有没有继续搜索的必要
```

---

### 用例子把过程走一遍

输入：

```text
nums = [1, 0, -1, 0, -2, 2], target = 0
```

排序后：

```text
[-2, -1, 0, 0, 1, 2]
```

---

### 第一轮：固定 `i = 0`，也就是 `nums[i] = -2`

再固定 `j = 1`，也就是 `nums[j] = -1`。

这时目标变成：

```text
在右边找两个数，让它们的和等于 3
```

于是：

- `left = 2`，值是 `0`
- `right = 5`，值是 `2`

当前总和：

```text
-2 + -1 + 0 + 2 = -1
```

偏小，所以 `left` 右移。

再算：

```text
-2 + -1 + 0 + 2 = -1
```

还是偏小，继续右移。

再算：

```text
-2 + -1 + 1 + 2 = 0
```

命中答案，于是得到：

```text
[-2, -1, 1, 2]
```

---

### 第二轮：固定 `i = 0`，再固定 `j = 2`

也就是：

```text
nums[i] = -2, nums[j] = 0
```

这时目标变成：

```text
在右边找两个数，让它们的和等于 2
```

双指针继续推进，最后会得到：

```text
[-2, 0, 0, 2]
```

之后如果下一个 `j` 还是 `0`，就必须跳过，否则会重复枚举同样的第二个数。

---

## 为什么这个方法最适合面试

本题最优解就是最适合面试的方法，原因有三点：

1. 复杂度从 `O(n^4)` 降到了 `O(n^3)`。
2. 它完整体现了排序、双指针、去重和剪枝这几个关键基本功。
3. 这版代码虽然有两层循环，但逻辑仍然是直的，现场比较容易写对。

如果面试官问“你是怎么想到的”，可以按这条线讲：

```text
先从四重循环出发
-> 发现固定前两个数之后，后两个数没必要再暴力枚举
-> 想把问题转成有序数组里的两数之和
-> 所以先排序，再用双指针
-> 最后补上每层去重和上下界剪枝
```

这个推导过程是顺的，不是硬背模板。

---

## 为什么我不把 “twoSum helper 抽象版” 当作面试主推

把 `twoSum` 抽成辅助函数是可以的，而且对理解 `k-sum` 很有帮助。

但对这道题本身来说，我不把它当作最优面试版，原因是：

1. 面试现场直接写“两层固定 + 双指针”更短。
2. 抽 helper 以后，代码结构更工程化，但读者要在函数间来回跳。
3. 这题的重点是把 `4Sum` 本身写稳，不是优先做通用框架抽象。

所以：

- 如果目标是这道题本身写对、讲清楚，直接写展开版更合适。
- 如果目标是继续往 `k-sum` 泛化，helper 版很有价值。

---

## 复杂度

### 方法一：四重循环 + 集合去重

- 时间复杂度：`O(n^4)`
- 空间复杂度：`O(m)`

### 方法二：排序 + 两层固定 + 双指针

- 时间复杂度：`O(n^3)`
- 空间复杂度：`O(1)` 额外空间

严格来说，排序本身可能带来 `O(log n)` 的栈空间，但面试里通常仍记作额外空间 `O(1)`。

---

## 总结

这题最值得记住的不是一串剪枝公式，而是下面这条主线：

```text
4Sum 本质上就是固定两个数，然后在有序区间里做两数之和
```

真正理解了这句话，这题就能自然推出：

```text
排序 + 两层固定 + 双指针 + 去重 + 剪枝
```

这就是最稳定的面试解法。
