# LeetCode 11. 盛最多水的容器 (Container With Most Water)

## 题目

给定一个长度为 `n` 的整数数组 `height`。
有 `n` 条垂线，第 `i` 条线的两个端点为 `(i, 0)` 和 `(i, height[i])`。

找出其中的两条线，使得它们与 x 轴共同构成的容器可以容纳最多的水。
返回容器可以储存的最大水量。

比如：

```text
height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
```

最大水量是：

```text
49
```

取下标 `1`（高 `8`）和下标 `8`（高 `7`），宽 `7`，高 `min(8, 7) = 7`：

```text
7 * 7 = 49
```

---

## 这题真正考的是什么

表面上看，这题是在问：

```text
选两根线，让它们围成的容器装最多水
```

关键在于面积怎么算：

```text
面积 = 宽 × 高
宽 = 两个下标的距离
高 = 两根线里较矮的那一根
```

高取 `min`，是因为水会从矮的那边漏出去。

所以这题本质是：

```text
在所有 (i, j) 对里，找 max( (j - i) * min(height[i], height[j]) )
```

和 `167` 两数之和很像，都是两个指针对撞。
但 `167` 是比较“和”的大小来决定挪谁，
这题是比较“高度”来决定挪谁。

---

## 这题和 167 的区别

| | 167 两数之和 II | 11 盛最多水的容器 |
| --- | --- | --- |
| 比较什么 | 两数之和 vs target | 两根线的高度 |
| 挪谁 | 和小了挪左、和大了挪右 | **谁矮挪谁** |
| 目标 | 和等于 target | 面积最大 |

核心区别一句话：

```text
167：和不够就换大的（挪矮的那侧）
11：面积受限于矮的，所以只能挪矮的碰运气
```

---

## 方法一：暴力枚举

### 核心思路

枚举所有两两组合，算每对的面积，取最大值。

面积公式：

```text
面积 = (j - i) * min(height[i], height[j])
```

---

### 为什么它可行

因为它就是题目的直接实现：

```text
试遍所有可能的两根线，算面积取最大
```

逻辑一定正确，只是慢。

---

### 复杂度

- 时间复杂度：`O(n^2)`，两层循环
- 空间复杂度：`O(1)`

---

### 评价

这是保底做法，适合建立“面积 = 宽 × 矮”的直觉。
但它完全没利用“可以同时调整两端”这个结构，面试里会超时。

---

## 方法二：对撞双指针（面试主推）

### 核心思路

两个指针，一个在左端（`left`），一个在右端（`right`）。

此时宽最大（`right - left`）。
算面积：

```text
面积 = (right - left) * min(height[left], height[right])
```

然后挪指针。**关键策略：谁矮挪谁。**

- `height[left] < height[right]`：`left` 右移
- `height[left] >= height[right]`：`right` 左移

---

### 为什么挪矮的，不挪高的

这是这题最关键的问题。

面积 = 宽 × 矮的那根。

现在你想让面积变大。宽只会越来越小（指针往中间挪），
所以唯一的希望是 **高能变大**。

而高由 `min(left, right)` 决定，也就是 **矮的那根**。

#### 如果挪高的

高的那根往里移，宽变小了。
但矮的那根没变，所以 `min` 还是原来那个矮的，高没变。

```text
宽变小 + 高没变 = 面积一定变小
```

完全没有希望。

#### 如果挪矮的

矮的那根往里移，宽变小了。
但新的那根可能更高，`min` 有可能变大。

```text
宽变小 + 高可能变大 = 面积有可能变大
```

虽然不保证一定变大，但至少有希望。

#### 一句话总结

```text
挪高的，面积一定变小；挪矮的，面积才有可能变大
```

所以只能挪矮的。

---

### 为什么挪矮的不漏答案

和 `167` 一样的思路：挪矮的，是在 **排除一堆不可能的情况**。

假设 `height[left] < height[right]`，
此时 `left` 是矮的。

如果保持 `left` 不动，让 `right` 往左移，
所有这些组合的面积都 **不可能超过当前**：

- 宽变小了（`right` 往左移）
- 高最多还是 `height[left]`（因为 `left` 没变，`min` 不会超过它）

所以：

```text
left 和 right 左边任何位置配对，面积都不如现在大
```

`left` 这个位置被排除了，可以安心右移。

---

### 过程演示

```text
height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
下标     0  1  2  3  4  5  6  7  8
```

初始化：

```text
left = 0 (高 1), right = 8 (高 7)
max_area = 0
```

#### 第 1 步

```text
宽 = 8 - 0 = 8
高 = min(1, 7) = 1
面积 = 8 * 1 = 8
max_area = 8
```

`height[0]=1 < height[8]=7`，挪左：

```text
left = 1
```

#### 第 2 步

```text
宽 = 8 - 1 = 7
高 = min(8, 7) = 7
面积 = 7 * 7 = 49   ← 最大
max_area = 49
```

`height[1]=8 >= height[8]=7`，挪右：

```text
right = 7
```

#### 第 3 步

```text
宽 = 7 - 1 = 6
高 = min(8, 3) = 3
面积 = 6 * 3 = 18
```

`height[1]=8 >= height[7]=3`，挪右：

```text
right = 6
```

#### 继续这样走

每一轮都是：

1. 算当前面积，更新最大值
2. 谁矮挪谁

直到 `left` 和 `right` 相遇。

最终 `max_area = 49`。

---

### 为什么这是面试主推

#### 1. 它是最优解

- 时间 `O(n)`：两个指针合起来走一遍
- 空间 `O(1)`：只用两个变量

#### 2. 它有清晰的贪心直觉

```text
宽只会变小，所以只能指望高变大；高由矮的决定，所以只能挪矮的
```

这个推理过程非常适合在面试里讲。

#### 3. 它是对撞指针的进阶

`167` 是“和不够挪左”，这题是“谁矮挪谁”。
同样是双指针，但决策依据不同。
搞清楚两者区别，对撞指针就彻底通了。

---

### 面试代码

```python
class Solution:
    def maxArea(self, height: list[int]) -> int:
        left, right = 0, len(height) - 1
        max_area = 0

        while left < right:
            area = (right - left) * min(height[left], height[right])
            max_area = max(max_area, area)

            if height[left] < height[right]:
                left += 1
            else:
                right -= 1

        return max_area
```

---

### 容易出错的地方

#### 1. 面积公式别写反

```python
area = (right - left) * min(height[left], height[right])
```

宽是 `right - left`，高是 `min`。别把 `max` 写进去。

#### 2. 挪的是矮的，不是高的

```python
if height[left] < height[right]:
    left += 1      # left 矮，挪 left
else:
    right -= 1     # right 矮，挪 right
```

和 `167` 不同，这里不是比较“和”，而是比较“高度”。

#### 3. 先算面积，再挪指针

顺序不能反：

```python
area = ...         # 先算当前面积
max_area = max(...)
if height[left] < height[right]:   # 再挪
    ...
```

如果先挪再算，会漏掉当前这对。

#### 4. 终止条件是 `left < right`

两指针相遇时指向同一根线，不能和自己配对。

---

### 复杂度

- 时间复杂度：`O(n)`，两个指针合起来走一遍
- 空间复杂度：`O(1)`，只用两个变量

---

## 两种方法的关系

- **方法一**：暴力枚举所有组合，建立“面积 = 宽 × 矮”的直觉
- **方法二**：对撞双指针，发现“挪高的没希望、挪矮的有希望”，把 `O(n^2)` 优化到 `O(n)`

这题最值得记住的一句话是：

```text
宽只会变小，高由矮的决定；所以挪高的面积一定变小，挪矮的才有可能变大
```

想通这一点，双指针的策略就会非常自然。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力枚举 | `O(n^2)` | `O(1)` | 保底，会超时 |
| 方法二：对撞双指针 | `O(n)` | `O(1)` | 面试主推，最优解 |

---

## 总结

如果你现在只准备记一个版本：

```text
就记方法二：对撞双指针
```

因为它同时帮你巩固了三件事：

- 面积公式：宽 × min(两根高度)
- 贪心策略：谁矮挪谁，因为挪高的面积一定变小
- 不漏答案：挪矮的是在排除一堆不可能的情况

这题是 `167` 的进阶，同样是双指针，但决策依据从“和的大小”变成了“谁矮”。
把它和 `167` 放在一起对照着记，对撞指针的两种用法就都清楚了。
