# LeetCode 16. 最接近的三数之和（3Sum Closest）解析

## 题目描述

给定一个整数数组 `nums` 和一个目标值 `target`，请你从数组中选出三个数，使它们的和最接近 `target`。

返回这个最接近的三数之和。

例如：

```text
nums = [-1, 2, 1, -4], target = 1
```

一种可选的三元组是：

```text
[-1, 2, 1]
```

它的和是：

```text
2
```

因为：

```text
abs(2 - 1) = 1
```

这是最接近 `target` 的结果，所以答案是：

```text
2
```

---

## 先理解题意

这题和 LeetCode 15「三数之和」长得很像，但目标完全不同。

第 15 题是：

```text
找所有和恰好等于 0 的三元组
```

这题是：

```text
在所有三元组里，找一个和，让它离 target 最近
```

所以这题有三个很重要的特点：

1. 返回的是一个整数和，不是三元组列表。
2. 不要求“刚好等于 target”，只要求“距离最小”。
3. 不需要像第 15 题那样专门处理结果去重，因为我们只维护一个当前最优答案。

判断“谁更接近 `target`”的标准就是：

```text
abs(sum - target)
```

谁的绝对差更小，谁就更接近。

---

## 方法一：三重循环暴力枚举

### 思路

最直接的想法就是枚举所有三元组：

- 第一个位置选 `i`
- 第二个位置选 `j`
- 第三个位置选 `k`

只要满足：

```text
i < j < k
```

就保证三个位置互不相同，而且不会重复枚举同一组下标。

每次算出：

```text
total = nums[i] + nums[j] + nums[k]
```

再和当前记录的最优答案 `ans` 比较。

如果：

```text
abs(total - target) < abs(ans - target)
```

就更新 `ans`。

---

### 为什么可行

因为它把所有可能的三元组都试过了。

只要某个三元组才是真正最接近 `target` 的，那它在遍历过程中一定会被访问到，最终就一定能把答案更新出来。

这是最朴素、但也最稳的正确性来源：

```text
全枚举，所以不会漏
```

---

### 复杂度

- 时间复杂度：`O(n^3)`
- 空间复杂度：`O(1)`

---

### 这个方法慢在哪里

慢在：

```text
后两个数仍然是完全暴力地一个一个试
```

也就是说，固定第一个数之后，我们还是在剩余区间里做双重枚举。

所以接下来最自然的优化方向就是：

```text
固定一个数之后，能不能更快找到“最接近 target 的另外两个数”？
```

这就引到排序 + 双指针。

---

## 方法二：排序 + 双指针（面试主推）

这是这题最经典、也最适合面试写的解法。

---

### 第一步：先排序

排序后，数组从小到大排列。

这一步的意义不是去重，而是为了让指针移动具备明确方向。

因为只有在有序数组里，我们才知道：

- 左指针右移，数值会变大
- 右指针左移，数值会变小

这正是双指针成立的基础。

---

### 第二步：固定一个数，把问题变成“两数尽量接近某个目标”

假设我们固定了 `nums[i]`，那么问题就变成：

```text
在 i 右边的区间里，找两个数，让它们的和尽量接近 target - nums[i]
```

也就是说，原题被拆成了：

```text
固定一个数 + 在右边找最接近的两数之和
```

这和第 15 题的思路很像，只不过：

- 第 15 题追求“恰好等于 0”
- 这题追求“尽量接近 target”

---

### 第三步：为什么双指针可以工作

固定 `nums[i]` 后，设：

- `left = i + 1`
- `right = n - 1`

当前三数之和是：

```text
total = nums[i] + nums[left] + nums[right]
```

如果：

- `total < target`，说明当前和偏小，想更接近 `target`，就应该让和变大，所以 `left += 1`
- `total > target`，说明当前和偏大，想更接近 `target`，就应该让和变小，所以 `right -= 1`
- `total == target`，说明已经完全命中，距离是 `0`，不可能再有更好的答案，可以直接返回

这一步的关键不是背模板，而是理解：

```text
排序后，指针移动会让和朝着可预测的方向变化
```

---

### 第四步：为什么只维护一个 `ans` 就够了

这题不需要保存所有组合。

我们真正关心的只有一件事：

```text
到目前为止，哪个三数之和离 target 最近
```

所以用一个变量 `ans` 记录当前最优答案就够了。

每次看到新的 `total`，只要它更接近 `target`，就更新：

```text
ans = total
```

这题和第 15 题最大的区别就在这里：

```text
第 15 题要收集所有答案
第 16 题只维护一个最优值
```

---

### 第五步：这题不需要像第 15 题那样做结果去重

这一点很容易在两题之间串台。

第 15 题一定要去重，是因为答案是一个“三元组列表”，重复三元组不能重复放入结果。

但这题返回的是：

```text
一个最接近的和
```

就算你在遍历过程中碰到了相同的三数之和，也不会影响正确性，因为我们只是拿它和 `ans` 比较。

所以这题的面试版代码可以比第 15 题更简洁。

---

### 用例子把过程走一遍

输入：

```text
nums = [-1, 2, 1, -4], target = 1
```

排序后：

```text
[-4, -1, 1, 2]
```

先初始化：

```text
ans = -4 + -1 + 1 = -4
```

---

### 第一轮：固定 `nums[0] = -4`

此时：

```text
left = 1
right = 3
```

当前和：

```text
total = -4 + -1 + 2 = -3
```

它和 `target = 1` 的距离是：

```text
abs(-3 - 1) = 4
```

比原来的 `ans = -4` 更近，所以更新：

```text
ans = -3
```

因为：

```text
-3 < 1
```

说明和偏小，所以让 `left` 右移，尝试把和变大。

---

继续：

```text
left = 2
right = 3
```

当前和：

```text
total = -4 + 1 + 2 = -1
```

距离变成：

```text
abs(-1 - 1) = 2
```

更近了，所以更新：

```text
ans = -1
```

此时还是偏小，所以 `left` 再右移，循环结束。

---

### 第二轮：固定 `nums[1] = -1`

此时：

```text
left = 2
right = 3
```

当前和：

```text
total = -1 + 1 + 2 = 2
```

距离是：

```text
abs(2 - 1) = 1
```

比 `ans = -1` 更近，所以更新：

```text
ans = 2
```

然后：

```text
2 > 1
```

说明和偏大，要移动 `right` 左移。

之后 `left` 和 `right` 相遇，遍历结束。

最终答案就是：

```text
2
```

---

## 为什么这个方法最适合面试

这题最优解就是最适合面试的方法，原因很直接：

1. 复杂度从 `O(n^3)` 降到了 `O(n^2)`。
2. 写法和第 15 题一脉相承，容易从已有经验里迁移出来。
3. 代码不复杂，核心逻辑只有“排序、固定一个数、双指针逼近、维护当前最优值”这几步。

如果面试官问“你是怎么想到的”，可以这样讲：

```text
先从三重循环出发
-> 发现固定一个数之后，后两个数没必要再完全暴力
-> 想利用有序性来判断该往哪边移动
-> 所以先排序，再用双指针逼近 target
-> 在过程中持续维护最接近 target 的 ans
```

这个推导过程是顺的，不是硬背出来的。

---

## 复杂度

### 方法一：三重循环暴力枚举

- 时间复杂度：`O(n^3)`
- 空间复杂度：`O(1)`

### 方法二：排序 + 双指针

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)` 额外空间

严格来说，排序过程可能带来 `O(log n)` 的栈空间，但面试里通常仍把它记作额外空间 `O(1)`。

---

## 总结

这题最值得记住的不是“套一个双指针模板”，而是下面这条思路：

```text
固定一个数之后，剩下的问题其实是在有序区间里找最接近目标的两数之和
```

一旦你真的理解了这句话，就能自然地写出：

```text
排序 + 固定一个数 + 双指针 + 维护当前最优值
```

这就是这题最稳定的面试解法。
