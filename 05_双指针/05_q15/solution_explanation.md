# LeetCode 15. 三数之和（3Sum）解析

## 题目描述

给定一个整数数组 `nums`，请你找出所有满足下面条件的三元组：

- 下标互不相同
- 三个数的和等于 `0`
- 结果里不能有重复三元组

例如：

```text
nums = [-1, 0, 1, 2, -1, -4]
```

答案是：

```text
[[-1, -1, 2], [-1, 0, 1]]
```

---

## 先理解题意

这题最容易混淆的地方有两个：

1. 返回的是“三元组的数值”，不是下标。
2. 不能出现重复答案，但数组里本身可以有重复元素。

比如：

```text
nums = [0, 0, 0, 0]
```

虽然能从 4 个 `0` 里选出很多组三元组，但答案只能保留一个：

```text
[[0, 0, 0]]
```

所以这题真正的难点不是“找三个数和为 0”，而是：

```text
既要找到所有解，还要把重复解处理干净
```

---

## 方法一：三重循环 + 集合去重

### 思路

最直接的想法就是枚举所有三元组：

- 第一个位置选 `i`
- 第二个位置选 `j`
- 第三个位置选 `k`

只要满足：

```text
i < j < k
```

就能保证三个位置互不相同，而且不会重复枚举同一组下标。

然后检查：

```text
nums[i] + nums[j] + nums[k] == 0
```

如果成立，就把这个三元组加入结果。

但这里马上会遇到一个问题：

```text
数组里有重复数字时，可能找到重复三元组
```

所以我们先对数组排序，再把三元组放进集合里去重。

---

### 为什么可行

因为它把所有可能的三元组都试了一遍。

只要某组解存在，遍历到那三个位置时就一定会被找到。

排序只是为了让同一个三元组写成统一形式，方便放进集合去重，不影响正确性。

---

### 复杂度

- 时间复杂度：`O(n^3)`
- 空间复杂度：`O(m)`，`m` 是去重集合里保存的三元组数量

---

### 这个方法慢在哪里

它的问题不是“想不到”，而是：

```text
明明很多组合已经不可能了，还是老老实实全试一遍
```

所以接下来要优化的方向很自然：

```text
固定一个数之后，后面两个数能不能别再暴力枚举？
```

这就引到双指针。

---

## 方法二：排序 + 双指针（面试主推）

这是本题最经典、也最适合面试写的解法。

---

### 第一步：先排序

排序后，数组会变成从小到大。

这一步非常关键，因为它同时解决了两件事：

1. 可以利用“有序”来移动指针。
2. 可以更自然地去重。

例如：

```text
[-1, 0, 1, 2, -1, -4]
```

排序后变成：

```text
[-4, -1, -1, 0, 1, 2]
```

---

### 第二步：固定一个数，把问题变成“两数之和”

如果我们固定 `nums[i]`，那么剩下的目标就变成：

```text
在 i 后面的区间里，找两个数，使它们的和等于 -nums[i]
```

也就是说，三数之和被拆成了：

```text
固定一个数 + 在右侧找两数之和
```

这一步是整题最核心的转化。

---

### 第三步：为什么可以用双指针

因为数组已经有序。

设：

- 左指针 `left = i + 1`
- 右指针 `right = n - 1`

当前和是：

```text
total = nums[i] + nums[left] + nums[right]
```

如果：

- `total < 0`，说明和太小了，要让它变大，所以 `left += 1`
- `total > 0`，说明和太大了，要让它变小，所以 `right -= 1`
- `total == 0`，说明找到一个答案

这里双指针能成立，本质上就是利用了排序后的单调性。

---

### 第四步：最关键的细节是去重

这题真正容易写错的不是双指针本身，而是去重。

#### 外层去重

如果当前固定的数和前一个一样：

```text
nums[i] == nums[i - 1]
```

那就直接跳过。

原因是：

```text
以前一个相同数字开头的所有组合，上一轮已经找过了
```

---

#### 内层去重

当我们找到一个三元组后，不能只简单地 `left += 1`、`right -= 1`，还要继续跳过重复值。

例如当前找到：

```text
[-1, 0, 1]
```

如果下一个 `left` 还是 `0`，或者下一个 `right` 还是 `1`，那会再次得到同样的三元组。

所以找到答案后要继续做：

- 左边跳过连续重复值
- 右边跳过连续重复值

这样才能保证结果不重复。

---

### 为什么 `nums[i] > 0` 时可以直接结束

排序后，如果当前固定数已经大于 `0`，那它右边的数只会更大。

这时三个数的和一定大于 `0`，不可能再找到答案，所以可以直接 `break`。

这是一个很自然、也很常见的剪枝。

---

### 用一个小例子串起来

排序后数组：

```text
[-4, -1, -1, 0, 1, 2]
```

当 `i = 1`，固定 `nums[i] = -1`：

- `left = 2`，`right = 5`
- 三数和是 `-1 + -1 + 2 = 0`，得到 `[-1, -1, 2]`
- 然后左右指针继续收缩，并跳过重复值
- 接着又会找到 `[-1, 0, 1]`

当 `i = 2` 时，`nums[2]` 还是 `-1`，和前一个固定数一样，所以直接跳过。

这就是“排序 + 双指针 + 去重”三件事如何配合起来工作的。

---

## 为什么这个方法最适合面试

这题的最优解就是最适合面试的方法，原因有三点：

1. 时间复杂度从 `O(n^3)` 降到 `O(n^2)`，优化很明显。
2. 写法不依赖复杂数据结构，面试现场更容易稳定写对。
3. 思路非常好解释：排序、固定一个数、双指针逼近、找到后去重。

如果面试官追问“你是怎么想到的”，可以按下面这条线讲：

```text
先从暴力三重循环出发
-> 发现后两个数没必要继续暴力枚举
-> 想把问题转成两数之和
-> 为了能用双指针，先排序
-> 最后补上外层和内层去重
```

这条推导链非常完整，面试里会比只背模板更有说服力。

---

## 复杂度

### 方法一：三重循环 + 集合去重

- 时间复杂度：`O(n^3)`
- 空间复杂度：`O(m)`

### 方法二：排序 + 双指针

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)` 额外空间

严格来说，排序本身可能带来 `O(log n)` 的栈空间，但通常面试里会把这题记作额外空间 `O(1)`。

---

## 总结

这题最值得记住的不是“双指针模板”四个字，而是下面这句话：

```text
排序让我们既能根据和的大小移动指针，也能自然地去重
```

只要真正理解了这一点，这题就不是死记硬背，而是可以自己推出来的。
