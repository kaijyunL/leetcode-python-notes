# LeetCode 209. 长度最小的子数组解析

## 题目描述

给定一个含有 `n` 个正整数的数组 `nums` 和一个正整数 `target`。

请你找出该数组中满足其和大于等于 `target` 的长度最小的连续子数组，并返回它的长度。

如果不存在符合条件的子数组，返回 `0`。

例如：

```text
target = 7, nums = [2, 3, 1, 2, 4, 3]
```

答案是：

```text
2
```

因为：

```text
[4, 3]
```

的和刚好是 `7`，而且长度最短。

---

## 先理解题意

这题最关键的要求有三个：

1. 必须是连续子数组。
2. 要求子数组和 `>= target`。
3. 在所有满足条件的连续子数组里，找长度最小的那个。

这题还有一个非常重要、决定解法方向的条件：

```text
nums 里的数全都是正整数
```

这句话非常关键。

因为“全为正数”意味着：

- 窗口右边加一个数，总和只会变大
- 窗口左边删一个数，总和只会变小

后面的滑动窗口解法，成立的根本原因就在这里。

---

## 方法一：暴力枚举起点，再向右累加

### 思路

最直接的想法是：

- 枚举每个起点 `left`
- 从这个起点开始，向右不断累加
- 一旦当前和已经 `>= target`，就可以用当前长度更新答案

由于数组里全是正数，所以从固定起点往右扩展时：

```text
和只会越来越大
```

因此一旦某个 `right` 已经让和达到 `target`，再继续往右扩只会让长度更长，不可能更优，所以可以直接 `break`。

这比“枚举所有子数组再重新求和”的纯暴力更合理。

---

### 为什么可行

因为它对每个起点都尝试了所有可能的最短终点。

只要某个最优子数组存在，那么当 `left` 枚举到它的起点时，向右累加的过程一定会在第一次达到 `target` 时命中它的最短长度。

---

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

---

### 这个方法慢在哪里

慢在：

```text
每换一个 left，右边的累加过程都要重新来一遍
```

也就是说，不同起点之间没有共享信息。

所以接下来会自然想到：

```text
能不能让右边不要每次都回到 left，而是在整体上一路向右走？
```

这就引到滑动窗口。

---

## 方法二：前缀和 + 二分查找

### 思路

这题因为所有数都为正，所以前缀和数组一定严格递增。

设：

```text
prefix[i] = nums[0] 到 nums[i - 1] 的和
```

那么任意子数组 `nums[left:right]` 的和就是：

```text
prefix[right] - prefix[left]
```

如果我们固定左端点 `left`，要求：

```text
prefix[right] - prefix[left] >= target
```

移项后就是：

```text
prefix[right] >= prefix[left] + target
```

所以问题变成：

```text
在 prefix 里，找第一个 >= prefix[left] + target 的位置
```

因为 `prefix` 严格递增，所以可以二分查找。

---

### 为什么这一步成立

核心就在于：

```text
nums 全是正数 -> prefix 严格递增
```

如果数组里有负数，前缀和就不再单调，二分查找也就不能直接用了。

---

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：`O(n)`

---

### 这个方法和最优解相比差在哪里

它已经比 `O(n^2)` 好很多，但还不是最优。

因为这题不是在做很多次独立查询，而是在一段连续区间上反复调整左右边界。

既然所有数都为正，其实不需要每次都二分，可以直接用滑动窗口在线性时间里完成。

---

## 方法三：滑动窗口（面试主推）

这是本题最适合面试的解法。

---

### 核心想法

维护一个窗口：

```text
nums[left:right + 1]
```

并维护这个窗口的当前和 `window_sum`。

窗口的策略很简单：

1. 先让 `right` 向右扩张，把和加大
2. 一旦 `window_sum >= target`，说明当前窗口已经达标
3. 这时尝试移动 `left` 缩小窗口，看看能不能在仍然达标的前提下把长度变短

这就是“可变窗口最短长度”题的标准思路。

---

### 为什么这个窗口可以这样滑

这一点必须说清楚。

因为数组里的数全是正数，所以：

- `right` 右移，窗口和一定不减
- `left` 右移，窗口和一定不增

因此：

- 当和还不够时，只能靠扩张右边让它变大
- 当和已经够了时，就应该尽量缩左边，看能不能把长度压到更短

如果数组里允许负数，这个逻辑就会失效。

所以本题滑动窗口成立，不是因为“背模板”，而是因为：

```text
正数数组保证了窗口和对左右边界的变化具有单调性
```

---

### 用例子走一遍

输入：

```text
target = 7
nums = [2, 3, 1, 2, 4, 3]
```

开始时：

```text
left = 0
window_sum = 0
ans = 正无穷
```

---

### `right = 0`

加入 `2`：

```text
window_sum = 2
```

还没达到 `7`，继续扩张。

---

### `right = 1`

加入 `3`：

```text
window_sum = 5
```

还不够，继续扩张。

---

### `right = 2`

加入 `1`：

```text
window_sum = 6
```

还不够，继续扩张。

---

### `right = 3`

加入 `2`：

```text
window_sum = 8
```

现在已经 `>= 7` 了，说明当前窗口 `[2, 3, 1, 2]` 可行，长度是 `4`。

先更新：

```text
ans = 4
```

然后开始收缩左边：

- 移出 `2`
- `left` 从 `0` 变成 `1`
- `window_sum = 6`

现在又小于 `7` 了，不能再缩，重新扩张右边。

---

### `right = 4`

加入 `4`：

```text
window_sum = 10
```

当前窗口 `[3, 1, 2, 4]` 可行，长度 `4`。

更新后尝试收缩：

- 移出 `3`，`window_sum = 7`，长度变成 `3`
- 仍然达标，所以继续更新 `ans = 3`
- 再移出 `1`，`window_sum = 6`

这时不达标，停止收缩。

---

### `right = 5`

加入 `3`：

```text
window_sum = 9
```

当前窗口 `[2, 4, 3]` 可行，长度 `3`。

继续收缩：

- 移出 `2`，`window_sum = 7`，窗口 `[4, 3]`
- 长度变成 `2`，更新 `ans = 2`
- 再移出 `4` 后就不达标了

最终答案就是：

```text
2
```

---

### 为什么时间复杂度是 `O(n)`

虽然代码里会看到一个 `for` 和一个 `while`，但整体不是 `O(n^2)`。

原因是：

- `right` 只会从左到右走一遍
- `left` 也只会从左到右走一遍

每个元素最多：

- 被 `right` 加进窗口一次
- 被 `left` 移出窗口一次

所以总操作次数是线性的。

---

### 为什么这是最适合面试的方法

这题的最优解就是最适合面试的方法，原因很直接：

1. 复杂度最好：`O(n)`。
2. 思路非常贴合题目条件，“正整数数组”这个关键信息被真正用上了。
3. 代码短，而且每一步都好解释。

如果面试官问“你是怎么想到的”，可以按这条线说：

```text
先从固定 left 向右累加出发
-> 发现不同 left 之间有大量重复工作
-> 由于数组全是正数，窗口和对左右边界变化有单调性
-> 所以可以用滑动窗口维护一个当前达标/不达标的区间
-> 不够就扩右边，够了就缩左边
```

这条推导链是完整的，不是硬套模板。

---

## 方法对比

| 方法 | 思路 | 时间复杂度 | 空间复杂度 | 面试建议 |
|---|---|---:|---:|---|
| 方法一 | 固定起点，向右累加到达标为止 | `O(n^2)` | `O(1)` | 过渡思路 |
| 方法二 | 前缀和 + 二分查找 | `O(n log n)` | `O(n)` | 补充思路 |
| 方法三 | 滑动窗口 | `O(n)` | `O(1)` | **面试主推** |

---

## 总结

这题最值得记住的不是“滑动窗口模板”，而是下面这句话：

```text
因为数组全是正数，所以窗口扩大时和只会变大，窗口缩小时和只会变小
```

一旦真正理解了这件事，就能自然推出：

```text
不够就扩右边，够了就缩左边
```

这就是本题最核心的解题逻辑。
