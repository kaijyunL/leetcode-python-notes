# 91. Decode Ways

## 题目理解

一串数字可以按下面规则映射成字母：

- `'1' -> 'A'`
- `'2' -> 'B'`
- ...
- `'26' -> 'Z'`

现在给你一个只包含数字的字符串 `s`，请你计算：

> 这个字符串一共有多少种解码方法。

例如：

- `s = "12"`，答案是 `2`
  - `"1" + "2"` -> `AB`
  - `"12"` -> `L`
- `s = "226"`，答案是 `3`
  - `"2" + "2" + "6"`
  - `"22" + "6"`
  - `"2" + "26"`
- `s = "06"`，答案是 `0`
  - 因为 `0` 不能单独解码

这道题最容易卡住的地方是：

1. `0` 不能单独解码
2. 只有 `10` 到 `26` 之间的两位数才能一起解码

所以它本质上是一个：

> 每个位置都要判断“取一位”还是“取两位”的计数型动态规划问题。

---

## 为什么这题我写 4 种方法

这题和第 70 题、198 题很像，天然适合完整走一遍：

```text
暴力递归 -> 记忆化递归 -> DP -> 状态压缩
```

而且这题的难点不在递推形式本身，而在：

- 合法性判断
- 边界处理
- `0` 的处理

所以把 4 个层次完整走一遍，教学价值很高。

---

## 方法一：暴力递归

### 思路

假设我们站在下标 `i`，要解码 `s[i:]`。

当前位置有两种可能：

1. **取一位**
   - 前提是 `s[i] != '0'`
   - 然后去解码后面的 `s[i+1:]`
2. **取两位**
   - 前提是 `s[i:i+2]` 构成的数字在 `10` 到 `26` 之间
   - 然后去解码后面的 `s[i+2:]`

所以定义：

```text
dfs(i) = 从下标 i 开始的子串有多少种解码方法
```

那么：

```text
dfs(i) = dfs(i + 1) + dfs(i + 2)
```

但这不是无条件相加，而是要看“一位”和“两位”是否有效。

### 代码

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)

        def dfs(i: int) -> int:
            if i == n:
                return 1
            if s[i] == '0':
                return 0

            ways = dfs(i + 1)

            if i + 1 < n and 10 <= int(s[i:i + 2]) <= 26:
                ways += dfs(i + 2)

            return ways

        return dfs(0)
```

### 为什么会慢

因为很多状态会重复计算。

比如：

- `dfs(0)` 可能会去调用 `dfs(2)`
- `dfs(1)` 也可能会去调用 `dfs(2)`

同一个位置后面的解码方法数被反复计算了很多次。

### 复杂度

- 时间复杂度：`O(2^n)`
- 空间复杂度：`O(n)`（递归栈）

### 评价

这个方法适合理解转移的来源，但不适合作为最终答案。

## 方法二：记忆化递归

### 思路

既然暴力递归慢，是因为同一个 `dfs(i)` 被反复算，那就把结果存下来。

定义：

```text
memo[i] = 从下标 i 开始的子串有多少种解码方法
```

每次递归时：

- 如果 `i` 已经算过，直接返回
- 否则再继续递归并存入 `memo`

### 代码

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)
        memo = {}

        def dfs(i: int) -> int:
            if i == n:
                return 1
            if s[i] == '0':
                return 0
            if i in memo:
                return memo[i]

            ways = dfs(i + 1)

            if i + 1 < n and 10 <= int(s[i:i + 2]) <= 26:
                ways += dfs(i + 2)

            memo[i] = ways
            return memo[i]

        return dfs(0)
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 评价

这个方法已经很好了。

优点：

- 保留了递归思路
- 能很清楚地看出“每个位置只算一次”

缺点：

- 仍然有递归栈
- 仍然需要额外字典

## 方法三：动态规划

### 思路

递归定义是：

```text
dfs(i) = 从下标 i 开始的子串有多少种解码方法
```

我们可以把它改写成 DP。

定义：

```text
dp[i] = 前 i 个字符（即 s[:i]）的解码方法数
```

这个定义在这题里更方便处理边界。

先看当前位置 `s[i-1]`：

#### 情况 1：单独取一位

如果 `s[i-1] != '0'`，那么它可以单独解码。

这时：

```text
dp[i] += dp[i - 1]
```

#### 情况 2：取最后两位一起解码

如果 `s[i-2:i]` 在 `10` 到 `26` 之间，那么最后两位可以作为一个整体。

这时：

```text
dp[i] += dp[i - 2]
```

初始值：

```text
dp[0] = 1
```

表示空字符串有 1 种“完成解码”的方式，这个初始化非常关键。

### 代码

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)
        dp = [0] * (n + 1)
        dp[0] = 1
        dp[1] = 0 if s[0] == '0' else 1

        for i in range(2, n + 1):
            if s[i - 1] != '0':
                dp[i] += dp[i - 1]

            two_digits = int(s[i - 2:i])
            if 10 <= two_digits <= 26:
                dp[i] += dp[i - 2]

        return dp[n]
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 为什么这题的 DP 定义要这么写

很多人会想定义：

```text
dp[i] = 以 i 结尾的解码方法数
```

但这样边界会更绕。

定义成：

```text
dp[i] = 前 i 个字符的解码方法数
```

会更自然，因为：

- 单独取最后一位时，看 `dp[i-1]`
- 最后两位一起取时，看 `dp[i-2]`

这和很多字符串 DP 题的写法很一致。

### 评价

这是这道题最标准、最稳妥的 DP 写法。

## 方法四：状态压缩（最优解）

### 思路

观察方法三：

每次计算 `dp[i]` 时，只会用到：

- `dp[i - 1]`
- `dp[i - 2]`

所以整张数组没必要保留。

我们只需要：

- `dp_i_2`：表示 `dp[i - 2]`
- `dp_i_1`：表示 `dp[i - 1]`
- `curr`：表示当前 `dp[i]`

每一步重新根据“一位是否合法”和“两位是否合法”来更新 `curr`。

### 代码

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)
        dp_i_2 = 1
        dp_i_1 = 0 if s[0] == '0' else 1

        for i in range(2, n + 1):
            curr = 0

            if s[i - 1] != '0':
                curr += dp_i_1

            two_digits = int(s[i - 2:i])
            if 10 <= two_digits <= 26:
                curr += dp_i_2

            dp_i_2 = dp_i_1
            dp_i_1 = curr

        return dp_i_1
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

### 评价

这是这道题最推荐的最优写法。

优点：

- 时间最优
- 空间最优
- 逻辑仍然很清楚
- 很适合面试手写

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法四，状态压缩版动态规划。**

但最好的表达方式不是一上来直接写压缩版，而是：

> 先讲清楚“最后一位单独解码”和“最后两位一起解码”这两个分支，再自然压缩到常数空间。

---

## 最适合面试的方法：详细讲解

### 第一步：先明确每个位置的最后一步怎么来

对于前 `i` 个字符的解码方式，最后一步只有两种可能：

1. **最后一个字符单独解码**
2. **最后两个字符一起解码**

所以这题本质上是一个“分最后一步讨论”的 DP。

---

### 第二步：为什么单独看最后一位时要判断不是 `0`

因为只有：

```text
'1' 到 '9'
```

才能单独映射成字母。

而：

```text
'0'
```

本身没有对应字母。

所以如果 `s[i-1] == '0'`，那么“最后一位单独解码”这一条路是走不通的。

---

### 第三步：为什么最后两位只能在 10 到 26 之间

因为题目只允许：

```text
1 -> A
2 -> B
...
26 -> Z
```

所以两位数必须满足：

```text
10 <= int(s[i-2:i]) <= 26
```

像：

- `06` 不行
- `30` 不行
- `27` 不行
- `10` 可以
- `26` 可以

这是这题最关键的合法性判断。

---

### 第四步：转移方程怎么写

定义：

```text
dp[i] = 前 i 个字符的解码方法数
```

那么：

#### 如果最后一位能单独解码

```text
dp[i] += dp[i - 1]
```

#### 如果最后两位能一起解码

```text
dp[i] += dp[i - 2]
```

所以：

```text
if s[i-1] != '0':
    dp[i] += dp[i-1]
if 10 <= int(s[i-2:i]) <= 26:
    dp[i] += dp[i-2]
```

---

### 第五步：为什么 `dp[0] = 1` 很重要

这点非常容易被忽略。

`dp[0] = 1` 不是说“空字符串有 1 种字母解码方式”，而是说：

> 空字符串作为递推起点，表示前面已经成功完成了一种合法拆分。

如果没有这个初始值，像 `"10"`、`"12"` 这样的转移会很难统一处理。

---

### 第六步：用例子走一遍

以：

```text
s = "226"
```

为例。

初始化：

```text
dp[0] = 1
dp[1] = 1
```

继续：

#### i = 2，对应前两个字符 `"22"`

- 最后一位 `"2"` 合法，所以加 `dp[1] = 1`
- 最后两位 `"22"` 合法，所以加 `dp[0] = 1`

所以：

```text
dp[2] = 2
```

#### i = 3，对应前三个字符 `"226"`

- 最后一位 `"6"` 合法，所以加 `dp[2] = 2`
- 最后两位 `"26"` 合法，所以加 `dp[1] = 1`

所以：

```text
dp[3] = 3
```

最后答案就是 `3`。

---

### 面试时推荐怎么讲

你可以这样讲：

#### 1. 定义状态

```text
dp[i] = 前 i 个字符的解码方法数
```

#### 2. 分两种情况讨论最后一步

- 最后一位单独解码
- 最后两位一起解码

#### 3. 写出合法性判断

- `s[i-1] != '0'`
- `10 <= int(s[i-2:i]) <= 26`

#### 4. 写出转移

```text
if s[i-1] != '0':
    dp[i] += dp[i-1]
if 10 <= int(s[i-2:i]) <= 26:
    dp[i] += dp[i-2]
```

#### 5. 再补一句空间优化

- 因为只依赖前两个状态
- 所以可以压缩成 `O(1)` 空间

这套表达会非常完整。

---

### 面试最推荐代码

```python
class Solution:
    def numDecodings(self, s: str) -> int:
        n = len(s)
        dp_i_2 = 1
        dp_i_1 = 0 if s[0] == '0' else 1

        for i in range(2, n + 1):
            curr = 0

            if s[i - 1] != '0':
                curr += dp_i_1

            two_digits = int(s[i - 2:i])
            if 10 <= two_digits <= 26:
                curr += dp_i_2

            dp_i_2 = dp_i_1
            dp_i_1 = curr

        return dp_i_1
```

## 总结

### 递进关系

1. **暴力递归**
   - 最直观
   - 但有大量重复子问题

2. **记忆化递归**
   - 每个位置只算一次
   - 时间降到 `O(n)`

3. **动态规划**
   - 把“最后一步”分类讨论写成递推
   - 是标准写法

4. **状态压缩**
   - 只保留前两个状态
   - 是最优写法，也是面试最推荐写法

### 一句话记忆

> 前 i 个字符的解码方法数，来自“最后一位单独解码”与“最后两位一起解码”这两种合法情况之和。
