# 300. 最长递增子序列

## 题目理解

给你一个整数数组 `nums`，请你返回：

> 最长严格递增子序列的长度。

注意这里是：

- **子序列**，不是子数组
- **严格递增**，所以后一个数必须 `>` 前一个数

例如：

```text
nums = [10,9,2,5,3,7,101,18]
答案是 4
```

因为一个最长递增子序列可以是：

```text
[2,3,7,101]
```

再比如：

```text
nums = [0,1,0,3,2,3]
答案是 4
```

```text
nums = [7,7,7,7,7,7,7]
答案是 1
```

这题是 LIS（Longest Increasing Subsequence）经典题，也是面试里非常高频的一道动态规划题。

---

## 为什么这题适合按 4 步来学

这题非常适合完整走一遍：

```text
暴力递归 -> 记忆化递归 -> O(n^2) DP -> O(nlogn) 贪心 + 二分
```

因为它的知识点是层层递进的：

1. 先理解“选 / 不选”怎么建模
2. 再理解重复子问题在哪里
3. 再掌握最经典的 `dp[i]` 含义
4. 最后再掌握 LIS 的最优解法

这道题最重要的不只是写出答案，而是要真正理解：

- 为什么 `dp[i]` 要定义成“以 `i` 结尾”
- 为什么贪心 + 二分能优化到 `O(nlogn)`

---

## 方法一：暴力递归

### 思路

先从最直观的做法开始。

来到下标 `i` 时，当前元素 `nums[i]` 只有两种选择：

1. **不选它**
2. **选它**，但前提是它要比上一个已经选的数更大

所以我们可以定义：

```text
dfs(i, prev_index) = 从下标 i 开始考虑，且上一个选中的下标是 prev_index 时，能得到的最长递增子序列长度
```

那么转移就是：

- 不选 `nums[i]`：`dfs(i + 1, prev_index)`
- 如果能选 `nums[i]``：1 + dfs(i + 1, i)`

最后取两者最大值。

### 代码

```python
from typing import List


# 方法一：暴力递归
class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        n = len(nums)

        def dfs(i, prev_index):
            if i == n:
                return 0

            best = dfs(i + 1, prev_index)

            if prev_index == -1 or nums[i] > nums[prev_index]:
                best = max(best, 1 + dfs(i + 1, i))

            return best

        return dfs(0, -1)
```

### 复杂度

- 时间复杂度：`O(2^n)`
- 空间复杂度：`O(n)`

### 评价

这个方法适合理解“状态”和“选 / 不选”的来源。

但它非常慢，因为同一个状态会被重复计算很多次。

---

## 方法二：记忆化递归

### 思路

暴力递归慢的根本原因是：

```text
dfs(i, prev_index)
```

这个状态会被重复计算。

那就很自然：

> 算过的状态存起来，下次直接复用。

我们用一个 `memo` 字典保存：

```text
memo[(i, prev_index)] = 当前状态的答案
```

这样每个状态最多只会算一次。

### 代码

```python
from typing import List


# 方法二：记忆化递归
class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        n = len(nums)
        memo = {}

        def dfs(i, prev_index):
            if i == n:
                return 0
            if (i, prev_index) in memo:
                return memo[(i, prev_index)]

            best = dfs(i + 1, prev_index)

            if prev_index == -1 or nums[i] > nums[prev_index]:
                best = max(best, 1 + dfs(i + 1, i))

            memo[(i, prev_index)] = best
            return best

        return dfs(0, -1)
```

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(n^2)`

### 评价

这个方法已经能过，而且很好地保留了原始递归思路。

优点：

- 容易从暴力递归升级
- 很适合理解状态复用

缺点：

- 仍然是递归
- 状态设计和实现都不如迭代 DP 直观

---

## 方法三：动态规划

### 思路

这是这题最经典的标准做法。

定义：

```text
dp[i] = 以 nums[i] 结尾的最长递增子序列长度
```

为什么要定义成“以 `i` 结尾”？

因为这样当我们要求 `dp[i]` 时，只需要去看前面所有位置 `j`：

- 如果 `nums[j] < nums[i]`
- 那么 `nums[i]` 就可以接在 `nums[j]` 后面

于是：

```text
dp[i] = max(dp[j] + 1), 其中 0 <= j < i 且 nums[j] < nums[i]
```

如果前面没有任何 `j` 能接过来，那它自己单独也能形成长度为 1 的递增子序列：

```text
dp[i] = 1
```

### 代码

```python
from typing import List


# 方法三：动态规划
class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        n = len(nums)
        dp = [1] * n

        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:
                    dp[i] = max(dp[i], dp[j] + 1)

        return max(dp)
```

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(n)`

### 评价

这是 LIS 最经典、最稳的写法。

优点：

- 状态定义特别清楚
- 很适合讲明白为什么正确
- 面试里就算先写这个，也已经是很不错的答案

缺点：

- 不是最优复杂度
- 这题的更高阶写法是 `O(nlogn)`

---

## 方法四：贪心 + 二分查找（最优解）

### 核心思路

这是这题的最优解法，也是 LIS 最有代表性的写法。

我们维护一个数组：

```text
tails[k] = 长度为 k + 1 的递增子序列中，结尾最小的那个结尾值
```

这句话是整道题最关键的地方。

它的意思不是：

```text
tails 本身就是某个真实的 LIS
```

而是：

```text
对于每一种长度，我们只关心“最小 possible 结尾”是多少
```

因为：

> 在长度相同的情况下，结尾越小，后面就越容易接上更大的数。

这就是贪心的核心。

---

### tails 为什么有用

假设现在我们已经找到两种长度都为 3 的递增子序列：

- 一种结尾是 `9`
- 一种结尾是 `5`

那显然：

```text
结尾是 5 的那个更有优势
```

因为未来如果来了一个 `7`：

- 它不能接在 `9` 后面
- 但它可以接在 `5` 后面

所以对于同样的长度，我们只需要保留“结尾更小”的那个。

这就是为什么 `tails` 只记录“最小结尾”。

---

### 每来一个数怎么处理

遍历 `nums` 中的每个 `num`：

#### 情况 1：`num` 比 `tails` 最后一个数还大

说明它可以把当前最长递增子序列再延长一位。

直接追加：

```text
tails.append(num)
```

#### 情况 2：`num` 不能直接接在最后面

那就说明它不能让长度变长。

但它可能可以把某个长度对应的“结尾”变得更小。

这时我们去 `tails` 中找：

```text
第一个 >= num 的位置
```

然后用 `num` 替换它。

这样做不会让最长长度变短，但会让未来更容易接新数字。

这一步要用二分查找来做，才能把复杂度降到 `O(logn)`。

---

### 用例子走一遍

以：

```text
nums = [10,9,2,5,3,7,101,18]
```

为例。

开始时：

```text
tails = []
```

处理 `10`：

```text
[10]
```

处理 `9`：替换第一个 `>= 9` 的位置

```text
[9]
```

处理 `2`：继续替换

```text
[2]
```

处理 `5`：比最后一个大，追加

```text
[2,5]
```

处理 `3`：替换第一个 `>= 3` 的位置

```text
[2,3]
```

处理 `7`：追加

```text
[2,3,7]
```

处理 `101`：追加

```text
[2,3,7,101]
```

处理 `18`：替换第一个 `>= 18` 的位置

```text
[2,3,7,18]
```

最后：

```text
len(tails) = 4
```

所以答案就是 `4`。

注意：

```text
[2,3,7,18]
```

不一定就是我们最终要输出的某条 LIS，但它的长度一定是对的。

---

### 代码

```python
from bisect import bisect_left
from typing import List


# 方法四：贪心 + 二分查找
class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        tails = []

        for num in nums:
            pos = bisect_left(tails, num)

            if pos == len(tails):
                tails.append(num)
            else:
                tails[pos] = num

        return len(tails)
```

### 复杂度

- 时间复杂度：`O(nlogn)`
- 空间复杂度：`O(n)`

### 评价

这是这题最优的标准答案。

优点：

- 复杂度最优
- 是 LIS 的高频面试写法
- 很能体现你对这题本质的理解

难点：

- 比 `O(n^2)` DP 更抽象
- 如果没有把 `tails` 的含义讲清楚，很容易写对了但说不明白

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法四，贪心 + 二分查找。**

但这题最好的面试表达不是“一上来只写最优解”，而是：

1. 先快速讲清楚 `O(n^2)` DP 的状态定义
2. 再主动补充可以优化到 `O(nlogn)`
3. 最后写出贪心 + 二分版本

这样会显得你：

- 基础扎实
- 会标准 DP
- 也掌握这题的最优解法

所以对 300 这题来说，最推荐的面试策略是：

> **先会方法三，再把方法四作为最终面试答案。**

---

## 最适合面试的方法：详细讲解

### 第一步：先明确我们到底在维护什么

很多人第一次学 `O(nlogn)` 写法时，最容易误解的是：

```text
tails 是不是当前某条最长递增子序列？
```

不是。

更准确地说：

```text
tails[i] 表示长度为 i + 1 的递增子序列里，最小 possible 结尾值
```

这个定义非常重要，因为它解释了为什么可以替换。

---

### 第二步：为什么“结尾更小”更优

假设有两条长度都为 4 的递增子序列：

- 一条结尾是 `20`
- 一条结尾是 `11`

那未来如果来了一个 `15`：

- 接不上 `20`
- 但能接上 `11`

所以长度一样时，我们当然更想保留结尾更小的那个。

这就是贪心依据：

> **同长度下，结尾越小越有潜力。**

---

### 第三步：为什么替换不会出错

当我们找到 `tails` 中第一个 `>= num` 的位置并替换时，本质是在说：

```text
我没有增加 LIS 的长度
但我让某个长度的结尾变得更小了
```

这件事只会让后续更有利，不会更差。

因为：

- 长度没变
- 结尾更小
- 可扩展性更强

所以替换是安全的。

---

### 第四步：为什么要找“第一个 >= num”的位置

因为我们希望：

- 尽量把 `num` 放到更靠前的位置
- 这样它对应的长度尽可能短
- 同时又能保证递增结构不被破坏

找第一个 `>= num` 的位置，恰好就能做到这件事。

这也是标准的二分查找场景。

---

### 第五步：为什么 `len(tails)` 就是答案

`tails` 的下标和长度是一一对应的：

- `tails[0]` 表示长度为 1 的最小结尾
- `tails[1]` 表示长度为 2 的最小结尾
- ...

所以如果 `tails` 当前长度是 4，就说明：

```text
已经存在长度为 4 的递增子序列
```

而如果还能形成更长的递增子序列，`tails` 也一定会继续变长。

因此最终：

```text
len(tails)
```

就是 LIS 长度。

---

### 第六步：面试里推荐怎么讲

你可以这样讲：

#### 1. 先给出基础 DP 版本

```text
dp[i] = 以 nums[i] 结尾的最长递增子序列长度
```

这是标准 `O(n^2)` 解法。

#### 2. 再说可以优化

因为题目是 LIS 经典题，还可以优化到 `O(nlogn)`。

#### 3. 再解释 tails 含义

```text
tails[i] 表示长度为 i + 1 的递增子序列的最小结尾值
```

#### 4. 说明两种更新方式

- 如果 `num` 大于 `tails` 最后一个值，直接追加
- 否则二分找到第一个 `>= num` 的位置替换

#### 5. 最后给出复杂度

- 每个数处理一次
- 每次二分 `O(logn)`
- 总复杂度 `O(nlogn)`

这套表达会很完整，而且很像真正面试里的高质量回答。

---

### 面试最推荐代码

```python
from bisect import bisect_left
from typing import List


class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        tails = []

        for num in nums:
            pos = bisect_left(tails, num)

            if pos == len(tails):
                tails.append(num)
            else:
                tails[pos] = num

        return len(tails)
```

## 总结

### 递进关系

1. **暴力递归**
   - 学会从“选 / 不选”建模
   - 但复杂度太高

2. **记忆化递归**
   - 消除重复子问题
   - 复杂度降到 `O(n^2)`

3. **动态规划**
   - 掌握经典状态：`dp[i]` 表示以 `i` 结尾
   - 是最标准的基础写法

4. **贪心 + 二分查找**
   - 最优解法
   - 是这题最推荐的面试答案

### 一句话记忆

> `O(n^2)` DP 关注“以每个位置结尾的最优值”，`O(nlogn)` 解法关注“每种长度下最小 possible 结尾”。
