# 70. Climbing Stairs

## 题目理解

你正在爬楼梯。到达第 `n` 阶台阶，方法有多少种？

每次你可以爬 `1` 阶或 `2` 阶。

例如：

- `n = 1`，只有 1 种走法：`1`
- `n = 2`，有 2 种走法：`1+1`、`2`
- `n = 3`，有 3 种走法：`1+1+1`、`1+2`、`2+1`

这道题的关键不是把所有路径真的列出来，而是找到“走到第 i 阶”和前面状态之间的关系。

---

## 方法一：暴力递归

### 思路

如果我要走到第 `n` 阶，那么最后一步只有两种可能：

- 从第 `n-1` 阶走 `1` 步上来
- 从第 `n-2` 阶走 `2` 步上来

所以：

```text
f(n) = f(n - 1) + f(n - 2)
```

边界：

```text
f(1) = 1
f(2) = 2
```

于是最直接的想法就是递归。

### 代码

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        if n == 1:
            return 1
        if n == 2:
            return 2
        return self.climbStairs(n - 1) + self.climbStairs(n - 2)
```

### 为什么慢

比如算 `f(5)`：

```text
f(5)
= f(4) + f(3)
= (f(3) + f(2)) + (f(2) + f(1))
```

你会发现 `f(3)`、`f(2)` 被反复计算了很多次。

这就是**重复子问题**。

### 复杂度

- 时间复杂度：`O(2^n)`
- 空间复杂度：`O(n)`（递归调用栈）

### 评价

这个方法适合理解状态转移的来源，但不适合真正提交，也不适合面试时作为最终答案。

---

## 方法二：记忆化递归

### 思路

既然暴力递归慢，是因为同一个状态被反复计算，那就把算过的结果存起来。

定义 `memo[x]` 表示“走到第 `x` 阶的方法数”。

当我们再次需要 `f(x)` 时：

- 如果已经算过，直接返回
- 如果没算过，再递归去算

### 代码

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        memo = {}

        def dfs(i: int) -> int:
            if i == 1:
                return 1
            if i == 2:
                return 2
            if i in memo:
                return memo[i]
            memo[i] = dfs(i - 1) + dfs(i - 2)
            return memo[i]

        return dfs(n)
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 评价

这个方法已经很优秀了。

优点：

- 保留了递归写法，思路直观
- 把暴力递归优化到了线性时间

缺点：

- 仍然用了额外字典
- 仍然有递归栈

如果面试官接受递归写法，这个答案通常没问题。但一般还可以继续优化到迭代版。

## 方法三：动态规划

### 思路

既然有递推关系：

```text
f(n) = f(n - 1) + f(n - 2)
```

那我们完全可以从小到大把答案推出来。

定义：

```text
dp[i] = 走到第 i 阶的方法数
```

那么：

```text
dp[i] = dp[i - 1] + dp[i - 2]
```

初始值：

```text
dp[1] = 1
dp[2] = 2
```

然后从 `3` 一直推到 `n`。

### 代码

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 2:
            return n

        dp = [0] * (n + 1)
        dp[1] = 1
        dp[2] = 2

        for i in range(3, n + 1):
            dp[i] = dp[i - 1] + dp[i - 2]

        return dp[n]
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 为什么这就是 DP

因为它满足动态规划最典型的两个特征：

1. **最优子结构 / 状态可由更小状态转移而来**
   - `dp[i]` 只依赖 `dp[i - 1]` 和 `dp[i - 2]`
2. **重复子问题**
   - 如果不用缓存或表格，很多状态会被反复计算

---

## 方法四：状态压缩（最优解）

### 思路

观察方法三：

```text
dp[i] = dp[i - 1] + dp[i - 2]
```

实际上我们每次只会用到前两个状态，根本不需要整张 `dp` 表。

所以可以只用两个变量来保存：

- `dp_i_2`：`dp[i - 2]`
- `dp_i_1`：`dp[i - 1]`
- `curr`：当前算出的 `dp[i]`

在第一次进入循环前：

- `dp_i_2 = dp[1] = 1`
- `dp_i_1 = dp[2] = 2`

每次更新：

```text
curr = dp_i_2 + dp_i_1
dp_i_2 = dp_i_1
dp_i_1 = curr
```

然后整体向前滚动。

### 代码

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 2:
            return n

        dp_i_2 = 1
        dp_i_1 = 2

        for _ in range(3, n + 1):
            curr = dp_i_2 + dp_i_1
            dp_i_2 = dp_i_1
            dp_i_1 = curr

        return curr
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

### 评价

这是这道题最常见、最实用的最优写法。

优点：

- 时间最优：线性
- 空间最优：常数
- 代码短，边界清楚
- 非递归，不会有栈深问题

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法四，状态压缩版动态规划。**

### 为什么它最适合面试

面试里通常不只看你会不会做，还看你是否能体现出完整的思考升级过程：

1. 先从题目中看出递推关系
   - `f(n) = f(n - 1) + f(n - 2)`
2. 说明暴力递归为什么会超时
   - 因为有大量重复子问题
3. 给出 DP 或记忆化搜索优化
   - 把时间降到 `O(n)`
4. 再进一步做空间优化
   - 因为只依赖前两个状态，所以能压缩到 `O(1)`

这一整套表达会让面试官觉得你不是“背答案”，而是真的理解了 DP 的推导过程。

### 面试时推荐怎么讲

可以按下面这个顺序讲：

#### 1. 先定义状态

令 `dp[i]` 表示：**走到第 `i` 阶台阶的方法数**。

#### 2. 推导状态转移

走到第 `i` 阶，最后一步只有两种来源：

- 从第 `i-1` 阶走 1 步
- 从第 `i-2` 阶走 2 步

所以：

```text
dp[i] = dp[i - 1] + dp[i - 2]
```

#### 3. 说明初始条件

```text
dp[1] = 1
dp[2] = 2
```

#### 4. 写出 DP 版本

先给出 `O(n)` 空间的正常 DP，说明你思路完整。

#### 5. 再说明为什么可以优化

因为当前状态只依赖前两个状态，所以没必要保存整个数组。

把：

- `dp[i - 2]`
- `dp[i - 1]`

压缩成两个变量即可。

### 面试最推荐代码

```python
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 2:
            return n

        dp_i_2 = 1
        dp_i_1 = 2

        for _ in range(3, n + 1):
            curr = dp_i_2 + dp_i_1
            dp_i_2 = dp_i_1
            dp_i_1 = curr

        return curr
```

### 这题背后真正要学会什么

这道题本质上是在练：

- 如何把问题定义成状态
- 如何找状态转移方程
- 如何识别“只依赖前几个状态”，从而做状态压缩

它是很多一维 DP 题目的起点，比如：

- 打家劫舍
- 解码方法
- 最大子数组和
- 零钱兑换

所以这题不要只记答案，要记住这条思路链：

```text
暴力递归 -> 发现重复子问题 -> DP -> 状态压缩
```

---

## 总结

### 递进关系

1. **暴力递归**
   - 最直观
   - 但有大量重复计算

2. **记忆化递归**
   - 保留递归思路
   - 时间优化到 `O(n)`

3. **动态规划**
   - 从底向上推答案
   - 更稳，更常见

4. **状态压缩**
   - 最优写法
   - 面试最推荐

### 一句话记忆

> 走到第 `i` 阶的方法数 = 走到第 `i-1` 阶的方法数 + 走到第 `i-2` 阶的方法数。

这其实就是一个从题目外壳里包装出来的斐波那契模型。
