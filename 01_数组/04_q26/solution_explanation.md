# LeetCode 26. 删除有序数组中的重复项（Remove Duplicates from Sorted Array）解析

## 题目描述

给定一个 **非严格递增** 的数组 `nums`，要求你 **原地** 删除重复元素，让每个元素只出现一次，并返回去重后的新长度。

题目真正关心的是：

```text
去重后前 k 个位置是否是正确答案
```

其中 `k` 是你返回的新长度。

也就是说，数组后面的内容其实不重要，判题时只看：

- 返回值 `k`
- `nums[:k]` 这段是否正确

例如：

```text
nums = [1, 1, 2]
```

处理后应该返回：

```text
2
```

并且数组前两位变成：

```text
[1, 2]
```

---

## 先理解这题最关键的条件

这题最关键的不是“删除重复”，而是：

```text
数组已经有序
```

有序意味着：

```text
相同的数一定挨在一起
```

比如：

```text
[0, 0, 1, 1, 1, 2, 2, 3]
```

你不会出现这种情况：

```text
前面一个 1，后面隔很远又来了一个 1
```

正因为重复元素是连续出现的，我们才可以只看“当前值和前一个唯一值是不是相同”，而不用回头检查整段数组。

这就是这题能用双指针高效解决的根本原因。

---

## 方法一：额外数组收集唯一值

### 思路

先不考虑“原地”这个要求，最直观的做法是：

1. 新建一个数组 `unique_nums`
2. 从左到右扫描 `nums`
3. 如果当前值和上一个保留的值不同，就加入 `unique_nums`
4. 最后把 `unique_nums` 拷贝回 `nums` 的前面部分
5. 返回 `unique_nums` 的长度

因为数组有序，所以判断“是不是新值”很简单。

只要看：

```text
当前元素是否和前一个保留元素不同
```

就够了。

---

### 代码

```python
class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        if not nums:
            return 0

        unique_nums = [nums[0]]

        for i in range(1, len(nums)):
            if nums[i] != nums[i - 1]:
                unique_nums.append(nums[i])

        for i, num in enumerate(unique_nums):
            nums[i] = num

        return len(unique_nums)
```

---

### 为什么可行

因为数组有序，所以相同元素一定连在一起。

这意味着：

- 如果 `nums[i] == nums[i - 1]`，那它就是重复值
- 如果 `nums[i] != nums[i - 1]`，那它就是一个新的唯一值

所以扫描一遍就能把所有唯一元素收集出来。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 不足在哪里

这个方法的问题是：

```text
它没有真正做到原地去重
```

虽然最后把结果拷回了原数组，但中间还是额外开了一个新数组。

所以它适合理解题目，不是这题最符合要求的解法。

---

## 方法二：双指针原地覆盖（面试主推）

### 核心思路

既然数组有序，那么去重后的结果一定也是按顺序排好的。

我们可以让：

- `slow` 指向“已经处理好的唯一元素序列的最后一个位置”
- `fast` 从左到右扫描后面的元素

如果 `nums[fast]` 和 `nums[slow]` 不同，说明我们找到了一个新的唯一值。

这时只要：

1. `slow += 1`
2. 把 `nums[fast]` 写到 `nums[slow]`

就可以把这个新值接到去重结果后面。

---

### 为什么这样想是对的

最关键的是要明确：

```text
nums[0...slow] 这一段，始终表示已经整理好的去重结果
```

`fast` 的作用只是不断往后看新元素。

一旦发现一个新值，就把它放到去重结果的下一个位置。

所以整个过程其实是在：

```text
边扫描，边把唯一值压缩到数组左边
```

---

### 用例子走一遍

假设：

```text
nums = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]
```

开始时：

- `slow = 0`
- `fast` 从 `1` 开始

此时可以认为：

```text
nums[0...0] = [0]
```

已经是整理好的去重结果。

### 第 1 步：`fast = 1`

看到：

```text
nums[1] = 0
nums[slow] = nums[0] = 0
```

两者相同，说明这是重复元素，不处理。

### 第 2 步：`fast = 2`

看到：

```text
nums[2] = 1
nums[slow] = 0
```

不同，说明 `1` 是新唯一值。

于是：

```text
slow += 1
nums[slow] = nums[2]
```

数组左边变成：

```text
[0, 1, ...]
```

### 第 3 步：继续扫描中间的 `1`

因为它们和 `nums[slow]` 相同，所以都是重复值，跳过。

### 第 4 步：扫描到 `2`

它和当前 `nums[slow] = 1` 不同，所以把它写到下一个位置。

左边结果继续变成：

```text
[0, 1, 2, ...]
```

后面 `3`、`4` 也是同样逻辑。

最后得到：

```text
[0, 1, 2, 3, 4, ...]
```

返回长度 `5`。

---

### 面试代码

```python
class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        if not nums:
            return 0

        slow = 0

        for fast in range(1, len(nums)):
            if nums[fast] != nums[slow]:
                slow += 1
                nums[slow] = nums[fast]

        return slow + 1
```

---

### 这段代码为什么这样写

这里最重要的一句是：

```python
if nums[fast] != nums[slow]:
```

它表示：

```text
当前扫描到的值，是否和“当前去重结果的最后一个值”不同
```

如果不同，就说明发现了新唯一值，应该把它接到去重结果末尾。

而 `slow += 1` 之后再赋值，是因为：

- `slow` 当前停在旧结果的最后一个位置
- 新元素应该写到下一个位置

这正好和“原地压缩”的思路一致。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

因为只扫描一遍数组，并且只用了两个指针。

---

## 为什么这个方法最适合面试

最适合面试的方法就是：

```text
双指针原地覆盖
```

原因有三个。

### 1. 它完全利用了题目的有序条件

这题最值钱的信息就是：

```text
重复元素连续出现
```

双指针正是把这个条件用到了极致。

### 2. 它满足题目的“原地”要求

不需要新数组，直接把答案压到原数组左边。

### 3. 代码短，而且非常自然

逻辑就是：

- `fast` 找新元素
- `slow` 维护去重结果末尾
- 找到新值就往前写

非常适合面试现场复现。

---

## 面试里可以怎么讲

你可以这样解释：

```text
因为数组已经有序，所以重复元素一定连续出现。
我用 slow 指向当前去重结果的最后一个位置，用 fast 从左到右扫描。
如果 nums[fast] 和 nums[slow] 不同，说明遇到了一个新的唯一值，
就把 slow 往前移动一位，再把这个新值写到 slow 的位置。
最后 slow + 1 就是去重后的长度。

这样每个元素只看一次，所以时间复杂度是 O(n)，额外空间复杂度是 O(1)。
```

这就是这题最标准的面试表达。

---

## 总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：额外数组收集唯一值 | `O(n)` | `O(n)` | 直观，适合理解 |
| 方法二：双指针原地覆盖 | `O(n)` | `O(1)` | 面试主推 |

这题最重要的一句话是：

```text
因为数组有序，所以重复元素一定连续出现；只要维护好“去重结果的末尾”，就能原地完成压缩。
```
