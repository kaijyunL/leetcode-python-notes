# LeetCode 169. 多数元素（Majority Element）解析

## 题目描述

给定一个大小为 `n` 的数组 `nums`，返回其中的多数元素。

多数元素指的是：

```text
出现次数严格大于 ⌊n / 2⌋ 的元素
```

题目还给了一个非常关键的保证：

```text
数组非空，并且多数元素一定存在
```

例如：

```text
nums = [2, 2, 1, 1, 1, 2, 2]
```

返回：

```text
2
```

---

## 先理解这题最关键的条件

这题最值钱的信息不是“找出现次数最多的数”，而是：

```text
多数元素的出现次数 > n / 2
```

这句话会带来两个很重要的结论。

### 结论 1：多数元素最多只会有一个

因为如果有两个不同的数都超过 `n / 2`，那总数量就已经超过 `n` 了，不可能成立。

所以答案一定唯一。

### 结论 2：多数元素的总数，比其他所有元素加起来还多

因为它超过一半，所以其余元素总数一定小于一半。

这个结论是摩尔投票法成立的根本原因。

---

## 方法一：暴力计数

### 思路

最直接的做法就是：

1. 枚举数组中的每个数 `num`
2. 再扫一遍数组，统计 `num` 出现了多少次
3. 如果次数大于 `n // 2`，它就是答案

---

### 代码

```python
class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        threshold = len(nums) // 2

        for num in nums:
            count = 0
            for other in nums:
                if other == num:
                    count += 1
            if count > threshold:
                return num
```

---

### 为什么可行

因为它把每个候选数的真实出现次数都算了一遍。

只要某个数超过 `n // 2`，就一定会被找出来。

---

### 为什么会慢

问题在于：

```text
每看一个数，都要重新扫完整个数组
```

所以会有大量重复统计。

---

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

---

## 方法二：哈希表计数

### 核心思路

既然暴力法慢在“重复统计”，那我们就可以在一次遍历里把每个数的出现次数记下来。

具体做法是：

- 用字典 `counts` 记录每个数字出现了几次
- 每读到一个数，就把它的计数加一
- 一旦某个数字的计数超过 `n // 2`，立刻返回

---

### 代码

```python
class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        counts = {}
        threshold = len(nums) // 2

        for num in nums:
            counts[num] = counts.get(num, 0) + 1
            if counts[num] > threshold:
                return num
```

---

### 为什么可行

因为字典帮我们把“统计次数”这件事缓存起来了。

这样每个数只需要处理一次，不用再反复回头数。

而题目又保证多数元素一定存在，所以一旦某个计数超过一半，就可以直接返回。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 这个方法的特点

这个方法有一个很大的优点：

```text
非常容易想到，也非常容易写对
```

如果你在面试里一时没想到更巧的方法，先写哈希表其实是很稳的。

---

## 方法三：排序后取中间值

### 核心思路

因为多数元素的数量超过一半，所以只要把数组排序，它一定会占住中间位置。

也就是说：

```text
排序后，下标 len(nums) // 2 位置的元素一定是多数元素
```

---

### 为什么中间位置一定是它

假设多数元素是 `x`，它出现次数大于 `n / 2`。

那么排序之后，`x` 会形成一大段连续区间，而且这段区间长度超过一半。

既然它超过一半，那无论怎么排，这一段都一定会覆盖数组中间位置。

所以中间位置上的数只能是它。

---

### 代码

```python
class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        nums.sort()
        return nums[len(nums) // 2]
```

---

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：在 Python 里通常按 `O(n)` 理解

---

### 这个方法怎么看

这个方法比暴力法好，也很有启发性，因为它利用了“多数元素会跨过中点”这个性质。

但它不是最优：

- 时间不是线性的
- 还会修改原数组顺序

所以一般不是这题的最终主推答案。

---

## 方法四：摩尔投票法（面试主推）

### 先别急着记模板，先想它为什么成立

这题最难的地方不是代码，而是：

```text
为什么两个变量就够了？
```

核心想法是：

```text
把不同元素两两抵消
```

因为多数元素的个数比其他所有元素加起来还多，所以就算不停地和别的元素互相抵消，它最后也一定会剩下来。

这就是摩尔投票法的本质。

---

### 怎么抵消

我们维护两个变量：

- `candidate`：当前候选人
- `count`：当前候选人的“净领先票数”

遍历数组时：

1. 如果 `count == 0`，说明前面的抵消已经打平了，那就把当前数设成新的候选人
2. 如果当前数等于 `candidate`，说明候选人多一票，`count += 1`
3. 如果当前数不等于 `candidate`，说明来了一张反对票，`count -= 1`

最后留下来的候选人，就是多数元素。

---

### 为什么 `count == 0` 时可以换候选人

因为这表示：

```text
当前候选人和其他数字在前面这段里已经完全打平了
```

既然已经两两抵消干净，那前面这段对最终答案就不再重要了。

接下来谁先出现，就可以把它当成新的候选人重新开始计票。

这一步不是拍脑袋换人，而是因为前面的信息已经“抵消完了”。

---

### 用例子走一遍

假设：

```text
nums = [2, 2, 1, 1, 1, 2, 2]
```

我们一步一步看。

### 第 1 个数：`2`

此时 `count == 0`，所以：

- `candidate = 2`
- 当前数等于候选人，`count = 1`

### 第 2 个数：`2`

当前数还是 `2`：

- `count = 2`

### 第 3 个数：`1`

和候选人不同，抵消一票：

- `count = 1`

### 第 4 个数：`1`

再抵消一票：

- `count = 0`

这表示前面这四个数里，候选人的优势已经被抵消掉了。

### 第 5 个数：`1`

现在 `count == 0`，所以把它设成新候选人：

- `candidate = 1`
- `count = 1`

### 第 6 个数：`2`

不同，抵消：

- `count = 0`

### 第 7 个数：`2`

又是 `count == 0`，设新候选人：

- `candidate = 2`
- `count = 1`

遍历结束，最终候选人是：

```text
2
```

这就是答案。

---

### 为什么最后剩下的一定是多数元素

因为多数元素的数量：

```text
大于其他所有元素数量之和
```

每次“不同元素抵消”时，最多消掉：

- 一个多数元素
- 一个非多数元素

就算一直抵消下去，非多数元素会先被耗尽，而多数元素还会有剩余。

所以最终候选人一定是它。

这也是为什么：

```text
题目保证多数元素一定存在
```

对这个方法非常关键。

---

### 面试代码

```python
class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        candidate = 0
        count = 0

        for num in nums:
            if count == 0:
                candidate = num
            if num == candidate:
                count += 1
            else:
                count -= 1

        return candidate
```

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

## 为什么这个方法最适合面试

这题最适合面试主推的方法就是：

```text
摩尔投票法
```

原因有三个。

### 1. 它把题目的关键条件用到了极致

题目的关键不是一般的“众数”，而是：

```text
超过一半
```

摩尔投票法正是围绕这个条件设计出来的。

### 2. 它同时做到线性时间和常数空间

哈希表虽然也是 `O(n)` 时间，但空间是 `O(n)`。

摩尔投票法把空间也压到了 `O(1)`，这就是它更强的地方。

### 3. 它的代码其实并不长

虽然第一次想到它不容易，但一旦把“不同元素两两抵消”这个核心理解了，代码反而非常短。

所以这题在面试里的最佳节奏通常是：

- 如果第一时间想到哈希表，可以先说出来
- 然后进一步优化到摩尔投票法

这样层次会很好。

---

## 面试里可以怎么讲

你可以这样解释：

```text
因为多数元素出现次数超过一半，所以它的数量比其他所有元素加起来还多。
我可以把不同元素看成互相抵消：每遇到一个和当前候选人不同的数，就消掉候选人的一票。
如果计数降到 0，说明前面这一段已经打平了，就从当前位置重新选择候选人。
最后还能留下来的那个候选人，一定就是多数元素。

这样只需要遍历一次数组，时间复杂度是 O(n)，额外空间复杂度是 O(1)。
```

如果面试官问你“有没有更稳一点的基础写法”，你就补充哈希表法。

---

## 总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力计数 | `O(n^2)` | `O(1)` | 直观，但重复统计太多 |
| 方法二：哈希表计数 | `O(n)` | `O(n)` | 最容易想到，面试保底很稳 |
| 方法三：排序取中间值 | `O(n log n)` | Python 中通常按 `O(n)` 理解 | 有启发性，但不是最优 |
| 方法四：摩尔投票法 | `O(n)` | `O(1)` | 面试主推 |

这题最重要的一句话是：

```text
多数元素不是“出现最多”而已，而是“比其他所有元素加起来还多”，所以它在两两抵消后一定还能剩下。
```
