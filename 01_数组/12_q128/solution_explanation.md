# LeetCode 128. 最长连续序列（Longest Consecutive Sequence）解析

## 题目描述

给定一个未排序的整数数组 `nums`，请你找出其中最长连续序列的长度。

这里的“连续”指的是：

```text
值连续
```

而不是：

```text
在原数组中的位置连续
```

例如：

```text
nums = [100, 4, 200, 1, 3, 2]
```

虽然 `1, 2, 3, 4` 在原数组里并不是挨着放的，但它们的值是连续的，所以答案是：

```text
4
```

题目还要求：

```text
时间复杂度尽量做到 O(n)
```

这句话非常关键，因为它基本上告诉我们：

- 纯暴力可以先想到，但不是最终答案
- 排序法容易想到，但严格来说不是题目要求的最优复杂度
- 最终要往哈希结构上想

---

## 先理解题意

这题有 3 个很容易忽略的点。

### 1. 连续看的是数值，不是下标

比如：

```text
nums = [10, 5, 12, 3, 55, 11, 4]
```

这里最长连续序列是：

```text
3, 4, 5
```

长度是 `3`。

它们在原数组中并不相邻，但这不影响答案。

### 2. 题目只要长度，不要把序列本身返回出来

也就是说，我们最后返回的是：

```text
最长连续序列的元素个数
```

而不是返回 `[1, 2, 3, 4]` 这样的数组。

### 3. 数组里可能有重复值

例如：

```text
nums = [0, 1, 1, 2]
```

最长连续序列仍然是：

```text
0, 1, 2
```

长度是 `3`，不是 `4`。

所以重复元素不能重复计数。

---

## 方法一：暴力枚举每个数，再不断找下一个数

### 思路

最直接的想法是：

- 枚举数组中的每个数 `num`
- 把它当成某个连续序列的开头
- 然后不断检查 `num + 1`、`num + 2`、`num + 3` 是否存在
- 统计这条序列能走多长
- 对所有起点取最大值

例如：

```text
nums = [100, 4, 200, 1, 3, 2]
```

如果从 `1` 开始：

- 找 `2`，存在
- 找 `3`，存在
- 找 `4`，存在
- 找 `5`，不存在

所以这一段长度是 `4`。

### 为什么可行

因为它真的把“以每个数为起点的连续序列”都试了一遍。

只要某条最长序列存在，我们总会在枚举到它的起点时把它数出来。

### 代码

对应代码文件：

```text
01_数组/12_q128/solution_1_brute_force.py
```

### 复杂度

- 时间复杂度：`O(n^3)`
- 空间复杂度：`O(1)`

### 为什么会这么慢

关键慢在这一句：

```python
current + 1 in nums
```

如果 `nums` 是列表，那么 `in` 查找本身就是 `O(n)`。

而我们外面已经有：

- 一层 `for` 枚举每个数
- 一层 `while` 不断尝试向后扩展

所以最坏情况下会到 `O(n^3)`。

比如当数组接近：

```text
[1, 2, 3, 4, ..., n]
```

时，很多重复检查都会发生。

## 方法二：先排序，再线性扫描

### 思路

既然我们想找“连续的数”，一个很自然的想法是：

```text
先排序
```

排序后，连续的值就会排在一起。

例如：

```text
nums = [100, 4, 200, 1, 3, 2]
```

排序后变成：

```text
[1, 2, 3, 4, 100, 200]
```

这时只要从左到右扫一遍：

- 如果当前数等于前一个数加一，说明连续段可以继续
- 如果当前数等于前一个数，说明只是重复值，跳过即可
- 如果都不是，说明连续段断开，需要重新开始统计

### 为什么它比暴力更好

因为排序之后，我们不需要从每个数出发反复去找后继了。

我们只需要：

```text
沿着排序后的数组走一遍
```

这样就把很多重复检查去掉了。

### 例子

看这个例子：

```text
nums = [0, 1, 1, 2]
```

排序后：

```text
[0, 1, 1, 2]
```

扫描过程：

- `0 -> 1`：连续，当前长度变成 `2`
- `1 -> 1`：重复，跳过
- `1 -> 2`：连续，当前长度变成 `3`

最终答案是 `3`。

### 代码

对应代码文件：

```text
01_数组/12_q128/solution_2_sorting.py
```

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：`O(1)` 到 `O(n)`，取决于排序实现

### 这个方法的问题

它已经比暴力法好很多，也很容易想到。

但题目明确要求尽量做到：

```text
O(n)
```

而排序本身就要 `O(n log n)`，所以它不是最终最优解。

## 方法三：哈希集合 + 只从序列起点出发（面试主推）

这是最适合面试的方法。

### 第一步：先想清楚我们真正要快的是什么

这题里最核心的操作其实是：

```text
快速判断某个数存不存在
```

比如当我们站在 `x` 时，我们总想知道：

- `x + 1` 在不在
- `x + 2` 在不在
- `x - 1` 在不在

如果还用列表做存在性判断，那么：

```text
每次都要 O(n)
```

这肯定达不到 `O(n)`。

所以第一反应应该是：

```text
把 nums 放进 set
```

因为哈希集合的查找平均是 `O(1)`。

### 第二步：为什么不能从每个数都往后扩展

如果我们已经用了 `set`，很多人会立刻写出：

- 对每个 `num`
- 不断检查 `num + 1` 是否存在

这看起来已经不错了，但仍然可能超时。

为什么？

因为会重复数同一段序列。

比如：

```text
[1, 2, 3, 4, 5]
```

如果你：

- 从 `1` 开始数一遍，得到长度 `5`
- 从 `2` 开始又数一遍，得到长度 `4`
- 从 `3` 开始又数一遍，得到长度 `3`
- ...

这样总工作量会变成：

```text
5 + 4 + 3 + 2 + 1
```

也就是 `O(n^2)` 级别。

所以真正关键的优化不是只有 `set`，而是：

```text
只从连续序列的起点开始扩展
```

### 第三步：怎么判断一个数是不是起点

如果一个数 `num` 的前一个数 `num - 1` 不存在，说明它前面接不上别人，那它就是一段连续序列的起点。

也就是：

```python
if num - 1 not in num_set:
```

只有满足这个条件，我们才从它开始往后数。

如果 `num - 1` 已经存在，说明 `num` 不是起点，它只是别人那条连续序列中的中间位置，直接跳过。

### 例子：为什么这个判断这么重要

还是看：

```text
nums = [100, 4, 200, 1, 3, 2]
```

转成集合后：

```text
{100, 4, 200, 1, 3, 2}
```

逐个判断：

- `100`：`99` 不在集合里，所以 `100` 是起点，往后找不到 `101`，长度是 `1`
- `4`：`3` 在集合里，所以 `4` 不是起点，跳过
- `200`：`199` 不在集合里，所以 `200` 是起点，长度是 `1`
- `1`：`0` 不在集合里，所以 `1` 是起点
  - 找 `2`，在
  - 找 `3`，在
  - 找 `4`，在
  - 找 `5`，不在
  - 所以长度是 `4`
- `3`：`2` 在集合里，跳过
- `2`：`1` 在集合里，跳过

最终最大长度就是 `4`。

### 为什么这样就是 O(n)

这是面试里最值得讲清楚的一点。

很多人会背结论：

```text
这个方法是 O(n)
```

但如果不解释为什么，面试官往往不会完全买账。

正确的解释是：

- 外层循环虽然遍历了集合中的每个数一次
- 但内层 `while` 只有在“起点”处才会进入
- 每个数最多只会在某一条连续序列里被向后访问一次

也就是说，不会出现：

```text
同一个数被从多个起点反复扩展统计
```

所以总工作量是线性的。


- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法三，哈希集合 + 只从起点出发。**

原因有 4 个：

1. 它满足题目要求的 `O(n)`
2. 思路自然，能从“快速判断是否存在某个数”一步步推出来
3. 代码不长，白板上容易写对
4. 重复值、负数、无序输入都能自然处理

### 为什么方法二不是面试主推

方法二的确很容易想到，而且实现也不难。

但如果题目已经明确要求：

```text
设计 O(n) 算法
```

那你最后停在排序法，通常不够。

更好的表达是：

- 先说排序法是一个自然过渡
- 再指出它卡在 `O(n log n)`
- 然后顺势引出哈希集合解法

这样你的思路会显得完整且有层次。

## 最适合面试的方法：详细讲解

### 1. 原数组顺序其实不重要

这题问的是：

```text
有没有连续的值
```

而不是：

```text
这些值在原数组里是不是相邻
```

所以原数组的下标顺序对我们没有帮助。

一旦意识到这一点，就会发现：

```text
我们更关心“某个值存不存在”
```

这就是为什么 `set` 很合适。

### 2. 真正的难点不是找连续，而是避免重复统计

如果只想到“把数组转成集合，然后一直找 `num + 1`”，那还是不够。

真正决定能不能到 `O(n)` 的，是这句：

```python
if num - 1 not in num_set:
```

它的含义是：

```text
只有当前数前面接不上别人的时候，它才有资格作为起点
```

这样同一段连续区间只会被完整统计一次。

### 3. 这个起点判断为什么一定正确

因为任何一段连续序列都一定长这样：

```text
x, x + 1, x + 2, ..., y
```

其中真正的起点一定是 `x`。

而 `x` 有一个非常关键的性质：

```text
x - 1 不存在
```

反过来说，只要某个数 `num - 1` 存在，那它就不可能是这段序列的开头。

所以用这个条件筛起点，既不会漏答案，也不会重复算。

### 4. 小例子手推一遍

看：

```text
nums = [0, 3, 7, 2, 5, 8, 4, 6, 0, 1]
```

转成集合后：

```text
{0, 1, 2, 3, 4, 5, 6, 7, 8}
```

其中：

- `0` 的前一个数 `-1` 不在集合中，所以 `0` 是起点
- 从 `0` 开始可以一路找到 `1, 2, 3, 4, 5, 6, 7, 8`
- 最终这段长度是 `9`

而像 `1, 2, 3, 4` 这些数，因为它们的前一个数都在集合里，所以全部跳过。

这就是“只从起点出发”的威力。

### 5. 边界怎么想

#### 空数组

如果 `nums = []`，那答案就是 `0`。

#### 有重复值

比如：

```text
[1, 2, 2, 3]
```

转成集合后自动变成：

```text
{1, 2, 3}
```

重复值不会影响结果，反而让处理更简单。

#### 有负数

比如：

```text
[-2, -1, 0, 1]
```

一样成立。

因为“前一个数是不是存在”这个判断，对负数也完全适用。

---

## 面试里可以怎么说

如果面试官问这题，你可以把主线概括成下面这几句话：

```text
这题不关心原数组顺序，只关心某个值存不存在，所以我先把所有数放进 set。
然后我不会从每个数都往后扩展，因为那会重复统计。
我只从连续序列的起点开始扩展，起点的判断条件是 num - 1 不在集合中。
这样每个数最多被处理有限次，所以总时间复杂度是 O(n)。
```

这套表达会比只背模板更有说服力。

## 三种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力枚举 | `O(n^3)` | `O(1)` | 能想到，但太慢 |
| 方法二：排序后扫描 | `O(n log n)` | `O(1)` 到 `O(n)` | 很自然的过渡解法 |
| 方法三：哈希集合 + 起点判断 | `O(n)` | `O(n)` | 最优解，也是面试主推 |

---

## 最后总结

这题最核心的不是“连续序列”这四个字，而是两次思维转换：

1. 从“按原数组看”切换到“只关心某个值是否存在”
2. 从“每个数都尝试扩展”切换到“只从起点扩展”

一旦这两步想清楚，`O(n)` 解法就会非常自然。
