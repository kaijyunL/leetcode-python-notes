# LeetCode 41. 缺失的第一个正数（First Missing Positive）解析

## 题目描述

给你一个未排序的整数数组 `nums`。

请你找出其中：

```text
没有出现的最小正整数
```

例如：

```text
[1, 2, 0] -> 3
[3, 4, -1, 1] -> 2
[7, 8, 9, 11, 12] -> 1
```

并且题目要求：

```text
时间复杂度 O(n)
额外空间复杂度 O(1)
```

这两个要求一起出现，基本就说明：

```text
不能老老实实排序，也不能直接开额外哈希表当正式最优解
```

---

## 先理解题意

### 1. 题目只关心“正整数”

负数、0、很大的数，其实都不重要。

因为我们要找的是：

```text
最小的缺失正整数
```

所以真正可能影响答案的，首先一定是：

```text
1, 2, 3, 4, ...
```

### 2. 一个最关键的范围结论

如果数组长度是 `n`，那么答案一定落在：

```text
1 到 n + 1
```

为什么？

因为长度为 `n` 的数组，最多只能把 `1` 到 `n` 这 `n` 个正整数都凑齐。

- 如果这里面缺了某个数，答案就在 `1..n` 里
- 如果 `1..n` 一个都没缺，那答案就是 `n + 1`

这个结论是整道题最核心的基础。

### 3. 这题本质上是在问：数字该不该待在某个“位置”上

既然答案只可能是 `1..n+1`，那就可以自然想到：

- 数字 `1` 最适合待在下标 `0`
- 数字 `2` 最适合待在下标 `1`
- ...
- 数字 `n` 最适合待在下标 `n - 1`

也就是说：

```text
数字 x 的理想位置是下标 x - 1
```

后面的最优解，就是围绕这个关系展开的。

## 方法一：排序后从 1 开始扫描

### 思路

最直观的做法是先排序。

排序后，我们从小到大去看，维护一个当前“期望出现”的正整数 `expected`。

初始时：

```text
expected = 1
```

然后遍历排序后的数组：

- 如果当前数比 `expected` 小，跳过
- 如果当前数正好等于 `expected`，说明这个数出现了，`expected += 1`
- 如果当前数大于 `expected`，说明 `expected` 缺失，直接返回

### 为什么可行

因为排序后，正整数会按从小到大的顺序出现。

所以你只要一路追踪：

```text
1 有没有
2 有没有
3 有没有
```

第一次断掉的位置，就是答案。

对应代码文件：

```text

```

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：取决于排序实现，通常不作为这题最优解

### 评价

优点：

- 最容易想到
- 逻辑顺
- 很适合第一层理解

缺点：

- 不满足题目要求的 `O(n)` 时间

## 方法二：用哈希集合检查 `1, 2, 3...`

### 思路

既然我们真正关心的是：

```text
1 在不在
2 在不在
3 在不在
```

那就可以把所有数先放进哈希集合里。

然后从 `1` 开始往上检查：

- `1` 在不在
- `2` 在不在
- `3` 在不在

第一个不在集合中的数，就是答案。

### 为什么这已经很接近正确方向

因为方法二已经抓住了这题最核心的本质：

```text
我们不是要重新排序所有数，而是要快速判断某个正整数有没有出现
```

所以它比方法一更接近最优思路。

### 为什么最多只要检查到 `n + 1`

因为前面说过，答案一定在 `1..n+1` 范围内。

所以不需要无限往后试。

只要检查：

```text
1, 2, 3, ..., n + 1
```

一定能找到答案。

### 代码

对应代码文件：

```text
01_数组/21_q41/solution_2_hash_set.py
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 评价

优点：

- 很自然
- 容易写对
- 已经达到了线性时间

缺点：

- 不满足题目要求的 `O(1)` 额外空间

## 方法三：把数字放回对应下标位置（面试主推）

这是最适合面试的方法。

### 第一步：把“数字出现过”转成“数字是否在正确位置上”

前面已经有一个关键关系：

```text
数字 x 应该放在下标 x - 1 的位置
```

那我们就可以把“是否出现过”转化成：

```text
如果数字 x 出现了，就尽量把它放到 nums[x - 1]
```

这样一来，数组本身就成了一个“原地哈希表”。

### 第二步：哪些数字值得放

不是所有数字都值得处理。

只有落在：

```text
1 <= x <= n
```

范围内的数字，才可能对答案有帮助。

因为：

- 小于等于 0 的数不可能是答案
- 大于 `n` 的数也不可能放进 `0..n-1` 这些有效位置里

所以这些数可以忽略。

### 第三步：为什么要用 `while` 不断交换

假设当前位置 `nums[index]` 里放着一个有效数字 `x`，但它不在自己该在的位置。

那我们就要把它交换到：

```text
下标 x - 1
```

但交换过去以后，当前位置可能又换来了另一个同样应该继续归位的数字。

所以这里不能只交换一次，而要：

```text
一直交换，直到当前位置这个数不需要再动为止
```

这就是为什么这里必须用 `while`。

### 第四步：什么时候停止交换

当前位置停止交换的情况只有几种：

1. 当前数不在 `1..n` 范围里
2. 当前数已经在正确位置上
3. 当前数想去的位置上，已经有一个和它一样的数了

第三种情况很重要。

比如数组里有重复的 `1`，如果不做这个判断，就会在两个位置之间来回交换，死循环。

所以条件里一定要有：

```python
nums[nums[index] - 1] != nums[index]
```

### 第五步：为什么最后再扫一遍就能得到答案

经过前面的归位之后，理想状态应该是：

```text
下标 0 放 1
下标 1 放 2
下标 2 放 3
...
```

所以第二次从左到右扫描时：

- 如果发现 `nums[index] != index + 1`
- 说明 `index + 1` 这个数没有出现在它该在的位置上
- 那它就是缺失的第一个正整数

如果一路都匹配，说明：

```text
1 到 n 全都在
```

那答案就是 `n + 1`。

### 手推一个例子

看这个数组：

```text
[3, 4, -1, 1]
```

数组长度 `n = 4`，所以答案只可能在 `1..5`。

#### 先处理下标 0

当前是 `3`，它应该去下标 `2`。

交换后：

```text
[-1, 4, 3, 1]
```

现在下标 0 是 `-1`，无效，停止。

#### 再处理下标 1

当前是 `4`，它应该去下标 `3`。

交换后：

```text
[-1, 1, 3, 4]
```

现在下标 1 是 `1`，它应该去下标 `0`。

再交换：

```text
[1, -1, 3, 4]
```

现在下标 1 是 `-1`，停止。

#### 继续扫完整个数组

最终数组变成：

```text
[1, -1, 3, 4]
```

这时候从左往右检查：

- 下标 0 是 `1`，对
- 下标 1 应该是 `2`，但现在不是

所以答案就是：

```text
2
```

对应代码文件：

```text
01_数组/21_q41/solution_3_index_placement.py
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

### 为什么交换总次数仍然是 `O(n)`

虽然代码里有 `while`，但不是说每个位置都会无限交换。

每次成功交换，本质上都至少把一个有效数字放回了更正确的位置。

一个数字一旦放到正确位置，就不会再被无意义地搬来搬去。

所以整体交换总次数是线性的，时间复杂度仍然是 `O(n)`。

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法三，把数字放回对应下标位置。**

### 为什么它最适合面试

1. 完全满足题目要求的 `O(n)` 时间和 `O(1)` 空间
2. 思路不是死记模板，而是从“答案只在 `1..n+1`”自然推出来的
3. 代码虽然有点绕，但每一步都能解释清楚
4. 很适合展示你对“原地哈希”思想的理解

### 方法二为什么不是主推

方法二已经非常自然，而且很好写。

但它用了额外集合，所以差在：

```text
没有满足 O(1) 额外空间
```

### 方法一为什么更适合第一层理解

方法一能很快帮你建立：

```text
我们其实就是在追踪 1、2、3、4... 哪个最先断掉
```

但它在复杂度上不够好。

## 最适合面试的方法：关键细节

### 1. 为什么答案一定在 `1..n+1`

这是整题最关键的理论基础。

如果这个结论不先想清楚，后面的原地解法就很难自然推出。

### 2. 为什么只处理 `1..n` 范围内的数

因为只有这些数，才有资格被放进数组的有效下标区间里。

### 3. 为什么要防止重复数字死循环

如果目标位置已经是同一个数，再交换就没有意义，只会无限打转。

### 4. 为什么第二遍扫描时返回 `index + 1`

因为我们建立的规则就是：

```text
下标 index 应该放数字 index + 1
```

所以一旦不匹配，缺的就是 `index + 1`。

## 最后总结

这题最重要的主线是：

1. 答案一定只会落在 `1..n+1`
2. 所以真正有价值的数只有 `1..n`
3. 最优解的核心就是让数字 `x` 去下标 `x-1`
4. 最后再看第一个“不在正确位置”的地方是谁

如果你能把“为什么答案只在 `1..n+1`”和“为什么数字 `x` 要去 `x-1`”这两件事讲清楚，这题就算真正掌握了。
