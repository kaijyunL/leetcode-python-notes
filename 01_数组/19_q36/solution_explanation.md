# LeetCode 36. 有效的数独（Valid Sudoku）解析

## 题目描述

给你一个 `9 x 9` 的数独棋盘 `board`。

其中：

- `'.'` 表示空格，暂时还没填数字
- `'1'` 到 `'9'` 表示已经填入的数字

你需要判断：

```text
当前这个棋盘是否有效
```

这里的“有效”只要求：

1. 每一行里，数字 `1` 到 `9` 不能重复
2. 每一列里，数字 `1` 到 `9` 不能重复
3. 每一个 `3 x 3` 宫里，数字 `1` 到 `9` 不能重复

注意：

```text
题目不是让你解数独，只是判断当前已填部分有没有冲突
```

例如：

```text
[
  ["5","3",".",".","7",".",".",".","."],
  ["6",".",".","1","9","5",".",".","."],
  [".","9","8",".",".",".",".","6","."],
  ["8",".",".",".","6",".",".",".","3"],
  ["4",".",".","8",".","3",".",".","1"],
  ["7",".",".",".","2",".",".",".","6"],
  [".","6",".",".",".",".","2","8","."],
  [".",".",".","4","1","9",".",".","5"],
  [".",".",".",".","8",".",".","7","9"]
]
```

这是一个有效棋盘，所以返回 `True`。

---

## 先理解题意

### 1. 只检查“已填数字”

这题不是判断这个数独最终能不能解出来。

它只问你：

```text
当前已经填进去的这些数字，有没有彼此冲突
```

所以遇到 `'.'`，直接跳过就行。

### 2. 冲突只有三种来源

任意一个已填数字，只可能在三个地方出问题：

- 和同一行重复
- 和同一列重复
- 和同一个 `3 x 3` 宫重复

所以这题本质上就是：

```text
每看到一个数字，就检查它在这三个维度上是不是已经出现过
```

### 3. 这题难点不在算法复杂度，而在“组织检查逻辑”

因为棋盘大小固定就是 `9 x 9`。

所以严格来说，不管你怎么写，时间复杂度都可以看成常数级。

真正的区别在于：

- 思路是不是直观
- 代码是不是顺
- 面试时好不好解释

---

## 方法一：分别检查行、列、九宫格

### 思路

最朴素的做法就是完全照着题目规则来。

题目要求检查三件事，那我们就分三轮来检查：

1. 检查每一行有没有重复数字
2. 检查每一列有没有重复数字
3. 检查每个 `3 x 3` 宫有没有重复数字

每次检查时，都用一个 `set` 记录已经见过的数字。

如果当前数字已经在 `set` 里出现过，说明冲突，直接返回 `False`。

### 为什么可行

因为题目本来就只有这三条规则。

而方法一相当于：

```text
把三条规则拆开，一条一条单独验证
```

只要这三轮检查都没发现重复，那当前棋盘一定有效。

### 方法一最适合用来建立第一层理解

这题第一次做时，最容易想到的就是这种写法。

它的优点不是“最巧”，而是：

```text
题目怎么说，你就怎么查
```

所以非常适合拿来建立最初的思路。

### 代码

对应代码文件：

```text
01_数组/19_q36/solution_1_three_passes.py
```

### 复杂度

- 时间复杂度：`O(1)`，因为棋盘固定是 `9 x 9`
- 如果按一般 `n x n` 棋盘抽象来看，可以理解为 `O(n^2)`
- 空间复杂度：`O(1)`，每次只用到最多大小为 `9` 的集合

### 评价

优点：

- 最直观
- 最容易理解
- 最适合作为第一反应

缺点：

- 同一个棋盘分三轮检查，写法略显重复
- 没有把“看到一个数就同时检查三个维度”的信息利用起来

## 方法二：一次遍历，同时检查行、列、九宫格（面试主推）

### 第一步：把三条规则合并到同一次扫描里

既然每个数字都只需要检查：

- 行
- 列
- 九宫格

那我们完全可以在扫描到某个位置 `(row, col)` 时，立刻同步检查这三个地方。

所以可以准备三组容器：

- `rows[row]`：记录第 `row` 行已经出现过哪些数字
- `cols[col]`：记录第 `col` 列已经出现过哪些数字
- `boxes[box_index]`：记录第几个九宫格里已经出现过哪些数字

### 第二步：九宫格编号怎么求

这是这题最值得记住的细节。

对坐标 `(row, col)` 来说：

- `row // 3` 表示它属于第几块“大行宫”
- `col // 3` 表示它属于第几块“大列宫”

所以九宫格编号就是：

```python
box_index = (row // 3) * 3 + col // 3
```

这个公式一定要会。

### 第三步：扫描时怎么判断

当我们看到一个数字 `value` 时：

1. 如果它在 `rows[row]` 里出现过，说明这一行重复了
2. 如果它在 `cols[col]` 里出现过，说明这一列重复了
3. 如果它在 `boxes[box_index]` 里出现过，说明这个九宫格重复了

只要任意一个成立，就直接返回 `False`。

否则就把这个数字加入这三个集合。

### 为什么这是方法一的自然优化

方法一是：

```text
分三轮，从全局分别检查三类约束
```

方法二是：

```text
扫描每个格子时，顺手把这三类约束同时检查掉
```

本质上检查的内容完全一样，只是组织方式更集中。

### 小例子

假设现在扫到位置 `(4, 5)`，里面是 `'3'`。

那我们要检查：

- 第 `4` 行里有没有 `'3'`
- 第 `5` 列里有没有 `'3'`
- 第几个宫里有没有 `'3'`

这里：

```text
box_index = (4 // 3) * 3 + 5 // 3 = 1 * 3 + 1 = 4
```

说明它属于中间那个九宫格。

### 复杂度

- 时间复杂度：`O(1)`，固定棋盘下就是常数次扫描
- 若按一般规模抽象，可看作 `O(n^2)`
- 空间复杂度：`O(1)`，因为总共也就是固定数量的集合

### 评价

优点：

- 结构更集中
- 一次遍历就完成检查
- 很适合作为面试主推解法

缺点：

- 比方法一稍微抽象一点
- 需要记住九宫格编号公式

## 方法三：一次遍历 + 位运算压缩状态

### 思路

方法二里，我们用 `set` 记录某个数字有没有出现过。

但这题里数字只可能是：

```text
1 到 9
```

所以我们其实根本不需要真的开一个集合。

只需要一个整数的二进制位，就够表示这 9 个数字是否出现过。

### 怎么表示

我们规定：

- 第 0 位表示数字 `1`
- 第 1 位表示数字 `2`
- ...
- 第 8 位表示数字 `9`

如果某个数字出现了，就把对应那一位设成 `1`。

比如数字 `5`：

```text
bit_index = 4
mask = 1 << 4
```

这时候 `mask` 就表示“数字 5 对应的那个位置”。

### 怎么检查重复

假设当前要检查数字 `value` 对应的 `mask`。

如果：

```python
rows[row] & mask
```

结果不是 `0`，说明这一位之前已经被点亮了，也就是这个数字已经出现过。

列和九宫格也是同理。

### 怎么更新状态

如果还没出现过，就用：

```python
rows[row] |= mask
cols[col] |= mask
boxes[box_index] |= mask
```

把对应的位点亮。

### 为什么它本质上和方法二一样

方法二是：

```text
用 set 记录“这个数字出现过没有”
```

方法三是：

```text
用二进制位记录“这个数字出现过没有”
```

所以方法三只是把“状态存储方式”从哈希集合换成了位掩码。

检查逻辑完全没变。

### 代码

对应代码文件：

```text
01_数组/19_q36/solution_3_one_pass_bitmask.py
```

### 复杂度

- 时间复杂度：`O(1)`
- 空间复杂度：`O(1)`

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，一次遍历 + 哈希记录。**

### 为什么方法二最适合面试

1. 代码比方法一更集中
2. 思路比方法三更自然
3. 很容易把“行、列、宫同时检查”讲清楚
4. 不需要额外引入位运算细节，沟通成本更低

### 方法一为什么不是主推

方法一当然也完全正确。

但它更像：

```text
把题目规则拆开逐项检查
```

可读性不错，但少了一点“统一组织信息”的感觉。

### 方法三为什么不一定最适合面试

方法三确实更紧凑。

但它的优化点主要在于：

```text
把 set 换成 bitmask
```

这对这道题来说不一定是最重要的展示点。

大多数面试里，面试官更看重你能不能：

- 快速想到方法二
- 正确写出九宫格编号公式
- 清楚说明为什么这样检查就够了

所以方法二通常是更稳的选择。

## 最适合面试的方法：详细讲解

### 1. 为什么一次遍历就够

因为每个已填数字只会影响三个维度：

- 它所在的行
- 它所在的列
- 它所在的九宫格

而这三个维度都可以在看到当前格子时立刻判断。

所以没有必要等到后面再分开处理。

### 2. `rows`、`cols`、`boxes` 分别表示什么

- `rows[row]`：第 `row` 行已经见过的数字
- `cols[col]`：第 `col` 列已经见过的数字
- `boxes[box_index]`：第 `box_index` 个九宫格已经见过的数字

只要你把这三个容器的语义讲清楚，代码就非常自然。

### 3. `box_index` 为什么这样算

这是最关键的面试点。

先把棋盘看成：

```text
3 行大块 × 3 列大块
```

那：

- `row // 3` 取出它属于第几行大块
- `col // 3` 取出它属于第几列大块

再把二维块坐标压成一维编号：

```text
(块行号) * 3 + 块列号
```

所以得到：

```python
(row // 3) * 3 + col // 3
```

### 4. 代码里最容易错的地方

#### 第一，忘了跳过 `'.'`

空格不是数字，不参与冲突判断。

#### 第二，九宫格编号公式写错

最常见写错点就是括号和乘法位置。

#### 第三，检查完忘了把数字加入记录

这样后续就检测不到重复。

## 最后总结

这题最重要的主线是：

1. 每个数字只可能在行、列、宫这三个维度上出冲突
2. 所以核心任务就是记录“这些地方已经出现过哪些数”
3. 方法一先帮你把题意拆开理解
4. 方法二把三类检查合并成一次遍历，是最自然的面试写法
5. 方法三只是把记录方式从 `set` 压缩成了位运算

如果你能把方法二的推导和 `box_index` 公式讲顺，这题面试基本就够用了。
