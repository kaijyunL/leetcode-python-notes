# LeetCode 119. 杨辉三角 II（Pascal's Triangle II）解析

## 题目描述

给定一个非负索引 `rowIndex`，返回杨辉三角的第 `rowIndex` 行。

例如：

```text
rowIndex = 3
```

返回：

```text
[1, 3, 3, 1]
```

---

## 先理解这题和 118 题的区别

LeetCode 118 是：

```text
生成前 numRows 行
```

而 119 是：

```text
只返回某一行
```

这句话非常关键。

因为它意味着：

- 118 更自然的是把整个三角形都建出来
- 119 则会更关注：

```text
能不能只保留当前需要的信息
```

所以这题最核心的优化方向其实是：

```text
空间压缩
```

---

## 先复习杨辉三角的规律

杨辉三角最核心的规律还是这句：

```text
每一行的首尾都是 1
中间每个数 = 上一行左上角 + 上一行右上角
```

比如：

```text
[1, 3, 3, 1]
```

下一行：

```text
[1, 4, 6, 4, 1]
```

中间值是怎么来的：

- `4 = 1 + 3`
- `6 = 3 + 3`
- `4 = 3 + 1`

所以这题本质上还是在用上一行生成下一行。

---

## 方法一：先生成前面所有行

### 思路

最直接的想法是：

1. 从第 0 行开始生成
2. 一直生成到第 `rowIndex` 行
3. 最后返回最后一行

这和 118 题几乎一样。

当前行的构造方式也很标准：

- 先把这一行初始化成全 `1`
- 再去填中间位置
- 中间位置由上一行的两个相邻元素相加得到

---

### 代码

```python
class Solution:
    def getRow(self, rowIndex: int) -> List[int]:
        triangle = []

        for row in range(rowIndex + 1):
            current_row = [1] * (row + 1)
            for col in range(1, row):
                current_row[col] = triangle[row - 1][col - 1] + triangle[row - 1][col]
            triangle.append(current_row)

        return triangle[rowIndex]
```

---

### 为什么可行

因为它完全按照杨辉三角的定义来构造。

只要前一行是对的，当前行就能正确生成。

从第 0 行一路推到第 `rowIndex` 行，最后拿到的自然就是答案。

---

### 复杂度

- 时间复杂度：`O(rowIndex^2)`
- 空间复杂度：`O(rowIndex^2)`

---

### 不足在哪里

这个方法的问题不是时间，而是：

```text
我们明明只要最后一行，却把前面所有行都完整存下来了
```

这就产生了不必要的空间浪费。

---

## 方法二：一个数组从后往前更新（面试主推）

### 核心思路

既然每一行只依赖上一行，那我们其实不需要保存整个三角形。

我们只需要一个数组 `row`，让它不断原地变成下一行。

比如：

- 开始是第 0 行：`[1]`
- 再更新成第 1 行
- 再更新成第 2 行
- ...
- 最后更新到第 `rowIndex` 行

为了方便实现，我们可以一开始就创建长度为 `rowIndex + 1` 的全 `1` 数组。

然后每次只更新当前这一行真正需要变化的中间位置。

---

### 为什么一定要从后往前更新

这是这题最关键的实现细节。

因为当前位置的新值，要依赖：

```text
上一行的左边值 + 上一行的当前位置值
```

如果你从左往右更新，那么左边那个值可能已经被你改成“新一行”的值了。

这样就会污染计算。

所以必须：

```text
从右往左更新
```

这样 `row[j - 1]` 还是上一行的旧值，公式才成立。

---

### 这道题一个特别容易写错的地方

很多人写到这里时，会把更新顺序写成：

```python
for j in range(1, i):
    row[j] = row[j] + row[j - 1]
```

也就是：

```text
从左往右更新
```

这个写法的问题是：

```text
你会过早覆盖掉上一行还没用完的旧值
```

于是后面的计算就会被污染。

---

### 用 `rowIndex = 4` 从 `i = 0` 一直走到 `i = 4`

这里我们只看正确代码的执行过程，按轮次手推。

开始时先初始化：

```text
row = [1, 1, 1, 1, 1]
```

因为 `rowIndex = 4`，所以数组长度是 `5`。

---

### `i = 0`

这一轮表示我们想得到第 `0` 行。

第 `0` 行本来就是：

```text
[1]
```

放在当前数组视角里，可以理解为：

```text
row = [1, 1, 1, 1, 1]
```

此时后面那些位置还没用到，先不用管。

---

### `i = 1`

这一轮表示我们想得到第 `1` 行。

第 `1` 行是：

```text
[1, 1]
```

这一轮中间没有位置要更新，所以数组仍然是：

```text
row = [1, 1, 1, 1, 1]
```

---

### `i = 2`

这一轮表示我们要得到第 `2` 行：

```text
[1, 2, 1]
```

这时内层只有一个位置：

- `j = 1`

执行后：

```text
row[1] = row[1] + row[0] = 1 + 1 = 2
```

所以这一轮结束后：

```text
row = [1, 2, 1, 1, 1]
```

也就是前 3 个位置已经变成第 `2` 行。

---

### `i = 3`

这一轮表示我们要得到第 `3` 行：

```text
[1, 3, 3, 1]
```

这时内层会经过：

- `j = 2`
- `j = 1`

#### 第一步：`i = 3, j = 2`

```text
row[2] = row[2] + row[1] = 1 + 2 = 3
```

数组变成：

```text
row = [1, 2, 3, 1, 1]
```

#### 第二步：`i = 3, j = 1`

```text
row[1] = row[1] + row[0] = 2 + 1 = 3
```

数组变成：

```text
row = [1, 3, 3, 1, 1]
```

所以这一轮结束后，前 4 个位置就是第 `3` 行。

---

### `i = 4`

这一轮表示我们要得到第 `4` 行：

```text
[1, 4, 6, 4, 1]
```

这时内层会经过：

- `j = 3`
- `j = 2`
- `j = 1`

#### 第一步：`i = 4, j = 3`

```text
row[3] = row[3] + row[2] = 1 + 3 = 4
```

数组变成：

```text
row = [1, 3, 3, 4, 1]
```

#### 第二步：`i = 4, j = 2`

```text
row[2] = row[2] + row[1] = 3 + 3 = 6
```

数组变成：

```text
row = [1, 3, 6, 4, 1]
```

#### 第三步：`i = 4, j = 1`

```text
row[1] = row[1] + row[0] = 3 + 1 = 4
```

数组变成：

```text
row = [1, 4, 6, 4, 1]
```

---

### 最终结果

当 `i = 4` 这一轮结束后，数组就是：

```text
[1, 4, 6, 4, 1]
```

这就是答案。

所以整个过程中，公式：

```text
新值 = 上一行当前位置 + 上一行左边位置
```

始终成立。

这里最关键的一句话是：

```text
一维数组做杨辉三角空间压缩时，更新方向必须和依赖方向反着来，才能保住旧值。
```

---

### 用例子走一遍

假设我们要生成：

```text
rowIndex = 4
```

初始时：

```text
row = [1, 1, 1, 1, 1]
```

### 生成第 2 行后

```text
[1, 2, 1, 1, 1]
```

### 生成第 3 行后

```text
[1, 3, 3, 1, 1]
```

### 现在生成第 4 行

必须从后往前：

- `row[3] = row[3] + row[2] = 1 + 3 = 4`
- `row[2] = row[2] + row[1] = 3 + 3 = 6`
- `row[1] = row[1] + row[0] = 3 + 1 = 4`

最后得到：

```text
[1, 4, 6, 4, 1]
```

如果你从前往后更新，会出什么问题？

比如你先更新 `row[1]`，它会先变成 `4`。

那接下来算 `row[2]` 时，用到的左边值就变成了新的 `4`，而不是上一行的 `3`，结果就会错。

这就是为什么“从后往前更新”必须讲清楚。

---

### 面试代码

```python
class Solution:
    def getRow(self, rowIndex: int) -> List[int]:
        row = [1] * (rowIndex + 1)

        for i in range(2, rowIndex + 1):
            for j in range(i - 1, 0, -1):
                row[j] = row[j] + row[j - 1]

        return row
```

---

### 这段代码为什么这样写

### 外层循环 `for i in range(2, rowIndex + 1)`

表示：

```text
我要从第 2 行开始，一直更新到目标行
```

为什么从第 2 行开始？

因为：

- 第 0 行是 `[1]`
- 第 1 行是 `[1, 1]`

它们天然已经是对的，不需要更新中间值。

### 内层循环 `for j in range(i - 1, 0, -1)`

表示：

```text
只更新当前行的中间位置，而且从右往左更新
```

范围里不包括 `0`，因为最左边始终是 `1`。

也不需要碰最右边，因为数组一开始就全是 `1`。

---

### 复杂度

- 时间复杂度：`O(rowIndex^2)`
- 空间复杂度：`O(rowIndex)`

相比方法一，这里的核心优化就是把空间从二维压到了一维。

---

## 方法三：组合数公式

### 核心思路

杨辉三角第 `n` 行的第 `k` 个数，其实就是组合数：

```text
C(n, k)
```

所以第 `rowIndex` 行本质上就是：

```text
C(rowIndex, 0), C(rowIndex, 1), ..., C(rowIndex, rowIndex)
```

如果每次都直接用阶乘公式去算会比较麻烦。

但相邻两个组合数之间有一个很好用的递推关系：

```text
C(n, k) = C(n, k - 1) * (n - k + 1) / k
```

这样只要知道前一个数，就能在线性时间里推出后一个数。

---

### 为什么这个公式好用

它的优势在于：

```text
不用真的去算完整阶乘
```

而是直接从左到右，逐个推出当前行所有元素。

例如第 4 行：

- `C(4, 0) = 1`
- `C(4, 1) = 1 * 4 / 1 = 4`
- `C(4, 2) = 4 * 3 / 2 = 6`
- `C(4, 3) = 6 * 2 / 3 = 4`
- `C(4, 4) = 4 * 1 / 4 = 1`

得到：

```text
[1, 4, 6, 4, 1]
```

---

### 代码

```python
class Solution:
    def getRow(self, rowIndex: int) -> List[int]:
        row = [1] * (rowIndex + 1)

        for k in range(1, rowIndex + 1):
            row[k] = row[k - 1] * (rowIndex - k + 1) // k

        return row
```

---

### 复杂度

- 时间复杂度：`O(rowIndex)`
- 空间复杂度：`O(rowIndex)`

---

### 这个方法是不是最适合面试

从复杂度上看，它当然是最优的。

但如果是普通算法面试，我通常不会把它当成第一反应主推，原因是：

- 它更依赖数学观察
- 如果没有先想到组合数关系，现场不太容易硬推出来
- 面试官很多时候更想看你是否理解“上一行生成下一行”这个过程

所以这题有一个很典型的结论：

```text
最优解不一定最适合第一时间面试手写
```

---

## 为什么方法二最适合面试

这题最适合面试主推的方法通常是：

```text
一个数组从后往前更新
```

原因有三个。

### 1. 它延续了杨辉三角本身的定义

还是在做“上一行生成下一行”，思路非常自然。

### 2. 它体现了真正的优化点

因为 119 只要一行，不像 118 需要整个三角形，所以空间压缩是最合理的优化方向。

### 3. 代码短，但关键细节很能体现理解

尤其是：

```text
为什么必须从后往前更新
```

如果你能把这点讲清楚，面试官会比较认可。

如果对方继续追问“还能不能再快”，你再补充方法三的数学公式法，会显得层次很好。

---

## 面试里可以怎么讲

你可以这样解释：

```text
118 题是生成整个杨辉三角，而 119 题只需要返回其中一行。
所以我不需要把前面所有行都存下来，只需要一个数组不断原地更新。
每次从右往左更新当前行的中间位置，因为如果从左往右更新，会提前覆盖掉上一行还要用的值。
这样最后就能在 O(rowIndex) 额外空间内得到答案。

时间复杂度是 O(rowIndex^2)，空间复杂度是 O(rowIndex)。
```

如果继续追问最优时间复杂度，你再补一句：

```text
还可以利用组合数递推关系，把时间降到 O(rowIndex)。
```

---

## 总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：生成所有行 | `O(rowIndex^2)` | `O(rowIndex^2)` | 最直观，但空间浪费明显 |
| 方法二：一个数组从后往前更新 | `O(rowIndex^2)` | `O(rowIndex)` | 面试主推 |
| 方法三：组合数公式 | `O(rowIndex)` | `O(rowIndex)` | 时间最优，但更依赖数学观察 |

这题最重要的一句话是：

```text
119 比 118 多出来的关键点，不是规律变了，而是“只求一行”让空间压缩变得非常自然。
```
