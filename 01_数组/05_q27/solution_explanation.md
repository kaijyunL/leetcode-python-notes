# LeetCode 27. 移除元素（Remove Element）解析

## 题目描述

给定一个数组 `nums` 和一个值 `val`，要求你 **原地** 删除所有等于 `val` 的元素，并返回删除后的新长度。

题目真正关心的是：

```text
删除后前 k 个位置里，是否都是应该保留下来的元素
```

其中 `k` 是你返回的新长度。

同时这题还有一个非常重要的条件：

```text
元素顺序可以改变
```

也就是说：

- 你不需要保留原有相对顺序
- 你也不需要关心 `k` 之后的内容
- 只要 `nums[:k]` 里放的是所有应该保留的元素就行

例如：

```text
nums = [3, 2, 2, 3], val = 3
```

处理后可以返回：

```text
2
```

并让前两位变成：

```text
[2, 2]
```

---

## 先理解这题和 26 题的关键区别

LeetCode 26 是：

```text
删除有序数组中的重复项
```

那题要求：

- 数组有序
- 相对顺序要保留

而 27 题不同。

27 题只要求：

```text
把等于 val 的元素删掉
```

并且：

```text
顺序可以改变
```

这句话非常值钱。

因为它意味着除了常规的快慢指针写法，我们还可以使用一种更灵活的做法：

```text
把右边元素换到左边来覆盖 val
```

所以这题通常可以讲三种方法：

1. 暴力前移
2. 快慢指针稳定覆盖
3. 左右指针 + 尾部覆盖

---

## 方法一：暴力前移

### 思路

最直接的做法是：

1. 从左到右扫描数组
2. 一旦遇到 `nums[i] == val`
3. 就把它后面的所有元素整体向前挪一位
4. 数组有效长度减一
5. 因为当前位置换来了一个新元素，所以这个位置还要重新检查

---

### 代码

```python
class Solution:
    def removeElement(self, nums: List[int], val: int) -> int:
        size = len(nums)
        i = 0

        while i < size:
            if nums[i] == val:
                for j in range(i + 1, size):
                    nums[j - 1] = nums[j]
                size -= 1
                continue
            i += 1

        return size
```

---

### 为什么可行

因为每次发现一个 `val`，我们都用后面的元素把它覆盖掉。

这样不断做下去，最终数组前面留下来的，就都是不等于 `val` 的元素。

并且因为每删掉一个元素，我们都会把有效长度 `size` 减一，所以最后返回的就是正确长度。

---

### 为什么会慢

问题在于：

```text
每删掉一个 val，都可能要搬很多元素
```

比如数组里有很多个 `val`，那就会不断重复移动。

所以最坏情况下会退化成：

```text
O(n^2)
```

---

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

---

## 方法二：快慢指针稳定覆盖（面试主推）

### 核心思路

我们可以不去“删除”元素，而是换个角度：

```text
把所有不等于 val 的元素，依次压到数组前面
```

这里用两个指针：

- `fast`：负责扫描整个数组
- `slow`：指向下一个应该写入保留元素的位置

只要 `nums[fast] != val`，说明这个元素应该保留。

那就把它写到 `nums[slow]`，然后 `slow += 1`。

---

### 为什么这样想是对的

整个过程中，我们始终维护这个含义：

```text
nums[0...slow-1] 是已经整理好的保留区间
```

`fast` 每往后看一个元素：

- 如果它等于 `val`，跳过
- 如果它不等于 `val`，就把它放进保留区间的下一个位置

所以最后：

```text
slow
```

正好就是保留下来的元素个数。

---

### 用例子走一遍

假设：

```text
nums = [0, 1, 2, 2, 3, 0, 4, 2], val = 2
```

开始时：

```text
slow = 0
```

### 扫描到 `0`

`0 != 2`，应该保留。

写入：

```text
nums[0] = 0
slow = 1
```

### 扫描到 `1`

`1 != 2`，应该保留。

写入：

```text
nums[1] = 1
slow = 2
```

### 扫描到两个 `2`

它们等于 `val`，都跳过。

### 扫描到 `3`

`3 != 2`，保留。

写入：

```text
nums[2] = 3
slow = 3
```

后面的 `0`、`4` 也是同理。

最后数组前面会变成：

```text
[0, 1, 3, 0, 4, ...]
```

返回长度：

```text
5
```

这就够了。

---

### 面试代码

```python
class Solution:
    def removeElement(self, nums: List[int], val: int) -> int:
        slow = 0

        for fast in range(len(nums)):
            if nums[fast] != val:
                nums[slow] = nums[fast]
                slow += 1

        return slow
```

---

### 这段代码为什么很稳

因为它完全不需要纠结“删除之后数组怎么补位”。

它只是做一件事：

```text
把该留下的元素往前收集
```

这比真的去做“删除动作”更自然，也更不容易写错。

而且即使 `slow == fast`，这次赋值也没问题，本质上只是把元素写回原位。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

## 方法三：左右指针 + 尾部覆盖

### 为什么这题可以这样做

因为题目明确说了：

```text
元素顺序可以改变
```

这就意味着，当左边遇到 `val` 时，我们不一定非要把后面所有元素整体前移。

我们可以直接拿当前有效区间的最后一个元素来覆盖它。

这样有时候能减少很多写操作。

---

### 核心思路

我们维护一个当前有效区间：

```text
[0, right)
```

这里：

- `left` 从左往右检查
- `right` 表示当前有效区间的右边界（开区间）

如果：

```text
nums[left] == val
```

那就做两件事：

1. 用 `nums[right - 1]` 覆盖 `nums[left]`
2. `right -= 1`

注意这时候：

```text
left 不能立刻加一
```

因为刚换过来的这个新值还没检查过，它也可能等于 `val`。

如果 `nums[left] != val`，那说明当前位置没问题，`left += 1` 即可。

---

### 用例子走一遍

假设：

```text
nums = [3, 2, 2, 3], val = 3
```

开始时：

- `left = 0`
- `right = 4`

当前看 `nums[0] = 3`，等于 `val`。

那就用最后一个有效元素覆盖它：

```text
nums[0] = nums[3] = 3
right = 3
```

这时 `left` 不能动，因为换过来的还是 `3`。

再看一次 `nums[0]`，还是 `3`。

继续覆盖：

```text
nums[0] = nums[2] = 2
right = 2
```

现在 `nums[0] = 2`，不是 `val`，于是 `left += 1`。

再看 `nums[1] = 2`，也不是 `val`，继续前进。

最后 `left == right == 2`，结束。

返回 `2`，前两位是：

```text
[2, 2]
```

---

### 代码

```python
class Solution:
    def removeElement(self, nums: List[int], val: int) -> int:
        left = 0
        right = len(nums)

        while left < right:
            if nums[left] == val:
                nums[left] = nums[right - 1]
                right -= 1
            else:
                left += 1

        return left
```

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

---

### 这个方法的优缺点

优点是：

```text
可能减少赋值次数
```

尤其是在要删除的元素很少时，它往往比稳定覆盖写得更少。

但缺点是：

- 顺序会变
- 细节更绕
- 更容易在 `left` 是否前进这件事上写错

所以它是很好的进阶方法，但通常不是最推荐的第一面试写法。

---

## 为什么方法二最适合面试

这题最适合面试的方法通常还是：

```text
快慢指针稳定覆盖
```

虽然方法三在某些情况下赋值更少，但方法二更适合作为“第一答案”。

原因有三个。

### 1. 逻辑最直观

它的核心只有一句话：

```text
把所有不等于 val 的元素收集到前面
```

面试官一听就明白。

### 2. 边界最少

不需要处理“换过来的元素要不要再检查”这种细节。

写起来更稳，出错率更低。

### 3. 复杂度已经足够好

时间复杂度已经是 `O(n)`，额外空间复杂度也是 `O(1)`。

通常已经完全满足这题要求。

如果面试官追问：

```text
能不能减少写操作？
```

你再补充方法三，会显得层次很完整。

---

## 面试里可以怎么讲

你可以这样解释：

```text
我用快慢指针来做。
fast 负责扫描整个数组，slow 指向下一个应该写入保留元素的位置。
当 nums[fast] 不等于 val 时，说明这个元素应该留下来，
我就把它写到 nums[slow]，然后 slow 往前走一步。
最后 nums[0...slow-1] 就是保留下来的所有元素，slow 也就是新长度。

这样每个元素只处理一次，所以时间复杂度是 O(n)，额外空间复杂度是 O(1)。
```

如果继续追问优化，你可以再补一句：

```text
因为题目允许顺序变化，所以还可以用左右指针，把尾部元素直接换到前面覆盖 val，进一步减少一些写操作。
```

---

## 总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力前移 | `O(n^2)` | `O(1)` | 直观，但会重复搬元素 |
| 方法二：快慢指针稳定覆盖 | `O(n)` | `O(1)` | 面试主推 |
| 方法三：左右指针 + 尾部覆盖 | `O(n)` | `O(1)` | 进阶优化，写操作更少但更绕 |

这题最重要的一句话是：

```text
不要执着于“删除”这个动作；更自然的想法是把该保留的元素收集到前面。
```

而题目那句“顺序可以改变”，则给了我们第三种更灵活的写法。
