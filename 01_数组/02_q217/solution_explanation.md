# LeetCode 217. 存在重复元素（Contains Duplicate）解析

## 题目描述

给定一个整数数组 `nums`，判断数组中是否存在重复元素。

如果任意一个值在数组中出现 **至少两次**，返回 `True`；如果数组中每个元素都互不相同，返回 `False`。

例如：

```text
nums = [1, 2, 3, 1]
```

因为数字 `1` 出现了两次，所以返回：

```text
True
```

---

## 先理解题意

这题不是让你找出“哪个数字重复了”，而只是问：

```text
有没有重复？
```

所以一旦我们发现某个数之前已经出现过，其实就可以立刻返回：

```text
True
```

不需要继续往后找。

这意味着这题的重点是：

```text
如何快速判断一个数之前是否出现过
```

---

## 方法一：暴力双循环

### 思路

最直接的办法就是枚举所有下标对：

- 固定一个位置 `i`
- 再去看后面的每个位置 `j`
- 如果出现 `nums[i] == nums[j]`，说明有重复

---

### 代码

```python
class Solution:
    def containsDuplicate(self, nums: List[int]) -> bool:
        n = len(nums)

        for i in range(n):
            for j in range(i + 1, n):
                if nums[i] == nums[j]:
                    return True

        return False
```

---

### 为什么可行

因为它把所有可能的两两组合都比过了。

只要数组里存在两个位置的值相同，就一定会在某次比较中发现。

例如：

```text
nums = [1, 2, 3, 1]
```

当：

- `i = 0`
- `j = 3`

时会发现：

```text
nums[0] == nums[3]
```

于是返回 `True`。

---

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

---

### 不足在哪里

这个方法的问题是：

```text
重复比较太多了
```

我们真正需要的其实不是“和所有后面元素都比一遍”，而只是：

```text
当前这个数以前见过没有？
```

只要能快速回答这个问题，就能更快解决。

---

## 方法二：哈希集合（面试主推）

### 核心思路

如果我们一边遍历数组，一边把已经见过的数字放进一个集合 `seen`，那么当我们看到当前数字 `num` 时，只要判断：

```text
num 是否已经在 seen 里
```

就行了。

- 如果在，说明重复，直接返回 `True`
- 如果不在，就把它加入 `seen`

这正好符合题意。

---

## 为什么集合特别适合这题

因为这题只关心：

```text
某个值是否出现过
```

并不关心：

- 它第一次出现在哪个下标
- 它总共出现了几次
- 重复值具体是什么

所以我们不需要哈希表存更多信息，只用：

```text
哈希集合
```

就够了。

这比哈希表还更自然。

---

## 用例子走一遍

假设：

```text
nums = [1, 2, 3, 1]
```

### 开始时

```text
seen = set()
```

### 1. 遍历到 `1`

检查：

```text
1 in seen ?
```

结果：

```text
False
```

把 `1` 加进去：

```text
seen = {1}
```

### 2. 遍历到 `2`

检查：

```text
2 in seen ?
```

结果：

```text
False
```

加入：

```text
seen = {1, 2}
```

### 3. 遍历到 `3`

检查后也不在集合里，加入：

```text
seen = {1, 2, 3}
```

### 4. 遍历到最后一个 `1`

检查：

```text
1 in seen ?
```

结果：

```text
True
```

说明 `1` 之前已经出现过，所以直接返回：

```text
True
```

---

## 面试代码

```python
class Solution:
    def containsDuplicate(self, nums: List[int]) -> bool:
        seen = set()

        for num in nums:
            if num in seen:
                return True
            seen.add(num)

        return False
```

---

## 还有一种更短的写法

也可以直接比较：

```python
return len(nums) != len(set(nums))
```

因为：

- `set(nums)` 会自动去重
- 如果去重前后长度变了，说明有重复

这个写法很短，也对。

但在面试里通常不如上一种好，原因是它把中间思路全压缩掉了。

面试官更希望看到你明确表达：

```text
我在遍历过程中，用集合记录已经见过的元素
```

这比直接写一行更能说明你理解了题目。

---

## 复杂度分析

## 方法一：暴力双循环

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

## 方法二：哈希集合

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

因为：

- 每个元素最多进集合一次
- 每次集合查询和插入平均是 `O(1)`

---

## 为什么这个方法最适合面试

最适合面试的方法就是：

```text
一边遍历，一边用集合记录已经见过的数
```

原因有三个。

### 1. 思路最直接

题目问的是“有没有重复”，而集合最擅长做的就是：

```text
判断某个值是否已经出现过
```

### 2. 复杂度最优

时间复杂度 `O(n)`，已经是这题最标准的最优解。

### 3. 代码短，但不是死记模板那种短

它既足够简洁，又能把思路完整展开，面试里很好讲。

---

## 面试里怎么讲

你可以直接这样解释：

```text
我用一个集合 seen 记录已经遍历过的元素。
从左到右扫描数组时，如果当前元素已经在 seen 里，说明它之前出现过，直接返回 True。
如果不在，就把它加入 seen，继续往后遍历。

这样每个元素只处理一次，所以时间复杂度是 O(n)，空间复杂度是 O(n)。
```

这就是这题最标准的面试表达。

---

## 总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力双循环 | `O(n^2)` | `O(1)` | 好想，但慢 |
| 方法二：哈希集合 | `O(n)` | `O(n)` | 面试主推 |

最重要的一句话是：

```text
这题不是要找重复值是谁，而是要快速判断“当前值之前见过没有”，所以用集合最自然。
```
