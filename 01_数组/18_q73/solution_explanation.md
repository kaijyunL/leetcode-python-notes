# LeetCode 73. 矩阵置零（Set Matrix Zeroes）解析

## 题目描述

给你一个 `m x n` 的矩阵 `matrix`。

如果某个位置的元素是 `0`，就要把它所在的：

```text
整行和整列
```

全部变成 `0`。

并且题目要求：

```text
必须原地修改矩阵
```

也就是不能新建一个同样大小的结果矩阵再返回。

例如：

```text
输入：
[
  [1, 1, 1],
  [1, 0, 1],
  [1, 1, 1]
]

输出：
[
  [1, 0, 1],
  [0, 0, 0],
  [1, 0, 1]
]
```

---

## 先理解题意

### 1. 这里最关键的是“按原始的 0 来决定”

不是说你把一个位置改成了 `0` 之后，它又继续向外扩散。

真正的意思是：

```text
只有原矩阵里一开始就是 0 的位置，才有资格触发整行整列置零
```

### 2. 为什么不能边扫描边直接改

比如这个矩阵：

```text
1 1 1
1 0 1
1 1 1
```

如果你扫描到中间的 `0`，立刻把这一行和这一列全改成 `0`，矩阵会临时变成：

```text
1 0 1
0 0 0
1 0 1
```

这时候你如果继续往后扫，就会看到很多“新出现的 0”。

但这些 `0` 不是原始的 `0`，它们不应该继续把别的行列再清空。

这就是这题最核心的难点：

```text
怎么避免修改后的 0 反过来污染后续判断
```

### 3. 所以这题本质是在做两件事

1. 先找出哪些行、哪些列最终要变成 `0`
2. 再统一去修改矩阵

三种方法的区别，本质只是：

```text
这些“标记信息”存在哪里
```

---

## 方法一：记录所有初始 0 的坐标

### 思路

最直接的想法是：

```text
先把所有原始 0 的位置都记下来，后面再统一处理
```

具体做法：

1. 第一遍扫描矩阵
2. 如果 `matrix[row][col] == 0`，就把坐标 `(row, col)` 记录下来
3. 扫描结束后，再遍历这些坐标
4. 对每个坐标，把对应整行和整列都改成 `0`

### 为什么可行

因为我们第一阶段只是：

```text
记录原始 0 的位置
```

并没有修改矩阵。

所以不会发生“新 0 污染判断”的问题。

### 为什么会慢

假设矩阵里有很多个 `0`。

那你每记录到一个 `0`，第二阶段都要重新把它所在的整行和整列扫一遍。

如果一共有很多个 `0`，就会出现大量重复清零操作。

### 代码

对应代码文件：

```text
01_数组/18_q73/solution_1_record_zero_positions.py
```

### 复杂度

设原始矩阵里一共有 `k` 个 `0`。

- 时间复杂度：`O(mn + k(m + n))`
- 最坏时间复杂度：`O(mn(m + n))`
- 空间复杂度：`O(k)`，最坏是 `O(mn)`

### 评价

优点：

- 最容易想到
- 很适合当第一层思路

缺点：

- 空间大
- 重复操作多
- 离题目的进阶要求比较远

## 方法二：使用行标记和列标记数组

### 思路

方法一的问题在于：

```text
我们其实不需要知道每个 0 的精确坐标，只需要知道哪些行、哪些列要清零
```

所以可以改成：

- `row_has_zero[row]`：第 `row` 行是否出现过 `0`
- `col_has_zero[col]`：第 `col` 列是否出现过 `0`

做法分两步：

1. 第一遍扫描矩阵
   - 只要发现 `matrix[row][col] == 0`
   - 就把 `row_has_zero[row]` 和 `col_has_zero[col]` 设成 `True`
2. 第二遍扫描矩阵
   - 如果当前元素所在行或所在列被标记过
   - 就把当前位置改成 `0`

### 为什么这是方法一的自然优化

方法一记录的是：

```text
哪个格子是 0
```

方法二记录的是：

```text
哪一整行、哪一整列会受影响
```

而题目最终真正关心的，恰好就是后者。

所以这是一次非常自然的压缩。

### 小例子

还是看：

```text
1 1 1
1 0 1
1 1 1
```

当我们扫到中间的 `0` 时：

- `row_has_zero[1] = True`
- `col_has_zero[1] = True`

第二遍再扫矩阵时，只要满足：

- 行号是 `1`
- 或列号是 `1`

就把这个位置设成 `0`。

于是结果就是：

```text
1 0 1
0 0 0
1 0 1
```

### 代码

对应代码文件：

```text
01_数组/18_q73/solution_2_row_col_markers.py
```

### 复杂度

- 时间复杂度：`O(mn)`
- 空间复杂度：`O(m + n)`

### 评价

优点：

- 思路很顺
- 代码不难写
- 已经把时间复杂度优化到了线性扫描级别

缺点：

- 还不是题目进阶想要的常数空间

## 方法三：用第一行和第一列做原地标记（面试主推）

这是最适合面试的方法。

### 第一步：先想清楚，方法二里的两个数组到底在做什么

方法二里的：

- `row_has_zero`
- `col_has_zero`

本质上只是用来存：

```text
这一行要不要清零
这一列要不要清零
```

那我们就会自然想到一个问题：

```text
能不能不额外开数组，而是直接借用矩阵本身来存这些标记？
```

答案是可以。

### 第二步：让第一列记录“哪些行要清零”

如果 `matrix[row][col] == 0`，那么第 `row` 行最终一定要清零。

所以我们可以把：

```text
matrix[row][0]
```

当成第 `row` 行的标记位。

也就是说，只要发现内部某个位置是 `0`，就做：

```text
matrix[row][0] = 0
```

### 第三步：让第一行记录“哪些列要清零”

同理，如果 `matrix[row][col] == 0`，那么第 `col` 列最终也要清零。

所以可以把：

```text
matrix[0][col]
```

当成第 `col` 列的标记位。

也就是：

```text
matrix[0][col] = 0
```

### 第四步：为什么第一行和第一列要单独先检查

问题在于：

```text
第一行和第一列自己既是“数据区”，又要被拿来当“标记区”
```

所以如果第一行原本就有 `0`，或者第一列原本就有 `0`，我们不能等到后面再判断。

必须一开始先分别记下来：

- `first_row_has_zero`
- `first_col_has_zero`

这样最后才能知道：

- 第一行是不是整行清零
- 第一列是不是整列清零

### 第五步：为什么内部扫描要从 `1` 开始

因为下标 `0` 的那一整行和那一整列，已经被我们保留出来做标记区了。

所以真正用来打标记的扫描范围是：

- 行：`1` 到 `m - 1`
- 列：`1` 到 `n - 1`

也就是只处理：

```text
去掉第一行和第一列之后的内部区域
```

### 第六步：完整流程

1. 先检查第一行是否本来就有 `0`
2. 再检查第一列是否本来就有 `0`
3. 扫描内部区域 `(1..m-1, 1..n-1)`
   - 如果 `matrix[row][col] == 0`
   - 就把 `matrix[row][0]` 和 `matrix[0][col]` 设成 `0`
4. 再扫描一次内部区域
   - 如果 `matrix[row][0] == 0` 或 `matrix[0][col] == 0`
   - 就把 `matrix[row][col]` 设成 `0`
5. 如果 `first_row_has_zero` 为真，就把第一行全清零
6. 如果 `first_col_has_zero` 为真，就把第一列全清零

### 手推一个例子

看这个矩阵：

```text
1 1 1
1 0 1
1 1 1
```

#### 先看第一行和第一列

- 第一行没有 `0`
- 第一列没有 `0`

所以：

```text
first_row_has_zero = False
first_col_has_zero = False
```

#### 再扫内部区域

内部只有四个位置，其中 `(1, 1)` 是 `0`。

于是我们打标记：

```text
matrix[1][0] = 0
matrix[0][1] = 0
```

矩阵会变成：

```text
1 0 1
0 0 1
1 1 1
```

注意，这时候：

- 第一行的 `0` 表示“第 1 列要清零”
- 第一列的 `0` 表示“第 1 行要清零”

它们现在承担的是标记职责。

#### 再扫内部区域一次

只要发现：

- 当前行的行头是 `0`
- 或当前列的列头是 `0`

就把当前位置设成 `0`。

最终得到：

```text
1 0 1
0 0 0
1 0 1
```

- 时间复杂度：`O(mn)`
- 空间复杂度：`O(1)`

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法三，用第一行和第一列做原地标记。**

### 为什么它最适合面试

1. 它满足题目进阶要求的 `O(1)` 空间
2. 它不是靠技巧硬凑，而是由方法二自然优化出来的
3. 代码仍然是可控的，没有很重的黑魔法
4. 只要把“第一行、第一列兼做标记区”讲清楚，面试官很容易跟上

### 面试里最稳的表达顺序

最推荐你在面试里这样说：

1. 先说明为什么不能边扫描边直接改
2. 先给方法二：行列标记数组
3. 再说可以把这两个数组压缩到第一行和第一列里
4. 最后写出方法三

这样会显得你的思路是：

```text
从直观解法一步步优化到常数空间
```

而不是直接背答案。

### 方法二为什么仍然值得讲

因为方法二是：

```text
最容易想到、最容易解释清楚的中间桥梁
```

如果你直接从方法三开讲，有些面试官会觉得跳得太快。

但如果你先把方法二讲顺，再把外部数组压缩进矩阵自身，整个推导会非常自然。

---

## 最适合面试的方法：关键细节

### 1. 为什么一定要单独保存第一行和第一列的状态

因为后面第一行、第一列会被你改写成标记区。

如果你不提前保存，就分不清：

- 这是它原本就有的 `0`
- 还是后来为了给别的行列做标记才写进去的 `0`

### 2. 为什么内部循环要从 `1` 开始

因为：

- 第 `0` 行用来记录列标记
- 第 `0` 列用来记录行标记

它们已经不是普通数据区了。

### 3. 为什么最后才处理第一行和第一列

因为在前面的大部分时间里，它们承担的是：

```text
标记板
```

如果你太早把第一行或第一列整行整列清零，就会把还没用完的标记抹掉。

### 4. 这题最容易写错的地方

#### 第一，忘了先保存第一行/第一列状态

这是最常见错误。

#### 第二，内部扫描下标写成从 `0` 开始

这样就会把标记区和数据区混在一起。

#### 第三，最后忘了单独处理第一行或第一列

这样带有原始 `0` 的第一行、第一列就会漏处理。

## 三种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：记录 0 坐标 | `O(mn + k(m + n))` | `O(k)` | 最直观，但慢且占空间 |
| 方法二：行列标记数组 | `O(mn)` | `O(m + n)` | 很自然，是通向最优解的桥梁 |
| 方法三：首行首列做标记 | `O(mn)` | `O(1)` | 面试主推 |

---

## 最后总结

这题最核心的主线是：

1. 不能边扫描边直接改，因为会产生“新 0 污染判断”
2. 本质上要先记录“哪些行列要清零”，再统一修改
3. 方法二先把思路讲顺
4. 方法三再把标记数组压缩到第一行和第一列里

如果你能把这条推导链自己复述出来，这题就算真正掌握了。
