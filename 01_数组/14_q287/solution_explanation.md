# LeetCode 287. 寻找重复数（Find the Duplicate Number）解析

## 题目描述

给定一个长度为 `n + 1` 的整数数组 `nums`，其中每个整数都在区间 `[1, n]` 内。

题目保证：

- 只有一个重复的数字
- 这个重复数字可能重复出现两次，也可能出现很多次

要求你返回这个重复的数字。

例如：

```text
nums = [1, 2, 3, 4, 2]
```

答案是：

```text
2
```

再比如：

```text
nums = [3, 1, 3, 4, 2]
```

答案是：

```text
3
```

---

## 先理解题意

这题最重要的不是“找重复数”这四个字本身，而是它附带的约束。

### 1. 数组长度是 `n + 1`，但数字范围只有 `[1, n]`

这说明什么？

说明：

```text
可放的值只有 n 种，但数组里有 n + 1 个位置
```

根据抽屉原理，至少有一个数字一定重复。

这就是为什么题目一定有答案。

### 2. 重复数字只有一个，但它可能重复很多次

比如：

```text
[2, 2, 2, 2, 2]
```

在合法约束下不一定长这样，但题目的意思是：

```text
重复值只有一个种类，不代表只重复 2 次
```

所以不能把思路建立在“恰好重复一次”上。

### 3. 这题真正难的地方是附加条件

这题如果只是让你找一个重复数，其实很简单：

- 排序
- 哈希集合
- 哈希表计数

都能做。

但题目经典版本通常还会强调：

- 不能修改原数组
- 只能用 `O(1)` 额外空间

这两个条件一加上来，很多常规方法就不满足要求了。

所以这题真正想考的是：

```text
你能不能利用“值域是 1 到 n”这个结构，想到更巧的方法
```

## 方法一：暴力双循环

### 思路

最直接的方法就是：

- 枚举每个位置 `i`
- 再枚举后面的每个位置 `j`
- 只要 `nums[i] == nums[j]`，就找到了重复数

因为题目保证只有一个重复数字，所以一旦找到相等的一对，直接返回即可。

### 为什么可行

如果某个数字重复出现，那一定会在某两个不同下标处相等。

双循环把所有下标对都检查一遍，当然不会漏。

### 代码

对应代码文件：

```text
01_数组/14_q287/solution_1_brute_force.py
```

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

### 评价

优点：

- 最容易想到
- 不需要额外数据结构
- 不修改原数组

缺点：

- 太慢

这个方法只适合当起点，不适合作为最终答案。

## 方法二：排序后扫描相邻元素

### 思路

如果把数组排好序，那么相同的数字一定会挨在一起。

所以可以：

1. 先排序
2. 再从左到右扫描
3. 只要发现相邻两个数相等，就返回它

比如：

```text
nums = [1, 2, 3, 4, 2]
```

排序后变成：

```text
[1, 2, 2, 3, 4]
```

这时候一眼就能看出重复数是 `2`。

### 为什么可行

排序会把所有相同数字放到一起。

而题目保证至少有一个重复数，所以扫描相邻元素一定能找到答案。

### 代码

对应代码文件：

```text
01_数组/14_q287/solution_2_sorting.py
```

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：
  - 如果直接对原数组排序，额外空间取决于排序实现
  - 如果先拷贝再排序，还要额外 `O(n)` 空间

### 这个方法的问题

它比暴力快很多，但有两个明显问题：

1. 不够快，达不到线性时间
2. 往往会修改数组，或者额外复制数组

所以如果面试官强调：

```text
不能修改原数组 + 只用 O(1) 额外空间
```

这个方法通常不算最终最优解。

## 方法三：哈希集合

### 思路

如果我们从左到右遍历数组，同时用一个集合记录已经见过的数字：

- 如果当前数字没见过，就放进集合
- 如果当前数字已经在集合里，说明它重复了，直接返回

比如：

```text
nums = [1, 2, 3, 4, 2]
```

遍历过程：

- 看到 `1`，放入集合
- 看到 `2`，放入集合
- 看到 `3`，放入集合
- 看到 `4`，放入集合
- 再看到 `2`，发现已经存在，返回 `2`

### 为什么可行

集合可以在平均 `O(1)` 时间判断一个数字是否已经出现过。

而题目里只有一个重复数字，所以第一次遇到“已经出现过”的数字时，它就是答案。

### 代码

对应代码文件：

```text
01_数组/14_q287/solution_3_hashset.py
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 评价

这是非常自然、非常稳的做法。

如果题目没有额外限制，这个方法其实就已经很好了。

但如果题目追求的是：

```text
不修改原数组，并且只用 O(1) 额外空间
```

那它仍然不满足。

所以还要继续优化。

## 方法四：Floyd 判圈（快慢指针，面试主推）

这是最适合面试的方法。

### 第一步：为什么这题能和“链表判环”扯上关系

这一步是整道题最关键、也最难想到的地方。

先看题目的特殊结构：

- 数组长度是 `n + 1`
- 每个值都在 `[1, n]`

这意味着：

```text
每个 nums[i] 都可以被当成“下一个位置”
```

也就是我们可以把数组理解成一种“指针跳转关系”：

```text
i -> nums[i]
```

注意这里不是普通数组思维了，而是在把它看成一个图。

比如：

```text
nums = [1, 2, 3, 4, 2]
```

下标和跳转关系是：

- `0 -> 1`
- `1 -> 2`
- `2 -> 3`
- `3 -> 4`
- `4 -> 2`

如果从 `0` 出发一路跳：

```text
0 -> 1 -> 2 -> 3 -> 4 -> 2 -> 3 -> 4 -> ...
```

你会发现：

```text
进入了一个环
```

也就是：

```text
2 -> 3 -> 4 -> 2 -> ...
```

### 第二步：为什么重复数一定会造成环

这是需要真正想明白的一步。

题目里说有一个数字重复，比如数字 `2` 重复。

这意味着：

```text
会有至少两个不同下标，它们都指向 2
```

在上面的例子里就是：

- `1 -> 2`
- `4 -> 2`

也就是说，有两条边汇入同一个点。

而整个跳转图中，每个位置只会跳向一个下一个位置。

这种结构一旦从 `0` 出发不断往前走，因为位置总数有限，就一定会重复走到某个点；一旦重复到某个点，后面路径就会开始循环。

所以这里一定存在环。

更重要的是：

```text
环的入口，对应的就是重复数字
```

这句是整题的核心结论。

### 第三步：为什么环入口就是答案

还是看：

```text
nums = [1, 2, 3, 4, 2]
```

跳转路径：

```text
0 -> 1 -> 2 -> 3 -> 4 -> 2 -> 3 -> 4 -> ...
```

第一次进入环的位置是 `2`。

而这个 `2` 恰好就是重复数字。

为什么？

因为题目不是让我们返回“重复数字出现在数组里的哪个下标”，而是返回：

```text
哪个值被重复了
```

在这个建图方式里，节点编号和数值范围刚好都是 `1` 到 `n`，所以“环入口节点的编号”本身就是那个重复值。

你可以把它理解成：

- 有多个位置都把边指向同一个值 `x`
- 那么从某条路径进入循环时，第一次汇入循环的那个节点，就是这个被重复指向的值 `x`

因此返回环入口节点编号，就等于返回重复数。

### 第四步：Floyd 判圈分两段做什么

Floyd 判圈一共分两阶段。

#### 阶段 1：先让快慢指针在环里相遇

设：

- `slow = nums[slow]`，每次走 1 步
- `fast = nums[nums[fast]]`，每次走 2 步

只要有环，它们最终一定会在环内某个位置相遇。

这里不需要一开始就知道环入口是谁，先找到“环存在，并且能进入环里相遇”就够了。

#### 阶段 2：一个指针回到起始跳转点，再同步前进

当快慢指针第一次相遇后：

- 让一个指针回到 `nums[0]`
- 另一个指针留在相遇点
- 两个指针每次都走 1 步
- 它们再次相遇的位置，就是环入口

这里要和代码初始化保持一致。

因为我们当前采用的写法是：

```python
slow = nums[0]
fast = nums[0]
```

所以第二阶段对应地要从 `nums[0]` 出发，而不是从 `0` 出发。

### 第五步：为什么第二次相遇就是环入口

这是面试里最容易被追问的一点。

设：

- 从起始跳转点 `nums[0]` 到环入口的距离是 `a`
- 从环入口到第一次相遇点的距离是 `b`
- 环长是 `c`

当快慢指针第一次相遇时：

- 慢指针走了 `a + b`
- 快指针走了 `a + b + k * c`

因为快指针速度是慢指针两倍，所以有：

```text
2(a + b) = a + b + k * c
```

移项得到：

```text
a + b = k * c
```

再变形：

```text
a = k * c - b
```

这句话的意思是：

```text
从相遇点继续往前走 a 步，等价于先绕若干圈，再走到环入口
```

而从起始跳转点 `nums[0]` 出发走 `a` 步，也刚好会到环入口。

所以：

- 一个指针从 `nums[0]` 走 `a` 步
- 一个指针从相遇点走 `a` 步

它们会在环入口相遇。

这就是第二阶段为什么成立。

### 第六步：手推一个例子

还是看：

```text
nums = [1, 2, 3, 4, 2]
```

初始化：

```text
slow = nums[0] = 1
fast = nums[0] = 1
```

第一轮：

```text
slow = nums[1] = 2
fast = nums[nums[1]] = nums[2] = 3
```

第二轮：

```text
slow = nums[2] = 3
fast = nums[nums[3]] = nums[4] = 2
```

第三轮：

```text
slow = nums[3] = 4
fast = nums[nums[2]] = nums[3] = 4
```

此时相遇在 `4`。

然后第二阶段：

```text
finder = nums[0] = 1
slow = 4
```

第一轮同步前进：

```text
finder = nums[1] = 2
slow = nums[4] = 2
```

这时两者在 `2` 相遇，`2` 就是环入口，也就是重复数。

对应代码写法是：

```python
slow = nums[0]
fast = nums[0]

while True:
    slow = nums[slow]
    fast = nums[nums[fast]]
    if slow == fast:
        break

finder = nums[0]
while finder != slow:
    finder = nums[finder]
    slow = nums[slow]

return finder
```

在这个写法里，最终返回值就是重复数。

### 这题为什么适合用 Floyd，而不是普通双指针

因为这里的“快慢指针”不是在数组下标上线性移动，而是在：

```text
按照 nums[i] 指向的下一个位置跳转
```

所以它本质上不是普通数组双指针题，而是：

```text
把数组隐式看成链表，再做判环
```

这是这题最巧的地方。


- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法四，Floyd 判圈。**

### 为什么它最适合面试

1. 满足题目经典附加条件：不修改原数组、`O(1)` 额外空间
2. 时间复杂度也是 `O(n)`
3. 思路有难度，但一旦讲清楚会非常加分
4. 是这题最标准、最有代表性的最优解

### 面试里怎么讲更稳

建议按下面顺序说：

1. 先说简单做法：排序、哈希集合都能做
2. 再指出它们为什么不满足进阶要求
3. 接着抓住题目结构：值域在 `[1, n]`，可以把值看成“下一个位置”
4. 说明重复数会让图里出现环
5. 最后自然引出 Floyd 判圈

这样讲，会比一上来直接说“这题用快慢指针”更有说服力。

## 最适合面试的方法：详细讲解

### 1. 真正关键的观察是什么

不是“数组里有重复数”。

因为这个观察太普通了，不足以推到最优解。

真正关键的是：

```text
每个数都落在 1 到 n 之间，所以 nums[i] 可以当成下一个下标
```

一旦有了这个观察，题目就从“数组查重”变成了“隐式链表找环入口”。

### 2. 为什么一定不是树状分叉后终止，而是一定会成环

因为每个点只有一条出边：

```text
i -> nums[i]
```

从某个起点不断往前走，不可能无限走下去。

节点总数有限，一旦走到之前来过的点，后面路径就会重复，于是形成环。

### 3. 为什么入口恰好是重复值

因为有多个不同位置都指向同一个值时，这个值就相当于“汇合点”。在这个例子里，`1` 和 `4` 都指向 `2`。

从起点一路往前走，第一次进入循环结构的地方，就是这个被重复指向的值。

而题目要的正是这个值本身。

### 4. 代码里最容易写错的地方

有两个：

#### 第一，初始化和更新顺序

常见写法是：

```python
slow = nums[0]
fast = nums[0]
```

然后进入循环后再更新。

这样更统一，也不容易漏掉第一步。

#### 第二，第二阶段从哪里出发

这一点一定要和你的第一阶段初始化保持一致。

如果你采用本文这份代码的写法：

```python
slow = nums[0]
fast = nums[0]
```

那么第二阶段就要把指针重置为：

```text
nums[0]
```

然后同步做：

```python
finder = nums[finder]
slow = nums[slow]
```

最终相遇点就是答案。

## 最后总结

这题的主线要记住：

1. 简单做法有很多：暴力、排序、哈希
2. 真正难的是满足“不修改原数组 + `O(1)` 额外空间”
3. 关键观察是：`nums[i]` 可以看成下一个位置
4. 重复数会让这个跳转结构形成环
5. 环入口就是重复值
6. 所以最终用 Floyd 判圈找环入口

如果你能把这 6 句话顺着讲出来，这题基本就算真正理解了。
