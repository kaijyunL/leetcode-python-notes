# LeetCode 48. 旋转图像（Rotate Image）解析

## 题目描述

给定一个 `n x n` 的二维矩阵 `matrix` 表示一个图像，请你将图像顺时针旋转 `90` 度。

题目强调：

```text
必须原地修改 matrix
```

也就是说，函数不能返回一个新矩阵，而是要直接把原矩阵改成旋转后的样子。

例如：

```text
matrix = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9]
]
```

旋转后变成：

```text
[
  [7, 4, 1],
  [8, 5, 2],
  [9, 6, 3]
]
```

---

## 先理解题意

### 1. 这是“原地修改”题，不是“返回新矩阵”题

很多人第一反应会写一个新矩阵，把旋转后的结果填进去。

这个思路本身没错，但它：

```text
不满足题目的原地要求
```

不过它非常适合当作第一步，因为它能帮我们先看清楚旋转规律。

### 2. 顺时针旋转 90 度，本质上是坐标变换

如果原来某个元素在位置：

```text
(i, j)
```

那么旋转后，它会去到：

```text
(j, n - 1 - i)
```

这是整题最基础的坐标规律。

### 3. 真正的难点不是规律本身，而是“怎么原地做”

如果允许开新矩阵，这题非常直接。

真正要思考的是：

- 不开新矩阵怎么改？
- 会不会覆盖还没用到的值？
- 有没有更自然的原地操作方式？

所以这题通常会从：

```text
辅助矩阵 → 原地交换 → 转置 + 翻转
```

这样一步步推进。

---

## 方法一：辅助矩阵

### 思路

最直接的方法就是新建一个同样大小的矩阵 `new_matrix`，然后把原矩阵中每个元素放到旋转后的位置。

根据坐标规律：

```text
(i, j) -> (j, n - 1 - i)
```

所以直接做：

```text
new_matrix[j][n - 1 - i] = matrix[i][j]
```

最后再把 `new_matrix` 的结果拷贝回 `matrix`。

### 为什么可行

因为我们已经知道每个元素旋转后应该去哪里。

只要把所有元素按照这个映射放到新矩阵里，结果就一定正确。

### 小例子

看：

```text
matrix = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9]
]
```

比如：

- `1` 在 `(0, 0)`，旋转后去 `(0, 2)`
- `2` 在 `(0, 1)`，旋转后去 `(1, 2)`
- `7` 在 `(2, 0)`，旋转后去 `(0, 0)`

最终得到：

```text
[
  [7, 4, 1],
  [8, 5, 2],
  [9, 6, 3]
]
```

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(n^2)`

### 评价

这个方法非常适合理解题目。

但它的问题也很明显：

```text
用了额外矩阵，不满足原地要求
```

所以它只能作为入门解法。

## 方法二：逐层旋转（四个位置循环交换）

### 思路

既然不能开新矩阵，我们就得考虑：

```text
能不能一次把 4 个位置直接原地轮换？
```

答案是可以。

把矩阵看成一层一层的方框：

- 最外层一圈
- 再里面一圈
- 再里面一圈

每一层里的元素，在顺时针旋转 90 度后，会发生四个位置的循环交换。

比如一个位置在上边，那么旋转后：

- 左边的值会到上边
- 下边的值会到左边
- 右边的值会到下边
- 上边的值会到右边

所以每次处理 4 个格子即可。

### 为什么要分层

因为旋转最外圈时，只会影响最外圈。

旋转内圈时，只会影响内圈。

各层之间互不干扰，所以很自然就能从外到内逐层处理。

### 四个位置怎么找

假设当前处理的是某一层：

- `first = layer`
- `last = n - 1 - layer`

对于这一层上边的一格 `matrix[first][i]`，它对应的另外三格分别是：

- 左边：`matrix[last - offset][first]`
- 下边：`matrix[last][last - offset]`
- 右边：`matrix[i][last]`

其中：

```text
offset = i - first
```

这个 `offset` 表示当前点在这一层里相对左上角偏了多少。

### 手推一个 4 个点交换

例如在 4x4 矩阵的最外层，先看左上角这一组：

```text
(top)    matrix[first][i]
(left)   matrix[last - offset][first]
(bottom) matrix[last][last - offset]
(right)  matrix[i][last]
```

顺时针旋转后应当变成：

- `left -> top`
- `bottom -> left`
- `right -> bottom`
- `top -> right`

所以只需要先用 `top` 暂存一个值，再按这个顺序覆盖回去。

对应代码文件：

```text

```

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

### 评价

这个方法是真正的原地旋转。

优点：

- 满足题目要求
- 没有额外矩阵

缺点：

- 索引比较绕
- 面试里更容易写错

所以它虽然正确，但通常不是最适合面试现场手写的版本。

## 方法三：转置 + 翻转（面试主推）

这是最适合面试的方法。

### 第一步：先想，能不能把“旋转”拆成两个更熟悉的操作

直接原地旋转，索引容易绕。

所以更好的思路是问：

```text
顺时针旋转 90 度，能不能拆成两个更简单的矩阵变换？
```

答案是可以的：

1. 先转置
2. 再把每一行左右翻转

### 第二步：什么叫转置

转置就是沿主对角线交换：

```text
matrix[i][j] <-> matrix[j][i]
```

例如：

```text
[
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9]
]
```

转置后变成：

```text
[
  [1, 4, 7],
  [2, 5, 8],
  [3, 6, 9]
]
```

也就是“行列互换”。

### 第三步：转置后再翻转每一行

然后把每一行左右颠倒：

```text
[1, 4, 7] -> [7, 4, 1]
[2, 5, 8] -> [8, 5, 2]
[3, 6, 9] -> [9, 6, 3]
```

结果就正好是：

```text
[
  [7, 4, 1],
  [8, 5, 2],
  [9, 6, 3]
]
```

这恰好就是顺时针旋转 90 度。

### 第四步：为什么这两步正好等价于旋转

这一步最好在面试里讲出来。

原坐标 `(i, j)`：

1. 转置后变成：
   ```text
   (j, i)
   ```
2. 再左右翻转这一行后，列坐标会变成：
   ```text
   n - 1 - i
   ```

所以最终位置就是：

```text
(i, j) -> (j, n - 1 - i)
```

这正好和顺时针旋转 90 度的规律完全一致。

### 第五步：为什么转置时 `j` 要从 `i + 1` 开始

这是代码细节里最容易写错的一点。

如果你写：

```python
for i in range(n):
    for j in range(n):
        matrix[i][j], matrix[j][i] = matrix[j][i], matrix[i][j]
```

那会出问题。

因为：

- 交换 `(i, j)` 和 `(j, i)` 一次之后
- 后面又会再交换回来一次

结果等于白做。

所以转置时只需要遍历主对角线右上角那一半：

```python
for i in range(n):
    for j in range(i + 1, n):
```

这样每对位置只交换一次。

### 代码

对应代码文件：

```text

```

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法三，转置 + 翻转。**

### 为什么它最适合面试

1. 满足原地修改要求
2. 空间复杂度是 `O(1)`
3. 代码比逐层旋转更短、更自然
4. 思路比死记四位置交换更容易复述
5. 面试里不容易写错

### 方法二为什么不是主推

方法二也是原地做，而且复杂度同样很好。

但它的问题是：

```text
索引关系太绕，现场很容易把四个位置写错
```

相比之下，方法三更像“把复杂操作拆成两个标准操作”，表达更自然。

---

## 最适合面试的方法：详细讲解

### 1. 先记住旋转的目标坐标

顺时针旋转 90 度后：

```text
(i, j) -> (j, n - 1 - i)
```

这是最终目标。

### 2. 再想怎么用两个简单操作拼出来

直接做到这个坐标变换并不直观。

但如果先转置：

```text
(i, j) -> (j, i)
```

再把每一行左右翻转：

```text
(j, i) -> (j, n - 1 - i)
```

刚好就拼成了目标。

这就是为什么“转置 + 翻转”不是技巧，而是真正推出来的。

### 3. 为什么是翻转每一行，不是翻转每一列

这是很多人会混的地方。

因为转置之后，我们已经把“原来的行”变成“新的列”了。

如果此时再左右翻转每一行，最终得到的是顺时针旋转。

如果你改成上下翻转每一列，得到的就是别的变换，不是这题要的结果。

### 4. 代码里最容易错的两个点

#### 第一，转置时的遍历范围

必须写成：

```python
for i in range(n):
    for j in range(i + 1, n):
```

不能从 `0` 开始遍历整行，否则会重复交换。

#### 第二，这题要原地改，不要返回新矩阵

LeetCode 这题函数签名通常是：

```python
def rotate(self, matrix: List[List[int]]) -> None:
```

意思就是：

```text
直接改 matrix，不返回东西
```

这一点面试里也要注意。

## 三种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 是否原地 | 评价 |
| --- | --- | --- | --- | --- |
| 方法一：辅助矩阵 | `O(n^2)` | `O(n^2)` | 否 | 最容易理解 |
| 方法二：逐层旋转 | `O(n^2)` | `O(1)` | 是 | 原地可做，但索引较绕 |
| 方法三：转置 + 翻转 | `O(n^2)` | `O(1)` | 是 | 面试主推 |

---

## 最后总结

这题最重要的主线是：

1. 先看清坐标规律：`(i, j) -> (j, n - 1 - i)`
2. 如果不考虑原地，辅助矩阵最好理解
3. 如果要原地，可以四位置循环交换
4. 但更适合面试的是：先转置，再翻转每一行

能把这条主线讲清楚，这题就算真正掌握了。
