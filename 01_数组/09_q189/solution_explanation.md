# LeetCode 189. 轮转数组（Rotate Array）解析

## 题目描述

给定一个整数数组 `nums`，将数组中的元素向右轮转 `k` 个位置，其中 `k` 是非负数。

题目要求：

```text
原地修改 nums
```

也就是说，函数不返回新数组，而是要直接把原数组改成轮转后的结果。

例如：

```text
nums = [1, 2, 3, 4, 5, 6, 7], k = 3
```

结果应该变成：

```text
[5, 6, 7, 1, 2, 3, 4]
```

---

## 先理解这题最关键的两个点

### 第 1 个关键点：`k` 可能比数组长度大

比如：

```text
nums = [1, 2], k = 3
```

向右轮转 3 次，其实和向右轮转 1 次是一样的。

因为轮转一整圈之后，数组会回到原状。

所以这题第一步通常都要先做：

```text
k = k % n
```

这样就把无效的整圈轮转去掉了。

---

### 第 2 个关键点：题目要求原地修改

这意味着有些很自然的做法虽然能写出来，但不一定满足最优空间复杂度。

所以这题会很典型地出现几层方法：

1. 暴力轮转
2. 额外数组
3. 原地反转
4. Python 切片

其中真正最适合面试主推的，通常是：

```text
三次反转
```

---

## 方法一：每次只轮转一位

### 思路

最直接的想法是：

```text
既然要向右轮转 k 次，那我就真的做 k 次
```

每次轮转一位时：

1. 先保存最后一个元素
2. 然后把前面的元素整体向右挪一位
3. 再把原来的最后一个元素放到最前面

---

### 代码

```python
class Solution:
    def rotate(self, nums: List[int], k: int) -> None:
        n = len(nums)
        k %= n

        for _ in range(k):
            previous = nums[-1]
            for i in range(n):
                nums[i], previous = previous, nums[i]
```

---

### 为什么可行

因为一次“向右轮转一位”本身就是正确操作。

那重复做 `k` 次，最后自然就得到了向右轮转 `k` 位的结果。

---

### 为什么会慢

问题在于：

```text
每轮转一次，都要动一遍整个数组
```

如果：

- 数组长度是 `n`
- 轮转次数是 `k`

那总操作量就是：

```text
O(n * k)
```

当 `k` 很大时就会很慢。

---

### 复杂度

- 时间复杂度：`O(n * k)`
- 空间复杂度：`O(1)`

---

## 方法二：额外数组记录新位置

### 核心思路

如果我们先不管“额外空间”，其实这题非常好做。

因为每个元素轮转后的新下标都能直接算出来：

```text
new_index = (old_index + k) % n
```

所以我们可以：

1. 新建一个和原数组等长的数组 `rotated`
2. 遍历原数组 `nums[i]`
3. 把它放到 `rotated[(i + k) % n]`
4. 最后再把 `rotated` 拷回 `nums`

---

### 代码

```python
class Solution:
    def rotate(self, nums: List[int], k: int) -> None:
        n = len(nums)
        k %= n
        rotated = [0] * n

        for i in range(n):
            rotated[(i + k) % n] = nums[i]

        for i in range(n):
            nums[i] = rotated[i]
```

---

### 为什么可行

因为轮转本质上就是“元素搬家”。

而这个公式：

```text
(i + k) % n
```

恰好就是“从旧位置向右走 `k` 步后，落到哪里”。

有了这个公式，每个元素的新位置都能一次确定。

---

### 用例子走一遍

假设：

```text
nums = [1, 2, 3, 4, 5, 6, 7], k = 3
```

那么：

- `1` 原来在下标 `0`，新位置是 `(0 + 3) % 7 = 3`
- `2` 原来在下标 `1`，新位置是 `(1 + 3) % 7 = 4`
- `3` 原来在下标 `2`，新位置是 `(2 + 3) % 7 = 5`
- `4` 原来在下标 `3`，新位置是 `(3 + 3) % 7 = 6`
- `5` 原来在下标 `4`，新位置是 `(4 + 3) % 7 = 0`
- `6` 原来在下标 `5`，新位置是 `(5 + 3) % 7 = 1`
- `7` 原来在下标 `6`，新位置是 `(6 + 3) % 7 = 2`

最终得到：

```text
[5, 6, 7, 1, 2, 3, 4]
```

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

---

### 这个方法怎么看

这个方法非常适合作为：

```text
最容易想到的 O(n) 解法
```

如果你面试时先给出这个方法，再继续优化到原地反转，层次会很好。

---

## 方法三：三次反转（面试主推）

### 先别背，先理解为什么能这样做

这是这题最关键的地方。

假设原数组是：

```text
[1, 2, 3, 4, 5, 6, 7]
```

`k = 3`。

我们想要的结果是：

```text
[5, 6, 7, 1, 2, 3, 4]
```

把原数组拆成两段：

- 前面 `n-k` 个元素：`[1, 2, 3, 4]`
- 后面 `k` 个元素：`[5, 6, 7]`

目标其实就是把它变成：

```text
后半段 + 前半段
```

也就是：

```text
[5, 6, 7] + [1, 2, 3, 4]
```

---

### 三次反转为什么成立

设：

- `A = [1, 2, 3, 4]`
- `B = [5, 6, 7]`

原数组是：

```text
A + B
```

我们想得到：

```text
B + A
```

现在看三步：

### 第一步：反转整个数组

```text
A + B
-> reverse(B) + reverse(A)
```

也就是：

```text
[7, 6, 5, 4, 3, 2, 1]
```

### 第二步：反转前 `k` 个元素

前 `k` 个元素就是 `reverse(B)`，把它反回来，就得到 `B`：

```text
[5, 6, 7, 4, 3, 2, 1]
```

### 第三步：反转后 `n-k` 个元素

后面这一段是 `reverse(A)`，再反回来就得到 `A`：

```text
[5, 6, 7, 1, 2, 3, 4]
```

这就正好变成目标答案。

所以这不是技巧硬记，而是：

```text
先整体倒过来，再把两段各自倒回来
```

---

### 面试代码

```python
class Solution:
    def rotate(self, nums: List[int], k: int) -> None:
        n = len(nums)
        k %= n

        def reverse(left, right):
            while left < right:
                nums[left], nums[right] = nums[right], nums[left]
                left += 1
                right -= 1

        reverse(0, n - 1)
        reverse(0, k - 1)
        reverse(k, n - 1)
```

---

### 这段代码为什么这样写

这里最关键的是三个区间：

1. `reverse(0, n - 1)`：先反转整个数组
2. `reverse(0, k - 1)`：把前面那段恢复成正确顺序
3. `reverse(k, n - 1)`：把后面那段恢复成正确顺序

而 `k %= n` 则是在保证：

```text
我们实际只处理有效轮转次数
```

如果你在面试里能把这三步和 `A + B -> B + A` 的关系讲明白，这题就算讲透了。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

因为每个元素最多被交换常数次。

---

## 方法四：Python 切片

### 核心思路

如果是在 Python 里，这题还有一个特别简洁的写法：

```python
nums[:] = nums[n - k:] + nums[:n - k]
```

这里：

- `nums[n-k:]` 是后 `k` 个元素
- `nums[:n-k]` 是前 `n-k` 个元素
- 拼接后刚好就是轮转结果

---

### 为什么必须写成 `nums[:] = ...`

这点很容易写错。

如果你写成：

```python
nums = nums[n-k:] + nums[:n-k]
```

那只是让局部变量 `nums` 指向了一个新列表。

外面的原数组并没有被原地修改。

而：

```python
nums[:] = ...
```

修改的是原列表内部的内容，所以才符合题目要求。

---

### 代码

```python
class Solution:
    def rotate(self, nums: List[int], k: int) -> None:
        n = len(nums)
        k %= n
        nums[:] = nums[n - k:] + nums[:n - k]
```

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

因为切片和拼接都会创建新列表。

---

### 这个方法适合什么时候讲

如果题目是 Python 环境下的日常编码，这个方法非常好用。

但如果是算法面试，它通常不是主推，因为：

- 太依赖语言特性
- 没有体现原地 `O(1)` 空间优化

所以它更适合作为：

```text
Python 补充写法
```

而不是第一答案。

---

## 为什么方法三最适合面试

这题最适合面试主推的方法就是：

```text
三次反转
```

原因有三个。

### 1. 它满足题目对原地修改的要求

不需要额外数组，直接在原数组上操作。

### 2. 它时间和空间都很好

- 时间复杂度 `O(n)`
- 空间复杂度 `O(1)`

这是这题非常标准的优秀答案。

### 3. 它虽然有技巧性，但可以推导出来

只要你能把数组拆成：

```text
A + B
```

然后解释：

```text
整体反转，再把两段分别反转
```

这个方法其实是可讲清楚的，不是只能死背。

---

## 面试里可以怎么讲

你可以这样解释：

```text
我先把数组看成前半段 A 和后半段 B，其中后半段长度是 k。
目标就是把 A + B 变成 B + A。
如果先反转整个数组，会得到 reverse(B) + reverse(A)。
然后再分别反转前 k 个元素和后 n-k 个元素，就能把它们恢复成 B 和 A，最终得到 B + A。

这样时间复杂度是 O(n)，空间复杂度是 O(1)。
```

如果你想先给一个更容易想到的解法，可以先说额外数组法，再优化到反转法。

---

## 总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：每次轮转一位 | `O(n * k)` | `O(1)` | 直观，但很慢 |
| 方法二：额外数组 | `O(n)` | `O(n)` | 最容易想到的线性解法 |
| 方法三：三次反转 | `O(n)` | `O(1)` | 面试主推 |
| 方法四：Python 切片 | `O(n)` | `O(n)` | Python 写法简洁，但不适合作为主答案 |

这题最重要的一句话是：

```text
把数组拆成前半段 A 和后半段 B，轮转本质上就是把 A + B 变成 B + A。
```

只要这一句真正想明白，反转法就不难记了。
