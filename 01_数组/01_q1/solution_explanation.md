# LeetCode 1. 两数之和（Two Sum）解析

## 题目描述

给定一个整数数组 `nums` 和一个目标值 `target`，请你在数组中找出 **两个不同下标**，使得它们对应的数字之和等于 `target`。

返回这两个下标。

题目还隐含了两个关键条件：

- 不能重复使用同一个元素
- 题目通常保证**恰好存在一个答案**

例如：

```text
nums = [2, 7, 11, 15], target = 9
```

因为：

```text
2 + 7 = 9
```

所以返回：

```text
[0, 1]
```

---

## 先理解题意

这题最核心的不是“找两个数的和”，而是：

```text
找两个下标 i 和 j，使得 nums[i] + nums[j] = target，且 i != j
```

也就是说，返回的不是数值本身，而是：

```text
这两个数所在的位置
```

这会直接影响我们怎么设计算法。

再看一个容易出错的例子：

```text
nums = [3, 3], target = 6
```

答案应该是：

```text
[0, 1]
```

而不是：

```text
[0, 0]
```

所以这题从头到尾都要记住一句话：

```text
不能把同一个下标用两次
```

---

## 方法一：暴力双循环

### 思路

最直接的想法就是枚举所有下标对：

- 第一个数选 `i`
- 第二个数选 `j`
- 检查 `nums[i] + nums[j]` 是否等于 `target`

因为题目要求两个下标不同，所以第二层循环可以从 `i + 1` 开始。

---

### 代码

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        n = len(nums)

        for i in range(n):
            for j in range(i + 1, n):
                if nums[i] + nums[j] == target:
                    return [i, j]

        return []
```

---

### 为什么可行

因为它把所有可能的两个下标组合都试了一遍。

只要答案存在，枚举到那一对时就一定能找到。

例如：

```text
nums = [2, 7, 11, 15], target = 9
```

枚举过程：

- `i = 0, j = 1`，`2 + 7 = 9`，直接返回 `[0, 1]`

逻辑非常直观。

---

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

---

### 不足在哪里

它慢在：

```text
每个位置都要和后面很多位置再配一次
```

如果数组很长，重复检查会很多。

所以接下来要想：

```text
当我看到 nums[i] 时，能不能更快知道“它缺的那个数”以前出现过没有？
```

这就自然引到哈希表。

---

## 方法二：两遍哈希表

### 核心想法

如果当前数是 `num`，那么我们真正想找的是：

```text
need = target - num
```

也就是说，问题可以改写成：

```text
对于每个 nums[i]，快速判断数组里有没有 target - nums[i]
```

“快速判断某个值是否存在”，最适合用：

```text
哈希表
```

---

### 第一步：先把所有值的位置记下来

我们先建立一个哈希表：

```text
数值 -> 下标
```

例如：

```text
nums = [2, 7, 11, 15]
```

建表后：

```text
{
    2: 0,
    7: 1,
    11: 2,
    15: 3
}
```

---

### 第二步：再枚举每个位置，找补数

假设当前：

```text
nums[i] = num
```

那就去看：

```text
target - num
```

是否在哈希表里。

如果在，就说明我们找到了另一半。

---

### 代码

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        pos = {}

        for i, num in enumerate(nums):
            pos[num] = i

        for i, num in enumerate(nums):
            need = target - num
            if need in pos and pos[need] != i:
                return [i, pos[need]]

        return []
```

---

### 为什么这里一定要检查 `pos[need] != i`

这是这个方法最关键的细节。

因为哈希表里可能出现这种情况：

```text
target = 2 * num
```

比如：

```text
nums = [3, 2, 4], target = 6
```

当遍历到 `num = 3` 时：

```text
need = 6 - 3 = 3
```

如果数组里只有一个 `3`，那么哈希表会查到它自己。

但题目不允许同一个下标用两次，所以必须额外判断：

```text
查到的那个下标不能等于当前下标
```

这也是两遍哈希表最容易漏掉的点。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

因为：

- 第一遍建表是 `O(n)`
- 第二遍查找是 `O(n)`
- 哈希表查询平均是 `O(1)`

---

### 这个方法已经很好，但还可以再顺一点

两遍哈希表已经达标了。

但它还有一个小别扭：

```text
要额外处理“别查到自己”这个问题
```

那么有没有办法从写法上自然避开这个坑？

有，就是：

```text
先查，再存
```

这就是方法三。

---

## 方法三：一遍哈希表（面试主推）

### 核心思路

我们从左到右遍历数组。

当遍历到当前数字 `num` 时，先问：

```text
我需要的 need = target - num，之前出现过吗？
```

- 如果出现过，直接返回答案
- 如果没出现过，再把当前数字存进哈希表

注意顺序一定是：

```text
先查 need
再存当前 num
```

这个顺序非常重要。

---

## 为什么“先查再存”这么关键

因为这样可以天然保证：

```text
哈希表里存的都是“当前下标左边已经出现过的数”
```

所以如果查到了 `need`，它对应的一定是：

```text
另一个下标
```

而不可能是当前这个位置自己。

这就不用额外写：

```python
pos[need] != i
```

写法更自然，也更适合面试现场。

---

## 用例子把过程走清楚

假设：

```text
nums = [2, 7, 11, 15], target = 9
```

### 开始时

```text
pos = {}
```

### 1. 遍历到 `2`，下标 `0`

先算：

```text
need = 9 - 2 = 7
```

检查 `7` 是否已经在哈希表里：

```text
不在
```

那就把当前数存进去：

```text
pos = {2: 0}
```

### 2. 遍历到 `7`，下标 `1`

先算：

```text
need = 9 - 7 = 2
```

检查 `2` 是否在哈希表里：

```text
在，且它的下标是 0
```

所以直接返回：

```text
[0, 1]
```

整个过程结束。

---

## 再看一个容易错的例子

```text
nums = [3, 3], target = 6
```

### 1. 遍历第一个 `3`，下标 `0`

- `need = 3`
- 哈希表里还没有 `3`
- 存入：`{3: 0}`

### 2. 遍历第二个 `3`，下标 `1`

- `need = 3`
- 哈希表里已经有 `3`，对应下标 `0`
- 直接返回 `[0, 1]`

这里就能看出“先查再存”的好处：

```text
不会把当前元素和自己配对
```

---

## 面试代码

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        pos = {}

        for i, num in enumerate(nums):
            need = target - num
            if need in pos:
                return [pos[need], i]
            pos[num] = i

        return []
```

---

## 为什么这个方法最适合面试

最适合面试的方法是：

```text
一遍哈希表
```

原因有三个。

### 1. 时间复杂度最优

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

这是这题最经典、最标准的最优解。

### 2. 思路自然

你只需要记一句话：

```text
遍历到当前数时，去看它需要的那个数以前出现过没有
```

这句话非常容易讲清楚。

### 3. 代码最稳

相比两遍哈希表，一遍写法天然避免“查到自己”的问题。

面试里更不容易出错。

---

## 面试里怎么讲

你可以直接这样解释：

```text
我用哈希表记录已经遍历过的数字及其下标。
当遍历到当前 nums[i] 时，我先计算它还缺多少，也就是 need = target - nums[i]。
如果 need 已经在哈希表里，说明我之前见过这个数，那么这两个位置就是答案。
如果不在，我再把当前数字和下标存进哈希表。

这样每个元素只处理一次，所以时间复杂度是 O(n)，空间复杂度是 O(n)。
```

这是最标准、也最好复述的说法。

---

## 复杂度总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力双循环 | `O(n^2)` | `O(1)` | 好想，但慢 |
| 方法二：两遍哈希表 | `O(n)` | `O(n)` | 达标，但要额外防止用到自己 |
| 方法三：一遍哈希表 | `O(n)` | `O(n)` | 面试主推 |

---

## 总结

这题最重要的不是背模板，而是把这个思路转化过程讲清楚：

```text
从“枚举两个数”
到“当前数要找的是 target - num”
再到“用哈希表快速判断这个补数是否出现过”
```

真正最适合面试的结论是：

```text
一边遍历，一边把已经见过的数存进哈希表；每次先查补数，再存当前数。
```

只要你把这句话和 `nums = [3, 3], target = 6` 这个例子讲清楚，这题通常就算真正理解了。
