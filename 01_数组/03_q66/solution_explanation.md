# LeetCode 66. 加一（Plus One）解析

## 题目描述

给定一个由数字组成的数组 `digits`，它按从高位到低位表示一个非负整数。

现在要在这个整数的基础上加 `1`，并返回结果对应的数组形式。

例如：

```text
[1, 2, 3] -> [1, 2, 4]
[1, 2, 9] -> [1, 3, 0]
[9, 9, 9] -> [1, 0, 0, 0]
```

题目的关键不是“会不会加一”，而是：

```text
数组怎么处理进位
```

---

## 先理解这题本质

这个数组本质上就是一个十进制数。

比如：

```text
[4, 3, 2, 1]
```

表示的就是：

```text
4321
```

现在让它加 `1`，最自然的想法有两种：

1. 直接把它转成数字，`+1` 之后再转回来
2. 按照手算加法，从最后一位开始处理进位

第一种更直观，第二种才是这题真正想考的内容。

---

## 方法一：类型转换（直观解法）

### 思路

最直接的做法是：

1. 先把数组拼成字符串
2. 再转成整数
3. 执行 `+ 1`
4. 把结果重新拆成数字数组

例如：

```text
[1, 2, 3]
-> "123"
-> 123
-> 124
-> [1, 2, 4]
```

---

### 代码

```python
class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        number = int("".join(str(digit) for digit in digits)) + 1
        return [int(digit) for digit in str(number)]
```

---

### 为什么可行

因为题目给的数组本来就是一个十进制整数的每一位。

只要我们能把它完整地还原成整数，那么加一之后再拆回去，结果一定正确。

---

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

这里的 `n` 是数组长度。

---

### 这个方法的问题

这个方法虽然简单，但它更像：

```text
借助 Python 语言特性做题
```

而不是在真正处理“数组里的进位逻辑”。

如果换成一些整数范围有限的语言，或者题目数据很大，这种写法就不够稳。

所以它适合帮助我们快速理解题目，但通常不是面试主推。

---

## 方法二：从后往前模拟进位（面试主推）

### 核心思路

这题本质上就是模拟十进制加法。

我们只需要关注最后一位：

- 如果最后一位不是 `9`，那它加一之后就结束了
- 如果最后一位是 `9`，那它会变成 `0`，并向前产生进位
- 进位会一直向左传，直到某一位不是 `9`
- 如果所有位都是 `9`，那最后就会多出一个新最高位 `1`

所以应该：

```text
从右往左扫描数组
```

---

### 为什么从右往左就够了

因为“加一”只会先影响最低位。

例如：

```text
123 + 1
```

最先变化的一定是最后那个 `3`。

如果它加一后没有进位，那么前面的数都不会变。

只有当当前位是 `9` 的时候，才需要把影响继续传到左边。

这就是为什么我们从后往前处理，而且一旦某一位成功加一，就可以立刻返回。

---

### 用例子走一遍

假设：

```text
digits = [1, 2, 9, 9]
```

我们从最后一位开始看。

### 第 1 步：看最后一位 `9`

```text
[1, 2, 9, 9]
          ^
```

这一位如果加一，会变成 `10`。

也就是说：

- 当前位要写成 `0`
- 向前继续进位

数组变成：

```text
[1, 2, 9, 0]
```

### 第 2 步：再看前一位 `9`

```text
[1, 2, 9, 0]
       ^
```

它也会因为进位而变成 `10`，所以同样：

- 当前位写成 `0`
- 继续向前进位

数组变成：

```text
[1, 2, 0, 0]
```

### 第 3 步：看 `2`

```text
[1, 2, 0, 0]
    ^
```

这一位不是 `9`，所以它只要加一就行：

```text
2 -> 3
```

于是结果直接变成：

```text
[1, 3, 0, 0]
```

到这里就结束了，因为已经没有继续进位的必要。

---

### 全是 9 的特殊情况

如果是：

```text
[9, 9, 9]
```

那么从右往左每一位都会变成 `0`。

最后数组会临时变成：

```text
[0, 0, 0]
```

但这还不是真正答案。

因为：

```text
999 + 1 = 1000
```

所以最后还要在最前面补一个 `1`：

```text
[1, 0, 0, 0]
```

这就是这题唯一需要额外注意的边界。

---

### 面试代码

```python
class Solution:
    def plusOne(self, digits: List[int]) -> List[int]:
        for i in range(len(digits) - 1, -1, -1):
            if digits[i] < 9:
                digits[i] += 1
                return digits
            digits[i] = 0

        return [1] + digits
```

---

### 这段代码为什么这样写

这里最关键的是 `if digits[i] < 9` 这一句。

它表达的是：

```text
只要当前位不是 9，那么这次加一一定不会继续进位
```

比如当前位是 `3`：

```text
3 + 1 = 4
```

直接结束。

比如当前位是 `8`：

```text
8 + 1 = 9
```

也直接结束。

只有当前位是 `9` 时，才会出现：

```text
9 + 1 = 10
```

这时候当前位必须变成 `0`，并把进位交给前一位。

所以这段代码不是在机械背模板，而是在非常直接地翻译“十进制加一”的规则。

---

### 复杂度

- 时间复杂度：`O(n)`
- 额外空间复杂度：`O(1)`

因为最多从右往左扫描一遍数组。

---

## 为什么这个方法最适合面试

最适合面试的方法就是：

```text
从后往前模拟进位
```

原因有三个。

### 1. 它真正抓住了题目本质

题目考的就是：

```text
数组里的十进制进位怎么处理
```

这个方法正面解决了这个问题。

### 2. 代码很短，但逻辑非常自然

不是为了短而短，而是因为规则本来就简单：

- 不是 `9` 就加一返回
- 是 `9` 就写成 `0` 继续往前
- 全是 `9` 就补一个 `1`

面试里很好写，也很好讲。

### 3. 它不依赖语言特性

无论是 Python、Java、C++ 还是 Go，这个思路都成立。

所以它比“转整数再转回来”更通用，也更像算法题解法。

---

## 面试里可以怎么讲

你可以这样说明：

```text
这题本质是在模拟十进制加一。
我从数组最后一位开始往前看：
如果当前位小于 9，那么它加一后不会继续进位，直接返回。
如果当前位等于 9，那么它会变成 0，并把进位继续传给前一位。
如果所有位都是 9，就说明最后需要新增一个最高位 1。

所以时间复杂度是 O(n)，额外空间复杂度是 O(1)。
```

这套表达在面试里非常稳。

---

## 总结

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：类型转换 | `O(n)` | `O(n)` | 直观，但更依赖 Python 特性 |
| 方法二：模拟进位 | `O(n)` | `O(1)` | 面试主推 |

这题最重要的一句话是：

```text
加一只会先影响最后一位，只有遇到 9 才会把进位继续往左传。
```

一旦把这句话想明白，这题就很顺了。
