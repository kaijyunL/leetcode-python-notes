# LeetCode 560. 和为 K 的子数组（Subarray Sum Equals K）解析

## 题目描述

给你一个整数数组 `nums` 和一个整数 `k`，请你统计并返回：

```text
和恰好等于 k 的连续子数组的个数
```

注意，这里要求的是：

```text
连续子数组
```

不是任意挑几个数。

例如：

```text
nums = [1, 1, 1], k = 2
```

答案是：

```text
2
```

因为和为 `2` 的连续子数组有两个：

- `[1, 1]`（下标 `0~1`）
- `[1, 1]`（下标 `1~2`）

---

## 先理解题意

这题最容易看错的地方有两个。

### 1. 要的是“个数”，不是最长长度

很多子数组题会问：

- 最长多长
- 最大和是多少
- 是否存在

但这题问的是：

```text
一共有多少个连续子数组，它们的和等于 k
```

所以只要找到一个符合条件的子数组，就要把答案加一，而不是立刻返回。

### 2. 数组里可以有负数

这点非常关键。

如果数组全是正数，那我们经常会想到滑动窗口。

但这题没有保证元素都为正。

比如：

```text
nums = [1, -1, 1]
```

这时候窗口右边加一个数，和可能变大，也可能变小。

所以：

```text
不能直接套“和太大就缩左边”的滑动窗口模板
```

这也是这题真正的难点。

## 方法一：暴力枚举所有子数组，再逐个求和

### 思路

最直接的想法就是：

- 枚举每个起点 `left`
- 枚举每个终点 `right`
- 对 `nums[left:right+1]` 单独求和
- 如果和等于 `k`，答案加一

这就是完全按题意硬做。

### 为什么可行

因为所有连续子数组都可以唯一表示成：

```text
[left, right]
```

只要我们把所有 `(left, right)` 组合都枚举到，就不会漏掉任何答案。

### 代码

对应代码文件：

```text
01_数组/13_q560/solution_1_brute_force.py
```

### 复杂度

- 时间复杂度：`O(n^3)`
- 空间复杂度：`O(1)`

### 为什么会慢

外层两层循环负责枚举子数组，已经是 `O(n^2)`。

而每次再去对一个子数组重新求和，又要 `O(n)`。

所以总复杂度变成：

```text
O(n^2) * O(n) = O(n^3)
```

这个方法能帮助我们理解题意，但性能太差。

---

## 方法二：固定起点，向右扩展时顺手累加

### 思路

方法一慢的原因之一是：

```text
同一个子数组里的和被重复算了很多次
```

比如固定起点 `left = 0` 时：

- `nums[0:0]`
- `nums[0:1]`
- `nums[0:2]`
- `nums[0:3]`

这些子数组其实只有右边不断多加一个数。

所以可以优化成：

- 固定起点 `left`
- 用一个变量 `current_sum` 表示从 `left` 到当前 `right` 的和
- 每次 `right` 向右走一步，就做：`current_sum += nums[right]`
- 如果 `current_sum == k`，答案加一

这样就不用每次对子数组重新求和了。

### 例子

看：

```text
nums = [1, 2, 1], k = 3
```

固定 `left = 0`：

- `right = 0`，`current_sum = 1`
- `right = 1`，`current_sum = 3`，答案加一
- `right = 2`，`current_sum = 4`

固定 `left = 1`：

- `right = 1`，`current_sum = 2`
- `right = 2`，`current_sum = 3`，答案再加一

最终答案是 `2`。

### 为什么可行

因为对于每个固定起点，我们仍然枚举了所有可能的终点。

只是把“反复重新求和”优化成了“边扩展边累加”。

所以结果仍然正确，只是更快了。

### 代码

对应代码文件：

```text

```

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

### 这个方法的问题

它已经把时间从 `O(n^3)` 降到了 `O(n^2)`。

但如果数组长度很大，平方级复杂度还是不够好。

而且题目这类“连续子数组 + 求和 + 统计个数”的组合，经常还可以继续往：

```text
前缀和 + 哈希表
```

上优化。

## 方法三：前缀和 + 哈希表（面试主推）

这是最适合面试的方法。

### 第一步：把“子数组和”改写成“两个前缀和之差”

这题最核心的一步是公式转换。

定义：

```text
prefix[i] 表示 nums[0] 到 nums[i] 的前缀和
```

那么子数组 `nums[left...right]` 的和就等于：

```text
prefix[right] - prefix[left - 1]
```

如果它要等于 `k`，那就有：

```text
prefix[right] - prefix[left - 1] = k
```

移项后得到：

```text
prefix[left - 1] = prefix[right] - k
```

这句话非常重要。

它告诉我们：

```text
当我们走到某个位置 right 时，问题就变成了：前面出现过多少个前缀和，值等于 current_prefix - k？
```

只要有这样的前缀和，就说明存在一个以当前 `right` 结尾的子数组，和正好等于 `k`。

### 第二步：先自然想到哈希结构

看到这一步，最自然的想法通常是：

```text
我能不能一边遍历，一边把前面出现过的前缀和存起来？
```

这当然要用哈希结构。

但这时候先不要急着决定到底是：

- `set`
- 还是 `dict`

因为我们还得先想清楚一个问题：

```text
我们到底只需要知道“它出现过没有”，还是需要知道“它出现过几次”？
```

这个问题不能靠拍脑袋决定，最好用例子推出来。

### 第三步：为什么初始要放 `0: 1`

这是这题最容易错的细节，也是面试里一定要讲明白的地方。

一开始我们会写：

```python
prefix_count = {0: 1}
```

为什么不是空字典？

因为这表示：

```text
在还没开始遍历数组之前，前缀和 0 已经出现过 1 次
```

它的作用是处理：

```text
从下标 0 开始的子数组
```

比如：

```text
nums = [1, 2, 3], k = 3
```

遍历到下标 `1` 时：

```text
current_sum = 3
```

这时我们要找：

```text
current_sum - k = 0
```

如果哈希表里提前有 `0:1`，就说明存在一个“之前的前缀和为 0”的位置，于是子数组 `[0...1]` 会被正确统计进去。

如果没有这个初始化，就会漏掉所有：

```text
从开头开始、和正好等于 k 的子数组
```

### 第四步：手推一个更能说明问题的例子

前面那个 `nums = [1, 1, 1], k = 2` 虽然能算对，但它确实有一个问题：

```text
每次查到的前缀和次数刚好都是 1
```

这样容易让人产生错觉：

```text
好像只要知道“这个前缀和出现过没有”就够了
```

但其实不是。

更好的例子是：

```text
nums = [1, -1, 1, -1, 1], k = 1
```

初始化：

```text
current_sum = 0
ans = 0
prefix_count = {0: 1}
```

遍历第一个 `1`：

```text
current_sum = 1
要找 current_sum - k = 0
0 出现过 1 次
ans = 1
把 1 记进去
prefix_count = {0: 1, 1: 1}
```

这里对应的子数组是：

```text
[0...0]
```

---

遍历第二个 `-1`：

```text
current_sum = 0
要找 current_sum - k = -1
没有
把 0 的次数加 1
prefix_count = {0: 2, 1: 1}
```

---

遍历第三个 `1`：

```text
current_sum = 1
要找 current_sum - k = 0
0 已经出现过 2 次
ans += 2
把 1 的次数加 1
prefix_count = {0: 2, 1: 2}
```

为什么这里要加 `2`？

因为这 2 次前缀和为 `0`，对应的是两个不同的左边界，所以会形成两个不同的合法子数组：

```text
[0...2]
[2...2]
```

---

遍历第四个 `-1`：

```text
current_sum = 0
要找 current_sum - k = -1
没有
把 0 的次数加 1
prefix_count = {0: 3, 1: 2}
```

---

遍历第五个 `1`：

```text
current_sum = 1
要找 current_sum - k = 0
0 已经出现过 3 次
ans += 3
把 1 的次数加 1
prefix_count = {0: 3, 1: 3}
```

这次又会新增 3 个合法子数组：

```text
[0...4]
[2...4]
[4...4]
```

最终答案是：

```text
6
```

这个例子比 `nums = [1, 1, 1], k = 2` 更适合讲方法三，因为这里能明显看出：我们统计的不是“某个前缀和有没有出现过”，而是“它之前一共出现过多少次”。

### 为什么这个方法是 O(n)

因为整个过程中：

- 每个元素只遍历一次
- 每次只做常数次哈希表查询和更新

所以总时间复杂度是：

```text
O(n)
```

### 代码

对应代码文件：

```text

```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法三，前缀和 + 哈希表。**

### 为什么它最适合面试

1. 它是这题的标准最优解，时间复杂度能到 `O(n)`
2. 思路有清晰推导，不是纯背模板
3. 代码长度适中，白板上可写
4. 关键细节明确，尤其是 `prefix_count = {0: 1}` 很适合展开解释

### 为什么这题不主推滑动窗口

这也是很常见的面试追问。

原因是：

```text
数组里可能有负数
```

一旦有负数，窗口和就不再具有单调性。

也就是说：

- 右边加一个数，和不一定变大
- 左边去掉一个数，和也不一定变小

所以没法稳定使用“和太大就缩左边”的套路。

这正是为什么这题要转向前缀和。

## 最适合面试的方法：详细讲解

### 1. 为什么“前缀和”特别适合连续子数组问题

只要题目出现：

- 连续子数组
- 区间和
- 统计个数

就要很自然地想到前缀和。

因为连续区间的和，本质上都能写成：

```text
两个前缀和相减
```

这比直接枚举整个区间要高效得多。

### 2. 这题真正统计的到底是什么

遍历到当前位置时，我们不是在问：

```text
当前这个数能不能组成答案？
```

而是在问：

```text
前面有多少个位置，使得“前缀和差值”恰好等于 k？
```

所以这题的统计单位其实不是元素，而是：

```text
前缀和出现的次数
```

这也是为什么哈希表里存的是“次数”，而不是只存“是否出现过”。

### 3. 为什么是“先查，再更新”

代码里顺序一般写成：

1. 更新当前前缀和
2. 查询 `current_sum - k` 出现过多少次
3. 把当前前缀和加入哈希表

这个顺序不能随便反。

因为我们要统计的是：

```text
以当前位置结尾的子数组
```

所以查找时，哈希表里应该只包含“当前位置之前”的前缀和。

如果你先把当前前缀和放进去，再去查，有些情况下会把当前位置自己错误算进去。

### 4. 为什么哈希表里存“次数”而不是“最后一次位置”

因为同一个前缀和可能出现很多次。

比如：

```text
nums = [1, -1, 1, -1]
```

前缀和会反复出现 `0`、`1`。

而每出现一次相同前缀和，都可能和当前前缀和组成一个新的合法子数组。

所以我们不能只记“这个前缀和出现过”，必须记：

```text
它之前一共出现过多少次
```

这样才能一次性把所有答案都加进去。

## 面试里可以怎么说

如果面试官让你口述思路，可以这样说：

```text
这题不能直接用滑动窗口，因为数组里可能有负数。
我会把子数组和转成两个前缀和之差：prefix[right] - prefix[left - 1] = k。
所以遍历到当前位置时，只要知道前面有多少个前缀和等于 current_sum - k，就知道有多少个子数组以当前位置结尾且和为 k。
因此我用哈希表统计每个前缀和出现的次数，边遍历边累加答案，时间复杂度是 O(n)。
```

这套表达会比较完整，也能体现你是真的理解了推导过程。

## 三种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：暴力枚举 + 单独求和 | `O(n^3)` | `O(1)` | 只适合理解题意 |
| 方法二：固定起点 + 滚动累加 | `O(n^2)` | `O(1)` | 很自然的中间过渡 |
| 方法三：前缀和 + 哈希表 | `O(n)` | `O(n)` | 最优解，面试主推 |

## 最后总结

这题最关键的不是记住代码，而是记住下面这条主线：

1. 这题不能稳用滑动窗口，因为可能有负数
2. 连续子数组和要想到前缀和
3. `区间和 = 两个前缀和之差`
4. 要统计个数，就用哈希表记录“前缀和出现次数”

把这四步串起来，这题基本就能自己推出来。
