# LeetCode 59. 螺旋矩阵 II（Spiral Matrix II）解析

## 题目描述

给你一个正整数 `n`，生成一个包含：

```text
1 到 n^2
```

所有元素的 `n x n` 矩阵，并且要求这些数字按照：

```text
顺时针螺旋顺序
```

填入矩阵中。

例如：

```text
n = 3
```

输出：

```text
[
  [1, 2, 3],
  [8, 9, 4],
  [7, 6, 5]
]
```

---

## 先理解题意

### 1. 这题和 54 题是“反方向”关系

第 54 题是：

```text
给你矩阵，让你按螺旋顺序读出来
```

这题则是：

```text
给你 n，让你按螺旋顺序填进去
```

所以两题的核心结构是一样的，都是：

```text
右 -> 下 -> 左 -> 上
```

不断转圈。

### 2. 这题本质上是“模拟填数”

我们不需要找什么复杂公式。

只要想清楚：

- 当前数字填在哪里
- 什么时候该转弯
- 或者当前四个边界是什么

就能把这题写出来。

### 3. 真正容易错的地方是边界和停止条件

因为我们要一边填，一边往里收缩。

如果控制不好，就容易：

- 填重复
- 越界
- 中心位置漏填

所以这题重点依然是：

```text
怎么把螺旋过程稳定地模拟出来
```

---

## 方法一：方向模拟

### 思路

最直观的想法是：

```text
想象有一个指针在矩阵里走路，一边走一边填数字
```

具体做法：

1. 先创建一个 `n x n` 的矩阵，初始全是 `0`
2. 从左上角 `(0, 0)` 出发
3. 当前方向先设为“向右”
4. 每次把当前数字填进当前位置
5. 预判下一步：
   - 如果下一步越界
   - 或者下一步已经填过了
   - 就顺时针转向
6. 持续填到 `n^2`

方向顺序固定是：

```text
右 -> 下 -> 左 -> 上
```

### 为什么可行

因为螺旋矩阵本质上就是一条固定转向规则的路径。

只要：

- 当前位置填数
- 下一步非法就转向
- 保证所有位置只填一次

最后得到的就是题目要求的顺时针螺旋矩阵。

### 为什么这里可以直接用 `0` 判断是否访问过

因为矩阵要填的是：

```text
1 到 n^2
```

不会出现 `0`。

所以初始矩阵里的 `0`，天然就可以表示：

```text
这个格子还没填过
```

这样就不需要额外的 `visited` 数组了。

### 小例子

以 `n = 3` 为例。

初始矩阵：

```text
0 0 0
0 0 0
0 0 0
```

先向右填：

```text
1 2 3
0 0 0
0 0 0
```

下一步再向右会越界，所以转向向下：

```text
1 2 3
0 0 4
0 0 5
```

接着再转向向左、向上、再向右，最后变成：

```text
1 2 3
8 9 4
7 6 5
```

对应代码文件：

```text

```

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

这里额外空间不算输出矩阵本身。

### 评价

优点：

- 最直观
- 很容易从题意直接想到

缺点：

- 要一直做“下一步是否合法”的判断
- 逻辑稍微碎一点

适合当第一种理解方式。

## 方法二：边界收缩（面试主推）

这是最适合面试的方法。

### 第一步：不要只想“转弯”，而要想“当前还能填的范围”

比起模拟一个点不断走，更自然的想法是：

```text
我每次就在当前剩下的矩形外框上填数
```

于是可以定义四个边界：

- `top`
- `bottom`
- `left`
- `right`

它们描述了当前还没填的那一块区域。

### 第二步：每填完一条边，就把对应边界收缩

顺序固定是：

1. 填上边：从左到右
2. 填右边：从上到下
3. 填下边：从右到左
4. 填左边：从下到上

每填完一条边后，对应边界都要收缩：

- 上边填完，`top += 1`
- 右边填完，`right -= 1`
- 下边填完，`bottom -= 1`
- 左边填完，`left += 1`

这样就相当于：

```text
一圈一圈往里面缩
```

### 第三步：为什么这个方法更自然

因为这题本来就是“填外圈，再填内圈”。

边界收缩法直接把这个过程写成：

```text
填完外圈，就把外圈剥掉
```

所以它比“点状模拟转弯”更像在整体控制问题。

### 第四步：为什么这里不一定非要加很多额外判断

这题和第 54 题有一点不同。

第 54 题是“读取已有矩阵”，如果边界交叉后还去读，就会重复读取旧元素。

但这题是“往空矩阵里填数”，而且我们可以用：

```python
while num <= n * n:
```

作为总停止条件。

所以只要循环结构写得稳，很多时候不需要像第 54 题那样在每一步都加很多单独判断。

不过本质上你仍然是在做边界控制。

### 手推一个例子

还是看 `n = 3`。

初始：

```text
left = 0, right = 2, top = 0, bottom = 2
num = 1
```

先填上边：

```text
1 2 3
0 0 0
0 0 0
```

然后 `top = 1`

再填右边：

```text
1 2 3
0 0 4
0 0 5
```

然后 `right = 1`

再填下边：

```text
1 2 3
0 0 4
7 6 5
```

然后 `bottom = 1`

再填左边：

```text
1 2 3
8 0 4
7 6 5
```

然后 `left = 1`

最后只剩中间一个位置，再填上边时就会把 `9` 放进去：

```text
1 2 3
8 9 4
7 6 5
```

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，边界收缩。**

### 为什么它最适合面试

1. 代码结构更整齐
2. 思路和第 54 题可以互相迁移
3. 比方向模拟少一些“下一步是否合法”的细碎判断
4. 更容易讲清楚“外圈 -> 内圈”的过程

### 方法一为什么不是主推

方法一当然也能做对，而且也不难。

但它更像：

```text
局部模拟下一步怎么走
```

方法二则更像：

```text
整体控制当前还剩下的矩形边界
```

所以表达更完整，面试里更稳。

---

## 最适合面试的方法：详细讲解

### 1. 本质还是右、下、左、上四个方向循环

只不过方法二不是通过“方向数组”来切换，而是通过：

```text
四条边依次填
```

来完成同样的效果。

### 2. 每填一条边，就说明这一整条边以后都不再属于未处理区域

所以边界要立刻收缩。

这是这个方法最核心的地方。

### 3. 为什么中心位置不会漏

以奇数阶矩阵为例，比如 `n = 3`、`n = 5`。

最后一定会收缩到中间那一个点。

由于我们的循环条件是：

```text
只要 num 还没填到 n^2 就继续
```

所以中心位置一定会在最后某一步被填上，不会漏掉。

### 4. 代码里最容易错的地方

#### 第一，四条边的遍历区间不要写反

尤其是：

- 下边要从右往左
- 左边要从下往上

#### 第二，边界更新顺序不要乱

必须是：

1. 填上边，缩 `top`
2. 填右边，缩 `right`
3. 填下边，缩 `bottom`
4. 填左边，缩 `left`

这样才能保持和螺旋方向一致。

| 方法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 方法一：方向模拟 | `O(n^2)` | `O(1)` | 直观，容易从题意想到 |
| 方法二：边界收缩 | `O(n^2)` | `O(1)` | 面试主推 |

---

## 最后总结

这题最重要的主线是：

1. 本质就是模拟螺旋填数
2. 可以从“方向模拟”入手理解
3. 更推荐“边界收缩”，因为它更自然地表达了“一圈一圈往里填”
4. 和第 54 题本质相通，只不过一个是“读”，一个是“写”

把这条线理解清楚，这题就不需要死记代码。
