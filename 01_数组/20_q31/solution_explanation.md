# LeetCode 31. 下一个排列（Next Permutation）解析

## 题目描述

给你一个整数数组 `nums`。

你需要把它原地修改成：

```text
字典序中的下一个更大排列
```

如果当前排列已经是字典序最大的那个排列了，就把它改成：

```text
字典序最小的排列
```

也就是把整个数组变成升序。

并且题目要求：

```text
必须原地修改，只能使用 O(1) 额外空间
```

例如：

```text
[1, 2, 3] -> [1, 3, 2]
[3, 2, 1] -> [1, 2, 3]
[1, 1, 5] -> [1, 5, 1]
```

---

## 先理解题意

### 1. 什么叫“下一个排列”

这里说的不是“任意一个更大的排列”，而是：

```text
比当前排列大，但又只大一点点的那个排列
```

也就是按字典序排好之后，紧跟在当前排列后面的那个。

比如这几个排列：

```text
123
132
213
231
312
321
```

那么：

- `123` 的下一个排列是 `132`
- `132` 的下一个排列是 `213`
- `321` 已经是最后一个了，所以要回到 `123`

### 2. 这题的难点不在“会不会枚举”，而在“怎么只改最少”

如果不考虑复杂度，当然可以把所有排列都列出来，再找下一个。

但题目要求是：

- 原地修改
- 常数空间

所以真正要解决的是：

```text
怎样在不枚举所有排列的前提下，直接把当前排列变成“刚好大一点”的那个
```

### 3. 一个关键直觉：越靠右改动，整体变大得越少

如果你想让一个排列变大，但又不想变大太多，那么最自然的想法就是：

```text
尽量在靠右的位置动手
```

因为左边位权更大，越靠左改，整体变化越大。

这就是这题最核心的突破口。

---

## 方法一：生成所有排列后找下一个

### 思路

最直接的想法是：

1. 生成当前数组的所有排列
2. 按字典序排序
3. 找到当前排列的位置
4. 取它后面的那个排列
5. 如果当前已经是最后一个，就回到第一个

### 为什么可行

因为“下一个排列”的定义，本来就是：

```text
在所有排列按字典序排好后，当前排列的下一个
```

所以只要你真把所有排列列出来，当然能找到答案。

### 为什么这个方法不行

因为排列数量是阶乘级别。

如果数组长度是 `n`，全排列数量就是：

```text
n!
```

这个增长速度非常可怕。

所以方法一虽然能帮助理解题意，但在真正提交时完全不可用。

```text

```

### 复杂度

- 时间复杂度：`O(n! * n)`
- 空间复杂度：`O(n! * n)`

### 评价

优点：

- 最容易从定义直接想到
- 有助于建立“字典序下一个”的直观理解

缺点：

- 完全不满足题目要求
- 只能作为理解思路，不能作为正式解法

## 方法二：找到转折点后交换并反转后缀（面试主推）

这是最适合面试的方法。

### 第一步：先找“从哪里开始没法再变大”

从右往左看数组。

如果某一段一直满足：

```text
从左到右是递减的
```

那这一段其实已经是它自己的最大排列了。

比如：

```text
1 5 8 4 7 6 5 3 1
            ^^^^^^^
```

右边这一长段：

```text
7 6 5 3 1
```

本身已经是降序。

降序意味着什么？

意味着：

```text
这部分已经没有办法只靠自己再变大一点点了
```

所以我们必须往它左边找一个位置，让整个数组稍微变大。

### 第二步：找最靠右的“转折点”

我们从右往左找第一个满足：

```text
nums[pivot] < nums[pivot + 1]
```

的位置，这个位置就叫转折点 `pivot`。

为什么要找它？

因为它表示：

```text
从 pivot 这里开始，还有机会把整体排列变大一点点
```

而且我们是从右往左找的，所以它是：

```text
最靠右、最划算的那个改动位置
```

这正符合“尽量在靠右位置动手”的目标。

### 第三步：为什么 `pivot` 右边一定是降序

这是一个必须理解的点。

因为我们是从右往左一直跳过：

```text
nums[i] >= nums[i + 1]
```

直到第一次遇到：

```text
nums[pivot] < nums[pivot + 1]
```

这就说明从 `pivot + 1` 到末尾这一段，原本一直都处在：

```text
降序状态
```

而降序后缀有一个很重要的性质：

```text
它已经是这部分数字能组成的最大字典序排列
```

后面我们正是利用这个性质，才能做到“交换后直接反转”。

### 第四步：在右边找一个“比它大一点点”的数

找到 `pivot` 之后，我们要让整体排列变大。

那就必须找一个数字来替换 `nums[pivot]`。

但不能随便找一个更大的数，否则会变大太多。

正确做法是：

```text
在右边后缀里，找一个刚刚比 nums[pivot] 大的数
```

又因为右边后缀是降序，所以从右往左找第一个满足：

```text
nums[successor] > nums[pivot]
```

的数，就一定是“刚刚比它大”的那个最合适选择。

### 第五步：交换以后，为什么还要反转后缀

交换完成后，前面已经变大了。

但我们还要保证：

```text
在已经变大的前提下，后缀尽量小
```

这样整个排列才会是“下一个”，而不是“后面很远的某个更大排列”。

而我们知道交换前后，后缀整体仍然是一个降序结构。

降序后缀如果想变成最小字典序，只要：

```text
直接反转成升序
```

就行了。

所以最后一步是反转 `pivot + 1` 到末尾这一段。

### 第六步：如果根本找不到 `pivot`

如果从右往左一直找，都找不到满足：

```text
nums[i] < nums[i + 1]
```

的位置，那说明整个数组本来就是降序。

例如：

```text
3 2 1
```

这已经是最大排列了。

所以下一个排列只能回到最小排列，也就是：

```text
1 2 3
```

而整个数组本来就是降序，所以直接整体反转即可。

### 手推一个例子

看这个例子：

```text
1 2 7 4 3 1
```

#### 先找 `pivot`

从右往左看：

- `3 > 1`
- `4 > 3`
- `7 > 4`
- `2 < 7` ← 找到了

所以：

```text
pivot = 1，nums[pivot] = 2
```

#### 再找 `successor`

在右边后缀里，从右往左找第一个大于 `2` 的数。

后缀是：

```text
7 4 3 1
```

从右往左找，先遇到 `3`，它大于 `2`，所以选它。

#### 交换

交换 `2` 和 `3`：

```text
1 3 7 4 2 1
```

#### 反转后缀

把 `7 4 2 1` 反转成升序：

```text
1 3 1 2 4 7
```

这就是答案。

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，找到转折点后交换并反转后缀。**

### 为什么它最适合面试

1. 完全满足题目要求的 `O(1)` 空间
2. 推导链非常完整：找转折点 → 找刚大一点的数 → 交换 → 反转后缀
3. 每一步都有明确目的，不是纯模板硬背
4. 代码短，但背后逻辑很强，适合展示思考过程

### 方法一为什么不是主推

方法一更像是：

```text
从定义直接出发的理解法
```

它适合帮助你理解题意，但完全不适合作为正式答案。

## 最适合面试的方法：关键细节

### 1. 为什么一定从右往左找 `pivot`

因为我们要的是：

```text
整体变大，但尽量只大一点点
```

越靠右的位置，对整体影响越小。

所以一定要优先在最右边找可调整的位置。

### 2. 为什么要找“从右往左第一个大于 `nums[pivot]` 的数”

因为右边后缀是降序。

所以从右往左遇到的第一个更大元素，恰好就是：

```text
后缀里刚刚比它大的那个数
```

这一步保证“增幅最小”。

### 3. 为什么最后是“反转后缀”，不是“排序后缀”

因为后缀本来就是降序。

降序数组想变成升序数组，直接反转就够了。

这也是为什么整个算法能做到 `O(n)`，而不是 `O(n log n)`。

### 4. 最容易写错的地方

#### 第一，`pivot` 没找到时要处理整段反转

这是 `3,2,1` 这种情况的关键。

#### 第二，`successor` 要从右往左找

这样才能保证找到的是“刚刚更大”的那个，而不是随便一个更大的数。

#### 第三，交换后反转的是 `pivot + 1` 到末尾

不是从 `pivot` 开始反转。

## 最后总结

这题最重要的主线是：

1. 目标不是找任意更大排列，而是找“刚好更大一点”的那个
2. 要想增幅最小，就尽量在靠右位置修改
3. 先找转折点，再找右边刚比它大的数
4. 交换后把后缀变成最小，也就是反转成升序

如果你能把“为什么找 `pivot`、为什么找 `successor`、为什么最后反转后缀”这三件事讲清楚，这题就算真正掌握了。
