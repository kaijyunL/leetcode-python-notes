# LeetCode 437 - 路径总和 III（Path Sum III）

## 题目

给定一棵二叉树和整数 `targetSum`，统计路径和等于 `targetSum` 的路径数量。

路径可以从任意节点开始、在任意节点结束，但只能从父节点向子节点向下走，不要求经过根节点，也不要求到达叶子节点。

例如：

```text
       10
      /  \
     5   -3
    / \    \
   3   2    11
  / \   \
 3  -2   1
```

当 `targetSum = 8` 时，符合条件的路径有三条：

```text
5 -> 3
5 -> 2 -> 1
-3 -> 11
```

答案是 `3`。

## 先说结论

从直观到优化，掌握两种方法即可：

1. 从每个节点出发，向下统计路径：直观，最坏 `O(n²)`。
2. 前缀和 + 哈希表：每个节点只处理一次，`O(n)`，**最适合面试**。

## 这题本质是什么

路径可以从树中任意节点开始，因此只从根节点向下找一次不够。一个直接办法是让每个节点都当作路径起点；优化时则利用前缀和，一次 DFS 就统计出所有以当前节点结尾的路径。

## 最容易错的地方

### 1. 路径不必从根开始，也不必到叶子结束

例如 `5 -> 3` 是合法路径，即使它没有从根节点 `10` 开始；经过某个中间节点时，只要路径和符合目标就可以计数。

### 2. 不能因为当前和超过目标就停止

节点值可以是负数。当前路径和超过 `targetSum` 后，下面的负数节点仍可能让路径和回到目标，因此不能按和的大小剪枝。

### 3. 前缀和计数要在左右子树间回退

哈希表只应保存“从根到当前节点这条路径上”的前缀和。离开当前节点后，要撤销它加入的计数，避免把左子树的前缀和错误地拿到右子树组合路径。

## 解法一：从每个节点向下统计

对应文件：[solution_1_bruteforce.py](solution_1_bruteforce.py)

### 思路

分成两件事：

1. 对每个节点，以它作为路径起点，向下遍历并统计路径和等于 `targetSum` 的数量。
2. 再递归处理它的左右孩子，让每个节点都当一次起点。

从固定起点向下走时，沿路径累加节点值。每走到一个节点，如果当前和等于目标，就找到一条路径；但仍要继续向下，因为后面可能还有另一条符合条件的路径。

### 为什么它慢

同一批节点可能会被不同的起点重复遍历。最坏情况下树退化成链，每个节点都从自己向下扫描剩余节点，总时间为 `O(n²)`。

### 复杂度

- 时间复杂度：`O(nh)`，`h` 是树高；最坏为 `O(n²)`。
- 空间复杂度：`O(h)`，来自递归调用栈。

## 解法二：前缀和 + 哈希表

对应文件：[solution_2_prefix_sum.py](solution_2_prefix_sum.py)

### 这是最适合面试的方法

定义从根节点到当前节点的路径和为 `current_sum`。若某个更早位置的前缀和是 `current_sum - targetSum`，那么这两个前缀之间的节点和就是 `targetSum`，形成一条以当前节点结尾的路径。

所以遍历到当前节点时，只需要查询：

```python
prefix_count[current_sum - targetSum]
```

哈希表记录当前递归路径上，每种前缀和出现了多少次。初始放入 `{0: 1}`，表示在根节点之前有一个和为 `0` 的前缀。这样从根节点开始的路径也能统一计数。

### 用例子看前缀和

仍使用 `targetSum = 8` 的例子。

路径 `10 -> 5 -> 3` 上，到值为 `3` 的节点时：

```text
current_sum = 10 + 5 + 3 = 18
需要的之前前缀和 = 18 - 8 = 10
```

前缀和 `10` 已在哈希表中，所以存在一条和为 `8` 的路径：`5 -> 3`。

同理：

```text
到值为1的节点：current_sum = 18，需要之前前缀和 10 -> 路径 5 -> 2 -> 1
到值为11的节点：current_sum = 18，需要之前前缀和 10 -> 路径 -3 -> 11
```

因此共找到三条。

### 为什么要在回溯时减少计数

进入节点时，先查询当前和，再把当前和加入哈希表，然后递归左右子树。两个子树处理完后，要把当前和的计数减回去。

例如 DFS 从值为 `5` 的节点离开左子树后，再进入右子树时，哈希表应该只包含根到值为 `5` 的节点这条路径上的前缀和，不能残留左子树的前缀和。计数减回去正是为了让哈希表始终只表示当前根路径。

顺序可以记为：

```text
查询需要的旧前缀和 -> 记录当前前缀和 -> 搜索左右子树 -> 撤销当前前缀和
```

### 复杂度

- 时间复杂度：`O(n)`，每个节点访问一次，哈希表操作平均 `O(1)`。
- 空间复杂度：`O(h)`，递归栈和当前路径上的前缀和表最多保存树高数量的状态。

### 面试时怎么讲

“我用 DFS 维护根到当前节点的前缀和。当前和减去目标值，就是所需的之前前缀和；哈希表里这个值出现几次，就有几条以当前节点结尾的目标路径。进入左右子树前记录当前和，返回时撤销，保证哈希表只对应当前根路径。”
