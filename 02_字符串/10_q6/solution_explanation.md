# LeetCode 6. Z 字形变换（Zigzag Conversion）解析

## 题目描述

给你一个字符串 `s` 和一个整数 `numRows`。

请你把字符串按照题目要求排成 Z 字形，然后再按行读取，返回得到的新字符串。

例如：

```text
s = "PAYPALISHIRING", numRows = 3
```

排列后大致是：

```text
P   A   H   N
A P L S I I G
Y   I   R
```

按行读出来就是：

```text
"PAHNAPLSIIGYIR"
```

---

## 先理解题意

### 1. 这题不是排序，而是“按轨迹放字符”

很多人第一次看这题，会把注意力放在“最后怎么按行拼”。

但真正的核心其实更早：

```text
每个字符在写入时，到底落在哪一行
```

字符串里的字符并没有被打乱顺序。

它们只是按一种固定轨迹依次落到不同的行里：

- 先一直往下走
- 走到最底行后，再沿着斜方向往上走
- 走到最顶行后，再重新往下走

所以这题本质上是在模拟一个“上下折返”的过程。

### 2. 真正重要的是“当前在哪一行”

如果你把每一行都看成一个容器，那么题目就变成了：

```text
遍历字符串，把当前字符放进当前行，然后更新下一步应该去的行号
```

也就是说，最关键的信息不是列坐标，而是：

- 当前字符属于哪一行
- 现在方向是向下还是向上

只要这两个量维护对了，最后把每一行拼起来就是答案。

### 3. 最自然的三条思路

看到这题，一般最自然会想到三种写法：

1. **二维矩阵模拟**：把整个 Z 字形真的“画出来”
2. **按行模拟**：只维护每一行收到了哪些字符
3. **周期规律**：直接根据下标周期，按行提取字符

这三种方法正好对应：

```text
先完全理解题意，再写最适合面试的版本，最后补上更进阶的规律法
```

## 方法一：二维矩阵模拟

### 思路

这是最直观的做法。

既然题目让我们把字符串摆成 Z 字形，那我们就真的准备一个二维表格，把字符一个一个填进去。

过程大致是：

1. 先根据周期长度算出需要多少列
2. 创建一个 `numRows x cols` 的矩阵
3. 用 `(row, col)` 记录当前字符应该填到哪里
4. 先向下填，触底后再沿右上方向走
5. 最后按行把非空字符依次读出来

### 为什么可行

因为它完全复刻了题目的摆放过程。

你可以把它理解成：

```text
先把图形搭出来，再从上到下、从左到右读取
```

这种做法几乎不需要额外抽象，所以很好理解。

### 手推一个核心规律

如果 `numRows = 4`，那么一个完整周期是：

```text
向下 4 个字符 + 斜着向上 2 个字符
```

所以周期长度就是：

```text
2 * numRows - 2
```

也就是：

```text
2 * 4 - 2 = 6
```

每遇到一个新字符，只要根据当前在周期中的位置判断：

- 前半段继续往下
- 后半段斜着往上

就能知道下一个字符该去哪里。

### 复杂度

- 时间复杂度：`O(numRows * n)`
- 空间复杂度：`O(numRows * n)`

这里的空间开销比较大，因为矩阵里会有不少空位。

### 评价

优点：

- 最直观
- 最容易帮助你真正看懂题意

缺点：

- 空间浪费明显
- 面试里通常不是最优选择

## 方法二：按行模拟（面试主推）

这是最适合面试的方法。

### 思路

我们其实并不关心每个字符具体落在第几列。

因为最后答案只要求：

```text
把每一行的字符拼起来
```

所以没有必要真的开一个矩阵。

只需要准备 `numRows` 个列表，分别代表每一行收到的字符。

然后遍历字符串：

1. 把当前字符直接拼到当前行对应的字符串后面
2. 如果到顶了，方向改成向下
3. 如果到底了，方向改成向上
4. 更新下一步要去的行号

最后把每一行连起来，就是答案。

### 为什么可行

因为题目最终只关心“每行有哪些字符，且顺序如何”。

而按行模拟正好直接维护了这件事。

它省掉了很多无意义的空列和空格，只保留真正有用的信息。

### 手推一个例子

还是看：

```text
s = "PAYPALISHIRING", numRows = 3
```

行号变化是这样：

```text
0 -> 1 -> 2 -> 1 -> 0 -> 1 -> 2 -> 1 -> ...
```

也就是说，字符会这样落行：

- `P` 放到第 `0` 行
- `A` 放到第 `1` 行
- `Y` 放到第 `2` 行
- `P` 放到第 `1` 行
- `A` 放到第 `0` 行
- ...

最后三行分别变成：

```text
row0 = "PAHN"
row1 = "APLSIIG"
row2 = "YIR"
```

拼起来就是：

```text
"PAHNAPLSIIGYIR"
```

### 为什么它最适合面试

1. 完全贴合题意，但比矩阵法更简洁
2. 只维护“当前行 + 方向”两个核心状态
3. 代码不长，逻辑稳定，现场容易写对
4. 能很好体现你已经抓住了这题的本质

### 代码

对应代码文件：

```text
02_字符串/10_q6/solution_2_row_simulation.py
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 关键细节

#### 1. 为什么 `numRows == 1` 要直接返回

因为只有一行时，根本不存在上下折返。

字符串原样就是答案。

#### 2. 为什么 `numRows >= len(s)` 也可以直接返回

因为字符数都不够走到第二轮折返。

每个字符自己占一行，按行读出来还是原字符串。

#### 3. 为什么方向只在顶端和底端变化

因为中间行一定还在沿着当前方向继续走。

真正会改变运动趋势的，只有两个边界：

- 顶行
- 底行

## 方法三：周期下标规律

### 思路

这题的摆放过程有明显周期性。

如果 `numRows = r`，那么一个完整周期长度就是：

```text
cycle_len = 2 * r - 2
```

于是我们不一定非要模拟“怎么走”。

也可以直接按最终答案的读取顺序来想：

```text
我现在正在处理第 i 行，这一行在每个周期里会出现哪些下标？
```

### 为什么可行

对于第 `row` 行、某个周期起点 `start`：

- 竖着那一列的字符下标是 `start + row`
- 如果当前既不是第一行，也不是最后一行，那么斜线上的字符下标是 `start + cycle_len - row`

这样就能直接把每一行该取的字符按顺序提出来。

### 手推一个关键点

以 `numRows = 4` 为例：

```text
cycle_len = 6
```

那么：

- 第 `0` 行只会取 `0, 6, 12, ...`
- 第 `1` 行会取 `1, 5, 7, 11, ...`
- 第 `2` 行会取 `2, 4, 8, 10, ...`
- 第 `3` 行只会取 `3, 9, 15, ...`

可以看到：

- 第一行和最后一行，每个周期只取一个字符
- 中间行，每个周期会取两个字符

这就是这题的下标规律来源。

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 评价

优点：

- 很有规律感
- 不需要显式模拟方向变化
- 适合作为进一步理解这题结构的补充

缺点：

- 面试里不如方法二自然
- 代码更依赖规律推导，第一次写容易漏边界

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，按行模拟。**

### 为什么

1. 它最贴近这题真正需要维护的信息
2. 不像矩阵法那样有额外空间浪费
3. 不像规律法那样太依赖推导
4. 代码长度和可解释性都非常合适

### 方法一的价值

方法一最大的价值，是帮助你把题意看透。

如果你一开始觉得 Z 字形轨迹有点绕，先想矩阵法会很有效。

### 方法三的价值

方法三更适合在你已经会写方法二之后，再进一步理解：

```text
为什么这题会有周期结构
```

它能帮助你从“模拟”过渡到“规律提取”。

## 最后总结

这题最重要的主线就是：

1. 字符的相对顺序没有变，变的是它们落入的不同行
2. 真正关键的是维护“当前行”和“当前方向”
3. 面试最稳的做法是按行模拟
4. 在理解透彻后，还可以进一步总结出周期下标规律

如果你能把这句复述清楚：

> **这题本质上是让字符沿着上下折返的轨迹落到不同的行里，最后再按行拼接。**

那这题就算真的掌握了。
