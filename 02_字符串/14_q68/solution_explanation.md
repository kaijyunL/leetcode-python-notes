# LeetCode 68. 文本左右对齐（Text Justification）

## 题目描述

给你一个单词数组 `words` 和一个整数 `maxWidth`，请你把这些单词排版成若干行，使得：

- 每一行恰好有 `maxWidth` 个字符
- 尽可能多地往当前行里放单词（贪心）
- 普通行要做**左右对齐**
- 如果空格不能平均分配，**左边的空格要比右边多**
- 最后一行必须**左对齐**

返回最终排版后的字符串数组。

---

## 先理解这题到底在做什么

这题表面上是“字符串处理”，其实本质是：

```text
先贪心分行，再按规则分配空格
```

也就是说，每一行都要做两件事：

1. **确定这一行放哪些单词**
2. **确定这一行的空格怎么补**

真正容易写乱的地方，不是“怎么拼字符串”，而是：

- 什么时候该停在这一行
- 普通行和最后一行的规则不同
- 只有一个单词的一行，也要按左对齐处理
- 多出来的空格必须优先分到左边

所以这题本质上是一道**贪心 + 模拟**题。

---

## 先抓住三个核心场景

无论怎么写，最后都绕不开这三种行：

### 1. 最后一行

规则最简单：

- 单词之间只放一个空格
- 整体左对齐
- 最后在末尾补空格到 `maxWidth`

比如：

```text
["shall", "be"]
```

如果 `maxWidth = 16`，那就是：

```text
"shall be        "
```

### 2. 当前行只有一个单词

这时虽然它不是最后一行，也没办法做“左右均匀分配”，因为根本没有间隙。

所以处理方式仍然是：

- 单词放左边
- 右边补空格

例如：

```text
"acknowledgment  "
```

### 3. 普通多单词行

这是本题真正的重点。

假设当前行有：

```text
word1 word2 word3 word4
```

如果这些单词总长度是 `letters`，这一行一共有 `gaps = 单词数 - 1` 个间隙，那么：

- 总空格数：`maxWidth - letters`
- 每个间隙至少分到：`base = total_spaces // gaps`
- 还剩多少个多出来的空格：`extra = total_spaces % gaps`

然后从左到右：

- 前 `extra` 个间隙分 `base + 1` 个空格
- 后面的间隙分 `base` 个空格

这就满足了题目的要求：

```text
左边比右边多
```

## 方法一：贪心模拟（面试主学）

这是这道题**最建议优先记住**的写法，也是最贴着题意的写法。

### 思路

用两个指针确定当前行的单词范围：

- `i`：当前行起点
- `j`：不断尝试把更多单词塞进当前行

判断能不能继续塞的条件很关键：

```text
当前单词总长度 + 新单词长度 + 最少间隔空格数 <= maxWidth
```

其中“最少间隔空格数”就是当前已经选入的单词之间至少要留的空格数量。

确定一行后，再根据是不是最后一行、是不是单单词行，分三种情况构造答案。

### 为什么可行

如果你面试时只准备记一种写法，这题就记这一种。

因为题目已经明确要求：

```text
每一行尽可能放更多单词
```

这就说明分行策略本身就是标准的贪心。

而分好行之后，空格分配又是确定性的：

- 最后一行：左对齐
- 一个单词：左对齐
- 多个单词：平均分，左边多拿余数

所以整个过程天然就是“先贪心、再模拟”。

### 代码

对应文件：

```text
02_字符串/14_q68/solution_1_greedy_simulation.py
```

### 复杂度

- 时间复杂度：`O(n)`，其中 `n` 是所有单词字符总数
- 空间复杂度：`O(n)`，用于保存最终答案

### 关键细节

#### 1. 为什么分行条件里要加 `(j - i)`

因为如果当前行已经放了 `j - i` 个单词，那么它们之间至少要有：

```text
j - i
```

个空格，才能把新单词接进来。

也就是：

```text
已有单词总长度 + 新单词长度 + 最少空格数
```

一起判断是否超宽。

#### 2. 为什么不是把余数空格平均往后补

题目明确规定：

```text
左侧空格数要多于右侧
```

所以多出来的空格必须优先给左边的间隙。

#### 3. 为什么单单词行不能走“平均分配空格”逻辑

因为这时间隙数量是 0。

如果你还去做：

```text
total_spaces // gaps
```

就会直接除零。

所以单单词行必须单独处理。

## 方法二：模块化模拟（补充理解）

如果说方法一是“直接写出来”，那方法二更像是把这题拆成几个清晰的小模块。

它的价值主要在于：**帮助你把规则拆开理解**，而不是作为这题面试时必须主记的版本。

### 思路

把整个过程拆成三步：

1. 找出当前行最右能放到哪个单词
2. 判断这一行属于哪种类型
3. 调用对应的格式化函数生成结果

这样能把“分行”和“补空格”彻底分开。

### 推荐的拆分方式

可以拆成下面几个函数：

- `_find_right(...)`：找到当前行的右边界，并计算该行单词总长度
- `_left_justify(...)`：处理最后一行或单单词行
- `_middle_justify(...)`：处理普通多单词行

这样主函数里只保留主流程，代码会很顺。

### 为什么它值得保留

虽然这不是我建议你主记的版本，但它仍然有价值。

因为它把题目规则拆得非常明确：

```text
找边界 -> 分情况 -> 构造行
```

如果你之后回头复习，或者想把这题讲给别人听，这种模块化写法会更清楚。

但如果你当前目标是：

```text
面试时只记一种、并且能稳定写出来
```

那还是优先记方法一更合适。

### 代码

对应文件：

```text
02_字符串/14_q68/solution_2_modular_simulation.py
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

虽然写法更模块化，但本质流程没有变化，所以复杂度和方法一一致。

## 手推一个例子

看经典样例：

```text
words = ["This", "is", "an", "example", "of", "text", "justification."]
maxWidth = 16
```

### 第 1 行

先贪心往里放：

- `This` 长度 4
- `This is` 最小长度 7
- `This is an` 最小长度 10
- 再加 `example` 就会超出 16

所以第一行是：

```text
["This", "is", "an"]
```

字母总长度：

```text
4 + 2 + 2 = 8
```

需要补的空格总数：

```text
16 - 8 = 8
```

间隙有 2 个，所以：

- 每个间隙先放 4 个空格
- 没有余数

得到：

```text
"This    is    an"
```

### 第 2 行

放：

```text
["example", "of", "text"]
```

字母总长度：

```text
7 + 2 + 4 = 13
```

需要空格：

```text
16 - 13 = 3
```

间隙有 2 个，所以：

- 平均每个至少 1 个空格
- 还多 1 个空格，优先给左边

结果：

```text
"example  of text"
```

### 第 3 行

最后一行：

```text
["justification."]
```

直接左对齐：

```text
"justification.  "
```

## 这题最容易写错的地方

### 1. 分行条件少算了最小空格

很多人只判断：

```text
当前字母数 + 新单词长度 <= maxWidth
```

这是不够的。

因为单词之间最少还要有空格。

### 2. 最后一行误用了普通行逻辑

最后一行必须：

- 单词间只有一个空格
- 末尾补齐

不能再做“平均分配空格”。

### 3. 余数空格分配方向写反

题目要求左边多，不是右边多。

所以一定是：

```text
前 extra 个间隙多拿 1 个空格
```

### 4. 忘记处理“只有一个单词的普通行”

这一类不是最后一行，但也必须左对齐。

否则要么除零，要么格式不对。

## 两种写法怎么选

### 方法一：贪心模拟

适合：

- 面试时只准备记一种写法
- 第一次做这题
- 想直接顺着题意写
- 先保证把题做出来

优点：

- 思路直接
- 代码更短
- 更贴近直觉
- 现场更容易稳定写对

### 方法二：模块化模拟

适合：

- 已经会方法一之后，再补充理解
- 想把逻辑拆得更清楚
- 后续复习时快速回忆结构

优点：

- 主流程干净
- 规则分层明确
- 更利于讲解和排错

如果是面试，并且你**只记一种写法**，我更推荐**方法一**。

---

## 总结

这题的核心就一句话：

```text
先贪心决定一行放哪些单词，再按行类型分配空格
```

真正需要记住的不是某个技巧，而是这三个规则：

1. **每行尽可能多放单词**
2. **普通行平均分配空格，左边优先拿余数**
3. **最后一行和单单词行都左对齐**

只要你把这三条写进代码结构里，这题就会很稳。

如果你现在只打算记一个版本，就直接记**方法一**。
