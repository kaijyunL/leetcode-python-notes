# LeetCode 151. 反转字符串中的单词（Reverse Words in a String）解析

## 题目描述

给你一个字符串 `s`，请你把其中单词的顺序反转后返回。

这里的“单词”指的是：

```text
由非空格字符组成的一段连续字符串
```

同时，返回结果还要满足：

- 单词之间只保留一个空格
- 不能有前导空格
- 不能有尾随空格

例如：

```text
"the sky is blue" -> "blue is sky the"
"  hello world  " -> "world hello"
"a good   example" -> "example good a"
```

---

## 先理解题意

### 1. 这题不是把整个字符串字符反过来

很多人一看到“反转字符串”，第一反应是把所有字符整体倒过来。

但这题不是要你得到：

```text
"eulb si yks eht"
```

而是要你得到：

```text
"blue is sky the"
```

也就是说，这题真正要反转的是：

```text
单词的顺序
```

而不是每个单词内部的字符顺序。

### 2. 这题还有一个隐藏重点：空格要被“规范化”

题目并不是简单让你换一下顺序。

它还要求：

- 前面的多余空格要去掉
- 后面的多余空格要去掉
- 中间多个连续空格要压成一个

所以这题其实包含两个动作：

1. **正确提取单词**
2. **按相反顺序重新拼接，并统一空格格式**

### 3. 最自然的三条思路

看到这题，一般最自然会想到三种方法：

1. **先切词，再反转，再拼接**
2. **手动扫描字符串，把单词按相反顺序收集起来**
3. **清理空格后，整体翻转，再逐词翻转**

这三种方法正好对应：

```text
先用最直观的方法理解，再用更像面试的手动处理方式实现，最后补上底层翻转思路
```

## 方法一：`split()` 后翻转

### 思路

最直接的做法是：

1. 用 `split()` 把字符串拆成单词列表
2. 把单词列表反转
3. 用单个空格把它们重新连接起来

### 为什么可行

因为 Python 的：

```python
s.split()
```

在不传参数时会自动：

- 忽略前导空格
- 忽略尾随空格
- 把中间多个连续空格视为一个分隔符

所以它已经帮我们顺便完成了空格规范化。

比如：

```text
"  hello   world  ".split()
```

得到的是：

```text
["hello", "world"]
```

这时再把列表反过来，然后用一个空格 `join`，就能直接得到目标答案。

### 代码

对应代码文件：

```text
02_字符串/08_q151/solution_1_split_reverse.py
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

其中 `n` 是字符串长度。

### 评价

优点：

- 最短
- 最直观
- 最容易一眼写对

缺点：

- 过度依赖 `split()` 的现成能力
- 如果面试官想考你手动处理空格和单词，就不够“展开”

## 方法二：双端队列扫描（面试主推）

这是最适合面试的方法。

### 第一步：先去掉首尾没意义的空格

因为首尾空格肯定不会成为单词的一部分。

所以先用两个指针：

- `left` 从左边往右走
- `right` 从右边往左走

把首尾连续空格跳过去。

这样后面的扫描范围就更干净了。

### 第二步：从左到右读单词

然后从左到右扫描字符串：

- 如果当前字符不是空格，就把它加入当前单词 `word`
- 如果当前字符是空格，并且 `word` 非空，说明一个完整单词读完了

这时把这个单词放到双端队列的最前面：

```text
dq.appendleft(word)
```

这样后面读到的单词自然会排到前面，最终顺序就反过来了。

### 第三步：为什么连续空格不会出问题

因为只有在：

```text
遇到空格，并且当前 word 非空
```

时，我们才会把单词压入队列。

所以多个连续空格只是不断被跳过，不会生成空单词。

这就自然做到了：

- 去掉多余空格
- 只保留真实单词

### 手推一个例子

看：

```text
s = "a good   example"
```

扫描过程大致是：

- 读到 `a`，得到单词 `a`，放到队列头部
- 读到 `good`，放到队列头部
- 中间有多个空格，直接跳过
- 读到 `example`，放到队列头部

最后队列里从左到右就是：

```text
["example", "good", "a"]
```

再用一个空格连接起来，就得到：

```text
"example good a"
```

### 为什么它最适合面试

1. 没有完全依赖 `split()`
2. 单词提取和空格处理逻辑都能清楚展示出来
3. 代码长度适中，不会像“三步翻转”那样太重
4. 既能体现过程理解，也比较容易现场写对

## 方法三：三步翻转

### 思路

这是这题非常经典的一种底层思路。

步骤是：

1. **清理空格**：去掉首尾空格，并把中间多余空格压成一个
2. **整体翻转**：把整个字符序列反转
3. **逐词翻转**：再把每个单词各自翻回来

### 为什么这样能成立

假设清理空格后得到：

```text
"the sky is blue"
```

#### 第一步：整体翻转

变成：

```text
"eulb si yks eht"
```

这时：

- 单词顺序已经反过来了
- 但每个单词内部的字符顺序也乱了

#### 第二步：逐词翻转

把 `eulb` 翻回 `blue`，把 `si` 翻回 `is`，依次处理。

就得到：

```text
"blue is sky the"
```

所以这套方法的关键思想是：

> **先用整体翻转改变单词顺序，再用逐词翻转修正单词内部字符顺序。**

### 为什么它在很多语言里很经典

在支持可变字符数组的语言里，这个思路很适合原地处理。

但在 Python 里，字符串本身不可变，所以通常还是要先转成列表来操作。

因此它在 Python 中更多是：

```text
用于理解底层思路和通用技巧
```

而不是最省事的写法。

对应代码文件：


### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 评价

优点：

- 很经典
- 能帮助理解这题更底层的处理方式
- 在支持原地修改字符数组的语言里很有价值

缺点：

- Python 里实现明显更长
- 现场手写成本高于方法二

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，双端队列扫描。**

### 为什么它最适合面试

1. 不完全依赖内置 `split()`
2. 能把“提取单词”和“处理多余空格”这两个关键点讲清楚
3. 比三步翻转更容易写、也更容易解释
4. 代码自然，失误率较低

### 方法一为什么更适合第一层理解

方法一最大的价值是让你先快速建立正确感觉：

```text
先把单词提出来，再反转顺序拼回去
```

它非常适合入门。

### 方法三为什么更像进阶补充

方法三的思想很经典，但在 Python 里不算最舒服的写法。

所以它更适合作为：

```text
进一步理解“整体翻转 + 局部翻转”套路
```

的补充视角。

---

## 最适合面试的方法：关键细节

### 1. 为什么先去首尾空格

因为这些空格不属于任何单词。

提前去掉后，后面扫描时边界更清楚，也避免把空串误当成单词。

### 2. 为什么只有 `word` 非空时才入队

因为这样才能避免连续空格产生空单词。

这是这题去掉“多余空格”的核心细节之一。

### 3. 为什么最后别忘了补一次入队

因为最后一个单词后面通常没有空格。

如果只在“遇到空格”时才入队，就会漏掉最后一个单词。

## 最后总结

这题最重要的主线就是：

1. 不是把整个字符串字符倒过来，而是把单词顺序反过来
2. 多余空格必须被清理掉，结果中单词之间只能保留一个空格
3. 可以先用 `split()` 建立理解，再用手动扫描方式展示真正的处理过程
4. 进一步还能从“整体翻转 + 逐词翻转”的角度理解底层思路

如果你能把这句复述清楚：

> **这题本质上是先正确提取单词、去掉多余空格，再把单词按相反顺序重新拼接。**

那这题就算真的掌握了。
