# LeetCode 242. 有效的字母异位词（Valid Anagram）解析

## 题目描述

给定两个字符串 `s` 和 `t`，判断 `t` 是否是 `s` 的字母异位词。

如果是，返回：

```text
True
```

否则返回：

```text
False
```

例如：

```text
s = "anagram", t = "nagaram" -> True
s = "rat", t = "car" -> False
```

---

## 先理解题意

### 1. 什么叫“字母异位词”

字母异位词的意思不是“长得像”，而是：

```text
两个字符串里，每种字符出现的次数完全一样，只是顺序可以不同
```

比如：

```text
"anagram"
"nagaram"
```

虽然顺序不同，但里面的字符和每个字符出现次数都一致，所以它们是字母异位词。

而：

```text
"rat"
"car"
```

里面字符种类就已经不一样，所以一定不是。

### 2. 这题的核心不是“位置”，而是“频次”

很多字符串题都在比较位置关系、相邻关系、子串关系。

但这题不是。

这题真正关心的是：

```text
每个字符出现了几次
```

也就是说：

- 字符顺序不重要
- 只要频次一样就行
- 只要某个字符缺了、少了、多了，都不行

这也是这题最关键的转折：

> **一旦意识到顺序不重要，最自然就会想到“排序”或者“计数”。**

### 3. 最自然的三条思路

看到这题，一般最自然会想到三条路：

1. **排序后比较**：如果排序后完全一样，那原来就只是顺序不同
2. **哈希计数**：统计每个字符出现次数，再逐个抵消
3. **定长数组计数**：如果字符范围固定为 26 个小写字母，就可以把哈希进一步简化成数组

这三种方法正好对应从直观到高效的递进过程。

---

## 方法一：排序后比较

### 思路

最直接的做法是：

1. 如果两个字符串长度不同，直接返回 `False`
2. 分别对 `s` 和 `t` 排序
3. 如果排序结果相同，说明它们包含的字符及次数完全一致

### 为什么可行

因为排序会把相同字符排到一起。

如果两个字符串本来只是字符顺序不同，那么排序以后一定会得到同一个结果。

比如：

```text
s = "anagram" -> 排序后是 aaagmnr
t = "nagaram" -> 排序后也是 aaagmnr
```

结果一样，所以它们互为字母异位词。

### 手推一个例子

看：

```text
s = "rat"
t = "tar"
```

排序后：

```text
"art"
"art"
```

相同，所以返回 `True`。

再看：

```text
s = "rat"
t = "car"
```

排序后：

```text
"art"
"acr"
```

不相同，所以返回 `False`。

对应代码文件：

```text
02_字符串/03_q242/solution_1_sorting.py
```

### 复杂度

- 时间复杂度：`O(n log n)`
- 空间复杂度：取决于排序实现，通常记作 `O(n)`

其中 `n` 是字符串长度。

### 评价

优点：

- 最直观
- 最容易想到
- 很适合作为第一层理解

缺点：

- 排序不是这题真正最需要的动作
- 时间复杂度不如线性计数法

## 方法二：哈希计数（面试主推）

这是最适合面试的方法。

### 第一步：先比较长度

如果 `s` 和 `t` 长度都不一样，那它们不可能由同一批字符组成。

所以第一步就可以直接做：

```text
长度不同，立刻返回 False
```

这一步很重要，因为它能提前排掉很多不可能情况。

### 第二步：先统计 `s` 里每个字符出现次数

用一个哈希表 `counts`。

遍历 `s` 时：

- 遇到一个字符，就把它的计数加一

比如：

```text
s = "anagram"
```

统计完后大致会得到：

```text
{
  'a': 3,
  'n': 1,
  'g': 1,
  'r': 1,
  'm': 1
}
```

这个哈希表表示的就是：

> **`s` 还“剩下”多少个对应字符可以匹配。**

### 第三步：再用 `t` 去抵消这些计数

然后遍历 `t`。

每看到一个字符，就把对应计数减一。

如果出现下面任意一种情况，就说明不匹配：

1. 这个字符根本不在哈希表里
2. 减完以后计数变成负数

这两个条件其实都在表达同一件事：

```text
t 里这个字符出现得比 s 更多，或者 s 根本没有这个字符
```

那就一定不是字母异位词。

### 为什么这比排序更贴题意

因为这题真正要比的是：

```text
字符频次是否一致
```

哈希计数就是直接在做这件事。

它没有去“重排字符串”，也没有做额外的顺序整理，而是直接记录每个字符出现了几次。

所以它更接近题目的本质。

### 手推一个例子

看：

```text
s = "anagram"
t = "nagaram"
```

#### 先统计 `s`

得到：

```text
{
  'a': 3,
  'n': 1,
  'g': 1,
  'r': 1,
  'm': 1
}
```

#### 再遍历 `t`

依次抵消：

- 遇到 `n`，`n: 1 -> 0`
- 遇到 `a`，`a: 3 -> 2`
- 遇到 `g`，`g: 1 -> 0`
- 遇到 `a`，`a: 2 -> 1`
- 遇到 `r`，`r: 1 -> 0`
- 遇到 `a`，`a: 1 -> 0`
- 遇到 `m`，`m: 1 -> 0`

全部抵消完成，没有出现负数，也没有缺字符，所以返回 `True`。

### 再看一个失败例子

如果：

```text
s = "aacc"
t = "ccac"
```

先统计 `s`：

```text
{
  'a': 2,
  'c': 2
}
```

遍历 `t`：

- `c`：`2 -> 1`
- `c`：`1 -> 0`
- `a`：`2 -> 1`
- `c`：`0 -> -1`

这里出现负数，说明 `t` 里的 `c` 比 `s` 更多。

所以直接返回 `False`。

对应代码文件：

```text

```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(k)`

其中：

- `n` 是字符串长度
- `k` 是不同字符的种类数

### 为什么它最适合面试

1. 逻辑最贴题意：直接比较字符频次
2. 时间复杂度是线性的
3. 不依赖字符集一定是 26 个小写字母
4. 代码自然、稳定，也很好解释

## 方法三：定长 26 数组计数

### 思路

如果题目已经告诉你：

```text
字符串只包含小写英文字母
```

那其实没必要用哈希表。

因为一共只有 26 种可能字符，我们可以直接开一个长度为 `26` 的数组。

做法是：

1. 如果长度不同，直接返回 `False`
2. 遍历 `s`，把对应位置计数加一
3. 遍历 `t`，把对应位置计数减一
4. 最后看数组是不是全为 `0`

### 为什么可行

数组下标可以直接表示字符。

比如：

- `a -> 0`
- `b -> 1`
- `c -> 2`
- ...
- `z -> 25`

所以我们可以用：

```text
ord(ch) - ord('a')
```

把字符映射到数组位置。

这样本质上仍然是在做“频次统计”，只是把哈希表换成了更固定、更轻量的数组。

### 代码

对应代码文件：

```text
02_字符串/03_q242/solution_3_array_count.py
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

这里空间复杂度是 `O(1)`，因为数组长度固定为 26。

### 评价

优点：

- 比哈希表更省常数开销
- 写法也不长
- 在字符集固定时很高效

缺点：

- 依赖“小写英文字母”这个前提
- 泛化能力不如哈希计数
- 面试里如果题目没强调字符范围，直接写数组法会显得假设太强

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，哈希计数。**

### 为什么它最适合面试

1. 它最贴题目本质：比较字符频次
2. 时间复杂度已经是最优级别 `O(n)`
3. 不依赖字符集必须固定
4. 代码短、解释顺、边界也很清楚

### 方法一为什么更适合第一层理解

方法一非常直观。

它先帮你建立这个认识：

```text
顺序不重要时，可以先把顺序“抹平”再比较
```

所以它很适合作为入门思路。

### 方法三为什么更像“特定条件下的优化版”

方法三本质上没有改变核心思想，还是在统计频次。

它只是利用了：

```text
字符范围固定且很小
```

这个前提，把哈希表进一步换成数组。

所以更适合在你已经理解方法二后，当作一个优化版本去补充。

---

## 最适合面试的方法：关键细节

### 1. 为什么长度不同就能直接返回 `False`

因为字母异位词要求两个字符串里的字符总数都一样。

只要长度不同，就不可能完全由同一批字符重排得到。

### 2. 为什么出现负数就能立刻返回 `False`

因为负数表示：

```text
t 中某个字符的出现次数已经超过 s
```

那它们肯定不匹配，没必要继续往后看。

### 3. 为什么哈希表里的值可以理解成“剩余可匹配次数”

因为我们先对 `s` 做加法，再对 `t` 做减法。

所以每个键对应的值，本质上表示：

```text
s 里这个字符还剩多少个没有被 t 抵消掉
```

这个理解在面试里很好讲，也能帮你避免写乱。

## 最后总结

这题最重要的主线就是：

1. 字母异位词不看顺序，只看字符种类和出现次数
2. 排序法能帮你快速理解“顺序不重要”
3. 真正更贴题意的做法，是直接统计每个字符出现次数
4. 如果字符集固定很小，还可以把哈希表再优化成定长数组

如果你能把这句复述清楚：

> **这题的关键不是比较位置，而是比较频次；先统计，再抵消，就能判断是不是字母异位词。**

那这题就算真的掌握了。
