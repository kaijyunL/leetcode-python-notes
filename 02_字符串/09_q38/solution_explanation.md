# LeetCode 38. 外观数列（Count and Say）解析

## 题目描述

外观数列是一个从 `1` 开始的字符串序列。

后面的每一项，都是对前一项的“描述”。

前几项如下：

```text
1
11
21
1211
111221
```

它们的含义分别是：

- 第 `1` 项是 `"1"`
- 第 `2` 项描述第 `1` 项：一个 `1`，所以是 `"11"`
- 第 `3` 项描述第 `2` 项：两个 `1`，所以是 `"21"`
- 第 `4` 项描述第 `3` 项：一个 `2`，一个 `1`，所以是 `"1211"`
- 第 `5` 项描述第 `4` 项：一个 `1`，一个 `2`，两个 `1`，所以是 `"111221"`

给你一个整数 `n`，请你返回外观数列的第 `n` 项。

---

## 先理解题意

### 1. 这题不是做数学运算，而是做“分组描述”

很多人第一次看这题，会误以为是在做某种数字规律推导。

其实不是。

这题真正做的事情是：

```text
把前一个字符串里连续相同的字符分成一组一组，再把每组写成“个数 + 字符”
```

比如：

```text
"1211"
```

要按连续段去看，而不是按字符种类整体统计。

它会分成：

```text
"1" | "2" | "11"
```

于是描述出来就是：

- 一个 `1` -> `11`
- 一个 `2` -> `12`
- 两个 `1` -> `21`

拼起来得到：

```text
"111221"
```

### 2. 关键不是“有几个 1”，而是“连续几个 1”

这是这题最核心的点。

比如：

```text
"1211"
```

里面一共有三个 `1`。

但你不能直接说成：

```text
三个 1，一个 2
```

因为题目要求的是按**出现顺序**去描述连续段。

所以必须按连续分组处理。

也就是说，这题的核心动作其实是：

> **扫描字符串，统计当前连续相同字符出现了多少次。**

### 3. 最自然的三条思路

看到这题，一般最自然会想到三种写法：

1. **迭代模拟**：从第 `1` 项一路生成到第 `n` 项
2. **递归**：先求第 `n-1` 项，再描述生成第 `n` 项
3. **`groupby`**：利用 Python 标准库更优雅地做连续分组

这三种方法本质一样，差别主要在表达方式。

---

## 方法一：迭代模拟（面试主推）

这是最适合面试的方法。

### 思路

最直接的做法是：

1. 先把第 `1` 项设为 `"1"`
2. 然后从第 `2` 项开始，一项一项往后生成
3. 每一轮都扫描当前字符串，把连续相同字符统计出来
4. 按照“数量 + 字符”的形式拼成下一项

### 为什么可行

因为题目已经告诉你：

```text
第 n 项由第 n - 1 项描述而来
```

所以最自然的办法，就是从 `1` 开始不断往后推。

每一步都只做一件事：

```text
把当前字符串按连续段重新描述
```

### 手推一个例子

看第 `4` 项 `"1211"` 怎么生成第 `5` 项。

扫描过程：

- 第一个连续段是 `"1"`，有 `1` 个 `1` -> `11`
- 第二个连续段是 `"2"`，有 `1` 个 `2` -> `12`
- 第三个连续段是 `"11"`，有 `2` 个 `1` -> `21`

拼接起来就是：

```text
"111221"
```

### 为什么它最适合面试

1. 完全贴题意，最容易想到
2. 不依赖额外语言特性
3. 连续分组的过程可以讲得很清楚
4. 代码稳定，现场不容易写崩

### 代码

对应代码文件：

```text

```

### 复杂度

如果把生成过程中某一步字符串的最大长度记为 `L`，那么：

- 时间复杂度：通常可记作 `O(n * L)`
- 空间复杂度：`O(L)`

这里的核心理解是：每一轮都会线性扫描当前字符串一次。

## 方法二：递归

### 思路

题目本身就带有很明显的递归定义：

```text
countAndSay(n) 依赖 countAndSay(n - 1)
```

所以我们可以：

1. 先递归求出第 `n - 1` 项
2. 再对这个结果做一次“连续分组描述”
3. 得到当前第 `n` 项

### 为什么可行

因为第 `n` 项本来就是从第 `n - 1` 项推出来的。

递归写法只是把“从前往后推”的过程，换成了“先向下求前一项，再向上返回当前项”。

也就是说：

- 方法一是显式地一轮轮迭代
- 方法二是把这些轮次交给递归栈处理

### 代码

对应代码文件：

```text
02_字符串/09_q38/solution_2_recursive.py
```

### 复杂度

- 时间复杂度：通常可记作 `O(n * L)`
- 空间复杂度：除了字符串本身外，还要算递归深度，因此会比方法一更高一些

### 评价

优点：

- 非常贴合题目定义
- 能展示你对递归结构的理解

缺点：

- 本质上并没有比迭代更优
- 面试里通常不如迭代版稳

## 方法三：`itertools.groupby`

### 思路

Python 里有一个很好用的工具：

```python
itertools.groupby
```

它可以把连续相同的元素分成一组一组。

而这题最核心的动作，恰好就是：

```text
把连续相同字符分组
```

所以我们可以直接利用它，把代码写得更简洁。

### 为什么可行

比如字符串：

```text
"111221"
```

按连续相同字符分组后，可以看成：

- 一组 `1`
- 一组 `2`
- 一组 `1`

更准确地说，是：

- 三个连续的 `1`
- 两个连续的 `2`
- 一个连续的 `1`

于是就能直接生成：

```text
"312211"
```

### 代码

对应代码文件：

```text
02_字符串/09_q38/solution_3_groupby.py
```

### 复杂度

- 时间复杂度：通常可记作 `O(n * L)`
- 空间复杂度：`O(L)`

### 评价

优点：

- 写法简洁
- 很有 Python 风格
- 适合作为补充视角

缺点：

- 面试里如果一上来就写 `groupby`，可能会弱化你对底层分组过程的说明

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法一，迭代模拟。**

### 为什么它最适合面试

1. 最贴题意
2. 连续分组的过程最容易解释
3. 不依赖递归和标准库技巧
4. 代码简洁且稳定

### 方法二为什么更像定义翻译版

递归法很好理解，因为题目本身就带递归味道。

但真正写起来，它并没有比迭代更自然，也没有更优。

### 方法三为什么更适合作为加分项

`groupby` 很漂亮，但它更像“我已经理解了连续分组，所以我用 Python 工具把代码写短”。

因此更适合在你已经掌握方法一之后，当成补充写法。

---

## 最适合面试的方法：关键细节

### 1. 为什么要按连续段处理

因为题目是在“读”前一个字符串。

读的时候必须按照从左到右的连续段来描述，而不是统计整串里某个字符总共出现了几次。

### 2. 为什么要用列表收集片段，最后再 `join`

因为 Python 字符串不可变。

如果在循环里不断用 `+=` 拼接字符串，会反复创建新对象。

所以更好的写法是：

- 先把每一段描述放进列表
- 最后一次性 `"".join(parts)`

### 3. 为什么外层要从第 `2` 项开始生成

因为第 `1` 项已经固定是：

```text
"1"
```

所以从第 `2` 项开始，才真正需要根据前一项去生成当前项。

## 最后总结

这题最重要的主线就是：

1. 每一项都来自对前一项的描述
2. 描述时要按连续相同字符分组，而不是统计整串字符总数
3. 每个连续段都写成“数量 + 字符”
4. 最稳的实现方式，就是迭代地一项一项生成

如果你能把这句复述清楚：

> **这题本质上是不断对上一项做“连续分组描述”；每组写成数量加字符，再拼成下一项。**

那这题就算真的掌握了。
