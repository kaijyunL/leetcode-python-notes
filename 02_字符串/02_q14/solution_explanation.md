# LeetCode 14. 最长公共前缀（Longest Common Prefix）解析

## 题目描述

给你一个字符串数组 `strs`。

请你返回这些字符串的：

```text
最长公共前缀
```

如果不存在公共前缀，就返回空字符串 `""`。

例如：

```text
["flower", "flow", "flight"] -> "fl"
["dog", "racecar", "car"] -> ""
```

---

## 先理解题意

### 1. 什么叫“公共前缀”

前缀就是：

```text
从字符串开头开始，连续相同的一段
```

比如：

```text
"flower"
"flow"
"flight"
```

它们开头共同拥有：

```text
"f"
"fl"
```

但到第三个字符时：

- `flower` 是 `o`
- `flow` 是 `o`
- `flight` 是 `i`

这时不一样了，所以最长公共前缀就是：

```text
"fl"
```

### 2. 这题本质上是在问：大家从左往右，最早在哪一位开始不一样

这题不用关心字符串后面有多长，也不用关心中间内容。

真正重要的是：

```text
从第 0 位开始，大家能一致多久
```

所以这题的核心动作其实只有一个：

> **不断比较开头这一段，还能不能继续保留。**

### 3. 两种最自然的想法

看到这题，一般最自然会想到两条路：

1. **横着比**：先拿第一个字符串当答案，再不断和后面的字符串求公共前缀
2. **竖着比**：先比所有字符串的第 0 位，再比第 1 位，再比第 2 位

这两条路都很自然，也都能做到线性级别。

---

## 方法一：横向扫描

### 思路

最直接的做法是：

1. 先把第一个字符串当作当前公共前缀 `prefix`
2. 再拿这个 `prefix` 去和后面的每个字符串比较
3. 只要当前字符串不是以 `prefix` 开头，就不断缩短 `prefix`
4. 如果 `prefix` 被缩成空字符串，说明根本没有公共前缀

### 为什么可行

因为最长公共前缀本来就是一个“越比越短”的东西。

比如：

```text
先拿 flower 当 prefix
再和 flow 比，缩成 flow
再和 flight 比，缩成 fl
```

你不可能越比越长，只会保持不变或者继续变短。

所以让 `prefix` 一路收缩，就是很自然的做法。

### 手推一个例子

看：

```text
["flower", "flow", "flight"]
```

初始：

```text
prefix = "flower"
```

拿它和 `flow` 比：

- `flow` 不是以 `flower` 开头
- 缩成 `flowe`
- 继续缩...
- 最后得到 `flow`

再拿 `flow` 和 `flight` 比：

- `flight` 不是以 `flow` 开头
- 缩成 `flo`
- 继续缩...
- 最后得到 `fl`

答案就是：

```text
"fl"
```

对应代码文件：


### 复杂度

- 时间复杂度：`O(S)`
- 空间复杂度：`O(1)`

这里的 `S` 表示所有字符串字符总数。

### 评价

优点：

- 最容易想到
- 逻辑很顺
- 很适合第一层理解

缺点：

- 虽然复杂度不差，但写的时候要不断缩字符串
- 面试现场解释时，没有纵向扫描那么“直给”

## 方法二：纵向扫描（面试主推）

这是最适合面试的方法。

### 第一步：固定一列去看

把第一个字符串当作“参考字符串”。

然后从左到右看它的每一个位置 `i`：

- 先看所有字符串的第 `0` 位是不是一样
- 再看所有字符串的第 `1` 位是不是一样
- 再看所有字符串的第 `2` 位是不是一样

一旦某一列出现不一致，就说明公共前缀到这里为止了。

### 第二步：什么时候停止

对于某个位置 `i`，只要出现下面任意一种情况，就可以停：

1. 某个字符串长度已经不够了
2. 某个字符串在这一位的字符和第一个字符串不一样

这两个条件其实都在表示同一件事：

> **从这一位开始，大家已经不能继续共享前缀了。**

### 为什么这方法更贴题意

因为这题本来就在问：

```text
从左往右，最早哪一位开始不一致
```

纵向扫描正好就是直接做这件事。

它不是先猜一个前缀再去修，而是：

- 一列一列确认
- 一旦出错立即停止

所以面试里会更自然。

### 手推一个例子

还是看：

```text
["flower", "flow", "flight"]
```

#### 第 0 位

- `f`
- `f`
- `f`

一致，继续。

#### 第 1 位

- `l`
- `l`
- `l`

一致，继续。

#### 第 2 位

- `o`
- `o`
- `i`

这里不一致了。

那说明最长公共前缀就是前面那一段：

```text
"fl"
```

### 再看一个边界例子

如果是：

```text
["dog", "racecar", "car"]
```

第 `0` 位就已经不一样：

- `d`
- `r`
- `c`

所以直接返回：

```text
""
```

### 为什么它最适合面试

1. 思路最贴题意：直接找“第一个不一致的位置”
2. 代码短，而且没有多余技巧
3. 退出条件非常清楚
4. 好解释，也好复现

## 方法三：排序后只比较首尾字符串

### 思路

还有一个很巧的角度。

如果先把字符串数组按字典序排序，那么：

- 排在最前面的字符串最“小”
- 排在最后面的字符串最“大”

这时整个数组的最长公共前缀，其实只取决于：

```text
第一个字符串 和 最后一个字符串
```

因为如果这两个字符串在某一位都不一样，那中间任何字符串也不可能在这一位继续都一样。

### 为什么可行

排序后，差异最大的两个字符串已经被拉到两端了。

所以公共前缀的上限，就由这两个边界字符串决定。

只要把首尾两个字符串从左到右比一遍，就能得到整个数组的最长公共前缀。

### 代码

对应代码文件：

```text
02_字符串/02_q14/solution_3_sort_then_compare.py
```

### 复杂度

- 时间复杂度：`O(n log n + m)`
- 空间复杂度：取决于排序实现

其中：

- `n` 是字符串个数
- `m` 是首尾两个字符串比较时走过的字符数

### 评价

优点：

- 思路巧
- 代码也不长
- 很适合作为补充视角

缺点：

- 排序本身不是这题最必要的动作
- 面试里通常不如方法二直接

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，纵向扫描。**

### 为什么它最适合面试

1. 它最贴题意，没有绕弯
2. 时间复杂度和空间复杂度都很好
3. 代码短，边界清楚
4. 面试里很容易一句话讲明白：

> **从左到右按列比较，第一列不一致的位置之前，就是最长公共前缀。**

### 方法一为什么更适合第一层理解

方法一也很好，因为它能让你很快接受这件事：

```text
公共前缀只会越来越短
```

所以它很适合作为第一层思路。

### 方法三为什么更适合作为补充

方法三不是主线思维，但它很巧。

适合在你已经掌握前两种方法后，再补一个“排序后只比首尾”的角度。

---

## 最适合面试的方法：关键细节

### 1. 为什么用第一个字符串当参考

因为最长公共前缀不可能比任意一个字符串更长。

所以直接拿第一个字符串的每一位去检查，是最自然的起点。

### 2. 为什么某个字符串长度不够时就可以返回

因为如果某个字符串已经走到底了，那公共前缀最多只能到它结束的位置。

### 3. 为什么返回 `strs[0][:i]`

因为 `i` 这一位刚刚发现不一致。

那真正还能保留的公共前缀，就是前面那一段，也就是：

```text
strs[0][:i]
```

## 最后总结

这题最重要的主线就是：

1. 最长公共前缀只和开头这一段是否一致有关
2. 一旦某一位出现不一样，公共前缀就到此为止
3. 所以最自然的面试写法，就是从左到右按列比较

如果你能把这句复述清楚：

> **从左到右一列一列比，第一处不一致之前的部分，就是最长公共前缀。**

那这题就算真的掌握了。
