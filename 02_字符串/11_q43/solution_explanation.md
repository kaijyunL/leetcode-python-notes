# LeetCode 43. 字符串相乘（Multiply Strings）解析

## 题目描述

给你两个非负整数 `num1` 和 `num2`，它们都以字符串形式给出。

请你返回 `num1 * num2` 的结果，也要以字符串形式返回。

注意：

- 不能直接把整个字符串转成整数来做乘法
- 不能使用大整数类型

例如：

```text
num1 = "123", num2 = "456"
```

返回：

```text
"56088"
```

---

## 先理解题意

### 1. 这题本质上是在“模拟手算乘法”

很多人一看到不能转整数，就会觉得这题很别扭。

其实它并不是让你发明新的乘法规则。

它只是要求你把平时纸上做乘法的过程，改成在字符串层面完成。

也就是说，核心动作还是那两个：

```text
逐位相乘 + 处理进位
```

### 2. 难点不在乘法本身，而在“结果怎么存”

如果只看某一位和某一位相乘，事情很简单。

比如：

```text
3 * 6 = 18
```

真正麻烦的是：

- 这个结果应该加到最终答案的哪一位
- 不同局部乘积之间怎么叠加
- 进位什么时候处理最顺

所以这题真正考的其实是：

```text
你如何设计结果的累加方式
```

### 3. 最自然的两条思路

看到这题，一般最自然会想到两种写法：

1. **普通竖式乘法**：先算每一行局部乘积，再做字符串加法
2. **数组位置累加**：直接把每次乘法贡献加到最终结果数组里

这两种方法正好对应：

```text
先完全照着手算过程做，再进一步把“乘法 + 加法”合并优化
```

---

## 方法一：竖式乘法 + 字符串相加

### 思路

这是最直观的做法。

我们就像手算竖式乘法那样，拿 `num2` 的每一位，去乘整个 `num1`。

过程是：

1. 从右到左遍历 `num2`
2. 用当前这一位去乘 `num1` 的每一位，得到一行局部乘积
3. 根据当前位所在的位置，在局部乘积后面补对应数量的 `0`
4. 再把这一行和之前的累计结果做一次字符串加法

### 为什么可行

因为这和纸上做乘法完全一致。

比如：

```text
123 * 45
```

你会先算：

```text
123 * 5 = 615
123 * 4 = 492
```

但第二行里的 `4` 实际代表 `40`，所以要左移一位，也就是补一个 `0`：

```text
  615
 4920
```

最后再把这两行加起来。

写成代码后，唯一额外需要补的就是：

```text
如何实现“字符串加法”
```

### 手推一个关键点

为什么每处理完 `num2` 的一位，要在局部乘积后面补 `0`？

因为从右往左看：

- 第 `0` 位代表个位
- 第 `1` 位代表十位
- 第 `2` 位代表百位

所以当你处理的不是个位，而是更高位时，它本身就对应更大的量级。

补 `0` 本质上就是在模拟这个量级偏移。

### 复杂度

设 `m = len(num1)`，`n = len(num2)`。

- 时间复杂度：可粗略记作 `O(n * (m + n))`
- 空间复杂度：`O(m + n)` 到更高一些

因为每一轮除了做乘法，还要做一轮字符串加法，所以整体不如方法二紧凑。

### 评价

优点：

- 最贴近手算过程
- 很适合理解题目本质
- 便于把“字符串加法”和“字符串乘法”联系起来

缺点：

- 中间字符串较多
- 实现步骤更长
- 面试里通常不如方法二利落

## 方法二：数组位置累加（面试主推）

这是最适合面试的方法。

### 思路

如果我们继续观察竖式乘法，会发现一个很重要的规律：

```text
num1[i] 和 num2[j] 相乘后，结果只会影响答案中的相邻两位
```

更准确地说：

- 个位会落到位置 `i + j + 1`
- 进位会落到位置 `i + j`

所以我们可以直接开一个长度为 `m + n` 的数组 `pos`，把每次乘法的结果累加进去。

过程是：

1. 从右到左遍历 `num1` 和 `num2`
2. 计算当前两位的乘积 `mul`
3. 把它加到结果数组的低位位置 `p2`
4. 把新的个位留在 `p2`
5. 把新的进位加到更高位 `p1`
6. 最后去掉前导 `0`，拼成字符串

### 为什么可行

因为两个数的某一位相乘后，最终只会对一个固定的量级区间产生影响。

这和竖式乘法里的“先写个位，再向前进位”是同一件事，只是我们把它直接落在数组位置上了。

也就是说，这个数组其实就是：

```text
把最终答案还没转成字符串之前的每一位先存起来
```

### 手推一个核心规律

假设：

```text
num1 = "123"
num2 = "456"
```

如果取：

- `3` 和 `6` 相乘，结果应该先放在最后一位附近
- `2` 和 `6` 相乘，位置要再往前一位
- `3` 和 `5` 相乘，也会落在和上一种相近的位置

你会发现：

```text
下标越靠右的数字相乘，结果越靠近答案末尾
```

而 `i + j`、`i + j + 1` 这两个位置，恰好能稳定描述这种关系。

这就是数组法成立的核心原因。

### 为什么它最适合面试

1. 本质仍然是竖式乘法，但写法更紧凑
2. 没有反复做字符串加法，效率更高
3. 位置规律清楚后，代码非常稳定
4. 能体现你不只是会模拟，还会做结构优化

### 代码

对应代码文件：

```text

```

### 复杂度

- 时间复杂度：`O(m * n)`
- 空间复杂度：`O(m + n)`

### 关键细节

#### 1. 为什么结果数组长度一定是 `m + n`

因为一个 `m` 位数乘一个 `n` 位数，乘积最多只有 `m + n` 位。

例如：

```text
99 * 99 = 9801
```

两个两位数相乘，结果最多四位。

#### 2. 为什么 `p1 = i + j`、`p2 = i + j + 1`

因为我们是从右往左做乘法。

当前两位相乘得到的结果：

- 个位留在较低位 `p2`
- 进位放到前一位 `p1`

这和手算时“写个位、向前进位”完全对应。

#### 3. 为什么最后还要去掉前导 `0`

因为数组长度按“最多 `m + n` 位”来开。

但实际结果不一定真的占满这么多位。

比如：

```text
2 * 3 = 6
```

数组可能会是：

```text
[0, 6]
```

所以最后要把前面的无效 `0` 去掉。

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，数组位置累加。**

### 为什么

1. 它仍然基于竖式乘法，思路并不跳脱
2. 但它把“局部乘积 + 最终累加”合并在了一起
3. 时间复杂度更好，代码也更集中
4. 只要你能讲清楚位置规律，就非常有说服力

### 方法一的价值

方法一最大的价值，是帮助你完全理解这题为什么本质上还是手算乘法。

如果你一开始对数组位置规律不够熟，先从方法一出发最自然。

## 最后总结

这题最重要的主线就是：

1. 不能转整数，不代表不能做乘法，而是要在字符串层面模拟乘法
2. 核心动作一直都是“逐位相乘 + 处理进位”
3. 方法一是完整竖式模拟，方法二是把乘法结果直接累加到最终位置
4. 真正关键的是你能不能把“每次乘法该影响答案哪两位”讲清楚

如果你能把这句复述清楚：

> **这题本质上是把手算乘法搬到字符串上做，而最优写法是直接把每次乘法的结果累加到最终答案数组的对应位置。**

那这题就算真的掌握了。
