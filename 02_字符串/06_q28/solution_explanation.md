# LeetCode 28. 找出字符串中第一个匹配项的下标（Find the Index of the First Occurrence in a String）解析

## 题目描述

给你两个字符串：

- `haystack`：主串
- `needle`：模式串

请你在 `haystack` 中找到 `needle` **第一次出现** 的位置，并返回它的下标。

如果不存在，就返回：

```text
-1
```

例如：

```text
haystack = "sadbutsad", needle = "sad" -> 0
haystack = "leetcode", needle = "leeto" -> -1
```

---

## 先理解题意

### 1. 这题本质上是在问：模式串第一次从哪里开始“完整匹配”

不是问某个字符有没有出现。

也不是问有几个匹配位置。

它真正问的是：

```text
从 haystack 的哪个起点开始，连续一段字符刚好等于 needle
```

而且只要找到**第一个**，就可以直接返回。

### 2. 为什么“起点”是这题最关键的视角

如果 `needle` 长度是 `m`，那你在 `haystack` 里尝试匹配时，本质上就是不断枚举一个起点 `i`：

- 试着看 `haystack[i:i+m]`
- 看它是否和 `needle` 一样

所以这题最自然的第一层思路其实就是：

> **枚举每个可能的起点，然后检查能不能完整匹配。**

### 3. 这题的三层理解路径

看到这题，一般最自然会想到三层做法：

1. **暴力匹配**：一个起点一个起点试
2. **内置函数**：直接用语言已经实现好的查找能力
3. **KMP**：在失配时复用已经匹配过的信息，避免主串回退

这三种方法刚好构成：

```text
先理解问题本身，再看工程写法，最后补上真正的字符串匹配优化算法
```

---

## 方法一：暴力匹配（面试主推）

这是最适合面试的方法。

### 思路

最直接的做法是：

1. 枚举 `haystack` 中每一个可能作为起点的位置 `i`
2. 从这个位置开始，逐个字符和 `needle` 对比
3. 只要中途有一个字符不一样，就说明这个起点不行
4. 如果 `needle` 所有字符都匹配完了，直接返回当前起点 `i`
5. 如果所有起点都试过还没找到，就返回 `-1`

### 为什么可行

因为“第一次出现的位置”本来就是按顺序试出来的。

我们从左到右枚举起点：

- 第一个能完整匹配的起点，就是答案
- 前面所有更早的位置都已经试过且失败了

所以这个过程虽然朴素，但逻辑完全正确。

### 手推一个例子

看：

```text
haystack = "hello"
needle = "ll"
```

`needle` 长度是 `2`，所以可以尝试的起点有：

- `i = 0`，比较 `he` 和 `ll`，不匹配
- `i = 1`，比较 `el` 和 `ll`，不匹配
- `i = 2`，比较 `ll` 和 `ll`，匹配成功

所以答案就是：

```text
2
```

### 再看一个失败例子

如果：

```text
haystack = "leetcode"
needle = "leeto"
```

你会从左到右尝试所有可能起点。

但每次比较时，都会在某一位失配。

最后没有任何起点能让整个 `needle` 匹配完，所以返回：

```text
-1
```

对应代码文件：


### 复杂度

- 时间复杂度：`O(n * m)`
- 空间复杂度：`O(1)`

其中：

- `n` 是 `haystack` 的长度
- `m` 是 `needle` 的长度

### 为什么它最适合面试

1. 思路最自然，完全贴着题意走
2. 代码简洁，几乎不会写崩
3. 边界也容易处理，比如空串、长度不够等情况
4. 即使后续被追问优化，也能顺着这版自然引出 KMP

## 方法二：内置 `find()`

### 思路

如果站在工程实践角度，这题最直接的写法其实就是：

```text
直接调用字符串的查找方法
```

Python 里可以直接写：

```python
haystack.find(needle)
```

它会：

- 返回第一次出现的位置
- 如果找不到，就返回 `-1`

这和题目要求完全一致。

### 为什么可行

因为语言内置的字符串查找，本来就是为这种需求准备的。

也就是说，我们其实是在把这个任务交给 Python 底层的高效实现来完成。

### 代码

对应代码文件：

```text

```

### 复杂度

- 底层实现较复杂，实际性能通常很好
- 面试里一般不重点讨论它的精确复杂度，而是把它视为语言提供的现成功能

### 评价

优点：

- 最短
- 最实用
- 工程里非常常见

缺点：

- 面试里通常不算真正展示算法能力
- 没有体现你对字符串匹配过程的理解

## 方法三：KMP（最优解）

### 核心问题：暴力法为什么会慢

暴力法在失配时，通常会：

- 主串起点往后挪一格
- 模式串重新从头开始比

这样会重复比较很多已经比较过的字符。

KMP 的核心价值就在这里：

> **当模式串发生失配时，不要傻傻从头重来，而是利用模式串本身的重复结构，决定下一步该从哪里继续。**

### 第一步：理解前缀表 `lps`

KMP 最关键的是预处理 `needle`，构造一个数组：

```text
lps[i]
```

它表示：

```text
needle[0:i+1] 这个前缀子串中，最长的“相等前缀和后缀”的长度
```

这里的“前缀”和“后缀”都不能是整个字符串本身。

比如：

```text
needle = "aabaaaf"
```

某些位置上，前面已经匹配好的内容里可能有一部分“开头”和“结尾”是相同的。

这意味着：

- 如果后面失配了
- 我们不必把模式串完全退回到开头
- 可以直接跳到那个仍然可能继续匹配的位置

### 第二步：匹配时为什么主串不用回退

在 KMP 匹配过程中：

- `i` 指向主串当前字符
- `j` 指向模式串当前字符

如果：

```text
haystack[i] == needle[j]
```

那就一起往后走。

如果失配了：

- 暴力法会让模式串从头开始
- KMP 会让 `j` 跳到 `lps[j - 1]`

这表示：

```text
模式串前面这段里，有一部分前后缀是相同的，所以可以直接复用
```

这样 `i` 不需要回头，整个主串只会一路往前扫。

### 手推一个小例子

看：

```text
haystack = "aabaabaafa"
needle = "aabaaf"
```

当前面已经匹配了若干位，后面突然失配时，KMP 不会让你重新拿 `needle[0]` 去比。

因为它知道：

- 你刚刚匹配成功的那段内部，本身就有重复结构
- 其中一部分仍然可能作为下一次匹配的起点

所以它通过 `lps` 直接把 `j` 跳过去，避免重复劳动。

这就是它能做到线性复杂度的关键。

对应代码文件：


### 复杂度

- 时间复杂度：`O(n + m)`
- 空间复杂度：`O(m)`

其中：

- `n` 是 `haystack` 的长度
- `m` 是 `needle` 的长度

### 评价

优点：

- 真正的字符串匹配优化算法
- 避免主串回退
- 理论复杂度最好

缺点：

- 实现和讲解都明显更复杂
- 如果面试官没要求优化到这个层级，现场手写成本偏高

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法一，暴力匹配。**

### 为什么不是 KMP

因为这道题虽然可以用 KMP 做到最优复杂度，但从面试表达角度看：

1. 暴力法更贴题意，几乎一眼就能想到
2. 代码更自然，更适合现场稳定写出
3. 对于这题本身，先把正确的匹配逻辑讲清楚更重要
4. 如果面试官追问更优解，再顺势升级到 KMP，会更合理

也就是说：

```text
KMP 是最优解，但不一定是最适合面试第一时间写出来的解法
```

这正是这题很典型的地方。

### 方法二为什么更偏工程写法

内置 `find()` 当然很好用，但它绕过了算法本身。

所以更适合日常工程，不太适合作为这题的主讲答案。

### 方法三什么时候值得写

如果面试官：

- 明确要求更优复杂度
- 或者追问“有没有比暴力更好的方法”

那就非常适合继续讲 KMP。

---

## 最适合面试的方法：关键细节

### 1. 为什么起点只需要枚举到 `n - m`

因为如果从更靠后的位置开始，剩余字符长度已经不够放下整个 `needle` 了。

那就不可能匹配成功。

### 2. 为什么空 `needle` 返回 `0`

这相当于说：

```text
空串在任意字符串的最开头就算匹配成功
```

这也是很多标准库和题目约定的行为。

### 3. 为什么一旦找到就能直接返回

因为我们是从左到右枚举起点。

所以第一个成功匹配的位置，天然就是“第一次出现”的位置。

## 最后总结

这题最重要的主线就是：

1. 先把问题看成“枚举起点，看能不能完整匹配模式串”
2. 暴力法最容易建立正确理解，也是最适合面试先写出来的版本
3. 内置 `find()` 更像工程实践写法
4. KMP 的价值在于：失配时复用已匹配信息，避免主串回退

如果你能把这句复述清楚：

> **这题先从枚举起点的暴力匹配理解；如果要进一步优化，就用 KMP 在失配时跳过重复比较。**

那这题就算真的掌握了。
