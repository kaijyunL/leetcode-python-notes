# LeetCode 125. 验证回文串（Valid Palindrome）解析

## 题目描述

给你一个字符串 `s`。

如果把它里面所有：

- 非字母数字字符去掉
- 大写字母统一转成小写

之后，剩下的字符串正着读和反着读完全一样，那么就返回：

```text
True
```

否则返回：

```text
False
```

例如：

```text
s = "A man, a plan, a canal: Panama" -> True
s = "race a car" -> False
s = " " -> True
```

---

## 先理解题意

### 1. 这题不是判断“原字符串”是不是回文

原字符串里可能有：

- 空格
- 逗号
- 冒号
- 其他符号
- 大小写混杂

而这些内容很多都不参与真正的回文判断。

所以这题真正要判断的不是原串本身，而是：

```text
清洗后的字符串是否是回文
```

比如：

```text
"A man, a plan, a canal: Panama"
```

清洗后会变成：

```text
"amanaplanacanalpanama"
```

这才是我们真正要检查的对象。

### 2. 题目的关键动作有两个

这题最核心的两个动作是：

1. **跳过无效字符**：只保留字母和数字
2. **统一大小写**：比较时不区分大小写

只要这两个动作做对了，剩下就只是普通的回文判断。

### 3. 最自然的两条思路

看到这题，一般最自然会想到两种做法：

1. **先清洗，再判断回文**：先把有效字符提出来，再和反转结果比较
2. **双指针原地判断**：左右指针向中间靠拢，边跳过无效字符边比较

这两种方法都能做对，但它们在空间使用上有明显区别。

---

## 方法一：筛选后反转比较

### 思路

最直接的做法是：

1. 遍历原字符串
2. 只保留字母和数字字符
3. 同时把它们统一转成小写
4. 把得到的新字符串和它的反转结果做比较

如果两者一样，就是回文；否则不是。

### 为什么可行

因为回文的定义本来就是：

```text
正着读和反着读一样
```

而题目又明确告诉我们：

- 非字母数字字符不参与判断
- 大小写不敏感

所以只要先把字符串清洗成“真正参与判断的版本”，然后直接比较它和反转后的自己，就完全符合题意。

### 手推一个例子

看：

```text
s = "A man, a plan, a canal: Panama"
```

先筛选并转小写：

```text
"amanaplanacanalpanama"
```

再反转：

```text
"amanaplanacanalpanama"
```

二者相同，所以返回 `True`。

再看：

```text
s = "race a car"
```

清洗后：

```text
"raceacar"
```

反转后：

```text
"racaecar"
```

不相同，所以返回 `False`。

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

其中 `n` 是字符串长度。

### 评价

优点：

- 最直观
- 最容易写对
- 非常适合第一层理解

缺点：

- 需要额外构造一个新字符串
- 空间复杂度不是最优

## 方法二：双指针（面试主推）

这是最适合面试的方法。

### 第一步：让左右指针从两端出发

我们定义两个指针：

- `left` 指向字符串开头
- `right` 指向字符串结尾

然后让它们不断向中间靠近。

### 第二步：先跳过不需要比较的字符

因为题目说：

```text
非字母数字字符不参与判断
```

所以如果：

- `s[left]` 不是字母数字，就让 `left += 1`
- `s[right]` 不是字母数字，就让 `right -= 1`

这一步本质上是在做：

> **把无效字符从比较流程里排除掉。**

### 第三步：比较有效字符是否相等

当左右两边都停在有效字符上以后：

1. 把它们都转成小写
2. 比较是否相等
3. 如果不相等，立刻返回 `False`
4. 如果相等，就让两个指针继续向中间移动

只要整个过程都没有出现不相等，最后就返回 `True`。

### 为什么这比方法一更贴题意

因为方法一是：

```text
先构造一个“新字符串”，再判断回文
```

而双指针是：

```text
一边跳过无效字符，一边直接在原字符串上完成判断
```

它没有做额外的整体拷贝，而是把“清洗”和“比较”合并进一次扫描里了。

所以更节省空间，也更像面试里希望看到的解法。

### 手推一个例子

还是看：

```text
s = "A man, a plan, a canal: Panama"
```

#### 第一次比较

- 左边是 `A`
- 右边是 `a`

转小写后都是 `a`，匹配成功。

#### 接下来继续移动

左指针会跳过空格、逗号等无效字符。

右指针也会跳过空格、冒号等无效字符。

然后继续比较：

- `m` 和 `m`
- `a` 和 `a`
- `n` 和 `n`
- ...

一路都匹配，所以最后返回 `True`。

### 再看一个边界例子

如果字符串是：

```text
s = " "
```

整个字符串里没有任何字母数字字符。

那左右指针会不断跳过空格，最后交错。

这意味着：

```text
有效字符序列是空串
```

而空串本身可以看成回文，所以返回 `True`。

### 为什么它最适合面试

1. 逻辑直接贴题意：边过滤边比较
2. 不需要额外构造新字符串
3. 空间复杂度更优，为 `O(1)`
4. 指针移动规则清楚，面试里也很好解释

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，双指针。**

### 为什么它最适合面试

1. 它把“过滤无效字符”和“回文比较”合并到一个流程里
2. 时间复杂度仍然是 `O(n)`
3. 空间复杂度更优，是 `O(1)`
4. 代码简洁自然，现场很容易复现

### 方法一为什么更适合第一层理解

方法一非常适合先建立正确感觉。

它先帮你把这题还原成一句最朴素的话：

```text
先清洗出真正要比较的字符串，再看它是不是回文
```

所以它很适合作为入门版本。

---

## 最适合面试的方法：关键细节

### 1. 为什么要先跳过非字母数字字符

因为题目明确说明这些字符不参与判断。

如果不先跳过，你比较的就不是题目真正要求的内容。

### 2. 为什么比较时要统一转小写

因为大小写不敏感。

例如：

```text
'A' 和 'a'
```

在这题里应该看作相同字符。

### 3. 为什么当 `left >= right` 时就可以返回 `True`

因为这表示所有需要比较的有效字符都已经配对检查完成了。

只要过程中没有出现不匹配，就说明它是回文串。

## 最后总结

这题最重要的主线就是：

1. 题目真正要求比较的是“清洗后的有效字符序列”
2. 非字母数字字符要跳过，字母比较前要统一转小写
3. 可以先构造新串再判断，也可以直接用双指针在原串上完成判断
4. 面试里更推荐双指针，因为它空间复杂度更优

如果你能把这句复述清楚：

> **这题本质上是边跳过无效字符、边从两端比较有效字符；只要一路都相等，它就是回文串。**

那这题就算真的掌握了。
