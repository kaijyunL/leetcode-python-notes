# LeetCode 58. 最后一个单词的长度（Length of Last Word）解析

## 题目描述

给你一个字符串 `s`，其中由单词和空格组成。

请你返回：

```text
最后一个单词的长度
```

这里的“单词”指的是：

```text
只包含字母、不包含空格的最大连续子串
```

例如：

```text
"Hello World" -> 5
"   fly me   to   the moon  " -> 4
"luffy is still joyboy" -> 6
```

---

## 先理解题意

### 1. 我们真正关心的是“最后一段连续非空格字符”

这题虽然说的是“最后一个单词”，但如果把题目翻成更程序一点的话，其实就是：

```text
从字符串末尾往前找，最后一段连续非空格字符有多长
```

所以重点不是把所有单词都拆出来，而是：

- 先跳过末尾多余空格
- 再数最后一个单词有多少个字符

### 2. 为什么末尾空格最值得先处理

比如：

```text
"Hello World   "
```

如果你直接从最后一个字符开始看，会先遇到一串空格。

但这些空格都不是最后一个单词的一部分。

所以这题最自然的第一步就是：

```text
先把字符串末尾的空格跳过去
```

跳完以后，停下来的位置才是真正最后一个单词的末尾。

### 3. 这题没有复杂数据结构，关键只是扫描顺序

因为答案只和字符串最后一段有关。

所以这里没有什么哈希、DP、栈这些结构要想，关键只是：

```text
是把字符串整体拆开再取最后一个
还是直接从后往前扫
```

这也正好对应下面两种方法。

---

## 方法一：`split()` 后取最后一个单词

### 思路

最直接的做法就是：

1. 用 `split()` 把字符串拆成若干单词
2. 如果拆完是空列表，说明原字符串里没有单词，返回 `0`
3. 否则返回最后一个单词的长度

### 为什么可行

因为 Python 的：

```python
s.split()
```

在不传参数时会自动处理这些情况：

- 忽略前导空格
- 忽略末尾空格
- 连续多个空格也不会生成空字符串

比如：

```python
"   fly me   to   the moon  ".split()
```

得到的是：

```text
["fly", "me", "to", "the", "moon"]
```

那最后一个单词自然就是 `words[-1]`。

### 代码

对应代码文件：

```text
02_字符串/01_q58/solution_1_split.py
```

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`

### 评价

优点：

- 最直观
- 最容易一眼写对
- 很适合第一层理解

缺点：

- 会把所有单词都拆出来
- 额外开了一个列表，不是最省空间的写法

## 方法二：从后往前扫描（面试主推）

这是最适合面试的方法。

### 第一步：先跳过末尾空格

先让指针从字符串末尾开始往前走。

如果当前字符是空格，就继续左移。

这一段在做的事其实就是：

```text
把不属于最后一个单词的尾部空格全部丢掉
```

比如：

```text
"Hello World   "
```

从右往左看，先跳过 3 个空格，才会停在 `d` 上。

### 第二步：从最后一个字母开始计数

跳过尾部空格后，指针停住的位置，就是最后一个单词的最后一个字符。

这时继续往左扫：

- 只要还不是空格，就说明还在最后一个单词里
- 每走一步，长度加 `1`
- 直到遇到空格或者走到字符串开头为止

这时候累计出来的长度，就是答案。

### 为什么这比方法一更接近题目本质

因为题目只问：

```text
最后一个单词多长
```

它根本不关心前面那些单词分别是什么。

所以从后往前扫，其实更贴题意：

- 不用拆出全部单词
- 不用关心中间有多少段空格
- 只围绕最后一段连续非空格字符做处理

### 手推一个例子

看这个字符串：

```text
"   fly me   to   the moon  "
```

#### 第一步：跳过尾部空格

字符串最后有两个空格，先一路往左跳。

跳完后，指针会停在：

```text
n
```

也就是 `moon` 的最后一个字母上。

#### 第二步：开始计数

继续往左：

- `n`：长度 `1`
- `o`：长度 `2`
- `o`：长度 `3`
- `m`：长度 `4`

再往左就是空格了，停止。

所以答案是：

```text
4
```

### 再看一个边界例子

如果字符串是：

```text
"     "
```

那从右往左会一直跳空格，最后指针会变成负数。

这说明：

```text
字符串里根本没有单词
```

所以直接返回 `0`。

### 为什么它最适合面试

1. 逻辑最贴题意：只处理最后一个单词
2. 不需要额外列表，空间复杂度更好
3. 代码短，而且边界清楚
4. 面试里也很好解释：**先跳过尾空格，再数最后一个单词长度**

## 哪个方法最适合面试

### 结论

**最适合面试的是：方法二，从后往前扫描。**

### 为什么它最适合面试

1. 它不依赖内置拆分函数去“整体处理”字符串
2. 它只围绕题目真正关心的最后一段字符展开
3. 空间复杂度是 `O(1)`
4. 代码自然、短、稳定，现场很好复现

### 方法一为什么更适合第一层理解

方法一非常直观。

它先帮你快速建立这个认识：

```text
题目本质上就是找到最后一个单词，再看它多长
```

但如果站在面试角度，方法二更像真正的算法解法。

---

## 最适合面试的方法：关键细节

### 1. 为什么一定要先跳过末尾空格

因为字符串最后可能不是字母，而是空格。

如果这一步不先做，后面的计数就会从错误位置开始。

### 2. 为什么全是空格时要返回 `0`

因为跳完尾部空格以后，如果指针已经越界，说明整个字符串都没有单词。

### 3. 为什么第二段循环遇到空格就可以停

因为我们从后往前扫，进入第二段循环时已经确定自己在最后一个单词内部。

那一旦遇到空格，就说明这个单词已经数完了。

## 最后总结

这题最重要的主线其实很简单：

1. 最后一个单词前面可能有很多内容，但真正相关的只有字符串尾部
2. 先跳过尾部空格，才能找到最后一个单词的结尾
3. 再往左统计连续非空格字符的长度，就是答案

如果你能把这句复述清楚：

> **先跳过末尾空格，再从后往前数最后一段连续非空格字符。**

那这题就已经掌握了。
