# LeetCode 12. 整数转罗马数字（Integer to Roman）解析

## 题目描述

给你一个整数 `num`，把它转换成罗马数字。

题目范围是：

```text
1 <= num <= 3999
```

罗马数字的基本符号是：

```text
I -> 1
V -> 5
X -> 10
L -> 50
C -> 100
D -> 500
M -> 1000
```

还有 6 个减法组合：

```text
IV -> 4
IX -> 9
XL -> 40
XC -> 90
CD -> 400
CM -> 900
```

例子：

```text
3 -> III
58 -> LVIII
1994 -> MCMXCIV
```

---

## 先理解题意

整数转罗马数字，本质是把一个数拆成若干个罗马数字面值。

比如：

```text
58 = 50 + 5 + 1 + 1 + 1
```

所以：

```text
58 -> L + V + I + I + I -> LVIII
```

再看一个包含减法规则的例子：

```text
1994 = 1000 + 900 + 90 + 4
```

所以：

```text
1994 -> M + CM + XC + IV -> MCMXCIV
```

这题最关键的地方是：不能只考虑 `I, V, X, L, C, D, M` 这 7 个基础符号。

如果漏掉 `4, 9, 40, 90, 400, 900` 这 6 个特殊面值，就会把 `4` 写成 `IIII`，把 `9` 写成 `VIIII`，结果不符合罗马数字规则。

---

## 方法一：分位查表

### 思路

因为 `num` 的范围固定是 `1` 到 `3999`，可以分别准备千位、百位、十位、个位的罗马数字表。

比如百位表：

```text
0 -> ""
1 -> C
2 -> CC
3 -> CCC
4 -> CD
5 -> D
6 -> DC
7 -> DCC
8 -> DCCC
9 -> CM
```

然后把每一位取出来，直接查表拼接。

### 代码

```python
class Solution:
    def intToRoman(self, num: int) -> str:
        thousands = ["", "M", "MM", "MMM"]
        hundreds = ["", "C", "CC", "CCC", "CD", "D", "DC", "DCC", "DCCC", "CM"]
        tens = ["", "X", "XX", "XXX", "XL", "L", "LX", "LXX", "LXXX", "XC"]
        ones = ["", "I", "II", "III", "IV", "V", "VI", "VII", "VIII", "IX"]

        return (
            thousands[num // 1000]
            + hundreds[num % 1000 // 100]
            + tens[num % 100 // 10]
            + ones[num % 10]
        )
```

### 评价

这个方法非常直接，代码也短。

缺点是表比较硬编码，讲起来更像“背规则”，不如贪心方法能体现这题的统一思路。

---

## 方法二：贪心反复扣减

### 思路

把所有合法面值都列出来，并按从大到小排列：

```text
1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1
```

然后每次都优先使用当前能用的最大面值。

比如 `1994`：

```text
1994 先用 1000 -> M，剩 994
994  先用 900  -> CM，剩 94
94   先用 90   -> XC，剩 4
4    先用 4    -> IV，剩 0
```

最后就是：

```text
MCMXCIV
```

### 代码

```python
class Solution:
    def intToRoman(self, num: int) -> str:
        values = [
            (1000, "M"),
            (900, "CM"),
            (500, "D"),
            (400, "CD"),
            (100, "C"),
            (90, "XC"),
            (50, "L"),
            (40, "XL"),
            (10, "X"),
            (9, "IX"),
            (5, "V"),
            (4, "IV"),
            (1, "I"),
        ]

        ans = []

        for value, symbol in values:
            while num >= value:
                ans.append(symbol)
                num -= value

        return "".join(ans)
```

### 评价

这个方法比方法一更能体现“为什么这样拆”。

缺点是 `while num >= value` 会反复扣减。虽然这题范围很小，实际性能完全没问题，但代码还可以再写得更简洁。

---

## 方法三：贪心加 `divmod`

### 核心思路

方法二每次只扣一个面值。

其实可以一次算出当前面值能用几次：

```python
count, num = divmod(num, value)
```

这里：

```text
count 表示当前符号要重复几次
num 表示扣掉当前面值后的剩余数字
```

比如处理 `3000` 和 `1000`：

```text
count = 3
symbol = M
```

所以可以直接加入：

```text
MMM
```

### 面试代码

```python
class Solution:
    def intToRoman(self, num: int) -> str:
        values = [
            (1000, "M"),
            (900, "CM"),
            (500, "D"),
            (400, "CD"),
            (100, "C"),
            (90, "XC"),
            (50, "L"),
            (40, "XL"),
            (10, "X"),
            (9, "IX"),
            (5, "V"),
            (4, "IV"),
            (1, "I"),
        ]

        ans = []

        for value, symbol in values:
            count, num = divmod(num, value)
            ans.append(symbol * count)

        return "".join(ans)
```

### 为什么贪心成立

罗马数字的规则本来就要求大的面值放在前面。

如果把 `IV, IX, XL, XC, CD, CM` 这些减法组合也当作独立面值，那么题目就变成了：

```text
每次从剩余数字里拿走当前能拿的最大面值
```

因为所有特殊情况都已经放进面值表里了，所以贪心过程中不需要再额外判断 `4` 和 `9`。

### 复杂度

- 时间复杂度：`O(1)`，面值表固定只有 13 项
- 空间复杂度：`O(1)`，不算返回结果本身

---

## 最适合面试的方法

最推荐方法三：贪心加 `divmod`。

原因是：

1. 它比方法一更容易解释推导过程。
2. 它比方法二更简洁，不需要内层 `while`。
3. 它把特殊规则统一放进面值表，代码里没有额外分支。

面试里可以这样讲：

```text
我先把所有可能出现的罗马数字面值按从大到小列出来，包括 4 和 9 对应的特殊组合。
然后从大到小遍历，每次计算当前面值能取几次，把对应符号加入答案，再处理剩余数字。
因为罗马数字本身就是大面值优先表示，所以这样贪心可以直接得到合法结果。
```

---

## 易错点

1. 忘记把 `4, 9, 40, 90, 400, 900` 加进面值表。
2. 面值表没有按从大到小排序。
3. 方法二里忘记在 `while` 中更新 `num`。
4. 拼接结果时一直用字符串 `+=`，代码能过，但不如列表收集后 `join` 清楚。

---

## 小结

这题可以从“分位查表”开始理解，也可以用贪心统一处理。

真正面试时，优先写方法三：把所有合法面值按降序列好，再用 `divmod` 一次处理当前面值的重复次数。
