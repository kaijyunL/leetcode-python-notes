# LeetCode 168. Excel 表列名称（Excel Sheet Column Title）解析

## 题目描述

给你一个整数 `columnNumber`，返回它在 Excel 表格中对应的列名称。

列号和字母的对应关系：

```text
1  -> "A"
2  -> "B"
...
26 -> "Z"
27 -> "AA"
28 -> "AB"
...
52 -> "AZ"
53 -> "BA"
...
701 -> "ZY"
702 -> "ZZ"
703 -> "AAA"
```

例子：

```text
1   -> "A"
28  -> "AB"
701 -> "ZY"
2147483647 -> "FXSHRXW"
```

约束：

- `1 <= columnNumber <= 2^31 - 1`

---

## 先理解题意

这道题是 **LeetCode 171 的反问题**：171 是字母串 → 列号，168 是列号 → 字母串。

171 已经看出关键性质：

```text
Excel 列号 = 没有 0 的 26 进制（bijective base-26）
```

每一位字母代表 1~26，而不是普通进制里的 0~25。这就是这道题所有“怪”的来源。

普通 10 进制把整数转成字符串大家都会写：

```text
n = 123
while n > 0:
    digit = n % 10        # 取最低位
    append(digit)
    n //= 10              # 砍掉最低位
最后倒序就是 "123"
```

很自然地，我们想把它套到 26 进制：

```text
while n > 0:
    digit = n % 26
    append(letter_of(digit))
    n //= 26
```

但是这样直接做会出错。我们先沿着这个直觉走一遍，看看它为什么错，再修。

---

## 方法一：直接套 26 进制（踩坑过程）

### 思路

最直觉的做法：

```text
A 对应 1，B 对应 2，... Z 对应 26
所以 digit = n % 26，digit - 1 就是字母偏移
```

写成代码：

```python
class Solution:
    def convertToTitle(self, columnNumber: int) -> str:
        chars = []
        n = columnNumber
        while n > 0:
            digit = n % 26                       # 期望落在 1~26
            chars.append(chr(digit - 1 + ord("A")))
            n //= 26
        return "".join(reversed(chars))
```

### 为什么不对

试一下 `n = 26`：

```text
n = 26
digit = 26 % 26 = 0
```

`digit` 本来应该落在 1~26，但 `% 26` 永远只会得到 0~25，
也就是说**取余 26 永远拿不到 26 本身**。

`digit = 0` 一旦传进 `chr(digit - 1 + ord('A'))`，就成了 `chr(-1 + 65) = '@'`，
字母都不对了。

再试 `n = 52`（应该是 "AZ"）：

```text
n = 52
digit = 52 % 26 = 0     ← 想表示 Z 但溢出成 0
n //= 26 → 2
digit = 2 % 26 = 2      ← 'B'
n //= 26 → 0，停止

倒序得到 "B?"，对不上
```

问题出在哪？

```text
% 26 永远拿不到 26，但 26（对应 Z）必须能被表达出来
```

怎么修？回头看 171 方法二——那里每读一个字符做 `ans = ans*26 + digit`，168 要做的就是逆这一步。
这条等式会直接告诉我们怎么动一下就能 divmod，详见方法二。

---

## 方法二：每次先 `-1` 再 divmod（面试主推）

### 核心思路（直接逆 171 方法二）

171 方法二每读一个字符做一次：

```text
ans = ans * 26 + digit              digit ∈ {1, 2, ..., 26}
```

把整数转回字符串，就是把这一步**反过来**：给我一个 `n`，要把最后一次累加的 `digit` 剥出来，剩下 `prev`：

```text
n = prev * 26 + digit               digit ∈ 1~26
```

第一反应是直接 `divmod(n, 26)`，商 = `prev`，余 = `digit`。但翻车了——
171 那一步的 `digit` 范围是 `1~26`，而 Python `% 26` 只能给 `0~25`，**多出来的 26 表达不出来**。

具体翻车点：当 `digit = 26` 时

```text
n = prev * 26 + 26 = (prev + 1) * 26
→ n % 26  = 0          想拿 26 拿到 0
→ n // 26 = prev + 1   商也多算了 1
```

修法：**等式两边同时减 1**：

```text
n     = prev * 26 + digit            digit ∈ 1~26
n - 1 = prev * 26 + (digit - 1)      digit - 1 ∈ 0~25  ← 标准 26 进制
```

现在 `digit - 1 ∈ 0~25` 正好是 `(n - 1) % 26` 能完整覆盖的范围，divmod 就可以直接用了：

```text
n -= 1                             # 把式子转成标准 26 进制
chr(n % 26 + ord('A'))             # n % 26 就是 digit-1，正是字母偏移
n //= 26                           # 剥掉最低位，对应 prev
```

跟 171 方法二刚好成对：

```text
171 正: ans = ans * 26 + (ord(ch) - ord('A') + 1)
168 反: n -= 1; chr(n % 26 + ord('A')); n //= 26
```

171 里那个 `+1` 和 168 里这个 `-1`，**就是同一件事（A 对应 1 而不是 0）在正反两面留下的同一道印记**，
两道题可以一起记。

### 面试代码

```python
class Solution:
    def convertToTitle(self, columnNumber: int) -> str:
        chars = []
        n = columnNumber
        while n > 0:
            n -= 1
            chars.append(chr(n % 26 + ord("A")))
            n //= 26
        return "".join(reversed(chars))
```

### 用 `n = 701` 走一遍（期望 "ZY"）

```text
n = 701
  n -= 1 → 700
  700 % 26 = 24 → 'Y'
  700 // 26 = 26
  chars = ['Y']

n = 26
  n -= 1 → 25
  25 % 26 = 25 → 'Z'
  25 // 26 = 0
  chars = ['Y', 'Z']

n = 0，循环结束
倒序 → "ZY" ✓
```

再用 `n = 52` 验证一下（期望 "AZ"，方法一翻车那个例子）：

```text
n = 52
  n -= 1 → 51
  51 % 26 = 25 → 'Z'
  51 // 26 = 1
  chars = ['Z']

n = 1
  n -= 1 → 0
  0 % 26 = 0 → 'A'
  0 // 26 = 0
  chars = ['Z', 'A']

倒序 → "AZ" ✓
```

### 关键点

```python
n -= 1
chars.append(chr(n % 26 + ord("A")))
n //= 26
```

要讲清楚四件事：

1. **为什么要 `-1`**
   - 171 方法二是 `ans = ans*26 + digit`（digit ∈ 1~26），168 就是逆这一步
   - 两边同减 1 后 `n-1 = prev*26 + (digit-1)`，`digit-1 ∈ 0~25` 正好能 divmod

2. **`-1` 和 `//` 的位置不能乱**
   - 必须先 `-1` 再 `% 26` 和 `// 26`
   - 否则 26 这种边界值会算成 'Z' + 高位多 1，结果错

3. **为什么循环条件是 `n > 0`**
   - 列号本身从 1 起步，不会出现 0
   - 当 `n // 26` 把所有高位砍光，n 变 0，就该停了

4. **结果要倒序**
   - 和普通进制转字符串一样：先算出来的是最低位

### 复杂度

- 时间：`O(log n)`，每次循环把 n 缩小 26 倍。
   `2^31 ≈ 2.1 * 10^9`，对 26 取对数大概 7 次循环，所以最长答案 7 个字母（"FXSHRXW"）。
- 空间：`O(log n)`，存输出字符。

## 哪个方法最适合面试

最适合面试的是 **方法二：每次先 `-1` 再 divmod**。

实际上这道题正确的写法基本只有方法二这一种，关键不在于挑哪种解法，而是**能不能把 `-1` 解释清楚**。

面试里可以这样说：

```text
168 是 171 的反问题。171 方法二每读一个字符做 ans = ans*26 + digit，
digit 是字母对应的 1 到 26。168 就是逆这一步：从 n 把最后那个 digit 剥出来，剩下 prev。
直接 divmod(n, 26) 不行，因为 digit 可以等于 26，而 % 26 只能给 0 到 25，拿不到 26。
关键是两边同减 1，等式变成 n-1 = prev*26 + (digit-1)，digit-1 范围是 0 到 25，
就是标准 26 进制，直接 divmod 即可。
所以代码每轮先 n -= 1，再用 % 26 拿当前字母，// 26 砍掉最低位，倒序输出。
171 正向里的 +1 和 168 反向里的 -1 是同一件事的正反面，两道题一起记。
时间 O(log n)，空间 O(log n) 存输出。
```

---

## 总结

- 方法一：直接 26 进制（错的）
  - 直觉自然，但 26 % 26 = 0 没有对应字母，且高位会多 1
  - 用来理解“为什么需要 -1”

- 方法二：每次先 `-1` 再 divmod（面试主推）
  - 一次 `-1` 同时修了“余数 0”和“高位多 1”两个问题
  - 写法简短，关键是讲清楚为什么减 1
