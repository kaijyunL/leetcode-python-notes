# LeetCode 172. 阶乘后的零（Factorial Trailing Zeroes）解析

## 题目描述

给定一个整数 `n`，返回 `n!` 末尾的 0 的个数。

例子：

```text
n = 3   -> 3! = 6              末尾 0 的个数 = 0
n = 5   -> 5! = 120             末尾 0 的个数 = 1
n = 10  -> 10! = 3628800        末尾 0 的个数 = 2
n = 0   -> 0! = 1               末尾 0 的个数 = 0
```

约束：

- `0 <= n <= 10^4`
- 进阶要求：能否设计 `O(log n)` 的解法？

---

## 先理解题意

“末尾 0 的个数”等价于问：

```text
n! 这个数能被 10 整除多少次？
```

也就是 `n!` 里包含多少个因子 10。

10 = 2 × 5，所以问题再转化为：

```text
n! 的质因数分解里同时包含 2 和 5，每凑齐一对 (2, 5) 就贡献一个末尾 0
末尾 0 的个数 = min(因子 2 的总数, 因子 5 的总数)
```

观察一下：在 1 到 n 之间，能被 2 整除的数远比能被 5 整除的数多
（每隔 2 个一个偶数，每隔 5 个才一个 5 的倍数）。所以**因子 2 永远多得用不完**，瓶颈在因子 5。

```text
末尾 0 的个数 = n! 里因子 5 的个数
```

剩下的工作就只是数 `n!` 里有多少个因子 5。

---

## 方法一：直接算 n!，再数末尾 0

### 思路

按题目字面意思：算出 `n!`，然后看末尾有多少个 0。

```python
class Solution:
    def trailingZeroes(self, n: int) -> int:
        f = 1
        for i in range(1, n + 1):
            f *= i

        count = 0
        while f > 0 and f % 10 == 0:
            count += 1
            f //= 10
        return count
```

### 为什么不推荐

- 思路最直白，正确性显然
- 但 `n` 才 100，`100!` 就已经是 158 位的天文数字了；`n = 10^4` 时 `n!` 大概 35660 位
- Python 虽然不会溢出（用大整数），但大整数乘法成本巨大，时间会爆
- 完全没必要去真的把这个数算出来

复杂度（粗估）：

- 时间：远超 `O(n)`，因为大整数乘法每次都越来越慢
- 空间：`O(n)` 量级的位数

这个解法在题目数据范围下勉强能过，但不是正确的“面试解”，**它的价值是用来提醒自己：题目根本不是要 n!，是要 n! 里的因子 5**。

---

## 方法二：枚举 1~n，逐个统计每个数贡献多少个因子 5

### 思路

既然只关心因子 5，就**别去算 n! 了**，直接把 1~n 每个数里的因子 5 一个个数出来加起来。

```text
对每个 i ∈ [1, n]：
    只要 i 还能被 5 整除，就累计 +1，并把 i 除以 5
```

举个例子 `n = 25`：

```text
5  贡献 1 个 5
10 贡献 1 个 5
15 贡献 1 个 5
20 贡献 1 个 5
25 贡献 2 个 5    ← 25 = 5 × 5，要数两次
合计 6 个 5

所以 25! 末尾有 6 个 0
```

### 代码

```python
class Solution:
    def trailingZeroes(self, n: int) -> int:
        count = 0
        for i in range(5, n + 1, 5):   # 不是 5 的倍数的数直接跳过
            x = i
            while x % 5 == 0:
                count += 1
                x //= 5
        return count
```

### 评价

- 避免了直接算 `n!`，再也不用搞大整数
- 但每个 5 的倍数都要循环到除尽，整体复杂度 `O(n / 5 · log_5 n) ≈ O(n)`
- `n = 10^4` 完全没问题，但题目进阶要求 `O(log n)`，还能再优化

下一步要意识到：**与其一个一个数去看“贡献几个 5”，不如反过来按“几个 5”分层数**。

## 方法三：Legendre 公式 / 按 5 的幂分层（面试主推）

### 核心思路

方法二是“枚举每个数，看它有几个 5”。我们换个角度：

```text
问：1 到 n 之间，至少含 1 个因子 5 的数有几个？  → n // 5    （5, 10, 15, ...）
问：至少含 2 个因子 5 的数有几个？               → n // 25   （25, 50, 75, ...）
问：至少含 3 个因子 5 的数有几个？               → n // 125  （125, 250, ...）
...
```

为什么把这三个加起来就是答案？

```text
对一个数 i，它如果恰好含 k 个因子 5：
- 在 "至少含 1 个" 这一行里被数过 1 次
- 在 "至少含 2 个" 这一行里被数过 1 次
- ...
- 在 "至少含 k 个" 这一行里被数过 1 次
- "至少含 k+1 个" 那一行里就不会被数到了
合计被数了 k 次，正好等于它实际贡献的因子 5 个数
```

所以：

```text
答案 = n//5 + n//25 + n//125 + n//625 + ...
```

（一直加到 `5^k > n` 为止。）

这就是 **Legendre 公式** 在 `p = 5` 时的特例。

### 面试代码

```python
class Solution:
    def trailingZeroes(self, n: int) -> int:
        count = 0
        while n > 0:
            n //= 5
            count += n
        return count
```

为什么这样写就等价于 `n//5 + n//25 + n//125 + ...`？

```text
初始 n = N
第 1 轮: n = N//5   ，count += N//5
第 2 轮: n = N//25  ，count += N//25   （因为 (N//5)//5 = N//25）
第 3 轮: n = N//125 ，count += N//125
...
直到 n == 0 才停
```

每一轮都把 n 缩小 5 倍，自然就跑完所有 5 的幂次。

### 用 `n = 30` 走一遍

```text
n = 30
  n //= 5 → 6,    count = 0 + 6 = 6
n = 6
  n //= 5 → 1,    count = 6 + 1 = 7
n = 1
  n //= 5 → 0,    count = 7 + 0 = 7
n = 0，结束

答案 = 7
```

手工验证：

- 5,10,15,20,30 各贡献 1 个 5 → 5 个
- 25 贡献 2 个 5 → 2 个
- 合计 7 个 ✓

再用 `n = 100`：

```text
100 // 5  = 20
20  // 5  = 4
4   // 5  = 0  停
答案 = 20 + 4 = 24
```

### 关键点

```python
while n > 0:
    n //= 5
    count += n
```

要讲清楚四件事：

1. **为什么数因子 5 而不是因子 10**
   - 末尾 0 = 配对的 (2, 5)，因子 2 永远多过因子 5，瓶颈是 5

2. **为什么是 `n // 5 + n // 25 + ...` 不是只算一次 `n // 5`**
   - `n // 5` 只数了“至少 1 个因子 5”
   - 25、125 这种贡献多个 5 的数，少数的部分要靠 `n//25`、`n//125` 补回来

3. **为什么循环里 `n //= 5; count += n` 就等价于求和**
   - 每轮把 n 替换成 `n // 5`，连续除等价于一次除高次幂

4. **循环什么时候停**
   - `n` 被反复除 5 后总会变 0，停在 0 这轮（这轮会加 0，可以省，也可以留着不影响结果）

### 复杂度

- 时间：`O(log₅ n)`，n 每轮缩小 5 倍
- 空间：`O(1)`

## 哪个方法最适合面试

最适合面试的是 **方法三：按 5 的幂分层计数**。

原因：

- 复杂度从 `O(n)` 直接掉到 `O(log n)`，命中题目“进阶要求”
- 代码极短，只有三行核心：`while`、`n //= 5`、`count += n`
- 解释路径自然：末尾 0 ← 因子 (2,5) 对 ← 因子 5 ← 分层数 5 的幂次

面试里可以这样说：

```text
末尾 0 来自因子 (2, 5) 配对，而 1~n 里因子 2 远多于因子 5，
所以问题转化成「n! 里有多少个因子 5」。
然后我把 1 到 n 里的 5 因子按层数：
n // 5 数所有含至少 1 个 5 的数，
n // 25 把含 2 个 5 的那些再数一次（补上少算的那个），
n // 125 再补含 3 个 5 的那一次，依此类推。
代码里用 while n > 0: n //= 5; count += n 一次把这些层全跑完。
时间 O(log n)，空间 O(1)。
```

---

## 总结

- 方法一：直接算 `n!` 再数 0
  - 字面思路，对小 n 也能跑
  - 大整数太慢，没抓住题目本质

- 方法二：枚举每个 5 的倍数，数它含几个 5
  - 不再算阶乘
  - 思路正确但 `O(n)`，没用上结构

- 方法三：按 5 的幂分层 (`n//5 + n//25 + ...`)（面试主推）
  - `O(log n)`，代码三行
  - 核心是“贡献 k 个 5 的数会被恰好数 k 次”这个组合论观察
