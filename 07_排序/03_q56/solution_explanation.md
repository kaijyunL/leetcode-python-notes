# LeetCode 56. 合并区间

## 题目理解

给定若干闭区间 `intervals[i] = [start, end]`，合并所有有重叠部分的区间，返回最终互不重叠、但覆盖范围不变的结果。

```text
intervals = [[1, 3], [2, 6], [8, 10], [15, 18]]
结果 = [[1, 6], [8, 10], [15, 18]]
```

两个闭区间 `[a, b]`、`[c, d]` 重叠的条件是：

```text
a <= d 且 c <= b
```

本题尤其要注意端点相接也算重叠：

```text
[1, 4] 和 [4, 5] -> [1, 5]
```

这道题的难点不在“如何合并两个已知重叠的区间”，而在于：如何避免让每个区间都和大量不相关区间反复比较。答案是先按起点排序。

---

## 方法一：暴力两两合并

文件：`solution_1_brute_force.py`

### 思路

不排序，先取一个区间作为当前区间，再扫描剩余所有区间：

- 如果有重叠，就扩展当前区间的左右端点。
- 合并后区间变长，原本不重叠的区间可能变成可合并，因此需要继续扫描，直到没有新的重叠区间。
- 当前区间最终确定后，再处理剩余区间。

例如：

```text
当前 [1, 2]
剩余 [4, 5]、[2, 4]

[1, 2] 先和 [4, 5] 不重叠
再和 [2, 4] 合并为 [1, 4]
此时 [1, 4] 又和 [4, 5] 重叠，必须继续扫描
最终得到 [1, 5]
```

这说明“不排序时只做一遍两两比较”不够，合并后的区间可能产生新的重叠关系。

代码为了让结果按起点有序，会手动选取剩余区间中起点最小的一个；但核心仍是反复扫描并合并，不是方法二的排序后线性扫描。

### 复杂度

- 最坏时间复杂度：`O(n^3)`。外层最多处理 `n` 个区间；每次合并后可能重新扫描剩余区间。
- 空间复杂度：`O(n)`，用于复制输入与保存结果。

### 面试定位

它能帮助理解“合并后为什么可能出现新重叠”，但效率太低。面试中简单提到这个问题后，应尽快转向排序。

---

## 方法二：按起点排序 + 一次扫描（面试主推）

文件：`solution_2_sort_merge.py`

这是本题最适合面试的标准解法。

### 怎么想到它

暴力法慢，是因为区间的相对位置杂乱，当前区间可能需要反复回头和之前漏掉的区间比较。

如果按区间起点升序排序：

```text
start_0 <= start_1 <= start_2 <= ...
```

那么每个新区间只可能和“当前正在合并的最后一个区间”重叠，不需要回头检查更早的区间。

原因是：假设当前合并区间是 `[merged_start, merged_end]`，下一个区间是 `[start, end]`。

- 若 `start <= merged_end`，下一个区间落在当前范围内或端点相接，应该合并。
- 若 `start > merged_end`，因为后面的区间起点只会更大，它们也都不可能再与当前区间重叠；所以当前区间可以安全放入答案。

这就是排序带来的关键优化：把“任意两两比较”变成“一次从左到右扫描”。

### 扫描过程

先处理空数组：

```python
if not intervals:
    return []
```

排序后，把第一个区间放入 `ans`，之后依次处理每个 `[start, end]`：

```python
if start <= ans[-1][1]:
    ans[-1][1] = max(ans[-1][1], end)
else:
    ans.append([start, end])
```

`ans[-1]` 就是当前最后一个已合并区间。

例如：

```text
排序后：[1, 3] [2, 6] [8, 10] [15, 18]

[1, 3] 先进入 ans
[2, 6]：2 <= 3，重叠，更新为 [1, 6]
[8, 10]：8 > 6，不重叠，[8, 10] 开始一个新区间
[15, 18]：15 > 10，不重叠，[15, 18] 开始一个新区间
```

最终：

```text
[[1, 6], [8, 10], [15, 18]]
```

### 为什么合并时只更新右端点

因为区间已经按起点排序，当前 `ans[-1][0]` 一定不大于 `start`。发生重叠时，合并区间的左端点仍然是原来的左端点；只需要将右端点更新为更大的那个：

```python
ans[-1][1] = max(ans[-1][1], end)
```

这也能正确处理包含关系：

```text
[1, 4] 和 [2, 3] 重叠
右端点 max(4, 3) 仍是 4
结果保持 [1, 4]
```

### 最容易错的边界

判断重叠必须写：

```python
start <= ans[-1][1]
```

不是：

```python
start < ans[-1][1]
```

因为区间是闭区间，`[1, 4]` 与 `[4, 5]` 在 `4` 处相接，仍应合并为 `[1, 5]`。

### 复杂度

- 时间复杂度：`O(n log n)`。排序为 `O(n log n)`，之后扫描为 `O(n)`，总复杂度由排序决定。
- 空间复杂度：`O(n)`。结果数组最多包含全部区间。

### 面试中怎么解释

可以直接说：

```text
我先按起点排序。排序后，如果下一个区间的起点大于当前合并区间的终点，
它以及后面的区间都不可能再与当前区间重叠，可以直接开启新区间；
否则只需更新当前区间的右端点。
```

## 方法对比与选择

| 方法 | 时间复杂度 | 空间复杂度 | 面试定位 |
|---|---|---|---|
| 暴力两两合并 | 最坏 `O(n^3)` | `O(n)` | 用于理解，不推荐写 |
| 排序 + 一次扫描 | `O(n log n)` | `O(n)` | 面试主推 |

本题需要记住的不是固定代码，而是排序后的判断逻辑：

```text
下一个起点 <= 当前终点：合并
下一个起点 > 当前终点：当前区间已经安全，可以开启新区间
```
