# LeetCode 57. 插入区间

## 题目理解

给定一个已经按起点升序排列、并且彼此不重叠的区间列表 `intervals`，再给定一个新区间 `newInterval`。要求把新区间插入进去，必要时合并重叠区间，最终仍返回有序且互不重叠的区间列表。

```text
intervals = [[1, 3], [6, 9]]
newInterval = [2, 5]

结果 = [[1, 5], [6, 9]]
```

这是一道区间题，不是在考排序算法。它和第 56 题的关系是：

```text
q56：输入区间无序，先排序，再合并
q57：输入区间已经有序且不重叠，直接插入并合并
```

第 57 题最重要的已知条件是：原数组已经有序。因此不应该忽略这个条件再重新排序。

---

## 方法一：追加后排序合并

文件：`solution_1_append_merge.py`

### 思路

最直接的做法是把 `newInterval` 放进原区间列表，然后完全按第 56 题处理：

```text
1. 将所有区间按起点排序
2. 从左到右合并重叠区间
```

例如：

```text
intervals = [[1, 3], [6, 9]]
newInterval = [2, 5]

追加后：[[1, 3], [6, 9], [2, 5]]
排序后：[[1, 3], [2, 5], [6, 9]]
合并后：[[1, 5], [6, 9]]
```

### 为什么它不是主解法

它当然正确，但题目已经保证原区间按起点有序。只插入一个新区间，却把 `n + 1` 个区间重新排序，是重复工作。

### 复杂度

- 时间复杂度：`O(n log n)`，排序占主导。
- 空间复杂度：`O(n)`，用于复制全部区间与保存结果。

### 面试定位

可以作为从第 56 题自然迁移过来的基础思路，但应立刻说明：原数组已经排序，能否跳过排序并做到 `O(n)`？

## 方法二：一趟三段扫描（面试主推）

文件：`solution_2_one_pass.py`

这是本题最适合面试的解法。

### 怎么想到它

原区间有序且不重叠。代码中先令 `start, end = newInterval`；这两个变量表示正在不断扩大的新区间。原区间统一通过 `intervals[i][0]`、`intervals[i][1]` 访问。每个原区间只会属于三类之一：

```text
左边：完全在 newInterval 左侧，不重叠
中间：与 newInterval 重叠，需要合并
右边：完全在 newInterval 右侧，不重叠
```

由于原区间已经按起点递增，三类区间一定按“左边 -> 中间 -> 右边”的顺序出现，不会来回交错。因此只需一个指针从左扫到右。

### 第一段：完全在左边

当前原区间满足：

```python
intervals[i][1] < start
```

它在新区间左侧，且连端点都没有相接，所以不需要合并，直接放进答案。

这里必须是严格小于：

```text
[1, 2] 和 [2, 3] 在 2 处相接，应合并
```

因此 `intervals[i][1] == start` 不能归入左边，而应进入重叠段。

### 第二段：重叠并扩大新区间

经过第一段后，当前区间不可能再完全位于新区间左边。只要：

```python
intervals[i][0] <= end
```

它就与当前不断扩大的新区间重叠或端点相接，需要合并：

```python
start = min(start, intervals[i][0])
end = max(end, intervals[i][1])
```

新区间的右端点可能因为合并而继续向右扩展，因此要持续检查后续区间。

例如：

```text
intervals = [[3, 5], [6, 7], [8, 10]]
newInterval = [4, 8]

[3, 5] 合并后 -> [3, 8]
[6, 7] 合并后 -> [3, 8]
[8, 10] 端点相接，合并后 -> [3, 10]
```

### 第三段：完全在右边

当当前区间满足：

```python
intervals[i][0] > end
```

它已经位于合并后新区间的右侧。因为后面的区间起点只会更大，它们也都不可能再重叠。

此时执行顺序是：

```text
1. 先把合并完成的 newInterval 放进答案
2. 再把当前区间及其后的所有区间按原顺序放进答案
```

### 过程举例

```text
intervals = [[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]]
newInterval = [4, 8]
```

扫描过程：

```text
[1, 2]：2 < 4，属于左边，直接加入答案

[3, 5]：3 <= 8，重叠，newInterval 变为 [3, 8]
[6, 7]：6 <= 8，重叠，newInterval 保持 [3, 8]
[8, 10]：8 <= 8，端点相接，newInterval 变为 [3, 10]

[12, 16]：12 > 10，属于右边
先加入 [3, 10]，再加入 [12, 16]
```

结果：

```text
[[1, 2], [3, 10], [12, 16]]
```

### 为什么是 `O(n)`

每个原区间只会被指针访问一次：

- 左边区间直接复制
- 中间区间参与一次合并
- 右边区间直接复制

没有排序，也没有回头扫描，因此总时间是 `O(n)`。

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(n)`，用于返回结果数组

### 面试中怎么解释

可以直接说：

```text
原区间已经有序且不重叠，所以相对于新区间只会依次出现三段：
左边不重叠、重叠、右边不重叠。
左边直接加入；中间不断用 min/max 扩展新区间；一旦进入右边，
后面都不可能再重叠，加入合并后的新区间和剩余区间即可。
```

## 方法对比与选择

| 方法 | 时间复杂度 | 空间复杂度 | 面试定位 |
|---|---|---|---|
| 追加后排序合并 | `O(n log n)` | `O(n)` | 过渡思路 |
| 一趟三段扫描 | `O(n)` | `O(n)` | 面试主推 |

第 57 题要记住的核心不是“插入”这个动作，而是利用输入已经有序的条件：

```text
intervals[i][1] < start：左边，直接加入
intervals[i][0] <= end：重叠，扩展 newInterval
intervals[i][0] > end：右边，加入 newInterval 和剩余区间
```
