# LeetCode 75. 颜色分类

## 题目理解

数组 `nums` 中只包含三种值：

```text
0：红色
1：白色
2：蓝色
```

要求把它们按 `0 -> 1 -> 2` 的顺序原地排列。

```text
nums = [2, 0, 2, 1, 1, 0]
结果 = [0, 0, 1, 1, 2, 2]
```

这里的“原地”表示直接修改传入的 `nums`，函数不需要返回数组。题目还要求不要直接调用排序函数。

这道题的关键不是一般意义上的排序，因为元素只有 `0`、`1`、`2` 三种。可以先利用“值域很小”做计数，再进一步思考：能不能只扫描一遍，就同时完成分类？

---

## 方法一：内置排序（题外对照，不可提交）

文件：`solution_1_builtin_sort.py`

### 思路

直接调用：

```python
nums.sort()
```

当然能得到正确结果，但它没有利用数组只有三种颜色的特点，也违背了题目的限制。因此它只用来明确最朴素的基线，不是本题的有效解法。

### 复杂度

- 时间复杂度：通常记为 `O(n log n)`
- 空间复杂度：取决于语言库实现；Python 的 `list.sort()` 使用 Timsort，最坏情况下可能使用 `O(n)` 辅助空间

### 面试定位

不能提交，也不应作为面试答案。真正的讨论应从计数开始。

## 方法二：计数后回填

文件：`solution_2_counting_fill.py`

### 怎么想到它

既然数组里只有三种数字，根本不需要比较两个元素谁大谁小。只要知道每种颜色各有几个，就能直接把数组写成：

```text
若 0 有 a 个，1 有 b 个，2 有 c 个：
[0, 0, ..., 0, 1, 1, ..., 1, 2, 2, ..., 2]
```

例如：

```text
nums = [2, 0, 2, 1, 1, 0]

计数后：0 有 2 个，1 有 2 个，2 有 2 个
回填后：[0, 0, 1, 1, 2, 2]
```

### 步骤

1. 第一遍扫描数组，统计 `0`、`1`、`2` 的出现次数。
2. 第二遍按 `0`、`1`、`2` 的顺序将这些值写回 `nums`。

虽然需要两遍扫描，但每个元素只会被常数次处理，仍然是线性时间。

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`。`counts` 永远只有 3 个位置，和输入长度无关。
- 扫描次数：两趟

### 面试定位

这是很自然的过渡解法：先利用值域只有三个数，得到线性时间。若面试官进一步要求“一趟扫描”，再推出方法三。

## 方法三：一趟三指针（荷兰国旗，面试主推）

文件：`solution_3_three_pointers.py`

这是本题最适合面试的答案。

### 怎么从计数法继续优化

计数法的两趟分别在做：

```text
第一趟：确认每个元素属于哪一种颜色
第二趟：把颜色放回正确区域
```

如果扫描到一个元素时就直接把它交换到对应区域，就不必等到第二趟。这正是三指针的想法。

初始化三个指针：

```python
zero = 0
current = 0
two = len(nums) - 1
```

它们把数组划分成四个区间：

```text
[0, zero - 1]       全是 0，已经处理好
[zero, current - 1] 全是 1，已经处理好
[current, two]      尚未处理
[two + 1, n - 1]    全是 2，已经处理好
```

因此循环条件必须写成：

```python
while current <= two:
```

只要未知区间 `[current, two]` 还存在，就继续处理。`current > two` 时，未知区间为空，整个数组自然已经分类完成。

### 三种情况如何处理

#### 1. `nums[current] == 0`

`0` 应放到最左边的 `zero` 位置：

```python
nums[zero], nums[current] = nums[current], nums[zero]
zero += 1
current += 1
```

交换后可以让 `current` 前进。因为当 `zero < current` 时，`nums[zero]` 属于中间的 `1` 区，交换到 `current` 后仍然正确；当 `zero == current` 时只是和自己交换。

#### 2. `nums[current] == 1`

`1` 正好属于中间区，不需要交换：

```python
current += 1
```

#### 3. `nums[current] == 2`

`2` 应放到最右边的 `two` 位置：

```python
nums[current], nums[two] = nums[two], nums[current]
two -= 1
```

这里最容易出错：**不能写 `current += 1`**。

从 `two` 换到 `current` 的元素来自未知区间，它可能是 `0`、`1` 或 `2`，必须留在 `current` 位置下一轮重新检查。

### 过程举例

以：

```text
nums = [2, 0, 2, 1, 1, 0]
zero = 0, current = 0, two = 5
```

开始：

```text
[2, 0, 2, 1, 1, 0]
 ^                 ^
current            two
```

`nums[current] = 2`，与 `two` 位置交换，`two` 左移，`current` 不动：

```text
[0, 0, 2, 1, 1, 2]
 ^              ^
current         two
```

接着依次遇到两个 `0`，都交换到左侧，`zero` 和 `current` 同时右移：

```text
[0, 0, 2, 1, 1, 2]
      ^     ^
      current two
```

此时又遇到 `2`，与 `two` 位置的 `1` 交换，`two` 左移，`current` 仍停在原地：

```text
[0, 0, 1, 1, 2, 2]
      ^  ^
      current two
```

随后两个 `1` 让 `current` 向右移动，直到：

```text
current > two
```

未知区间为空，结果就是：

```text
[0, 0, 1, 1, 2, 2]
```

### 为什么它是一趟扫描

`current` 通常向右移动，`two` 只会向左移动。每轮循环至少会让其中一个指针靠近终点：

- 遇到 `0` 或 `1`：`current` 右移
- 遇到 `2`：`two` 左移

所以每个元素至多被检查常数次，总时间是 `O(n)`。

### 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`
- 扫描次数：一趟

### 面试中怎么解释

可以直接说：

```text
我维护四段区间：左侧全是 0，中间已处理部分全是 1，
右侧全是 2，中间剩下的是未知区间。
扫描未知区间时，0 交换到左边，1 直接跳过，2 交换到右边。
2 换回来的是未知元素，所以 current 不前进，这是最关键的边界。
```

## 方法对比与选择

| 方法 | 时间复杂度 | 空间复杂度 | 是否满足题目要求 | 适用场景 |
|---|---|---|---|---|
| 内置排序 | `O(n log n)` | 依实现而定 | 否 | 仅作对照 |
| 计数后回填 | `O(n)` | `O(1)` | 是 | 值域小、不要求一趟 |
| 三指针荷兰国旗 | `O(n)` | `O(1)` | 是 | 本题面试主推 |

这题最重要的不是记住三个指针的名字，而是记住四段区间的含义。只要每一轮都维护住这四段区间，就能自然判断指针该怎么移动。
