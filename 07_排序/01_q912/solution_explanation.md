# LeetCode 912. 排序数组

## 题目理解

给定整数数组 `nums`，按升序排序并返回。

```text
nums = [5, 2, 3, 1]
返回 [1, 2, 3, 5]
```

题目要求不能直接调用 `sort()` 或 `sorted()`。因此重点不在“能否排好序”，而在于理解不同排序算法如何完成同一件事，以及它们的复杂度和适用条件。

本题的数组长度最多为 `50000`。因此 `O(n^2)` 的选择、插入、冒泡排序在最坏情况下会超时，它们保留在这里是为了建立排序直觉，不是最终提交方案。

---

## 方法一：选择排序

文件：`solution_1_selection_sort.py`

### 思路

把数组分成两部分：

```text
左边：已经排好序
右边：还没有排序
```

第 `i` 轮在区间 `[i, n - 1]` 中找到最小值，放到 `i` 位置。

代码中的 `min_index` 表示：在当前未排序区间里，目前找到的最小值下标。扫描完这个区间后，它指向的一定是该区间的最小值。

为什么可以把它直接放到 `i`？因为左边的 `[0, i - 1]` 在前几轮已经固定为全数组最小的 `i` 个元素；当前剩余元素中最小的那个，恰好就应该排在第 `i` 个位置。

例如：

```text
[4, 2, 5, 1, 3]
 ^

第 1 轮：在 [4, 2, 5, 1, 3] 中找到 1，交换后 [1, 2, 5, 4, 3]
第 2 轮：在 [2, 5, 4, 3] 中找到 2，本来就在正确位置
第 3 轮：在 [5, 4, 3] 中找到 3，交换后 [1, 2, 3, 4, 5]
```

每完成一轮，左边就多一个“位置和值都已经正确”的元素。因此只需要执行 `n - 1` 轮，最后一个位置会自动正确。

选择排序慢在每一轮都要扫描剩余区间：第一次比较 `n - 1` 次，第二次比较 `n - 2` 次，直到 `1` 次。比较总数是：

```text
(n - 1) + (n - 2) + ... + 1 = n * (n - 1) / 2
```

这就是它的时间复杂度为 `O(n^2)` 的原因。

### 复杂度

- 时间复杂度：`O(n^2)`
- 空间复杂度：`O(1)`
- 稳定性：不稳定。交换最小值时，可能改变相等元素的先后顺序。

### 面试定位

用于理解“每轮确定一个位置”的排序思路。数据量大时不适合作为本题答案。

## 方法二：插入排序

文件：`solution_2_insertion_sort.py`

### 思路

始终维护一个有序前缀。每次取出当前元素 `value`，从右向左移动所有比它大的元素，最后把它插入空出的位置。

```text
[2, 5, 3, 1]
       ^ value = 3

5 比 3 大，右移： [2, 5, 5, 1]
把 3 放入空位： [2, 3, 5, 1]
```

与选择排序的区别是：选择排序每轮从剩余元素中找最小值；插入排序会利用前缀已经有序这一事实来寻找插入位置。

### 复杂度

- 最坏时间复杂度：`O(n^2)`
- 最好时间复杂度：`O(n)`，数组本来有序时，每轮无需移动元素
- 空间复杂度：`O(1)`
- 稳定性：稳定。只有严格大于 `value` 的元素才右移。

### 面试定位

它不适合本题的大规模最坏输入，但非常值得掌握。许多工业排序会在小区间或接近有序的数据上使用插入排序。

## 方法三：冒泡排序

文件：`solution_3_bubble_sort.py`

### 思路

每次比较相邻两个数，前者更大就交换。一轮结束后，当前未排序区间里的最大值一定被移动到末尾。

```text
[5, 2, 3, 1]
5 和 2 交换 -> [2, 5, 3, 1]
5 和 3 交换 -> [2, 3, 5, 1]
5 和 1 交换 -> [2, 3, 1, 5]
```

代码里的 `swapped` 是提前结束优化：如果某一轮没有发生交换，数组已经有序，后续无需继续比较。

### 复杂度

- 最坏时间复杂度：`O(n^2)`
- 最好时间复杂度：`O(n)`，依赖提前结束优化
- 空间复杂度：`O(1)`
- 稳定性：稳定

### 面试定位

知道过程即可。它直观，但通常不是面试中值得主写的排序。

## 方法四：归并排序（面试主推）

文件：`solution_4_merge_sort.py`

这是本题最适合面试的通用解法。

### 怎么想到它

`O(n^2)` 排序慢在：每个元素可能反复扫描或移动很多次。要达到 `O(n log n)`，一个自然想法是把大问题不断二分：

```text
排序 [5, 2, 3, 1]
-> 分成 [5, 2] 和 [3, 1]
-> 分成 [5] [2] [3] [1]
```

单个元素天然有序。难点变成：怎样把两个有序数组合成一个有序数组？

答案是双指针。比较两段当前最小的元素，把更小的那个放进辅助数组；某一段用完后，直接复制另一段剩余元素。

```text
左段 [2, 5]，右段 [1, 3]
比较 2 和 1 -> 放 1
比较 2 和 3 -> 放 2
比较 5 和 3 -> 放 3
复制剩余 5   -> [1, 2, 3, 5]
```

### 递归函数的含义

```python
merge_sort(left, right)
```

表示把闭区间 `nums[left:right + 1]` 排好序。

- `left >= right`：区间只有零个或一个元素，天然有序
- `mid`：把当前区间拆为 `[left, mid]` 和 `[mid + 1, right]`
- 两边递归排序后，再执行一次 `merge(left, mid, right)`

合并时使用 `<=`，而不是 `<`。当两个元素相等时先取左段元素，因此保留原有相对顺序，归并排序是稳定的。

### 为什么是 `O(n log n)`

每次递归把区间长度减半，所以递归层数是 `O(log n)`；每一层合并时会处理全部 `n` 个元素，所以每层为 `O(n)`。

```text
总时间 = O(n) * O(log n) = O(n log n)
```

### 复杂度

- 时间复杂度：`O(n log n)`，最好、平均、最坏都一样
- 空间复杂度：`O(n)`，辅助数组 `temp`
- 稳定性：稳定

### 为什么它最适合面试

1. 最坏情况下仍然是 `O(n log n)`，复杂度有保证。
2. 分治和合并的逻辑清晰，容易从函数含义开始解释。
3. 重复元素不需要特殊处理。
4. 相比堆排序，代码更容易写对；相比快排，不会退化到 `O(n^2)`。

面试中可以这样概括：

```text
我先把区间递归拆到单个元素，再用双指针合并两个有序区间。
每层合并处理 n 个元素，一共 log n 层，所以时间是 O(n log n)，
代价是一个 O(n) 的辅助数组。
```

## 方法五：随机三路快速排序

文件：`solution_5_quick_sort.py`

### 思路

归并排序是先把数组拆开、再合并；快速排序则反过来：先选一个基准值 `pivot`，把元素按和它的大小关系分开，再递归排序尚未有序的两侧。

本实现随机选一个 `pivot`，通过荷兰国旗分区把当前区间分成：

```text
[小于 pivot] [等于 pivot] [大于 pivot]
```

等于 `pivot` 的中间区间已经不需要排序，所以分区结束后只递归处理左右两边。这就是快排能不断缩小问题规模的原因。

`quick_sort(left, right)` 表示把闭区间 `nums[left:right + 1]` 排好序。每次分区开始时，三个指针都围绕这个区间工作：

- `lt` 是“小于区间”后面的第一个位置
- `i` 是当前正在检查的位置
- `gt` 是“大于区间”前面的最后一个位置

循环不变量是：

```text
[left, lt - 1]：小于 pivot
[lt, i - 1]：等于 pivot
[i, gt]：还未处理
[gt + 1, right]：大于 pivot
```

每次只处理 `nums[i]`，分三种情况：

```text
nums[i] < pivot：和 nums[lt] 交换，lt 和 i 都右移
nums[i] = pivot：它属于中间区，i 右移
nums[i] > pivot：和 nums[gt] 交换，gt 左移，i 不动
```

最后一种最容易写错。交换 `nums[i]` 和 `nums[gt]` 后，从右侧换到 `i` 位置的元素还没有检查过，它可能小于、等于或大于 `pivot`，因此不能立即 `i += 1`。

### 分区过程举例

例如当前处理：

```text
nums = [3, 5, 2, 3, 1, 4, 3]
pivot = 3
```

开始时 `lt = i = 0`，`gt = 6`。

```text
看到 3：等于 pivot，i 右移
看到 5：大于 pivot，和 gt 位置的 3 交换，gt 左移，i 留在原地
         [3, 3, 2, 3, 1, 4, 5]
看到 2：小于 pivot，和 lt 位置交换，lt、i 都右移
         [2, 3, 3, 3, 1, 4, 5]
继续处理后，最终得到：
         [2, 1 | 3, 3, 3 | 4, 5]
```

竖线两侧的位置由 `lt` 和 `gt` 确定：

```text
[left, lt - 1]：小于 3，仍需排序
[lt, gt]：等于 3，已经全部正确，不再递归
[gt + 1, right]：大于 3，仍需排序
```

三路分区的价值在于重复元素：所有等于 `pivot` 的元素一次就被放到中间，递归时跳过它们。

例如数组全是 `3` 时，普通二路快排可能仍然把它反复拆分；三路快排只需扫描一遍，就发现整个区间都在“等于 pivot”区间中，直接结束。

### 递归如何收缩

分区结束后，逻辑上只需递归：

```python
quick_sort(left, lt - 1)
quick_sort(gt + 1, right)
```

当前代码多做了一步栈优化：先递归较短的区间，再用 `while` 循环继续处理较长的区间。

```text
左侧长度：lt - left
右侧长度：right - gt
```

这样每次真正压入递归栈的区间至多是当前区间的一半，递归栈可稳定控制在 `O(log n)`。这个优化不改变排序结果，只是更适合 Python，避免极端分区时递归层数过深。

### 复杂度

- 平均时间复杂度：`O(n log n)`。每次分区扫描当前区间一次；随机 `pivot` 通常能让区间不断接近对半缩小，约有 `log n` 层。
- 最坏时间复杂度：`O(n^2)`。如果每次都选到最小或最大值，问题规模只能从 `n` 变成 `n - 1`，总工作量变成 `n + (n - 1) + ... + 1`。
- 额外空间：`O(log n)`。代码先递归较短的一侧，再用循环处理较长一侧，避免递归栈随极端分区增长到 `O(n)`。
- 稳定性：不稳定

随机 `pivot` 降低了连续出现极端分区的概率，但不改变最坏时间复杂度的理论上界；三路分区则专门减少重复值带来的无效递归。

### 面试定位

快排和分区思想必须掌握。面试官若关心原地分区或重复值很多的场景，三路快排是很好的选择；但若只求最稳妥的答案，优先写归并排序。

## 方法六：堆排序

文件：`solution_6_heap_sort.py`

### 思路

把数组原地建成最大堆。最大堆的堆顶始终是当前最大元素：

```text
1. 建最大堆
2. 交换堆顶和当前末尾
3. 末尾元素已归位，堆的有效范围缩小
4. 对新的堆顶执行下沉 sift_down
```

`sift_down(root, heap_size)` 的任务是恢复以 `root` 为根的最大堆。它每次选择左右孩子中更大的那个；如果根已经不小于该孩子，堆性质就恢复了。

### 复杂度

- 时间复杂度：`O(n log n)`
- 辅助空间：`O(1)`
- 稳定性：不稳定

自底向上的建堆是 `O(n)`，随后有 `n - 1` 次下沉，每次 `O(log n)`，因此总复杂度是 `O(n log n)`。

### 面试定位

当题目同时要求“原地排序”和“最坏 `O(n log n)`”时，堆排序是标准答案。它的边界较多，现场写时需要特别留意 `heap_size` 是开区间上界。

## 方法七：希尔排序

文件：`solution_7_shell_sort.py`

### 思路

希尔排序是插入排序的改进。先按较大的间隔 `gap` 做插入排序，让相距很远的逆序元素能较快靠近正确位置；随后不断缩小 `gap`，最后 `gap = 1` 时完成一次普通插入排序。

```text
gap 较大：先消除远距离逆序
gap = 1：数组已接近有序，插入排序成本更低
```

### 复杂度

- 空间复杂度：`O(1)`
- 稳定性：不稳定
- 时间复杂度取决于间隔序列。本实现使用 `n // 2, n // 4, ..., 1`，最坏情况为 `O(n^2)`。

### 面试定位

知道它是“带间隔的插入排序”即可。实际性能不错，但复杂度不如归并、堆排序清晰，通常不是本题主写方案。

## 方法八：计数排序

文件：`solution_8_counting_sort.py`

### 思路

如果数值范围不大，就不必比较元素。令：

```text
min_num = 最小值
max_num = 最大值
counts[x - min_num] = 数字 x 的出现次数
```

统计完后，按 `counts` 从小到大把每个数写回数组。

负数没有问题。减去 `min_num` 后，最小值映射到下标 `0`。

```text
nums = [-2, 3, -2, 1]
min_num = -2
counts[0] = 2  -> -2 出现两次
counts[3] = 1  ->  1 出现一次
counts[5] = 1  ->  3 出现一次
```

### 复杂度

令 `k = max_num - min_num + 1`：

- 时间复杂度：`O(n + k)`
- 空间复杂度：`O(k)`
- 当前实现只还原数值，稳定性不是讨论重点；若要排序带附加信息的记录，需要按前缀和方式实现稳定版本。

LeetCode 912 的数值范围是有限的，因此这里的 `k` 至多约为 `100001`，计数排序可以通过。但在没有范围保证的通用排序问题中，不能贸然使用它：`[0, 10^9]` 只含两个数也会要求巨大的计数数组。

### 面试定位

它不是通用比较排序，但必须能说明适用前提：整数范围足够小。

## 方法九：基数排序

文件：`solution_9_radix_sort.py`

### 思路

基数排序从低位到高位依次进行稳定排序。

```text
先按个位
再按十位
再按百位
...
```

每一轮把数字放入 `0` 到 `9` 号桶，再按桶编号收集。桶内保持放入顺序，所以低位建立的顺序不会被高位排序破坏。

本题包含负数。代码的处理方式是：

```text
1. 非负数正常做基数排序
2. 负数取相反数后做基数排序
3. 负数部分反向再取负，接到非负数前面
```

例如绝对值排序结果为 `[2, 5]` 时，对应负数应为 `[-5, -2]`。

### 复杂度

令 `d` 为最大绝对值的十进制位数：

- 时间复杂度：`O(d * n)`，十进制桶数量 `10` 是常数
- 空间复杂度：`O(n)`
- 稳定性：对非负数的每一轮分配是稳定的

### 面试定位

适合整数、固定长度字符串等“能按位处理”的数据。它不是任意对象的通用排序方案。

## 九种方法如何选择

| 方法 | 时间复杂度 | 额外空间 | 稳定性 | 本题定位 |
|---|---|---|---|---|
| 选择排序 | `O(n^2)` | `O(1)` | 不稳定 | 建立基础直觉 |
| 插入排序 | 最坏 `O(n^2)` | `O(1)` | 稳定 | 小规模或接近有序 |
| 冒泡排序 | 最坏 `O(n^2)` | `O(1)` | 稳定 | 知道即可 |
| 归并排序 | `O(n log n)` | `O(n)` | 稳定 | 面试主推 |
| 三路快排 | 平均 `O(n log n)` | `O(log n)` | 不稳定 | 原地分区、重复值多 |
| 堆排序 | `O(n log n)` | `O(1)` | 不稳定 | 原地且最坏复杂度有保证 |
| 希尔排序 | 依赖 gap，本实现最坏 `O(n^2)` | `O(1)` | 不稳定 | 知道即可 |
| 计数排序 | `O(n + k)` | `O(k)` | 视实现而定 | 数值范围小 |
| 基数排序 | `O(d * n)` | `O(n)` | 稳定分配时稳定 | 整数或可分位数据 |

## 最终建议

第 912 题请按下面优先级学习：

```text
第一优先级：归并排序
第二优先级：三路快速排序、堆排序
第三优先级：插入排序
第四优先级：计数排序、基数排序
第五优先级：选择排序、冒泡排序、希尔排序
```

实际面试中，默认写归并排序；题目明确要求原地且不能接受快排的最坏 `O(n^2)` 时，写堆排序；面试官明确想看分区过程时，写随机三路快排。
