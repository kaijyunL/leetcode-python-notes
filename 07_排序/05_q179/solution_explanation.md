# LeetCode 179. 最大数

## 题目理解

给定一组非负整数 `nums`，每个数都必须作为一个完整整体使用。重新排列它们的顺序，使拼接结果最大，最后返回字符串。

```text
nums = [3, 30, 34, 5, 9]
结果 = "9534330"
```

返回字符串而不是整数，原因有两个：

- 拼接结果可能超过整数类型范围。
- 结果的本质是数字字符串的拼接顺序，而不是普通的数值加法。

这题最容易误入的思路是“按数字从大到小排序”。它不总是正确。

```text
nums = [121, 12]

按数值降序：121, 12 -> "12112"
正确顺序：12, 121 -> "12121"
```

因此我们真正要回答的问题不是“哪个数字更大”，而是：**两个字符串谁放在前面，能让拼接结果更大？**

---

## 方法一：全排列枚举

文件：`solution_1_permutations.py`

### 思路

最直接的做法是枚举 `nums` 的每一种排列：

```text
[10, 2]

[10, 2] -> "102"
[2, 10] -> "210"

取其中最大的 "210"
```

它一定正确，因为它没有遗漏任何可能的排列。

### 为什么不可用

如果有 `n` 个数，就有：

```text
n! 种排列
```

第 179 题的 `n` 最多为 `100`，全排列在很小的数据规模外就完全不可执行。这个方法只用于说明“最终目标确实是在所有排列中取最大”。

### 复杂度

令 `D` 为所有数字转换为字符串后的总长度：

- 时间复杂度：`O(n! * D)`，每个排列都需要拼接并比较。
- 空间复杂度：`O(n + D)`，不计排列生成器内部的实现细节。

### 面试定位

用于建立最朴素的正确性思路。面试中只需要提一句，随后立刻寻找不必枚举全排列的排序规则。

## 方法二：自定义排序比较

文件：`solution_2_custom_sort.py`

这是本题最适合面试的解法。

### 核心推导：只比较两个数的前后顺序

假设两个数字转成字符串后分别是 `a` 和 `b`。它们放置顺序只有两种：

```text
a 在前：a + b
b 在前：b + a
```

谁的拼接结果更大，谁就应该排在前面：

```text
若 a + b > b + a：a 排在 b 前
若 a + b < b + a：b 排在 a 前
若 a + b == b + a：两者先后无所谓
```

例如：

```text
a = "3"，b = "30"

a + b = "330"
b + a = "303"

"330" > "303"
所以 "3" 应排在 "30" 前面
```

再看前面“数值降序会错”的例子：

```text
a = "121"，b = "12"

a + b = "12112"
b + a = "12121"

"12121" 更大
所以 "12" 必须排在 "121" 前面
```

### 为什么只要按这个规则排序

假设一个排列中相邻的两个字符串是 `a, b`，但发现：

```text
b + a > a + b
```

那么交换这两个元素，一定能让整体结果更大：

```text
prefix + a + b + suffix
prefix + b + a + suffix
```

前缀 `prefix` 和后缀 `suffix` 都没有变化，决定大小的只有中间的 `a + b` 与 `b + a`。

因此，只要排序后不存在这种“相邻两项放反了”的情况，就不能再通过交换相邻元素让答案变大。`a + b` 与 `b + a` 的比较规则正是在消除这些逆序对。

### 为什么用字符串比较

对于同一对 `a + b`、`b + a`，它们长度一定相同。长度相同的数字字符串按字典序比较，结果和按数值比较一致：从左到右，第一个不同字符更大的那个整体更大。

所以可以直接写：

```python
if a + b > b + a:
```

不需要把拼接结果转回整数。

### Python 中怎样使用比较器

Python 的 `sort()` 接收的是 `key`，而不是 Java 风格的双参数比较函数，因此需要：

```python
cmp_to_key(compare)
```

把比较函数包装成 Python 可排序的键。

比较函数的返回值约定是：

```text
负数：a 排在 b 前
正数：a 排在 b 后
0：两者顺序无所谓
```

因此当 `a + b > b + a` 时返回 `-1`，让更优的 `a` 排在前面。

### 全零边界

如果输入是：

```text
[0, 0, 0]
```

排序拼接后会得到：

```text
"000"
```

但数值意义上的最大数应写成：

```text
"0"
```

排序后如果第一个元素是 `"0"`，说明所有元素都是 `"0"`，直接返回 `"0"` 即可。

### 复杂度

设 `k` 为单个数字字符串的最大长度：

- 时间复杂度：`O(n log n * k)`。排序约有 `O(n log n)` 次比较，每次比较最多拼接和比较 `2k` 个字符。
- 空间复杂度：`O(n * k)`，用于保存字符串列表与最终结果。

### 面试中怎么解释

可以直接说：

```text
不能按数字大小排，因为 121 和 12 组成的最大结果是 12121。
所以我定义两个字符串的相对顺序：若 a+b 比 b+a 大，就让 a 在前。
按这个比较器降序排序后拼接即可；最后把全 0 的 "000" 归一化为 "0"。
```

## 方法对比与选择

| 方法 | 时间复杂度 | 空间复杂度 | 面试定位 |
|---|---|---|---|
| 全排列枚举 | `O(n! * D)` | `O(n + D)` | 仅用于说明暴力思路 |
| 自定义排序比较 | `O(n log n * k)` | `O(n * k)` | 面试主推 |

本题的核心模板不是“把数字降序排列”，而是：

```text
当题目要求拼接后最大或最小时，比较 a+b 与 b+a，决定 a、b 的相对顺序。
```
